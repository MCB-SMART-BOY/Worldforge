# 明契卷 · 第二十四章 · 开炉布道，crate 发布、二进制交付与用户入口

第23章把那次该发未发的热气硬生生压回去以后，北院小室里反而更安静了两日。

变更日志补齐了。

弃用说明补齐了。

发布检查单也终于从头走到尾，没再漏口。

于是新的问题便不再是“这版敢不敢抬出去”。

而是更具体、也更门外的一刀：

· · ·

别人到底怎样得到青炉。

程知序把这句话问得极不客气。

“我不关心你们内部多漂亮。”她把长案上的几张发布页一齐推开，“我只关心三件事。怎么装，怎么跑，怎么判错。门外的人第一眼只会问这个。”

这话把众人的目光一下都压到了石镜最外层那张新发布页上。

页上如今已经有版本号，有变更日志，有迁移说明。

可若有人真站在门外，想把青炉拿回去用，眼前仍旧还有两条岔路。

第一条，是把青炉当一份可被别的 Rust 项目直接接进来的公开包（crate）发出去。

第二条，是先把能直接装、直接跑的命令器发出去，也就是二进制成品（binary）。

苏野平一眼就看中了第一条。

“既然都做到这一步了，不如索性把核心层也一起放出去。”他说，“别人若想接进自己的器里，不必只走命令入口，直接依赖青炉的骨。这样看上去才像真正成熟。”

季循听见这句，心里先是一动。

因为“把内部骨架也公开出去”这件事，确实有种很漂亮的味道。

像是真把一件器做到能传世的程度了。

可程知序几乎立刻摇头。

“那是你们维护者会高兴的事。不是第一次用的人会先碰到的事。”

她说着，直接把一张外侧收来的新问单摊到了众人眼前。

上头只有三行字：

“青炉怎么装？”

“我装完以后先打哪条命令？”

“若它回错，我先看哪？”

闻衡看着那三行，先写下第一句解释：

给别的 Rust 项目直接拿去当依赖的一份公开包，叫 crate 发布（crate publish）

又写第二句：

给使用者直接装来运行的一份成品命令器，叫二进制交付（binary release）

然后她把两张纸分左右摆开。

左边，是给维护者、集成者和深度使用者的路。

右边，是给第一次只想把青炉装起来、跑起来的人走的路。

“现在最该先做扎实的是哪边？”她问。

贺时进这回倒没有站苏野平那边。

因为门外窗口催得最紧的人，从来不是想把青炉接进自己项目骨里的那批人。

而是想先拿来用、先拿来跑、先拿来判一份工件的人。

沈见微没有让争论拖太久，直接落了裁定：

“第一版，先把二进制入口做实。crate 这条路先只保留最窄边界，不为了显得成熟就把半熟 API 一口气抬出去。”

这句话一落，季循反而像松了半口气。

因为他自己也知道，眼下青炉内部很多骨虽然已经站稳，却还没稳到可以让门外的人直接拿来长久依赖的程度。

若为了虚荣先把一大串内部接口暴露出去，后面每收一回骨、每改一回边界，都会在门外多留一层债。

程知序点头。

“这才像给人真入口。先别把别人带进你们自己都还在变的内室里。”

于是第24章第一件真正落地的事，不是再补新功能。

· · ·

而是把发布路径写明。

沈见微在石镜上写下第一条新说明：

若你只想安装命令器，走二进制入口

然后写下第二条：

若你明确知道自己要把青炉接进 Rust 项目里，才看 crate 说明

季循顺着往下补，第一次把安装方式写成别人真能照着走的话。

他先写下第三句解释：

用 Cargo 直接把命令器装到本机，叫安装（`cargo install qinglu`）

又补一句更白的话：

这不是“把源码抄下来自己研究”，而是先把能跑的器装到手里

程知序看着这两句，仍不满意。

“还差一步。装完以后第一眼看什么？”

这一下，所有人的目光都落回了前面几章其实已经碰过、却从没在门外真正当成第一入口来写的那两条命令上：

`qinglu --help`

`qinglu --version`

闻衡把纸翻到新页，写下第四句解释：

帮助入口（`--help`）不是装饰，它是第一次见面时青炉先对人说的话

又写下第五句：

版本入口（`--version`）不是炫耀，它是让人先确认自己手上到底拿的是哪一版

苏野平看着这两句，忍不住笑了一下。

“你们现在是连一句帮助话都要当外史来写。”

“本来就是。”程知序说，“门外的人最先碰到的不是你们的模块图，是这两行。”

于是这一夜，北院最花力气的地方，竟不是核心层。

而是 `--help`。

原来那版帮助页，站在维护者眼里已经算清楚。

可放到程知序手里，却被一条条挑出问题。

“什么叫 `doctor --legacy-bridge-audit`？第一次收窗的人看不懂。”

“什么叫‘请检查输入前提’？该检查哪张纸，哪一步先看，也没写。”

“安装完以后最小第一步是什么？只给命令，不给一句场景，也不行。”

季循第一次不是站在写器的人那边替这些字辩护。

而是老老实实照着门外视角，一行行重写。

帮助页最前面先写：

青炉用来检查、解释与深查历史工件问题

再往下才分成三条最小入口：

第一次先跑 `qinglu --help`

想确认版本先跑 `qinglu --version`

想先做最小检查，从 `qinglu check <输入>` 开始

后面所有更重的选项，都被往后压。

先让第一次进门的人看得懂。

再让第二次、第三次进门的人往深处走。

与此同时，外头也真的开始有人按这条新入口来用。

北岭二号守门房的段迟舟，那位先前已经在 issue 和 PR 里露过面的守门匠，这一回没再来问“这条桥该不该这样走”，而是直接送来了一张更朴素、也更尖的回报：

“我按安装说明装上了青炉。第一眼能跑起来。但我看 `--help` 时，还是不明白 `doctor` 和 `check` 到底先用哪个。”

程知序看完，抬头看向众人。

“看见没？这就是真用户。不是顺着你们设想的美路走，而是照他自己的处境问最朴素、也最容易把入口问穿的那种问题。”

这一下，季循第一次真切地感到，第24章并不是在“把发版做完”。

而是在让门外的人反过来塑形青炉。

不是维护者设想别人怎么用。

而是别人真的拿到手以后，逼你承认第一眼到底哪句还不够直、哪条入口还太像内行话。

于是帮助页又被压了一轮。

`check` 后面，补了一句：

先看这份输入现在合不合格，用它

`doctor` 后面，也补了一句：

当你已经知道这里有老病、想把构件清单、缓存和深层边界一起翻出来时，用它

程知序看完这两句，终于点了头。

“这才像把门开在外头。”

天快亮时，第一版真正要交出去的两样东西终于站到了一起。

左手，是给门外人直接装来用的二进制入口。

右手，是跟着一起更新好的 `README`、安装说明、帮助页和版本页。

而那条本来很诱人的“大面积公开 crate API”的路，被沈见微亲手压回了后面。

贺时进看着那页被暂时收起的 crate 公开计划，低声道：

“真不抬？”

“现在不抬。”沈见微说，“先把别人第一次怎样得到青炉、装好青炉、看懂青炉，做成可以独立走通的事实。再谈内部骨头有多好看。”

这句话让季循心里猛地一静。

他忽然明白，第24章要他主动放下的，其实是一种很隐蔽的虚荣。

不是“我会不会写”。

而是“我是不是急着让别人看见我内部写得多漂亮”。

可真正的出山，从来不是先把内室全掀给门外看。

而是先把门口的路修平。

临近收尾时，石镜另一面终于亮起了段迟舟补回来的第一条真正意义上的安装回报：

“已装。按帮助页先跑 `qinglu check`，再跑 `qinglu doctor`，结果与文档一致。唯一的问题是，我误把 `doctor` 当常规入口，幸好帮助里已经写了它更重。”

这条回报不算惊天动地。

可长案边的人都知道，它比许多内部掌声都更实。

因为这意味着，青炉第一次真的不只是被维护者设想用途。

它开始被门外的人拿在手里，用自己的处境去理解、去误用、再逼它长出更像入口的样子。

沈见微在文契第十九层落下最后一句话：

> 出山不是把内室炫给门外看，而是让门外的人第一次自己走得进来

石镜微亮，帮助页与安装说明一并沉入石录。

而青炉在这一章之后，终于真正迈出了“给人用”的那一步。
