# 明契卷 · 第十六章 · 留影为史，Git 不只是备份

第十五章刚把“优雅要服从可继承”写进文契第十层，北院小室里就又迎来了一件极不体面的事。

事情不大。

可它偏偏把大家最不想碰的一种旧病，又从角落里翻了出来。

午后，程知序抱着一叠旧窗回报走进来，把最上面那张压在长案中央。

“这扇旧窗，青炉现在照理说该能认。”她说，“可今天外头来人照着说明走，还是卡住了。”

季循接过那张回报，一眼就看见问题出在一个很不起眼的别名字段上。

青炉按现在公开写出的规则，本该把它归进“旧窗别名”那一类，再往下照常查。

可这一次，石镜里跳出来的却是：

`error: unknown legacy alias`

这行字并不大。

却让韩砺年站在门边的身形，微微僵了一下。

程知序最先看见。

“你见过这病？”

韩砺年没有立刻答。

他沉默了好一会儿，才低声说：

“见过。两年前的冬末，这扇旧窗夜里连炸过三回。后来我在旧机子上改过一口补丁，才把它先压住。”

屋里一静。

贺时进立刻追问：

“那补丁呢？”

韩砺年抬起眼，声音更低了。

“在我旧副本里。”

这六个字一出来，季循心里便是一沉。

不是因为“旧副本”三个字陌生。

恰恰因为它太熟了。

卷首那夜，太多事就是靠旧壳、旧桥、旧补丁、旧记性在暗处续着。

如今青炉已经走到第十六章，却还是要回头去问一台旧机子里是不是还藏着什么没人看过的答案，这本身就够刺眼了。

· · ·

沈见微没有立刻发作，只问：

“带来了么？”

韩砺年点了点头，从袖里取出一枚灰黑色旧存片。

石镜一照，里面连着跳出四个目录名：

`qinglu_old`

`qinglu_old_fix`

`qinglu_old_final`

`qinglu_old_final2`

程知序看得直接闭了闭眼。

“这谁分得清？”

韩砺年脸色很硬，却也没有替自己辩。

“那时候只顾着先把火压住。”他说，“谁还有空给每一刀起名字。”

苏野平先替他挡了一句。

“真出事时，先多抄几份备着，本来也没错。至少东西没丢。”

闻衡这时才走近长案，把那四个目录名一行行抄到白纸上。

她在旁边补了第一句解释：

把整份项目多抄几份留着，叫备份（backup）

然后停了停，才又写第二句：

把一次明确改了什么、为什么改，按先后留进公共历史里，才叫提交（commit）

季循盯着这两句，几乎是一眼就明白了问题到底卡在哪。

备份能保住东西不丢。

可备份回答不了另一件更要命的事：

这份东西，为什么会长成现在这样。

· · ·

沈见微让韩砺年把那几份旧目录一一打开。

结果越看，屋里越静。

有一份里多了一行对旧窗别名的手工归并。

有一份里又把那行改到了另一处。

还有一份把报错文案也顺手换了，却没写为什么换。

每一刀看上去都像救过火。

可放到今天，谁也说不清，最后到底该信哪一份，哪一份只是半夜里试过又丢下的旧痕。

季循盯着那几处细小差异，忽然觉得胸口发冷。

第十二章他们刚把 `README`、设计说明、注释分清。

第十四章才把总工地立住。

第十五章又刚学会别太早假统一。

可如果改动的历史仍旧只存在于“韩砺年大概记得”“这台旧机子里也许还留着”，那青炉迟早还是会滑回旧世界。

他低声说：

“若历史只活在谁还记得里，后来的人就永远只能靠猜。”

这句话让韩砺年握着旧存片的手，微微紧了一下。

他不是不知道这个理。

只是旧日那些夜里，活下来比写下来更急。

闻衡没有绕开这一层。

“你当年救火是真的。”她说，“可若救完以后没有留下公共可回查的史，那责任就只完成了一半。”

苏野平皱起眉。

“总不能每次刚救完火，还逼人坐下来写长文章。”

“不是长文章。”沈见微终于开口，“是历史。”

他把石镜转到空白面上，落下第三句解释：

给项目留公共历史的石录法（Git）

季循看着那句，心里微微一震。

入卷说明里早说过，石录接近 `Git`。

可直到今天，他才第一次真正明白，它为什么不只是一个“把东西存起来的柜子”。

沈见微继续往下写：

把一次清楚的改动留成一笔，叫提交（commit）

为了一件还没定案的事，先分出一条旁线单独试，叫分支（branch）

给一个共同承认的稳定节点起名，叫标签（tag）

把这些历史按先后翻出来看，叫日志（log）

程知序念完以后，问得很直：

“也就是说，`Git` 不是拿来多存几份副本的？”

“副本只能回答‘有没有留住’。”闻衡说，“`Git` 要回答的是‘这一刀是谁在什么时候改的、为什么改、后来又怎么接了下一刀’。”

韩砺年沉默很久，终于还是把那句最难听的话说了出来。

“可我当年没留。”

这一次，没人替他圆。

因为这正是第十六章要面对的那根刺。

你做过，不等于后来者能接住。

你救过火，不等于共同体已经得到这笔史。

沈见微没有继续追旧账。

他只把当前这件事拆成两个动作。

“第一，把那次补丁重新走一遍，但这次不许只存在于旧副本。”

“第二，从今天起，青炉的每一次明确改动，都不再只是一份能跑的目录，而是一笔能回查的史。”

说完，他在石镜上落下第一串命令：

```bash
git init
git status
```

然后补了一句人话：

先给青炉立一部能记史的石录，再看眼下有哪些改动还没写进去

季循盯着镜面上的字，没有觉得陌生，反而有种很稳的感觉。

因为这一次，他们不是在给青炉再添一块新骨。

他们是在给青炉补一条“后来者能沿着往回走”的时间脉。

沈见微把旧副本里那几处真正有关的改动单独摘出来，压到一旁。

没有一股脑全抄。

而是先开一条只为这件事存在的旁线：

```bash
git checkout -b trace-old-alias-fix
```

他在旁边解释：

不把还没看清的旧改动直接压上主线，先另开一条旁线试着追清，这就叫分支（branch）

这一下，连苏野平都点了下头。

因为这说法很实。

不是一上来就把整锅旧债再倒回青炉里。

而是先隔开，先查清，先让这件事在自己的那条线上说清楚。

接下来的一炷香里，屋里几乎没有多余的人声。

季循对着旧副本，一点点把那次真正救火的那一刀重新抄回青炉现在的写法里。

程知序在旁边补现实复现链，把“哪一类旧窗、什么情况下会卡住、补完后该看到什么”一条条写明。

闻衡则盯着每一处改动后面有没有理由，凡是只有“这样能过”的，她就不放行。

等那一刀终于重新落稳，沈见微才写下第二串命令：

```bash
git add .
git commit -m "fix: 补旧窗别名归并规则，并补复现说明"
```

他停了停，又补上一句解释：

提交（commit）不是说“我改完了”，而是把这次改动能交代给后来者

韩砺年望着那行提交说明，目光很久没动。

因为他忽然看见了一件旧日从没看清的事。

过去他也不是不负责。

只是他的负责，常常停在“我当晚把火压住了”。

而今天这笔提交逼着他承认，真正能交给后来者的负责，得多一步：

把为什么改、改了什么、影响到哪，一起留下。

程知序这时又问：

“那以后我若想知道，旧窗别名这条规则到底是什么时候立下来的，不必再去问人了？”

沈见微点头，写下第三串命令：

```bash
git log --oneline
```

然后解释：

日志（log）就是把项目一路怎么走到今天翻出来给人看

石镜里很快浮起刚刚那笔新留的史。

虽然只是一行短字。

可季循看着那行字，却第一次真切地觉得，青炉有了一种过去从未真正有过的东西。

不是“某个人还记得”。

而是“后来的人可以自己沿着这条史回看”。

韩砺年这时忽然从怀里又摸出一张更旧的折纸。

上面写着几个月前北院共同承认过的一次小稳点。

那是青炉第一次把 `check` 和 `explain` 放出去给门内几处窗口试用的日子。

以前这类节点，大家顶多口头记着“差不多就在那时候”。

如今沈见微却把这张折纸放到石镜旁，写下第四串命令：

```bash
git tag qinglu-v0.3.0-alpha
```

他解释道：

标签（tag）不是随手钉个记号，而是给共同承认过的稳定节点正式起名

贺时进看着那行字，先是愣了一下，随后竟少见地点了头。

“这比‘大概那一版’强。”他说。

“以后再有人问，门内第一次真能给人用的是哪一版，不用再靠猜。”

这就是标签真正补上的那层东西。

不是装饰。

而是把“大家都记得差不多”压成“公共历史里正式承认过哪一个点”。

临近傍晚时，石镜上已经不再只是几份互相打架的旧副本。

最外层有青炉当下的总工地。

中间有刚补上的那笔旧窗别名修补。

再往前，有今日第一次被认真命名的稳定节点。

韩砺年站在那面镜前，沉默了很久，最后才把手里的旧存片放到长案上。

“这东西我以后不单独压着了。”他说。

“不是因为它没用。恰恰因为它真救过命，我才不该再让它只活在我一个人的旧机子里。”

这句话一出，季循心里那点一直压着的冷意，终于慢慢松开。

他忽然懂了，第十六章最重的并不是几条命令。

而是从今天起，北院开始承认：

> 备份只能保住过去留下的东西。
>
> 历史才能把过去发生过的判断，真正交给后来的人。

沈见微在文契第十一层落下最后一句话：

> 能回查的改动，才算共同体真正拥有过的历史

石镜微亮，字痕沉下。

而那枚灰黑色旧存片，终于第一次不再像一块只认熟人的暗石。

它开始被放进公共石录，变成后来者也能沿着摸到的内史。
