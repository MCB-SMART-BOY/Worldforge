# 明契卷 · 第十八章 · 门规初成，提交规范、评审文化与新人接引

第十七章把远端仓库的门打开以后，北院小室里头一回出现了一种新鲜的忙乱。

不是火烧到脚边的忙。

而是远处的人终于真的沿着那扇门摸进来了，问题、补充、改动一下子都开始有了去处。

可去处有了，不等于秩序立住了。

· · ·

第二天一早，季循那张 `dry-run` 的 PR 下头，就已经挂了三条很不好受的意见。

第一条，是闻衡留的。

“第二笔提交只写了 `update explain`，看不出你到底补了哪一类说明。”

第二条，是程知序留的。

“报错里只写‘请检查输入’，没告诉收窗人该去看复现步骤、还是该先检查旧别名。”

第三条最短，来自韩砺年。

“你改了给人看的说明，却没同时改 `README` 里的入口提示。”

这三条字都不长。

却让季循盯着石镜看了很久。

因为每一条都不是在说“你的代码不对”。

可每一条，又都正正好好戳在他最不想承认的地方。

他的改动能跑。

可它还没有被整理成一个别人不见他本人也能接住的样子。

苏野平站在旁边扫了一眼，先替他说出那句最顺口的话：

“差不多就并了吧。说明一句句改，标题一行行抠，外头那边又不会因为你多写两句就少炸一次窗。”

贺时进也点头。

“对。门都开了，先把真正能用的东西并进去。剩下这些字面活，后面补不也一样？”

这正是第十八章最难顶的一股力。

当远端协作刚刚立起来时，所有人都会觉得，评审太慢，规矩太细，礼数太多。

尤其眼前还有现实窗口在催。

可闻衡连语气都没抬，只把石镜转回季循那张 PR。

“若 review 只是看看能不能跑，那第十七章开的门，很快就会重新只认熟人。”

· · ·

她写下第一句解释：

别人按同一套规则来看你的改动、提问题、要补证，这就叫评审（review）

然后她在旁边补了第二句：

评审不是挑刺，是防止主线再退回“谁最会讲，谁说了算”

季循看着这两句，胸口先是一紧，随后又慢慢沉了下去。

因为他其实知道，闻衡挑出来的那三条都没错。

只是在第十七章刚学会开 PR 以后，他本能地还想靠一句“我到时候再解释”把剩下那半步拖过去。

沈见微这时才开口：

“今天要解决的，不只是你这张 PR。”

“那是什么？”苏野平问。

“是谁来评，评什么，外头第一次想进门的人又该先看哪张纸。”

这三句一落，屋里立刻静了下来。

因为它们正好是第十八章绕不开的三道门槛。

若不答，远端仓库很快就会变成另一种更远的熟人场。

能提单，不等于能进门。

能开 PR，不等于能被公平看待。

闻衡先把季循那张 PR 单独抄出来，分成三栏。

第一栏写：

这笔改动本身到底改了什么

第二栏写：

别人怎么看得懂你为什么这么改

第三栏写：

外头的人以后第一次碰到这件事，能顺着哪张纸走进来

她把三栏往长案上一推。

“这就是以后评审至少要看清的三层。”

程知序立刻接上了她最关心的一层。

“若是给人看的入口变了，说明就得跟着变。否则你们北院觉得这次改动已经并了，外头却还是顺着旧话往错处走。”

韩砺年点头。

“若提交历史只写‘修一下’‘补一点’，后来查史的人也根本不知道你那一刀到底是冲哪件事去的。”

苏野平还是不服。

“照你们这套，评一次不得看半天？”

“是。”闻衡说，“但总比以后所有人轮流替一笔糊账擦屁股快。”

她说完，在白纸上写下第三句解释：

每次提改动时，先自动跑一遍固定检查的机关，叫持续集成（CI）

又补了一句更白的话：

CI 不负责替人理解改动，但它负责先拦住那些连基本门槛都没站稳的东西

季循盯着“自动跑一遍固定检查”，一下就明白了这东西为什么偏偏要在第十八章立。

若没有它，评审第一步总得先靠人去看：能不能构起、会不会立刻炸、文档样例是不是已经对不上。

这不但慢，也太靠老手手感。

沈见微把石镜翻到另一面，列出青炉当前最小的一套门槛：

总工地能不能完整站住。

给人看的说明样例是不是还能对上现在的入口。

这笔改动若碰了外显行为，相关文档有没有一起更新。

“以后凡是 PR 先过这三关。”他说，“过不去，先别进人评。”

贺时进皱眉。

“文档也算门槛？”

“对。”程知序这次回得比谁都快，“因为外头第一次撞上的，从来不是你们的内部骨头，是你们写给人看的那几行字。”

这句话一落，季循心里那点还想替自己辩的劲，终于散了大半。

他忽然看见，自己这张 PR 被挑出来的问题，确实不是礼节问题。

它们都是“这笔改动能不能真正交出去”的问题。

沈见微没有让这场争论空停在口头上。

他直接抽出一张新纸，写下第四句解释：

告诉第一次想提问题、提改动、进主线的人该怎么做的纸，叫贡献指南（CONTRIBUTING.md）

然后在下面一条条落规矩：

先看有没有已有问题单，再决定是补旧单还是开新单。

一张 PR 只做一件清楚的事，不把无关修补混在一起。

给人看的行为若变了，说明、示例、帮助入口一起改。

提交标题要让后来查史的人看得懂，不许只写“fix”“update”这种空话。

过了 CI，再进人工评审。

作者自己不算自己的最终裁定人。

这几条一写出来，长案边忽然安静得只剩石镜细响。

因为所有人都看得出来，这不是在给熟人之间加礼数。

这是在把“你得先认识谁、先求谁抬手”拆掉，换成第一次进门的人也能照着走的明规。

苏野平看了半天，最终还是卡在最后一句上。

“作者自己不算最终裁定人。这是不是太死？”

闻衡看了他一眼。

“如果改动的人自己说‘我已经没问题了’就能算完，那主线还是只认人，不认规矩。”

这句话像把整章的根一下钉住了。

> 门规不是拿来修饰关系。
>
> 门规是关系不好时也得照样成立。

季循这时低头重新去看自己的 PR，忽然第一次有点不敢直视那两笔提交。

`update explain`

`fix more`

这两行字在昨夜看着还像省事。

如今再看，却几乎像是在对后来查史的人说：

你自己猜吧。

他没再辩，只当着众人的面把那两笔重写了一遍。

第一笔，改成：

`docs: 补 dry-run 复现入口与窗口收单说明`

第二笔，改成：

`fix: explain 增补旧别名错误后的下一步提示`

程知序看着那两行新标题，轻轻出了口气。

“这回至少我三日后再翻，不用靠猜你昨夜脑子里装的是什么。”

可第十八章真正要验证的，还不是季循会不会改自己的 PR。

而是外头第一次想进门的人，能不能真的不靠人情进来。

临近午后，远端仓库最下方那张第十七章留下的 issue，又亮起了一行新动静。

还是北岭二号守门机那位守门匠。

这一次，他没有只补复现链。

他先在问题下留了一句：

“已按贡献指南自查，准备补窗口收单视角的示例说明。若方向不偏，我来起一张 PR。”

季循看着那行字，先是一怔。

因为这是青炉第一次，不靠北院里谁先点头，也不靠谁私下递话，就有人顺着门规自己问路、自己起步。

闻衡只回了很短一句：

“方向对。记得一张 PR 只补这一件事。”

一个时辰后，那位守门匠的 PR 真的挂了出来。

标题没有花样，就写：

`docs: 补北岭收窗视角的 dry-run 复现场景`

改动也很小。

只补了一段窗口收单人真正会照着走的示例说明，又把“看到这个错误后先看哪里”写得更直。

没有顺手再去改别的。

没有把个人习惯塞进公共说明里。

更没有靠一句“你们懂我意思”就把空白留给熟人去补。

程知序是第一个点开那张 PR 的。

她没有去看季循，也没有先去问沈见微“这能不能过”。

她就照着刚立下的门规，一条条往下看。

问题单有没有对上。

改动是不是只做了一件事。

说明有没有真站在收窗人的角度写。

CI 那三关是不是已经都过了。

看完以后，她在石镜上留了第一条正式 review：

“方向正确，示例够直。补一处：把‘旧别名未归并’时的下一步动作再写得更明一点，让第一次收窗的人不必回头翻两张纸。”

季循站在旁边，没有插话。

因为他忽然明白，自己此刻最该做的不是赶紧出声解释、也不是替对方说情。

而是看这套门规，是否真能在自己不出手时照样成立。

那位守门匠回得也很快。

没有辩，也没有借“我在外头不熟你们规矩”替自己松绑。

他只按程知序指出的那一点，补了一小段更清楚的下一步提示，然后回了一句：

“已补，请再看。”

程知序第二次点开石镜，重新过了一遍。

这回她没有再找季循。

也没有再找沈见微。

她只在那张 PR 最下方稳稳落了两字：

“可并。”

这两个字不大。

却让长案边所有人都静了一息。

因为这是青炉第一次真正出现：

一个不是主角的人，按规则提改动。

一个不是主角的人，按规则完成评审。

主线第一次没有靠主角独占解释权，照样往前走了一步。

苏野平望着那两个字，半天才低声说：

“原来门规真立住时，不是显得更冷，反而是少求人。”

贺时进也没有再顶。

因为连他都看出来了，这种看似慢一步的秩序，一旦站稳，反而比“谁急谁先喊、谁熟谁先过”的那种快路省下更多后账。

沈见微把那张新过的 PR 压进石录，又在远端仓库根页补上最后一张门纸：

给第一次进门的人看这里

下面接着三行：

先看 `README`

再看 `CONTRIBUTING.md`

有问题先开 issue，有改动再提 PR

闻衡看着那张纸，终于缓缓吐出一口气。

“现在这扇门，才算开始像门。”

第十八章收尾时，沈见微在文契第十三层落下一句短话：

> 门规若不能让生人第一次进门，它就还只是熟人之间的默契

石镜微亮，远端页安静铺开。

而青炉第一次显出了一点真正的“公共之门”的轮廓。

不是因为它从此再无争执。

而是因为从今天起，争执、改动、裁定，都开始有了不必求人情也能走完的入口。
