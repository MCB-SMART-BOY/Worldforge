# 《万构界·化形卷》第七章：壳与门

第六章那场关于"神谕"的会议之后，岑照渠做了一件周栖野没想到的事。

她没有开会。没有发传讯牌。没有在白板上画"我们要改革"的路线图。她只是安静地坐在自己的石镜前，把共享目录里被引用最多的二十张试验纸（`notebook`）全部翻了出来。一张一张地打开。一张一张地检查——不是检查逻辑对不对，是检查它们能不能在其他人手里跑通。

第一张就跑不通。

那是一张周栖野三个月前出的收入趋势分析——被季晚禾引用过至少十几次。她打开之后按了一下"全部重新运行"。石镜上跳出一串红色的错误信息。不是逻辑错误——是依赖错误。notebook 第三格引用了一个叫 `data_utils` 的模块，版本号是 `0.3.1`。但共享目录里的 `data_utils` 已经更新到 `0.4.0` 了。`0.3.1` 在作者机上周栖野的本地环境里还在——但他从来没有把那个版本标注为"此试验纸锁定依赖版本"。所以任何人打开这张试验纸，系统都会自动拉最新版——然后炸。

第二张是唐野渡的快速诊断脚本。第三格引用了一个数据源——北岭设备集群的实时日志端点。那个端点地址是半年前写死在代码里的。两个月前北岭那边迁移了日志系统，新端点换了地址。唐野渡在自己机器上跑的时候没问题——因为他的本地配置里手动覆盖了端点地址。但他从来没有把那个覆盖写进任何文档。任何人打开这张试验纸，第三格就会对着一个已经不存在的数据源发呆——然后返回空数据。不会报错。返回空——比报错更糟。因为报错你知道炸了。返回空——你可能以为业务正常，然后基于空数据做决策。

第三张。第四张。第五张。每一张都炸在不同的地方。依赖版本漂移（`dependency drift`）。硬编码路径。环境变量缺失。基座差异——在稳流派上写的脚本用到前沿派上，系统 Python 版本号差了一个大版本，语法报错。

二十张试验纸。八张能在作者机以外的地方一次性跑通。

"八张。"岑照渠把那二十张试验纸的检查结果摊在长案上，"二十张里——十二张在别人手里第一遍必炸。其中三张不会报错——返回空数据或者错误结果，但不会告诉你它错了。季晚禾上个月做的季度结算报告——引的那张收入趋势分析就在这里。如果她不是提前问了你一句'这个数字正常吗'——她会在董事会前拿着基于错误数据算出来的结果做汇报。"

周栖野盯着那二十张检查结果。每一张试验纸旁边都有岑照渠用红笔写的标注——"依赖版本未锁定""硬编码路径已失效""本地环境变量未声明""基座差异——稳流派 vs 前沿派"。四条标注。十二张试验纸。每一种错误都是同一种病：作者机上的"能跑"不等于别人也能跑。作者旁边的隐式前提——"这个模块版本在我机器上""这个路径在我本地配置里""我的 Python 是哪个版本""我的操作系统是哪个流派"——在别人手里全部变成雷。

"这不是工具集。"岑照渠把一张新纸贴在公共记录板上。纸上画了二十个方块——每张试验纸一个。方块之间的连线代表依赖关系：这张引了那个模块，那个模块又引了另一个数据源。图上一片密密麻麻的箭头。有些箭头指向已经不存在的数据源。有些箭头指向同一个模块的四个不同版本——`data_utils 0.2.8`、`0.3.1`、`0.3.5`、`0.4.0`，全部同时在用。有些箭头形成一个闭合的环——A 依赖 B，B 依赖 C，C 依赖 A 的一个旧版本。不是循环依赖（`circular dependency`）——是循环废弃（`circular abandonment`）。没有人敢动任何一环，因为动了任何一环不知道整个环会怎么断。

"这是生态系统。"岑照渠用手指在图上画了一圈。"一个没有人在维护的生态系统。而且——"她用石笔在图的右下角画了一条粗线，"这些方块分布在至少三种不同的基座（`foundation`）上。季晚禾用的是稳流派（Debian），系统 Python 三年没升过级。白又新用的是承契派（RHEL），企业仓库里的包版本是认证过的定制版。你和唐野渡用的是前沿派（Arch），滚动更新，最新版本。同一个 `data_utils`——在稳流派上的版本是 `0.2.8`，在前沿派上的是 `0.4.0`，在承契派上的是企业仓库定制版 `0.3.1-rhel`。三个版本。三种行为。零份文档说明为什么会有三个版本。"

她顿了顿。"我们的依赖图不是平的。它是站在三片不停移动的大地上。大地每动一下——依赖就断一截。但没有人感觉到——因为每个人只在自己的那片大地上跑自己的脚本。直到季晚禾用你的脚本——两片大地不一样——一切都炸了。"

"这是乱流在化形侧的形态。不是没有流——是流太多了。同一个模块有四条流在同时跑，每一条都觉得自己是主流。没有人告诉后来者该跟哪一条。"

---

"所以你要做什么？"周栖野问。他的声音比平时低。不是因为害怕——是因为他在看那张图的时候，发现那二十个方块里有九个是他写的。

"分层。"岑照渠在图旁边画了两条横线，把二十个方块分成了三层。

最上面一层她写了三个字：**对外壳**（`gate`）。中间一层：**稳定骨**（`core`）。最下面一层：**实验田**（`lab`）。

"以后凡是给别人用的东西，必须从对外壳进去。壳只做两件事——接收请求，调用稳定骨。壳不允许直接引实验田里的任何东西。实验田里的东西可以在内部随便引、随便改、随便炸——那是试法的空间。但如果有人想把实验田里的东西给别人用，必须先把它迁到稳定骨里，再从壳上开一个入口。"

她指着中间那层。"迁入稳定骨之前——必须通过宋既明的三条标准。第一：最小环境可复现——不是'在我机器上跑一下就行'，是'一个从零装好的新环境照着你的文档也能跑'。第二：输入输出有明确约定——不是'大概长这样'，是字段、类型、边界、错误情况全部写清。第三：必须有基座兼容声明——这个模块在哪些基座流派上验证过？如果季晚禾的稳流派和你的前沿派用的包版本不一样，骨里的文档必须写清楚。"

她指着最上面那层。"壳上的东西——就是承诺。承诺不是'应该能跑'。承诺是'我们在这些基座上验证过，在这些条件下测试过，如果跑不通——找这个页面上的人'。"

唐野渡从门口走进来。他已经听了一阵——手里的茶杯没喝，凉了。"你现在让周栖野每次想给别人看一个结果，都得先迁骨、再开壳、还要标注基座兼容性。以前他半刻钟就能出的图，现在可能要半天。"

"以前他半刻钟出的图——"岑照渠把那张 check result 推到唐野渡面前，指着其中一行，"两年后还在被人用。用错了都没人知道。而且用错的原因不只是逻辑过期——是基座变了。前沿派滚动了新版本，系统 Python 从 3.11 跳到 3.12。稳流派还在用 Python 3.9。同一个语法在两边表现不一样。包管理器的默认行为也不一样——稳流派用 apt 装的包和前沿派用 pacman 装的包路径不同。图在两片大地上跑出来的结果不一样——但没有人知道是因为基座差异。他们只知道'上周还能跑'。"

唐野渡沉默了。他看着那张图——二十个方块里有六个是他写的。第六个旁边岑照渠用红笔写着一行小字："此脚本在作者机上硬编码了数据源地址。数据源已迁移。脚本仍返回空数据。无报错。"

返回空。无报错。这是他三个月前写的快速诊断脚本——一个下午写完的。"先给个 demo"——谢催成当时是这么说的。他做到了。demo 很漂亮。结果很好看。然后他把脚本丢进共享目录，标了个"可用"，去干下一件事。那个数据源迁移的时候没有人通知他——因为没有人知道他的脚本还在用那个旧地址。依赖链是隐形的。直到岑照渠今天打开它。

"所以分层不是限制。"周栖野慢慢说。他还在看那张图——九个方块。每一个旁边都有岑照渠的红笔标注。有些是"依赖版本未锁定"。有些是"硬编码路径"。有一个旁边写着"此试验纸在三个基座流派上行为不一致——已在稳流派和前流派上复现差异"。他指着那行字。"这个——行为不一致——我从来没发现。"

"因为你只在你的基座上跑。我也是——我只在稳流派上跑。唐野渡只在前沿派上跑。白又被企业仓库绑在承契派上。我们四个人在四片大地上各自跑各自的脚本——从来没有把同一个脚本放在对方的大地上试过一次。"岑照渠把石笔放在那张图上。"分层的第一层不是壳。是承认——大地是碎的。不承认大地是碎的——就不会有人在稳定骨里写基座声明。不写基座声明——季晚禾就会继续在你的脚本上看到 ModuleNotFoundError 和安静的空白。不是因为你写错了什么。是因为你从来没有被要求过——说清楚你的脚本站在哪片大地上。"

---

当天下午，周栖野开始动手把共享目录里最核心的几个能力迁进稳定骨。

第一个是数据清洗流水线——息壤里被引用最多的模块。没有之一。他打开代码目录时，发现这个模块有四个版本同时在用。`v0.2.8`——稳流派上跑的，因为稳流派的系统 Python 版本太旧，不支持新语法，所以锁死在旧版本。`v0.3.1-rhel`——承契派上的企业定制版，在企业仓库里有认证签名。`v0.3.5`——过渡版本，周栖野自己写的，只用了一个月就因为"太复杂"被放弃了。`v0.4.0`——前沿派上的最新版本，用了 Python 3.12 的新语法，在稳流派上根本打不开。

四个版本。四种基座。零份文档。共享目录里只有一个文件名：`data_utils`。没有任何人知道——当他们 import `data_utils` 时，他们实际拿到的是哪个版本。取决于他们的基座。取决于他们本地环境里有没有手动安装过某个特定版本。取决于他们的包管理器是 apt 还是 pacman 还是企业仓库镜像。取决于运气。

"四个版本。"周栖洲把这份发现写在公共记录板上。旁边贴了一张岑照渠的检查结果——那张检查结果的最后一行写着："建议：迁入稳定骨之前，必须确认此模块在目标基座上的行为一致性。如果不能确认——至少在骨里标注已知差异。"

唐野渡站在旁边，看着板上越来越多的记录。沉默了很长时间。然后他说了一句让周栖野和岑照渠都转头看他的话。

"你那张分层图——给我留一列。我的那些快速诊断脚本，也该有个地方标清楚。哪些是实验——在红色标签里。哪些是承诺——该迁进骨里，标上基座声明。我上周出的 revenue_check——在稳流派上跑的结果和前沿派上不一样。前沿派上新版 pandas 的默认行为改了。同样的代码。不同的结果。如果不是季晚禾问了一句——我会一直以为它是对的。"

"你说真的？"

"说真的。"唐野渡把自己那张 revenue_check_v1 的试验纸翻出来。标题下面他亲手写了一行："本试验纸仅在前沿派基座上验证。稳流派和承契派上行为未确认。如需跨基座使用——请联系我。"然后他在试验纸角上贴了一个红色标签——实验田。

"这是我的第一张红色标签。"他说。"我写了三年脚本。从来没有在任何一张上标注过基座前提。不是我不愿意写。是从来没有人告诉我需要写。化形之道的整个文化都在说同一句话——'先做出来。做出来就是对的。能跑就是对的。'但没有人说过——在你自己的基座上能跑，不等于在别人的基座上能跑。在现在的基座上能跑，不等于在下一次滚动更新之后还能跑。在你自己的基座上能跑——只是第一步。不是最后一步。"
