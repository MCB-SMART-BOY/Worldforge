# 《万构界·化形卷》第十三章：三层息壤

白又新独立走通季度结算校验的那个傍晚，岑照渠把她三个月前画的那张分层图从公共记录板上取了下来。

纸已经有点旧了——边角被翻得起了毛，上面画的三层结构被各种颜色的笔反复修改过。周栖野在上面加过标注。唐野渡在上面划过线。叶藏拙用最小号的字在最下面那层旁边写了一行："此处有林过川旧桥遗迹——迁入前需先清桥。"宋既明在中间层的旁边贴了一张便条："迁入标准已更新至第三版——新增基座兼容声明。"

三个月。这张图从岑照渠一个人画出来，到现在被每个人的笔改过——变成了息壤的公共记录板上被翻得最旧的一张纸。

她把纸摊在长案上，用石笔在每一层旁边写了一个正式名称。

最上面一层：**xirang-gate**——对外壳。中间一层：**xirang-core / xirang-pack**——稳定骨。最下面一层：**xirang-lab**——实验田。

"从今天起，息壤正式分层。"她把纸重新贴在板上。"以后凡是给别人用的东西，必须从壳进去。壳不允许直接引实验田里的任何东西。实验田里的东西——试验纸、临时脚本、探索性分析——可以在内部随便引、随便改、随便炸。那是试法的空间。但如果有人想把实验田里的东西给别人用——必须先让它'存在'。通过宋既明的三条标准——最小环境可复现、输入输出明确约定、基座兼容声明——然后迁进稳定骨。"

谢催成站在门口，手里拿着两张新的需求单。他的表情和三个月前第一章里拍下第一张需求单时一模一样——急。但这次他没有直接说"先给个能看的"。他看完了岑照渠的分层图，然后才开口。

"北岭那边刚提了两个新需求。一个是实时数据监控面板，一个是自动化异常报警。你现在告诉我不能直接从实验田里拿东西给别人用——那这两个需求怎么办？"

"先在实验田里做。"周栖野说。"做到能跑了，拿给季晚禾试。"

"这和以前有什么不一样？"

"以前我写完了就丢进共享目录——标个'可用'，然后去干下一件事。现在——"他把岑照渠那张旧检查结果翻出来，指着上面那行"十二张在别人手里第一遍必炸"，"——我知道'能用'不等于'能在别人的基座上跑'。所以现在我做完了先在实验田里放着。然后我会问季晚禾——你的基座是什么流派？你的系统 Python 版本是多少？你的包管理器是 apt 还是 pip 还是企业仓库镜像？如果和我的不一样——我需要先在文档里写清楚我的基座前提。然后让她在自己的基座上验证一遍。不是'我这边能跑'。是'我和你在不同的基座上都跑通了'。"

谢催成愣了一下。"基座？"

"就是——我们每个人脚下踩的大地。"岑照渠接过话，"周栖野用的是前沿派——滚动更新，系统 Python 3.12，所有包都是最新版本。季晚禾用的是稳流派——系统 Python 3.9，版本冻结三年。白又新用的是承契派——企业仓库定制版，包版本经过认证，和外面的开源版本不一样。唐野渡也是前沿派——但他的系统 Python 和包管理器配置和周栖野不完全一样，因为他不喜欢某些最新版本的默认行为，手动降级了几个关键包。"

她摊开手。"我们五个人。四个基座流派。同一个脚本——在这四片大地上跑出来的行为不完全一样。以前我们不觉得这是问题——因为化形之道的默认前提是'作者就在旁边，作者的基座就是你的基座'。你写了一个脚本，季晚禾用——你在旁边帮她调环境。你不在旁边——她调不了。因为她不知道你的基座前提。她不知道你的 Python 版本、你的包管理器、你的系统库路径。这些信息没有被写下来——因为它们在作者脑子里。作者的脑子是唯一的文档。作者离职——文档消失。"

"化形之道的原罪不是写得快。"唐野渡说。他一直在旁边听，没有插话——他现在学会了在开口之前先听完整段。"是把所有文档都留在作者脑子里。写得越快——脑子里的文档越多——离职的时候带走的就越多。林过川为什么留下那么多沼泽？不是因为他写得不好。是因为他写得快。快到他来不及把脑子里的前提写成别人能看的文档。他的脚本跑通了——他标'可用'——下一个需求已经砸过来。他没有时间写'这个脚本的前提是我的 Python 是哪个版本'。他不是不想写。是化形之道的奖赏机制不奖励写前提。奖赏机制奖励'下一个能跑'。"

谢催成沉默了片刻。然后他问了一个他以前从来不会问的问题："那这次的两个新需求——你们打算在哪些基座上验证？"

周栖野看着他。三个月前谢催成说的是"先别管像不像样，能跑就行"。三个月后他在问基座验证。不是因为谢催成变了——是因为他终于看见了：不写基座前提的"能跑"，会在三个月后变成季晚禾石镜上的 ModuleNotFoundError，会在六个季度后变成北岭文档里的"息壤正式数据接口"——而那个接口在作者的基座之外根本不能用。

---

接下来一周，息壤的共享目录发生了肉眼可见的变化。

每一个文件名旁边都多了一个标签。红色——"实验田：不可外部依赖"。黄色——"迁入中"。绿色——"已入稳定骨：可外部调用"。每一个绿色标签旁边有三样东西：最小环境配置、输入输出说明和错误提示文档——以及一行**基座声明**。

基座声明不长。只有三行。第一行：本模块在哪些基座流派上已验证——列出基座名称和验证日期。第二行：各基座流派的最小版本要求——系统 Python 版本、关键依赖版本、包管理器类型。第三行：如果基座不匹配——应该联系谁。不是"去找周栖野"。是"联系 xirang-core 维护组"。人名会离职。角色不会。

唐野渡把自己过去三个月出的所有快速诊断脚本全部翻了出来，一个一个标标签。一共二十三张。二十一张红色。两张黄色——在迁入中。没有绿色。

他在每一张红色试验纸的标题下面加了一行基座注："本试验纸在前沿派基座上编写。未在其他基座流派上验证。如需迁移至稳流派或承契派——请注意依赖版本差异。前沿派上 pandas 默认行为与稳流派上不一致。如需跨基座使用——请联系我。"

"你以前不会写这种话。"周栖野看着他加的标签。

"以前我以为大地是平的。所有人站在同一片地上。后来我发现大地是碎的——岑照渠的前沿派、季晚禾的稳流派、白又新的承契派、叶藏拙的古式正脉——每一片大地上的默认前提都不一样。我的脚本在前沿派上能跑——不是因为我的脚本写得好。是因为我的脚本恰好站在了它被编写的那片大地上。换一片大地——同样的代码，不同的大地——结果就不一样。我以前不知道是因为我从来没有在别人的大地上跑过自己的脚本。现在我跑过了——在季晚禾的稳流派上，二十三张里能跑的一张都没有。不是我写得不好。是我从来没有告诉过任何人——我的脚本站在前沿派的哪一块具体地上。"

"那两张黄色的呢？"

"在迁。pandas 默认行为差异我已经定位了——是在稳流派上 groupby 的排序行为和前沿派上不一致。前沿派新版 pandas 默认不排序，稳流派旧版默认排序。同样的代码——同样的输入——输出顺序不一样。下游依赖输出顺序的脚本会炸——不会报错，只是计算结果偏移。和简阵卷里乔落的行序事故一模一样。同一种病。不同的道。"他顿了顿，"这两张迁完之后——就是我第一批绿色标签。预计下周。"

---

季晚禾从北岭发来一条消息。不是传讯牌——是写在共享目录里那批新上的稳定骨模块旁边的留言。消息很短："新上的三个稳定骨模块——我在稳流派上全部跑通了。没求助任何人。这是我第一次不需要在传讯牌上找人问'这个模块在哪'。也是我第一次在跑之前就知道——这个模块在稳流派上被验证过。"

消息末尾加了一个词："谢谢。"

周栖野把那行留言看了两遍。三个月前季晚禾在试验纸上写满了"最后放弃"——谢催成把那张纸贴在公共记录板上时，整组人都沉默了。三个月后她用"谢谢"替换了那个词。不是因为她变强了——是因为入口终于被写出来了。不是因为基座变统一了——是因为有人在文档里写清了：你站在哪片大地上，这片大地需要什么前提，如果不匹配应该怎么办。

"你知道三层息壤最核心的一层是哪层吗？"岑照渠站在板前，指着那张分层图。

"稳定骨？"周栖野猜。

"不是。是基座声明。壳是给使用者看的门——告诉他们入口在哪。骨是给维护者用的梁——告诉他们结构在哪。但基座声明是给每一个后来者的第一句话——告诉他们：你不是站在真空中。你站在一片特定的大地上。这片大地有它的规则、它的版本、它的默认前提。我们不再假装所有人站在同一片大地上了——所以我们不再让'我这边能跑'成为唯一的验证标准。"

她把手指从图上移开，转向公共记录板上那张被翻得最旧的分层图。"三个月前我画这张图的时候——我以为分层就是划三条线。实验田在下面。稳定骨在中间。壳在上面。现在我明白——三条线是骨架。基座声明是大地。没有大地——骨架就飘在空中。每一片大地上的骨架都不一样。稳流派上的稳定骨和前沿派上的稳定骨——不是同一具骨。除非有人写清楚——这具骨站在哪片大地上，对那片大地做了什么假设。"

周栖野看着那张图。三个月前的笔迹——岑照渠的、他的、唐野渡的、叶藏拙的、宋既明的——一层一层叠在上面。最外一圈是他自己今天早上加的一行字："化形之道的最终承诺不是'在我这儿能跑'。是'在任何被声明的大地上都能跑。如果跑到一片未被声明的大地上——联系基座声明上的那个人。他会告诉你——这片大地和已知的大地有什么不同'。"
