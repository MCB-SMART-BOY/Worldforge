# 守序卷 · 第35章 · 迁移之后

七个月后，常安完成了 Java 21、Spring Boot 3.2 和 Hibernate 6 的分批迁移。单元与集成测试通过；十四条旧的跳过测试都有了处置记录，未能判定的条目仍标为风险，没有混进“通过”的数字。接口契约、隔离负载和请求回放覆盖了评审批准的范围。

新版先在小流量实例上运行，再逐步扩展。第一周没有观察到异常的内存增长、GC暂停或连接等待；这只说明这一轮样本和观察窗口里没有发现问题。月末批处理还要在实际周期继续监控，回滚方案也保留到稳定性评审结束。

回放中有两处响应差异。其一来自团队确认并接受的日期精度变化，调用方已经得到通知；另一处是一个 `final` 事务方法的旧缺陷，团队在迁移前修复并按正确的事务行为建立基线。除此之外，纳入验收的业务字段、错误结构和连接等待范围都符合约定。每项结论都连着样本、容差和责任人。

言知非在迁移报告末尾写道：“版本升级完成，行为复核仍在继续。新版让维护重新回到受支持的基础上，也让我们看见旧系统里哪些假设一直没有被验证。后续改动应在触及它们时补证据、修前提、更新记录。”

旧接口工作仍未完成：两家已确认在用的团队尚未回应迁移通知，另外两家只有历史调用线索，是否仍运行还未查明；SOAP 服务因此继续保留，没有因平台升级而自动销账。每一次基础设施变化都能通过测试留下证据，但仍有些规则没有进入测试、配置或文档，只靠老员工口头传给新人。迁移结束后的第一张问题单，恰好写着这样一条从未登记过的约定。
