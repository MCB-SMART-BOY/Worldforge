# 守序卷 · 第29章 · 接口的调用方

旧接口清单建立后，第一项任务是给 `SettlementInquiryService` 找到真实调用方。网络团队从负载均衡与代理记录里筛出访问来源；其中大部分能按客户端证书或服务标识对应到系统，另一些只经过共享出口 IP，无法单凭地址认领。

第二项任务是在可访问的代码仓库中搜索 WSDL 地址、服务名和端点配置。结果找到六个候选调用方：四个能与近期部署和流量记录相互印证；另两个仓库最后一次部署在四年前，当前是否仍运行，记录不足以确认。

言知非把这些结果拆成三种状态：“已确认在用”“候选调用方”“待查来源”。代码里搜到引用，不等于线上仍在运行；暂时没在某个网关看见请求，也不能证明没有直连路径。基础设施组把旧代理上的路由也纳入流量核对，避免漏掉绕过常安网关的流量。

随后，接口维护人逐一联系四个已确认的团队，说明旧接口现状、替代 REST API 和拟定的迁移评估时间。一个团队很快确认迁移，一个团队提出需要更长窗口，另两个尚未回应。对未回应的对象，言知非继续找其服务负责人和部署管理员，并在清单上保留“未确认”，没有替他们勾选“已迁移”。

这次查找没能一次找全所有人，却留下了可复用的路径：从认证身份和传输日志识别来源，用代码搜索生成候选，再由系统负责人确认实际部署。每个调用方要记录服务名、负责人、业务用途、最近调用证据、迁移计划和联系人；不知道的部分也要明确标出来。

“关掉接口”暂时不在议程上。下一步是把已知调用方放到同一份迁移计划里，先听清他们依赖的行为和现实约束，再决定什么时候可以安全退场。
