# 守序卷 · 第2章 · 没人敢碰

事故记录归档后，言知非没有立刻提交升级回滚。他先把调查范围从一个依赖扩到整座常安：一百四十三个模块，最老的 `core-settlement` 创建于二十一年前，最初运行在 Java 1.4，如今已经迁到 Java 21。Spring 从 2.x 升到 6.x，Hibernate 也跨过了多个大版本。每一次升级都让它继续编译、继续启动，却没有人能保证每次默认行为都被重新核对。

`core-settlement` 的作者陈鹤鸣十年前离职。交接文档里，他写道：核心结算逻辑在 `SettlementService.java`；修改配置前先确认影响范围；当时已知有七个下游模块依赖它。最后还有一行提醒：“这些模块也没有稳定的维护人，但仍在生产处理交易。”

那份文档此后再没更新。七个下游里，一个在三年前的重构中已经移除，文档却仍把它列作现行依赖；剩下六个中，有三个在组织架构里挂着已经解散的团队。基础架构组只负责让它们通过升级后的编译和测试，没有人知道它们为何存在，也不知道哪些旧测试仍在保护关键行为。

言知非抽查了十四个被 `@Ignore` 标记的测试。每个旁边几乎都有相同的注释：“原作者已离职”“原意不明”“暂时跳过，避免阻塞发布。”这些测试没有消失，却不再执行；警报被关掉以后，代码还在，保护已经不在。

他把一张依赖关系草图贴上墙。箭头从结算模块伸出去，又绕回几组已经改名的服务。文档上找不到的地方，只能靠仓库记录、部署清单和还记得旧事的人一点点补齐。可每多问一个团队，便多听见一句“我们以为别人负责”。

“没人敢碰，不是因为代码一定有多复杂。”一位维护人看着那张草图说，“是因为我们不知道碰了以后，谁会先接到电话。”

言知非把十四个被忽略的测试、六个仍在生产的下游，以及三支已经解散的团队写进调查表。数字不会替他还原旧网，却至少让那张网第一次有了可以追问的边。
