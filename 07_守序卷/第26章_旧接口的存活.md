# 守序卷 · 第26章 · 旧接口的存活

常安的接口清单上共有四十七个入口：三十四个 REST API、八个 SOAP Web Service、五条 JMS 消息通道。最老的 SOAP 服务 `SettlementInquiryService`，其 WSDL 文件创建于十八年前。REST 尚未成为常见的企业接口形式时，SOAP 与 XML 是许多系统交换数据的日常。

“这些接口每天都还有流量。”值班经理指着图表，“可我们不知道每一条流量背后是谁。十八年前的接口说明已经丢了，WSDL 只剩一份。没人愿意关掉它，怕凌晨把别人的系统一起带停。”

言知非先去网关日志里找调用方，结果一无所获。部分 SOAP 服务早于 API 网关存在，仍直接暴露在内网；另外一些请求可能经过旧 ESB 或后来接手它的代理。网关看不到的流量不会因此消失，基础设施团队也有自己的配置和部署记录。

WSDL 能描述消息结构、操作和绑定信息，却不能代替调用方名单、业务场景、可用性约定和失败后的处理方式。一个接口的契约还包括谁依赖它、依赖到什么程度。若调用方只存在于某位离职同事的记忆里，服务团队便无法判断一次看似安全的改动会影响谁。

言知非启动旧接口审计。每条记录要有协议和版本、维护团队、已知调用方、流量来源、最近调用时间、未确认路径、替代方案、迁移责任人以及退役阻塞原因。发现到的调用方先标为“已确认”或“候选”，没有证据时不填“无人使用”。

清单上线后，大家第一次能把接口历史和仍在发生的调用放在一起看。下一步是追查最难认领的一类遗产：那份仍被当作权威，却可能早已和线上行为分离的 SOAP 描述。
