# 守序卷 · 第53章 · 与玄枢对话

理由链的调查记录整理好后，言知非把它寄给了玄枢的纪承钧。信里只有一个问题：当旧系统留下的理由断了，人该从哪里开始？

纪承钧回信时附上了玄枢的一页考古记录。玄枢是一套运行多年的 C++ 古器核心。一次断火之后，纪承钧沿着构建记录、旧版本和未归档的修正，追出一段适配代码当年保护的边界条件。那段代码看起来笨拙，却曾经让另一种平台上的设备保持运行。动它之前，他先找到了旧约束，再判断今天是否仍然成立。

回信末尾，他写道：“我的办法是在代码下面挖，直到看见它为什么这样长出来。可我写给息壤的迁移手册，后来也因为依赖关系在那边并不完整而失效。考古能找到过去的前提，却不能替你证明那些前提今天还在。”

言知非把这句话读给团队听。有人问：“那我们的方法有什么不同？”

“玄枢留下了很多结构和版本的痕迹，适合沿着代码历史往下挖；常安的问题，常常是规则还在运行，理由却散在审批、接口和人事记录里。”言知非说，“这是两个项目留下的证据不同，不是 C++ 或 Java 天生会解决哪一种问题。”

纪承钧的记录不能替常安回答监管要求，常安的规则档案也不能替玄枢辨认平台差异。但两边都从同一处开始：不把旧代码当成答案，也不因它看起来陈旧就贸然删掉。先查明它曾保护什么，再验证那个前提是否仍成立。

言知非把回信归到重构档案中，标题写作“他处的考古方法，及其边界”。它为常安提供了一个可借鉴的方向，也留下清楚的限制：理解过去，不等于获得修改现在的许可。
