## 五、本章最小实践

### 1. 核心概念

- commit
- branch
- tag

### 2. 最小项目动作

- 为 `qinglu` 建立一条可读提交历史，并用分支和标签明确一次变化节点

### 3. 推荐工具 / 命令 / 观察点

- 工具：`git`
- 命令：`git init`、`git status`、`git add .`、`git commit -m`、`git switch -c`、`git log --oneline`、`git tag`
- 观察点：别人是否能只靠历史消息看懂“发生了什么、为什么发生”

### 4. 必做练习

- 练习目标：把“做过修改”变成“留下可复查历史”
- 输入：当前 `qinglu` 项目
- 输出：至少 `3` 个有意义的提交、`1` 个功能分支、`1` 个标签
- 完成标准：每条提交信息都能说明意图而不是只写“fix”或“update”，并能从 `git log --oneline` 看出一条清楚变化线

### 5. 可选延伸

- 再写一段“如果没有这条历史，后来者最可能误判什么”

## 七、常见误区

- 误区一：
  - 表现：把 Git 当成自动备份箱，只求有历史，不求历史可读
  - 为什么不对：不可读的历史和没有历史，对后来者几乎一样坏
- 误区二：
  - 表现：把很多不相关改动挤进同一个提交
  - 为什么不对：这样会把“为什么这样改”再次埋回黑箱
