# 通界卷 · 第7章 · Schema注册表

"桥的契约——不是写在桥上——是写在注册表（schema registry）里——桥——只是注册表中'在此处——此版本——生效'的一个实例。"

顾迁舟建了渡桥司的第一个Schema注册表——不是Excel——是一个可以在四个世界之间查询的系统。"每一座桥——在注册表中——有一条记录——包含——桥ID——名称——两端世界——协议类型（protobuf / JSON Schema / Avro / 自定义）——契约文件（proto / JSON / 其他）——契约版本——注册日期——最后更新日期——维护人——退场日期——调用方列表——依赖桥列表。注册表——不是文档——是可查询——可审计——可被机器消费——的真相源（source of truth）。"

注册表的核心——不是记录——是验证。"注册表——不只是存契约——是验证——'此契约——在两端——是否一致。'当一个团队更改了桥的proto——注册表——自动比对——'此proto——在桥的另一端——对应的契约——是否兼容——字段编号是否冲突——新增字段——是否有默认值——删除字段——是否在调用方中仍被引用。'不兼容——注册表拒绝注册——要求——'请与以下调用方确认——字段变更——影响以下桥——请获得确认——或提供兼容方案——才可更新注册表。'"

注册表——也为调用方提供查询。"如果我想调用从玄枢到息壤的支付接口——桥是否已经存在——先去注册表——查——'支付桥——存在——版本v2.1——契约——proto在此——调用方——需要先注册——在注册表中声明——'我——XX服务——将依赖此桥——请在此桥的契约变更时——通知我。'——然后——才能调用。不是'问顾迁舟有没有桥'——是查注册表——注册表——是桥的目录——和桥的依赖声明——的公共基础设施。"

"注册表——让桥——从'人的记忆——和Excel——和'我去问一下'——变成可查询——可验证——可审计——从——'顾迁舟知道——顾迁舟更新——顾迁舟通知'——变成——'系统知道——系统验证——系统通知——任何人——在任何时候——都能查到——此桥——此刻——承诺什么——依赖谁——被谁依赖。'"

注册表的第一个版本——只有九座桥——从第九号桥的事故中幸存下来的——最需要被管理的——九座。顾迁舟在注册表的首页写了——"此注册表——开始时九座桥——目标是——三百四十七座桥——和之后——所有新生的桥——所有被退役的桥——所有——跨世界——契约。"
