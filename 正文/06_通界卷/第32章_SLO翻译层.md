# 通界卷 · 第32章 · SLO翻译层

"跨域SLO——需要——翻译层——不是——语言翻译——是——语义翻译——'在C++世界——可用率99.9%——延迟——p99在200ms内'——翻译到——Python世界——是——什么——在Python世界——可用率——99.9%——但延迟——需要——加上——桥本身的延迟——网关的延迟——sidecar的延迟——序列化开销——跨世界总延迟——不是——目标世界的延迟——是——端到端——的延迟。Python世界的调用方——在SLO中——看到——'可用率99.9%——延迟p99在200ms内'——期望——200ms——但实际——可能——350ms——因为——桥——是——额外的——跳——不是——目标服务——的一部分。"

翻译层——在注册表中——"每一座桥——声明——桥自身的SLO——桥的——p50延迟——p95延迟——p99延迟——桥的可用率——桥的吞吐量。然后——源世界的SLO + 桥的SLO + 目标世界的SLO + 网关的SLO + sidecar的SLO ——>端到端SLO——对于每一个——特定的——调用路径——计算——不是——估算——是计算——'在当前——观测到的——延迟分布——下——此——调用路径——的p99延迟——期望——在X毫秒——可用率——在——Y%——（假设——桥——按照——当前——状态——运行）。'"

"计算——被记录——被监控——被定期——重新计算——因为——SLO——不是——静态——随着——桥的版本——演化——调用模式——变化——目标世界的负载——波动——端到端——SLO——改变——不是——'一次——设定——永不——改变'——是——'持续——重新——计算——在——以下——因素变化时——重新——验证——是否——仍然——可被承诺。'"

翻译层——也标注——"SLO的前提——此端到端SLO——在以下前提下——成立——'桥当前版本v2.1——网关正常——未降级——目标世界的支付服务——在正常负载下——未超载——sidecar——配置——正确——没有——未完成的MAJOR——变更。'"如果——前提——改变——某一条——SLO——可能——不再成立——不是——自动——降低——SLO——是——告警——'此SLO的前提——以下——已变更——请——重新评估——可承诺的SLO。'"

"SLO翻译——不是——把数字——从一种语言——变到——另一种语言——是——把——'在A世界的——条件——下——可承诺——的——可用性——'——翻译——成——'在B世界——的——条件——和——桥——的——条件——组合——下——B世界——的调用方——能期望——什么。'——不是——数字——的——翻译——是——承诺——的——翻译——承诺——在翻译中——不能——丢失——精确性——否则——SLO——变成——谎言——在——不同的——语境——下。"
