# 简阵卷 · 第48章 · 观测的代价

观测体系运行满一个月——秦望秋面对一个意外的问题。OpenTelemetry 的 tracing 开销在生产环境中产生了影响——`data-aggregator` 的 P99 延迟增加了约百分之五。

团队有人提出质疑：观测让系统变慢了——值得吗？秦望秋没有回避这个质疑——她把观测的开销做成了可观测的。在 RED 面板上同时展示业务延迟和 tracing 开销——两条线，同一张图。凌晨接传讯牌的人可以看到：百分之五的开销换来从零到可见的全链路追踪，之前一个对账故障从追查到恢复需要几小时，现在平均不到半小时。

"观测不是零成本的——它消耗 CPU 和网络带宽来采集和传输数据。但灾备事故消耗人的注意力、下游的信任、结算的延期、凌晨的恐慌——这些成本是庞大的，而且不可见。观测的百分之五开销让追查时间从几小时降到了不到半小时。不是免费——是成本和收益都被量化。选择'用观测'不是一个信仰——是一个可以用数据做的决定。"

她把观测开销的数据贴在公共记录板上——每月复盘一次：开销在上升还是下降，收益在增加还是减少，是否需要调整采样率、优化数据传输、为特定服务降低采集频率。观测自身的成本也是观测的对象——不是一次性的决定，是持续的权衡。观测让不可见变成可见，包括观测本身。
