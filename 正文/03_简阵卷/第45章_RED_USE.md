# 简阵卷 · 第45章 · RED / USE

OpenTelemetry部署后每个服务有几十个指标。团队不知道看哪个——指标太多等于没有指标。

秦望秋引入RED/USE分类——不是选最好的指标，是选问对了问题的指标。RED：Rate（每秒请求数）、Errors（错误率）、Duration（延迟分布）——面向用户的服务，回答"用户感受到什么"。USE：Utilization（利用率）、Saturation（饱和度）、Errors（错误）——面向基础设施，回答"资源在承受什么"。

面向用户的API服务用RED——外部调用方关心的是这个接口有多快、多可靠。面向资源的数据库用USE——运维关心的是这台机器用了多少资源、快满了没有。问错了问题——指标越多越没用。问对了问题——几个指标就能定位。

凌晨两点接传讯牌的人最需要的不是全部数据——是用户视角和资源视角同时出现。RED告诉他哪个接口在慢，USE告诉他哪个资源在瓶颈。缩减后的仪表盘上只有几个核心数字，凌晨的人打开一眼就能判断——需要行动还是可以等到早上。这是对凌晨人的注意力的尊重——不是把全部数据塞给他们，是替他们筛选了最关键的问题。
