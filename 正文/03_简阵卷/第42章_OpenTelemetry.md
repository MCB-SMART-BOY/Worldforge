# 简阵卷 · 第42章 · OpenTelemetry

秦望秋完成了全部五十一个服务的 OpenTelemetry 部署。全景 trace 仪表盘上线——一个对账请求展开成二十七个 spans，跨七层服务，总耗时两千八百毫秒。

其中一千九百毫秒是等数据库，六百毫秒是等 gRPC，三百毫秒才是业务逻辑。业务逻辑只用了十分之一的时间——九成的时间在等。这不是慢——是不可见变成了可见的浪费。

"之前我们的系统不是在运行——是在等待。等待数据库返回、等待下游响应、等待连接池释放。等待本身不是问题——问题是没有人知道等待占了这么多时间，没有人知道最长的等待点在哪里。现在知道了——可以决定：哪些等是必要的，哪些等是因为查询没做优化，哪些等是因为数据库在整点被其他系统抢走。"

全景 trace 上线第一个二十四小时——团队围在仪表盘前面。乔落看到自己凌晨处理的对账故障的完整路径——之前只能看到一个服务的日志，现在看到整个请求走过的每一步、在哪一步花了多长时间、在哪一步出了错误。"之前我排查故障——在黑暗里摸。现在 trace 像一条主线——把所有日志串在一起。"

"OpenTelemetry 不是工具链——是文明的叙事能力。之前驿河在运行时是无言的——服务在跑但没有人能听懂它们在说什么。现在它们在说话——不是用人类的语言，是用 traces 和 spans 画出自己的行为。每一个请求都是一个故事——从入口到出口，经过了什么地方，在哪个地方停了多久，结束时带着什么结果。凌晨接传讯牌的人打开这个仪表盘不是在查 bug——是在阅读系统今天的行为。"
