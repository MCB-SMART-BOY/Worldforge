# 简阵卷 · 第53章 · 版本化

API 版本化——v1 到 v2 不是改数字，是重新承诺。semver 应用于 API：MAJOR 是不兼容变更，依赖方需要迁移。MINOR 是新增功能但向后兼容。PATCH 是 bug 修复向后兼容。

"我们内部服务——为什么也要版本化？因为不知道谁在依赖。Ch21——改日志格式——不知道七层在依赖。如果日志格式有版本，那个工程师在改之前会看到 v1 到 v2 是 MAJOR 变更——不兼容——需要通知依赖者。版本号不是数字——是给使用者的地图。告诉他们——这个接口的稳定性承诺是什么。1.0.0 意味着'我承诺 MINOR 和 PATCH 是安全的，MAJOR 是不兼容的需要你迁移'。0.x.x 意味着'我不承诺任何东西——随时可能变'。"

大部分内部服务在 0.x 版本跑了很久——从来没想过升级到 1.0。因为从来没想过向依赖方承诺稳定性。现在有了版本号——每个 API 有了承诺等级：0.x 是不承诺，1.x 是承诺向后兼容，弃用声明提前一个版本公告。版本号告诉每个服务的依赖者——"这个接口你能信任到什么程度"。不是接口变了才升级版本——是在变更发生之前版本号就定义了它能承受什么级别的变更。
