# 简阵卷 · 第41章 · 看得见的与看不见的

秦望秋在 `data-aggregator` 上部署了 OpenTelemetry 的第一个 tracing agent。对账请求经过七个服务——第一个 trace 用了两千三百毫秒。之前没有人知道这个数字——因为没有人能看到完整的路径。

trace 展开成瀑布图，七个服务的每一层都显示在上面。最宽的一栏是数据库查询——一千四百毫秒，占了超过一半的时间。冯知远盯着这张图。

"我的服务不是在等别人——是在等数据库。之前我一直在优化自己的代码——以为是我自己慢。但真正的瓶颈在数据库查询——和我的代码没有关系。tracing 让我看到了——之前我以为的慢不是我的。"

"这就是观测的意义。之前你只能看到'从 A 到 B 有调用'。现在你看到 A 调用 B，B 调用 C，C 等数据库等了一千四百毫秒。你可以停在任何一层看——看什么、看多久。不是看到单个服务——是看到服务之间的空白。哪里最慢、哪里在等、哪里断了。"

第一个 trace 不只是一条线——是一个世界的运行时在说话。之前驿河的运行时是无言的——请求进来、服务处理、结果返回。中间发生了什么没有人能看到。现在每一个请求都有了护照——trace ID 贯穿所有服务。护照上记录着它经过了哪些口岸、在每个口岸停留多久、有没有被拦截。

"观测不是为了监控。观测是为了让看不见的变成看得见的。监控告诉你什么坏了——观测告诉你为什么坏了、坏在哪一层、从什么时候开始坏的。凌晨传讯牌响了——打开 trace 仪表盘，输入 trace ID，看到瀑布图上有七个服务的延迟分布。不是从零开始猜——是从数据开始看。"
