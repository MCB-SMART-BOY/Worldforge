# 简阵卷 · 第81章 · 新手接住

凌晨洪峰——外部流量飙升，`data-aggregator` 数据库连接池耗尽。请求超时，重试，更多请求涌进来，死亡螺旋。

乔落接传讯牌。打开观测面板——trace 显示请求在数据库连接获取处断裂，metrics 显示数据库连接数持续碰顶。她连到数据库查看连接数——应用端用了全部一百五十一个连接，数据库端最大连接数就是一百五十一，刚好超过。每一个新请求都在等那个连接，永远等不到。

连接池没有设上限——`database/sql` 默认值是零，即无限制。应用在洪峰时抢占了所有数据库连接——数据库自己也需要连接做维护。她设了 MaxOpenConns 为一百，给数据库留几十个连接的余量。限制应用端连接数——保护数据库不被饿死。

"你设了一百——为什么不是一百五十？因为数据库最大一百五十一——如果应用拿满，数据库本身也需要连接做维护。留一些是给数据库呼吸的。Ch43 秦望秋的 goroutine 泄漏教会我看余量——设限制不是限制自己，是留余地。"

整个过程她没有呼叫傅远洲。观测面板让她看到根因，依赖图让她知道影响范围，on-call 流程让她知道每一步该做什么。不是背了手册——是理解限制不是削弱，是保护。新手接住了第一次完全独立的事故处理。
