# 简阵卷 · 第81章 · 新手接住

凌晨洪峰。外部流量飙升，`data-aggregator`的数据库连接池在几秒内耗尽。请求超时。重试。更多请求涌进来——死亡螺旋。

传讯牌亮在乔落的面板上。她不是刚好醒着——她是在on-call轮值表上。打开观测面板——trace显示请求在数据库连接获取（`connection acquisition`）处断裂，不是查询慢，是根本没有拿到连接。metrics显示连接数持续碰顶——所有可用连接被占满。依赖图告诉她`data-aggregator`的数据库被七个下游依赖——如果它死了，整个对账链停摆。

她连到数据库查看连接数。应用端用了全部一百五十一个连接。数据库端最大连接数就是一百五十一。刚好满了——没有余量。每一个新请求都在等连接。永远等不到。

问题在连接池没有设上限。`database/sql`的默认值是零——无限制。应用在洪峰时抢占了所有数据库连接。数据库自己也需要连接做维护——但连接被应用拿满了。

她设了`MaxOpenConns`为一百。留了几十个连接的余量给数据库自己。

整个过程她没有呼叫傅远洲。观测面板让她看到根因。依赖图让她知道影响范围。on-call流程让她知道每一步该做什么。新手接住了第一次完全独立的事故处理。
