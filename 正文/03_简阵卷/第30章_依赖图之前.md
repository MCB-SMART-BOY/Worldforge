# 简阵卷 · 第30章 · 依赖图之前

卷三最后一天，傅远洲在公共记录板上画了一条线。左边是已知依赖——RPC 接口、数据库连接、消息队列，这些在文档中声明过的依赖。右边是隐式依赖——日志格式、超时设置、环境变量、配置文件中的默认值，这些从未被文档化但被多个服务在运行时依赖。

"日志端点事故告诉我们——真正的依赖不只在 API 里。在日志格式里，在超时设置里，在环境变量里，在那些'我以为只影响我'的决定里。这些依赖从未被画成地图。我们需要——不是继续追事故，是在下次事故前把看不见的依赖变成看得见的线。"

卷四「依赖图」——画隐式依赖的地图。不是五十一个服务的组织架构——是它们之间的真实调用关系、数据流转、格式依赖、超时链。在日志端点事故之后再画——因为已经知道什么格式可以被改、什么格式改了会影响七个服务。观测体系是画地图的工具——结构化日志标注了依赖链的断点，分布式追踪标出了七个服务的传染顺序。地图会让后来者不需要在凌晨重新发现：这个日志格式不能被改，它在七个服务下面被依赖。

向卷四开门——从看见隐式依赖到把它们画成所有人都能查的地图。不再是事后追查，是事前可见。
