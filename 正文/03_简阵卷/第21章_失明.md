# 简阵卷 · 第21章 · 失明

一个工程师改了日志端点（log-endpoint）——从 v1 升级到 v2。日志格式从纯文本变成了 JSON。这是内部优化，不涉及 API 变更——测试全部通过，部署顺利。

十五秒后 `data-aggregator` 开始报错——它的日志解析模块基于 v1 的纯文本格式写的。四十五秒后 `stats-calculator` 超时——它依赖 `data-aggregator` 的输出。九十秒后 `report-generator` 累挂了。一百二十秒后 `settlement-validator`、`notification-bus`、`external-gateway`——七个服务，一串倒下去。

不是 bug——七个服务都在等同一个日志，同一个日志的格式变了。日志格式不是 API——没有人觉得它是契约。但它被七层服务依赖——比任何正式 API 都更深的依赖。

执行变更的工程师愣在屏幕前。"我以为只改了我自己的日志。我不知道七个服务在等它。你怎么知道？我没有地方可以查。没有人写过——哪些服务依赖了哪些日志格式。它是隐形的。"

这是驿河的第四维度——隐式依赖网——藏在所有正式 API 下面。服务之间有文档声明了 RPC 接口，但没有文档声明了日志格式。日志是每个服务自己生成的，在生成它的服务看来它是输出——但在读取它的下游服务看来，它是输入。输出者不觉得它是契约，输入者不觉得它有承诺。但依赖是存在的，只是没人声明。

失明——不是眼睛被蒙住。是从来没有人告诉过他——其他人依赖他的日志格式。一个看似无关的内部优化，通过不被声明的依赖链传播到了七个服务，在凌晨之前炸了半个平台。
