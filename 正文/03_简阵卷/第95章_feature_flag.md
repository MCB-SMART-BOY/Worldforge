# 简阵卷 · 第95章 · feature flag

回顾 Ch61——优化让服务变快，因为时序假设改变，炸了下游。全量部署等于信任一切测试——但测试不能复制生产。如果有 feature flag——先给百分之一的流量，在百分之一上发现时序变化——不会炸百分之九十九。

Feature flag 让变更不再是二进制开关——是渐进交付。开关层——on 或 off。百分比层——百分之一到十到五十到一百。定向层——特定用户或条件。部署不再是全量上线后祈祷——是先给少量流量，等几分钟，看指标——正常就扩大，异常就回滚。那百分之一的流量是唯一真正的测试——因为在生产环境上的百分之一比任何测试环境上的百分之一百更接近真实。

Flag 的生命周期——创建、上线、渐进扩大、全量、清理。不是永远的——有保质期。flag 留在代码里会变成新的"四十三项模板"，是新的技术债。每个 flag 创建时就标注了退场日期——两周后要么全量，要么删除。特性开关让上线从一次赌博变成一次可控的实验——不是让变更更慢，是让变更更安全。
