# 简阵卷 · 第104章 · 四人的伤痕

同一时刻——四人各自收到了旧屋的召唤。

沈见微在青炉。记录板上一道旧伤痕浮现——来自他发给玄枢的诊断报告 v0.3.1，那份做了所有对的事然后炸了玄枢的报告。cargo-audit 全量审计、静态分析、调用统计——每一步都对。但"对"在玄枢变成了凌晨的断火——北岭设备集群结算失败——因为他的'可安全废弃'漏了一行 Makefile 注释里的 Unix domain socket。他的"写清楚就是一切"在另一个平台上——因为清楚是有语境的——炸了别人。他看着记录板上的伤痕——纪承钧的传讯原文还贴在那里——"不是指责——是继续。"他放下手中的 crate 文档，起身。

纪承钧在玄枢。runbook 在息壤炸了之后散落的纸页还在旧石案上。他以为写了完整地图——十七步，每一步基于玄枢的扎实经验。但第三步——"确认所有下游依赖方已全部迁移"——在息壤是不可执行的步骤。季晚禾标记了十一个"待确认"。他的完整地图在 Python 的世界里不通行。他收到传讯的那一刻——想到了周栖野的回信——"你把你世界的前提当成了所有世界的前提。"他把纸页收好——和钟守玄留下的七个字"前提可能不成立"放在一起。起身。

周栖野在息壤。512MB 默认值模块在驿河 OOM 的记录还在板子上——白又新带模块去驿河的时候他写了"在息壤验证通过"。验证是真实的——但验证的前提是息壤的单租户小批量场景——在驿河的五十一个共享服务的全量加载中——512MB 是致命的。"速度自足"留下的预设没有声明前提。温故来设这个值的时候是对的——在他那个时代——但他没有把"为什么"和数字一起传递。周栖野继承了数字——丢了理由——模块在驿河的凌晨 OOM。他看着叶藏拙账本上的记录——"Ch87——息壤模块在驿河 OOM——三条管道超时。"放下笔，起身。

傅远洲在旧屋。他的制度能保证有人接传讯牌——on-call 轮值、手册签名、四项模板。但不能保证接的人会多写一行"待补"。制度是地板——但远古告警在地板下面——在驿河还没建的时候就在发送——等一个从来没有出现过的回应。制度充分——但不充分于回应一个比制度更老的召唤。他独自站在创始者的设计图前——发出最后的传讯。

四道伤痕——四种道的极限——同时浮现。沈见微看到自己的"写清楚"炸了别人。纪承钧看到自己的"完整地图"在另一个世界不通行。周栖野看到自己的"够快"在另一个平台成了炸弹。傅远洲看到自己的"充分制度"在远古告警面前沉默。同一道伤痕——"我以为我的道——就是道"——在他们各自的世界被击穿。另一头的召唤来自旧屋——同一次传讯同时到达四人——四个人各自放下手上的东西，出发。修补者工坊的门虚掩着——创始者的字迹还在墙上。石镜在等。
