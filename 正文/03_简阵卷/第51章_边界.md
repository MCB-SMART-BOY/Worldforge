# 简阵卷 · 第51章 · 边界

外部对接系统改了 API 返回格式。驿河的结算炸了。

追查时对方的解释是"我在更新日志里写了"。驿河的回应是"我们没有订阅你们的更新日志——因为从来没有人告诉我们需要。"双方都以为是对方的责任——但其实谁都没错，因为根本没有契约。API 的语义不在任何地方，只在双方的"我以为"里。他以为改了字段名不影响下游，他以为更新日志就是通知，他以为如果有问题对方会来问。驿河以为外部系统不会改接口，以为接口的格式是固定的约定，以为不需要订阅更新日志因为"从来没人说过需要"。

"边界不是技术边界——是信任边界。信任不能靠'我以为'。需要白纸黑字。需要 API 契约——不是文档，是双方都承认的约定。契约不是防炸——是炸了之后知道谁该知道、谁该通知、谁该迁移。没有契约的边界不是边界——是幻觉。边界是服务的承诺——'这是我的接口，这是它的格式，这是它的版本，这是我的兼容性承诺。'每次变更——所有依赖方自动收到通知。每份通知都有迁移指南和窗口期。"

傅远洲和外部团队签了第一份正式 API 契约。protobuf 定义了接口，每一个字段有注释、有约束、有版本号。不是不会炸——是炸了之后有一份文档写着炸裂的责任在哪一侧。契约是信任的外壳——不是替代信任，是让信任有可验证的形式。
