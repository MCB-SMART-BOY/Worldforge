# 简阵卷 · 第112章 · 四个伤痕

四人将各自平台标志性的事故永久刻在记录板上——作为"为什么共约需要存在"的证据。不是隐藏——是公开。不是耻辱——是路标。

玄枢的伤痕——诊断报告 v0.3.1。"来自青炉——沈见微用 cargo-audit 和静态分析生成——标注'可安全废弃'——legacy-report-gateway——青炉侧调用为零——三十六个月。玄枢侧观测面板——调用为零——三年。判断——安全——删除。后果——北岭设备集群结算失败——玄枢断火——凌晨丑时。根因——北岭备份系统通过 Unix domain socket 在每夜丑时调用该接口——socket 不在任何网络采集点上——Makefile 注释中的编译开关——六年前搭的——从未被文档化。写清楚不是一切——清楚在另一个世界的语境下可能不够。"

息壤的伤痕——runbook 十七步。"来自玄枢——纪承钧基于渡桥司桥治理标准写的迁移流程——十七步。第三步——'确认所有下游依赖方已全部迁移'——在玄枢——依赖注册表存在——在息壤——不存在。季晚禾按步骤执行——标记十一个'待确认'——整个 runbook 无法执行。根因——玄枢的依赖管理靠注册表——息壤的依赖管理靠 import 链——两种基础设施——同一个动词'确认'——完全不同的含义。地图不是疆域——地图在另一个世界可能不通行。"

驿河的伤痕——模块 512MB 默认值 OOM。"来自息壤——白又新携带 seasonal-settlement-validator 部署到驿河——内存默认值 512MB——在息壤单租户小批量场景中够用。在驿河五十一个共享服务全量加载中——2.3GB——OOM——三条管道超时。根因——温故来三年前设的值——在他那个时代是对的——但'为什么是这个值'没有和数字一起传递。后人继承了数字——丢了理由。制度不是充分——制度需要带着前提声明。"

青炉的伤痕——写清楚的边界。"来自玄枢——沈见微收到纪承钧的传讯——诊断报告在玄枢炸了。做了所有对的事——cargo-audit、静态分析、调用统计、免责声明——炸了。因为他不知道玄枢的 Makefile 注释——不知道那个 Unix domain socket——不知道凌晨丑时的备份脚本。写清楚的边界不是写的人的边界——是跨过道的边界之后——不可见的东西的边界。唯一的路会杀死后来者。"

"伤痕不是暴露弱点——是建立信任。我们犯过的最大的错在这里——后来者不要重复。格式——事故摘要：发生了什么。根因：什么假设被打破了——不是谁错了。教训：不是以后怎么做——是以后怎么判断——判断假设是否在你的世界里仍然成立。"

四个伤痕不是失败的标记——是文明的免疫记忆。没有伤痕的文明没有免疫系统——它记不住自己在哪里生过病。这次病过——留下了疤痕——疤痕标注了"此处——前提可能不成立——请验证"。伤痕不是结局——是为什么我们需要共约。共约不是从天上掉下来的——是从这四个凌晨的断裂中蒸馏出来的。每一个读到伤痕的后来者——不是在读前人的失败——是在读文明在自己身上的实验——和实验之后留下的路标。
