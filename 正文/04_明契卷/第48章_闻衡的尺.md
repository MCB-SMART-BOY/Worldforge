# 明契卷 · 第48章 · 闻衡的尺

闻衡——审契者——首次介入。不是测试，不是 code review——是审契。

"这个接口——承诺了什么？承诺成立的前提是什么？如果前提不成立，接口的行为是什么？"他的尺不是找 bug——是问"你写的够不够让后来者不需要来问你？"

沈见微的第一个 scoped API 被审。"你的文档写了成功时的行为——但失败时返回什么？""Err。""具体——什么 Err？构建失败可能是配置错，可能是依赖缺失，可能是权限不够。你的接口只返回 'Err'——调用者不知道是哪种——无法决定该重试、还是告警、还是放弃。写清楚——不只写'会出错'，写'会出什么错，每种错意味着什么。调用者凌晨面对你的 Err 需要立刻判断该做什么——不是去翻代码。"

闻衡的尺有四条度量标准。接口的所有输入、输出都有文档。所有错误情况都有文档——每种错误的含义和应对。所有隐式依赖——环境、版本、配置——都被声明。承诺失效的条件被写清楚。

"不是批评你的代码——是让你的代码能说清楚它自己的边界。之前程知序用你的 API 时每次出错都要翻源码——他在凌晨翻了几小时才发现是权限不够。如果你的文档写清楚了——他不会需要翻源码。闻衡的尺不是为程知序一个人建的——是为所有以后会在凌晨面对你的 API 返回的 Err 的人建的。"
