# 明契卷 · 第76章 · 测试的契约

测试不是验证代码——是定义"对"。每一个测试用例在说"这个行为——是有承诺的。如果后来者改动了它——测试会告诉他们——这里有一个约定被改变了。"

Rust 的测试体系——单元测试和代码放在同一个文件中、集成测试放在 tests 目录、文档测试保证文档中的代码示例正确。`cargo test` 跑所有测试——不只是验证功能，也是验证文档和示例。每次 CI 跑测试——不是在找 bug，是在验证承诺未被打破。每一个测试在替使用者说——我依赖这个行为，如果你改了它，先通知我，给我迁移指南。

"测试不是写给机器跑的——是写给后来者看的。每个测试用例的名字是一句话——描述被承诺的行为。后来者不需要读代码——只需要读测试的名字列表——就知道这个模块承诺了什么。测试名字是给后来者的目录——按行为分类、按场景归类，一目了然。如果后来者想改某个行为——先看测试列表——知道哪些人在依赖什么——然后再改。"
