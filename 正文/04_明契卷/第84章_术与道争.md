# 明契卷 · 第84章 · 术与道争

何时该用 Rust——何时不该用。不是技术比较——是场景判断。

"如果你的系统是一个人维护——几个月内不会换人——Python 够快。Rust 的 trait 和生命周期需要时间——一个人没有 code review——写错了可能更危险。如果你的系统被外部依赖——凌晨有人接传讯牌——Rust 的编译器替后来者验证了大部分。如果系统是短命工具——写完就扔——Rust 太重——不值得。如果系统需要运行十年——后来的维护者不是你——编译器的严格是对他们的唯一承诺。"

Rust 的真正优势不是性能也不是安全——是承诺的可验证性。但可验证性有代价——抽象的学习曲线、编译时间、生态系统的成熟度。不是所有场景都应该用 Rust——有时快和省力比可验证更重要。需要判断场景需要什么样的"清楚"来保护相应的后来者——然后选择相应的道。"不是 Rust 好过 Python——是选择服务于后来者。在你的场景里——后来者需要什么——你就给他们什么。在青炉的场景里——后来者凌晨会接传讯牌——它需要 Rust 的严格。在息壤的场景里——后来者需要快速验证数据格式——Python 的灵活是它的承诺。道不是武器——是工具。工具的价值由后来者定义。"
