# 明契卷 · 第50章 · 立制之后

卷五收束。Trait 系统建立——类型契约有了。顾迁衡搭了第一座桥——退场日期在桥账上，临时不再是永远。闻衡的尺亮出——审契者让承诺可验证。门规初稿在记录板上——所有 pub API 必须经过审契。

但沈见微看着门规的第一行——心里知道制度立起来了，但制度本身会不会成为新的黑箱？

"闻衡的尺是好的——但如果闻衡不在，谁来执尺？门规是好的——但如果门规被当成不可更改，它就成了新的不可理解的旧脚本。制度也需要自反——也需要'此规则可能不完整'——也需要退场日期。立制是好的——但制度不是终点。制度需要被审视——被后来者——在前提变了之后——重新判断。"

闻衡在门规第一行加了一句话——这是审契者对自己的审查。"此门规由闻衡起草——基于青炉前五十章的事故教训——可能不完整。当新的事故发生时——补充。"

卷六「同修」——Git、review 流程、苏野平的碰撞。立制之后，需要验证的是制度能不能在多人协作中存活——不是一个人维护所有规则，而是每一个人在规则下知道自己的位置。
