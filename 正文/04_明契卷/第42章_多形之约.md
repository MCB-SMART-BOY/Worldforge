# 明契卷 · 第42章 · 多形之约

Trait bound——类型契约的另一种写法。`fn process<T: Display + Debug>(item: T)` 不是"接受任何类型"——是"接受任何实现了 Display 和 Debug 的类型"。你在声明这个函数只接受能满足这些契约的类型。使用者在调用前编译器会检查——如果类型不满足，编译不过。

与驭器卷 C++ templates 形成跨卷对照——在玄枢，template 的错误在调用点，在十层调用栈之后显示，没人看得懂。在 Rust，trait bound 让错误在"你签了契约但满足不了"的时候就在定义点显示——在这里，不传递。

"这不仅是编译器的便利——是文明级别的差异。C++ 的 template 错误像炸弹在最后一步爆炸——你需要回溯十层调用栈才能找到出错的地方。Rust 的 trait bound 在入口处就告诉你——你不能进来，因为你的契约没满足。前者的哲学是'先让进来，炸了再说'，后者的哲学是'进门之前请先声明你有这些能力'。和化形卷'先让它跑'的 Python 相比——Rust 在门的维度上是最严格的。不是不让跑——是跑之前先签署能力契约。"
