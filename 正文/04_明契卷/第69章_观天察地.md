# 明契卷 · 第69章 · 观天察地

青炉需要诊断——日志、追踪、指标。不是"加上 tracing"——是让生产中的错误能被追溯到源码中的具体行。

Rust 的 `tracing` crate 提供结构化日志——每条日志自动带 timestamp、span 上下文、trace ID。不是写 `println!`——是写 `info!(request_id = id, "processing started")`。生产环境中一个请求失败了——凌晨的人用 trace ID 反向查询在哪个 crate、哪个函数、哪一行、什么参数。凌晨的人不需要 grep 源码翻几百行日志——查询自动串联整条调用链。

"诊断不是'记录一切'——是'记录后来者需要知道的'。他们需要知道——什么请求、哪个 span、在哪一步出错、当时的上下文是什么。tracing 让生产状态变得可查询。错误在生产中是沉默的——除非日志让它们发出声音。而日志发出声音的条件不是'日志多'——是每条日志带好了 trace ID 和上下文，能被凌晨的人反向拼接成故障路径。"
