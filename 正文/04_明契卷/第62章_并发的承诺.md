# 明契卷 · 第62章 · 并发的承诺

Rust 的并发模型不是"线程加上锁"——是类型系统加上 Send 和 Sync trait。编译器在编译期检查跨线程传递的值是否安全——如果类型不满足 Send，不能跨线程移动。

不是靠人在 review 中检查——是编译器在编译时拒绝。Send 标记"这个值可以安全地转移给另一个线程"。Sync 标记"这个值的引用可以安全地被多个线程共享"。编译器自动为大多数类型推导这些 trait——如果你的类型包含非 Send 的字段，编译器直接说"不能"。在运行时崩溃之前——编译器的错误信息就是防线。

青炉的 report 模块从单线程改成了多线程批处理——用 `std::thread::spawn` 并行处理多个报表。第一次编译时编译器报错——因为闭包捕获了一个 `Rc<Config>` 而非 `Arc<Config>`，`Rc` 不能在线程之间安全共享。"不是让你少用并发——是让你知道并发时哪些值不该跨线程。编译器帮你守边界——跨过去之前检查这条路是否安全。"
