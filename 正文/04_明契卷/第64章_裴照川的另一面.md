# 明契卷 · 第64章 · 裴照川的另一面

裴照川——镜像者——是沈见微的更极端版本。沈见微写 safety comment 时解释前提和边界，裴照川写 safety comment 时写下形式化证明——从 Rust 的内存模型推导出某个 unsafe 操作在所有可能的执行路径上都是安全的。不是写了三行注释——是写了一份不短的形式化推导。

"你的论证——是给后来者读的。但后来者可能不懂形式化证明。"

"形式化——不是让人完全懂——是让机器可以验证。如果后来者不懂——他们可以问机器。机器是我留给他们的中立方——不是我的断言——是机器可以重新计算的证明。"

两人在 unsafe 的边界上有不同的风格。沈见微的 unsafe 是给人读的——以人能理解的逻辑推导为基础。裴照川的 unsafe 是给机器验证的——以形式化工具为裁判。两个方向都试图让越过编译器保护的代码能被后来的维护者理解和验证。不是谁对谁错——是不同的传递方式。给不同时代的后来者留下不同形态的证明——人能读的注释和机器能跑的证明——在同一座仓库里可以共存。
