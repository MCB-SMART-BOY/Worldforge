# 明契卷 · 第08章附 · panic边界，什么时候该炸，什么时候不该

那面镜在跑完两个样本之后，安安静静地亮了整整两天的好光。

季循开始习惯一件事：每次 `check` 跑完，青炉要么把结果平整整地递出来，要么停在半路，递一个带名字的错误。他觉得自己终于不用再猜——不用猜到底是自己写坏了，还是样本本身不完整，还是系统在发谁也不知道的脾气。

然后第三天，他自己写的一段命文，又把镜子炸停了。

· · ·

事情是这样。

他已经能抬手就写出很干净的 `match`。该 `Some` 走 `Some`，该 `None` 走 `Err`。可那天下午，他试着把一段构建流程拆得更细，在中间写了一行小到不能再小的辅助函数。

那个函数只做一件事：从一份校验清单里找出目标版本的构建编号。他在写的时候心里想得很清楚——到了这一步，编号一定在。前面的检查已经把缺了的情况挡掉了。这里不可能空。绝对不会空。

他写完，按习惯敲了 `.unwrap()`。

镜面炸了。

不是真的炸。是那段熟悉的、生硬得好像从石缝里挤出来的红字又回来了：

`thread 'main' panicked at ...`

季循盯着那行字，这次不是困惑。

是恼怒。

不是因为镜子不通人情。

是因为他自己亲手把前面每一步都写好了——他知道这里不该空，也不会空。他只是在最确定的一步，顺手用了最快的方式说"我知道它不空"。

可镜子不认。

· · ·

苏野平过来了，看了一眼，笑了。

"你这回总算不是为了学新东西卡住。你这回是写了自以为对的东西，镜子偏说你对不起来。"

"可我知道它不空。"

"你知道。"苏野平说，"可镜子不知道。它又没跟着你把前面的三百行全读完。"

季循沉默了。

沈见微从门外进来，只看了一眼镜上的报错，就在他旁边坐下。

"你写这行的时候，心里想的是'这里绝不可能空'。"

"对。"

"可你把这事写在哪了？"

季循低头看那行 `.unwrap()`。它只说了四个字母——够短，够快。可它根本没说出"这里绝不可能空"这句话。它甚至比之前那版 `panic` 更哑。因为它连到底缺了什么都说不出。

"所以 `unwrap` 错在哪？"

"`unwrap` 没有错。"沈见微说，"它只是把一件本该写清楚的事，用最短的方式跳过去了。你心里知道这里不该空，可你没有把它写进代码里。等你走了，下一个碰这行的人——他得先把你三百行前面的检查全读一遍，才敢信这里真的不会空。"

他把那段命文改了一个词：

```rust
let build_id = manifest.build_id
    .expect("build_id must exist: validated upstream");
```

季循盯着那个 `expect`。

"这就够了？"

"它比 `unwrap` 多了一样东西：你把你为什么觉得这里不可能空的理由，写下来了。不是你脑子里的理由——是下一个读代码的人可以直接查证的理由。"

· · ·

闻衡就是这个时候进来的。

她把镜上那段回铃记录抄下来，压到长案上，又写了三行：

`unwrap`：我相信这里有——不加解释

`expect`：我相信这里有，因为——补一句理由

`match / ?`：我不假设这里有。空了我有路。

"这三种写法，没有哪一种一定错。"她说，"但你得知道，你在给后来者留下什么样的判断尺。"

苏野平皱眉。

"要是每一步都得写理由，命文会多出大量杂音。"

"对。所以你也要判断：什么情况下，一句 `expect` 就足够？什么情况下，你必须回到 `match`，替空的情况也把路铺好？"

闻衡把一张旧抄片推过来。那是卷首那夜事故里的一段旧钩子——调用的是一段已经在别处被改掉的接口。写它的人当时也 `unwrap` 了，因为他觉得"接口不可能变"。

"他也不是故意骗人。"闻衡说，"他只是没有把他那个'不可能'的前提写出来。后来者替他改了接口——他自己不知道自己在依赖一个不成立的前提。"

· · ·

季循翻开记事板，把他自己在青炉里用过 `.unwrap()` 的地方全部找出来。

不是三十二处。是不到十处。可他已经不敢肯定每一处都经得起后来者的拷问。

他一条一条往下看。

第一处：临时目录名从环境变量里取。确实有，前面检查过了——他补了句 `expect("WORKDIR must be set: enforced by env validator")`。

第二处：构建编号在清单里。也是前面验证过的——补了 `expect("build_id missing after validation pass")`。

到第三处，他停了。

那是一段读取下级说明的入口。他写的时候默认了"下级说明一定存在"，可他并没有在代码里做过任何验证。他只是觉得"当然应该有"。

他把 `.unwrap()` 删了，改成：

```rust
let child_manifest = match manifest.child {
    Some(child) => child,
    None => return Err(CheckError::MissingChildManifest),
};
```

改完以后，他在旁边注了一行：`此处未经验证——不应使用 unwrap。`

韩砺年从他身后经过，看见了这行注。

他停了一步。

"你刚才改的那一段，"他说，"北院旧壳里有一模一样的写法。用了七年。直到去年才被人炸掉。"

"是谁炸的？"

"一个新来的。他把那句 `unwrap` 当作'这里一定有'的承诺——然后他改动了上游，不知道下游在等。等他收到报错，镜上只有一句 `panicked`，连是什么炸的都没说清。"

"他后来查了多久？"

"一整夜。"韩砺年说，"最后他自己也没搞清楚到底是哪里缺了东西。他和我说——我以后再也不想碰这段了。"

季循低下头，把自己刚才补的那行 `expect` 重看了一遍。

不是因为它多了几个字。

是因为它可能让后来者少熬一整夜。

· · ·

到傍晚，裴照川来了。

他不是来检查命文的。他只是路过北院，顺便看看青炉的新进度。

可他看见季循笔记本上那行关于 `unwrap` 的注以后，在桌边站了很久。

季循不敢先出声。

裴照川这个人，平时话极少。可每次开口，都是在所有人最不想被戳到的地方精确地下刀。

"你知道 Rust 为什么把 `unwrap` 和 `expect` 分开吗？"

"因为一个不给理由，一个给理由。"

"不止。"裴照川说，"`unwrap` 其实是一种试探。它是在说——我觉得这里不可能空。`expect` 是一种承诺。它是在说——我敢替这里打包票，而且我把包票的内容写下来，让后来者自己判断我的票值不值得接着信。"

他看了一眼季循。

"你以前在没有 Rust 的世界里写命文，是不是也经常在心里替很多地方打过包票？"

"是。"

"那些包票后来都怎么样？"

季循想了想。有些还在。有些被时间悄悄地撕掉了——不是他自己撕的。是上游变了，下游跟着炸了，而那个"这里应该不空"的前提从来没有人写下来过。连他自己也忘了自己当年是凭什么打的包票。

"所以 `expect` 不只是文档。"裴照川说，"它是把不可见的前提变成可见的声明。写下来——不是为了求镜子原谅。是为了让你自己知道：你到底敢替哪一步负责。"

· · ·

天快黑了。闻衡把长案上那三行对比纸收进青炉文契的第三层。

`unwrap`：可以信——但先写清楚为什么信

`expect`：把"为什么"写在命文里，让后来者能查

`match / ?`：不确定就分岔。空有路。错有名。

她抬头看着屋里的人。

"以后，在北院写命文——"

"不许再用裸的 `unwrap`。"韩砺年先接了。他的声音不高，却像一把锈锁终于被从里向外顶开了最后一圈。

苏野平看了他一眼。

"连你也把这条路堵了？"

"不堵。"韩砺年说，"是讲清楚什么时候该走别的路。"

· · ·

沈见微把季循今天改的那段 `Match` 推到众人面前。

"这不是在惩罚写 `unwrap` 的人。这是在保护读它的人。"

他停了停。

"青炉的原则一直都是一样的：你得先把'可能会坏在哪'说清。真正让一根骨头摔断的，不是它本来就脆。是谁都觉得它不可能断，所以谁也没替它多留一步退路。"

季循翻开记事板。他在第八章那片"错误被说清的失守"下面，又添了今晚的这一句：

> **`panic` 不是罪。不写清楚'为什么不可能'的 `unwrap`，才是。**

窗外入夜，廊下最后几滴残雨顺着石缝渗下去，不再响了。

青炉的镜面上，季循今天改过的那段命文安安静静地亮着——没有 `unwrap`，没有 `panic`，只有一句清清楚楚的 `match`，和一条被补上名字的错误路径。

他不是在写一段更保险的命文。

他是在替未来的某个人，把那条或许会断的路提前画了出来。
