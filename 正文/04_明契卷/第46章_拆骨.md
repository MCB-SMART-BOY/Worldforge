# 明契卷 · 第46章 · 拆骨

沈见微把青炉从一个大 crate 拆成三个。`qinglu-core`——核心逻辑。`qinglu-build`——构建。`qinglu-report`——报告。

不是"我觉得太大了"——是"这些代码服务于不同的使用者，有不同的承诺周期，应该被分开。让变更独立，不影响无关的人"。程知序只需要 build——不需要 core，不需要 report。分开了他的依赖是明确的——不会因为 core 的变更被迫升级。

"拆分不是重构——是重新承诺。这个 crate 承诺什么、不承诺什么——独立于其他 crate。三个 crate 的版本各自独立——core 升级不影响 build 和 report。三个 crate 构建在一个 workspace 中共享同一个 Cargo.lock——依赖关系被锁定，但它们发布的承诺各自独立。以前改 core 的一行代码——build 莫名其妙编不过——因为 build 用了 core 的一个内部类型。现在 build 声明依赖 core 的公开 API——不是内部类型。pub 被重新审计——这一次拆分的过程就是重新审计每个模块的边界。"
