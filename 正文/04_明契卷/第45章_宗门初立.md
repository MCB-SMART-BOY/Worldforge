# 明契卷 · 第45章 · 宗门初立

沈见微把青炉从单个 crate 变成 workspace。多个 crate——各自有各自的承诺，但共享同一个 Cargo.lock、同一个构建目录、同一个版本空间。

"不是'合并代码'——是让 crate 之间的契约在同一个构建中被验证。crate A 承诺某个 API 版本——crate B 依赖同一版本——workspace 保证它们用的是同一个版本，不是'我以为'，是构建系统保证。workspace 让 crate 之间的依赖在同一个构建中被优化、被检查、被管理。编译一次所有 crate 一起跑——不兼容的版本在编译时就被发现，不等到运行时的凌晨。"

宗门初立——青炉从单个 crate 变成 workspace。多个 crate，各自有各自的承诺，但共享同一个"为什么"。不是组织架构——是契约的空间布局。每个 crate 有自己的 CI、自己能独立发布、有自己的版本号——但它们在一起构成了青炉的完整功能集。后来者打开 workspace 的 Cargo.toml 看到成员列表——就知道青炉由哪些模块组成，每个模块负责什么。
