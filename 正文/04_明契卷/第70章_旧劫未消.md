# 明契卷 · 第70章 · 旧劫未消

青炉 1.0 发布后第一个外部使用者报告了一个兼容问题——他的项目依赖了旧版本，升级到新版本后编译不过。MAJOR 版本确实变了——但变更内容不在 changelog 的任何 breaking change 描述中。

沈见微追查——发现是六个版本前的一个 trait bound 改了——当时以为是内部实现细节，没有标记为 breaking。但使用者在自己的代码中直接依赖了这个 trait bound。"我以为没人会用到那个 bound——但程知序的同事——在项目中写了一个泛型函数，依赖了那个 bound 的具体约束。我改了它——他的代码在升级时突然编不过。"

程知序在凌晨更新依赖的时候整个 crate 编译失败——几百个错误。本来应该是"更新了一个小版本——一切正常"。但一个未声明的 breaking change 让他的半夜变成了排查第三方依赖变更的半夜。"你的 changelog 没有写这行更改——因为它在一个不被注意的 PR 里被合了。changelog 不是'我记得的改动'——是'机器能从 git log 中提取的改动'。"
