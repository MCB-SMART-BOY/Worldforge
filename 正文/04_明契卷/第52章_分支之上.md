# 明契卷 · 第52章 · 分支之上

分支不是"分开做"——是"各自在自己的轨道上不互相阻碍，然后汇合。在汇合时检查两条路有没有撞"。Git 分支：feature branch → PR → review → merge。不是"主干是真理"——是"每条 branch 是一个假说，在 merge 时验证假说是否和主干不冲突"。

沈见微建青炉的 main 分支。每一条 feature 在自己的 branch 上开发、测试、闻衡审契后合并。"不是效率低——是让每个人在自己的节奏上不被别人打断。季循改配置在自己的 branch 上，苏野平写脚本在自己的 branch 上，程知序修 bug 在自己的 branch 上。三条分支独立推进——互不干扰。合并时在 PR 里交汇——如果冲突在 review 阶段被解决而不是在生产环境中爆炸。"

"旧的工具链没有分支——所有人在同一个目录里改代码，凌晨改了之后另一个人早上一打开发现自己的东西被覆盖了。分支不是让人分开做——是让人的独立性被保护。每个人在自己的 branch 上对自己的假设负责——merge 时再让两条路径对话。不是慢——是不让并行的人在凌晨撞上对方。"
