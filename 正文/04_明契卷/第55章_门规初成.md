# 明契卷 · 第55章 · 门规初成

闻衡写了 PR template 和 Conventional Commits 规范。commit message 格式——`feat:` 新功能，`fix:` 修 bug，`docs:` 文档，`refactor:` 重构，`test:` 测试，`chore:` 杂务。不是形式——是信号。让后来者扫一遍 log 就知道这个版本主要做了什么。

PR template——标题简短描述做了什么；描述为什么做、什么场景需要、怎么验证、影响了谁。不是"写得多"——是"让 reviewer 不需要猜"。之前 merge conflict 说两个人都做了对的事但没有告诉对方——PR 就是"在做之前——声明你要做什么"。不是做完了再告诉别人，是在做的过程中公开你的意图——别人看到 PR 标题就知道你正在改什么，他们如果也在改同一样东西会提前协调。

"不是审批——是告知。告知在代码合并之前、影响扩散之前、凌晨炸裂之前。这就像化形卷里的弃用声明在接口变更之前告诉所有依赖方——给你时间准备。PR 是变更的弃用声明——不声明就合并等于是偷袭。闻衡的门规不是限制——是让意图在实现之前被看见。"
