# 明契卷 · 第78章 · 收到传讯

纪承钧的传讯到了。不是指责——是"你的诊断报告 v0.3.1 在玄枢炸了"。

沈见微读第一遍的时候是困惑。报告本身是正确的——每一步：cargo-audit 全量审计、调用统计、风险等级、替代方案、免责声明。"未知依赖不在检查范围内"——他写了。每一个接口的废弃建议都附了青炉侧的数据——青炉侧调用为零的，标为可安全废弃。他在扉页写了"此报告基于青炉侧的可见依赖关系——请在使用任何建议前——在你那边确认你的依赖关系。"

但玄枢那边的确认——不是"查依赖注册表"——因为注册表在那个被删除的接口上不存在。那个接口的依赖——在六年前的 Makefile 注释里，在 Unix domain socket 上，在凌晨丑时的备份脚本里。不在任何注册表里。不在任何他能查到的数据里。他写了"未知依赖不在检查范围内"——但他不知道未知依赖有多大。他不知道未知依赖是一个在凌晨三点十七分搭的 hotfix——没有作者、没有文档、没有 git commit。

第二遍是恐惧。因为他做了所有前人做过的事——一份做了所有对的事的文档，在一个他不知道的语境里，炸了。梁故川清空记录板——因为怕写下来的东西成为墙。纪承钧的 runbook 炸了息壤——因为"确认所有下游依赖方已全部迁移"在息壤是不可执行的步骤。现在他自己——一份做了所有对的事的诊断报告——在玄枢炸了。他不是例外——他是链上的新一环。写清楚——在边界处断裂。

纪承钧在传讯结尾没有说"你错了"。他说的是——"继续。"

"我写这封传讯——不是让你停止。是让你继续——同时知道——'对的事——在不知道的语境里——是不够的事。'你的诊断报告——会去往其他地方。每一次——都可能在不同的语境下炸掉。不是因为你做得不够——是因为没有一个人——在所有的地方——都看得见。我们——都在——各自的——世界里——对的人——但——世界和世界之间——有人——站着——在看不到的地方——依赖着——你以为——没人在用的——东西。"

第三遍是理解。梁故川的恐惧是对的——写下来的东西会被当成真理。但他的回应是错的——不写，让后来者在黑暗里摸。不是不写——是写，同时写清楚前提。"我的诊断报告少了一行——不是'未知依赖不在检查范围内'——而是'在青炉，确认依赖的方式是查 Cargo.toml 和 crates.io。如果你的世界没有这些——请不用这个报告做删除决定。请先建立你的依赖声明制度。'——纪承钧教会了我这一行。"

沈见微在青炉记录板上写下："此报告——基于青炉侧的可见依赖。在玄枢——它炸了。伤痕在此——不删。后来者——如果你收到跨域 runbook 或诊断报告——先问——那个世界的前提——在你的世界成立吗。——前提可能不成立。——沈见微。"

韩砺年在远处看着。他看到了梁故川清空记录板那天——也看到了今天。同一个问题——写清楚在边界处会炸——两种回应。梁故川的沉默和沈见微的前提声明。同一条路——被两个人各自走了一遍。第一个人停在了断裂处——留下了"不文档化"三个字。第二个人也走到了断裂处——但他找到了纪承钧的传讯。不是因为他更强——是因为断裂处多了一行路标。路标不是第一人留的——是第一人停在了路标缺失的年代。
