# 明契卷 · 第63章 · unsafe 的契约

青炉需要调用一个 C 库来做特殊格式的解析——这是 FFI，必须用 `unsafe`。Rust 的 `unsafe` 不是"关闭编译器检查"——是"我在此处自负其责"。你在 unsafe 块内向编译器承诺："我已经验证了这里的操作满足 Rust 的所有安全要求——尽管编译器不能自动验证它。"编译器信任你的承诺——但这份承诺需要被写明。

沈见微在 unsafe 块旁边写了安全论证——不是注释，是一份文档解释为什么这个 FFI 调用是安全的。C 库的生命周期——谁分配内存，谁释放，在什么时候释放。参数类型——C 侧和 Rust 侧的对应关系，已逐条验证。并发安全性——该函数是线程安全的，可以跨线程调用。失败模式——如果 C 库返回 null，Rust 侧如何处理。"unsafe 不是禁区——是签字画押。你越过编译器保护边界——必须自己留下承诺和论证。不是'我认为它安全'——是'以下是基于什么验证它是安全的——在这个前提下。后来者——如果前提变了——请重新论证。'"
