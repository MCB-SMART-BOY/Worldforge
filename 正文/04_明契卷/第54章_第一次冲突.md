# 明契卷 · 第54章 · 第一次冲突

第一次 merge conflict。沈见微和季循各自改了同一段逻辑——各自都对，但合在一起不兼容。沈见微改了配置文件加了参数，季循改了同一个配置文件删了一个旧的。Git 不知道谁对——因为它不知道你们两个在做之前有没有通过气。

"我们没有聊——因为我们觉得'我们做的是分开的事'。但代码不是分开的——它在同一行。我们撞了。不是 Git 的错——是我们的错——没有在改之前告诉对方。"

merge conflict 是背契的工程表现——两个人都做了对的事，但没有互相告诉。各自在自己的 branch 上做了正确的判断——但判断相互冲突。契约不只是代码——是"我做之前告诉你会影响你"。Git 的冲突标注是制度在替人传话——不是挡墙，是信使：告诉两个人他们需要对话。之前玄枢的冲突没有制度——钟守玄改了某个变量，纪承钧也改了同一个变量——两个人第二天早上发现系统启动不了。"现在 Git 在 merge 的时候替他们对话：这里有两个版本——你们自己决定。"
