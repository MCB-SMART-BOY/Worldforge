# 明契卷 · 第49章 · 门规初稿

第一版门规——CONTRIBUTING.md——被贴在青炉记录板上。

所有 pub API 必须经过闻衡审契——通过的接口在文档首页标注审查人和审查日期。所有变更必须有 changelog——不只是"改了什么"，是"为什么改，影响谁"。所有错误处理必须区分可恢复和不可恢复——可恢复的错误给调用者处理空间，不可恢复的错误直接终止。所有 unsafe 代码必须附带安全论证——不是"这里用了 unsafe 因为需要性能"，是一份有逻辑推导的文档解释为什么在编译器保护范围之外的操作仍然是安全的。

不是沈见微说了算——是所有进入青炉的代码必须遵守这些规则。规则不是他定的——是闻衡和团队讨论的，基于事故的教训。季循的抽象陷阱、程知序凌晨翻源码找权限问题、顾迁衡的"临时"桥——每一个规则的背后都有一个具体的人在某天凌晨付出的代价。

"不是限制——是保护。保护使用者不被没写清楚的承诺伤害，保护维护者不被不知道影响的变更压倒。门规不是惩罚写错代码的人——是让写对的代码能清楚地传递到使用者。"
