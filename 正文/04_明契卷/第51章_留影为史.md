# 明契卷 · 第51章 · 留影为史

Git 不只是备份——commit 是因果秩序。每一次 commit 是"我在这个时间，基于这些原因，做了这个变更"。commit message 不是"修了 bug"——是"修了什么 bug，为什么存在，修了之后如何验证"。commit 是写下来的历史——后来者在 `git log` 里看到历史，不是看到"一堆代码改了"，是看到"为什么改"。

沈见微写青炉的第一个 commit。"此 commit 不完整——只包含 scope 和 Cargo.toml。后来者：接下来——每一行都会写'为什么'。不是代码的'为什么'——是决策的'为什么'。"

"旧的工具链中变更没有记录——每个脚本悄悄变，每个笔记独自存。Git 让变化从隐式变成显式——每个 commit 有作者、时间戳、diff、原因。后来者 `git blame` 一行代码能看到最原始的设计意图——不是猜，是读。好的 commit message 让后来者知道这个变更当时是为了什么、在什么条件下做的。如果条件变了——这个变更可能需要重新审视。"
