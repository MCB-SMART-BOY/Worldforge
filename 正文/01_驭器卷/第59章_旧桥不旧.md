# 驭器卷 · 第59章 · 旧桥不旧

卷六进入收束阶段。纪承钧把桥谱系表更新到了最终状态。

十七条桥。所有桥都被分析、分类、标注了代价。七条——可拆——其中四条 shim 已进入拆除窗口——一条 wrapper 已在拆除中——两条 adapter 在等待两边协调日期。三条——桥——被包裹——等待硬件升级或系统退役——各有退役条件和重评估周期。七条——暂时保留——有保留理由、保留期限、和续期后的重评估日期。

以前——桥是隐形的。北岭的人不知道自己走在桥上。协阵的人不知道 mid-layer 在转什么。渡桥司的登记册上只有四条。现在——每一条桥都有名字、类型、出生时间、出生原因、依赖方清单、代价评估、当前状态、和下一次重估日期。

"不是所有的桥都被拆了。"纪承钧在桥谱系表的最上面写了一段收束语。"但所有的桥都被记录了。这是第一阶段清理。未来——每一座新桥——搭的时候——必须在渡桥司登记——必须填退场日期——必须经过分类——必须标注——'拆除需要什么条件'。——桥——不是不被允许——是不再被允许——活在没有管理的地方。——纪承钧。"

· · ·

陆踏痕完成了最后一步——把桥谱系放入玄枢石录（version control）作为公共记录。不是放在接火阶梯的铁柜上——铁柜是工作工具——上面贴的粉笔字会褪色——纸会黄。石录——是玄枢的 Git 历史——是所有后来者——只要会 `git log`——就能找到的地方。

他在玄枢的公共仓库里建了一个文件——`docs/bridge-registry.md`。文件里是完整的桥谱系——十七条桥——每一条的完整记录。包括 Git 追溯、观测数据、代价评估、拆除或包裹方案、下一次重估日期。

第一次 commit。commit message：「桥谱系——十七条旧桥。第一卷。来自接火阶梯第三层。每条桥——都曾被叫做'临时'。现在——每条桥——都有了名字、出生证、和死亡证。——陆踏痕。——前提：基于纪承钧、顾迁舟、渡桥司季容、和玄枢十一年值班记录。——后来的后来者——请继续维护此文件。——桥谱系——不是完成的——是活的。——每条桥的退役——请在此记录。——每条新桥的出生——请在此登记。」

纪承钧看了 commit message——然后在旁边——用 `git notes` 加了一行。

"这是玄枢——第一次——不是用 Git 记录源代码——而是用 Git 记录——'桥的生命周期'。——石录——不只是版本控制——是——让桥的出生到退役——每一步——都能被后来者追溯。——追溯——不是考古——是——知道——'这座桥——为什么在这里——谁搭的——什么时候——可以拆。'——不是石录的原始设计——是石录的——被后来者发现的价值。——纪承钧。——前提：Git 之前的桥——历史不全——只有文件夹备份。——那些备份——仍在旧柜子里——待后来者——考古。"

· · ·

陆踏痕在桥谱系文件的最后——留了半页空白。在空白处——写了一行小字。

"接手的——你也写。——陆踏痕。"

然后他加了一句——"Git 之前的桥——历史不全。待后来者补充。——备份在旧柜第三层——文件夹'北岭-旧备份-勿删'。——如果后来者——在未来的考古中——找到了这些桥的更早历史——请补在此处。——不是一定要补。——是——如果你来了——翻到了——觉得——应该给后面的人留一条路的话。——留。——前提：那些备份的格式——可能已经打不开了。——如果打不开——不是你的问题。——是——时间——比文件格式——走得更远。"

写完——他把文件推送到玄枢的 Git 远程仓库。`git push`。十七条桥的历史——从玄枢深处的备份文件夹——从钟守玄私人的记忆——从渡桥司薄薄的登记册——从顾迁舟的桥账——从纪承钧的桥谱系——从陆踏痕的分析和代价表——现在——进了石录。石录——是玄枢所有代码的家——现在也是玄枢所有桥的家。

"桥和代码——在 Git 里——拥有同样的可见性。"陆踏痕在笔记上写道。"以前——桥活在 commit message 里——'临时——先搭上'——只有搭桥的人知道。现在——桥活在自己的文件里——每个后来者——`git log docs/bridge-registry.md`——都能看到——桥的出生——桥的退役——桥的代价——和每一代人——在桥的条目上——加的注释。——这不是代码。这是——记忆。"

· · ·

傍晚。钟守玄看了 `docs/bridge-registry.md` 的第一次 commit。他坐在旧石案前——屏幕上——是陆踏痕的 commit message 和纪承钧的 git note。

他翻了翻自己几十年前的私人日志。那些年——他独自记录玄枢的系统状态——从不用 Git——只写纸——因为纸不会被覆盖——但纸——只有他自己能看到。

"以前——桥的出生——在我脑子里。桥的死亡——在我脑子里。后来——出生在 commit message——死亡还是在我脑子里。"他把日志翻到最早的那一页——"从今天开始——所有决策——记在脑子里——不写。"

在那行字旁边——他画了第三条横线。然后在横线下面——加了一行。

"现在——桥的出生和死亡——都在石录里。石录——不只是工具——是——让记忆——活在一个——任何后来者——都能找到的地方。——不是我的脑子。——是——'git log'。——钟守玄。——前提：此判断——基于陆踏痕的桥谱系提交。——可能——未来的记录工具——比 Git 更好。——届时——请迁移。——迁移时——保留——'接手的——你也写'——那条——被传了几十年的——话。"

· · ·

那天晚上。纪承钧在值守卫室——看着铁柜上的桥谱系格子。格子已经分成了三层。

最上层——桥谱系表——十七条桥——每一条的状态。中间——拆除 checklist——按类型——shim / adapter / façade / bridge / 包裹中——每种——有步骤。最下层——代价表——三百七十次——注意力、时间、信任——被静默消耗的代价。

他拿起粉笔。在铁柜上——在格子旁边——写了一行。

"旧桥不旧。——不是因为桥年轻——是因为——桥的生命——被记录之后——就不再只是过去的负担——而是——'曾经被搭过——后来被拆了——这里——是它来过——和它离开——的记录。'——桥可以被拆除——但'临时方案的生命周期'——是后来者要永远面对的问题。不是技术问题——是人的问题。——'临时'——是希望的别名。——管理——是让希望——不至于变成谎言的——方法。"

· · ·

卷六接近尾声。第一阶段清理——七条桥开始拆——三条被包裹——七条暂时保留。桥的出生证和死亡证——在渡桥司的制度里——在玄枢的石录里——在接火阶梯的铁柜上——在顾迁舟从化形卷带来的桥账模板里——被记录——被看见——被管理。

但更深的问题——在收束中浮现出来。桥是连接——是静态结构。桥上的东西——数据在流动——资源在被消耗——错误在传播——这些——是运行时的——动态的——还没有被看见。

"桥我们已经能看见了。"沈照痕在观测台前——看着北岭 wrapper 拆除中的实时数据——说了一句。"但桥上的东西——在运行的时候——发生了什么——我们还看不见。先照后立——不照清楚——修什么都是在修纸墙。"

纪承钧点了点头。卷七的方向——观测体系——"先照后立"——已经在地平线上。

但今晚——他只是站在铁柜前——看着桥谱系——看着那十七条曾经叫"临时"的桥——现在——每一条——都有了一个确定的、被记录的未来。

不是所有桥都被拆了。但所有桥——都从遗忘里——被捞了出来。

"旧桥——不旧。"他小声重复了一遍——然后熄了值守卫室的灯。

窗外——玄枢的散热塔在夜色中安静地转。北岭的设备灯光——在wrapper拆除的窗口期里——依然稳定地闪烁。十七座桥——在 Git 的石录里——在渡桥司的登记册上——在接火阶梯的铁柜中——终于——可见。
