# 驭器卷 · 第77章 · 追查三个时辰

火托住后——追查开始。

不是追"为什么断"——那个已经知道了——legacy-report-gateway 被删——北岭丑时备份系统——调用失败——连锁反应。要追的是——"为什么——北岭——有一条——在任何地方——都不可见——的调用——在丑时——存在了六年——而——没有任何人——知道。"

纪承钧、沈照痕、陆踏痕——三个人——从凌晨四点——追到天光大亮。不是追一个 bug——是追——一条信息——在时间——和——交接——中——如何——从'有人知道'——变成——'没有人知道'——变成——'连自己不知道——都不知道'。

· · ·

第一步——追 Makefile 中的那行注释。

"# 临时——北岭每日丑时报表——等新系统上线后删"——作者——六年前——一个早已离开玄枢的名字——姓卢——在玄枢做了两年——主要负责北岭侧的集成。他的 commit 记录——共二十一次——大多数是——"临时——北岭——先跑"——"修复——北岭格式"——"同上"。

那行注释——写在他最后一次 commit 里。他当时——在北岭和玄枢之间——搭了这条 Unix domain socket 通道——因为——"HTTP 请求——在北岭的旧系统上——不支持——走本地 socket——最简单。——等新报表系统上线——这条通道就不需要了。"——三年后——新报表系统上线——但——没有人——通知——玄枢——"旧通道——不需要了。"——新系统——走了新接口——旧通道——没有调用方——在 HTTP 和 RPC 的层面上——为零——但——那个 Makefile——中的编译开关——没有被关——那个本地 socket——每晚——丑时——仍然——静默地——在文件系统上——监听——因为——没有人——知道——它——在监听。连——写它的那个人——离职时——交接文档里——没有——这一条。

"交接文档——写了所有'接口'——但没有写——'这个 Makefile 里的开关——控制着——一个——不走网络——只在本机文件系统上——监听丑时请求——的 socket。——因为——在写交接文档的人看来——那不是接口——是——构建配置。——构建配置——不在接口交接清单上。——这是一个——分类——失误——不是因为粗心——是因为——'接口'——被定义在——'文档化的入口'——但——实际的——数据入口——是——所有——能——从外面——到达——玄枢内部——的路径。——包括——构建配置里——打开的那一条。"

· · ·

第二步——追北岭为什么不知道。

秦叔平——被叫醒时——是凌晨两点——他花了一个多小时——追到了——北岭那边——失联的备份服务器——在丑时——没有收到数据——静默退出——没有报错——因为——备份脚本——是一个 shell 脚本——`curl --silent`——静默模式——连接失败——返回空——脚本——把空——当成——"今天没有新数据"——存进了备份目录——然后——正常退出。

"这个——`curl --silent` ——是六年前的人写的——他的理由——是——'如果连不上——说明玄枢在维护——不要报错——安静跳过。——明天再试。'"秦叔平的声音——通过传讯——很累。"他——想的是对的——玄枢维护——确实——偶尔——会有维护窗口——在丑时——但是——他把——'连不上'——和——'正常维护'——划了等号。——这个等号——在当年——大概率——是对的——因为——那时候——玄枢的维护窗口——确实——在丑时——而且——接口——一直在。——所以——'连不上'——唯一的可能——就是——'在维护'。——但是今天——'连不上'——是——'接口不存在了。'——他的脚本——无法区分——'不存在'——和——'在维护'——因为——`curl --silent`——不给区分。——而——六年——没有人——更新过这个脚本——因为——它——'一直在跑。'"

· · ·

第三步——追沈见微的报告——为什么——零调用——三年——是——准确的——但——不够。

"青炉侧——零。"沈照痕在观测面板上——把青炉那边——传过来的——诊断报告附录——数据源——重新——读了一遍。"Cargo-audit——检查的是——Cargo.toml 中声明的依赖——和——Rust 侧的 FFI 接口。Legacy-report-gateway ——在玄枢侧——是一个——C++ 编译开关——控制——一个——Unix domain socket。——它不在任何——Cargo.toml——不在任何——静态链接库——不在任何——可以通过——依赖分析——自动发现——的地方。"

"沈见微——用了——他能用的——最好的工具——在——他能访问到的——数据——范围内——做对了所有事。但——'他能访问到的数据'——和——'玄枢实际在跑的数据'——之间的空白——是——由——技术栈的差异——历史的沉积——和——信息——在两个世界之间——无法——自动同步——造成的。——不是他的工具不对——是——工具——无法跨过一个——'构建配置里的编译开关——控制——一个——本地 socket——被——一个 shell 脚本中的 `curl --silent`——静默调用'——这样的——链条。——这不是工具的问题——是——复杂性——超出了——任何——单一工具——的——采集范围。"

· · ·

天光大亮时——纪承钧把完整的事故因果链（incident causality chain）——画成了一张图。

从青炉——沈见微的 `cargo-audit`——标注——"可安全废弃"——到——玄枢——"观测面板——零"——"合理判断——删除"——到——Makefile——六年前注释——编译开关——打开——`legacy-report-gateway` 的本地 socket——到——北岭——`curl --silent` 脚本——静默模式——"连不上——=——在维护"——到——丑时——调用失败——静默退出——空文件——备份未被生成——然后——北岭调用——失败——牵连——wrapper——适配层——信号码转发——协阵——连锁——从一层——传播到另一层——像推倒了一排——多米诺——每一块——都是纸做的——然后——一个凌晨——一座你不知道的城——在你拆一座你知道的桥时——塌了。

"每一个环节——都是'当时不知道'。"他在图下面写道。"不知道 Makefile 里有一个开关——不知道开关控制着一个 socket——不知道 socket 被一个静默脚本调用——不知道脚本把'不存在'当成'在维护'。——不是某一个人的不知道——是——整个系统——没有——让——这些'不知道'——变得——可见——的——机制。"

沈照痕看着这张图——然后——说了一句——不是总结——是——判断。

"沈见微——做了所有对的事。他的标注——免责声明——都是对的。他唯一不知道的——是他不知道的那些事。而那些事——在我们这边。——这不是他的错。——但——这封诊断报告——会去往其他地方。每一次——都可能——在不同的语境下——炸掉。——不是因为他做得不够——是因为——没有一个——单一的——位置——能让人看到——所有——语境。——永远有——你不知道的——那边。——'对的事'——在不知道的语境里——是——不够的事。——不是——'不要做对的事'——是——'做对的事——并——知道——你可能——不够。'"
