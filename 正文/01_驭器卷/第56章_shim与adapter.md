# 驭器卷 · 第56章 · shim 与 adapter

陆踏痕发现一个问题——不是所有桥都应该用同样的方法拆。

北岭-wrapper 的拆除方案——迁移指南、窗口期、通知用户——是一套完整的流程。但当他把同一套流程应用到协阵-shim 上时——发现不对。shim 的调用方只有一个——协阵旧子阵——而且调用路径很简单——只是信号码转发的薄层。用 wrapper 级别的迁移流程——是杀鸡用牛刀。

"不是所有桥都像 wrapper 那么重。"陆踏痕在笔记上画了一个表。"有些桥是薄片——替换调用路径就行。有些桥是厚层——两边都要改。拆桥的方法——应该按桥的类型来——不是按'桥'这个泛称。"

他把这个发现告诉纪承钧。纪承钧正在看桥谱系表上的桥分类——那些从顾迁舟那学来的类型——wrapper / adapter / shim / bridge / façade——每一类桥的结构性脆弱不同。

"顾迁舟的分类——是用来看桥的——不是为了拆桥。拆桥需要另一套分类——按拆除难度和影响范围——不是按结构。"

"那我们自己分。"

· · ·

他们花了三天——把十七条桥按拆除难度重新分类。

第一类——shim（薄垫层）——只做简单的格式转换或路由转发。调用路径单一。替换成本低。这类桥——只需要确认调用方的数据格式——建一条直接路径——然后移除 shim。拆除周期：一周。桥谱系中有四条。

第二类——adapter（适配器）——连接两边不同的接口。Adapter 不只是转发——是在两种不同的数据格式、调用约定、或协议之间做翻译。拆 adapter——需要两边同时升级——确认两边的数据格式差异——在两边各自实现原生支持——然后移除 adapter。拆除周期：至少一个月——因为两边需要协调。桥谱系中有五条。

第三类——façade（外观层）——不是连接外部系统——而是简化内部接口。Façade 把复杂的内部调用链包成一个简单入口。拆 façade——不是建新路——是让调用方理解 façade 后面的复杂逻辑——然后自己选择需要的部分。拆除周期：不确定——取决于调用方对复杂性的接受程度。桥谱系中有三条。

第四类——bridge（系统桥）——连接两个独立运行的系统——各自有自己的生命周期、升级节奏、维护团队。这类桥——不能单方面拆——要先建新桥——让新桥和旧桥并行运行一段时间——等调用方全部迁移到新桥——旧桥才能退役。拆除周期：至少三个月——如果有硬件依赖——可能需要几年。桥谱系中有五条——包括北岭-wrapper——它的 Fortran 底层连接着第三时代的北岭硬件。

"同一个名字——'桥'——底下是完全不同的东西。"陆踏痕在分类表上写了一行。"shim——薄到可以一周内消失。bridge——厚到需要几年才能退役。以前我们不管——所有桥都用同样的方式对待——'先搭上——回头再说'。现在——至少——搭的时候——你知道——你在搭的是哪一类。拆的时候——你知道——该用多长的时间。"

· · ·

他为每类桥写了一份拆除 checklist（dismantling checklist）。

Shim 拆除 checklist——"确认调用方数据格式。确认 shim 是否做了隐式转换（implicit conversion）——如果有——先让调用方显式处理。建直接调用路径。测试一周。移除 shim。"

Adapter 拆除 checklist——"记录 adapter 两边的数据格式差异（data format mapping）。通知两边维护者。确定统一日期——两边同时升级。升级后——并行运行两周——确认无静默失败（silent failure）。移除 adapter。"

Façade 拆除 checklist——"记录 façade 后面封装的调用链。提供内部调用链的直接入口文档。通知调用方——façade 将在 X 日期后不再维护。调用方可选择——直接调用内部接口——或保留自己的本地 façade——但不再依赖玄枢的中间层。移除 façade。"

Bridge 拆除 checklist——"建新桥（new bridge）——提供现代接口。新桥与旧桥并行运行——至少三个月。通知所有依赖方。确认所有调用方已迁移到新桥。确认旧桥无残留调用。退役旧桥。"

四份 checklist。每份一页纸。放在接火阶梯铁柜的桥谱系旁边——wrapper 审计 checklist 的下面。

纪承钧看了之后——在每份 checklist 的末尾加了一行——"前提：以上步骤基于桥谱系中已分析的桥。新桥——或未分析的桥——可能需要不同的步骤。请在拆除前——先独立分析。——'先照后立'——也是拆桥的前提。"

· · ·

钟守玄看到了这些 checklist。他从值守卫室走出来——手里还端着他的白开水——站在铁柜前——一页一页翻。

翻完之后——他把杯子放在铁柜顶上。

"以前——拆桥靠一个人说——'这个可以拆'。那个人——以前只有我。我不能说太多'可以拆'——因为每一次——'可以拆'——意味着我要承担拆错了的全部后果。如果桥断了——没有人能接——只能我接。所以我说'备着'。不是说桥不该拆——是说——我一个人——拆不起。"

"现在——你把这些——拆桥的方法——写成了 checklist。不是写给我——是写给任何一个需要拆桥的人。'这类桥——这样拆。先做这些检查。确认这些前提。然后——如果出问题——回到这些步骤——找你在哪个前提上出了错。'——你把我一个人扛的——拆桥的判断——变成了一份可以被验证的流程。"

他在 shim 的 checklist 上——用手指点了一下。

"这个——不是技术文档。是——'你不需要是我——也能拆——只要你会用这份 checklist——和接火阶梯上的工具。'——这是——传。"

· · ·

傍晚。陆踏痕在笔记本上写了一行。

"桥的类型——决定了它该怎样被拆。以前没有分类——因为以前只有一种桥——'临时的'。'临时'不是类型——是不愿面对。现在——shim / adapter / façade / bridge——每一种——有自己的结构——自己的脆弱——自己的拆除节奏。——知道桥是什么类型——才知道拆它的正确方法。——陆踏痕。——前提：分类基于十七条桥的分析。——后来的桥——可能有新的类型。——请补充。"

在他旁边——纪承钧在接火阶梯铁柜的桥谱系格子旁边——加了一行粉笔字。

"不是所有桥都该用同样的方法拆。不是所有桥都该用同样的时间拆。不是所有桥都该拆。——但所有桥——都该被知道——它是什么——它连着谁——它什么时候——到站。——纪承钧。"

卷六的桥——从看不见——到看见——到分类——到每一种类型都有了自己的拆除方法。桥谱系——不只是一张表。是一套——让后来者——不需要重新发明"怎么拆桥"的——工具。

章末。陆踏痕在桥谱系表的最下面——在纪承钧那行"接手的——你也写"旁边——加了一句。

"接手的——桥的类型——可能比我今天分类的更多。请补充。——陆踏痕。——前提：分类——不是完成——是开了一扇——让后来者继续分的——门。"
