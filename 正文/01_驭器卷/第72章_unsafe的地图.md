# 驭器卷 · 第72章 · unsafe 的地图

纸墙报告出来后——纪承钧决定绘制一张地图——不是桥的地图——是 unsafe（不安全边界）的地图。

在 C++ 的世界里——unsafe 没有关键字。Rust 有——`unsafe` 关键字——强制标注——任何越过编译器保护边界的地方——必须显式声明——"此处——自负其责。"——C++ 没有这种机制。所有 unsafe ——都是隐式的——藏在裸指针（raw pointer）——藏在手工内存管理（manual memory management）——藏在 FFI（foreign function interface）——藏在 `reinterpret_cast`——藏在——看起来正常——但恰好——做了不安全的事——的——任何一行代码里。

"我们需要知道——玄枢——有多少 unsafe 边界——在哪——多老了——在什么条件下——可能炸。"纪承钧对陆踏痕说。"不是要消灭它们——消除 C++ 的所有 unsafe ——不现实。——是——让后来者——在踩进雷区之前——能看见地图。"

"像桥谱系——但是——是——被隐式标注的——不安全地带。"

"对。桥——是连接。unsafe 边界——是——断层。程序在这里——从安全的一侧——跨到不安全的一侧——编译器不再保护你——之后的每一行——都需要你自己——证明——安全。"

· · ·

陆踏痕用观测工具——从 sanitizer 的三千条报告里——找出所有涉及 unsafe 操作的条目。不是所有报告——只有那些——涉及裸指针——涉及跨语言调用——涉及手工内存管理的。然后他逐条追溯源码——每一个 unsafe 操作——是谁写的——什么时候写的——在什么上下文里。

三天。他找到了四十三处 unsafe 边界。不是四十三处 bug——是——四十三处——程序员越过了 C++ 编译器的保护边界——靠自己——保证安全——而没有留下任何——"此处——我——自负其责"——的标注。

最深的一处——一个 FFI 调用——跨了三个语言边界——C++ → C → Fortran → 硬件接口。

"这一处——在这一层——C++ 的 `std::string`——被转成——C 的 `char*`——然后——在一层 C 绑定里——被转成——Fortran 的 `CHARACTER`——最后——送到硬件接口——一个第三时代的帧编码器。——每一层——都假设下一层——是安全的。没有一层——验证过——因为——验证——需要同时理解——C++ 的内存模型——C 的 ABI——Fortran 的字符串布局——和硬件的帧格式。"

"这种人在玄枢——存在过——但已不在了。"

钟守玄走过来——看着那个 FFI 调用链。"那个 Fortran 库——在卫千枢来之前就有了。我问过——'为什么用 Fortran？'——回答是——'因为当时只有 Fortran 能算这个。'——那是——创始者的时代——在 C++ 之前。"

"所以——这个 unsafe 边界——比玄枢的 C++ 道统——更老。"

"对。它是最初用 Fortran 写的——后来——有人用 C 包了一层——再后来——用一个 C++ wrapper 包了 C 的那层。三层——三个语言——三个时代——每一层——都假设——前一层——是对的。三层——都是对的——但'对'——是建立在——每一个假设——都成立——的前提下。前提——没有人记录过。——因为——在每一层被加上的时候——加的人——只了解——自己那层——和——相邻的一层。——没有人——从上到下——看过整条链。——这条链——不是设计出来的——是——一层一层——贴上去的——像——纸墙——贴在纸墙上。"

· · ·

纪承钧把四十三处 unsafe 边界——画成了一张地图。不是地理位置的地图——是代码结构的拓扑图——每一条 unsafe 边界——标注着——类型——语言边界——年代——已知的假设——和——在 sanitizer 报告中——是否被标记过。

地图上——最老的那条——就是 Fortran 调用链——十二年——在最深处——像一条——从旧核最底层——贯穿到玄枢表面的——竖井。最危险的那条——北岭-wrapper——十一年——被标注了五次——因为它的隐式假设——被打破的频率——比任何其他 unsafe 都高。最新——陆踏痕在 shim 分类时写的那条——转换函数——本来是安全的——但他在合并重复实现时——留下了一个裸指针——在协阵旧子阵不再使用后被释放——但 shim 的另一个分支——偶尔——仍然会访问它。

不是故意 unsafe ——是——在 C++ 里——安全——需要持续的关注——而——在一代代的维护中——关注——可能被转移——然后——曾经安全的代码——在新的上下文里——变得不安全——而没有人——注意到。

"unsafe 的地图——不是用来消除 unsafe 的。在 C++ 里——消除所有 unsafe——是不可能的——因为——C++ 本身就是一种允许 unsafe 的语言。"他在 map 的最上面——写了标注。"这张地图——是让后来者知道——'此处——你越过了编译器能保护你的边界。——此处——需要额外的谨慎。——此处——在你修改任何东西之前——先验证——那些——依赖隐式假设的——在代码里没有被写下来的前提——仍然成立。'——unsafe——不是错误——是——需要注明的——责任。在 Rust 里——`unsafe` 关键字——就是这种注明。在 C++ 里——我们没有关键字——但我们有——地图。——地图——是我们后来加上的——关键字。——纪承钧。——前提：这些 unsafe 边界——基于当前源码。——新代码——可能引入新的 unsafe。——请后来者——更新此地图——标注——你发现的——新的 unsafe——和——你加固的——旧的 unsafe。"

· · ·

那天晚上。钟守玄看着 unsafe 地图——他的手指——在 Fortran 那条最老的边界上停住了。

"这条——一直在我的'感觉'里。几十年来——每次断火——我都会查它——因为我知道——它——不属于任何一层——它——穿过了所有层——从 Fortran——到 C——到 C++——到——硬件。——每一层——都可能——误解——上一层——传下来的东西。我以前查它——靠的是——经验——和——直觉。——现在——它在地图上。后来者——不需要有我的经验和直觉——也能知道——'此处——危险。'——危险——不是被解决了——是——被标注了。——标注——不减少危险——但——减少——'不知道的危险'。——不知道的危险——才是最危险的。"

他在 map 旁边——用铅笔——在 Fortran 那条边界上——画了一个很轻的圈。然后在圈旁边——写了一段——"此 unsafe 边界——比四道更老。——在被看见之前——它只是——恰好——不出事。——现在——它被看见了。——看见——是——管理的前提。——后来者——如果你加固了它——请标注——'钟师——那时候——它是在地图上——但还未被加固。——我——现在——加固了。——用——什么方法——在——什么前提下。'——钟守玄。——前提：加固——可能——改变它的行为——请在加固后——重新观测——并通知——北岭——和——所有——在它上面的——桥。"
