# 驭器卷 · 第35章 · 平台矩阵

纪承钧试图在第二个平台上构建玄枢，是因为苏野平的一句话。

苏野平离开前提到过——"明契的构建——在 Linux、macOS、Windows 上——行为一样。因为 Cargo 从第一天就抽象了平台差异（`platform abstraction`）。你们的玄枢——从来没有被要求过——在第二个平台上跑。"

从来没有。玄枢从第一天起就在 Linux 上。不是特意选的——是那时候只有 Linux。十几年来，所有外部调用方都在 Linux 上。没有人提出过跨平台的需求——因为不需要。

但苏野平说了那句话之后，纪承钧一直在想。他找了一台闲置的旧机器——macOS——装了工具链，把玄枢的源码拷过去。跑 `make`。

编译失败了。不是预想中的那种失败——不是缺依赖、不是缺头文件、不是编译器版本不对。是链接阶段——一个结构体的大小——在 Linux 上是 24 字节——在 macOS 上是 32 字节。多了 8 字节。因为两个平台对结构体内部的填充（`padding`）规则不同。一个隐式的类型转换——在 Linux 上因为填充刚好对齐——正常工作。在 macOS 上——填充不同——转换悄悄地截断了数据。没有编译错误。没有警告。只是行为——不一样。

"这是 ABI 差异（`Application Binary Interface`）。"沈照痕站在他身后。"不是 bug——是两个平台对同一个标准的实现——有微妙的差异。你在 Linux 上写的代码——假设了 Linux 的 ABI。那个假设——从来没有被声明过。因为从来没有人想过——玄枢需要在别的平台上跑。"

"所以默认值——"

"默认值是——Linux。而'默认'——当环境变了——就是错误。"

· · ·

纪承钧花了三天，把玄枢所有的平台敏感代码过了一遍。不是改——是标记。每一个隐式的 ABI 假设：结构体布局依赖、调用约定（`calling convention`）、类型大小假设、字节序（`endianness`）依赖。他标记了十几处。每一处旁边写："此代码假设 Linux ABI。——在非 Linux 平台上行为未验证。"

然后他画出玄枢的平台矩阵（`platform matrix`）。

七个平台。三个编译器版本。二十一种组合。其中六种组合标注了"已验证"——都是在 Linux 上的。一种标注了"已发现差异"——是那台 macOS 机器上的。剩下的——十五种——标注了"未知"。

"不是不能测——"沈照痕看着那张矩阵，"——是不知道哪些组合在被使用。玄枢的外部调用方——他们可能在任何一个平台上跑。但他们在调用玄枢的时候——从来不声明自己的平台。因为在他们看来——玄枢是一个服务——不是一个库。服务的内部行为——不应该因为调用方的平台而变。"

"但玄枢不是服务。"纪承钧说。"玄枢是库。调用方在链接玄枢的产物——在自己的机器上——用自己的编译器——用自己的 ABI。我们一直以为——能跑——就够了。"

他把平台矩阵贴在铁柜上。在旁边加了一行：

"平台矩阵——第一版。二十一种组合中——六种已验证——十五种未知。未知的——不是不危险——是不知道有多危险。——后来者——如果你在非 Linux 平台上调用玄枢——以下是你需要知道的平台差异。以及——我们标记的——我们不知道的。——前提：此矩阵基于当前工具链版本。如果外部调用方升级了编译器——此矩阵需要重新验证。"

· · ·

陆踏痕是这个矩阵的第一个使用者。他在自己的笔记本上抄了一份，然后在旁边写了分析——关于为什么 ABI 差异在今天之前没有被发现。

"玄枢的外部调用方——大多数在 Linux 上。那些不在 Linux 上的——他们自己做了适配——但他们没有把适配反馈给玄枢。因为他们觉得——'玄枢不支持其他平台——我得自己搞定'。他们搞定了——但他们的搞定——变成了一种隐式的、只在他们那边存在的知识。玄枢不知道自己的代码被怎样使用——所以玄枢不知道自己的代码——在那些平台上——是什么样的。"

他停了一下——然后加了一条前提：

"前提：以上——基于一台 macOS 的测试。——只是二十一种组合中的一种。其他十四种——未知。——这意味着——可能有外部调用方——在某个未知的平台上——已经自己适应了玄枢的 ABI 差异——而玄枢不知道。当玄枢有一天主动修复这些差异的时候——他们的适应——会变成不兼容。——隐式的兼容——是两个方向的。不只是玄枢适应平台——调用方也在适应玄枢。双方都在适应——但双方都不知道对方在适应什么。后来者——如果你要修 ABI——不只是告诉调用方。是去问调用方——'你们已经修了什么——我们不知道'。——陆踏痕。"

· · ·

那天深夜，钟守玄在平台矩阵前站了很久。

"我们把'能跑'当成了'正确'。"他说。声音比平时更沉。像在说一个很久以前就该承认的事实。

"不是因为我们不想跨平台测试。是因为那时候——跨平台不是需求。外部调用方只有一个——就是协阵扩域。协阵扩域在 Linux 上。所以——够了。后来——变得更多调用方——更杂的平台——我们没有更新我们的假设。因为我们一直——在用旧时代的思维——维护一个早已不是旧时代规模的系统。"

他看着那十五个"未知"。

"这些未知——不是我一个人的未知。是整个玄枢的未知。因为如果有一个人在凌晨——在他们那边——在玄枢不知道的平台上——玄枢的行为不对——他们不会找我们。他们会自己修。修完之后——他们的修复——在他们那边的环境里——是一个补丁。他们不会发回来。因为发回来——就要解释——为什么他们在用玄枢不支持的方式。解释——很麻烦。所以他们的补丁——留在他们那边。下一次玄枢升级——他们的补丁可能失效。然后——又是凌晨。"

他停了。然后转身对着纪承钧。

"你画这张矩阵——不只是给后来的维护者的。是给那些——在凌晨——在自己那边修了——但从来没有发回来的人。告诉他们——'我们不知道——但我们在问——请告诉我们——你那边——是什么样子的。'"

然后他从铁柜上拿起粉笔——第一次——在那些"未知"旁边加了一行字。不是注释。是一句话：

"如果你在凌晨修过——请告诉我们。不是替我们修——是告诉我们——我们不知道你的平台。——钟守玄"

他把粉笔放回去。

粉笔灰从他手上落下来——和之前纪承钧、陆踏痕、沈照痕留下的——混在一起。那些字——在铁柜上——有一种旧石板上粉笔字特有的灰白——不刺眼——但擦不掉。除非有人特意来擦。但在玄枢——没有人会擦这些。

在玄枢——不擦——就是承认。
