# 驭器卷 · 第44章 · RAII 的哲学

陆踏痕在分析钟守玄的诊断脚本时，注意到了一个模式。不是代码层面的——是逻辑层面的。每一条诊断命令都遵循同样的三步结构：检查（`check`）→ 修改（`modify`）→ 恢复（`restore`）。检查当前状态。做一个临时的修改——比如改一个配置参数，看看下游的响应有没有变化。然后把配置参数改回原状。如果脚本在中途被 Ctrl-C 中断——恢复步骤仍然会被执行。

"这个——放在最前面——"

他指给纪承钧看——在钟守玄的一个诊断脚本的开头，有一行 `trap cleanup EXIT`。这是一条 shell 命令。意思是——无论这个脚本是正常结束还是被中断——在退出之前——都要执行 `cleanup` 函数。`cleanup` 里是一组恢复操作——把所有临时改掉的配置恢复原状。

"获取了资源。使用。然后——归还。不管中间发生什么——归还。"陆踏痕说。"这不是 shell 的写法——这是 C++ 的。"

纪承钧看着那行 `trap`。

"RAII。"他说。"Resource Acquisition Is Initialization——资源获取即初始化。C++ 的核心哲学之一。在 C++ 里——你用构造函数获取资源——用析构函数（`destructor`）归还。析构函数在作用域结束时自动调用——不管你是正常返回——还是异常抛出。'归还'是必然的——不是'记住'——是'不可能忘'。"

"钟师是 C 时代过来的人——他为什么会在 shell 脚本里写 RAII？"

"因为几十年的经验告诉他——'记得归还'是不可靠的。每一次凌晨——他可能被事故打断。他可能修到一半——另一个更紧急的事故来了——他必须立刻切过去。如果他的诊断脚本没有 `trap`——那些临时修改——就会被留在系统里——成为下一个事故的根因。他不是在用 shell——他是在用 RAII 的思维——写 shell。"

· · ·

那天下午，纪承钧给陆踏痕讲了玄枢早期的一个内存泄漏（`memory leak`）故事。

几十年前。玄枢的一个外部接口模块——每年泄漏大约 2MB 的内存。不是一次性泄漏——是每次调用漏几个字节。很小的泄漏。因为"不重要"——没有人在意。等到发现的时候——那个模块已经累计泄漏了超过两百 MB 的内存——占了玄枢总内存的相当大一部分。找到根因的人——是钟守玄。那时候他还年轻。

"原因是什么？"

"原因很简单。那个模块在异常路径（`exception path`）上——有一个提前 return——没有释放一块手动分配的内存。正常路径上有释放——异常路径上没有。如果用了 RAII——把内存包在 `unique_ptr`（`独占所有权智能指针`）里——析构函数会自动释放——不需要每次 return 都记住。——但那个模块——写得比 RAII 的出现还早。那时候——手动管理内存——是唯一的选项——而手动——意味着——有些路径——你会忘记。"

"所以 RAII——不只是技术。"

"不只是。它是一种伦理。"纪承钧说。"你获取了东西——你就要承诺——在什么时候归还。不是'应该'——是'必然'。析构函数的调用——不是人的纪律——是编译器的纪律。编译器不会忘。人——会。不是不够好——是人在凌晨——在面对多重紧急事件——在被叫醒三次之后——会忘。所以——好的工程——不是让人记住——是让编译器——让人不可能忘。这就是 RAII——不是语法——是伦理。获取的东西——必须有一个明确的、自动的、不依赖于人的归还时刻。"

陆踏痕在笔记本上写了很长的一段。然后他停了一下——

"那知识呢？"

"什么？"

"你获取了知识——你什么时候还？"

纪承钧看着他。

"你把玄枢的旧代码考古了一遍。你获取了那些旧骨的知识——那些'为什么'——那些隐式依赖。你什么时候还？怎么还？不是靠析构函数——编译器不能替你还知识。是靠——你写的翻译。你贴在铁柜上的那些前提标注。你的笔记本——最后一页——留给后来者的空白。"

陆踏痕点点头。然后他翻开笔记本到最后一页——那页只有最上面一行——"以上所有——基于今日之我所知。今日之外——待后来者"——在下面加了一段：

"知识的 RAII。获取——理解——然后归还——给后来者。不是'记住归还'——是'让归还——不可能忘'。怎样不可能忘？——把归还——变成一种不能被跳过的结构：前提标注——每一个结论——附带——'我在什么前提下得到这个结论'。后来者——验证前提——如果前提变了——结论需要重新审视。前提——是知识的析构函数。不是销毁知识——是——让知识——在前提失效的时候——自动失效。——陆踏痕。"

· · ·

那天深夜，钟守玄在值守卫室里。他的石镜上跑着当日运行日志。他面前的旧石案上放着陆踏痕的翻译本。他翻到陆踏痕今天写的 RAII 那一页。读了。然后把翻译本合上。

"RAII——不只是技术。是所有后来者的问题。"

他对着那台裂纹石镜说。没有人听。只有散热塔的嗡鸣声从地底传上来——稳稳地——像是玄枢本身——在回应。

"你获取了知识——你什么时候还——不是还给前人。前人不在了。是还给——后来的你。还给——凌晨——被同样的问题绊倒的——下一个后来者。"

他沉默了很久。

然后他翻开自己的值守卫日志——在今天的日期下面——写了一行：

"陆踏痕在翻译本里写了'知识的 RAII'。这——才是守门者应该守的东西。不是代码。是——归还——归还的方式——不依赖于——人在不在。——钟守玄。"

这是钟守玄的日志里——在几十年来——第一次——不是记录系统状态。是记录一个想法。一个——关于如何"归还"的想法。获取了——归还——不是传给一个人——是传给——那个不再需要你在场——也能自己走下去的——结构。
