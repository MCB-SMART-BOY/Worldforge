# 驭器卷 · 第33章 · 卫千枢的指纹

在旧核深处，纪承钧发现了一处修正。

那是一小段模板元编程（`template metaprogramming`）——用 SFINAE（`替换失败不是错误`）解决了一个隐式类型转换（`implicit type conversion`）的问题。代码本身只有几十行。但它的精妙程度——让纪承钧坐在旧机柜旁的石板上，读了一遍又一遍。

这处修正做了一件事：当外部调用方传入一个旧格式的类型时，它自动检测类型的特征——如果该类型缺少某个在新标准（`C++11`）中才引入的成员函数，它就启用一个特化版本，用兼容的方式处理。外部调用方不需要知道这个机制——它只是在调用，像调用任何一个正常的接口——而这个机制在编译期（`compile time`）悄悄地、准确地把旧类型和新接口缝合在一起。

没有任何文档。没有任何注释。只有结果。

纪承钧试图理解这段代码。他花了将近两个时辰——不是因为它长。是因为它"太对"了。每一步都是最优的——每一步都精确地利用了模板推导（`template deduction`）的边界条件。它不需要注释——因为写出它的人觉得：看代码就够了。代码本身就是文档。

但陆踏痕——花了四个时辰。

他不是看不懂。他是需要知道——为什么这个特化版本被启用。为什么不是另一个。为什么那个条件判断用 `decltype`（`类型推导`）而不是 `enable_if`（`条件启用`）。为什么这个 SFINAE 的触发条件放在这里而不是那里。每一个"为什么"——代码里没有回答。代码只说"怎样做"。

四个时辰后，陆踏痕在笔记本上写下：

"发现——卫千枢模板特化修正。功能：自动兼容旧类型格式。技术水平：极高。代码行为：正确。注释：无。——理解代码行为：两个时辰。理解'为什么这样写而不是那样写'：四个时辰——仍未完全理解。——如果有注释说明——'因为旧类型缺少 X 成员，而新接口需要 X，此处用 SFINAE 做编译期分派（`compile-time dispatch`）'——一个时辰就够了。——前提：以上时间基于笔者当前的 C++ 模板水平。模板水平更高的后来者——可能更快。——但再快——也需要有人告诉他——'为什么'。——代码不说'为什么'。"

他把笔记本给纪承钧看。纪承钧看了那一页，沉默了一会。

"不是代码的问题。是写代码的人——他太强了。强到——他觉得不需要解释。"

"所以——强——是一种障碍？"

"强本身不是。但当强的人——忘记了不是每个人都和他一样强——他的强——在被后来者继承的时候——就变成了墙。不是故意立的。是不自觉的——他的代码——对他自己来说——是透明的。他忘了——没有他那个级别的理解——代码——是不透明的。"

· · ·

傍晚，钟守玄从值守卫室出来了。纪承钧把那段代码指给他看。

钟守玄只看了一眼。

"卫千枢的。"

"你怎么知道？"

"因为这种写法——只有他。用 SFINAE 做类型分派——那时候 C++ 还没有 Concepts（`概念约束`）——他用 SFINAE 达成了类似的效果。但这个写法——在当时——不是唯一的解法。只是他的解法。他选择了这个——因为他觉得——这个最优雅。"

钟守玄顿了顿。像是想起来什么。

"卫千枢不是不写注释。他写。他在最关键的地方写——'此处逻辑——来源未知'——'此处逻辑——最早见于某年某月的旧脚本'。他的注释——是给'理解水平和他接近的人'看的。但后来——接替他的人——理解水平不如他。那些注释——他们看不懂。他们不觉得自己看不懂——他们觉得——'注释写了——这里来源未知——那就是没有来源'——不再追问了。你看——卫千枢写了注释——但他们还是没看懂。"

纪承钧看着那段几十行没有注释的代码。"这段——他没写注释。"

"这段——他写了。在这。"钟守玄翻开散页笔记中的一页——纪承钧在旧核深处翻出来的散页之一。那一页是关于同一段代码的设计草稿。上面有密密麻麻的手写推导——类型关系、特化条件、边界情况。在最下面——有一行被划掉的注释。不是划得看不见——是保留了原来的字迹，然后画了一道横线。

那行注释是："此处特化逻辑——依赖旧协阵接口的类型定义。如果旧协阵接口被迁移——此处特化可能不再需要。——但迁移时间未定。——卫千枢。"

"他写了。"纪承钧说。"为什么划掉？"

"因为他不知道迁移时间。如果他说'可能不再需要'——后来者可能会在迁移之前就把这个特化删掉。如果他说'未定'——后来者会问——'什么时候定'。他回答不了。所以他划掉了。他不是不写——他是写了——然后发现——写了——会引出他回答不了的问题。所以他不写——让后来者自己发现——自己判断。"

纪承钧把那张散页翻到背面。背面是空白。

他拿起笔——在背面写了一行：

"卫千枢——此处特化逻辑的注释——他写了一半——划掉了。不是不写完。是写完——会引出他回答不了的问题。所以他不写——让后来者自己判断。——前提：这个选择——保护了后来者的警惕——但消耗了后来者的时间。后来者花在理解他的代码上的时间——本可以用来追更深的病。——这是一个没有最优解的困境。后来的后来者——如果你在读——你也会面对。——纪承钧。"

他把散页放回原位。

窗外——旧核的琥珀色指示灯在黄昏中一闪一闪。那段几十行的模板特化——此刻又在处理一个新请求。它完美地缝合了旧类型和新接口——卫千枢写它的时候——他想的可能是"这够清楚了"。但在陆踏痕的笔记本里——那四个时辰——是一个年轻人坐在旧机柜前——对着几十行没有任何注释的天才代码——一遍一遍地问"为什么"——然后自己回答。

卫千枢留下的不是错误。是"太正确了以至于不需要解释"。而"不需要解释"本身——成了后来者最难跨过的注释空白。

不是天才的错。是天才不知道——"够清楚"——不在自己脑子里——在后来者的眼睛里。
