# 驭器卷 · 第108章 · 传火之后

传火之后第三天。玄枢日常运行。陆踏痕值班。纪承钧在古器院外，没有进去。

这是纪承钧第一次在玄枢运行时不在控制台前。不是因为不重要，是因为不需要。制度在运转，陆踏痕在守，观测面板在亮，一切正常。散热塔在窗外低沉地转，和每一个凌晨一样。但今晚的安静不是"没人发现问题"的安静，是"制度在工作"的安静。

陆踏痕在值守日志上写："子时。一切正常。runbook 第三页的第三步——在今天的情境下需要调整。北岭的新信号码格式改变了依赖确认的路径。已在空白页补充。陆踏痕。"然后继续值班。不是"我修了一个问题"，是"我发现了 runbook 里的一个前提变了，我修正了它"。不是照着做，是判断。不是继承，是继续。

纪承钧在外面看到日志更新通知。笑了，然后转身离开。火传下去了。不是完美的火，是带着前提声明的火。但它在烧。不在他一个人手里，在制度里。任何后来者走到铁柜前，打开 runbook，读到那七个字，然后开始做——就是下一代的守门者。不需要任命，不需要确认，只需要走上来，拿起工具，然后在留白处写下自己的那一行。

沈照痕的观测面板仍然在安静地滚动。迹、脉、势——三条灯。但现在监测它们的不是沈照痕一个人，是每一个值夜的人。观测 runbook 在陆踏痕的后来者注之后，已经被第三个人、第四个人补充过——每一个新值夜的人，在第一次独立发现异常之后，在后来者补充页上写下自己的第一条记录。观测不再是少数人的眼睛。

桥谱系在石录里被更新过很多次。已拆的桥标注了退场日期，包裹中的桥标注了最近一次重评估。渡桥司的登记册上，玄枢的桥从四条变成了十七条，然后变成了十四条——因为有三条已经在指定日期退役。制度不再默许"临时"的谎言。

公共记录板上的"伤痕"分区多了几条新的记录。最近一条是陆踏痕写的，关于 glibc 行为变更导致的协议解码异常。下面有他用 readelf 追查的详细过程，有修复方案，有"为什么观测面板没提前告警——因为告警规则需要更新，已更新"。伤痕不是越来越少，是伤痕越来越多——但每一个都被记录，被标注，变成路标。不是系统变危险了，是系统的危险越来越容易被发现了。

传火之后——不是所有问题都解决了。问题还在，纸墙还在，旧骨深处的灰色区域还在，那些在 Fortran 和 C 和 C++ 之间跨了三层语言边界的 unsafe 调用还在。但问题不再依赖某一个人来解决。这就是传火——不是解决一切，是让后来者能够继续解决。每一代解决一部分，标注解决的前提，留白给下一代。文明的进步不是一蹴而就，是一代代人，在自己能走到的尽头停下，写一行字，然后那行字变成下一代人的入口。
