# 驭器卷 · 第52章 · 适配层

桥谱系建立后的第二天，纪承钧决定深入分析最老的那座桥——北岭-wrapper。十一条前搭的。commit message：「临时方案——等新版本出来就删」。新版本从来没有来过。

不是因为新版本没被做出来——是因为从来没有人去定义什么是"新版本"。wrapper 搭好之后，北岭设备集群继续运行自己的周期，玄枢继续维护自己的核心——两边各自迭代了十几个版本——wrapper 夹在中间——它的假设停在十一年前。

纪承钧把 wrapper 的源码从石录里拉出来。不是 C++。是 Fortran——一种比 C++ 更老的语言。wrapper 包裹着一段 Fortran 代码——那段 Fortran 是北岭在第三时代写的——处理设备状态信号的协议解析。玄枢这边用 C++ 调用 Fortran 的接口——中间经过一层薄到几乎不存在的 C 绑定（C binding）。

"这段 Fortran——是谁写的？"纪承钧问钟守玄。

钟守玄看了一眼。然后摇了摇头。

"不是我。也不是卫千枢。比我们更早——可能是创始者的时代。那段代码在玄枢旧核更深的地方——我们从来不碰它。不是因为它重要——是因为没有人知道碰了之后什么会坏。"

"wrapper 呢？谁搭的？"

钟守玄沉默了几秒。

"我记得那个人。姓崔。离职七年了。他离职的时候跟我说——'钟师，北岭那条 wrapper——不是好方案——但当时没有别的方案。等北岭升级——记得拆。'——然后他走了。北岭升级了两次。wrapper 没拆。没有人记得他说的'记得拆'。"

· · ·

陆踏痕用 Git 石录追溯了 wrapper 的每一次修改。

十一年——七次修改。没有一次是结构性改进。每一次——都是"加一行处理新格式"——"修复：北岭传了一个之前没见过的信号码"——"临时：兼容新调用方的请求格式"。每一次修改——都在旧的假设上再加一层假设。七层。

"这不是适配层（wrapper）。"陆踏痕说。"这是一个叠了七层的纸墙。它看起来还在工作——不是因为它设计得好——是因为每一次要塌的时候——有人贴了一张创可贴。创可贴叠了七层——看起来像一面墙——但它还是创可贴。"

他写了一个 fuzzing 脚本——随机生成输入喂给 wrapper，看它如何响应。正常的输入——wrapper 按预期工作。但当输入偏离"非负整数"的假设时——wrapper 开始产生未定义行为（undefined behavior）。传入浮点数——wrapper 静默截断。传入负数——wrapper 输出一个不合理的大数。传入超大值——wrapper 溢出——然后返回一个看似正常但完全错误的结果。

"百分之四十七的异常输入——wrapper 产生未定义行为。"陆踏痕看着 fuzzing 的输出。"百分之四十七。这条桥每天被调用三万次。如果万分之一的输入是异常的——每天就有三次——wrapper 在静默产生错误。"

"静默——意味着什么？"

"意味着——没有人被叫醒。数据悄悄地错了——然后在下游——在十天后的结算里——有人发现数字对不上——然后开始追——追了三天——最后发现——是这条十一年前搭的桥——在 Fortran 和 C++ 之间——截断了一个浮点数。"

· · ·

沈照痕把观测面板的数据和 fuzzing 结果放在一起看。

"wrapper 的假设——不只是假设输入类型。它假设北岭的信号协议不变。假设玄枢这边的调用模式不变。假设两边的时间格式一致。假设——"

"多少条假设？"

"至少十二条。每一条——都写在 wrapper 的代码里——但没有写在任何文档里。因为 wrapper 本身就是文档。但文档——用 Fortran 写成——没有人读。读 Fortran 的人——不在玄枢。在玄枢的人——不会读 Fortran。wrapper 夹在两个世界之间——用两种人都不会的语言——定义了两种人都不知道的约定。"

"不是适配层。"纪承钧说。"是翻译——没有告诉任何人——他翻译的时候加了主观判断的那些东西。"

沈照痕在 wrapper 的源码旁边——标注了十二条隐式假设。每一条假设旁边——写了"前提可能不成立"——然后标注了他观测到的——那些假设在最近三个月内是否被满足。

十二个假设——四个在两年前被打破——两个在最近三个月内被打破。剩下的六个——目前还成立。但没有任何机制——在任何假设被打破的时候——通知任何人。

· · ·

下午，纪承钧把 wrapper 的 fuzzing 结果和隐式假设清单放在钟守玄的桌上。

钟守玄看了很久。不是看数字——是看那些假设被打破的记录。

"两年前——北岭升级——引入浮点数。wrapper 截断——但没出事。如果出事了——我们会被叫醒——然后修——然后——可能就拆了。"

"但恰好没出事。"

"恰好。"钟守玄的手指在"恰好"这两个字上停了一下。"我们不是靠工程活下来的——是靠运气。运气会耗尽。"

他翻开 fuzzing 的结果——那页 47% 的数字。

"如果我没看错——你的意思是——这条路——我们走了十一年——它随时可能塌。只是恰好——没有塌在我们身上。"

"对。"

钟守玄沉默了一会儿。然后说了一句让纪承钧意外的话。

"拆。但要先告诉被影响的人。"

· · ·

那是钟守玄十几年来——第一次主动说出"拆"这个字。不是"备着"。不是"先别碰"。不是"不要动——你不知道它连着多少东西"。是"拆"。

纪承钧没有立刻回应。他看着钟守玄。

"你以前——不会说拆。"

"以前——我知道它不能拆。不是因为不该拆——是因为拆了之后——如果断了——只有我能接。我不能让所有人都靠我一个人去接。所以我不说拆。不是不想拆——是不敢拆。"

"现在呢？"

"现在——你有桥谱系。陆踏痕有 fuzzing。沈照痕有观测。你们知道它连着多少东西。知道拆了会影响谁。知道怎么通知。知道拆了之后——怎么验证不会断到别处。以前——拆——是盲拆。现在——拆——是看的见地拆。"

他把手放在 wraper 的源码上——那张印着 Fortran 的旧纸。

"拆——不是因为它坏了。是因为——它现在——可以被看见地拆。可以被验证地拆。可以在拆完之后——后来者不需要再问'为什么拆这个'。——这些条件——以前没有。现在有了。"

· · ·

那天傍晚，陆踏痕写了一份 wrapper 审计 checklist。不是只针对北岭这一条——是针对所有 wrapper 类型的桥。

"每条 wrapper 都需要被审计。检查——它的隐式假设。输入类型、输出格式、时序依赖、错误处理。每一个假设——验证在当前环境下是否仍然成立。如果不成立——wrapper 必须被包裹或替换。如果还成立——标注验证日期——一年后重新审计。"

他把 checklist 放进接火阶梯的铁柜——在桥谱系旁边——开了一格——标题："wrapper 审计"。

纪承钧在旁边看。

"你把这东西——从一次分析——变成了一个流程。"

"不是流程。"陆踏痕说。"是让后来的人——不需要重复我做的事。我花了三天——跑 fuzzing、读 Fortran、查假设。后来的人——用这张 checklist——也许半天就够了。省下的两天半——可以用来做更难的判断。"

· · ·

那天深夜。纪承钧在笔记本上写了一行。

"适配层的问题不是适配——是适配中的假设——没有被记录、没有被验证、没有被到期审计。Wrapper——不是让不安全变安全——是让不安全看起来更远。远到——没有人记得它在那。直到凌晨——它塌了。"

他停了一下。然后加了一句。

"钟师——今天说了'拆'。不是因为他变了——是因为他看见的东西不同了。以前他看见的是——桥连着太多东西——看不见——不能拆。现在他看见的是——桥谱系——fuzzing——观测——每一条桥的脆弱性被标注——每一条假设被登记——每一条影响被评估。——当桥从不可见变成可见——'不能拆'就变成了'可以拆——但要注意这些'。——可见性是拆桥的前提。不是勇气。——是看见。——纪承钧。——前提：基于北岭 wrapper 的逐行分析和陆踏痕的 fuzzing 测试。——十七条桥——不是每条都能拆。——但每条都能被看见。"
