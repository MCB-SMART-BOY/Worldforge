# 驭器卷 · 第23章 · 记录者

陆踏痕的笔记本第一页写着："玄枢——第一天。不知道从哪里开始。"

现在这一页已经翻过去了很久。本子用掉了三分之一。每一页的空白处都有前提声明——那是他从苏野平留下的依赖分析里学来的写法。本子的侧面已经磨毛了边——他每天揣在兜里，在旧构建区灰扑扑的机柜间钻进钻出，翻出旧文件就蹲在地上抄，灰沾到纸上，字迹有时候被汗潮得有点洇。

他开始理解玄枢了——不是通过读文档。是通过翻那些从来没有人读的文件。

文档在玄枢不存在——至少不是他想象中的那种"文档"。没有架构说明（`architecture overview`）。没有 API 参考（`API reference`）。没有"新人上手指南"。钟守玄的值守卫室门上贴着一张泛黄的纸条，上面写着："玄枢——看代码。代码在 src/。构建——跑 make。需要改什么——问。"纸条的边角卷了，纸面被手指反复按过的部分已经薄得透光——但没人换。因为不需要换。所有新人都是这样过来的：看代码，跑 make，问。

陆踏痕第一天来的时候也看了那张纸条。然后他去 src/ 看了。src/ 里有几百个文件，分布在三十几个子目录里。没有 README。没有注释大纲。代码的注释像化石一样零星散落——有些是十几年前的，有些是钟守玄的（很短的，只写"此处不要改"），有些是卫千枢的（多几行，有时候会写"此处逻辑——来源未知"）。

他那时才意识到：读懂玄枢——不是靠文档。是靠翻。

于是他开始翻。不是翻代码——是翻一切。旧构建文件。旧编译日志。旧变更记录。旧机柜底下压着的打印纸。钟守玄值守卫室里那些手写的日志册。苏野平离开前留下的依赖分析。纪承钧贴在铁柜上的追火考古计划。

他最开始的翻——是漫无目的的。打开一个文件，看标题，看日期，看第一行有没有"临时"两个字——因为是纪承钧教他的，"临时"两个字意味着"这里有问题等人来发现"。然后抄下来。抄到一个单独的本子上——不是他的笔记本，是他的"临时代码追踪录"。里面的条目和纪承钧的重叠了一部分，但也发现了几处新的——钟守玄甚至都不记得了的那种。

"钟师——这个——构建脚本里有一个'临时——等旧核升级后移除此处'——你看？"

钟守玄看了一眼他抄的那一行。"那个——旧核升级从来没有发生过。那次升级被取消了——因为外部调用方不同意停服窗口。——那是哪一年的？"

"日志上写的是丙午年。"

"十八年了。"

"十八年。这处——要不要加到纪师的依赖图上？"

"加。标——'旧核升级被永久推迟——临时变永久——根因：外部调用方否决停服窗口。——前提：此信息来自钟守玄口述。钟守玄说——他不确定外部调用方是否还活着。'"

陆踏痕写了。每一字都写了。包括"他不确定外部调用方是否还活着"。因为这也是一个需要被传递的信息——"不确定"。不是答案。但比不写——更诚实。

· · ·

陆踏痕在旧构建区深处发现了一件事：翻旧文件——最可怕的不是找不到东西。是找到一个东西——但不知道它是什么。

比如有一次他翻到一张旧磁盘——上面的标签已经模糊了，只看得见最前面的几个字："玄枢——核心——"...后面全花了。他把磁盘插进旧机柜里的一台还能跑的老式读取器，等了很久。里面的文件结构是一个他完全不认识的格式。文件后缀名没有出现在任何玄枢文档里。他试着用现代的工具打开——编码不对，全是乱码。他把它摘下来，去问钟守玄。

"这个——你看得懂吗？"

钟守玄接过磁盘，看了一瞬。然后他的眼神变了。不是那种"发现了什么"的兴奋——是那种"原来它还在"的安静。

"这是卫千枢写的。他早期的构建日志——用一种现在已经不用的格式。那时候我们没有统一的编码标准——每个外部平台用自己的。这份——是跨格式的——可能只有卫千枢自己能读。"

"你能读吗？"

"能读一部分。但这个格式——在玄枢已经没有人需要读它了。因为里面的内容——应该已经被迁移到新格式了。"

"应该？"

沉默。

"放在那边吧。"钟守玄说。没有拿走。也没有放回旧机柜里。他放在了值守卫室的旧石案上——一个他每天能看到的位置。"我晚点看。"

陆踏痕没有追问。但他回到旧构建区后，在本子上写了一段：

"发现一张旧磁盘。格式过时且仅有卫千枢完整掌握。钟守玄可以读取部分内容，但不确定里面的信息是否已经完全迁移。此磁盘仍在值守卫室——未归档，未确认。——前提：如果磁盘里的信息没有被完全迁移——玄枢有一块知识在旧格式里等着腐烂。"

· · ·

有一天傍晚，陆踏痕在旧构建区翻到了最底层。

那里有一个木箱子。不是铁柜——是木头箱子。箱盖上没有锁，只有一个搭扣，已经锈得打不开——他是用螺丝刀撬开的。里面的东西很杂：几卷打印纸，几本线装册子，几个已经不亮的旧石镜，一些手写的便条，一块刻着"玄枢——构建——第一版"的旧石板——已经裂成两半。最下面是一本笔记。封面上没有标题。纸已经脆了。

他小心翼翼地翻开。第一页的字迹和后面不一样——更老，更稳。第一页写的是一行标题：

"玄枢——构建系统设计草稿。执笔——卫千枢。前提：以下不是正式文档。是笔记。所以以下会有很多'不知道'。——写给我的后来者。你——可以改。"

他翻到最后一页。那一页只有一行字：

"以下空白。接手的——你也写。——卫千枢。"

陆踏痕的呼吸停了很短的一瞬。

"接手的——你也写。"——这句话他两周前刚从纪承钧那里听过。纪承钧是从钟守玄那里知道的。钟守玄是卫千枢离开后——第一个——也是唯一一个——没有在空白处写下去的接替者。

不是因为不想写。是因为——"我写的东西——后来者会把它当成真理"。钟守玄害怕"写得太多会让后来者不去自己看"。所以他选择了不写。

但陆踏痕不这样想。他想的是：卫千枢写了"接手的——你也写"——意思是——你可以写你的，不是写我的。你可以不同意。你可以加前提。你可以改。你可以标注"卫千枢当年说——前提是——但现在前提变了"。

不写——不是尊重前人的方式。写——带着前提——才是。

他在这本旧笔记的最后一页后面——卫千枢写"以下空白"的后面——夹了一张白纸。然后他在白纸上写了第一行字：

"接手的——我写了。以下是我的部分。——前提：我是陆踏痕，玄枢新人，所知有限。以下所有观察基于钟守玄口述、纪承钧依赖图、苏野平分析——以及我在旧构建区翻过的每一份旧文件。我不确定——以下是否完全正确。但我知道——如果我写下来——后来的后来者——可以验证、修正、补充。不是替代——是接力。——陆踏痕。"

然后他继续写。不是写"玄枢的完整说明"。是写他翻到的东西。那张旧磁盘。那些十八年的临时。那些没有人敢删的旧 Makefile。钟守玄的十四次决策里他理解的八次——另外六次他标注了"不理解——待追问"。

他不是在写文档。他是在写他发现的东西。空白——不是等待被填补。是等待被传递。

这就是卫千枢说的："接手的——你也写。"
