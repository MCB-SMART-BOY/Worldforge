# 驭器卷 · 第64章 · sanitizer

观测三视图部署一周后——沈照痕做了一件让整个玄枢震惊的事。

他在构建配置中启用了 sanitizer（运行时检测器）三件套——ASAN（AddressSanitizer——内存地址检测）、TSAN（ThreadSanitizer——数据竞争检测）、UBSAN（UndefinedBehaviorSanitizer——未定义行为检测）。不是只开一个——三个全开。然后——他重新编译了玄枢——全部代码——`-fsanitize=address,thread,undefined`——然后跑了一遍玄枢的回归测试。

结果——三千个报告。

三千个。不是三十个——不是三百个——三千个。

玄枢的值守卫室里——石镜上翻滚着红字——heap-use-after-free（释放后使用）、stack-buffer-overflow（栈缓冲区溢出）、memory leak（内存泄漏）、data race（数据竞争）、undefined behavior（未定义行为）——密密麻麻——像翻了一夜的火焰警报——每一行都在说——"这里——可能——会炸。"

纪承钧站在石镜前——看着那三千条红字。"三千个——这些代码——跑了十几年——从来没有出过事。"

"在当前的输入模式下——没有出过事。"沈照痕说。"但输入模式会变。Ch75 到 Ch78——青炉的诊断报告——会改变北岭的数据模式——届时——这三千个'可能'——会有一批——同时变成'已经'。——sanitizer 不是预测灾难——是让那些——在特定条件下才会触发的东西——在你改变条件之前——先被看见。"

· · ·

钟守玄从值守卫室里出来。他看着石镜上的红字——看了一段——又一段。不是惊慌——是缓慢的、逐条的辨认。

"这个——"他指着一条 use-after-free——在旧骨深处的 Fortran 绑定层里。"这段代码——是我年轻时写的。那时候——Fortran 的边界——C 的指针——混在一起——写完——跑通了——就没回头看过。快二十年了——它没出过事——因为——在它的调用路径上——释放内存的操作——在那个指针被再次使用之前——不会发生。但如果有人改了调用顺序——或者——在一个新的调用方——释放了那块内存——然后——旧路径上——指针被再次访问——"

"那时候——它会炸。"

"对。不是现在炸。是——条件变了——炸。——sanitizer——不是在说它现在有 bug。是在说——'它有不被保证的行为。'——UB ——不是一定会出错——是'不保证不出错'。以前——没有人知道——哪些地方——是'不保证'的。——现在——这三千条——每一条——都是一个人——在某个年代——写了某种'不保证不出错'的代码——然后——留下的——"——他停了一下——"——债务。"

"UB 不是 bug。bug ——是错了。UB ——是'可能没错——但没有人能保证它永远没错'。Bug ——修掉。UB ——标注——评估——决定——修、忽略、还是监控。——你不可能把所有 UB 都修掉——因为有些——是语言本身的设计——是 C++ 的遗产。但你可以——把最重要的——那些——在关键路径上——在输入模式可能变化的地方——在曾经绊倒过人的地方——的 UB——标出来——修掉——或者在旁边写——'此处有 UB——已知——在 X 条件下不变——但如果 X 变化——先查这里。'——sanitizer——不是修 bug 的工具——是——让 UB 从不可见——变成可见——然后——由人——决定——哪些值得修——哪些值得标注——哪些——暂时——可以放在那——但被看着。"

· · ·

那天下午——纪承钧和陆踏痕花了几个小时——逐一分析三千个 sanitizer 报告。

大多数——是同一个模式在多个地方重复——同一个类型的 use-after-free——在 wrapper 层的多个调用点上——因为所有 wrapper 都是同一个人写的——他有一个习惯——在函数末尾手动释放临时变量——但调用方的一次修复——偶尔会重新引用那个变量。大部分已经被后来的修复绕过了——但 sanitizer 不知道——它看见的是代码——不是修复历史。

但有几个——是真的。

北岭-wrapper 的深层——一个 buffer overflow——当输入数据超过 256 字节时——栈上的局部数组会溢出——写到相邻的栈变量上。当前——输入数据从未超过 200 字节——所以从来没炸过——但如果北岭的信号格式某天加了一个超过 256 字节的新字段——wrapper 会静默覆盖栈上的另一个变量——那个变量——恰好是返回值指针。——不是报错——是——程序——会跳到一块随机的内存上——执行——不可预测。

"这个——必须修。"沈照痕在 report 上画了一个圈。"不管输入模式什么时候变——一旦变——它的失败模式——不是'报错'——是——'跑到一个随机的地址——执行一段可能是任何东西的代码。'——这种失败——无法诊断——因为——它的错误——看起来和 wrapper 完全无关——像一个随机的崩溃——在任何地方——任何时间。——如果没有 sanitizer——这种 bug——追几个月——都不一定追得到。——因为崩溃点——和出错点——在栈上——相隔了好几个函数——中间——是被覆盖的返回值——把你带到了一个——和错误源完全无关的地方。"

"无 bug 系统。但那三千个数字提醒你——bug 到处存在。在当前的输入模式——在当前的调用顺序下——在当前的编译器和平台下——它们没炸。但这种状态——没有保证。你不是靠工程活着——你是靠运气。——而运气——会耗尽。"

· · ·

傍晚。纪承钧在接火阶梯铁柜上——在观测三视图旁边——开了一个新格。标题："sanitizer 报告"。

里面放了五页纸。第一页——三千个报告的摘要——按严重程度分类。第二页——十个必须修的高危报告——每个都有分析、修复方案、和修复截止日期。第三页——五十个中危报告——标注了触发条件和监控建议。第四页——其余报告——归类为"在当前的输入模式下——已知——不触发——但如果输入模式变化——需逐条复审。"第五页——沈照痕写的一段。

"sanitizer——不是安全网——是探照灯。它照亮的——不是 bug——是'不确定'。每一个 UB——都是程序在说——'此处——我不保证。'——以前——这些'不保证'——在黑暗里——安静地——等着——条件变化。——现在——它们在探照灯下。——你看得见——哪些'不保证'——是你可以接受的——哪些——是你必须修的——哪些——是你现在不能修——但你标注出来——告诉后来者——'此处——在什么条件下——可能失效。'——sanitizer——不是让程序没有 UB——是——让 UB——从'不知道'——变成——'知道——并且——选择过。'——沈照痕。——前提：sanitizer 会升级。新版本的 sanitizer——可能发现新的'不保证'——届时——请重新跑——重新标注。——后来的后来者——请不要假设我今天标注的'安全'——在你的时代——仍然成立。——前提可能不成立。"

· · ·

那天深夜。钟守玄在值守卫室里——对着 sanitizer 报告——坐了很久。不是在看报告——是在想。

"三千个。每一个——都是某个人——在某个年代——在不知道的情况下——留下了一行——'不保证'。我自己——就在里面。那条 use-after-free——二十年前写的。——但是——sanitizer——让我知道——我的'不保证'——在哪。——不是在指责我——是在告诉我——'钟师——这里——你可能自己都不知道——你在二十年前——留下了一个不保证。——现在——你知道了。——你可以修——也可以标注——但——你不再是——不知道的了。"

他把 sanitizer 报告的摘要页——折好——放进他的私人日志里。在那页旁边——他写了一段。

"知道——是责任。但不知道——不是免责。——我以前——不知道——因为——没有工具——能让我知道。——现在——有了。——知道——是第一步——修——是第二步——传给后来者——'这里曾经有一个不保证——是我留下的——我修了——或我没修——但我标注了——为什么'——是第三步。——sanitizer——让我完成了第一步。——后面的——是我的。——钟守玄。——前提：今天标注的'已修'——是基于今天的 sanitizer 版本。——后来者——在你那个时代的 sanitizer 下——请重新跑。——可能——我修的——在你的时代——已经不够了。——那时候——你来——修——并——标注——'钟师——在那时候——只能修到这里。——我——现在——继续。——前提可能不成立。'"
