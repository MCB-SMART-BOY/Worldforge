# 驭器卷 · 第62章 · profile 之道

观测三视图建立后的第三天——沈照痕在玄枢上跑了第一次性能剖析（profiling）。

他在构建配置中打开了 `--enable-profiling` 开关——不是永久打开——像打开一盏临时灯——照向正在运行的玄枢。`perf record`——采集运行数据。`perf report`——生成火焰图（flame graph）。火焰图——是一张倒置的图——底是最顶层的调用——往上——是每一层调了什么——每层的宽度——是它花了多少 CPU 时间。不是数字表——是视觉——一眼——就能看见——"这个地方——好宽——它在干嘛。"

纪承钧站在石镜前——看着火焰图。图上——最宽的那一栏——一个函数——占了整张图将近一半的宽度。

"这个函数——是什么？"

沈照痕把那栏放大。函数名字——`legacy_hw_align()`——一个名字里带着"legacy"（遗产）的函数。

"它在做什么——为什么占了百分之四十的 CPU 时间？"

"不知道。但它每一天——都在跑。每一秒——都在占着 CPU——被调用——执行——返回——然后重新被调用。像一个——一直在转——但没人知道它为什么还在转——的齿轮。"

· · ·

纪承钧去找钟守玄。他把火焰图的拓片放在值守卫室的桌上——手指点在 `legacy_hw_align()` 上。

"钟师——这个函数——是什么？"

钟守玄戴上他的旧石镜——凑近了看。看了很久——不是看函数名——是看它的调用栈——它在什么上下文里被调用——它调用了什么——谁又调用了它。

然后他把石镜摘下来。手有些慢。

"这个函数——是十二年前——为了兼容一台已经被废弃的硬件——写的 workaround。"

"什么硬件？"

"北岭早期的一批设备——第三时代的第一代硬件——在传输数据时——帧对齐（frame alignment）方式和后来的协议不一样。第一代硬件——按十六字节对齐帧。后来的硬件——按三十二字节对齐。旧设备传过来的帧——如果不做对齐调整——玄枢这边解不出来。所以——当时写了一个函数——`legacy_hw_align()`——把十六字节对齐的帧——转成三十二字节对齐的帧——然后交给下一层解码。"

"那批设备——还在？"

"不在了。十年前——北岭升级了那批设备的通信模块——换成三十二字节对齐的——和后来的硬件统一了。`legacy_hw_align()`——从那天起——没有需要它处理的帧了。但它还在被调用——因为——调用它的那个函数——不知道它已经不需要了。那个调用——在代码里——没有被删。"

"没有被删——所以——每次——玄枢接收北岭的数据——哪怕是三十二字节对齐的新帧——也会先调用 `legacy_hw_align()`——这个函数跑进去——检查帧的对齐方式——发现已经是三十二字节了——什么都不做——返回——然后下一层正常解码。——十年——没有被删——没有被停——因为——没有人知道它在——没有人能看见它。"

· · ·

陆踏痕在石录（version control）里追溯了这个函数的首次提交。十二年前——commit message：「临时：兼容北岭旧设备帧对齐——等设备升级后删。」作者——一个名字——不在玄枢八年了。

"十二年前的'临时'。设备升级十年了——函数还在。"陆踏痕在火焰图上——在 `legacy_hw_align()` 那一栏旁边——画了一个圈。"不是 bug——是——被遗忘的 workaround。它没有做坏事——只是——在什么都不做的情况下——消耗着 CPU。十年来——每天——每秒——都在被调用——检查——发现不需要——返回。——像一盏——在空房间里——亮了十年的灯。没有人关——因为没有人知道——灯是亮的。"

沈照痕看着火焰图——不是看那个函数——是看它周围的调用关系。

"这不是性能问题。——是认知问题。这个函数——十年前就该被删。但它一直在跑——不是在黑暗里——是在一个——没有人能看见的地方。它被调用——执行——返回——所有的行为都是正确的——但存在本身——就是错的。不是因为错了——是因为——没有必要。而没有人知道——它没有必要。——因为——没有人——能看到——'程序的时间花在了哪里'。——如果十年前有人跑了 perf——这个函数——在那个时代——也是占着最多 CPU——当时就会有人问——'这是什么——需要吗。'——可能当天就删了。"

"但现在——"

"但现在——十年后——因为观测工具终于被装上了——我们第一眼——就看见了它。不是因为我们更聪明——是因为——我们终于——能看见了。"

· · ·

那天下午——纪承钧从代码里移除了 `legacy_hw_align()` 的调用。不是删掉函数——是在调用方加了一行注释——"legacy_hw_align() 已无需要对齐的旧帧。保留函数体作为历史参考。不再调用。——纪承钧。——前提：北岭设备十年前已全部升级为三十二字节对齐。"

然后他重新跑了一次 perf。火焰图上——那个占百分之四十宽度的栏——消失了。整个玄枢的 CPU 消耗——下降了将近百分之四十。

钟守玄站在石镜前——看着新火焰图。两张图——并排——有 `legacy_hw_align()` 和没有——的差异——不是用数字表达的——是宽度——直接——被眼睛看见。

"我们不是在'优化'玄枢。"他说。"我们是在'看见'玄枢。优化——意味着你知道它慢了——你让它变快。但这里——你根本不知道它慢了——因为它从来没报过错——从来没触发过告警——它就是——一直——在花时间——在一个没有必要的操作上。不是优化——是——发现了一个——十年的——不可见。——让它从不可见——变成可见——并且——花了五分钟——删了。——优化——需要数学。看见——需要灯。灯亮了——不是性能提升了百分之四十——是一个十年前就该关的灯——终于被关了。"

· · ·

陆踏痕在笔记本上写了一段。

"profile 之道——不是为了优化——是为了理解。火焰图——不是'哪里慢'的工具——是'程序的时间花在哪里'的镜子。慢的——不一定有问题——也许它就是需要那么多时间。快的——不一定没问题——也许它被过度优化——付出了可维护性的代价——而实际上——不值得。——profile——让你看见——'程序实际上在做什么'——而不是——'你以为它在做什么'。`legacy_hw_align()`——它什么都没做——但它在'做'这件事——本身——消耗了时间。我们不是优化了它——是发现了——它不该在那。——这是两种完全不同的行动。优化——是让正确的东西更快。删除不需要的东西——是让系统回到——它本来应该的状态。——不是更快——是更真。——陆踏痕。——前提：火焰图是会变的。——今天的 profile——不是明天的 profile。——后来者——请定期跑——不是为了找 bug——是为了——不要让任何东西——在被遗忘的状态里——活过——另一个——十年。"

· · ·

那天深夜——钟守玄在他的私人日志里写了一笔。不是关于性能——是关于看见。

"很多年前——我写过——'从今天开始——所有决策——记在脑子里。'那时候——没有工具——脑子是唯一的记录。——后来——有了 Git——工具链——接火阶梯。——现在——有了观测——profile——火焰图。脑子不是唯一的记录——也不是唯一的眼睛。——火焰图——是另一双眼睛——一双——能看到程序在'做什么'而不是'应该做什么'的眼睛。——这双眼睛——不会累——不会忘——不会因为守了太久——觉得'一直这样就是对的'。——钟守玄。——前提：观测工具——不是替代人——是——让人——在判断的时候——有数据——不只是感觉。——感觉——会骗人——尤其——当感觉来自——太久的习惯。"
