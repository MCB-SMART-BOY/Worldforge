# 容断卷 · 第23章 · 监督的边界

"Supervisor不修bug——它只负责重启。它的职责不是诊断——是保持进程存活。诊断——是人的事——是日志的事——是告警的事。Supervisor不应该试图判断'这个crash是不是同一种原因'——它只需要数——'几次了——频率多高。'判断原因——留给crash的堆栈——留给监控面板——留给凌晨被叫醒的人。"

柯守在磐的supervisor配置里删掉了一个复杂的错误分类逻辑——那是前任写的——试图在supervisor层面区分"临时错误"和"永久错误"——临时错误重启——永久错误不重启。这个逻辑在气象API事故中被证明是错的——因为"格式变更"被归类为"临时错误"——supervisor不断重启——导致系统在crash loop中消耗资源而不告警。

"Supervisor的边界——是进程生死。不是业务逻辑——不是错误分类——不是智能判断。让它简单——让它可靠。复杂的判断——在上层——在人——在告警面板——在runbook里。Supervisor是容断的最底层——最底层应该是——最可靠的——最不容易出错的——不应该有它自己的判断逻辑。它的判断——只是——'重启——还是不重启——什么时候放弃。'"
