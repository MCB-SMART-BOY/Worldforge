# 求式卷 · 第2章 · 过时的图

听了秦衡的话，林见微第一周什么都没画。他做的是一件更笨的事：核对。

他把三年前那张 Confluence 分层图上所有模块抄下来，一共二百一十四个。然后逐个去问三个地方：部署平台上还有没有这个东西；网关的流量日志里它最近三十天有没有请求；代码仓库里谁还在提交。核对工具是他花一天搭的小脚本——用 API 拉部署清单和流量统计，剩下的人工比对。六层的一个实习生自告奋勇来帮忙，两个人对着 Excel 核了整整四天。

核对结果用了一整面白板才写得下。

二百一十四个模块里，六十一个已经不存在——服务下线了，图上的方框还端端正正画在那里，甚至保留着当年的浅蓝色填充。三十八个改了名字：有的改得温和，"user-service"变成"account-center"；有的改得面目全非，一个叫"促销引擎"的模块拆成了三个，新名字里已经看不出和促销有任何关系——它们现在管的是会员等级、优惠券核销和一个叫"膨胀金"的东西。

最扎眼的是第九类发现：九十一个在跑的服务，任何一张图上都没有。

实习生小唐在核对中还贡献了一个考古级标本。他在机房巡检照片库里找到一个机柜，机架标签上贴着一张褪色的二维码贴纸，扫码跳转的是一个 2021 年停更的内部页面，页面上只有一句话："此服务由老王负责，问题联系老王。"他们顺着部署平台反查，这个服务至今每天被调用四十多万次——它的完整文档是一张贴纸、一个死链接和一个离职多年、部门已经不存在的人。小唐把照片发进核对群，配了一句："我以为我在做架构核对，其实我在做出土文物登记。"群里沉默了半分钟，然后有人回："别笑，我手上三个服务，文档是我自己，而我已经在看机会了。"

林见微挑了其中流量最大的一个去追。它叫"异步总线"——就是白板照片里那个第一张图上不存在的名字。他顺着代码仓库的提交记录往回翻，翻到了它的出生证明：四年前的一个周五下午，两个工程师为了绕开订单服务在高峰期被批量任务打挂的问题，花三天搭了一条临时消息通道。合并请求的描述里写着："临时方案，下个季度重构掉。"

四年过去了。异步总线每天搬运两千三百万条消息，下游挂着十九个消费方，其中六个是后来入职的人基于它又长出来的服务——他们不知道这条总线是临时的，就像住在桥上的人不知道桥本来要拆。没有人重构它。不是忘了——是它早就从"临时方案"长成了承重墙，谁都知道不能动，但没有任何一张图上写着它是承重的。

林见微去拜访了总线的现任维护人，一个头发稀疏的中年工程师。对方听完来意笑了："你是第一个拿着总线来问我'它在架构里是什么位置'的人。以前来找我的都是问'这条消息为什么丢了''这个队列怎么积压了'。"他点了根没点燃的烟——楼层禁烟，他就叼着——"我跟你说实话：它该在什么位置我不知道，我只知道它不能停。上季度有人提议给它做主备切换演练，我否了。不是技术做不到，是我不知道十九个消费方里，有几个的代码里写着'总线挂了就不重试'。这种问题你没法问，因为写那行代码的人你也找不到——他离职时也不知道自己写的这行意味着什么。"

林见微问："如果现在就动手重构呢？把十九个消费方逐个改造。"老工程师把没点燃的烟从左边嘴角换到右边："你算过改造一次的验证成本吗？十九个下游，每个都要回归测试，可其中四个我们连怎么触发它都不知道——测试用例得先考古才写得出来。你看，这是个闭环：越不了解，越不敢动；越不敢动，越不了解。"他掐了烟，"所以我们给总线加监控、加重试、加了三年补丁——用运维换时间，赌下一代人比我们有缘。"

这段话让林见微在笔记本上画了一条很长的下划线：**结构知识的流失不是从离职开始的，是从"临时"开始的那一秒。**每一个临时方案出生时都带着一个没人签的欠条：将来有人来收拾。四年后，写欠条的人走了，收条的人没留地址，而债滚成了资产——平台最繁忙的主动脉，法律状态是"临时"。

复盘会上，老工程师们把话说得更透："问题不是有人画了过时的图，是画图这件事没有反馈。我把图画得再新，三个月后一样过时，没人因为我维护了图得到什么；我不维护，同样没有任何东西变坏——至少当周不会。图和代码之间没有闸门，也没有报警。它俩各过各的，中间靠人的自觉连着。而自觉这种东西，"他笑了笑，"扛不住组织架构调整。一次重组，认识这条总线的人走一半，图就彻底成了文物。"

林见微在那本笔记里算了一笔账。万象平台平均每天有四十多个提交会触碰模块边界：新建服务、迁移接口、改依赖方向。也就是说，任何一张手工维护的架构图，从画完那一刻起每时每刻都在变得更错一点。指望人靠自觉去追一个每天变化四十次的东西，本身就是设计错误——不是人的错误，是制度的错误。

那天他给秦衡发了一封很短的邮件：

"图不会自动更新，但代码每天在变。这不是态度问题，是机制缺位。我建议先停止争论'哪张图是对的'，改为回答另一个问题：什么样的东西才配叫'当前结构'的记录——它必须能被机器校验，必须有人为它的失实负责，并且失实的时候要有东西真的变红。否则我们只是在积累下一批文物。另：建议本周内冻结对'异步总线'的一切非必要变更，直到弄清十九个消费方的真实依赖。它是全平台流量最大、文档最少、法律状态仍为'临时'的组件——这三个条件同时成立的东西，出事只是时间问题。"

秦衡回了一个字："写。"

过了几分钟又追了一条："方案里把总线的事单独立一章，标题就叫《论临时的永生》。另外别急着动手建东西——先去看人是怎么丢结构的。去找老张：他管了万象八年的服务拆分，全平台没有比他更清楚每个服务为什么在那一层。趁他还没走。"

林见微查了一下人事系统。老张的离职流程，显示的是"已提交"。审批人那一栏空着——连他要走这件事，都还没有人认领。
