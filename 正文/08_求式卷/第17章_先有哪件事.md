# 求式卷 · 第17章 · 先有哪件事

讲解员念十张卡的时候，总有人问：这些卡片排起来会是什么？答案要等第二天才揭晓——把所有"发生过的事"按发生的先后，在第三面墙上排成一条河。

规则听起来很简单——从左到右，时间之流。第一排就顺："客户提交订单"→"库存被扣住"→"风控开始判断"。然后河断了。

断在风控下游。

"交易被发起"这张卡应该接在哪里？风控放行之后才轮到它，这没有争议。争议来自风控组自己抛出的事实：大额订单，风控会先拦下来，等人工审核——短则十分钟，长则三天。这段时间里，订单已经存在了，库存已经扣住了，但交易还没有被发起。

也就是说，河里出现了一段真空：**订单活着，钱的世界完全不知道它。**

"那又怎样？"有人不以为然，"审核过了自然就发起了。"

仓储来的拣货员老陈这时候开了口。他是第二天上午被换进来的第二批一线员工，一早上几乎没说话。这次他站起来，指着那段真空说："就这个候——你们别给我发任何东西。以前就发过这种单子：风控还没放行，拣货单先到了仓里。我们的人把货从货架上挪下来、打到暂存区。后来订单取消了，那批货在暂存区转了三天才回到原位——中间盘点盘不上，系统说它在 A 位，实际在 C 位，客户又下单买了同一件货，拣货员跑到 A 位扑空，全仓找了一下午。"

他顿了顿，补了一句让全场记了很久的大白话："你们画这个图的时候记住一句话：**单子可以等，货不能等。货一动，就没有'还没发生'这回事了。**"

会议室安静下来。这段真空被写上一张白色卡片，贴在河断开的地方，上面只有一行字：此段时长不定（十分钟至三天），期间订单、库存、履约三方状态不一致——历史上至少三次事故经由此段。

围绕这张白卡，爆出了第一天最长的一次争论。风控拦下来等人工的那个东西，到底是什么？客户团队说当然是订单——它在我们表里躺着；财务团队说不是，钱没动就什么都还没发生；而老陈的遭遇证明第三个世界已经动了——货的世界对"审核中"毫无概念，它只认拣货单。

三方各执一词的本质，林见微在白板上写了出来：**这不是同一条河上的三个刻度，是三块地各自根据利害在同一段时间里插了三套刻度。**订单的时间轴上，风险敞口从下单那刻就开始计；财务的时间轴上，一切以落账为准；仓库的时间轴上，拣货单打印出来就是既成事实。所有系统文档都假设事情有一个标准顺序——那个顺序其实只是"大多数正常订单的顺序"，而事故从来不长在大多数里。

排河排到第二天中午，最终通的方式出乎所有人意料：不是大家对顺序达成了一致——是放弃了"一条河"。

墙上出现的是一条主干加七条支流：每块地自己的事件流各自成线，用竖直的同步线缝在一起。订单支流的"已确认"和履约支流的"指令生成"之间一根竖线，标注着"正常 0.3 秒 / 风控挂起时不定"；交易支流的"落账"和记账支流的"入账凭证"之间一根竖线，标注"T+0 或 T+1，跨日需人工标记"。

墙上的东西比一条河复杂了十倍。但每一处复杂都有人签字认领——七条支流各有维护人，每根竖线两端各有两个签名。一个旁听的架构师嘀咕："这还叫架构图吗？乱成这样。"

陆拾伍正好站在旁边，回了一句：

"一条干净的河，是拿一百个特例淹死换来的。你现在看见的乱，是那些特例一个个爬回墙上的样子。**它们宁可被画出来难看，也不愿意回到水下好看地憋着。**"

专场散会后有人统计了那段真空的真实数据：风控挂起的订单日均一千二百单，平均滞留四小时十七分，最长一单挂了六天——而在这段"系统认为还没发生"的时间里，客服侧每天接到三百多个"我的单子怎么没动静"的查询电话。三百个电话对着一千二百单沉默，这就是刻度不一致的日常税率。这份数据后来成了"等待是一等状态"立项时最硬的一页论据。

更有意思的是滞留分布：风控挂起的订单里，百分之九十七在当天放行——绝大多数"等待"短得像一次呼吸，但正是那百分之三的长尾把整个系统拖进了刻度战争。**平均数会骗人，长尾才是结构的形状。**这句话后来写进了万象的容量规划手册，署名是那个做统计的实习生小唐。

小唐后来顺着长尾做下去，产出了一张《滞留分布图》：全平台所有等待环节的时长，按 P50/P95/P99 排开。图揭示了一条铁律——凡有人工介入的点，尾巴都肥；纯机器链路细得像针。**系统的尾部厚度由人决定；要优化体验，先看人，别看服务器。**这一页成了当年万象内部转发最多的文档之一，标题起得很直白：《我们在哪里让人等》。

图集后来有了续篇《谁在让谁等》——把每条肥尾标注等待方与被等方。首页只写了一行：这套系统里，多数等待是人在等另一个人，机器只是替人站着。

那天傍晚收工前做了一次"回放验证"：随机抽十张卡片，请写卡人讲那件事真实发生的一天——包括加班、电话和骂声。第七张是客服的"客户打电话说要改地址"，讲到最后发现：这件事在系统里的唯一痕迹，是一个人工备注字段，而仓库看见它与否，取决于当班的人有没有点开那个折叠面板。

十张卡片回放完，六张暴露出"系统与真实日子之间的缝隙"。这些缝隙全部被登记成新的白色卡片——它们后来成了求式卷后半程反复回访的矿脉：等待、人工介入、口头约定、折叠面板。

十张里有两张的缝隙深得离谱。一张是"已确认"：回放时发现商家"确认接单"这个动作，在高峰期有三分之一不是商家点的——是系统按历史行为自动代确的，开关三年前为"提升体验"打开，再没人关过；也就是说，事件河里三分之一的"确认"根本不是承诺，是猜测。另一张是"退款完成"：客服承认大额退款的真实决策发生在电话里——先谈、先吵、先安抚，谈完才回系统点那个按钮；系统里的"退款流程"是给审计看的仪式，真正的流程在录音里。这两张卡当场被登记进欠条簿，一张挂给了订单域（自动确认的边界），一张挂给了客服域（决策留痕的方式）。

林见微在笔记里总结这一章：**事件河最大的发现不是任何一条具体的线，而是一个否定句——不存在一条所有人共用的时间轴。结构工作从承认这句话开始。**
