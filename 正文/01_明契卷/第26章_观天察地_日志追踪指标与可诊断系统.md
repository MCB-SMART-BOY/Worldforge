# 明契卷 · 第二十六章 · 观天察地，日志、追踪、指标与可诊断系统

第25章把青炉的三种运行形态写清以后，北院小室里总算有了一阵少见的平稳。

一次性命令不再偷借长驻默认。

流水线调用也补清了输入来源与失败即停。

守望壳开始有了自己的站位、锁和退出条件。

可这平稳，偏偏只维持到了下一场真正的入世事故。

· · ·

事情发生在北岭二号守门房。

段迟舟按第24章的入口装上了青炉，又按第25章的守望说明把一条定时深查挂了起来。

按理说一切都像该顺。

命令按时起。

退出码是零。

守望进程也没死。

可门外的人等了整整半日，却始终没等到该出现的那份修正后报告。

更糟的是，旧结果还稳稳地挂在外头，看上去像“什么都没变”。

程知序把段迟舟那张回报压上长案时，连字都像比平时冷了半度。

“表面完成。结果不对。没人知道它到底卡在哪一步。”

贺时进几乎立刻起身。

“那还等什么，直接找最懂的人去看现场。”

苏野平也跟着点头。

“对。先别绕。远端环境一变味，最怕隔着纸猜。你让沈见微过去一眼，多半马上就能看出来。”

这其实是北院过去最熟的一条老路。

出事。

先找最懂的人。

靠他进场、靠他看懂、靠他现场把那层没人写出来的内情说给别人听。

可沈见微这一次却没有立刻起身。

他看着那张回报，沉默了两息，才把众人都按了回去。

“先不去现场。”

屋里立刻静了。

连程知序都抬头看了他一眼。

“不去？”

“先沿痕迹走。”沈见微说，“若这次还是只能靠谁亲自赶到现场，卷二十到卷二十五写的那些东西，就还都只是半成。”

· · ·

这句话一落，季循心里微微一震。

因为他立刻就明白了第26章真正要写的不是“如何更快排障”。

而是“出了事以后，后来者能不能顺着留下来的痕迹自己追进去”。

闻衡在白纸上先写下第一句解释：

给人看的、能按时间读懂发生过什么的记录，叫日志（log）

又写下第二句：

把一轮运行从入口到关键步骤一路挂上同一串标记，叫追踪（trace）

第三句则更短：

把最小几个能看出系统是不是正在变坏的数字口径收起来，叫指标（metrics）

她顿了顿，又补了一句更白的话：

观测不是把字多打一遍，是让失明不再被误认成平静

程知序看完，点了点头。

“先别讲大话。眼下这场，最缺的到底是哪一条？”

这正是第26章最难也最实的一问。

因为北院不是完全没有日志。

前面几章里，大家已经零零散散往关键入口补过一些运行记录。

问题在于，它们还远没长成能让跨环境问题被真正串起来的那种“痕迹链”。

季循先把远端送回来的那一页现有日志摊开。

上头只有寥寥几句：

`doctor started`

`doctor finished`

`report flushed`

看上去一点毛病没有。

可正因为太没有毛病，反而让人一点也摸不到真正的病。

程知序皱起眉。

“这跟没写差多少。”

韩砺年站在门边，听到这里，脸色先沉了一层。

“旧守夜后期就最爱这样。表面永远是‘开始了’、‘结束了’、‘没报警’。越这样，越像一口没人知道里面早空了的钟。”

沈见微没有先评论，只让季循把这一轮远端运行从头到尾应当经过的步骤，先在纸上列出来。

季循很快写下：

读配置。

定运行模式。

找工作目录。

拿守望锁。

起 `doctor`。

收集 `CheckPlan`。

跑核心判断。

写回报告。

交出退出码。

写完以后，他自己先怔了一下。

因为眼前那三句“started / finished / flushed”，几乎压根没覆盖这些真正会出错的节点。

闻衡顺手写下第四句解释：

关键步骤标记，就是在真正会拐弯、会失位、会把锅甩给下一层的那些节点，留下能回查的步骤名

她又补了一句：

不是所有地方都要打点，只把真正会决定命运的弯口钉出来

沈见微点了点季循列出的那串步骤。

“先补这条链。再谈别的。”

于是北院没有先去修那处远端异常。

而是先给青炉立起第26章真正的第一层骨：

`qinglu-observe`

不是豪华楼阁。

只是最小反失明层。

季循先给每一轮运行补上一个运行标识（run id）。

也就是让这一轮从起到落，都挂在同一串号上。

随后，再把方才列出来的关键步骤，一步步钉成清楚标记：

`mode_selected`

`workdir_resolved`

`lock_acquired`

`checkplan_built`

`doctor_completed`

`report_written`

`exit_emitted`

程知序看着这些名字，先问得很直：

“门外的人真看得懂？”

“光名字不够。”闻衡说，“还得有人话。”

于是每个关键标记后面，又都被补上一句最短解释。

选中了哪种运行形态。

工作目录最后定在哪。

这次有没有真拿到唯一锁。

报告写到了哪一处。

退出时到底交的是什么码。

这时，苏野平仍旧皱着眉。

“你们这也太多了。日志、标记、运行号，一个个挂上去，最后只会把人淹死。”

“那是因为你还少了一层。”闻衡说。

她把纸翻到另一面，写下第五句解释：

指标（metrics）不是细节全抄，而是先收最少几个能看出系统现在是不是怪了的数字

然后只列了四项最小口径：

本轮运行总耗时。

拿锁等待时长。

实际构建出的 `CheckPlan` 条目数。

最终写出的报告数。

贺时进盯着最后一项，眼睛先是一动。

“这就够了？”

“先够追这场。”闻衡说，“你现在最怕的，不是少一百个数字。是明明报告没真的写出去，门外却只能看见一条‘finished’。”

这句话一下把整章最实的那根线拉紧了。

于是他们把这层最小观测补进去后，才重新去跑那处远端事故的复盘。

这一次，不再只看那三句平平无奇的旧日志。

而是顺着 run id 一层层往下拉。

程知序先把远端送回来的运行标识贴到了石镜上。

季循接过以后，沿着这一轮的步骤标记一点点往下追。

`mode_selected: daemon`

`workdir_resolved: /var/qinglu/night-watch`

`lock_acquired: true`

`checkplan_built: entries=148`

`doctor_completed: report_items=23`

到这里为止，都还像正常。

可再往下一层，季循的手忽然停住了。

因为本该跟在后头的 `report_written`，并没有如前面那样稳稳落一条成功。

它只留下了一句极短、过去几乎一定会被所有人顺手略过去的话：

`report_write_retry`

后面跟着第二条。

第三条。

然后就没有了。

退出码却仍是零。

程知序看着那三条重试，脸色一下沉了。

“也就是说，它表面上完成了。其实报告根本没真正写稳。”

“对。”季循说，“而且以前那套粗日志根本看不出来它是卡在‘写回报告’这一步，只会让人以为整个 `doctor` 都已经好好走完了。”

韩砺年站在门边，长长出了口气。

“这就是旧守夜最会害人的地方。它不是明着炸，是把真正坏掉的位置藏在一片像样话里。”

可沈见微仍没有让众人只停在“终于找到了卡点”的欣喜里。

他继续逼季循往下追。

“为什么会重试？”

这一下，前面刚补上的指标就真起了力。

季循把同一 run id 下的指标口径往旁边一拉，很快看见一处更小、却更尖的异样：

本轮拿锁等待时长远高于前几轮。

工作目录没变。

`CheckPlan` 条目数也没少。

唯独写回报告前，锁等待拖得异常。

顾迁衡忽然开口。

“不是 `doctor` 本身慢。是写回那边还挂着旧守望留下来的单机锁习惯。”

程知序立刻听懂了。

“所以它不是没做完。是做完后被旧锁语义卡在门口，报告没真落回去。”

这一下，整个事故终于被真正照亮了。

不是远端环境神秘发疯。

不是青炉“偶尔就是会这样”。

而是一条早该在第25章就被当作运行契约重写的旧锁语义，还在用最不吵的方式咬人。

季循望着那条被 run id、步骤标记和指标一层层拽出来的病线，胸口忽然一松，又忽然一紧。

松，是因为这次他终于不是靠谁在场口述，才把问题找出来。

紧，是因为他第一次真切地看见：如果没有这层观测，北院会多快地重新滑回“先找最懂的人现场看”。

闻衡看着石镜上那条完整拉开的痕迹链，低声道：

“这就叫可诊断系统。不是它永远不出错。是它一出错，别人能顺着留下来的痕迹追你。”

这句话一落，连苏野平都没再说“观测是豪华件”。

因为他也看得见，这次若没有 run id、关键步骤标记和最小指标口径，长案边现在还在围着那三句粗日志空猜。

北院这一夜最终没有靠沈见微亲自赶去远端，便把病位圈到了极窄。

而更重的那件事，则在季循心里慢慢站稳了。

前面许多章，他一直在学怎样写骨、怎样守边、怎样立契。

到第26章，他第一次真正学会了一种更像“后来者之术”的本事：

沿着痕迹追下去，而不是沿着人情问下去。

天快亮时，`qinglu-observe` 的最小说明也被正式写进项目记忆。

上头没有浮夸口号。

只有四样东西：

人类可读日志。

关键步骤标记。

跨环境可追的运行标识。

最小指标口径。

程知序看完那页纸，终于缓缓点了头。

“现在就算你们都不在，至少别人也知道先沿哪条痕迹找。”

沈见微在文契第二十一层落下最后一句话：

> 若观不到，就不算真的立住

石镜微亮，观测说明沉入石录。

而青炉在这一章之后，终于第一次长出了一种从前北院最缺的力量：

别人能顺着痕迹追它，而不必只能仰赖某个人的直觉。
