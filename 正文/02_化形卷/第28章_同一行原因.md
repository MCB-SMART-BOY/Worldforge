# 化形卷 · 第28章 · 同一行原因

周栖野把三段代码的最后一行并排放在屏幕上。不是比较代码——是比较它们在停下之前写的最后一个注释。同一句话，以三种不同的方式。

C 工具的最后注释："此函数依赖内部 API。该 API 已废弃。无法完成。后来者如果需要此功能——应该自己重新实现。"Shell 脚本的最后注释："TODO: handle the case when pip is not installed. 如果后来者试图完成此脚本——请注意——pip 的行为在不同环境中不同。我无法预测你的环境。你自己判断。"林过川的 README 最后一行："这个工具本身不能被自动化交接。放弃。后来者应该自己重新判断需求。"

同一个意思，用不同的措辞，跨越了漫长的年代。"后来者应该自己判断。"

三个人在各自的停下的地方，用了同一种理由解释自己为什么放弃。不是因为技术原因——不是因为做不到。是他们都在某个时刻意识到：自己做的东西不能被完整地传给下一代，因为下一代的前提会变。而他们没有制度来声明"在我的前提下，这是对的"，所以只能选择沉默。

Shell 脚本的作者面对的是 pip 行为的不确定性——他知道依赖检查脚本本身的依赖会变。林过川面对的是交接工具本身不能被交接的悖论——他写了交接工具，但交接工具的规则在下一版 Python 中会变。C 工具的作者面对的是内部 API 被废弃——他所依赖的东西已经不在了。三个人在不同的时代停下，但停下的理由完全相同：他们信不过自己写的东西在下一代人的手上仍然成立。

这就是在驭器卷中被纪承钧发现的、嵌在玄枢最深处的残码——`[RESERVED FOR INHERITANCE COVENANT — PENDING RATIFICATION]`——在另一个世界、用另一种语言、以另一种形态——说出了同样的东西。在玄枢——创始者留下 PENDING，不敢写完。在化形——三代人各自写到关键处停下，不敢传。在驿河——远古告警发了上万次，没有人回应。同一种恐惧——"我传下去的东西，会不会在后来者的世界里成为墙？"

"不是巧合。不是同一个师门传承。是同一个问题在不同世界、不同语言中被不同的人独立发现了——'写下来的东西不能自动保证在后来者的时代成立'。在玄枢，钟守玄选择了不写。在化形，林过川选择了写，但写完发现工具过时了。在旧石镜的主人那里，那个人选择在代码中留注释警告后来者。三种回应，同一个认识：知识传递的困境不是技术——是前提会变，而声明的制度不存在。他们每个人——都是对的。他们怕写下来的东西变成墙——所以选择沉默。但沉默也是墙——只是墙的形状是空的。"

周栖野在林过川的 README 旁边加了一行标注。"林过川。你的工具本身不能被自动化交接——是因为交接需要的不是工具，是制度。我读到了你的 README。在玄枢，有人发现了同样的困境——他们用了不同的方法来回应。他们建了前提声明制度、公共记录板、伤痕制度。制度让后来者不需要重新发现你的困境。你的 README 是第一步——但你不应该是最后一步。我不是来完成你的工具的。我是来继续你的思路——用制度，而不是代码。——周栖野。"

卷三的核心揭示不是林过川失败了。是三代人失败了，因为他们不知道彼此的存在。每一个人都是真诚的，每一个人都在自己的能力范围内做对了事——但每一个人都不知道有人曾在这条路上走过。制度不是为了让单个人更强——是为了让代际之间能看见彼此。制度是文明的记忆。没有记忆，每一代人都像第一代人一样努力，也像第一代人一样不知道曾经有人在这条路上走过。
