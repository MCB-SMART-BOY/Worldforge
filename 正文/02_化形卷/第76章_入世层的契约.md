# 化形卷 · 第76章 · 入世层的契约

`field-mapper` 即将进入 gate 层。入世之前必须有正式契约。

周栖野写第一份入世契约——`API_CONTRACT.md`。semver：MAJOR.MINOR.PATCH。兼容性承诺：MINOR 和 PATCH 保证向后兼容。废弃策略：MAJOR 变更需提前一个 MINOR 版本公告。迁移指南：每个 MAJOR 版本需要配套迁移文档。

写每一行时他都在想："我能兑现吗？"之前他改 API 版本号完全随意——从 0.1 到 0.4，没有任何规律。改变竟味着什么，没人知道。他的版本号在撒谎——不是因为想撒谎，是因为没有语义定义版本号。MAJOR 意味着"你依赖的东西可能不兼容，你需要准备迁移"，MINOR 意味着"新增功能，你现有的调用不受影响"，PATCH 意味着"bug 修复，什么都不影响"。

他把 `field-mapper` 从 0.4 升级到 1.0.0，入世。"1.0.0 意味着 API 契约正式生效。接下来的 MINOR 和 PATCH 保证兼容。在 2.0.0 之前，你依赖的东西不会突然变。没人能确定未来永远不会变——但这份契约在说：'如果我不能兑现，我会提前告诉你。我不会突然变。'"

季晚禾看了契约。"所以如果版本变成 2.0.0，我需要读迁移指南。2.0.0 会提前一个 MINOR 版本公告——我至少有三个月准备。之前是你突然改代码和我的季度结算冲突。三个月够了。之前如果我季度结算炸了是我的运气不好，现在是我没读公告。这是我能接受的——因为责任在书上而不是在迷雾里。"

入世层的契约不是让变化不发生——是让变化可预测。可预测的变化不是事故，是计划。后来者需要的是计划，不是永恒的稳定。
