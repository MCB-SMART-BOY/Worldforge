# 化形卷 · 第85章 · 模块入世

固核层最成熟的模块——`seasonal-settlement-validator`——准备部署到驿河（简阵卷·Go 道统）。这是息壤第一个真正"入世"的模块：被外部系统深度依赖，从 Python 世界交付到 Go 世界。

周栖野执行跨域部署检查清单：运行模型适配——驿河是长期运行的服务，不是脚本驱动的请求-响应。错误恢复——服务挂了之后的自动重启策略。观测挂钩——让驿河的观测系统能看到模块状态。前三项通过。第四项——"资源声明"——他填了"默认配置即可"。

他没有标峰值内存。因为在息壤的典型使用场景中，这个模块处理的是小批量数据，内存不超过 200MB。他没有意识到驿河的全量数据集有多大。顾迁舟质疑："你没有标峰值负载。为什么？""因为在息壤的测试中它从来没有超过 500MB。""驿河那边的数据集有多大？""不知道。""那你为什么写默认配置？""因为默认是 512MB。我觉得够了。"

模块带着未标注的前提离开了息壤。和 Ch31 的壳后面那个隐式配置文件一样，和三年前那个 3:17am 的 hotfix 桥一样。隐式的前提不知道自己是前提——在有默认值的环境里被保护着，一旦离开默认成立的世界，前提就断裂。这次的前提不止在息壤内部——它在另一个世界。模块在息壤是安全的，在一个默认内存 512MB 的世界里是安全的。到驿河后，在它自己的内核里安静地全量加载所有集群数据。它不知道自己的上限——因为在息壤从来不需要知道。
