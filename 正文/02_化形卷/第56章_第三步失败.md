# 化形卷 · 第56章 · 第三步失败

周栖野把纪承钧的 runbook 逐行翻译成息壤术语，标注每一步的可行性。十七步，十一步不可行。不是因为写错了——是因为息壤不存在执行这些步骤的系统。

核心问题在第三步。"确认所有下游依赖方已全部迁移。"在玄枢，每座桥都有渡桥司的依赖注册表——依赖方在登记时就声明了自己依赖什么接口、什么版本。确认依赖方迁移只需查注册表。在息壤，依赖在 import 链里、在人的记忆里、在叶藏拙的账本里——唯独不在系统里。

顾迁舟在 runbook 旁边贴了一张对照表。十七步，每步对应玄枢的前提，息壤是否有对应系统，如果没有，替代方案的成本。第三步——依赖注册表——息壤无——替代方案：人工审计所有 import——每桥约两到三个时辰。第八步——构建系统验证——息壤无——替代方案：在每台使用者机器上手动跑迁移验证——成本不可扩展。第十一步——渡桥司退场审批——息壤无此机构——替代方案：目前就是顾迁舟一个人。

"这份 runbook 的价值不在它写了什么，在它暴露了什么。它暴露了息壤最脆弱的地方：我们不管理依赖——我们猜测依赖。玄枢不猜测——他们注册依赖。这是根基性的不同，不是修一两个工具能解决的。玄枢用注册管理依赖，息壤用 import 管理依赖。两种哲学，在不同的复杂度层面有不同的合理性。但当它们试图对话——语法都对，语义全错。"

runbook 的失败不是事故，是镜像。它照出了两个世界的架构鸿沟。不是谁的错——是各自工程文化的差异。但这种差异让双方看不见对方的前提。玄枢的每一步"理所当然"在息壤是需要被重新发明的概念。不是息壤做得不够好，是它们从来不需要这些东西——直到沼泽大到需要它们为止。
