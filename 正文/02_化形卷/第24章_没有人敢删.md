# 化形卷 · 第24章 · 没有人敢删

周栖野在脚本林的第三层子目录里找到一个文件。名字极其诚实：`delete_this_later.py`。创建日期是四年前。林过川创建的。内容：一个空函数。函数名叫`placeholder`。函数体只有一行注释——`# 先占个位。等北岭新接口上线后补全。`

北岭新接口早在四年前就上线了。但那个接口从来没有被这个空函数补全过。可能是因为林过川忘掉了。可能是因为新接口上线太快、他的紧急需求列表又满了。不重要。重要的是——四年。一个空函数。在共享目录里躺了四年。没有人碰。

周栖野准备删。鼠标已经放在删除按钮上了。

然后谢催成的声音从门口传来："等等——可能有人在引用。上个月季晚禾那张报表的调用链里我好像看到过类似的名字。"

"你确定？"

"不确定。但等等。"

岑照渠从另一面石镜后面抬起头："等等。我记得好像有个 notebook 里引过它做 import——我不记得是哪个 notebook，但我有印象。"

白又新站在周栖野身后，翻着自己的记录本："等等——我没用过，但我看到过一个 README 里写了它的名字。是林过川的 `final_v3` 里的 README。"

一个空函数。一行注释。四个人说"等等"。

· · ·

不是因为他们懒。不是因为不想清理。是因为在息壤的目录结构里，没有任何依赖声明（`dependency declaration`）、没有引用追踪（`import tracker`）、没有弃用策略（`deprecation policy`）。没有人知道删了它会发生什么。可能没有后果——它只是一个空函数。可能——如果谁在某个年久失修的notebook里写了 `from delete_this_later import placeholder`，然后那个notebook又恰好是财务组月度结算流程里的一环——会炸。

谁知道？没有人知道。查清楚需要时间。时间可以用来写新脚本——会被表扬的那种。查一个四年前的空函数是不是还在被引用——不会。

"不作为永远不会被惩罚。"叶藏拙的声音从角落传来，"行动则可能。删了之后出事——是你删的，你的责任。没删、出事了——是写它的人的责任。写它的人不在了。所以没删。"

这就是沼泽的生长机制。不是恶意。不是懒惰。是理性。在没有任何工具能帮你判断"删它是否安全"的世界里，保留永远比删除更安全。每一个保留的文件都是一个小小的沼泽增量。几千个增量——几千天——就是息壤。

· · ·

周栖野把鼠标从删除按钮上移开。不是放弃——是决定先查清楚。

他花了整整一个时辰。grep了整个息壤共享目录，检查每一个`import`语句，验证每一个`from xxx import delete_this_later`的痕迹。结果：只有一个地方引用过它——在林过川自己的`final_v3_merged.py`里。而且那个引用也被注释掉了。三年前就被注释掉了。

"它真的是没用的。"周栖野把grep结果投到石镜上，"从来就没用过。四年前占了个位。那个功能根本没做完。没人回来删。"

一个时辰。一个空文件。

脚本林里有几千个文件。如果每一个都要花一个时辰追查——追查完需要的时间超过任何人的职业生涯。所以没人追查。没人删。文件越来越多。沼泽越来越深。

· · ·

叶藏拙在账本上写了新的一行。不是关于`delete_this_later.py`被删了——关于它为什么花了这么久才被删。

"清理一个空文件——需要一个时辰。清理整个脚本林——需要一套工具。"他把笔放下。"恐惧不是个人的。是系统性的。当删任何一个文件都等于自己承担全部后果——而保留任何一个文件等于集体分担'不知道的后果'——保留永远比删除多。这不是勇气问题。是工具问题。依赖图、测试覆盖、版本管理——这些在驭器道被建起来的东西，在化形道还是空白。桥谱系让玄枢的维护者知道每条桥连着谁。依赖声明让驿河的开发者能安全地拆。息壤还没有这些。"

"我们需要它们。"

"对。但第一步不是建。是承认——清理沼泽不是靠更勇敢的人。是靠更好的工具。而工具需要被当成和交付一样重要的事——才能被建出来。"
