# 化形卷 · 第24章 · 没有人敢删

周栖野在脚本林里找到一个文件。文件名：`delete_this_later.py`。创建日期：四年前。内容：一个空函数，加一行注释："先占个位。"

他准备删。鼠标已经放在文件上了。然后谢催成说："等等——可能有人在引用。"岑照渠说："等等——我记得好像有个地方 import 过它。"白又新说："等等——我没用过，但我看到过一个 README 里写了它的名字。"

一个空函数，一行注释。四个人说等等。不是因为懒——是因为在息壤的目录结构里没有任何依赖声明、没有引用追踪工具、没有弃用策略。没有人知道删了它会有什么后果。可能没有后果——它只是一个空函数。但"可能"二字的代价是：如果删了之后出事，是删的人的责任。如果没删、出事了——是写它的人的责任。不作为永远不会被惩罚，行动则可能。恐惧让所有人选择保持现状。保持现状，沼泽永远不会消失。

周栖野花了一个时辰追查 `delete_this_later.py` 的全部引用。grep 整个息壤目录，检查每一个 import 语句，验证每一个 `from xxx import delete_this_later`。结果：只有一个地方 import 过它，而且那个 import 也被注释掉了。"它真的是没用的。从来就没用过。四年前占了一个位，然后那个功能根本没做完。没人回来删。"

追查这个空文件花了他一个时辰。脚本林里几千个文件。如果每个都要花一个时辰追查——追查完需要的时间超过了任何人的职业生涯。所以没人追查。没人删。文件越来越多，沼泽越来越深。清理恐惧的根源不是勇气不足——是工具不足。没有依赖声明，没有引用追踪，没有弃用策略。在一个完全没有工具来帮助判断"删它是否安全"的世界里，不作为是最理性的选择。而集体不作为，就是沼泽的生长激素。

叶藏拙看着周栖野追查完这个空文件，在账本上写了新的一行。"`delete_this_later.py`——四年前林过川占位，从未被使用。周栖野花了一个时辰追查确认。已删。清理一个空文件——需要一个时辰。清理整个脚本林——需要一套工具。"

"恐惧不是个人的。是系统性的。当删任何一个文件都等于自己承担全部后果——而保留任何一个文件等于集体分担不知道的后果——保留下来的东西永远比删掉的多。需要的不是更勇敢的人，是更好的工具链。"依赖图、测试覆盖、版本管理——这些在驭器卷被建起来的东西，在化形卷还是空白。桥谱系让玄枢的维护者知道每条桥连着谁，依赖声明让玄枢的开发者能安全地拆。息壤还没有这些。还需要走过去。走完沼泽的第一步是看见沼泽的深度。第二步是接受这个深度不是靠个人勇气能填平的——需要制度。卷四到卷十二——就是制度从无到有的过程。
