# 化形卷 · 第19章 · 沼泽之后

周栖野提议做一件事：给息壤的所有脚本打标。

"我们不需要一次清理——清理需要知道删了会不会影响别人。我们先知道自己有什么。"他画了一个简单的色标体系。绿色：可复现——任何人拿到这个脚本，按文档操作，能得到同样的结果。黄色：有条件可复现——需要特定的 Python 版本、特定的系统库、或者需要问作者才知道的某个前提。红色：不可复现——文档不存在或已过时，运行环境不可知，输出无法独立验证。

团队花了三天。不是写新东西——是坐下来，面对自己之前做过的东西，一个一个标注。三天后，墙上贴满了脚本的名字和颜色标。从远处看，像一面病态的彩虹。绿15%，黄45%，红40%。每十个脚本，有四个是"根本不知道为什么还能跑"的。每十个，有四个是"跑不跑取决于运气"的。

每个红色标签旁边都有叶藏拙的记录。`field_mapper.py`——3月17日季晚禾放弃。`signal_cleaner.ipynb`——4月2日白又新放弃。`fast_export.py`——4月28日谢催成要求失败。每一条记录不是一个抽象的分类，是一个具体的人在一个具体的时间被绊倒。红不是危险等级——红是"至少有一个后来者在这里摔过"。

团队沉默地看着墙。不是绝望——是一种奇怪的安心。之前沼泽是"感觉很大""越来越乱""好像哪里都有问题"。现在是具体的——一百四十个脚本，五十六个红色。可数的，可管理的，有名字的，有历史的。具体的敌人比模糊的恐惧更容易面对。

"我们可以开始拆了。不是乱拆——从红色的开始。每个红色脚本，先确认有没有人还在用。没有人用的，删。有人用的——标注它的前提，给引用它的人迁移建议和一段时间。然后删。不是一次删完——是一批一批。每一批删完，更新这面墙。让红色越来越少。每次红色变少，都是有人在修理沼泽的证据。"

沼泽画出了边界。从"感觉"到"数据"——是付代价的关键一步。之前"快"的代价是不可见的，散落在每个人的日志和记忆里。现在它贴在墙上，任何人走过都能看到——"那面红色的墙是我们过去几年的加速度留下的账单。"不需要被批评，只需要被看见。看见本身就是管理的前提。

叶藏拙在墙的最下方加了一行小字。"此墙上的每一个红色，都不是一个人的错。是所有人——包括我——在'先这样'的系统里，留下的脚印。脚印不是耻辱——是路被走过的地方。现在我们需要把这些脚印从泥里提出来，画成路。路不是一天画的。但我们已经开始测量沼泽的深度了。"
