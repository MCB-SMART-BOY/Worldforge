# 化形卷 · 第25章 · 旧石镜

叶藏拙告诉周栖野，林过川留下了一台旧石镜——一台老的开发机器，插在试法场的角落，已经没人动过了。如果想知道林过川更完整的东西，那里可能还有。

周栖野找到那台机器。擦掉外壳上的灰，接上电源，屏幕亮了。桌面上只有几个目录，其中一个叫 `archive`。

打开之后不止林过川的东西。三段代码，三个不同的风格，三个不同的时代。

第一段是 shell 脚本，写在一个没有后缀名的文件里，注释风格是很多年前的 Bourne shell 语法。功能：自动扫描脚本目录，检查每个脚本的依赖是否仍然可用，生成一份可复现性报告。脚本没有跑完——在某个函数中间断了，最后一行是 `TODO: handle the case when pip is not installed`。

第二段是 Python 代码，风格很熟悉——七个 `final` 的作者。林过川的尝试。他写了同一个功能——自动交接工具（automated handover tool）：提取一个脚本的所有 import，生成 requirements.txt，验证每个包是否存在。代码几乎完整，测试也写了。但在 `README` 里写了一行："这个工具本身不能被自动化交接。放弃。"

第三段是 C 写的命令行工具。比 Python 那版更老——编译器版本至少是十年前。功能也是同一个：自动扫描依赖关系。注释写得很详细，每一个结构体的用途都解释了。但代码在关键逻辑处有一个大洞——一个函数的实现被删了，留下一行注释："此函数依赖内部 API。该 API 已废弃。无法完成。"

三段代码，三个不同的人，三个不同的时期，尝试解决同一个问题：自动交接。每一个都接近了，每一个都在某个关键点停下。不是因为技术不够——是因为每一代人的交接工具本身都需要交接，而那个"元交接"的问题，没有人能单独解决。

最老的那段 shell 脚本旁边有一行铅笔字，写在机器外壳内侧，已经快被灰盖住了。"To whomever finds this: the handover protocol was never completed. You are not the first. You will not be the last. Please leave your attempt below."

"林过川不是第一个。他只是这台旧石镜的上一任主人。在他之前有别人，在别人之前还有别人。每一代都在修同一个问题：怎么让后来者不需要从零开始。每一代都修到了一半，停下来了。停下来不是因为放弃——是因为手里的工具能建桥，但建不了桥的桥。那个需要的不只是技术，是制度。在他们那个时代，制度不存在。他们用代码修制度的问题，代码不够。现在我们知道了——需要的不只是更好的脚本，是更好的制度。"

周栖野在最老的那段代码下面，加了一行他的笔迹。"周栖野，息壤第四代。仍在尝试。前提：我不知道我的 attempt 会不会也是下一份遗迹。但至少我知道我不是第一个。接手的——你也写。"
