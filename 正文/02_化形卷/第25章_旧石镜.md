# 化形卷 · 第25章 · 旧石镜

林过川的脚本林被翻完之后，叶藏拙告诉周栖野还有一样东西。

"他留下了一台旧石镜。一台老的开发机器，插在试法场最角落的架子后面，已经好几年没人动过了。我试过一次——还能亮。"

周栖野找到那台机器的时候，外壳上落满了灰。不是几个月——是几年。机器侧面贴着一张已经褪色的标签，标签上的名字不是林过川。是另一个名字，更老，更模糊，几乎不可辨认。他把灰擦掉。标签下面还有一层标签。再下面是第三层。三层标签。三个名字。都不是林过川的。

"这台机器不是他的。"周栖野说。

"不是。它被传了很多手。"叶藏拙把电源接上。"每一代最孤独的那个人最后都坐在这台机器前面。"

屏幕亮了。桌面上只有几个目录。其中一个叫 `archive`。打开之后，不止林过川的东西。

· · ·

三段代码。三个不同的风格。三个不同的时代。

第一段是一个 shell 脚本，写在一个没有后缀名的文件里。注释风格是很多年前的 Bourne shell 语法——比息壤最早期的Python版本还老。功能极简：自动扫描脚本目录，检查每个脚本的依赖是否仍然可用，生成一份可复现性报告（`reproducibility report`）。脚本没有跑完——在某个函数中间断了。最后一行是 `TODO: handle the case when pip is not installed`。pip（`package installer for Python`）在当时可能还是一个很新的东西。

第二段是 Python 代码。风格很熟悉——七个 `final` 的作者。林过川的尝试。他写了同一个功能：自动交接工具（`automated handover tool`）。提取一个脚本的所有 import，生成 `requirements.txt`，验证每个包是否存在。代码几乎完整，测试也写了。但在 README 里写了一行："这个工具本身不能被自动化交接。因为它依赖的 Python 版本在下一代息壤已经不兼容。放弃。"

第三段是 C 写的命令行工具。比 Python 那版更老——编译器版本至少是十年前。功能也是同一个：自动扫描依赖关系。注释写得极详细，每一个结构体的用途都解释了。但代码在关键逻辑处有一个大洞——一个函数的实现被删了，留下一行注释："此函数依赖内部API。该API已废弃。无法完成。"

· · ·

三段代码。三个不同的人。三个不同的时期。同一个问题：自动交接——怎么让后来者不需要从零开始。每一个都接近了。每一个都在某个关键点停下。

不是技术不够。shell 脚本的作者不知道 pip 会成为标准。林过川不知道 Python 版本的兼容性会成为问题。C 工具的作者依赖了内部的 API——那个 API 没有做弃用声明（`deprecation notice`），有一天就没了。每一个人都在修同一个问题：怎么让交接本身可以交接。而每一个人手里都只有代码。没有制度。没有弃用策略。没有版本兼容性声明。只有代码。而代码不够。

· · ·

周栖野在机器外壳内侧发现了一行铅笔字。已经被灰盖得快看不见了。他用手抹了几下，字迹露出来。英文，写得很慢，像是每写一个单词都在想下一个该不该写：

`To whomever finds this: the handover protocol was never completed. You are not the first. You will not be the last. Please leave your attempt below.`

后面是四行签名。

第一行——一个认不出的名字。日期模糊了。墨迹极淡。第二行——另一个名字。用的是钢笔，比第一行新，但也是很多年前的了。第三行——林过川。第四行是空白的。等着下一个人。

周栖野在最老的 shell 脚本旁边，加了一行他的笔迹。

"周栖野。息壤第四代。仍在尝试。前提：我不知道我的 attempt 会不会也是下一份遗迹。但至少我知道我不是第一个。接手的——你也写。前提可能不成立——但方向是对的。"
