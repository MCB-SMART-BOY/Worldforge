# 化形卷 · 第75章 · 稳定骨的诞生

第一批活着的模块——不是林过川的火种，而是团队成员正在使用的代码——开始走晋升流程。

岑照渠的 `xirang-csv-validator` 在试法层稳定运行了三个月。她决定申请晋升固核层。自评时她发现模块在试法层的三个月里 MRC 过时了两次（依赖变化），测试少了边界条件，mypy 有一个她一直忽略的 warning。"在试法层这些不是问题。在固核层——每一个都是问题。试法层的'能跑'不等于固核层的'够稳定'。差距在于固核层的东西后来者会直接 import 进生产。"

她修复了所有问题：MRC 更新、测试覆盖增加、mypy 清零、依赖全部锁定。第二次审核通过。公示期七天——没有人提出异议。模块正式迁入固核层。

"在试法层写这个模块花了两周。让它进固核花了三周。进固核比写它多花了一半时间。但后来者 import 它——不用花三周排查为什么跑不通。我花了三周替所有人省了三周。每个人省的时间加在一起早就超过三周了。晋升流程的核心不是一个模块变稳定了——是这个制度被生命测试了一次，证明它可以保护后来者。之前固核只有林过川的火种，现在有活着的代码。固核不是博物馆——是运行的器官。"
