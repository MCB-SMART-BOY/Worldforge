# 化形卷 · 第04章 · 上周还能跑

季晚禾的石镜上跳出那行报错的时候，离月度结算截止还有六个时辰。

她盯着那行字看了三遍，像是多看几遍它就会自己消失。

ModuleNotFoundError: No module named data_utils

"什么意思——"她转头看向身后空荡荡的试法场，"上周还能跑。"

周栖野不在。唐野渡不在。连岑照渠都不在——她去了通界那边开会。试法场里只有季晚禾一个人，和一面吐着红色报错的石镜。外面走廊上有人快步走过的声音，大概是谢催成又在催另一张需求单。

她深呼吸了一次。然后翻开周栖野上周留给她的那张试验纸。纸上写着步骤：把新数据样本放进输入目录。执行映射脚本。检查输出。前三步旁边都有岑照渠后来加的注释——"如果报KeyError就检查字段名""路径要写绝对路径"——季晚禾照着做了。第四步旁边只有一个字："跑。"

她跑了。报错。

"周栖野——"她对着空试法场喊了一声。没有人应。

她拿起传讯牌，给周栖野发了一条消息："你的映射脚本报 ModuleNotFoundError。data_utils 是什么？在哪里？怎么装？"发完之后她盯着传讯牌等了一会儿。没有回复。周栖野大概在另一台机器上跑着什么新东西，没看消息。这就是化形之道最让使用者抓狂的地方——作者永远在点火，不在维护。

传讯牌终于亮了。周栖野的回复只有一行："在我机器上。路径是 ~/tools/data_utils。你把它复制过去就行。"

季晚禾看着那行回复，慢慢把传讯牌放下了。

她没有去复制。她坐在石镜前，把试验纸上那行"跑"字旁边空白的地方写满了字：我需要的模块在作者的机器上。路径是作者的家目录。作者觉得"复制过去就行"。但作者没有告诉我——如果没有传讯牌，如果作者在睡觉，如果作者已经离开了这个宿域——我应该怎么知道这个模块的存在。

· · ·

同一时辰，白又新站在息壤共享目录的入口前，手里捏着宋既明给他的那张清单。

"十个最常用脚本。"宋既明把清单递给他时，脸上没有任何表情。"逐一跑通。确认每个脚本的依赖和输入输出。写出最小复现步骤。这就是你今天的全部工作。"

白又新看了一眼清单。十个名字。有几个他认得——batch_mapping、pipeline_runner、auto_report——都是共享目录里被引用最多的那几个。有几个他不认得。有一个名字叫 final_v3_merged_FIXED_use_this_one.py。他在协阵扩域宿域做了三年平台运维，从来没有见过任何一个正式项目里有这种文件名。

他决定先从这个开始。

第一步：打开文件。代码有四百多行。没有注释。开头有一行被注释掉的 import 语句——# from data_utils import *——后面跟着一段看起来像是直接复制粘贴过来的工具函数。函数名和下面实际调用的函数名不完全一致。

第二步：尝试运行。石镜上跳出的第一行报错是 IndentationError: unexpected indent。白又新盯着那行报错看了片刻。空格和制表符混用了。这在协阵扩域宿域那边会被代码审查直接打回。在这里——它已经在生产环境里跑了至少半年。

第三步：修好缩进。再跑。这次报错变成了 ImportError: No module named old_data_pipeline。白又新在共享目录里搜索 old_data_pipeline。找到了三个版本——v1、v2、和一个叫 old_data_pipeline_legacy_final 的目录。他不知道应该用哪个。

第四步：去问宋既明。

"old_data_pipeline 有三个版本。我用哪个？"

宋既明从石镜前抬起头。"你试一下。"

"三个都试？"

"对。看哪个不报错。"

白又新一个一个试。第一个——报错。第二个——跑通了，但输出是一堆看起来格式完全不对的数字。第三个——跑通了，输出的数字和第二个不一样。

"两个都能跑。输出不一样。哪个是对的？"

宋既明沉默了两息。"清单上标注的预期输出是上周的。你用上周的预期对一下。"

白又新对了。两个都不完全匹配。第三个更接近——差了不到百分之一。可能是浮点精度。可能是某处逻辑被改过。没有文档说明。

"所以我的工作不是逐一跑通。"他把清单放在桌上，"是逐一考古。十个脚本，每一个都像一座没有地图的废墟。我要先猜出它是谁建的，再猜出它原来要做什么，再猜出后来的人对它做了什么。"

宋既明看着他。没有反驳。

"你知道最让我难受的是什么？"白又新说，"不是这些脚本写得乱。是它们每一个都能跑。在某个时间点、在某个人的机器上、在某组恰好匹配的依赖版本下——它们真的能跑。但没有人把'能跑的条件'写下来。所以后来的人只能在废墟里猜。"

· · ·

傍晚，周栖野终于从另一台机器上下来了。他看到季晚禾的消息，赶回试法场时，发现季晚禾已经不在那里了。石镜还亮着。试验纸摊在桌上。他低头看那张纸——季晚禾在"跑"字旁边密密麻麻写满了字。不是抱怨。是她在报错之后自己摸索出来的全部步骤：搜索 data_utils。找不到。尝试用 pip 安装（`pip install`）。找不到包。尝试在共享目录里搜索。找到三个可能相关的目录。不确定哪个是对的。最后放弃。

周栖野看着那行"最后放弃"，胸口像被什么东西轻轻撞了一下。

他把 data_utils 的路径补进试验纸的依赖说明，又在共享目录里放了一份独立副本。然后他走到试法场角落里的公共记录板前——这是叶藏拙上周建议的，每次发现一个"默认读者知道但实际没写"的东西，就记下来，让所有人看见。

板上已经有三条记录了。岑照渠写的：脚本引用的外部数据源URL没有标注由谁维护、何时可能变更。季晚禾上周写的：试验纸上的步骤不包含"如何判断两个字段是否同一件东西"的判断方法。还有一条是他自己之前写的——忘了是什么了，已经被新记录覆盖了一半。

他拿起石笔，在板上加了一条新的：

data_utils 依赖未标注路径。作者默认使用者知道模块在作者的家目录下。使用者不可能知道。补救：补全依赖声明，放入共享目录独立副本。责任人：周栖野。

写完之后他没有立刻走。他看着板上那四条记录——每一条都是一个"我以为你知道"。每一条都是化形之道最核心的盲区被戳破的瞬间。你能跑。你的机器能跑。你的环境能跑。你的传讯牌能联系到你。所以你以为别人也能。直到某一天——一个季度结算截止前六个时辰——别人坐在你的试验纸前面，发现你写的"跑"字对她们来说是一堵墙。

"你知道这些记录加起来在说什么吗？"宋既明不知什么时候站在了他身后。

"在说——我写的每一张试验纸，都假设看的人是我自己。"

"不止。"宋既明说，"你在假设看的人拥有和你一模一样的机器环境、一模一样的依赖路径、一模一样的隐性知识。化形之道的默认前提是'作者就在旁边'。这个前提在试法阶段是效率——它让你不用花时间写那些只有你自己需要的文档。但只要作者不在旁边——每一张试验纸都是一座迷宫。"

"而且作者不可能永远在旁边。"白又新从角落里抬起头。他的石镜上摊着那个 final_v3_merged_FIXED_use_this_one.py——已经跑通了，但输出和清单标注不一致。他在旁边写了一行备注，然后转过椅子面朝周栖野和宋既明。

"今天十个脚本。我跑了四个。四个都有问题。依赖缺失。版本冲突。缩进混用。输出不一致。但最让我不舒服的不是这些技术问题——是每个脚本的作者在写它的时候，大概都觉得'反正别人会来问我'。然后他们离开了。然后别人来了。然后别人发现——没有人在等他们来问。"

白又新把自己的记录本翻开，指着最下面那行总结：

> 十个脚本，零个可以不经考古直接复用。

"这不是他们的错。"他说，"是'作者就在旁边'这个默认假设的错。它让化形之道在短距离冲刺里无敌。但在长距离——在时间、在人员更替、在环境漂移面前——它每一步都在替未来挖沼泽。"
