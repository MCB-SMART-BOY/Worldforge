# 化形卷 · 第94章 · GIL 的边界

Profiling 发现了 CPU 密集型的热点——CSV 解析中有一大段字段映射逻辑在 CPU 上跑得很重。周栖野试图用多线程加速。性能没有提升——反而下降了。

GIL（Global Interpreter Lock）——CPython 解释器的全局锁。一次只有一个线程可以执行 Python 字节码。他的四个线程不是在并行——是在轮流等同一把锁。你以为你在用四只手，实际上四只手都在等同一根接力棒。

"GIL 不是 bug——是设计决定。它让 CPython 的单线程更快，让内存管理更安全，代价是多线程在 CPU 密集型任务中无效。知道边界在哪——你就知道在哪战斗、在哪撤退。I/O 密集型：线程在等 I/O 时释放 GIL——asyncio 有效。CPU 密集型：线程在 CPU 上运行时持有 GIL——应该用 multiprocessing 或者 C 扩展。"

周栖野把 CPU 密集部分改成 `ProcessPoolExecutor`，多进程绕过 GIL，性能提升了几倍。"GIL 不是敌人——是边界。知道边界在哪，就不会在边界之内浪费资源。文明的意义不是消除限制——是标注限制。后来者看到'GIL 在 CPU 密集型任务中是多线程的边界'——他们就不会犯我犯过的错。不是让他们变聪明——是让他们不浪费和我同样的时间。"
