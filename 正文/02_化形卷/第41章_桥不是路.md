# 化形卷 · 第41章 · 桥不是路

顾迁舟到息壤的那天，腰上挂着一本旧册子。封面写"桥账——息壤"，里面是一页页桥的记录：搭桥时间、类型、依赖方、退场日期。每一页退场日期那栏都填着——但都是已经过去了的时间。

他在息壤的公共记录板前摊开桥账。"七条桥。全部没有有效的退场日期。最老的一条搭了快五年。搭的时候说的是'等那边修好就拆'。那边在第三年就修好了。没人来拆桥。"

第一条：`xirang-cpp-bridge`，一个从 Python 调用 C++ 模块的 FFI（Foreign Function Interface）包装。搭了快五年，当时说要等玄枢那边的新接口出来就拆。新接口在第三年就出来了，但桥还在。第二条：`xirang-excel-adapter`，Excel 导入导出桥。第三条：`xirang-old-api-shim`，旧 API 兼容层。第四条：`xirang-r-report`，R 语言统计桥。第五条：`xirang-legacy-db`，旧数据库连接器。第六条：`xirang-temp-migration`——周栖野认出它。他自己三年前搭的。"两周的临时方案。"顾迁舟在账本上写："实际寿命：三年。原因：方案生效了。没人想动。"

第七条：`xirang-unknown`。不知道谁搭的，不知道搭来干什么。没有 git commit 记录，没有作者，没有任何文档。只有一条部署日志——"hotfix - 凌晨三点十七分"。三年了，它一直在跑，没有人知道它在桥接什么。

"桥不是路——但桥被走成了路。不是任何人的错。是没有人负责桥的退场。你在搭桥的时候就想好了它应该什么时候拆，但制度没有让你把这个日期写下来并确保后来会有人回来检查。结果——每一座'临时'的桥都变成了永久建筑。不是建筑的材料好，是'临时'这个标签让所有人以为它会在某天消失，于是没有人对它负责。"

"桥有一个退场条件（sunset condition）——'等那边修好'、'等迁移完'、'等新版本出来'。条件满足了，但没有人回来核实。因为没有人负责回来核实。退场条件不是只写给自己的备忘——是写进制度的承诺。承诺需要有人在它到期的时候回来检查。在玄枢，他们建了渡桥司管理这个。在息壤，还没有。所以我来——不是来拆桥的，是来让桥有出生证和死亡证。"
