# 化形卷 · 第44章 · typing 的迟到

桥的分类让入世层的契约变得可见。宋既明指出契约还有一个看不见的漏洞：类型标注（type hints / PEP 484）。

"入世层的 API 函数没有类型标注。外部调用方不知道你的函数接受什么参数，返回什么类型。他们得看源码——或者猜。但猜是季晚禾在凌晨被炸的原因。"

周栖野本能地抗拒。"类型会让试法变慢。化形之道的速度就是因为不用想清楚——不用先定义函数签名就能开始写。动态是自由的。类型是枷锁。"

宋既明翻出 Ch11 季晚禾的报错记录。当时周栖野的函数 `parse_fields(data)` 接受 `data` 参数——可能是 DataFrame、dict、list、None。函数内部对不同类型有不同的处理逻辑。季晚禾传了 None，触发了未处理的 None 分支。如果函数有类型标注 `def parse_fields(data: pd.DataFrame) -> dict`，mypy 会在她传 None 时就警告她。她不会在生产环境炸掉。

"类型不是为了约束作者——是为了保护使用者。你写类型的时候花的每一秒，都在替季晚禾省下她排查报错的时间。类型是作者和使用者之间的契约——机器可以验证这份契约。之前化形之道没有类型也能跑——因为脚本只在一个人的机器上跑。现在脚本变成了入世层的 API——被人依赖了。被依赖的东西需要更明确的契约。"

Typing 的迟到不是技术难。是化形之道的"自由"被神圣化了——类型标注被视为违背化形之道的教条。但现在看清了：类型不是枷锁，是边界线。没有边界线的自由是沼泽。

"动态不是错的——动态是化形之道的根基，是试法层所以能存在的理由。但入世层不是试法层。入世层的东西被人依赖了。被依赖的东西需要更明确的契约。动态在试法层是对的，在固核层需要部分约束，在入世层需要完整声明。不是所有地方都需要类型标注——是外部系统依赖的地方需要。渐进类型——只在关键的边界上标注，不是全量。三层息壤的好处就在这里：试法层不需要 type hints，固核层推荐，入世层强制。同一个项目，不同的承诺等级。自由在它适合的地方被保留，约束在它需要的地方被施加。不是一刀切。"
