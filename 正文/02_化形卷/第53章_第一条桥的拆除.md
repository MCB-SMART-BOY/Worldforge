# 化形卷 · 第53章 · 第一条桥的拆除

第二条桥的拆除比第一条难。前两个使用者迁移顺利，第三个卡住了。

"我 import 了 `xirang_excel_adapter._helper.auto_detect_encoding`。你的迁移指南里没有提到这个函数。"

`auto_detect_encoding` 是一个内部工具函数。周栖野三年前写的。它没有一个下划线前缀——Python 的"私有"约定是 `_` 前缀，但这个函数没有。它不是文档化的公共接口，但它也没有被标记为内部。它只是在那里，被发现了。第三个使用者发现了它，依赖了它两年。它解决了文件编码自动检测的问题——`chardet` 需要这个功能但接口太复杂，周栖野在桥里顺手写了一个简单的包装。

桥上的使用者不仅 import 了桥，他们还依赖了桥的内部实现细节。他们的代码不是"通过桥"——是"住在桥上"。桥成为了基础设施的一部分之后，它的每一个 helper 函数都可能被某个人发现并依赖。Python 没有绝对的私有——`_` 前缀只是约定，不是强制。使用者可以 import 任何东西。不标记私有的东西就是公开的 API。

周栖野必须决定是把 `auto_detect_encoding` 迁移到新 API 中，还是在弃用声明中加入它的替代方案。他选了后者——这个函数从来不是正式的，但它解决了一个真实的问题。问题还在，解法需要进入正式的接口。

顾迁舟翻出旧注释。"临时方案——等 chardet 更新后删除。"chardet 更新了三次。这个函数还在。而且不是临时的了——有人在依赖它。他从不知道，因为他从来没有告诉这个人"这是临时的"。在息壤的历史上有无数个临时的 helper 函数——它们从来没有被声明为公共或私有。它们只是在"那里"。被发现了，就成了基础设施。桥账需要记录的不仅是正式宣告的桥，还有这些在代码中沉默地存在的、未声明的连接。
