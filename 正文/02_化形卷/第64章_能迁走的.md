# 化形卷 · 第64章 · 能迁走的

十二个火种逐个迁入固核层。不是复制粘贴——是翻译。每个火种都要过三道门。

代码审查——确认没有隐藏依赖。不是import声明里的依赖——那些已经写在`pyproject.toml`里了。是硬编码的路径、环境变量、系统工具调用。在代码里，但不在任何声明文件里。林过川知道这些依赖存在——他的手指记得。但后来者不知道。每一个隐式依赖被逐一发现、记录、声明。

补充测试——定义"对"的行为。不是"能跑就行"。是有断言：输入空DataFrame——返回空字典。输入含特殊编码的文件——正确检测编码。输入缺少必要字段——返回具名错误。不是替林过川测他当年没测的东西。是替后来者建验证——以后改这个模块的人会知道"什么算对"。

补充MRC——让独立使用成为可能。不是周栖野在机器上能跑。是白又新在干净环境里能跑。是季晚禾不打电话能跑。每一个火种旁边都有白又新的签名："已验证——独立复现成功"。

· · ·

周栖野在每个模块的`__init__.py`里加了同一行注释。字迹很认真——不是平时写代码的潦草。

"Originally authored by Lin Guochuan (former maintainer). Migrated to xirang-core during the Fire Seed cleanup. Original code preserved in xirang-archive."（原作者林过川，前维护者。火种清理期间迁入固核层。原始代码保留在归档目录。）

叶藏拙翻着更新后的固核层目录。"之前固核层里只有你和岑照渠的名字。现在有林过川的名字了。不是他的全部。但至少不是空白。不是'对不起'。"

火种迁入固核层——是化形卷对"断史"最具体的回答。失传者的代码不是不可传的。是需要一个愿意花时间翻译的人。代价落在翻译者身上——白又新花了两天翻译一个README，周栖野花了一周给十二个火种补文档。但后来者不再需要付这份代价。
