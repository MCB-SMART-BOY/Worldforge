# 化形卷 · 第82章 · CI for Python

手动审查的成本随模块数量线性增长——二十一个模块乘以四个 Python 版本，八十四次手动跑。不只慢——是不可能持续进行。

周栖野配了 tox。`[tox] envlist = py39,py310,py311,py312`。`[testenv] deps = -r requirements-dev.txt; commands = pytest`。一次配置，以后每次改代码后自动在多版本上验证。四个环境并行跑：3.11 和 3.12 全绿；3.10——一个模块在 import 时失败；3.9——两个模块的测试不通过。

"这些问题在宋既明手动审查时不会发现——因为他用的是 3.11。现在机器告诉我们了。3.9 的用户可能不会报告问题，他们以为是自己不会用。其实——是模块真的在 3.9 上有 bug。他们默默承受了——因为没有人告诉他们'这不是你的问题'。"

周栖野修复了 3.9 和 3.10 的问题后再次全绿。"之前 3.9 的用户默默承受了 bug——因为他们不知道这是 bug，以为是自己不会用。现在机器替他们说了——这不是你的问题，是代码的问题。"

CI 不是让审查者失业——是让审查者从"验证器"升级为"异常分析师"。机器跑常规检查，人看在常规之外的东西。这是审契者的进化。之前宋既明需要手动在四个版本上各跑一次 MRC，每次模块更新都要重新跑——他的时间全部被验证消耗了。现在 tox 自动跑，他的时间被释放出来看更复杂的问题。机器没有偏见，不会忘记，不需要休息——是时间的放大器。审查者的判断用在机器做不到的事上。
