# 化形卷 · 第82章 · CI for Python

手动审查的成本随模块数量线性增长——二十一块模块，四个Python版本，八十四次手动跑。不只慢——是不可能持续进行。

周栖野配了`tox`。`envlist = py39,py310,py311,py312`。一次配置，以后每次改代码自动在多版本上验证。四个环境并行跑——3.11和3.12全绿。3.10——一个模块import失败。3.9——两个模块测试不通过。

"这些问题在宋既明手动审查时不会发现——因为他用的是3.11。3.9的用户可能不会报告问题——他们以为是自己不会用。其实代码真的在3.9上有bug。他们默默承受了——因为没有人告诉他们'这不是你的问题'。"

周栖野修复了3.9和3.10的问题后再次全绿。"之前3.9的用户默默承受了bug——他们不知道这是bug，以为是自己不会用。现在机器替他们说了——这不是你的问题，是代码的问题。"

CI（`continuous integration`）不是让审查者失业——是让审查者从验证器升级为异常分析师。机器跑常规检查，人看在常规之外的东西。机器没有偏见，不会忘记，不需要休息——是时间的放大器。
