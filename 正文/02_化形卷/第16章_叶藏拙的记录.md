# 化形卷 · 第16章 · 叶藏拙的记录

叶藏拙在团队会议上摊开了一本账本。不是财务账——是工程账。封面手写了四个字："沼泽记录"。

"过去三个月，息壤的共享目录中有三十一个脚本被引用超过三次。其中十八个已经不能被作者以外的任何人复现。"

他翻开第一页。不是列表——是一条一条的记录。每一条有一个日期，一个名字，一段描述。

"3月17日。季晚禾试图跑周栖野的 `field_mapper.py`。pandas 版本不匹配。放弃，改用手工映射。花了三个时辰。"三个时辰。本来应该是一键的事。一个脚本，一个用途，一个下午应该完成的工作量——变成了三个时辰的手工劳动。不是因为脚本写得不好，是因为它依赖的 pandas 版本在季晚禾的机器上不存在。

"4月2日。白又新试图复现岑照渠的 `signal_cleaner.ipynb`。notebook 的第三个 cell 依赖一个已经被 pip uninstall 的包。白又新花了半天找替代包。找到了。但替代包的 API 不同。他又花了半天改逻辑。改完之后输出和原来的 notebook 差了两个小数点。他放弃了。复制粘贴了上一次的输出。"

"4月28日。谢催成要求用周栖野三个月前的 `fast_export.py` 出临时报表。脚本在周栖野的机器上还能跑。在服务器上报错——因为服务器上的 Python 是 3.9，脚本用了 3.11 的 f-string `=` 语法。谢催成说：'那就在你的机器上跑。'周栖野的机器跑了整晚。没有关屏幕。第二天早晨——周栖野的机器死机了。临时报表失败。"

不是批评。每条记录都是一个具体的人在某个具体的时间被沼泽困住。不是"系统有问题"——是"这个人在这一天因为一个前提不成立的脚本，浪费了几个时辰"。

叶藏拙翻到最后一页。十八个不可复现的脚本，对应着二十三个后来者的失败尝试。八个放弃了，直接改用手工方案或换工具。七个去问了别人，但问的人也给不出完整的复现路径。六个找到了 workaround——但他们的 workaround 本身又成了新的隐式前提，等着绊倒下一个人。剩下的两个还在坚持，但已经在边缘了。

房间里没人说话。不是因为被批评了，是因为"看不见的代价"第一次被看见了。每个人都知道沼泽存在，但没有人知道沼泽里困着多少人——有名有姓，有具体的时间，有具体的放弃。

"我不是来批评你们的。我只是想让你们知道——你们的速度每快一步，就有一个人在后面试图跟上你们的脚印。有些跟上了。大多数没有。那些没有的人，你们不知道他们的名字。我知道。现在你们也知道了。"

叶藏拙合上账本。他做这件事不是出于愤怒，不是出于指责——他只是觉得，这些被困住的人值得被记录。不是因为他们是受害者，是因为他们的失败不是个人能力问题——是系统前提不成立。而前提不成立这件事本身，应该被看见。
