# 化形卷 · 第65章 · 只能留的

不能迁的废土需要归档，而非删除。废土全量删除等于历史湮灭——但如果不做判断，废土会永远存在。处理废土需要判断哪些对后来的考古者有价值。

有些代码写得很好——但依赖的系统已经不存在了。林过川写了一个数据管道，连接到一个已经关闭的远程 API。管道本身是完美的，架构设计是完整的——但它接入的系统三年前就关了。有些代码解决了真实问题——但后来有更好的解决方案。有些代码永远无法判断价值——因为永远无法复现它运行的环境。

废土被移入 `xirang-archive/`。每个文件旁边有一份 `WHY_NOT_MIGRATED.md`，标注为什么不能迁、保留代码作为考古证据、如果判断可能错误则设定重新评估日期。第一份标注："`data_pipeline_v3.py`——依赖的远程 API 于三年前关闭。管道的逻辑仍然有价值，可作为类似管道的参考模板。如果有人需要重建类似的管道，这里的架构设计是完整的。重新评估：无——API 已关闭，除非该 API 重新开放。"

"这不是失败。这是历史。历史本身是有价值的——即使历史中的东西不可用了。后来的考古者会感谢你保留了它们，而不是删了。废土不是垃圾——是文明的沉积层。每一层都有它的故事，即使故事已经结束了。保存废土是对后来的考古者的尊重。他们需要知道这里曾经有人建过东西，这个东西为什么不能用了，它的哪个部分仍然有用。删了——他们就不知道了。"

废土归档的最重要部分是"为什么不能迁"的标注。哪个外部依赖不存在了，哪个上游 API 关闭了，哪个系统库在现在版本中不再可用。这些理由让后来者不需要重复判断。后来的考古者面对一份标注了原因的废土，可以快速判断"这个不值得恢复"，然后把时间花在值得的火种上。沉积层不是负担——是文明的记忆。记忆不是所有东西都活着，是死掉的东西也被记录在案。
