# 化形卷 · 第93章 · profiling 的真相

争论快与慢之后，周栖野决定用数据而不是直觉来理解"快"。他对 `field-mapper` 做了性能分析（profiling）。cProfile——Python 标准库的分析工具，给出每个函数的调用次数和耗时。py-spy——采样型 profiler，可以 attach 到运行中的进程，生成火焰图。

火焰图最宽的横条是 pandas 的文本解析——占了 60% 的时间。周栖野引以为傲的核心映射逻辑不到 15%。"我以为我在跑这个 show——我在等，大多数时候。我的'快'在 pandas 的等待中没有任何意义。"

快不是感觉——是可量化的。Profiling 不只让代码更快——它还原了"快"的真相：作者以为的快可能在等待中被消耗。他最快的部分是他的算法直觉——函数式映射、向量化操作。他最慢的部分不是他的错——是 CSV 解析依赖了 pandas 的 C 引擎，pandas 在等磁盘 I/O。优化自己的代码没有意义——优化 pandas 的调用方式才有。用 `pyarrow` 引擎替代默认的 C 引擎，性能提升了三倍。不是他的代码写得更好——是他发现了瓶颈不在他的代码里。

"Profiling 不只让代码更快——它还原了快的真相。作者以为的快可能在等待中被消耗，作者没注意的慢可能消耗了大部分时间。认识到'在等什么'比'写更快'更有效。数据不说谎——但直觉会。直觉说我快——数据说我大部分时间在等。不是否定我自己——是让我知道把力气花在哪里。"
