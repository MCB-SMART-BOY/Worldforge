# 化形卷 · 第48章 · 测试 ≠ 信任

三十个测试全绿。部署到生产。一个小时后，线上报错：`ValueError: Empty DataFrame`。

追查发现 `pandas.read_csv` 在文件为空时返回 Empty DataFrame，而周栖野的函数假设输入 DataFrame 非空。测试为什么没发现？因为所有测试用例都提供了非空的 DataFrame。没有人想到需要测试空文件——因为在正常流程中不会出现空文件。但异常流程中出现了。线上有一个凌晨的备份任务因为磁盘满了只生成了空文件，然后这个空文件被传进了 `field_mapper`。

测试只能验证"作者想到了什么"。作者没想到的场景，测试不会提醒你。测试全绿不代表安全——代表"从你意识到的问题的角度看，是安全的"。这不是安慰，而是更诚实的说法。每一次炸场都在扩大你知道的问题的半径。你加了一个新测试，半径扩大了一毫米。一百次后半径大了很多，但永远有未知。

白又新在代码里加了一行 `if df.empty: return {}`，然后写了一个新的测试用例 `test_parse_fields_empty_dataframe`。全绿。只花了五分钟。"不是我们没做测试。是我们没想到。但现在我们想到了——测试帮我们记住了。"

测试 ≠ 信任。测试是诚实。诚实地说"我测试了这些"，诚实地说"我没测试那些"。诚实比安全更重要——因为诚实让后来者知道安全区的边界。让他们知道哪些行为是被验证过的，哪些还没被验证过——他们可以自己决定要不要补充测试来覆盖那些还没被验证的边界。全绿的测试套件可能会骗人，但诚实的测试套件不会——因为诚实的测试套件会自己在空白处标上"此处未覆盖"。
