# 化形卷 · 第81章 · 最低限度的存在

宋既明开始固核层的全量复现性审查。二十一块固核模块，每一块必须在新环境中独立复现——干净的机器，只靠 MRC 和 uv.lock。

十四块一次性通过。七块不通过。问题不是代码有 bug——是环境声明漏了前提。一个模块需要系统级 OpenSSL 的特定版本，MRC 没有标注。另一个依赖了 CUDA 的某个编译选项，在没装 CUDA 的机器上静默失败。第三个的 uv.lock 里有一个间接依赖的平台特定版本——在 Linux 上通过，在 macOS 上失败。

"不是你的代码有 bug——是你的存在声明有 bug。你的代码是存在的，但它只在你的机器上存在。在干净的机器上——它不存在。"

通过的模块贴绿色标签"已成立"。不通过的贴黄色标签"待补充前提声明"。公共记录板上固核层状态从模糊的"大多数稳定"变成精确的数字——14/21 完全复现，7/21 需补充声明。每个黄色标签旁边标注了具体缺失的前提。后来者看到这张表，知道哪些模块可以无条件信任，哪些需要确认自己的环境。"精确性不是批评，是尊重。之前我们说'大部分稳定'——后来者不知道哪些是'大部分'。现在他们知道了。精确的可验证胜过模糊的感觉。复现性不是美德——是文明底线。后来者不应该需要猜哪个模块能否信任——模块自己应该声明。"
