# 化形卷 · 第81章 · 最低限度的存在

宋既明开始固核层的全量复现性审查。二十一块模块。每一块必须在干净环境里独立复现——新的机器，只靠MRC和`uv.lock`。不问任何人。

十四块一次性通过。绿色标签"已成立"——`field-mapper`、`csv-validator`、`signal-parser`，从`git clone`到`pytest`全绿，白又新在干净环境里验证过。七块不通过。不是代码有bug——是环境声明漏了前提（`undeclared prerequisite`）。

一个模块需要系统级OpenSSL的特定版本——MRC里写了`pip install`，但没有写`apt install libssl-dev`。另一个依赖了CUDA的编译选项——在没装CUDA的机器上静默失败，不是报错，是算出了错的结果。第三个的`uv.lock`里有一个间接依赖的平台特定版本——Linux上通过，macOS上失败。

"不是你的代码有bug——是你的存在声明有bug。你的代码是存在的——但它只在你的机器上存在。在干净的机器上——它不存在。"

通过的贴绿色标签"已成立"。不通过的贴黄色标签"待补充前提声明"。公共记录板上从模糊的"大多数稳定"变成精确的数字——14/21完全复现。每个黄色标签旁边标注了具体缺失的前提。后来者看到这张表——知道哪些模块可以无条件信任，哪些需要确认自己的环境。

"精确性不是批评，是尊重。之前我们说'大部分稳定'——后来者不知道哪些是'大部分'。现在他们知道了。"
