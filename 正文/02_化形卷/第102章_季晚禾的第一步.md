# 化形卷 · 第102章 · 季晚禾的第一步

季晚禾接受一个新任务——处理一个数据格式变更。和 Ch11 几乎一样的任务。那时她在月度结算截止前打开上周还能跑的 notebook——报错了。不是业务逻辑——是导入了上周不存在的依赖冲突。她花了三个时辰手动做完——放弃了脚本，手工映射数据。

那时入口不存在。路上只有沉默的代码和无法复现的环境。

这一次她打开终端。Onboarding 文档告诉她环境怎么建——Python 版本、uv 安装、venv 创建——每一步都可执行。"`uv sync`——依赖全部锁定。`pytest`——测试全绿。每一步都有验证步骤——验证告诉你'如果正确完成，你应该看到什么'。"

MRC 范例告诉了她怎么做数据清洗。不是一次读完——是每一步执行完之后有一行小小的验证：如果你看到这个输出，这一步是对的。测试告诉她怎么验证结果——`pytest test_field_mapper.py`——全绿就是正确。公共记录板告诉了她这个格式变更的历史——Ch11 的记录还在上面，旁边有人写"此处曾裂——季晚禾花了三个时辰——已修——前提：Python 3.11 + pandas 1.5——2026。后来的后来者：如果你的 Python 版本或 pandas 版本不同——请重新验证此数据格式。——季晚禾。"那是她自己写的。上一次被同一个格式变更绊倒之后，她留下的。

她的体验完全不同。Ch11 从头到尾是焦虑——"我不知道怎么开始"——挫折——"为什么跑不通"——放弃——"我手动做了，花了三个时辰"。Ch102 是从容——"让我试试"——小困惑——"这一步不确定——让我看看验证"——确信——"验证通过了——我应该是做对了"——成就感——"我做到了——不是靠人——是靠路"。

她完成了。跑了自己的测试——全绿。提交了代码——CI 通过——合入固核层。

周栖野看到了那个 PR。"你不需要帮我。"

"不需要。以前需要——是因为路上只有你。现在路在——我不需要你站在路上，我只需要路。不需要天才——只需要有人告诉我下一步是什么。今天这个'有人'不是人——是文档，是 MRC，是测试，是公共记录板上我自己上一次留下的伤痕。"

叶藏拙在账本里记下这一刻。"Ch102：季晚禾不依赖任何口传独立完成第一个正式任务。这是息壤历史上第一个真正'独立'的后来者。不是白又新——他有技术背景，他会写代码。不是岑照渠——她从旧系统过来的，她认识所有的坑。是季晚禾——一个曾经被沼泽吞掉的人——在秩序中走了出去。Ch11 她的三个时辰不是白费的——那三个时辰变成了今天 onboarding 文档里她的那一行标注。"

季晚禾的第一张 PR 被贴在公共记录板旁边。不是因为她写的代码有多好——是因为在她之前没有人能在这个位置上独立完成任何事。制度有没有用不是看最强的人走得多快——是看最需要帮助的人在制度里能不能自己站起来。她的第一步不是她一个人的胜利——是制度的胜利。制度让最需要帮助的人不再需要帮助。

窗外，一个新的脚本刚刚在试法层被创建。它的作者是下一个新人——她还不知道这条路是怎么铺出来的。她只需要打开 onboarding 文档——然后从第一步开始。路在。
