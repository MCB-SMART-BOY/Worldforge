# 化形卷 · 第55章 · 收到 runbook

桥拆除进行到一半，顾迁舟收到一份来自驭器卷的包裹。不是传讯——是一份装订好的册子，封面写着"息壤桥退场迁移流程——共十七步——基于驭器卷渡桥司桥治理标准——纪承钧——供参考"。

"玄枢的纪承钧。他写了这个——听说我们在整理桥账。这十七步在玄枢是标准流程——每座桥从弃用声明到退役归档，全链路。每一步都有验证——在玄枢。"

周栖野打开册子。前两步是术语翻译——"桥 = adapter，退场 = sunset。"字迹工整，像一个认真的人在对着另一个世界的人翻译自己的语言。他能想象纪承钧坐在玄枢值守卫室的老旧石案前，一页一页写这些字。他不认识纪承钧——但他认识这种认真。

第三步——"确认所有下游依赖方已全部迁移。"这一行下面没有验证步骤，没有脚本，没有命令，没有工具。因为在玄枢，每座桥都有渡桥司的依赖注册表——所有依赖方在搭建时就声明了自己依赖什么接口、什么版本。确认依赖方迁移就是查注册表——一行命令的事。

在息壤——依赖注册表根本不存在。

周栖野把册子放在叶藏拙的桌上。叶藏拙翻开，扫到第三步，停了。"他假设我们有依赖注册表。在玄枢，这个假设成立——因为那是 C++ 的世界，编译期就知道谁依赖了谁。在息壤——Python 的动态 import——依赖在运行时才被解析。我们从来不知道谁在依赖什么——直到爆炸。"

季晚禾从公共记录板前转过身。她手里还拿着那本册子，已经翻到了第十一页。"我试着按 runbook 执行了。"她走到第三步——"确认所有下游依赖方已全部迁移。如果无法确认，标记为'待确认'，继续下一步。"她标记了"待确认"。

第四步也需要依赖注册表——又标记了"待确认"。第七步需要构建系统验证——息壤没有统一的构建系统，每个人的 `pip install` 在不同的 venv 里，版本各不相同。她标记了"待确认"。第十一步需要渡桥司退场审批——息壤没有渡桥司，顾迁舟一个人在做桥账。"待确认。"第十五步——她在那行旁边写道："我不知道该怎么做。没有标准。没有人告诉我什么是'够好了'。"

十一个"待确认"。整个 runbook 在她的世界里无法执行。

每一行都是善意的，每一行都写得很清楚——但每一行都依赖了息壤不存在的系统。不是写错了，是前提不同。玄枢的桥治理建立在依赖注册表、构建系统、渡桥司这三个基础设施上——它们花了纪承钧和钟守玄和沈照痕几年的时间才建立起来。息壤的桥治理建立在 import 链、叶藏拙的账本、顾迁舟一个人的桥账上——不是更差，是不同。

季晚禾把册子还给周栖野。她的手指在"待确认"的标记上停了一下。"我不生气。但我觉得——外面的人以为我们有这些系统。但我们没有。我以为是我不知道——后来发现——是没有。不是'我找不到'——是'它不存在'。这两者——只能通过执行发现区别。"

叶藏拙在他的账本里写了一条——"收到跨卷 runbook。季晚禾按步骤执行。十七步中十一步标注待确认——无法执行。非执行者之过——前提不成立。"

"这不是谁的错。但有一个很重要的认知——你在你世界里的'理所当然'，在另一个世界里可能是不存在的基础设施。纪承钧写这份 runbook 的时候——他大概从没想过有人会没有依赖注册表。在玄枢那是空气——存在到不需要被注意。他的 runbook 在玄枢是最有效的流程——在息壤，它是一份'我们缺了什么'的清单。那份清单的价值比 runbook 本身更大。它告诉我们：我们需要依赖注册表。我们需要统一的构建验证。我们需要正式的桥治理机构。他的 runbook 用失败的方式帮我们画了一张地图。"

周栖野决定写一封回信。不是抱怨——是解释每一步的前提在息壤是否成立，哪些成立，哪些不成立，哪些在特定条件下成立但需要额外工具。

"这是最重要的一课——你的方法建立在什么前提之上？那些前提——在别人的世界里成立吗？如果你跨过了道的边界去发一份 runbook，请带上前提清单。不是为了保护你——是为了让收到的人能判断。我不知道你的世界的形状。你不告诉我你脚下的地基长什么样，我就不知道你的路能不能接上我的路。"

他停了一下，然后在信的末尾加了一行字。不是批评，不是感谢——是一句跨越道的边界的诚实。

"你的 runbook 还留在我们的公共记录板上。我不会删。它是我教新人'跨域文档的前提可能不成立'的第一课。谢谢你——替我准备了这份教材。虽然你当时不知道你在写教材。——周栖野。"

窗外，息壤的脚本林里有人在跑一个新的 notebook。散热塔不在这里——但路在延伸。从玄枢到息壤，从 C++ 到 Python——一份做了所有对的事的 runbook，在一个不知道的语境里，完成了它写的时候没想到的事。不是帮助——是教育。不是成功——是路标。
