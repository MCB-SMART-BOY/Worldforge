# 化形卷 · 第12章附 · 火种，林过川没有写完的那一行

白又新独立跑通季度结算之后的第二天，他在稳定骨的模块文档里发现了一个东西。不是代码。是林过川的一行旧注。那行注嵌在 `batch_legacy_adapter` 模块的最底层——桥拆之前，叶藏拙把整座桥的代码都做了静态快照，迁进稳定骨的不是桥本身，是桥里那段"专门处理某种特殊数据格式变体"的核心逻辑。林过川当年在这段逻辑旁边写了一行注：`此处格式非标准，待数据管道修复后移除此段。`

但下面还有一行。被后来的人压在更下面。白又新是在翻模块的完整提交记录时发现的。它不在正式版本里——是林过川在最后一次提交中加在注释末尾的。不是修正。不是说明。是一句被后来的版本覆盖掉、但 Git 历史里还留着的话：

`此段逻辑非我原创。源头：旧玄枢适配层手工修正#7。若后来者追溯至此——请知：此修正在玄枢已失传。息壤持有一份副本。非为替代——为存。若玄枢后来者需要回溯此修正的原始逻辑，此处可查。`

白又新把这段话读了三遍。然后他打开明契卷那边传来的诊断报告追踪记录——沈见微在第27章附里提过的那个玄枢旧修正，那个被钟守玄标注为"来源未知"的偏移修正。林过川留了一份副本。不在玄枢。在息壤。不是代码——是知识。一份在旧系统里已经失传的知识，被一个脚本沼泽里的守灯人悄悄存了下来。

· · ·

"他不是在搭桥。"白又新把发现告诉了周栖野，"他是在存火种。bridge_legacy_adapter 不是桥。是一座伪装成桥的火种库。他把玄枢已经不记得的东西，藏在了息壤的脚本林深处——等着某一天，有人来挖。"

周栖野沉默了很久。然后他把林过川那行被覆盖的注抄下来，贴进公共记录板。旁边加了他自己的一行："后来者已查。此修正的原始逻辑已被再次确认——并在此处保留副本。"

"所以林过川不是只留了一堆 final_v2_really_final。"叶藏拙翻着那行注，"他在最乱的地方藏了最重的东西。不是脚本——是他认为不该失传的逻辑。"

"他为什么不直接放到共享目录里？为什么藏在最底层？"

"因为直接放——三年就会被人删掉。藏在一段没有人敢删的旧桥代码深处——等一个会翻 Git 历史的人。"

白又新想起自己在第04章的十个脚本考古。那些 final_v3_merged_FIXED 的名字让他以为林过川只是一个被沼泽吞没的快乐点火者。现在他知道了。林过川是被吞没的——但他被吞没之前，在沼泽最深处埋了一盏灯。不是留给当时的人。是留给后来的人——留给他预感到有一天会来翻 Git 历史的人。

· · ·

当天晚上，白又新在稳定骨模块文档的最底层加了一页。标题只有两个字：`火种`。

下面不是技术文档。是一份声明：

`以下逻辑在此模块中保留——非为当前功能需要。为存。若后来者在其他道或其他系统中需要追溯以下逻辑的原始来源——此处可查。`

第一行就是林过川那条被覆盖的注——玄枢旧适配层手工修正#7。旁边标注了来源道、失传状态、保存人、保存日期。

"你这是在做什么？"宋既明问。

"给火种建目录。林过川留了一颗——如果还有更多人像他一样，在被沼泽吞没之前藏了东西在代码深处——它们需要被标注。不是被删。不是被拆。是被看见——然后被放进目录。"

"所以后来者不需要再翻 Git 历史。"

"对。他们只需要打开这一页。"

宋既明看着"火种"目录的第一行。玄枢旧修正。失传。保存人：林过川。确认人：白又新。

"你知道这一页让我想起什么吗。"他说，"驭器卷的残码。那张写着 [INHERITANCE COVENANT] 的散页。也是被藏起来的。也是在一个没有人会去翻的地方。也是等着后来的某一个人——把它从夹层里抽出来，问一句'这是什么'。"

"残码没有被批准。火种也没有。"

"但都被保留了。保留本身——就是继承的一种。"
