# 化形卷 · 第35章 · 宋既明登场

宋既明在公共记录板上贴出了三条标准。

"第一：环境声明完整——Python 版本、操作系统、依赖锁（uv.lock）。第二：最低复现链（MRC）从 `git clone` 到 `python main.py` 不能断。第三：不能有'我的机器上可以'——复现的验证必须在不依赖作者的机器上完成。"

他不是来提意见的。他是来建立"复现"这个概念的。在此之前，息壤的"能跑"是一个人打开自己的终端，输入命令，看到预期输出。那个"能跑"是主观的——依赖于那个人的机器状态、环境变量、系统配置。那个人离职或换机器之后，"能跑"就消失了。宋既明贴出的三条标准在说同一件事：不能复现就不算存在。不是代码不好——是代码不存在。它只存在于一台机器上，那台机器是作者的记忆的物理延伸。作者走了，记忆消失了，代码变成遗迹。

周栖野按这三条标准跑自己的十五个脚本。九个不通过。不是因为代码有 bug——是因为环境声明不完整。没有记录 Python 版本，没有记录安装步骤，没有记录"在这之前需要先装 openssl 和 libffi"。他自己知道这些步骤——他的手指记得，就像钟守玄的手指记得在凌晨输入那条命令的节奏。但后来者不知道。

"之前你们的标准——'周栖野的机器上能跑'——那才是随意。我的三条标准对所有脚本、所有人、所有时间一样。这是公平。"对于每个不通过的脚本，宋既明贴上"未成立"标签。"不是你的代码不好。是你的代码不存在。它只在你的机器上存在——那是你的想象。在我的标准下——它不存在。"

团队集体抗拒。"太严了。""不是严——是一致。公平是标准对每个人一样。"

审契者的角色不是被欢迎的——但他让"能跑"这个词有了可验证的含义。之前"能跑"是一个人的直觉。之后"能跑"是机器验证通过。"我不是来挑刺的。你们的共同目标是让季晚禾不需要打电话给作者就能自己跑通任何一个脚本。我替季晚禾做她做不了的事——替她验证那些脚本是不是真的'存在'。"三条标准是替所有不会写代码但依赖代码的人——在交付的末尾加了一道门。门上写着：请不要把作者的个人环境当成公共接口。
