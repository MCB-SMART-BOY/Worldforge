# 化形卷 · 第46章 · 顾迁舟的方法

顾迁舟开始给七条桥写退场日期。他发现最后一列空白比前面三列加起来都大，那张桥账上搭桥时间、类型、依赖方都填好了，唯独退场日期没人写过。

"退场日期空白，意味着桥永远不会被拆。不是没人想拆——是没有人敢说'我会拆'。说'我会拆'意味着你承认桥是临时的，你承认它的存在是一个过渡状态。而在息壤的文化里，承认'这是临时的'等于承认'这不是最好的'。没有人想承认自己的产物不是最好的。"

退场日期不是对未来的预测——是对未来的提问。写日期的人替未来的检查者问一个现在没人问的问题：这座桥还在吗，为什么？写在纸上的日期会到期，到期的时候就有人在桥账上看到它，然后去问。那个问题本身，就是进步——之前没有人问。

他逐座桥填写日期。那座只有季晚禾一个使用者的 shim，三个月后弃用，六个月后拆。桥上只有一个使用者，给她三个月过渡就够了。周栖野的 C++ 桥——两年后弃用。"两年？""桥上有一个外部系统依赖，它们的升级周期本身就是两年。不能更快。拆桥不是越快越好——是让桥上的人不会摔。"

周栖野看着自己那座桥被写上"两年后"，不太相信两年后真的会拆。但两年后的人会看到这个日期，他们会问——"这桥应该拆了，为什么还在？"那个问题本身，就是管理。

"退场日期不必完美。写日期的人不需要负全责——只需要给未来的检查者留下一个可以问的问题。你现在不敢确定两年后能不能拆——没关系。但你写了两年后，到时候会有人来检查。那个人不一定是今天的你，可能是后来者。你只需要给他们一个提醒：这里有一座桥，我们曾经打算在某个日期让它退役。那个提醒不是承诺，是入口。"
