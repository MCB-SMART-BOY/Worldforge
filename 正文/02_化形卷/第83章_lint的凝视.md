# 化形卷 · 第83章 · lint 的凝视

周栖野在固核层配了 pre-commit hooks——ruff 和 mypy 在每次 `git commit` 时自动运行。

第一个提交被 ruff 拦住了。不是 bug——是代码风格问题。ruff 告警："这个变量定义了但未使用。这个 import 重复了。这个 f-string 可以简化。"这些不影响功能，但它们让代码更嘈杂。每个未使用的变量都是后来者阅读时的负担——他们需要判断"这个变量是不是被忘在了某处"，每个重复的 import 都让后来者以为这里有某种依赖关系——实际上只是复制粘贴的残留。

"lint 不是'漂亮'——是'可读'。可读的定义：后来者在凌晨三点最快的理解代码意图的方式，不被不必要的噪音干扰。每一个 ruff 规则都是对这种噪音的一种消除。未使用的变量是噪音，重复的 import 是噪音，过于复杂的表达式是噪音。噪音不致命——但噪音累积。累积到后来者需要花比理解逻辑更多的时间来过滤噪音。lint 替后来者过滤了噪音，让逻辑本身成为唯一需要被理解的东西。"

一周后提交被拦截的次数几乎为零。不是审查更严了——是作者内化了规则。机器在教人写更清晰的代码，不是从美学的角度，从"后来者能不能读懂"的角度。在提交之前替后来者做第一轮判断。后来者不需要忍受噪音——机器在提交时就替他们走了。
