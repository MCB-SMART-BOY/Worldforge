# 化形卷 · 第61章 · 火种与废土

周栖野和叶藏拙开始清理林过川的遗迹。三千多个文件，目标是在废土中找到还能用的火种，迁入固核层。

他们给遗留资产分了三个类别。火种——有长期价值，可迁入固核层，需要补文档、测试、MRC。废土——不可迁移的遗留物，依赖的系统已不存在或逻辑已被替代，只能归档，保留作为考古证据。骨殖——曾经有功能但现在无法判断价值，需要考古者进一步分析。

前三百个文件的分类结果：十二个火种，剩下的多数是废土和骨殖。能明确判断有价值的不到 10%。大部分是"不知道有没有价值"——它们可能在跑，但没有人知道它们在哪跑、谁在依赖它们、解决的是什么问题。

十二个火种里有一套数据清洗流水线、一个 API 速率限制工具、一个日志解析器。代码质量很高，就是没有文档。"如果林过川多花一个时辰写文档，这些东西可以直接进固核。他不是没能力——他是没有把文档当成交付的一部分。"

叶藏拙翻出其中一个火种——`auto_field_mapper`。这个函数在四个不同的脚本中被 import——每个脚本都复制了一份。没有人知道原始版本在哪里。每次复制离原版更远，每次复制都不能被更新。四个版本在四年间各自长出了不同的 bug 修复和功能添加，彼此不知道对方的存在。"这就是火种的价值——如果不迁出它，它会继续被复制，每次复制离原版更远。火种存在于废土中——不是不存在，是没有人能确认它们的存在。清理遗迹的第一步是找到火种，第二步是给火种写文档、测试、MRC，第三步是让后来者能独立使用它们——不再需要林过川。"
