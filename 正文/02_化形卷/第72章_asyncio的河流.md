# 化形卷 · 第72章 · asyncio 的河流

入世层的 `field-mapper` 需要同时处理多个并发的 API 请求。同步版本每次只能等一个返回——一条请求卡住，后面全堵在门口。周栖野开始学异步编程（asyncio）。

协程（coroutine）——`async def` 定义的函数，可以暂停和恢复。事件循环（event loop）——调度所有协程的中央控制器，像一个调度员在多个任务之间切换。`await`——在协程中暂停，把控制权还给事件循环，让它去处理其他协程。不是多线程——是协作式多任务。线程是操作系统强制切换，协程是自己主动交出控制权。

"不是更快——是更可读。同步代码里的 callback 像拼命传纸条，你不知道纸条现在在谁手上。asyncio 像一条河——船依次经过，你知道哪条船在哪个位置。`await` 告诉你'我在这里等'，你不需要在脑子里模拟代码现在卡在哪个 I/O 操作上。同步代码的问题不是慢——是等待的时候 CPU 几乎不做什么，但整个进程被阻塞了。异步让等待的时间被利用起来——不是加速计算，是消除空等。"

化形之道的本质是流。Python 的异步不是最快的并发模型——但是最诚实的。它告诉你"我在等"。别的并发模型不告诉你，你得猜。在可见的世界里，有人能优化。在不可见的世界里，等是一种诅咒。async/await 是把诅咒变成可读的代码——"这里在等 I/O，这里在等网络响应，这里在等数据库返回"。读了就知道哪里可能卡，哪里需要优化。之前读同步代码需要心智模拟整个调用栈的阻塞状态，现在直接看 `await` 标记。不是更快，是更诚实。
