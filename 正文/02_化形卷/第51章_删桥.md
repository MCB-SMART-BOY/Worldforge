# 化形卷 · 第51章 · 删桥

三个月迁移窗口到期。`xirang-old-api-shim` 的退场日到了。这是息壤历史上第一条被正式写进制度、公开弃用、按流程拆除的桥。

顾迁舟执行退场三验证。第一，依赖者确认——七个使用者全部在公共记录板上签字确认迁移完成。不是口头说"我好了"，是每个使用者跑了一遍验证脚本，确认自己的新接口输出和旧桥输出一致。

第二，运行时验证——在删除前打开监控，看旧桥的最后二十四小时。有没有意外的调用？有没有人还在用但没确认？发现一个人在凌晨的备份脚本还在调旧接口——他忘了更新这个脚本。不是故意的。备份脚本在 cron 里跑了三年，他从来没打开过。顾迁舟等他更新，推迟了一天。

第三，代码归档。旧桥的代码不删除，移到 `archive/` 下，文件名加上退场日期。"桥的代码应该保留，作为'我们曾经需要这座桥'的证据。以后的人考古时应该看到这段历史——不是'不知道为什么有这段代码'，而是'这是桥——它活了两年，死于 Ch51，死于旧 API 不再被需要'。"

七个依赖者中的最后一个人——林过川时期的最后一个活跃使用者——他的脚本 import 过旧 API。新 API 的接口完全不同，他重写了调用部分。十五分钟。然后他说："这是林过川的 API，被用到了现在。它不再存在了。"不是悲伤，是陈述。旧的结束了，新的已经在跑。

第一条桥拆除成功。不是技术的成功——是治理的成功。桥有出生日期，桥有退场日期，桥的被依赖者提前知道了。桥的退场被记录，桥的代码被归档，桥的历史被保留。"这是息壤历史上的第一次——一座桥被有计划地退役了。不是因为它断了，是因为它的使命完成了。'临时'在这次有了终点。不是'不知道什么时候拆'——是'今天，拆了'。"
