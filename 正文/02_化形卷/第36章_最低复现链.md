# 化形卷 · 第36章 · 最低复现链

宋既明的三条标准贴出来之后，他加了一条更具体的：每个脚本在进入固核层之前，必须有一份最低复现链（`MRC` / `Minimum Reproduction Chain`）。"从零开始。不需要问任何人。十步以内跑通。如果走不通——不是执行的人的问题。是MRC没写清楚。"

周栖野写的第一份MRC只有七步。很自信。然后交给白又新——独立执行，不问他任何问题。

第一步：克隆仓库。通过。第二步：创建venv。通过。第三步："确保你的环境是正常的。"

白又新停了。

"这一步——什么算'正常'？"

"就是Python装好了，pip能跑。"

"我的Python装好了。pip能跑。版本是3.9。你的脚本用了3.11才有的语法。报错了。你的MRC没说需要3.11。"

周栖野沉默了。不是白又新刁难。是他的MRC里藏了一个他自己都没意识到的前提：Python 3.11。在他的机器上——Python版本是3.11，环境是"正常的"。所以他写了"确保环境正常"。但在别人的机器上——"正常"是3.9。"正常"不是一个可执行的命令。

"常识是最大的盲区。"宋既明说，"写MRC的人觉得'环境正常'是常识——因为他自己的环境就是正常的。执行MRC的人不知道这个常识——因为他的环境不一样。你的MRC不能依赖任何'常识'。"

· · ·

周栖野重写了MRC。从七步变成了十三步。

第一步不是"克隆仓库"。是`python --version`——确认Python版本。第二步，`python -m venv .venv`——创建隔离环境。第三步，`source .venv/bin/activate`——激活。第四步，`pip install -r requirements.txt`——安装依赖。每一步都是机器可执行的命令。每一步的输出都明确标注——如果成功你应该看到什么，如果失败应该先检查什么。

第十三步：`python -c "import xirang_field_mapper; print(xirang_field_mapper.__version__)"`作为最终验证——如果这一步正确完成，你应该看到版本号。如果看不到——回到第几步检查。

白又新独立执行。一步都没有问。一次通过。

"这十三步——前面的七步你不写不是因为你在藏私。是因为你不知道自己在依赖它们。你的手指记得。你的环境替你记着。但写MRC让你对自己的依赖有了自觉——你第一次知道'我需要什么才能让这段代码跑起来'。MRC不只是给后来者的。它是给自己的。写MRC的过程就是重新审视你的代码在别人的机器上是什么样子。你会发现你以为理所当然的东西其实不存在。那些不存在的东西——就是你的代码的盲区。"
