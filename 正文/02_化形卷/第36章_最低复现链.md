# 化形卷 · 第36章 · 最低复现链

宋既明要求每个脚本在进入固核层之前必须有最低复现链（Minimal Reproduction Chain / MRC）。"从零开始，不需要问任何人，十步以内跑通。"

周栖野写的第一份 MRC 只有七步。白又新执行——第三步卡住。"这一步写的是'确保你的环境是正常的'。什么算正常？"周栖野说："就是 Python 装好了，pip 能跑——"白又新打断他："我的 Python 装好了，pip 能跑。但报错，因为我的 Python 版本是 3.9。你的 MRC 没说需要 3.11。"

MRC 的每一步都必须是机器可执行的命令。`python --version`，不是"确保你的 Python 是正常的"。`pip install -r requirements.txt`，不是"安装必要的包"。`python -c "import xirang_field_mapper; print(xirang_field_mapper.__version__)"` 作为验证——如果这一步正确完成，你应该看到版本号。不能依赖"常识"，因为"常识"是最大的盲区。写 MRC 的人觉得"环境正常"是常识，因为他自己的环境就是正常的。执行 MRC 的人不知道这个常识——因为他的环境不一样。

周栖野重写了 MRC——从七步变成十三步。增加了 Python 版本检查、venv 创建、依赖安装、配置文件的自动生成。白又新独立执行——全部通过。没有问周栖野一个问题。

"之前的十三步——你不写不是因为你在藏私。是因为你自己不知道你在依赖它们。MRC 让你对自己的依赖有了自觉——你第一次知道'我需要什么才能让这段代码跑起来'。"周栖野沉默了一会儿。"叫它 MRC，但它不只是给后来者的。它也是给自己的。写 MRC 的过程就是重新审视你的代码在别人的机器上是什么样子。你会发现你以为理所当然的东西其实不存在。那些不存在的东西就是你的代码的盲区。"

MRC 的核心价值不只是让后来者能跑——它也让作者第一次明确知道自己的代码真正依赖什么。之前隐式的前提在写 MRC 的过程中被一条条拎出来，变成了显式的步骤。
