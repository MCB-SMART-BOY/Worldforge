# 化形卷 · 第21章 · 脚本林

叶藏拙带周栖野来到试法场最角落的架子后面。

"你一直在问林过川是谁。这里是他的遗迹。"

几千个文件。不是隐喻——是几千个实打实的 Python 脚本、notebook、CSV 导出、随手写的 README 片段、半成品的工具。它们堆在一个旧目录里，目录的名字已经没人记得是什么意思。文件名像地质层一样从有序到混乱——最早的几百个有规律，`data_cleaner.py`、`signal_parser.py`、`monthly_report.py`。后来的开始失控，`script_v2.py`、`script_final.py`、`script_really_final.py`。再往后，进入了另一种状态——`final_v2_really_final.py`、`copy_of_backup.py`、`do_not_delete` 目录下又叠了一个 `do_not_delete` 目录。

最新的文件是三年前的。一个叫 `README` 的文件，内容只有一行："对不起。"

不是技术文档——是一个人在离开之前留下的最后一句话。

"你看这些文件名。它们不是混乱，是一个人的信念的轨迹。每一次他命名 `final`——他都真心觉得这次是最后一次。然后需求变了，或者环境变了，或者他发现了更好的做法。然后他又写了一个 `final`。写了七次。"

周栖野开始翻阅。很多脚本引用了已经被删掉的模块，依赖了已经不存在的 API，调用了三年前已经废弃的外部服务。它们不能跑——早就不能跑了。但也有一些确实解决了真实问题——信号码解析、数据清洗、日报表生成。那些问题现在还在被解决，只是换了新的脚本、用新的方式、由新的人重写了一遍。

林过川的遗迹不是代码债。是"为什么没有人把他的好东西传下来"这个问题的答案。答案在文件名里——在他每次在凌晨写 `final` 却又被新的需求打回重做的时候，他没有停下来建一套能让后来者接手的结构。不是因为懒，是因为系统不奖赏建结构。系统只奖赏交付。他每次交付之后，留下的不是路，是脚印。

他在 `README` 前站了很久。三个字。这个人知道。他留下的不是秩序，是废墟。他知道。
