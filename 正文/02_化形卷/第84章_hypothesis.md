# 化形卷 · 第84章 · hypothesis

Ch48 的测试盲区——空文件炸了生产——没有人想到需要测试空文件。宋既明引入了 hypothesis，Python 的属性测试框架。

不是"给定 X → 应该返回 Y"，是"对所有满足条件的 X，属性 P 应该始终成立"。框架自动生成边缘案例——空 DataFrame、全 NaN 列、Unicode 列名、百万行数据、负值、超长字符串。这些是人类在写测试时几乎不会想到的输入——但它们在线上的某处真实存在。

周栖野为 `field-mapper` 写了三个属性测试。hypothesis 生成了三千个随机输入，发现了五个边缘情况——每一个都是他永远不会自己写进测试的输入。"空 DataFrame with Unicode column names。我以为这种情况不存在。hypothesis 说——它存在。"线上荒谬的输入每天都在发生——不是由恶意用户制造的，是由自动化脚本、数据迁移、编码错误、上游系统升级共同制造的。任何可能的数据形态，只要概率不为零，在足够多的调用次数下一定会出现。hypothesis 是在测试所有可能的数据形态。

五个边缘情况全部被修复并加到了 pytest 的固定用例中。hypothesis 不是替代 pytest——是补充。pytest 验证你想到的，hypothesis 验证你没想到的。"你写：当输入是 X 时，属性 P 成立。hypothesis 跑：当输入是 X₁, X₂, ..., Xₙ 时，P 还成立吗？其中几个 Xₖ 你从来没想过——线上已经有人在用了。传统测试验证已知的安全区，属性测试探索安全区的边界。边界之外就是线上事故。hypothesis 让边界更快被发现。"
