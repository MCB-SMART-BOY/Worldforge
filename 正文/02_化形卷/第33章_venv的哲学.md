# 化形卷 · 第33章 · venv 的哲学

周栖野一直抗拒虚拟环境（virtual environment / venv）。"太麻烦了。每次都要 `source .venv/bin/activate`。我的机器上所有东西都能跑。为什么要把已经能跑的东西分离开？"

宋既明没有反驳。他在季晚禾的机器上跑了周栖野的一个脚本，报错了。季晚禾的全局 `pip` 里有三十几个包——来自五个不同的项目。其中一个包（`requests` 的旧版本 2.20.0）和息壤的新需求冲突。她的机器不是花园——是五个人的垃圾场。每个作者都往她机器的全局 `site-packages` 里装了东西，她不知道这些东西之间的关系，不知道哪些可以删，哪些在悄悄被某个脚本依赖。她的全局 `pip list` 是一面墙的名字，每个名字背后都是一次"先装上再说"的决定。

"你的机器是一个花园——你种了三年。你知道每一棵植物是什么，为什么在那里，什么时候种的。季晚禾的机器是一块荒地——上面有五个人各自留下的种子，有些发芽了，有些烂了，有些在土里长出了互相缠绕的根。她不知道哪些是你的，哪些是岑照渠的，哪些是林过川的。她的全局 pip 是一份没有主人的遗产。"

venv 的隔离哲学不在"隔离"而在"声明"。每个项目独立一份 Python 二进制，独立一份 `site-packages`，独立一棵依赖树。从 venv 内部看——`pip list` 只显示这个项目的东西。后来者走进这面墙之内，看到的一切都是这个项目需要的，没有意外，没有全局环境中的幽灵包。墙之外的东西影响不到墙之内，墙之内的东西也不会悄悄污染别人的项目。

周栖野为息壤创建了官方 venv，把所有已验证的依赖锁定在里面。他做了一个测试，在自己的机器上删掉全局 `pandas`，息壤仍然能跑——因为 venv 里有它自己的一份。不是复制，是隔离。隔离是后来者的地图——每一面 venv 的墙都在说：这是你需要的东西。墙外的东西，与你无关。不是拒绝世界，是让你知道你在依赖什么。知道依赖是管理依赖的前提。
