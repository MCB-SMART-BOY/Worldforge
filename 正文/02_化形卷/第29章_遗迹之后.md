# 化形卷 · 第29章 · 遗迹之后

遗迹考古结束了。周栖野把林过川的脚本林、旧石镜的三段代码、测绘墙上的红黄绿标，以及三层图，全部摊在团队面前。不是展示——是交底。

"林过川不是孤例。在试法场最角落的架子上堆着几千个属于前人的文件，在旧石镜的 archive 目录里躺着三条不同时代的人写的代码——shell、Python、C——都在尝试做同一件事：自动交接。全部失败。失败的原因完全相同：交接工具本身需要交接，而他们手上只有代码，没有制度。工具的前提会随时间和环境改变，改变时没有文档声明、没有版本管理、没有人知道前提已经变了。所以每一代人的工具在离开之后就变成了遗迹。下一代人从头开始，重新发明同样的轮子，在同样的泥坑里停下。然后变成下一批遗迹。"

"林过川不是源头。"

"在他之前，有人也曾坐在这里。那个人留下的注释，跨过时间，最后一行写着后来者应该自己重新判断，和林过川在 README 里写的、和旧石镜壳上那一行铅笔字——在说同一件事。不是不努力——是在一个人的时代里，这个问题无法被单个人解决。"

"不是来骂前人的。是来搞清楚一件很具体的事——如果我们继续像以前那样做，我们的 track 就是林过川。那个速度会让你成为沼泽里最快的鱼，林过川的七个 final 是同一个脚本的七次。但最终你会留下一个只有三个字的 README。不是你的错——是你手里的工具只有代码。而代码不能解决制度的问题。"

"制度需要的东西不是更多代码。是版本管理，是依赖声明，是前提声明制度，是公共记录板。让每一代人停下的地方被记录下来，让下一代人不需要从零开始考古——他们只需要翻开记录板，看到前人的困境，然后继续。这些在玄枢已经被建起来了。他们叫它桥谱系、接火阶梯、伤痕制度。不是不能在我们这里建。是需要有人决定——'我们不再只是交付代码。我们也交付能让后来者继续交付的制度。'"

测绘墙上的红黄绿标还没有被擦掉。三层图还在旁边。林过川的脚本林暂时被搬到公共记录板旁边的架子上——不再是角落的废墟，而是公开的考古资源。每一代人不应该只是盯着自己的交付速度，而是应该偶尔回头看一眼——沼泽下埋着的是多代人重复失败的遗迹。那些遗迹不是垃圾，是路标。标注了"这里有人试过，他没成功，但他的失败不是没用的——他在沼泽里标出了最深的几个坑。"
