# 化形卷 · 第27章 · 全部失败

周栖野把三段代码按时间顺序排列在屏幕上。最早的 C 命令行工具。中间的 Python 工具。最近的 shell 脚本——仔细看日期戳，才发现 shell 脚本其实不是最早的，它夹在 C 和 Python 之间，属于另一个他完全不认识的人。

不是"一个人失败了，后面的人不知道，重复失败"。是"每代人都尝试了，每代人都失败于同样的结构问题——工具的前提会在下一代改变"。而每一代人不知道前一代人尝试过，因为在那个时代，没有公共记录板，没有桥谱系，没有任何记录"有人尝试过什么、在哪一步停下来的、为什么停"的东西。残码留在旧石镜里，只能在被偶然开机时被某人看到。

息壤的问题不是没有能人。每一代都有能人——林过川是能人，那个写 C 工具的人可能是更早时代的林过川。但没有制度，能人的能力只在他们的时代有效。他们离开之后，他们的能力变成了遗迹，而不是继续生长的阶梯。能人消失后，他们写的工具没人能维护，工具变成废铁，沼泽重新覆盖他们的脚印。下一代能人从零开始，重复发明同一个轮子，然后在同样的泥坑里停下。

"息壤的沼泽不会消失。只要制度不存在，每一代人都在重新发明同一个工具，然后看着它在自己离开之后沉入沼泽。这个循环不会自己停。能人延长了系统存活的时间，但没有改变系统存活的方式。方式应该是一套制度——前提声明、版本管理、公共记录板、依赖声明。制度让普通人也能够继承能人的工具，而不仅是在能人离开之后叹息。"

叶藏拙听周栖野说完，沉默了一会儿。然后翻开他的账本，翻到最早的那一页。上面写着第一行记录，日期是很多年前。"今天第一次看到林过川的 `final_v2`。不知道他是谁。不知道为什么叫 final。不知道还有没有 v3。"

"我记录沼泽很多年了。但我从来没有想过——沼泽下面埋着的是失败。不是能力失败，是制度失败。制度失败不能被更多的 code 修复。只能被制度修复。"

周栖野把三段代码放在脚本林的墙角，旁边贴了一行标注。"三代人，同一问题，同一失败原因。失败原因不是技术不足——是交接工具本身需要交接，而这需要的不只是代码，是制度。后来者，如果你在试图写同一个工具——请先看这三段。不是让你放弃——是让你知道，你需要的不是更好的代码，是更好的前提。"
