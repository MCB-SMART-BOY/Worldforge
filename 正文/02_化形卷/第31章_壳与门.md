# 化形卷 · 第31章 · 壳与门

岑照渠对周栖野提了一个要求：把他最常用的几个脚本做成正式的包（package）。"给它们一个门——让别人能从门进来，而不是翻窗户。你那些脚本，别人要用的时候得翻开你的目录，猜哪个文件是入口，猜对了还要猜它在什么环境下能跑。你应该给它们一扇门——门上有名字，有版本，有依赖声明。门后面是你的代码。别人不用猜——走进来就行。"

周栖野开始做第一个壳（wrapper / package）。目标：`field_mapper.py`——那个在叶藏拙账本里被记录"季晚禾放弃"的脚本。他写 `pyproject.toml`，声明 package 名字、版本号、依赖。写 `__init__.py`，定义公开接口。然后 `pip install .`，成功了。他让季晚禾测试。

季晚禾打开终端，`pip install xirang-field-mapper`，成功。`import xirang_field_mapper`，成功。调用主函数——报错。配置文件不存在。

"你的 README 说 pip install。我装了。import 成功了。但一跑，它说找不到 `/home/zhou/tmp/config.ini`。这个路径在你的机器上是对的，在我的机器上不存在。"

周栖野愣了一下。他的 `field_mapper.py` 第一行不是 `import pandas`——是硬编码了一个配置文件路径。那是他自己的 home 目录下的一个临时文件，三年前他自己放的，用来调试。后来调试完了，文件还在，代码里那条路径也还在。每次在他的机器上跑——文件在，路径对，一切正常。每次在别人的机器上跑——文件不在，路径不对。

"这不是你的脚本的 bug。是你脚本的前提不在代码里。前提在你的 home 目录下——那个配置文件。你的代码假设它存在。但你没有告诉任何人这个假设。"

壳是一扇门。门后面——你放了你的函数、你的变量、你的 docstring。但你在门口站了一个隐形的守门人：一个只在你的机器上存在的配置文件。季晚禾不知道有这个守门人，她甚至不知道它在第一级台阶上。她推开门，走了三步，被绊倒了。

做壳不难。难的是意识到：你的代码运行的前提不都在代码里。有些在你的环境里——home 目录下的临时文件、三年前设的环境变量、记不清什么时候装的系统级工具。你的环境不是别人的环境。做壳就是重新审视你的代码在别人的机器上是什么——这个过程会暴露你从来没意识到的前提。暴露不是坏事——暴露是修复的开始。
