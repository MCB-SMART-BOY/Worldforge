# 化形卷 · 第31章 · 壳与门

岑照渠把一层图——三层息壤的最外层——摊在周栖野面前。"壳。不是包装——是入口。你那些脚本，别人要用的时候得翻开你的目录，猜哪个文件是入口，猜对了还要猜它在什么环境下能跑。你的环境不等于别人的环境。你应该给它们一扇门——门上有名字，有版本，有依赖声明。门后面是你的代码。别人不用猜——走进来就行。"

周栖野决定从`field_mapper.py`开始。他有几分自信——这是他最常用的脚本之一，逻辑清晰，输入输出明确。他写`pyproject.toml`，声明包名、版本号、Python版本约束、依赖列表。写`__init__.py`，定义公开接口。然后`pip install .`，在自己的机器上跑——成功。

"叫季晚禾来。"

· · ·

季晚禾第一次试着从正式的包入口（`package entry point`）使用周栖野的脚本。不是翻目录。不是猜文件。是`pip install xirang-field-mapper`。安装成功。`import xirang_field_mapper`——成功。调用主函数——报错。

`FileNotFoundError: /home/zhou/tmp/config.ini`

她盯着那行路径。`/home/zhou/tmp/config.ini`。这不是她的家目录。她不叫zhou。

"你的README说pip install。我装了。import成功了。但一跑——它说找不到这个文件。这个路径在你机器上是对的。在我机器上不存在。"

周栖野打开`field_mapper.py`的第一行。不是`import pandas`。不是`from typing import`。是一行硬编码的配置文件路径（`hardcoded path`）。`CONFIG_PATH = "/home/zhou/tmp/config.ini"`。三年前他自己放的。调试用的。调试完了——代码还在。路径还在。每次在他的机器上跑——文件在，路径对，一切正常。每次在别人的机器上跑——文件不在，路径不对。三年来他从来没有发现过这行硬编码——因为三年来只有他自己在用这个脚本。

"这不是你的脚本的bug。"岑照渠指着那行路径，"是你脚本的前提不在代码里。前提在你的home目录下——那个配置文件。你的代码假设它存在。但你没有告诉任何人这个假设。"

· · ·

做壳不难。壳就是`pyproject.toml`、`__init__.py`、公开接口。难的是——在给别人开门的时候，发现你的门口站着一个你自己都忘了的隐形守门人。它在你自己的机器上从来不挡路——所以你从来不知道它在。只有当另一个人试着走进来——走到第三步——被绊倒——你才发现：你的代码一直在依赖一个只在你的世界里成立的前提。

壳是一扇门。但它也是一面镜子——它照出了你从未意识到的所有"我这边能跑"。

周栖野把那行硬编码路径改成了环境变量。不是删掉——是用配置声明替代硬编码假设。在README里加了一行：`本包需要环境变量 XIRANG_FIELD_MAPPER_CONFIG 指向配置文件路径。若未设置——使用默认配置。`

这不是修复一个bug。这是暴露了一个前提。把它从隐形的变成显形的。从"只有作者知道"变成"任何使用者都能在文档里读到"。
