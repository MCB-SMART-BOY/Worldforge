# 化形卷 · 第06章 · 神谕与迷雾

林过川的 README 贴出来之后，周栖野开始注意到一个之前被他忽略的现象。共享目录里有一些试验纸——不是他写的，不是唐野渡写的，是更早以前的人留下的——被团队当成了不可质疑的"神谕"。

他发现这件事是因为季晚禾。

季晚禾在准备北岭管理层月度汇报时，需要一组"数据管道健康度"的指标。她没有去查原始数据，而是直接打开了共享目录里一张叫 pipeline_health_v1.ipynb 的试验纸，点了一下"全部运行"。石镜上跳出一张漂亮的趋势图，曲线平稳，颜色柔和。她把图直接贴进了汇报材料。

周栖野刚好路过，扫了一眼那张图。"这是哪个时间段的数据？"

"上个月的。"

"你确定？"

季晚禾指了指试验纸上的标题——"数据管道健康度趋势（月度）。"周栖野没有看标题。他看的是试验纸内部引用的数据源路径。那个路径指向的是一个已经停用了两个月的旧数据管道。这张试验纸吐出的图——颜色柔和、曲线平稳——用的是两个月前的旧数据。

"这张图是错的。"

"什么意思？"

"它用的数据源已经停用了。它画的趋势是旧管道的历史数据。新管道的数据它根本没读。"

季晚禾盯着那张漂亮的图，脸色一点点变了。"我上周给管理层做的汇报——"

"用的也是这张纸？"

"对。"

"那上周的汇报数据也是错的。"

季晚禾把那张试验纸的文件名记了下来——pipeline_health_v1.ipynb。她在旁边加了一行注：数据源已于两个月前停用。输出不代表当前管道状态。不要再用作汇报依据。写完之后她抬起头，看着周栖野。"为什么没有人告诉我这张纸过期了？"

"因为没有人知道它过期了。"岑照渠从门口走进来，手里拿着另一张试验纸的输出——同样的问题，不同的数据源。"试验纸不像代码。代码有编译期检查——依赖变了，编译就报错，你立刻知道。试验纸没有。它唯一的验证是——作者当时跑通了。作者跑通之后就把它放在共享目录里。后来的人打开它，点'全部运行'，拿到一张图，以为这就是真相。没有人会去翻试验纸内部引了什么数据源、什么模块版本、什么外部API。因为——"

"因为它能跑。"周栖野说。

> "对。因为它能跑。这就是化形之道最隐蔽的沼泽。不是跑不通。是跑通了但你不知道它跑的是不是对的。"

· · ·

季晚禾把那张 pipeline_health_v1 的问题报告给了团队。岑照渠决定借此机会做一次系统性排查——把共享目录里被引用最多的二十张试验纸全部翻出来，逐一检查依赖版本、数据源有效性和输出一致性。

排查结果在当天傍晚的团队会议上公布。二十张试验纸里，六张引用的数据源已经变更或停用。四张引用的依赖模块已经有过破坏性更新。两张的输出和当前数据手工核对的结果存在显著偏差。还有一张——最老的那张 revenue_check_v1.ipynb——引的 data_utils 是两年前的版本，而共享目录里现在有四个不同版本的 data_utils，没有人知道这张纸用的是哪一个。

"你们在拜神。"岑照渠把结果投到石镜上，"不是写这些纸的人想当神。是没有人告诉后来者——这张纸只是某个时间点的试法记录，不是永恒真理。试验纸不会自动标注过期日期。试法不会自动告诉后来者'我不再可信了'。"

白又新举手。"revenue_check_v1 被七个不同的流程直接或间接引用。如果它的输出是错的——"

"那七个流程的结果都是错的。"宋既明替他说完了。

会议室里安静了几息。然后季晚禾问了一个所有人都想过但没有人敢问的问题："如果连被引用最多的试验纸都可能是错的，那我们怎么知道哪些还能用？"

"没有办法。"周栖野说。他站起来，走到石镜前，把那张 revenue_check_v1 的输出和岑照渠手工核对的结果并排显示。两边的数字差了不到百分之二。但对于季度结算来说，百分之二不是小数字。"除非我们给每一张试验纸加一个过期检查机制。不是靠人记。是靠系统自动提醒——'这张纸引用的数据源上次更新是两个月前，请确认仍然有效'。"

"那不是化形之道的风格。"唐野渡说。他靠在门边，但语气不像平时那样轻快。"化形之道讲究快——先跑起来，先看见形。过期检查是慢功夫。"

"对。"周栖野说，"但我们已经快了很多年了。快到了连自己用的数据是不是对的都不知道。也许该慢一步了。"

唐野渡没有反驳。他看着那张 revenue_check_v1 的输出，沉默了片刻。"我上周给北岭出的那两张延迟对比图——如果两个月后数据源变了，它们就是下一对 pipeline_health。"

"所以你打算怎么办？"

"给我的图加过期日期。"唐野渡走到石镜前，在自己上周出的一张图的标题下面加了一行小字：本图基于截至今日的数据源生成。数据源如有变更，本图自动失效。请在引用前确认数据源版本。

"这行字会让人犹豫。"周栖野说。

"对。犹豫是好的。"唐野渡把石笔放下，"不犹豫的人会拿着过期的图去做决策。犹豫的人至少会先问一句'这图还准吗'。"

会议结束后，岑照渠在那张 revenue_check_v1 旁边加了一个醒目的红色标签：已过期。标签下面写着过期原因和替代方案。然后她把排查结果整理成一张表，贴在公共记录板旁边。表的最上面写着一行标题：试验纸不会自动过期。神谕不是恶意制造的——是没有过期机制的必然产物。后来者以此为鉴。

> 白又新在自己的记录本上写下今天的第六行：后来者需要的不只是能跑的脚本。是需要知道哪些脚本已经不能再跑、以及为什么。他写完，在下面又加了一行更小的字：试验纸不是神谕。试验纸是某个时间点、某个环境、某组依赖版本的快照。快照会过期。只有作者知道它什么时候过期。如果作者不写——快照就变成神谕。没有人敢质疑。直到有人因为信了神谕而做错了决策。
