# 化形卷 · 第63章 · 从 README 开始

白又新选择了林过川的另一份火种——`data_cleaner`。没有 MRC，没有测试，没有任何文档。只有一个 README，内容三个字："对不起。"

从这三个字出发，他必须自己重建所有知识。代码在跑，但他不知道应该怎么跑——没有参数文档，没有输入示例，没有预期的输出格式。函数签名告诉他输入类型，但不知道输入的数据长什么样。异常处理告诉他作者预期了一些不正常情况，但不知道那些不正常情况在实际使用中出现的频率。注释里有只言片语——"这块的速度有问题，以后再优化"——但没有说为什么"以后"从来没有来。每次他猜错一个参数的含义，就要重新跑一次。每次重新跑都是一次"林过川在另一个世界里没有告诉我"的惩罚。

他用了两天。从代码里重建设计意图。函数签名推断输入输出类型，硬编码的路径推断预期的文件结构，异常处理推断作者预期的不正常情况，注释推断作者认为值得标注的信息。他写了 MRC，十四步。每一步旁边都有注释："这一步是猜的，基于第 X 行的一个注释。"其中三步他猜错了——反复验证后修正。最终 `data_cleaner` 在他的环境中跑通了。

他在林过川的 README 上，在"对不起"下面加了一行。"没关系。我替你写了。后来的人不会需要对不起。"

"你用两天时间填补了林过川沉默了三年的空白。"

"不是填补。是翻译。林过川在代码里说了所有东西——但他没有翻译成后来者能读的语言。我做了翻译——不是创造。"

极限继承的价值——继承者不是被动的接收者，是主动的翻译者。林过川的沉默不是恶意，但翻译是必需的。不是所有继承者都有时间翻译——这就是为什么需要一个人先翻译好。那个人曾经应该是林过川自己。他没做。白又新替他做了。不是为了让林过川的遗憾消失——是为了让下一个后来者不需要多花两天。
