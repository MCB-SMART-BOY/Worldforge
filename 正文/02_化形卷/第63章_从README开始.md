# 化形卷 · 第63章 · 从 README 开始

白又新选了林过川的另一份火种——`data_cleaner`。没有MRC。没有测试。没有任何文档。只有一个README，内容三个字："对不起。"

从三个字出发。他必须自己重建所有知识。

代码在跑——但他不知道应该怎么跑。没有参数文档。没有输入示例。没有预期的输出格式。函数签名（`function signature`）告诉他输入类型是DataFrame——但不知道DataFrame里应该有什么列，列名是什么，数据类型是什么。异常处理告诉他作者预期了一些不正常情况——空文件、字段缺失、编码错误——但不知道那些不正常情况在实际使用时出现的频率。

代码里有注释。散落的。"这块的速度有问题，以后再优化。"没有说为什么"以后"从来没有来。没有说"优化"的方向是什么。没有说这段代码的瓶颈在哪。"这个参数默认值来自北岭旧系统。"没有说北岭旧系统还在不在。没有说参数默认值是否需要更新。

每一行注释都是一句没有说完的话。林过川留下了入口——但入口被沉默封住了。

· · ·

白又新用了整整两天。从代码里重建设计意图（`design intent`）。函数签名推断输入输出的类型和结构。硬编码路径推断预期的文件布局。异常处理推断作者担心的边界情况。注释推断作者认为值得后代知道的——但没说完的——信息。

他写了MRC。十四步。每一步旁边都有注释——"这一步是猜的，基于第X行的注释。""这一步是我试了三次才跑通的——原始代码里有个隐式的文件路径假设。"

其中三步他猜错了。反复验证后修正。最终`data_cleaner`在他的干净环境里跑通了。

他在林过川的README上，在"对不起"下面加了一行。"没关系。我替你写了。后来的人不会需要对不起。"

"你用两天填补了林过川沉默了三年的空白。"

"不是填补。是翻译。林过川在代码里说了所有东西——但他没有翻译成后来者能读的语言。我做了翻译。不是创造。"
