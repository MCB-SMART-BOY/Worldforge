# 化形卷 · 第42章 · 桥的出生证

顾迁舟开始给每座桥补出生证。不是新造，是把桥上的注释、git log、群聊记录里散落的"当时为什么"找回来，填进一张统一的表里。Author——谁搭的。Date——什么时候。Reason——为什么搭。Sunset Condition——在什么条件下退场。Consumers——谁在用。Why Sunset Missed——为什么退场条件满足了但桥还在。

六座桥的出生理由全部合理。每一个都是当时最好的选择。没有一座是恶意的，没有一座是懒惰的。FFI 桥——玄枢那边当时没有 Python 接口，C++ 是唯一的选择。Excel 桥——财务团队需要，只能用 Excel，没有任何替代方案。旧 API shim——外部系统还在用旧协议，不能直接改。每一个"最好的选择"在当时都是省时间的，在后来都变成了长期维护负担。不是选择的错——是"省时间的临时方案没有自动变成需要重新评估的长期承诺"这个系统缺陷的错。

第七条——`xirang-unknown`——没有任何信息。没有 git commit，没有作者，没有注释。只有部署日志里的"hotfix - 3:17am"。叶藏拙翻他的账本，找到一条对应时间的记录——那天凌晨玄枢断火，息壤有好几个外部接口跟着报错，有人紧急搭了这条桥让系统撑过那晚。"可能是周栖野，也可能是林过川。他们可能在半梦半醒中搭的。桥已经在跑了，问题消失了。于是没人提。"

桥的出生证不只是考古——是为拆桥做准备。你不知道桥为什么出生，你就不知道它能不能死。你不知道桥上站着谁，你就不知道拆了之后谁会掉下去。

"桥必须写明退场日期——哪怕那个日期是错的。错了可以改。没有日期，就是'永远不会拆'。但退场日期只是第一步。第二步是——到那个日期时，有人回来检查。制度负责让人回来。不是指望搭桥的人在几年后还记得。"
