# 明契卷 · 第77章 · 形式化的边界

裴照川引入了形式化验证工具——Kani、Creusot——把明确写下的性质交给工具检查。Kani 在给定的 harness、输入范围和循环展开界限内检查执行；Creusot 则把带契约的 Rust 程序转换成证明义务。它们不只是多测几个样例，但结论只覆盖已声明的性质、模型、前提和工具实际证明的范围，不能笼统说任意属性对所有输入都成立。

但形式化有边界——不是所有东西都能被当前的证明模型完整覆盖。I/O、系统调用、并发交互和外部环境通常需要抽象或额外建模；没有纳入模型的行为不会因为证明通过就自动安全。形式化检查能覆盖的是已经描述并成功证明的性质。边界之外的——仍然需要测试、观测、文档和人的判断。

"形式化不是替代测试——是补充。测试覆盖'我选来检查的输入'。形式化工具可以在指定模型和前提下证明某个性质——覆盖到多大范围，取决于证明方法和边界。两者之间——是人的判断——哪些输入和交互需要纳入——哪些边界还没建模。形式化验证不了的——仍需安全论证和其他证据；形式化验证通过——也要审查规格与假设是否符合现实。"

裴照川在青炉的核心模块上加了形式化证明——在 Creusot 的契约和循环不变量下，证明某个排序算法的输出满足升序性质。不是"我测了十个数组——都排对了"——而是把输入、前置条件和排序后置条件写清，让证明器检查契约是否成立。结论仍受规格和证明工具覆盖范围约束；reviewer 不必逐项手算每个边缘输入，但仍要确认写下的性质就是系统需要的性质。
