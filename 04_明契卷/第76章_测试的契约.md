# 明契卷 · 第76章 · 测试的契约

测试不只是验证代码——也是把某些预期行为写成可重复检查的约定。每一个测试用例都在说"在这些输入和条件下——我们预期这个行为"。如果后来者改动了它——测试会提醒他们行为变了；这是不是对外承诺、是否需要通知使用者，还要看接口和变更影响。

Rust 的测试体系——单元测试通常和代码放在同一个文件中、集成测试放在 tests 目录、文档测试可以验证文档中的代码示例。`cargo test` 会运行配置启用的测试目标和文档测试，也会默认编译 examples；普通示例不会因此自动运行。每次 CI 跑测试——既是在找回归，也是在检查已写下的行为约定是否改变。若改动影响对外 API 或兼容性，再由发布流程决定通知方式和迁移指南。

"测试不只是写给机器跑的——也是给后来者看的。好的测试名能描述预期行为和场景，测试列表可以当作一份行为目录。但光看名字不能知道所有使用者依赖什么——还得读断言、接口文档和调用方。后来者想改某个行为——先看测试，再查它的边界和实际使用者——然后再改。"
