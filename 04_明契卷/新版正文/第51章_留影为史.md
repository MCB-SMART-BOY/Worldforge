# 第51章《留影为史》

Git commit保存文件快照和提交元信息，说明文字则能为代码补上一条可追问的理由。

沈见微写下青炉的第一个commit：只有scope，以及根目录和成员目录里的`Cargo.toml`。Ch27复走过的原型源码、测试和已经生成的`Cargo.lock`仍留在工作目录，尚未进入版本历史。

季循看着空下来的`src/`路径：“后来的人能从这次提交复走什么？”

“现在还不能。”沈见微没有把它称作可复现的项目基线，“它只记录了范围和包关系。共享之前，我们还得把源码、测试和复走步骤纳入仓库。不能拿本地通过的结果，冒充仓库里已有的能力。”

他在提交说明里写明本次收录了什么、哪些验证材料仍缺席。`git log`可以让后来者找到这条记录；`git blame`能把一行代码指向最近一次改动，再沿着`git show`、提交记录和评审讨论追查上下文。但工具留下的是线索，不会替作者补出当时的判断。眼下这次提交尤其如此：它能说明青炉从哪里起步，还不能让别人重建那次试验。
