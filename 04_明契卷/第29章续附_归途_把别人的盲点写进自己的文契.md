# 明契卷 · 第29章续附 · 归途，把别人的盲点写进自己的文契

从旧屋回来的路上，沈见微没有和任何人说话。他坐在顾迁衡的车后座，手里捏着那张从石镜前带回来的纸——上面是他在那一夜加写的第六句：`先写自己的盲点——并请别人来补。`

回到北院已是清晨。季循在炉房门口等他，膝上摊着记事板。板上是他自己在那几天里重新翻过的所有青炉对外承诺——接口契约、发布说明、前提声明、变更影响声明模板。他在每一条旁边都用红笔标了一行小字：此条的前提声明中没有写明——本道的盲点是什么。

"你一直在做这个？"沈见微问。

"那夜你们去旧屋之后。我想了很久——如果纪承钧的传讯能击穿你，那是因为他看到了你没有看到的东西。如果连你都有看不到的东西——那青炉的每一份对外承诺，也都可能有。"

他把记录本摊开。第十七条——青炉预备公开 Rust crate API 的接口契约模板；当前公共包仍只发布命令器，不对外提供 `qinglu-core` API。季循在旁边写的是：`本道盲点：这份安全 Rust API 契约把 Rust 调用方的编译期检查当作背景。它不能直接支撑跨语言或 FFI 调用。对此类调用，必须另写指针生命周期、同步与错误边界，并用相应集成测试验证。`

这不是批评。这是补全。

· · ·

沈见微花了整整一天，把青炉所有对外文契重新翻了一遍。每翻一份，他就做三件事：先确认前提声明是否完整；再确认失效条件是否写清；最后——问自己一个在石镜之前从没认真问过的问题：这份文契的哪个地方，只有我这个道的人能看见——别的道的人看不见？

他翻到第27章附的那份跨卷诊断报告。那份报告发出前，顾迁衡说它"太干净了——没写桥上的人"。后来他补了前提声明——写清了观测条件。但现在他再看，仍然少了一行。

他在报告的末尾加了一段——不是给收报告的人看的前提，是给自己看的：

`本报告的观测来自青炉侧；其中关于队列、并发上限和重试的建议，假设对方有能力采用这类调度机制。若没有，不应照搬，须与对方共同寻找可执行的替代方案。此即青炉之盲点：以己之道量人之道。`

然后他把这段话也复制到了诊断报告模板的底部——不是附录。是正文的最后一段。命名为：`本道盲点声明`。

· · ·

闻衡是傍晚过来的。她翻完沈见微加在每份文契末尾的盲点声明，沉默了片刻。

"你以前写的是——'先写失败。先写资源边界。先写行为承诺。先写后来者能否复走。先写前提——并声明前提可能不成立。'现在加的是——'先写自己的盲点——并请别人来补。'"

"对。"

"这几行——从最早的文契到今天的盲点声明——记下了青炉一路走来的选择。"

"不止是青炉的。"沈见微说，"纪承钧在旧屋里说了一句话——'我们每个人都只建了一条路。可后来者要走的是整个地面。'我之前理解的'写清楚'——是把我的路写清楚。但我没想过——我的路写清楚之后，后来者仍然需要知道：这条路在什么地方会断。在什么地方需要换别人的路。"

闻衡没有接话。她只是翻开青炉文契的目录页，在第一章那四句旁边，用很小的字引了一行来自简阵卷的话：`"绿色不意味着活着。"`

然后她在下面加了自己的注：`文契不意味着全知。声明——是为了让看不见的地方也被标注。`

· · ·

季循在收工前把青炉文契的封面翻开，在第一页——那页只有标题"青炉文契"——的下面，加了一行他进入青炉以来自己写过的最长的话：

> `青炉之契，非全知之契。安全 Rust API 的编译期保证只适用于安全 Rust 调用；跨语言与 FFI 调用另须写明指针生命周期、同步和错误边界，并补做相应验证。本契之盲点：把一种语言的静态保证误当成所有调用方共有的前提。`

他写完以后，把笔放下。抬头看向沈见微。

"这不是对你写的东西的否定。"

"我知道。"

"这是对它的完成。"
