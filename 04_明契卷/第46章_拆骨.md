# 明契卷 · 第46章 · 拆骨

青炉已经有 `qinglu-cli`、`qinglu-config`、`qinglu-core` 和 `qinglu-doctor` 等 workspace 成员。随着构建与报告职责继续长大，沈见微又把其中混在一起的代码拆出 `qinglu-build` 和 `qinglu-report`，让核心逻辑、构建流程、报告输出各自有清楚边界；原有成员仍留在 workspace。

不是"我觉得太大了"——而是这些代码服务于不同的使用者，有不同的承诺周期，边界值得拆开。程知序只需要 build，不需要直接依赖 report；新的依赖图让他能看清自己拿了什么，也让团队可以检查哪些变更与他无关。拆分并不保证 core 的任何变化都不会影响 build；能否不改调用方，仍取决于公开 API 是否兼容。

"拆分不是重构——是重新承诺。每个 crate 要写清自己承诺什么、不承诺什么。它们可以独立发布和定版本；workspace 仍共享根 `Cargo.lock`，但这不代表版本会自动一致，也不保证接口兼容。以前 build 直接拿 core 的内部类型，一处实现调整就让它编不过。现在 build 只通过 core 的公开 API 交互；只要公开约定保持兼容，内部改动就不必牵动所有调用方。若公开约定要变，各自的依赖和发布仍须明确升级。拆分时我们也重新审计了每个模块的可见边界。"
