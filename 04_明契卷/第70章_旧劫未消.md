# 明契卷 · 第70章 · 旧劫未消

青炉 1.0 发布后，第一个外部使用者程知序报告了兼容问题——他把项目依赖从旧版本升级到新版本后，代码编译不过。MAJOR 版本号确实上调了——但 changelog 没有说明这项 breaking change，也没有给出迁移线索。

沈见微追查——发现是六个版本前的一个 trait bound 改了——当时以为是内部实现细节，没有标记为 breaking。但使用者在自己的代码中直接依赖了这个 trait bound。"我以为没人会用到那个 bound——但程知序在自己的项目里写了一个泛型函数，依赖了那个 bound 的具体约束。我改了它——他的代码在升级时突然编不过。"

那次升级让整个 crate 编译失败——几百个错误。版本号已提醒程知序这是一次不兼容升级，但 changelog 没说具体改了什么，迁移只能从编译错误和源码里一点点倒推。"你的 changelog 没有写这行更改——因为它在一个不被注意的 PR 里被合了。changelog 不能只凭维护者记忆凑——应当从已审查的变更记录和发布内容里核对出来，再由人确认使用者需要知道什么。"
