# 明契卷 · 第78章 · 收到传讯

纪承钧的传讯到了。不是指责——是"你的诊断报告 v0.3.1 在玄枢炸了"。

沈见微读第一遍的时候是困惑。扫描与统计确实只覆盖青炉可见的依赖锁文件、已接入调用源和静态分析范围；他也在扉页写了"未知依赖不在检查范围内"。可工具仍把观测窗内没有调用记录的接口标成"可安全废弃"。这不是统计错误，而是他把有限观察翻译成了超出证据的处置结论。免责声明说“请在接收方确认”，绿色标签却先替接收方作了判断。

但玄枢那边没有可供他查询的集中依赖注册表，`legacy-report-gateway` 的消费者也没有登记。那个接口的依赖——藏在六年前的 Makefile 注释、Unix domain socket 和凌晨丑时的备份脚本里。不在他能查到的数据里。他写了"未知依赖不在检查范围内"——但他不知道未知依赖有多大。他不知道其中有一个凌晨三点十七分搭起的 hotfix——没有作者、没有文档、没有 git commit。

第二遍是恐惧。纪承钧在传讯里没有把责任全推给报告：他看见本地 socket 未观测，也知道退役核查没有闭合，仍批准了维护窗移除；绿色标签和青炉侧零调用给了他错误的确信，值守与回滚只缩小风险，没有补上证据。两处选择接在一起，才让旧接口退出生产。梁故川清空记录板的缘由，他还没有查清；那句"此处逻辑不应被文档化"却让他想起同一种风险：写下来的东西可能在另一处被当成无条件保证。纪承钧的 runbook 也曾在息壤受阻——"确认所有下游依赖方已全部迁移"在那里是不可执行的步骤。写清楚——仍须让接收者看见条件，也不能替他完成核验。

纪承钧在传讯结尾没有说"你错了"。他说的是——"继续。"

"我写这封传讯——不是让你停止。是让你继续——同时知道——'对的事——在不知道的语境里——是不够的事。'你的诊断报告——会去往其他地方。每一次——都可能在不同的语境下炸掉。不是因为你做得不够——是因为没有一个人——在所有的地方——都看得见。我们——都在——各自的——世界里——对的人——但——世界和世界之间——有人——站着——在看不到的地方——依赖着——你以为——没人在用的——东西。"

第三遍是一个暂时判断。梁故川为何清空记录板，仍待查证；但这次事故不能只靠再添一行免责声明修好。他打开报告生成器，把绿色状态字段改成两项事实："观测窗口内未见调用"和"覆盖范围"；没有任何自动结果再叫"可安全废弃"。若需退役评估，接收方必须补录本地调用来源、未覆盖的通道和核验人；有盲区就保持待核。纪承钧那边已经留下了另一半教训：即便知道有盲区，也不能把监护和可回滚当作批准删除的替代证据。

沈见微在青炉记录板上写下："此报告——基于青炉侧的可见依赖。在玄枢——它炸了。伤痕在此——不删。后来者——如果你收到跨域 runbook 或诊断报告——先问——那个世界的前提——在你的世界成立吗。工具不得把没有观测写成安全——接收者也不得把待核当成批准。——前提可能不成立。——沈见微。"

韩砺年在远处看着。他看到了梁故川清空记录板那天——也看到了今天。同一个问题——写清楚在边界处会炸——两个人可能走向不同的回应。梁故川为何停在那行"不文档化"旁边，仍需从他的旧记录里继续查；沈见微此刻先在自己的报告边界上添了一行路标。它能否让另一个世界少走弯路——还要等后来者验证。
