# 明契卷 · 第61章 · 守界

在 safe Rust 的范围内，所有权（ownership）、借用（borrowing）和生命周期（lifetime）规则让编译器能拒绝许多悬垂引用、重复释放和别名冲突。这个保证属于安全抽象的边界；若代码借 `unsafe` 或外部 C 库越过边界，正确性还取决于人是否满足并维护那些额外前提。

程序员不必只靠记忆维护每一条引用关系——编译器会按类型和借用规则检查它能验证的部分。"你说'我借用这个值'，编译器就会追问：借用还活着时，所有者能不能被释放？有没有另一条冲突的可变借用？"这道约束能挡住一类内存错误，却不替人保证程序逻辑都正确。

青炉的一个模块在旧工具链中是 C 写的——裸指针、手动内存管理。迁移到 Rust 时，原来的指针操作被替换成引用和生命周期标注。编译器在第一次编译时拒绝了它——因为一个借用活得太久，可能与另一个可变引用同时存在。在 C 中，这段代码可以通过编译；如果这些引用关系在运行时真的同时成立，就可能造成未定义行为，例如内存访问错误。在 Rust——编译期就拦住了这组不满足借用规则的引用。"不是编译器讨厌你——是编译器替你检查它能证明的内存约束。编译器不骗人，但人会骗自己——觉得自己记得所有指针的生命周期。"
