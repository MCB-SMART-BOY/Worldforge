# 明契卷 · 第86章 · 放弃"写清楚就是一切"

纪承钧的传讯击穿之后，沈见微在青炉的公共记录板上站了很久。

他在想梁故川。那个在他之前来到青炉的人——写文档、写 scope、写"为什么"——然后有一天清空了记录板，只留下一行字："此处逻辑不应被文档化。"然后离开。梁故川是否因为担心跨域说明失效才清空记录，沈见微仍不能确定；旧笔记至少让他看见，接收者若读不懂前提，写下来的东西也可能被误用。

沈见微拿起笔。他要在同一个位置——梁故川清空的地方——写下另一种回答。

"我放弃'写清楚就是一切'。"

"我仍然会写清楚。写每一个接口的输入、输出、错误处理——写每一条 unsafe 的安全论证——写每一个 trait 的设计理由和替代方案。但我会在第一行写清楚：'以下内容的前提——在你的世界里可能不成立。——你的前提——可能和我不一样。'写清楚不是保证正确——是让错误在发生时能被追溯。写清楚——不是一切——是知道自己的边界——并在边界处标注——'这里——我的清楚——可能不够。'"

他停了笔。看着自己写下的字。

"梁故川——我还不知道你为什么清空记录板。那行旧注让我猜：你也许怕自己的判断被后来者当成不容质疑的真理。经历过跨域爆炸的人——知道这种风险确实存在。但我不能替你断定——沉默是不是你当时唯一能找到的回答。沉默会让后来者没有入口——可你留下那行字，或许也是想让人停下来重看。你当时还留下了什么——我得继续查。"

"我选择写——并在第一页写'前提可能不成立'。也许我们面对的是同一类风险——但我还不知道这是不是你当年停笔的理由。你的沉默和我的声明——可能是不同年代给出的两种回应。若你担心自己的字变成墙——我就先在自己的字旁标注：'此处是纸——前提可能不成立。'这能不能让墙变成门——还得由后来者检验。"

"也许你的时代还没有'前提声明'这种格式——也许你试过写，却遇到了别的问题。如果你能把承诺的前提和失效条件一并留下——后来者至少能判断哪些部分需要重验。可我不知道，这会不会改变你清空记录板的决定。以下这句话，是我给现在的文档写的试法——不是替你补写过去：'内容基于青炉的考古——在 Rust 1.x 与 Linux 的前提下成立；如果你的环境不满足这些前提，请先验证。'"

他在梁故川留下的那行"此处逻辑不应被文档化"旁边——刻上了新的字。"此处逻辑的前提已被声明。——此后失效条件被标注。——你可以文档化。——前提可能不成立。——沈见微。"

不是反驳——是把另一种做法写出来。梁故川的话没有被擦掉——它被保留了——作为路标。路标说：这里有人停过；他为什么停、还有什么经历，后来者仍可继续查。沈见微能先做的，是留下自己这次选择的前提。

"放弃不是失败。是让写清楚知道——它有一个边界。——在边界内——它是路。——在边界外——它是墙。——知道边界在哪——比假装没有边界——更诚实。——诚实——是写清楚的前提。——前提可能不成立——但方向是对的。"
