# 明契卷 · 第49章 · 门规初稿

第一版门规——CONTRIBUTING.md——被贴在青炉记录板上。

对外发布的公共 API 新增或发生兼容性变化时，必须经过闻衡或指定审契者审查，并记录审查结论。影响用户或发布内容的变更须写入 changelog，说明变更内容及受影响的调用方。错误类型和文档应让调用者知道可采取什么处理；是否恢复由具体场景决定，不用“可恢复/不可恢复”两类标签替代判断。每处 `unsafe` 都必须附带安全论证，说明编译器无法验证的前提以及代码如何满足这些前提。

这不是沈见微一人说了算——规则由闻衡和团队讨论，先约束对外承诺与发布流程。季循的排序样本、原型接口里未说明的错误信息、顾迁衡的临时桥，各自暴露了不同的缺口；门规不把它们伪装成已经发生过的生产事故。

"不是限制——是保护。保护使用者不被没写清楚的承诺伤害，保护维护者不被不知道影响的变更压倒。门规不是惩罚写错代码的人——是让写对的代码能清楚地传递到使用者。"
