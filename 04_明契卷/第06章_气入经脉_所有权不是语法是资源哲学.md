# 明契卷 · 第06章 · 气入经脉，所有权与资源边界

北院的雨是在后半夜落下来的。

雨线打在东廊瓦沿上，一阵密，一阵疏，把那间小室外头的声音都压得很远。

屋里却不静。

青炉第一张 `Cargo.toml` 写定以后，真正难的事才刚开始冒头。

程知序把两份样本抄片摊在长案上，一份是错版夜发时最常见的发版校验单，一份是她刚从外侧拿回来的新窗口样本。

"纸写完了。"她说，"现在总得让它做第一件真事。"

沈见微点头。

"从最小的 `check` 开始。"

季循对这个词已经不算陌生了。

最小检查入口（`check`），就是让青炉先去看一样东西是不是合格，而不是一上来就承诺替所有人做完所有事。

可真到动手的时候，他还是很快碰见了昨天没碰到的新麻烦。

第一份样本一跑，石镜上就开始往外吐临时文件路径、构建产物路径和中间记录。

第二份样本还没开始，苏野平已经伸手在另一侧镜面上点了几下，随手写下三行旧法：

共用一个临时目录。

共用一份旧缓存。

谁先跑完，谁顺手清掉。

季循盯着那三行，隐约觉得不对，却又一时说不出哪里最不对。

"这不是很省事吗？"苏野平说，"全北院以前都这么干。临时东西本来就是临时的，放一个大家都知道的地方，省得你到处找。快的时候，快得不是一点半点。"

贺时进立刻点头。

"窗口最认这个。别管它干不干净，先跑得起来再说。"

韩砺年站在门边，没有立刻表态。

因为他知道这法子确实快，也知道它为什么快。

快在不用多想。

谁来都往同一个地方堆，谁顺手谁就清。眼前这一把火若只求先过，很多时候真能比规规矩矩分清边界更早见效。

可程知序的脸色已经沉下去了。

"错版夜发那晚，病就是这么快冒出来的。"

苏野平摊手。

"可你现在要的只是最小 `check`，又不是并着十几扇窗口一起跑。拿一个共用目录先顶着，有什么大不了？"

"有没有大不了，试一次就知道。"沈见微说。

· · ·

他把那三行旧法照样留在镜上，没有擦。

"季循，第一份样本你来。程知序，第二份你来。都按旧法，临时文件全放同一处。"

季循心里一紧。

他知道这多半不是好事，可也正因为如此，才更想看见它到底坏在哪里。

两面石镜同时亮起。

一边是他手里的旧发版样本，一边是程知序带回来的新窗口样本。

起初一切都很顺。

共用的临时目录里，一份接一份地吐出中间文件。第一张样本刚写到一半，第二张样本已经把自己的记录也塞进去了。

季循看着那些字光在同一处来回叠压，心里越来越不踏实。

"这两份东西，真的不会撞上吗？"

"平时都这么过来的。"苏野平说，"你别自己先吓自己。"

话音刚落，程知序那边已经先一步跑完。

她照着旧习，顺手敲下清理命令。

下一刻，季循面前那面石镜猛地一暗。

原本还在继续写的中间记录，像是忽然被人从地上整把掀走，断得极干脆。

紧跟着，镜面吐出一行冷字：

`No such file or directory`

屋里一下静了。

程知序手还停在镜前，像被那行字当面扇了一记。

"我清掉了你的。"

她说这句时，声音很低。

季循没有立刻答。

因为他自己也终于看清了。

不是谁故意使坏。

也不是谁手慢了。

而是这套旧法从一开始就没回答几个最该先回答的问题：

两次检查为何共用同一个路径？哪一次运行可以清理它？清理前怎样确认另一项工作已经结束？

季循看向镜面：“这回的问题，是两个进程共用了目录，又有一边提前清理。它和错版夜发里三处结果不同，是同一个根因吗？”

“不能这么说。”闻衡答道，“我们刚才复现的是临时目录共享造成的文件冲突；错版夜发的唯一触发仍未查明。相似的失控感，不能替代不同事故的证据。”

· · ·

苏野平脸上的散漫一下收了不少。

"再补个名字不就行了。"他说，"临时目录后面加一道样本号，或者加个时刻戳，也不是多难的事。"

"这就是问题。"闻衡终于开口，"你一出事就说'再补一个'，可前头那张纸从来没有先写清谁创建、谁拿着、谁能改、谁来清。"

她走到镜前，把季循那行断掉的记录抄下来，压到长案中央。

"今日丢的是中间文件。明日若丢的是校验结果、构建产物，或者一份别人正要拿去发版的说明，你们准备再补几个名字？"

韩砺年低头看着那行报错，眼神比方才更沉。

因为这东西他太熟。

北院过去太多年，就是靠这种"再补一个"过日子。

先共用。

出了事，再补区分。

还不够，再补规则。

规则还是不稳，就再补一个知道内情的人。

补到最后，人人都觉得自己眼前只是省了一步，没人承认后面已经被补成了一堵没人敢碰的旧墙。

· · ·

沈见微这时才把另一张白纸推到季循面前。

“先分清两个‘归谁’。”沈见微说，“临时目录由哪个任务创建、谁有权清理，是运行约定；Rust的所有权（`ownership`）则是程序里的值由哪个变量持有、何时能继续使用。两者相关，但不是一回事。”

季循看向镜面：“那所有权能不能挡住另一进程删掉这个目录？”

“不能。”沈见微说，“编译器看不到另一台机器或另一个进程正在做什么。这里要靠路径隔离和清理时机的约定。”

程知序看着自己方才清掉的那一份中间文件，半晌才低声道：

"这让人想起错版夜发，但还不能说是同一种根因。"

"对照可以帮助我们提问，不能替我们判定事故相同。"闻衡说，"旧夜发的根因还没收敛；今天这次目录冲突，证据只指向共享路径和提前清理。"

苏野平还不甘心。

"你们别把话说得这么大。说到底，不就是一个目录共用出了岔子？分开不就完了。"

"分开也得先知道怎么分。"沈见微说。

· · ·

他转过石镜，把一小段青炉的试验代码亮给众人看。

```rust
// 以下片段位于main函数中
fn store_report(body: String) {
    // 原型中的写入步骤
}

let report = String::from("sample check: passed");
store_report(report);
println!("{report}"); // 错误：report 已移动
```

季循看到错误行：“字符串交给函数后，原来的绑定就不能再用。”

“对。对`String`这样的非`Copy`值，按值传递会移动所有权；函数参数在函数里持有这个值，离开作用域时会运行析构逻辑。”沈见微说，“这是值的生命周期，不是这段代码替目录加了锁。”

韩砺年问：“那镜面上的‘主人’，不能直接当成清理人的名字？”

“不能。”闻衡说，“清理人是团队约定；`String`的owner是语言规则。把两个意思混起来，就会以为编译器替我们承担了并发和操作责任。”

· · ·

程知序也走到了镜边。

"那现在怎么改？"

沈见微没有废话，直接把旧法那三行划掉，换成了四句新规：

每次 `check` 自己建自己的临时目录。

只有确认该次任务已结束并收齐结果后，才清理它自己的目录。

构建产物不和别人共用一处中间地。

共享缓存暂不开放。

贺时进看见最后一句，眉头立刻拧紧了。

"为什么连共享缓存也不让碰？你们这不是明摆着让速度往下掉？"

"因为我们现在根本还没写清谁负责它。"闻衡说。

"缓存又不是谁家的祖产。"

"越不是祖产，越得先写清。"闻衡看着他，"不然人人都能动一点，等它真把谁绊倒，就又是谁都只碰了一点。"

苏野平冷着脸看那四句新规。

"你们这是把快法全挡在门外。"

"不是挡。"程知序说，"是先承认我们现在还没资格把它们放进来。"

韩砺年这次没再犹豫。

"共享缓存，先别开。"他说。

苏野平看了他一眼，像是有点意外。

"连你也站这边？"

韩砺年盯着那行 `No such file or directory` 的抄片，声音很低，却比任何时候都实。

"因为我太知道这种省一步的后果了。今日清掉的是中间文件，明日就可能是别人还没收齐的验证结果。"

· · ·

屋里一时没人再说话。

雨打瓦沿的声音隔着窗传进来，倒把这一刻衬得更静。

季循重新坐回镜前，照着新规把第一份样本又跑了一遍。

这一回，青炉先为它单独立了一处临时目录，再把所有中间文件、构建产物和最终记录都落进它自己的地界。

程知序那边也重新跑第二份样本。

两面镜的字光仍旧交错，却再也没有谁把谁的东西踩碎。

等到两份样本都安安稳稳落停，季循竟比第一次跑通那台空机子时还更长久地沉默了一会儿。

沈见微没有催他。

他知道，有些东西必须让人自己咽下去，才会真正变成骨头。

良久，季循才低声说：

"我以前一直以为，所有权（`ownership`）这种词，是写 Rust 的人才会在意的讲究。"

苏野平没说话。

闻衡抬眼看着他。

程知序也没有催。

季循看着那两面互不相撞的镜子，把后半句慢慢说完：

> "现在我才明白，它不是炫技。它让编译器替我们检查一部分值的转移规则；至于哪次任务能清理目录，仍得由我们把运行约定写清楚。"

他停了停，像是在替自己把错版夜发后那团一直没说透的阴影终于往前推进了一步。

> "过去北院那种'都能碰一点'的便利，确实让今天这次目录冲突更容易发生；但错版夜发的根因，我们还没有证据定下来。"

这句话落下去，屋里很久没有人接。

不是因为没人听懂。

恰恰因为人人都听懂了。

沈见微把那四句解释纸重新折好，压进青炉文契的第二层。

比起昨日那份薄得近乎寒酸的 `Cargo.toml`，今天这张纸更不像什么拿得出手的成果。

它没有多新一件本事。

它只是先把"谁能碰、碰到哪里为止"写清了。

可沈见微知道，青炉若没有这一层骨，后面长出来的每一段能力，最后都还会滑回北院旧病里去。

雨还在下。

东廊尽头的灯被风吹得微微一斜，又稳住了。

季循望着镜里那两份互不侵占的记录，忽然觉得自己第一次看懂了先前写下的"先写资源边界"。

> 原来所谓边界，既有代码里的值何时移动、何时析构，也有团队怎样隔离目录、何时允许清理。它们都需要说明，却不能混成一种保证。

不把这些写清，所谓方便，迟早都会长成别人看不见的祸。
