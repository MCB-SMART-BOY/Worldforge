# 明契卷 · 第51章 · 留影为史

Git 不只是备份。每个 commit 保存一次变更快照及相应元信息；提交说明可以补上"为什么改、当时依据什么、如何验证"。后来者在 `git log` 里看到的不该只是一串改动标题，还应当有足够线索追问当时的判断。提交本身并不会自动保存动机，历史也可能被重写；写下来的理由，才让旧决定有机会被重新审视。

沈见微写青炉的第一个 commit。"此 commit 不完整——只包含 scope 和 Cargo.toml。后来者：接下来——每一行都会写'为什么'。不是代码的'为什么'——是决策的'为什么'。"

"旧的工具链中变更没有记录——每个脚本悄悄变，每个笔记独自存。Git 让变化更容易追查——commit 记录作者、时间戳和 diff；好的提交说明再补上原因。后来者用 `git blame` 能找到某行最近一次修改对应的提交，再沿着 `git show`、日志和评审记录追上下文。单看 blame 不能还原设计意图；原因还得有人写下来。若当时的条件变了——这个变更可能需要重新审视。"
