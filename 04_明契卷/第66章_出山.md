# 明契卷 · 第66章 · 出山

青炉从内部开发走向外部发布。Rust 的发布不是"代码写完了"——是"承诺写下来了"。crates.io 是 Rust 的公开仓库——发布到上面意味着所有外部使用者都可以依赖青炉。

"发布不是把代码推上去——是签一份公开的契约。`cargo publish` 之后——外部 crate 就可能在 `Cargo.toml` 里写下 `qinglu = "0.1"`，把它纳入自己的依赖。那个版本号——是对陌生人的承诺。0.x 阶段的稳定性约定要先说清；等我们承诺稳定的 1.x API 后，不兼容变更就该升 MAJOR，并提供迁移说明，必要时提前发出弃用声明。"

semver 在 Rust 生态中是重要约定——Cargo 会按版本要求解析依赖，却不会替发布者证明两个版本真的兼容。等进入稳定的 1.x 阶段，若按承诺维护，1.0.1 应保持对 1.0.0 的向后兼容；但 0.x 阶段的兼容范围更窄，不能把版本号当成同一套稳定承诺。编译器未必能发现行为层面的破坏——还得靠测试、变更说明和使用者反馈把问题找出来。
