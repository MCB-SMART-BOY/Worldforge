# 明契卷 · 第62章 · 并发的承诺

Rust 的并发模型不只有"线程加锁"，也把跨线程共享和转移的约束写进类型系统。`Send` 表示一个值可以安全地转移到另一线程；`Sync` 表示对该类型的共享引用可以安全地跨线程共享。编译器会检查线程边界上的这些 trait 约束，但它们不替程序证明业务结果正确，也不保证没有死锁。

这些标记 trait 多数由字段类型自动推导；如果类型包含不能安全跨线程转移或共享的字段，相关操作就无法通过检查。它是并发安全的一道静态防线，不是对所有运行时故障的担保。

青炉的 report 模块改为多线程批处理，闭包却捕获了 `Rc<Config>`。编译器拒绝把它送进新线程：`Rc` 的引用计数并不支持无同步的跨线程共享。季循把它换成 `Arc<Config>` 后重新检查，同时补问了一句："这个值能跨线程，只说明这一步允许；线程之间的业务顺序还要我们自己设计，对吗？"沈见微点头。类型系统守住一部分边界，剩下的仍是人的约定。
