# 容断卷 · 第32章 · 第一个混沌实验

第二个混沌实验——模拟气象API格式变更。和最初那场气象 API 格式变更事故相同——但这次——团队准备好了。

实验在生产环境的canary分片——使用隔离的测试数据，在`data-ingestor`和气象API之间注入了一个代理。代理只改写canary流量的返回格式，从`{temperature: 23}`改成`{data: {temperature: 23}}`——精确地复现了那次外部变更；核心结算指标一旦触及中止阈值，实验就立即停止。这次——canary上的`data-ingestor`解析器——在新的容断配置中——没有静默跳过。它在模式匹配失败时crash——supervisor重启——第二次还是crash——第三次——supervisor触发告警。

从格式变更到告警触发——不到两分钟。那次事故中，同样的问题从发生到被发现——隔了两个时辰。"容断不是让事故不发生——是让事故从'潜伏的静默'变成'可见的信号'。Crash是可见的——静默偏差不可见。混沌实验——证明了这个转变——从不可见到可见。"

不是每个混沌实验都要复现历史事故——这个实验只验证了这条改进链：气象API格式变化被`data-ingestor`显式拒绝，crash经Supervisor重试后触发告警。它没有证明其余容断机制都已有效。最初那场气象 API 事故——在同样的输入条件下——这次——两分钟内发出告警——不是潜伏两个时辰后才从结算端被发现。
