# 容断卷 · 第58章 · 判断的框架

容断的取舍——不是凭直觉——是四相与四蚀——作为判断的框架。

"式——结构——容断的取舍中——'什么样的结构变化——会改变取舍的边界。'如果一个服务被拆成两个——原来共享容断策略——现在各自独立——取舍需要重新算。式——也在问——'当前的容断策略——在结构上——是否自洽——降级X——是否在不知道的情况下——破坏了Y的隔离墙。'"

"流——运行时——容断的取舍中——'在当前的负载分布中——保护X——消耗多少资源——这些资源——从哪来。'流——让取舍成为可计算的——'保护支付服务的断路器——需要额外的连接池和内存——在当前的负载下——这些资源如果给推荐服务——推荐服务的降级阈值可以提高——更多用户在超载时——能看到推荐。保护支付——还是保护推荐——流——给出数字——取舍——是数字上的选择——和价值上的选择——不是二选一。'"

"契——约定——容断的取舍中——'我们对用户承诺了什么——对下游承诺了什么——对上游承诺了什么——放弃某个功能的保护——是否背弃了某个SLO。'契——也在问——'我们的容断声明——是否真的说了真话——'此功能在容量98%时仍可用'——这个承诺——在最新的演习中——是否被验证。如果没被验证——我们的承诺——是契——还是空话。'"

"史——时间——容断的取舍中——'一年前——这个功能是核心——今天——它仍然是核心——还是只是没人记得把它从核心降级为增强。'史——也在问——'我们的容断策略——是否被记录了为什么当初这么决定——后来者——读取这个策略——能否知道——'这个取舍——是在什么前提下做的——那些前提——今天——是否还成立。'"

柯守把四个问题写成了容断判断清单——

1. 式问——"此取舍——在结构上——自洽吗——会破坏隔离边界吗。"
2. 流问——"此取舍——在资源上——多少代价——多少收益——可计算吗。"
3. 契问——"此取舍——是否背弃已有承诺——如果背弃——对谁宣告。"
4. 史问——"此取舍——的前提——被记录了吗——后来者——能知道为什么吗。"

"四相不是分类工具——是判断框架。每一个容断取舍——在四个维度上——同时被检查。一个取舍——如果在流上合理——但在契上背弃——它可能是正确的工程决策——却是错误的产品决策——需要被重新判断。容断的取舍——不是纯工程的——四相——强制了四个视角——让容断的判断——不是'技术上最优'——是'在所有被影响的维度上——被知道——在被评估后——做选择。'"
