# 驭器卷 · 第73章 · FFI 的地狱

unsafe 地图完成后的第二天——一次外部调用失败了。

不是大爆炸——是协阵扩域的一个旧子阵在调用玄枢的信号码查询接口时，收到了乱码。Java 服务通过 JNI 进入本地接口，数据再经过 Fortran 绑定、C 适配层，最后由 C++ 查询实现返回。平常信号码较短，问题不显眼；这次一个编码后恰好占满 256 字节的名称，末尾多出几个不可打印字符。

Java 服务收到的——是乱码。不是全部——是——字符串末尾——多了几个不可打印字符——看起来——像是——"未初始化内存"。

陆踏痕花了整个上午追这条调用链：JNI → Fortran → C → C++，再沿返回路径核对字符串。C++ 的 `std::string` 保有字节长度，`c_str()` 也会提供终止符；问题出在旧 C 适配层：它把 Fortran 的定长结果拷进 256 字节缓冲区，短字符串会补零，恰好占满缓冲区时却没有额外空间写入终止符。JNI 侧仍把它当作以 NUL 结尾的 C 字符串处理，于是边界样本触发了越界读取。

"Fortran 的定长 `CHARACTER` 按长度保存内容，不保证末尾有 NUL；它可能用空格补足定长。C 适配层把这段内容交给 JNI 时，既丢了显式长度，又沿用了 C 字符串假设。恰好写满 256 字节的那次没有终止符，JNI 的旧转换代码调用 `strlen` 后继续读到缓冲区之外，才把相邻字节带进了结果。问题不是四种语言都各自做对了——是边界转换没有共同约定，也没有检查满长输入。"

"每层单独看，都有自己的约定；拼在一起却没有一份共同契约。C++ 到 C，接口只传指针，没有显式长度；Fortran 的定长字符与 C 字符串不是一回事；JNI 转换还要遵守它的编码和终止规则。三道边界各自漏掉一项前提，最后落在同一个越界读取上。"

"ABI 兼容，只说明二进制按约定找到符号并传递参数；它不会替你核验字符串长度、布局和编码。这里跨了 C++、C、Fortran、Java 四种语言和几种字符串表示。地狱不是某一步必然写错，而是每层的局部约定没有被合成一份端到端契约。"

· · ·

下午。陆踏痕画出这条 FFI 调用链：从 Java 8 服务的 JNI 入口，经 Fortran 绑定和 C ABI，抵达 C++17 的查询实现，再沿返回路径转换回 Java `String`。图上标出了每次长度、编码和所有权约定发生变化的位置，也标出了这次越界读取的具体缓冲区。

"这不是最复杂的。玄枢里还有 Fortran 到汇编、再到硬件寄存器的路径。但这条很典型：C ABI 方便不同语言互调，却不替调用方决定内存由谁持有、字符串有多长、编码是什么。C 接口传来的指针必须配套明确的长度和生命周期；Fortran 定长字符需要按约定转换；JNI 也不能把任意字符数组直接当作已终止、编码正确的字符串。旧代码只在短字符串样本上验证过，没测满 256 字节的边界，于是错误一直藏着。"

"这个 bug 不是某个人一次写错就能解释的。各层代码都在自己的局部样本里跑通了，却没有人负责核对满长输入穿过整条链后的结果。空白就在 C ABI 的通用约定和每种语言的具体表示之间。"

· · ·

他们没有只在JNI入口补一个终止符。沈照痕把返回契约改成“字节缓冲区＋显式长度”，C适配层校验容量，Fortran绑定按约定传递长度；JNI侧再用明确的UTF-8解码器构造Java字符串。回归样本覆盖空串、255/256/257字节和多字节字符，满长输入不再触发越界，非法编码则返回可识别的错误。

钟守玄看到了陆踏痕的画——那条跨了三道语言边界的 FFI 调用链。他把这张图贴在 unsafe 候选清单上，在最深的那一层。

"这条路径确实需要适配层。"他说。"不同语言的调用约定、字符串表示和内存所有权规则不一样；适配层把转换放在一个可核验的边界上，让两侧按明确契约交换数据。它的作用是把前提写清、测明，不是把假设藏起来。"

"我刚才把桥和 FFI 说成一回事，太粗了。桥是连接系统的结构，FFI 是跨语言调用机制。它们可以在同一条路径上相遇，却不是同一个概念。这次确有缺口：C 适配层丢了显式长度，满 256 字节时没有空间写终止符，JNI 仍按 C 字符串调用 `strlen`，造成越界读取。缓冲区生命周期和字符编码也应纳入端到端契约，但现有证据不能说它们触发了这次故障。适配层的前提可以被记录、测试和管理；并非每座桥都是纸墙。纸墙指文档承诺与已核验的实际行为不符；尚未验证的边界应标作待核，不能自动判成纸墙。"钟守玄说。

· · ·

傍晚。纪承钧在 unsafe 地图上——FFI 边界的地方——加了一行说明。

"FFI 不是邪法，但每次跨语言转换都要明确调用约定、长度、生命周期、编码和错误处理。编译器在各自语言范围内能检查一部分问题，不能代替端到端验证。这里已经补上显式长度和受测的转换路径；边界样本覆盖 0、255、256、257 字节及多字节字符，并用 sanitizer 检查越界。——纪承钧。——前提：验证只覆盖列出的构建、编码和调用路径。后来者修改任一约定时，须重跑边界测试并更新此图。"
