# 驭器卷 · 第75章 · 收到诊断报告

一封传讯——从青炉（明契·Rust 道统）——到达了玄枢。

不是普通的传讯——是一份诊断报告（diagnostic report）——版本 v0.3.1，作者是青炉的核心维护者沈见微。报告汇总了青炉依赖清单与调用记录，并用静态分析工具检查了青炉可见的 Rust/C 接口；`cargo-audit` 部分只核对 Rust 依赖中的已知安全公告，并不负责判断接口是否可删除。报告正文把若干接口列为“青炉侧可进入废弃评估”，但每项旁边醒目的绿色状态却写着“可安全废弃”。扉页要求接收方确认本地依赖；报告没有证据证明玄枢全域安全，状态标签却把这种有限分析说成了处置建议。

报告本身不长，但边界写得清楚。每个接口都附了青炉侧最近三十天的调用统计、风险备注、评估建议和替代方案；这些数字只覆盖青炉接入的采集点。最下面是一段免责声明（disclaimer）。

"前提声明——'此分析基于青炉侧可见的依赖关系图。未知依赖（unknown dependencies）不在检查范围内。——请——在使用此报告的任何建议前——在你那边——确认——你的依赖关系。——沈见微。——前提：本报告是工具输出——不是权威判断。——工具——可能错。——语境——可能不同。'"

纪承钧读了三遍。不是只读报告正文——也读了那段免责声明。那句话——"未知依赖——不在检查范围内"——写得诚恳——也写得清醒。可绿色状态比脚注醒目得多。他看见了边界，却仍把玄枢已接入网络监测中的零记录当作补充佐证，没有核清这份监测与青炉采集所共有的盲区。不是"我查了，没问题"——而是——"我能查到的——都在这里。——我不能查到的——我不知道。——你的世界——有我不知道的东西——请你自己——确认。"

"这份报告把自己的边界写出来了。"纪承钧把报告放在旧石案上。"依赖清单、静态分析和调用统计各自说明了依据，也写了前提声明和免责声明。可那个绿色标签把‘未观测到’写成了‘可安全废弃’；我不能只挑脚注来判断它。"

"对。"沈照痕说。"他看不到——北岭——在丑时——通过一条六年前的 Makefile 注释——私接了一条调用——那条调用——不在青炉的可见范围里。但报告把这个盲区里的接口标成了‘可安全废弃’。而我们——看见本地 socket 没有观测——仍然批准了删除。不是只有一边该负责。"

"统计本身——没有说谎——青炉接入的调用源里确实为零。错的是——工具把这个观察——升格成了‘可安全废弃’。而我——明知道本地 socket 没被观测——还是决定在维护窗移除。——这不是一句‘报告写了免责声明’就能推开的责任。"

· · ·

纪承钧逐条评估报告中的建议。三分之二——在青炉可见的依赖范围内——有替代接口或长期零调用记录，进入本地复核后得以退场。另有三分之一仍需核对接收方环境；其中一个——`legacy-report-gateway`——被绿色标签列为“可安全废弃”，实际尚未通过玄枢本地调用范围的核验。

其中一个接口——名字叫——`legacy-report-gateway`。

Legacy-report-gateway——是一个老接口——八年前搭的——用来——让北岭生成日报表。后来——北岭换了报表系统——新系统——用新接口——不再调用 legacy-report-gateway。在青炉侧的调用统计里——这个接口的调用次数——为零。为零——已经三年了。

沈见微的标注——"可安全废弃——青炉侧调用统计为零——已持续三十六个月。——替代方案——report-gateway-v2。——建议——在下一个维护窗口——删除。——前提——确保——没有其他调用方。——未知依赖——不在检查范围内。"

纪承钧查了玄枢侧的数据。最近三个月留存的 trace 和指标里，已埋点的 HTTP/RPC 入口没有记录到 `legacy-report-gateway`；旧日志也没有这条网络路径的请求。可是观测档案明确写着：本地 Unix socket 尚未接入采集，零记录不能覆盖那条通道。

"青炉侧——零。玄枢已接入的网络路径——零。——可那条本地 socket 仍是盲区。"

沈照痕没有说话。他打开观测档案，确认当前分布式追踪只留存了三个月；更早的旧日志也只覆盖已接入的网络入口，并没有本地 socket 的调用记录。

"这只能说明我们接入的入口没有记录，不能替那条 socket 作证。"

纪承钧翻到桥谱系里那条北岭旧备份主机的记录：丑时调用，经三个 wrapper、两个 adapter，落在一个标记为废弃的接口上。记录尚未把接口名与报告中的 `legacy-report-gateway` 对起来，也没查清本地调用方式。那是个该停下核对的缺口——他想起自己曾让秦叔平确认备份任务，却没有把这条旧记录带进眼前的退役评估。

他看着报告的前提，再看了看自己刚写下的盲区。已接入网络路径的零记录确实没有覆盖本地 socket；而桥谱系里那条已知线索也还没有核实完。值守窗口已排定，北岭的新接口已完成兼容，他仍把未完成的对应核查留到后面，决定先在维护窗口移除旧入口，并要求值守台盯紧首轮夜间任务，若有异常立即回滚。

纪承钧在报告上——在 `legacy-report-gateway` 那一条旁边——画了一个勾。然后——他写了一条传讯——给沈见微。

"沈见微，收到 v0.3.1。我们按青炉侧证据复核了已接入的玄枢网络入口，暂未见调用；本地 Unix socket 仍未观测，不能据此证明全域无人依赖。我们已排维护窗口，准备先移除旧入口并盯守第一轮夜间任务，异常即回滚。这个决定仍带着未验证的盲区，后续补做主机与构建开关核查。你的报告为我们指出了核查起点。——纪承钧"

传讯发出。纪承钧删除了 `legacy-report-gateway`。

测试通过。部署到生产。一切正常。

· · ·

一切正常——直到丑时。

丑时还没到。

今晚——纪承钧熄了灯——和往常一样。散热塔在窗外转——和往常一样。观测面板上——迹——脉——势——安静地滚动——和往常一样。

没有告警。没有异常。没有漂移。

Legacy-report-gateway ——从玄枢的代码里——消失了。干净。快速。没有引起任何编译错误——任何测试失败——任何面板告警。

一切正常。

可桥谱系里那条北岭旧备份主机的线索还没有闭合。六年前，有人在 Makefile 注释下留下一个调用；它每晚丑时经过三个 wrapper、两个 adapter，到达 `legacy-report-gateway`，取回信号码汇总，再存进那台备份服务器。此前留存的 trace 只把主机连到一个废弃接口，当时尚未核出这个 API 名称，更没找出本地入口。

那台备份服务器不在青炉的依赖分析范围里。玄枢也没有采集本地 Unix domain socket；此前留存的 trace 只留下部分调用片段，没有照见本地入口和构建开关。线索曾经出现，却没有被补成一条可用于退役核查的完整路径。

青炉——零。玄枢接入的网络观测——零。丑时旧调用——曾被看见，却还没有被认出就是眼前这个接口。

本地入口与构建开关仍未被照见。但今晚——一切——都——安静地——正常。是那种——所有的面板都是绿色的——所有的迹都是正常的——没有人被叫醒——散热塔——低沉地转——一切——安静地——正常——的那种——正常。

在那种——灾难——来临之前——特有的——正常。
