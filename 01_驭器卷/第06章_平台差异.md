# 驭器卷 · 第06章 · 平台差异

那台闲置的 macOS 机器，被推到值守台旁边时，纪承钧以为最难的部分已经过去了。

他照着旧脚本装好构建工具，拷入玄枢源码，逐条执行命令。编译通过。链接通过。最后一行日志落下时，钟守玄看了他一眼，像是准备说“可以了”。

纪承钧却没有合上记录。

“还没跑完。”他说。

他取出一份北岭备份服务写入、再读回的旧记录。Linux 机器上，记录长度是二十四字节。macOS 上，调用返回成功，读回的数据却少了末尾一段。

不是构建失败。

是同一段代码，在另一种平台布局下，把本机结构体的大小当成了固定格式。

· · ·

沈照痕赶来时，纪承钧已经把两份记录并排放在石案上。

“编译器没有报错。”他说。

“它不一定该报错。”沈照痕看着字段排列，“两个平台的填充规则不同，本身不代表谁错了。问题在于接口把内存布局直接当成了持久格式，却没有把布局写成契约。”

纪承钧在记录边缘画了一道线。

“在 Linux 上，它看起来一直是对的。”

“看起来对，是因为所有人都在同一组前提下使用它。”

· · ·

他们没有立刻改结构体。

钟守玄把手按在那台旧机器的机箱上，提醒他们：玄枢的外部调用方可能还有各自的适配层。单方面把记录格式改得更“正确”，也可能让那些已经按旧布局工作的系统读不懂新数据。

纪承钧看着机器里那份读回失败的记录。少掉的不是一串数字，而是某个后来者以为永远不变的前提。

“那先做什么？”他问。

“把我们知道的和不知道的分开。”沈照痕说，“先记下这一次差异。不要把一台机器的结果写成所有平台的结论。”

· · ·

纪承钧在新页上写下：

`已复现：同一份记录在 Linux 与 macOS 的结构体布局不同。`

下一行：

`待核：所有外部调用方是否都使用同一布局；是否有人在本地另作适配。`

再下一行：

`当前行动：暂停格式变更；先收集平台、编译器和调用方证据。`

他把“平台不兼容”改成“一个已复现的平台差异”。

钟守玄看见了这个改动。

“你现在知道该怎么写了。”

“知道怎么写不等于知道怎么修。”

“很好。”钟守玄说，“先别急着证明自己能修。”

· · ·

夜深时，那份记录仍摊在石案上。两种布局，两种结果，一条从未写下来的假设。

纪承钧把它夹进平台记录册的第一页，在页角留下一个尚未填满的标题：

`平台矩阵：待建。`

玄枢仍在运行。那台 macOS 机器没有被关掉，也没有被宣布为新基线。它只是把一件以前没人看见的事，放到了所有人面前。

下一次要动手之前，他们得先知道：这张桌子上，还摆着多少种不同的平台。
