# 驭器卷 · 第72章 · unsafe 的地图

纸墙报告出来后——纪承钧决定绘制一张地图——不是桥的地图——是 unsafe（不安全边界）的地图。

在 C++ 的世界里，没有与 Rust `unsafe` 等价的关键字，提醒维护者某段代码正在依赖调用者自行证明的安全前提。C++ 的类型系统和编译器仍能阻止不少错误，但不会替程序证明所有指针生命周期、手工资源管理、FFI（foreign function interface）约定或 `reinterpret_cast` 的用法都安全。风险可能藏在一段看起来普通的代码里；要靠审查、契约、测试和工具逐项判断。

"我们需要知道——玄枢——有多少 unsafe 边界——在哪——多老了——在什么条件下——可能炸。"纪承钧对陆踏痕说。"不是要消灭它们——消除 C++ 的所有 unsafe ——不现实。——是——让后来者——在踩进雷区之前——能看见地图。"

"像桥谱系——不过先把可能需要额外证明的边界列出来，再分清哪些只是候选，哪些已有缺陷证据。"

"对。桥是连接；这些边界清单标的是假设容易失效的地方。程序跨过语言、所有权或表示约定时，编译器未必能验证两边的前提是否一致——但风险要看具体操作，不能说边界之后每一行都不安全。"

· · ·

陆踏痕先把 sanitizer 多轮运行产生的原始报告去重，再把能复现的缺陷与其调用路径关联起来；这批报告既不是缺陷总数，也不能覆盖所有危险边界。他另从源码检索裸指针操作、跨语言调用、手工内存管理和表示转换，建立候选清单，再逐项对照提交记录与调用上下文。作者和年代只有在历史记录能支持时才标为已确认，其余注明未知。

三天后，清单上有四十三处候选边界。不是四十三个 bug，也不代表四十三处都越过了某条统一的“编译器保护线”；其中有些是需要补契约或边界测试的跨语言转换，有些是生命周期和表示假设，还有些经复核后可能只是普通调用。接下来要逐条分级，而不是先给它们统一贴上 unsafe 标签。

最深的一处——一个 FFI 调用——跨了三个语言边界——C++ → C → Fortran → 硬件接口。

"这一处——C++ 的 `std::string` 先经显式转换交给 C 接口，再由 C 绑定按 Fortran 约定传入 `CHARACTER`，最后送到硬件帧编码器。要核对的不只是每一层单独能运行，还包括指针有效期、字符串终止与长度约定、字符编码和帧格式。现有记录没有证明这些前提曾被端到端验证过；要判断风险，得把各层的契约和真实构建方式放在一起看。"

"能把整条链都讲清楚的人——如今已经不在玄枢了。"

钟守玄走过来——看着那个 FFI 调用链。"那个 Fortran 库——在卫千枢来之前就有了。我问过——'为什么用 Fortran？'——回答是——'因为当时只有 Fortran 能算这个。'——那是——创始者的时代——在 C++ 之前。"

"所以——这条跨语言链里最早的部分——比玄枢的 C++ 维护史更老。"

"对。最初是 Fortran，后来加了 C 绑定，再后来才有 C++ wrapper。三种语言，几代维护者。每一层可能都按自己的局部契约工作，但整个链路是否满足字符长度、生命周期和帧格式的共同前提，还没有一份端到端证据。它不像一次设计完成的接口，更像几代人逐层接上的旧桥——各段看着能走，连接处却没人重新验过。"

· · ·

纪承钧把四十三处 unsafe 边界——画成了一张地图。不是地理位置的地图——是代码结构的拓扑图——每一条 unsafe 边界——标注着——类型——语言边界——年代——已知的假设——和——在 sanitizer 报告中——是否被标记过。

地图上最老的一条候选链，是通往 Fortran 帧编码器的调用路径；旧记录显示它至少延续了十二年，但最初实现的准确年代仍待核。北岭-wrapper 已有多次假设偏差记录，优先级暂列较高；偏差次数不能单独证明它比所有其他候选都危险。最新的一条则来自陆踏痕合并 shim 转换实现后的回归测试：协阵旧子阵释放对象后，另一个分支仍可能访问保存下来的裸指针。这个 use-after-free 已由测试复现，属于确认缺陷，不再只是地图上的假设。

不是故意 unsafe ——是——在 C++ 里——安全——需要持续的关注——而——在一代代的维护中——关注——可能被转移——然后——曾经安全的代码——在新的上下文里——变得不安全——而没有人——注意到。

"这张地图不是要把所有复杂代码都叫作 unsafe，也不是试图消灭 C++ 里的风险。它要提醒后来者：此处有一项需要验证的前提；修改前先查调用方、生命周期、表示和失败路径。Rust 的 `unsafe` 是语言定义的边界标记，C++ 没有同等关键字，这份清单只能作为本地审查索引，不能替代代码约束和验证。——纪承钧。——前提：四十三处是当前源码扫描和人工核查所得的候选，新增代码或漏检都可能改变清单。后来者请标出证据、验证状态和复核日期。"

· · ·

那天晚上。钟守玄看着 unsafe 地图——他的手指——在 Fortran 那条最老的边界上停住了。

"这条调用链一直在我的感觉里。几十年来，每逢断火我都会查它——不是因为我能证明它有错，而是我知道它穿过 Fortran、C、C++，最后抵达硬件，接口之间有些前提没人说得清。以前我靠经验记着它；现在它进了清单。后来者能从这里开始核对，而不必把我的担心当成结论。风险还在，至少它有了名字和复查入口。"

他在 map 旁边——用铅笔——在 Fortran 那条边界上——画了一个很轻的圈。然后在圈旁边——写了一段——"此 unsafe 边界——比四道更老。——在被看见之前——它只是——恰好——不出事。——现在——它被看见了。——看见——是——管理的前提。——后来者——如果你加固了它——请标注——'钟师——那时候——它是在地图上——但还未被加固。——我——现在——加固了。——用——什么方法——在——什么前提下。'——钟守玄。——前提：加固——可能——改变它的行为——请在加固后——重新观测——并通知——北岭——和——所有——在它上面的——桥。"
