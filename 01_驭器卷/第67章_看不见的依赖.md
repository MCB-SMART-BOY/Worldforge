# 驭器卷 · 第67章 · 看不见的依赖

观测体系运行到第六周——沈照痕的分布式追踪（distributed tracing）面板上——出现了一条异常。

迹（trace）把一条请求中已埋点、且成功传递了上下文的调用片段串在一起：能看到哪些服务参与、各段耗时和状态，却不等于系统里每一步都被完整记录，更不应默认收集业务载荷。大多数保留下来的迹——是他们熟悉的北岭定时信号、协阵订阅查询和几条 wrapper 中转。但这一组夜间记录——不一样。

这组迹——在六周的留存窗口里，多次出现在丑时（凌晨一点到三点）。被记录到的调用路径——穿过三个 wrapper、两个 adapter——最后落在一个已经标记为"废弃"的接口上。那个接口——三年前纪承钧在旧骨深处发现后，标注了"废弃——不再维护——请勿调用"。

但每夜丑时——它被调用。调用方——不明。

"这个调用——不应该存在。"沈照痕把这条迹放大。调用链上的每一步——都有时间戳——都在正确的时间——调用了正确的函数——但最后一步——那个废弃接口的入口——没有人知道——是谁在调它。

"追溯。"纪承钧说。"从最后一步——反向——追到源头。"

· · ·

陆踏痕先沿 trace ID 回看玄枢内已关联的片段，再对照入口网关保留的源系统标识和北岭设备清单。追踪只能把他们带到边界；真正认出那台机器，靠的是两份记录相互印证。它来自北岭方向，却不是北岭主系统——而是一台标签早已失效的旧主机。秦叔平后来确认，那是九年前搭建的备份系统：趁主系统维护窗口，在丑时备份当日数据。

这个备份系统——不在任何依赖声明（dependency declaration）上。不在桥谱系上——不在渡桥司的登记册上——不在北岭运维的值班手册里。它只是——每夜丑时——静默地——调了玄枢的一个废弃接口——拿到当日的信号码汇总——存进备份文件——然后退出。

九年来——它没有进入现行依赖清单。北岭的值班人员不知道它还在运行：系统是九年前一个已离职的人搭的，他走后任务仍在跑，却没有文档、告警或值班记录把这台旧主机与玄枢的接口联系起来。

"如果——我们在不知道的情况下——拆了那个废弃接口——"

"北岭备份系统——在丑时——调用失败——静默退出。——备份——没有被生成。——没有人知道——备份没有被生成。——直到——有一天——北岭需要恢复备份——发现——最近的可用的备份——是——拆接口之前的那个版本。"

"可能——是今天拆——明天——备份就消失——但没有人知道——直到——某天——需要备份的时候。——可能是一周后——可能是一个月后——可能是——一年后。——那个发现的人——会追——追到——'废弃接口被拆了——没有人通知备份系统。'——然后——他会问——'为什么拆之前——不先照？'"

"此前的依赖清查和日志没有把这条路径带出来。不是说没有 trace 就绝不可能发现——而是这次保留下来的调用片段，让我们有了可追的入口；再和设备清单、值班记录对照，才认出那台机器。"

"这就是'看不见的依赖'。代码一直在执行，人却没有把它登记成一条依赖。分布式追踪没有照亮所有角落——它只是留下了一条可追的线索；沿着这条线，我们才把旧主机、维护窗口和那个废弃接口连起来。一个活了九年的未知路径，终于有了名字。"

· · ·

纪承钧把这条隐式依赖——加进了桥谱系。不是作为一条新桥——是作为一条标注——贴在 deep-bridge 旁边。

"隐式依赖。线索来自留存的分布式追踪与入口记录，后经北岭设备清单确认。依赖方——北岭旧备份主机——丑时调用——路径——wrapper/adapter → 一个标记为废弃的接口。已确认主机和备份任务；这个接口与具体 API 名称的对应关系、本地调用方式仍待核对。若接口移除且主机仍按旧地址调用，请求会失败；备份任务是否告警、产物是否可用，尚待北岭核验。已通知秦叔平。——纪承钧。——前提：当前记录只覆盖已采样并成功关联的调用，不能证明不存在其他路径。后来者若发现新依赖，请记录发现手段、验证证据和仍未知之处。"

然后他给北岭的秦叔平发了一封传讯——"一台北岭旧主机在丑时调用玄枢的废弃接口。现有记录显示它可能参与备份，但任务状态和备份可用性还需你们确认。请先核验主机与调用，再商定替代接口和迁移窗口；核验完成前，我们不会只凭'废弃'标签直接拆掉这条路径。"

秦叔平的回复——半个时辰后——"备份系统——？我们——不知道——我们有备份系统。——我去查。"

· · ·

傍晚。秦叔平的回信到了。不是传讯——是他亲自来玄枢了一趟。

"查到了。九年前老严搭的任务，他离职后没人接手。主机还在按时写文件，但我们没有定期恢复演练，也没人能确认那些文件现在是否可用。主系统另有一套备份，所以这批文件长期没人查看——任务运行，不等于备份可靠。你们发来线索后，我们才把机器、接口和任务对上。"

"不是坏事——但——不知道——不是好事。不知道——意味着——没有人维护——没有人监控——没有人通知——在它失败的时候。——它已经——安静地——跑了九年了。——九年——没有被看见——没有出过错——但——'没有出过错'——不是因为它不会出错——是因为——没人知道——它什么时候出过。"

纪承钧在桥谱系上——在这条隐式依赖旁边——加了一行。

"不知道——不是无害的。不知道——是——把'恰好没问题'——当成——'永远没问题'。分布式追踪——让不知道——变成知道。——知道——不保证不出错——但保证——出了错——有人——能追到。——不是运气——是可见。"

· · ·

那天晚上。钟守玄站在分布式追踪的面板前——看着丑时的那条迹——一条灰蓝色的线——穿过三个 wrapper——两个 adapter——落在废弃接口上。

"这就是我一直在怕的。"他说。"不是已知的依赖——是未知的依赖。已知的依赖——你可以管理——可以拆——可以包裹——可以通知。——未知的依赖——像——在你脚下的冰——你看不见——你走——它不会断——因为——恰好——你这次走的——不是它薄的地方。——但你不知道它在。——下一次——你去拆一个你知道的桥——拆了——它在的冰——裂了——然后——一座你不知道的城——在你看不见的地方——塌了。"

"你拆了一座你知道的桥——炸了一座你不知道的城。"陆踏痕重复了一遍——然后把这句话——写在了笔记本上。

"这不是桥的问题——是可见性的问题。每发现一个隐式依赖——就是——把一座——你不知道的城——标在地图上。——后来者——看到地图——知道——'此处——有城——修桥时——注意。'——不是保证以后不炸——是——让炸的时候——不是——从'不知道'——到'灾难'——而是——从'知道'——到——'我们错过了某个前提。'"

钟守玄点了点头。然后——他在私人日志上——写了一段。

"三十几年来——我一直害怕——玄枢的深处——有我不认识的东西。今天——沈照痕的分布式追踪——发现了一个——我不认识的——备份系统——活了九年——调用一个我已经忘了的废弃接口。我害怕的东西——终于被看见了。——不是不再害怕——是——害怕——有了名字——有了位置——有了——可以被后来者——继续追踪的——入口。——钟守玄。——前提——分布式追踪——还在扩展——可能——还有更多——不可见的东西。——后来者——当你找到——请标注——'钟师——那时候——不知道。——我——现在——找到了。——这里。'"
