# 《万构界·化形卷》设定细化

## 一、卷定位

《化形卷》要回答的问题不是“如何快速做出东西”，而是：

**如何让探索与快速化形，不最终变成新的脚本黑箱。**

这卷必须承认化形之道的真正价值：
- 它让未知有了形
- 它让新问题可以被迅速试探
- 它常是文明最先点火的那双手

但它也必须正视另一面：
若试法没有分层，最灵的火也会长成最深的沼泽。

### 双层主线
- 表层主线：主角把息壤从脚本林、notebook 堆与临时流程中重新分出试法层、固核层、入世层
- 深层主线：主角必须证明，探索之火不必以黑箱沼泽为代价，文明可以既保留试法能力，又不把未来交给无法复现的灵感碎片

---

## 二、时代与宿域

### 1. 时间位置
同样发生在第七时代，但更靠近新需求、新实验与快速变化的边缘地带。

### 2. 主要宿域
主场在**化形试法宿域**，并与**通界前沿宿域**、**协阵扩域宿域**频繁接壤。

### 3. 时代压力
- 新问题层出不穷
- 试验结果需要尽快给出
- notebooks、脚本、临时工具不断长出
- 环境与依赖的漂移比结构本身更先崩坏

---

## 三、核心器、阵、门

### 1. 核心项目：息壤
定位为：
**一个从实验脚本、数据处理和自动化流程中长出来的试法平台。**

它最初只是许多 notebook、脚本和小工具的集合，
但随着越来越多人依赖，它不得不回答“什么该死、什么该留、什么该固核”。

### 2. 息壤的结构形态
- `xirang-lab`：实验与 notebook 区
- `xirang-flow`：自动化流程与脚本群
- `xirang-core`：稳定复用能力
- `xirang-pack`：环境与依赖封装
- `xirang-gate`：对外 CLI / service / API 接口

### 3. 主对象层级推进
- 起卷主对象：念、文
- 中段主对象：骨、器
- 卷尾主对象：门

### 4. 卷内真正的产物
不是把探索全部制度化，而是建立三层分明的秩序：
- 试法层
- 固核层
- 入世层
- 让“先出结果”不再天然等于“以后一定有人替你收烂摊子”

---

## 四、主道与辅道

### 1. 主道
**化形之道**

### 2. 辅道
- 通界之道：推动界面、交互与快速反馈
- 明契之道：逼迫试法成果写下边界
- 简阵之道：当成果进入多人协作和稳定部署时承担后续压力

### 3. 主相与次相
- 主相：式之初轮、流
- 次相：契

### 4. 典型共构关系
- 化形—明契
- 化形—简阵
- 化形—通界

## 五、角色阵型

### 1. 主角位
自动化高手、研究构师或试验环境中的化形者。
他最稀缺的能力，是让未知迅速有了形。

### 2. 镜像者位
极端试法派。
总能第一个把东西做出来，也最容易被短期成果奖赏。

### 3. 守门者位
长期帮大家收拾 notebook、脚本、环境和旧流程的人。
他知道哪些试法救过命，也知道哪些遗迹已经烂到无法再碰。

### 4. 同门者位
来自通界或简阵的协作者。
他代表“东西一旦被别人用上，代价结构就变了”的现实。

### 5. 使用者位
研究者、分析者、运营者或业务团队。
他们不关心你用什么法，只关心结果是否还跑得起来。

### 6. 继承者位
后来接手实验平台的人。
他最先遭遇的不是复杂算法，而是“为什么这个环境根本复现不了”。

### 7. 审契者位
对 packaging、测试、typing、依赖锁定极度敏感的人。
他是试法秩序化的关键压舱石。

### 8. 渡桥人位
负责把 notebook 结论、脚本成果、安全地迁入核心库或服务的人。

### 9. 失传者位
可能是一位留下满地 notebook、实验目录与半成品流程后离开的前辈。
他没有恶意，却用自己的残迹证明：若试法只顾点火不顾归档，最亮的灵感也会变成后来者无法复现的荒地。

### 10. 诱惑者位
不断提出“先出结果”“先给个 demo”“先接上这次需求”的短期压力代表。

---

## 六、主要矛盾与病理

### 1. 表层冲突
- notebook 只在作者机器上能跑
- 环境和依赖漂移
- 重复脚本横生
- 临时解法被长期依赖

### 2. 中层冲突
- 团队分不清什么是实验、什么是产品、什么是临时桥
- 因为试法真的有效，所以没人愿意清理旧遗迹
- “先这样也行”被不断奖励

### 3. 深层冲突
主角最珍贵的能力，恰好是最容易制造未来沼泽的能力。
如果他不能学会分层与止损，就会成为自己最讨厌的黑箱来源。

### 4. 主病理
- 失式
- 背契
- 原型沼泽
- 环境漂移
- 断桥潮

### 5. 主角最容易犯的错
- 留太多半成品
- 把临时解法默认为长期秩序
- 低估后期维护与迁移代价

### 6. 卷级大悬念
真正的问题不是“息壤能不能继续高产”，而是：
**息壤能不能证明，探索速度不必永远靠牺牲复现性、边界感与后来者的理解成本来换。**

---

## 七、叙事推进

### 第一段：灵火
主角凭借极快的化形能力解决了一连串真实问题，化形之道因此被高度奖赏。

### 第二段：沼生
随着越来越多人依赖这些试法成果，脚本林、环境漂移、重复流程与 notebook 真理开始反噬团队。

### 第三段：分层
主角第一次被迫区分：
- 哪些只配停留在试法层
- 哪些值得固核
- 哪些必须真正入世并承担契
- 哪些桥只是临时救急，哪些桥若不回收就会长成下一片沼泽

### 第四段：归约
通过 package 化、依赖锁定、测试、typing、文档和对外接口整理，把真正应该留下的部分沉进稳定层。

### 第五段：留路
卷尾不是让化形之道失去速度，而是让它学会：
- 速度应该停留在哪一层，哪些成果必须被认真送入时间
- 创造力不是靠把一切都变成遗迹来证明自己

---

## 八、工程主题分配

### 起卷阶段
- script / notebook
- 快速原型
- 自动化脚本
- 环境管理

### 中卷阶段
- package 化
- 依赖锁定
- typing
- 测试与复现
- CLI 与库的边界

### 后卷阶段
- 流程固核
- 服务化 / API 化
- 清理试法遗迹
- 迁移与归档策略

---

## 九、卷尾产物

卷尾最理想的收束应包括：

- 息壤的三层结构
- 明确的实验归档与淘汰规则
- 能复现环境的最小制度
- 一批真正被固核、可被他人继续使用的能力

---

## 十、跨卷接口

### 1. 与明契卷
明契卷先建立“什么才算值得写成可继秩序”的判断尺；化形卷则去看在试法前线，这把尺为何总被速度与灵感挑战。本卷单读时，这套判断也会由事故自行建立。

### 2. 与驭器卷
许多快速脚本会通过临时桥调用重器，由此暴露古器边界不清与桥梁长期滞留的风险。

### 3. 与简阵卷
当息壤中的一部分能力进入多人协作与稳定部署后，简阵卷会继续结算它留下的复杂度总账；但息壤本卷的胜负必须在本卷内部完成。

## 主线锚点

### 周栖野的发现
在清理林过川的脚本林时，周栖野发现林过川不是第一个失传者。林过川的旧石镜里存着至少三段比他更早的残码——不同的人，不同的时代，用不同的语言，试图实现同一个功能：让后来者能自动接住前人的东西。每一段都失败了。不是技术失败——是每个人都在最后一刻选择了放弃。放弃的原因写在同一行："后来者应该自己判断。"

周栖野把这个发现贴在息壤的公共记录板上。旁边写："失传不是一个人的事。是一整条链。每一代都在做同一个选择——传什么，不传什么。林过川不是起点。他是这个链上的最后一环。"

### 林过川的真正选择
林过川的"对不起"不是道歉。是他发现了这条链之后做的选择。他选择不整理。不是因为没时间——是因为他发现：整理太好，会让后来者不再自己理解这些脚本。他留下的 README 是一种交接：不是"这里有什么"，是"这里曾经有过什么——你自己去看。自己判断。"
叶藏拙知道这个。但他从来没有告诉周栖野。因为这也是一个不能被告知的道理。
