# 《万构界》四卷学习目标、项目目标与思想命题对照表

## 一、文档定位

本文件建立在 `09–12` 四卷设定与 `19_教学型长篇总蓝图.md` 之上。

它的任务不是替代分卷设定，而是把此前仍然分散在多份文档里的三条主线正式压成同一张执行表：

1. 读者在每一卷到底学会什么
2. 主项目在每一卷到底推进到什么程度
3. 每一卷到底要把什么思想命题写成真正的情节与代价

换句话说，`19` 回答“《万构界》整体要成为什么”，
本文件回答“四卷分别要怎样交付，才能既像小说，又真能教人，又能组成一个完整世界故事”。

---

## 二、基于现有资料发现的四个不足

### 1. 卷级命题已清楚，但读者成长路径还不够显眼

现有 `09–12` 都已经有强命题，
但此前仍缺一张明确对照表，说明读者从第一卷到第四卷究竟经历怎样的判断升级。

### 2. 主项目名称与组件已经有了，但项目里程碑还不够硬

青炉、玄枢、息壤、驿河都已成立，
但此前更多是在说明“这是什么项目”，
还不够明确“这一卷结束时，项目必须被推进到什么可验证状态”。

### 3. 思想命题已成立，但还需要和戏剧代价绑定

此前每卷都有哲学气质，
但如果不把它和角色失去什么、承担什么、证明什么绑定起来，
思想就容易停在气氛，而不是落成故事。

### 4. 跨卷关系已成立，但单卷自足与卷尾交接标准还不够硬

此前已经明确四卷互文但不硬依赖，
但还需要进一步写明：

- 本卷单独阅读时，读者必须得到什么
- 卷尾应该留下什么，才能自然交给下一卷

## 三、总编排原则

### 1. 卷序按工程判断成熟度，而不按语言入门难度

第一阶段四卷顺序仍固定为：

**明契 → 驭器 → 化形 → 简阵**

原因不是 Rust 比其他语言“更适合所有新人”，
而是《万构界》这套世界解释器，本来就先从契、史、边界、责任出发。

### 2. 每一卷都必须同时完成四种交付

- 教学交付：让读者获得一段清楚的工程判断升级
- 项目交付：让主项目抵达一个可以被验证的阶段成果
- 剧情交付：让卷内主冲突在本卷内成立并完成结算
- 思想交付：让角色用代价证明一种文明判断，而不是只说出来

### 3. 单卷自足的最低标准

每一卷都必须满足下面四条：

- 不依赖前卷知识也能读懂本卷核心事故与主冲突
- 本卷最关键的判断尺必须在本卷内部重新立起
- 本卷主项目的胜负必须在本卷内部完成一次清楚结算
- 卷尾必须留下可被下一卷接住的公共问题，而不是剧情硬断

### 4. 正文与卷外配套继续双轨分工

正文负责：

- 问题为什么痛
- 人为什么这样选
- 代价到底落到谁身上
- 语言哲学为什么会长成这样

卷外配套负责：

- 最具体的实践动作
- 项目里程碑拆解
- 术语、工具、命令与练习索引

这套配套系统的统一说明与模板，现已落到：

- `21_卷外配套系统与模板说明.md`
- `卷外配套/00_配套索引.md`

## 五、分卷展开

### 1. 明契卷

#### 读者起点

适合这样一类读者进入：

- 写过脚本、CLI、小工具或课程项目
- 见过“能跑就行”的现实
- 听过测试、文档、版本、review 这些词
- 但还没有把它们理解成同一套责任结构

#### 本卷学习目标

- 学会从事故定义问题，而不是从功能清单定义项目
- 学会区分“命令成功”和“秩序成立”
- 学会理解 scope、manifest、边界、错误处理与模块拆分
- 学会理解 README、测试、review、changelog 为什么不是附属劳动
- 学会理解继承失能为什么是文明病，而不是团队偶发混乱

#### 本卷项目目标

青炉本卷必须被推进到：

- 有清楚的问题定义与非目标
- 有可信的 CLI 入口与配置边界
- 有能代表真实行为的测试
- 有最小发布口径与兼容承诺
- 有后来者可以继续推进的门规入口

#### 本卷戏剧任务

- 通过卷首事故让世界第一次看见“旧脚本成功执行”并不等于“公共秩序可靠”
- 让主角从救火者转向立约者
- 让主角失去“只有我能修”的价值中心
- 让卷尾真正出现一次不靠主角在场也能接火的继承场景

#### 本卷思想命题

**写清楚，是不是一种文明责任。**

这不是“文档重不重要”的职场口号，
而是整个系列的第一判断尺：
若契与史不被写下，后来者就只能继续靠人脑、口传与事故学习。

#### 卷尾完成判据

- 青炉不是主角私器，而是门内公共器
- 至少一位继承者能够沿门规继续推进
- 使用者开始相信“这套东西的行为是可预期的”
- 读者明确获得“责任先于技巧炫示”的第一把尺

#### 对下卷交接

明契卷卷尾应自然留下两类问题：

- 旧核与古器深处，到底藏着多少只能靠少数人解释的重量
- 许多试法前线的临时桥与老脚本，到底是怎样一路长成今天的病

也就是说，它可以同时向驭器卷与化形卷开门，但不强制读者先读后者。

#### 本卷卷外配套最低配置

- 章节实践单：问题定义、scope、错误处理、测试与 README
- 卷级项目里程碑表：青炉从事故修补到最小可信发布
- 术语索引：契、史、门规、继承失能、兼容承诺

---

### 2. 驭器卷

#### 读者起点

读者在进入本卷前，最好已经具备：

- 对边界、责任与继承的基本判断
- 对模块、配置、测试与发布最小秩序的认识
- 对“历史遗留不会自己消失”的直觉

#### 本卷学习目标

- 学会理解 build system 与平台差异不是细枝末节，而是古器生存条件
- 学会理解 ABI、FFI、unsafe 边界与资源生命周期
- 学会理解 profile、dump、trace、probe 这些诊断手段为什么是接火工具
- 学会理解 wrapper、adapter、runbook 与兼容策略
- 学会区分“我会修”与“别人能接”之间的巨大差距

#### 本卷项目目标

玄枢本卷必须被推进到：

- 核心危险边界被明确标识
- 外部调用通过较清楚的包裹层接近核心
- 关键诊断手段被公开化、制度化
- 维护者知识从秘义变成有梯度的接火路径

#### 本卷戏剧任务

- 让主角第一次真正看见古器的功绩与风险同时成立
- 让“传奇宗匠”不再只是偶像，而成为结构性问题的见证
- 让主角放弃“成为下一位唯一掌火者”的诱惑
- 让卷尾形成一条不靠传奇独占也能继续运转的传火阶梯

#### 本卷思想命题

**功绩不能替代交代，敬畏也不能替代传火。**

真正可敬的不是“只有我会修”，
而是明知古器沉重，仍然肯为后来者留下进入重器的梯子。

#### 卷尾完成判据

- 重器不再只有极少数人知道如何接近
- 最危险的边界被明确写出，而不是继续靠暗规维持
- 维护者开始接受“公共知识不会削弱重器尊严，反而保护它”
- 读者获得处理历史重量与危险边界的第二把尺

#### 对下卷交接

驭器卷卷尾应自然把两个问题抛给后续：

- 许多临时桥为什么会在古器边缘积成长期债
- 如果没有试法前线点火，很多后来平台其实根本不会出现

这使它可以把读者自然送入化形卷，但本卷自身必须完成“传火可能性”的结算。

#### 本卷卷外配套最低配置

- 章节实践单：build、FFI、unsafe 边界、诊断与 wrapper
- 卷级项目里程碑表：玄枢从事故追史到边界重写与阶梯接火
- 术语索引：古器系缚、观象、接火、适配层、兼容债

### 3. 化形卷

#### 读者起点

本卷最适合接在前两卷之后阅读，因为此时读者已经知道：

- 责任和边界为什么重要
- 历史遗留为什么会长期讨债
- “快而有效”不能天然免责任

在这个前提下，读者才能真正公平地重新看待化形之道，而不是简单把它写成轻浮快法。

#### 本卷学习目标

- 学会区分 notebook、脚本、自动化流程、库与服务的不同责任层
- 学会理解 environment、dependency lock、packaging、typing、testing 与 reproducibility
- 学会判断什么只适合停在实验层，什么必须固核，什么必须入世
- 学会理解试法遗迹如何形成，以及为什么必须清理、归档、删桥
- 学会理解速度真正的价值，以及速度真正的代价

#### 本卷项目目标

息壤本卷必须被推进到：

- 试法层、固核层、入世层三层结构成立
- 环境复现与依赖封装最小制度成立
- 值得留下的能力被抽进稳定层
- 不再需要的实验遗迹被归档或淘汰
- 对外入口不再由 notebook 真理直接承担

#### 本卷戏剧任务

- 让主角看见自己最珍贵的能力，也正是最可能制造废墟的能力
- 让短期奖赏与长期秩序发生真正冲突
- 让“先出结果再说”被写成真实有效但必须止损的道路
- 让卷尾完成一次真正的分层与删桥，而不是口头宣布规范

#### 本卷思想命题

**速度与灵性可以被保住，但不能靠牺牲复现性与后来者理解成本来维持。**

这卷不是否定探索，
而是证明：若文明不能把试法送入时间，最亮的灵感也会变成荒地。

#### 卷尾完成判据

- 息壤的三层边界可被讲清楚
- 后来者能够复现实验，而不是只能膜拜作者机器
- 团队开始接受“不是所有有用的东西都该永久留下”
- 读者获得处理速度、原型与秩序关系的第三把尺

#### 对下卷交接

化形卷卷尾应向简阵卷留下清楚接口：

- 哪些能力准备进入多人协作与长期运行
- 哪些试法成果一旦入世，就必须面对发布、观测、回滚与 ownership

但本卷自身必须已经完成“试法分层是否成立”的胜负结算。

#### 本卷卷外配套最低配置

- 章节实践单：环境管理、打包、typing、测试、迁移与归档
- 卷级项目里程碑表：息壤从 notebook 林到三层平台
- 术语索引：试法层、固核层、入世层、环境漂移、原型沼泽

---

### 4. 简阵卷

#### 读者起点

进入本卷时，读者最好已经具备三层前置判断：

- 知道边界、契约与责任必须写明
- 知道历史重量与兼容债会长期存在
- 知道试法成果若要入世，就必须接受分层与交接

本卷负责把这些判断全部拉进多人协作与长期运行的现实。

#### 本卷学习目标

- 学会理解 service boundary、ownership 与团队协作成本
- 学会理解 goroutine、channel、context 这类并发工具在工程中的责任语义
- 学会理解 deploy、rollback、incident response、runbook 与 observability
- 学会理解 tracing、metrics、logs 为什么不是附加豪华件
- 学会区分“表面统一”与“真正简明”

#### 本卷项目目标

驿河本卷必须被推进到：

- 服务责任图清楚
- 发布与回滚路径清楚
- 关键观象手段清楚
- ownership 与 oncall 秩序清楚
- 迁移与兼容期不再无限延长

#### 本卷戏剧任务

- 让主角面对平台扩张后“大家都在用，但没人真的看懂”的局面
- 让“统一口径”与“真实差异”发生冲突
- 让被隐藏的复杂度在事故中集中讨债
- 让卷尾证明：平台可以不是靠少数老人值班和隐性经验维持

#### 本卷思想命题

**真正的简，不是把复杂删掉，而是让复杂回到该被看见、该被负责的位置。**

简阵之道不是抽象癖，
而是文明在规模化现实中重新分配理解成本与责任成本的方法。

#### 卷尾完成判据

- 平台不再只靠老人脑内模型维持
- 责任、观测、发布、回滚和事故复盘都变成公共秩序
- 新人第一次能真正看懂、敢改、能守
- 读者获得处理规模化系统与组织责任的第四把尺

#### 对后续阶段交接

简阵卷是第一阶段总收束。
它卷尾应留下的不是“世界完全治好”，而是：

- 跨门共享判断尺第一次成立
- 后来者第一次有比前代更清楚的入口
- 文明第一次证明秩序可以不靠少数传奇单点续命

这会成为第二阶段诸卷继续扩写的公共地基。

#### 本卷卷外配套最低配置

- 章节实践单：服务边界、部署、观测、事故响应、回滚与 runbook
- 卷级项目里程碑表：驿河从扩域失明到成阵定责
- 术语索引：ownership、oncall、观象、回滚、平台门规

## 六、为什么这个顺序成立

四卷顺序必须是“明契 → 驭器 → 化形 → 简阵”，原因可以压成四步：

### 1. 先问什么算成立

明契卷先回答：
什么叫边界，什么叫承诺，什么叫后来者可接。

没有这一层，后面所有重器、试法、服务阵都只会变成风格之争。

### 2. 再问历史重量如何被接住

驭器卷把第一卷立起的判断尺压进旧核和古器，
让读者知道：问题不只是“写不写清楚”，还包括“历史重到什么程度时，清楚本身都很难”。

### 3. 再回头看速度与生长

化形卷不应放在前两卷之前，
因为如果太早进入“速度、灵感、试法”视角，读者很容易只看见它的爽快，而看不见它如何制造后债。

先有明契与驭器的判断尺，再回头看化形，读者才能同时看懂它的价值与风险。

### 4. 最后在系统规模里结总账

简阵卷必须最后出现，
因为只有当前三卷已经把边界、历史、试法三类债都立住，
“多人协作、长期运行、观测、回滚、治理”才不会写空。

## 七、本表落地后的直接用途

从这一版开始，后续所有章纲、人物卡与卷外配套，都应先对照本文件检查三件事：

1. 这一卷到底要让读者多获得哪一把判断尺
2. 这一卷的主项目到底要抵达什么可验证状态
3. 这一卷的思想命题到底通过谁的代价被证明

如果一场戏不能同时回答其中至少两项，
那它大概率还没有真正接上《万构界》的教学型长篇目标。
