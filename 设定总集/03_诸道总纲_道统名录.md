# 诸道总纲与道统名录

## 一、总原则

在万构界中，编程语言不是语法集合，而是**构世之道**。
每一道都在回答同一个文明难题：

**如何让器成立、让阵运转、让门可继。**

---

## 二、诸道分类

### 1. 原道
具有独立文明回答、独立气质、独立戏剧张力，足以单独成书的大道。

### 2. 宿道
与特定宿域高度共生，脱离其平台生态就难以完整显形的道路。

### 3. 覆道
建立在既有主道或同一生态上的约束增强层、工程强化层。

### 4. 学脉
思想性极强，常以旁照、回潮、借势的方式影响诸道的高地之脉。

---

## 三、理解诸道的四重判定法

未来判断一门语言在万构界中的位置，至少要连问四次：

### 1. 血脉
- 它在思想谱系上更像谁
- 它继承了哪些旧问题与旧答案

### 2. 宿域
- 它主要寄居在哪个大平台世界
- 它与谁共享运行时、生态与工具链

### 3. 道心
- 它最先守什么
- 它愿意先牺牲什么
- 它如何排序边界、速度、控制、协作、继承

### 4. 行界
- 它在现实工业中最常出现在哪些疆域
- 它最典型的工程战场是什么

## 五、补充判定

### 1. 明契之道为何归原道
明契之道虽然常借他宿立炉，但它对“黑箱化与继承失能”给出了独立而完整的文明回答，因此归原道而非宿道。

### 2. 通界之道为何归宿道
通界之道最强烈的戏剧张力来自前沿边界的高速变化，它与宿域生态深度绑缚，因此更适合归入宿道。

### 3. 简阵之道不是容断之道的弱化版
容断之道回答的是“局部失守成为常态后如何继续活”；
简阵之道回答的是“多人共构、频繁部署、长期维护下如何让阵仍可共同理解”。

### 4. 覆约支不是独立主道
覆约支的力量建立在既有通界生态之上，本质是对式与契的补强，而不是重新发明完整宇宙回答。

### 5. 造言之道不必独占宿域
造言之道常在关键转型期出现，靠改写构器之法影响诸道，因此更像跨宿匠脉，而不是固定平台文明。

### 6. 血脉相近，不等于宿域相近
- F# 与 C# 宿域相近，但血脉与道心差异很大
- TypeScript 与 JavaScript 血缘同源，但在道心上更重式与契
- Scala 与 Java 同宿，却不等于同道

### 7. 宿域相近，不等于行界相同
同住一个宿域的道统，也可能在现实中承担完全不同的工程职责。
因此后续筛题时，不应只看“跑在哪”，还要看“常在哪类战场上显世”。

### 8. 求式之道宜先统写，再分四支
求式之道在当前阶段更适合作为一条思想高地总脉统一处理，而不是过早拆成多本。
若后续要继续细分，可先按四支留位：
- 纯演支：Haskell，偏纯度与现实的张力
- 务式支：OCaml，偏表达力与务实的平衡
- 归台支：F#，偏异血入宿与平台制力
- 杂融支：Scala，偏统一诸式的野心与代价

## 六、筛题原则与开卷优先级

### 1. 系列扩张原则
万构界后续不应按“语言名单”扩张，而应按“独立文明回答”扩张。
一门语言若不能带来新的母题、新的戏剧张力、新的病理切面，就不宜急于单独成卷。

### 2. 第一梯队主卷
- 明契卷：秩序如何可继
- 驭器卷：文明如何继续驭使古老重器
- 化形卷：探索如何不坠为脚本沼泽
- 简阵卷：扩张中如何守住简明与协作

### 3. 第二梯队主卷
- 容断卷：断裂成为常态后，秩序如何继续活
- 通界卷：变化最快的人器边界如何守约

### 4. 第三梯队高概念卷
- 守序卷：大型共同体中的长期制度秩序
- 造言卷：当现有器具不足以构世时，能否改造造器之法
- 求式卷：形式、表达与现实工程如何真正接轨

### 5. 当前不宜急于独开的支脉
- Kotlin：更像守序宿域内部的现代化更新，不足以优先拉开独立卷气质
- TypeScript：应与通界卷共写，维持“通界主道 + 覆约支”的结构
- F# / Scala：更适合作为求式之道在平台宿域中的分支，而不是先拆成单卷
- Elixir：更适合作为容断卷内部的重要支火，而不是脱离 Erlang 单开

### 6. 可留作未来旁卷的方向
- 学图卷 / 算学卷：以 R 与统计文明为入口，处理图形、数据、学术传统之道
- Swift 或平台交界卷：若后续要写平台制力与原生交界，可另起支卷
