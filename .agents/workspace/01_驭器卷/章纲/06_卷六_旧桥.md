# 卷六「旧桥」Ch 51-60：十七条旧桥谱系

## Section 总览

- **章段**：Ch 51-60
- **叙事主题**：十七条旧桥谱系——每一条都是"临时"的，没有一条承认自己是永久
- **核心冲突**：桥支撑整个系统运转——但每一座桥都在消耗注意力，随时可能断裂
- **工具链阶段**：旧桥——Git制度化（commit记录桥的出生和退场），cppcheck运行中
- **对象层**：阵（桥作为器与器之间的连接——每条桥都是一个依赖关系）
- **主相→蚀**：流+史 → 乱流+断史
- **张力引擎**：十七条桥——每一条背后都有一个"先搭上，回头再拆"的故事。回头从来没有来过。
- **卷尾落点**：桥谱系建立——十七条桥，至少七条可以开始拆。但更深的问题在观测。

### 第51章：旧桥谱系

- **核心对象层**：阵
- **核心相与失守**：史 → 断史（桥的历史被遗忘）
- **工程锚点**：桥的分类学——wrapper/adapter/shim/bridge/façade，Git追溯
- **张力曲线**：攀升型（Section开局——建立桥谱系→逐条追溯→发现惊人模式）
- **角色焦点**：纪承钧（建立桥谱系——十七条桥，每一条都比预想更老）；陆踏痕（协助——用Git追溯桥的commit历史）；沈照痕（观测数据——"这座桥每月被调用三万次，没人知道它还在被用"）
- **六拍骨架**：
  1. 问题先出：从残码发现中回神——纪承钧追查玄枢连接外部系统的十七条桥。每一条的起源都是"临时"二字
  2. 为什么痛：每条桥都在支撑真实系统——北岭设备集群、外部调用方、跨道依赖。但没有一条桥有退场日期。最老的桥活了11年——搭桥的人已离职7年
  3. 引出方法：Git石录制度化——用`git log`和`git blame`追溯每条桥的第一次commit。大多数commit message都是"临时方案"或"先搭上"
  4. 项目落地：建立桥谱系——按类型分类，标注出生时间、作者、最后活跃时间、依赖方数量。平均年龄4.7年
  5. 多方复盘：陆踏痕的统计——"十七条桥。最老的——11年。11年前Git还没被发明。那条桥的历史——只有文件夹备份。"
  6. 高层收束：旧桥谱系不是指责——是理解"为什么桥会从临时变成永久"。快是桥的出生方式——也是桥永远死不了的原因
- **入门检查**：前置：Ch14-16（临时方案考古）/ 新术语：桥（bridge）作为通用概念、shim（≤2）
- **三问预检**：🩻断史 😣依赖桥的用户——他们不知道自己在桥上走 🛤️开始——桥谱系建立

### 第52章：适配层

- **核心对象层**：阵→门（适配层——wrapper的边界安全）
- **核心相与失守**：式 → 失式（wrapper的结构性脆弱）
- **工程锚点**：wrapper设计——compatibility layer的安全边界和隐式假设
- **张力曲线**：倒钩型（追溯最深的一处wrapper→发现安全假设→验证→假设早已不成立）
- **角色焦点**：纪承钧（追溯最老的wrapper——包裹着钟守玄也说不清来源的代码）；陆踏痕（fuzzing测试——wrapper在47%异常输入下产生未定义行为）
- **六拍骨架**：
  1. 问题先出：纪承钧深入分析最老的wrapper——包裹玄枢核心的一段Fortran代码，作者早已离职
  2. 为什么痛：wrapper的安全假设——"输入永远是非负整数"——两年前被打破，外部系统开始传入浮点数。wrapper截断了——行为恰好正确，但只是恰好
  3. 引出方法：wrapper的本质——不是让不安全变安全，是让不安全"看起来安全"。真正的安全需要边界检查、输入验证、错误处理——这些wrapper都没有
  4. 项目落地：陆踏痕fuzzing测试——47%异常输入下产生未定义行为。"Wrapper没有让事情更安全——只是让不安全的事看起来更远"
  5. 多方复盘：钟守玄看了fuzzing结果——"这就是为什么每两年断一次火。wrapper给了所有人假的安全感"
  6. 高层收束：适配层不是问题——没被审计的适配层才是。每个wrapper都应定期审计：输入假设还成立吗？边界条件还正确吗？
- **入门检查**：前置：Ch51 / 新术语：fuzzing、输入验证（input validation）（≤2）
- **三问预检**：🩻失式 😣依赖wrapper的外部调用方——他们的"安全"是假的 🛤️开始——wrapper审计制度化

### 第54章：桥上的用户

- **核心对象层**：阵→人（桥上的用户——不知道自己站在什么上面）
- **核心相与失守**：契 → 背契（桥对用户的隐性承诺——双方都不知道承诺存在）
- **工程锚点**：迁移代价——拆桥的社会工程学，迁移指南和弃用窗口期
- **张力曲线**：双峰型（发现用户→沟通→恐慌→制定迁移计划）
- **角色焦点**：纪承钧（走访北岭——"你们依赖的这条桥，是一个三年前就该拆的临时方案"）；北岭运维（"对我们来说——它就是生产环境。我们没有备用方案。"）
- **六拍骨架**：
  1. 问题先出：纪承钧决定拆第一条桥——先通知桥上用户。北岭的反应："你拆了它——我们的每日结算就会断。"
  2. 为什么痛：北岭不知道它是临时的——"对我们来说，它就是生产环境。我们依赖了三年。"
  3. 引出方法：拆桥的前提——不是桥可以被拆，是桥上的用户有替代路径。迁移指南："从此桥到新路——你需要知道的事"
  4. 项目落地：为北岭写迁移指南——"第一步：确认你的调用路径。第二步：在新接口上测试。第三步：确认无误后——旧桥停止。给你一个月。"
  5. 多方复盘：陆踏痕——"拆桥不是技术活——是沟通活。"钟守玄——"这就是为什么旧桥越来越多。沟通比搭桥难得多。"
  6. 高层收束：桥上的用户不是敌人——是被"临时方案"困住的人。拆桥的人有责任为他们建新路
- **入门检查**：前置：Ch53 / 新术语：迁移指南（migration guide）、弃用窗口期（deprecation window）（≤2）
- **三问预检**：🩻背契 😣桥上的用户——需要迁移 🛤️开始——有迁移指南和窗口期

### 第55章：渡桥司

- **核心对象层**：阵→制度（渡桥司——管理桥的机构）
- **核心相与失守**：契 → 制度漏洞（"临时桥"豁免登记——制度默许了谎言）
- **工程锚点**：桥的出生证和死亡证制度——渡桥司的制度设计及其局限
- **张力曲线**：攀升型（渡桥司来人→发现制度漏洞→制度默许了"临时"的谎言→修复）
- **角色焦点**：渡桥司来人；纪承钧（"你们的制度——为什么漏了十三条？"）
- **六拍骨架**：
  1. 问题先出：渡桥司使者来访——从公共记录板上的伤痕得知玄枢在拆桥。但登记册上只有四条玄枢的桥——另外十三条从未被登记
  2. 为什么痛：制度漏洞——"因为那些桥搭的时候说'等新版本出来就拆'。既然是临时的——就不需要登记。"
  3. 引出方法：制度的盲区和人的盲区一样——"临时"听起来比"永久"轻松，所以大家都选择相信"临时"
  4. 项目落地：纪承钧与渡桥司协商——十七条桥全部补登记。"没有桥是临时的——只是有些人希望它们是临时的。制度不能建立在希望上。"
  5. 多方复盘：渡桥司来人的反思——"我们的制度默许了'临时'这个谎言。承认永久——意味着要承担永久的责任。"
  6. 高层收束：制度也有盲区。制度的盲区往往和人的盲区重合
- **入门检查**：前置：Ch54 / 新术语：渡桥司（worldbuilding）、桥的出生证和死亡证（≤2）
- **三问预检**：🩻契（制度漏洞被修复） 😣未来的渡桥司——需要管理更多"临时"桥 🛤️是的——制度不再豁免"临时"

### 第56章：shim与adapter

- **核心对象层**：阵（桥的工程分类——不同桥不同拆法）
- **核心相与失守**：式 → 失式（不同桥类型对应不同结构脆弱性）
- **工程锚点**：shim/adapter/façade/bridge的分类学和拆除策略
- **张力曲线**：双峰型（分类学→典型失败模式→为每类设计不同拆除策略）
- **角色焦点**：纪承钧（建立分类学）；陆踏痕（为每类桥设计拆除checklist）
- **六拍骨架**：
  1. 问题先出：陆踏痕发现不同类型的桥拆除难度不同——shim最容易，adapter最难
  2. 为什么痛：用拆shim的方法拆adapter——调用方数据格式不兼容。"adapter不只是改调用方——是改两边对数据的理解"
  3. 引出方法：shim（薄层，替换即可）、adapter（适配接口差异，需两边同时升级）、façade（简化接口，需提供新façade）、bridge（连接独立系统，需先建新桥才能拆旧桥）
  4. 项目落地：陆踏痕为每类桥写了拆除checklist——"shim：确认调用路径→替换→移除。adapter：确认两边数据格式差异→两边升级后→移除。"
  5. 多方复盘：钟守玄——"以前拆桥靠一个人说'这个可以拆'。现在拆桥靠'这类桥应该这样拆'。你把经验变成了方法。"
  6. 高层收束：不是所有桥都该用同样的方法拆——知道桥的类型，才知道拆它的正确方法
- **入门检查**：前置：Ch51 / 新术语：shim、façade、bridge pattern（≤3）
- **三问预检**：🩻失式 😣无——制度建设 🛤️是的——后来者知道"这类桥该这样拆"

### 第57章：不能拆的桥

- **核心对象层**：阵→现实（有些桥拆了会让世界的一部分停转）
- **核心相与失守**：流 → 乱流（拆除会导致北岭设备集群全部停转）
- **工程锚点**：现实约束 + 包裹策略（wrapping strategy）
- **张力曲线**：攀升→崩塌型（发现这条桥→制定策略→发现不能拆→接受现实→包裹策略）
- **角色焦点**：纪承钧（"这条桥——拆了会让北岭设备集群全部停转。它不能拆。至少现在不能。"）
- **六拍骨架**：
  1. 问题先出：陆踏痕发现一条"deep-bridge"——维持北岭设备集群和玄枢之间唯一的通信协议
  2. 为什么痛：北岭设备是第三时代老硬件——不支持新协议。拆了它——北岭全部停转，不是降级，是完全停转
  3. 引出方法：不能拆的桥用包裹策略——在旧桥外建新桥，新桥提供现代接口，底层仍走旧桥协议。等北岭硬件升级后——旧桥自动退役
  4. 项目落地：包裹策略——不是最优雅的解法，但是唯一安全的解法
  5. 多方复盘：钟守玄——"这就是为什么我从来不说'拆'。知道拆得了哪些、拆不了哪些——比'把所有桥都拆了'更重要。"
  6. 高层收束：不是所有问题都有完美方案——有些事只能等。知道什么可以等、什么不能等——是判断力，不是知识
- **入门检查**：前置：Ch54-56 / 新术语：包裹策略（wrapping strategy）、遗产系统（legacy system）（≤2）
- **三问预检**：🩻乱流 😣北岭操作者——如果拆了就没法工作 🛤️是的——包裹策略保证过渡期

### 第58章：桥的代价

- **核心对象层**：阵→人（桥的真正代价——不是代码，是注意力）
- **核心相与失守**：全部（桥的代价是系统性——消耗注意力、制造不可见性、阻碍后来者）
- **工程锚点**：维护成本量化——每座桥每年消耗多少人的注意力
- **张力曲线**：攀升型（量化代价→逐条展示→总和的震撼→认知升级）
- **角色焦点**：陆踏痕（制作"桥的代价表"——十七条桥每年引发37次事故或困惑）
- **六拍骨架**：
  1. 问题先出：陆踏痕计算每座桥的年维护成本——不只是代码行数，是事故次数、困惑次数、影响人数
  2. 为什么痛：十七条桥——每年37次事故或困惑。每一次——都是某个人在凌晨被叫醒，或花了一下午才发现"原来是这座桥在作怪"
  3. 引出方法：桥的真正代价——认知负载。"这段代码的行为为什么和文档不一样"——那种困惑
  4. 项目落地：最贵的那座桥——十一年来引发超过200次事故或困惑
  5. 多方复盘：钟守玄——"这比任何runbook都更说明问题。桥消耗了我们最稀缺的资源：注意力。而我们甚至不知道。"
  6. 高层收束：不是一次性支付就可以忘记——是每年、每月、每次新系统接入时都在支付
- **入门检查**：前置：Ch57 / 新术语：认知负载（cognitive load）（≤1）
- **三问预检**：🩻全部 😣每个被桥困住过的维护者 🛤️开始——代价被量化了

### 第60章：旧桥之后

- **核心对象层**：阵→器（从桥到观测——需要看见的不只是桥，是整个系统的运行状态）
- **核心相与失守**：全部 → 向卷七过渡
- **工程锚点**：卷尾收束——桥的可见性问题解决后，运行时不可见性浮现
- **张力曲线**：收束→开门型（总结旧桥→引出观测→向卷七开门）
- **角色焦点**：纪承钧（"桥我们已经能看见了。但桥上的东西——在运行的时候发生了什么——我们还看不见。"）；沈照痕（"先照后立"）
- **六拍骨架**：
  1. 问题先出：旧桥清理完成。最大发现不是十七条桥——是"可见性"本身的价值
