# 明契卷 · 第57章 · 苏野平的脚本

苏野平从化形卷过来，带着一句“我那边有个脚本能帮上”。他写了一个 Python 依赖扫描脚本，调用`pip-audit`检查已知安全漏洞并整理结果；它不判断依赖兼容性，也不单凭扫描结果判定某个依赖已经废旧。

“我先放进workspace，在本地试跑。等CI有了同等的漏洞扫描步骤，或者旧的Python依赖迁走，再删掉这层脚本。”

“运行入口写在哪儿？”沈见微问。

“看代码就行，很简单。”

“谁来跑、输入什么、结果该怎么看？”沈见微指着脚本，“若只靠你在场解释，其他人接不过去。”

苏野平没有否认这一点：“我能把这些写在脚本旁边，不必先写一篇长文档。”

沈见微在脚本名旁写下三项：运行方式、结果解释、维护责任与退场条件。苏野平在另一页画了CI接入草案：“如果今晚就接进夜间构建，漏洞能早点被发现。”沈见微没有签字：“先看本地试跑能否被别人复走。明天再决定它能不能成为每个人都依赖的构建步骤。”两人把草案留在待审栏。
