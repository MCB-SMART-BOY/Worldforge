# 明契卷 · 第57章 · 苏野平的脚本

苏野平从化形卷过来——带着 Python 的生态和"我那边有个脚本能帮上"的姿态。他写了一个 Python 依赖扫描脚本——调用 pip-audit 检查已知安全漏洞，并把结果整理出来。它不负责判断依赖之间是否兼容，也不会单凭扫描结果判定某个依赖已经废旧。

"放你 workspace 里——先临时用着。等现有 CI 有了同等的漏洞扫描步骤，或者旧的 Python 依赖迁走，再删掉这层脚本。"

"你的脚本——文档在哪？"

"呃——看代码——很简单的——三百行——不需要文档。"

"三百行——不需要文档。但后来者看到 py 文件——不知道它做什么，什么时候该跑，结果该怎么看。你的脚本——依赖了 pip-audit——它的版本变了，接口或扫描结果可能跟着变——后来者不知道。'简单'——不等于'清楚'。"

苏野平从化形卷带来的不是一条普遍的道规，而是他自己的做事习惯：先把可用的东西交出来，再看它会不会留下。"三百行不算多，"他说，"有时把入口和输入输出说明白，就比先写一份长文档更能帮上忙。"

沈见微没有立刻反驳，只在脚本名旁边写下三行待补：如何运行、结果怎么看、何时退场。扫描器可以先跑；它的边界也得跟着一起交给后来者。苏野平瞥见那几行字，没删，只把光标移回文件开头。
