# 明契卷 · 第45章 · 宗门初立

青炉早在第14章就立起了 workspace。如今新拆出的成员也要登记进来，根目录清单上又多了几行。各 crate 仍有各自的接口和发布承诺；Cargo workspace 则让它们共享根目录的 `Cargo.lock` 和默认构建目录，一起接受跨成员的构建检查。

"不是'合并代码'——是让 crate 之间的依赖在同一座工地里被管理。成员之间仍须显式声明依赖；workspace 不会替它们保证 API 兼容，也不会自动统一各自的版本号。用 `cargo check --workspace` 或 `cargo test --workspace`，可以要求构建系统检查所有成员及其当前依赖能否一起编译、测试。"

workspace 不会替青炉决定边界。多个 crate 各自承担不同的承诺，却在一张清单里彼此可见。每个 crate 仍可有自己的 CI、发布节奏和版本号；根清单让后来者看清成员关系，是否兼容则要回到各自声明的依赖与公开接口。
