# 明契卷 · 第45章 · 宗门初立

Ch14那时，青炉还只有一个 package；到Ch31，命令入口与核心检查已经分成 `qinglu-cli`、`qinglu-core` 两个 workspace 成员。现在，配置读取仍挤在命令入口里，检查与解释结果也留在核心 crate。季循建议把这两处边界各自拆出来：`qinglu-config`承接Ch33建立的配置读取，`qinglu-doctor`承接Ch27–28已复走的检查与说明路径。拆完后，他们把两个新 package 登记进根清单。

各 crate 仍有自己的接口与版本声明；workspace 让它们共享根目录的 `Cargo.lock` 和默认构建目录，也能一起接受跨成员的构建检查。成员之间仍须显式声明依赖，workspace 不会替它们保证 API 兼容，也不会自动统一版本。

"不是把所有代码揉成一块——是把已经拆开的 package 放进同一座工地里管理。用`cargo check --workspace`，我们能检查当前成员能否一起通过构建；但这不能证明接口兼容，也不能替我们决定哪些成员应该公开发布。"

运行检查时，`qinglu-config`的字段错误从`qinglu-doctor`入口返回；构建摘要仍在`qinglu-core`里，命令参数和终端输出留给`qinglu-cli`。季循追着一条依赖边核对了两遍，确认它们没有因为搬进workspace就互相获得额外权限。根清单让成员关系看得见，边界仍须由每个 crate 的依赖与公开接口说明。
