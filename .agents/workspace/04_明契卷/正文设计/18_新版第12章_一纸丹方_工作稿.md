# 新版第12章《一纸丹方》工作稿

> **状态：工作稿，不是正式正文。** 目标映射现有第05章《一纸丹方》。本稿保留“声明先于实现”的冲突，将Cargo.toml写作Cargo读取、协作者可检查的manifest；不把它神化成行为保证，也不将semver讲成自动通知或强制审批机制。依赖的精确解析与锁文件只作边界提示，留待后续对应章节展开。

---

季循把昨夜的试验记录放在一旁，照着新写的步骤建立青炉的空项目。

目录里多了一个 `Cargo.toml`，几行字安静地留在镜面上：

```toml
[package]
name = "qinglu"
version = "0.1.0"
edition = "2024"
```

苏野平看了一会儿：“炉子还没本事，名字和版本倒先占齐了。”

“名字是给Cargo和协作者识别这个包用的。”沈见微说，“版本也是项目声明的一部分。它不会替我们判断青炉够不够成熟，更不会因为写了某个数字就替使用者发出通知。”

贺时进把手搭在桌沿：“那就写成 `1.0.0`。外面看到零开头，只会觉得我们不敢交付。”

程知序抬头看他：“外面要的不是一个好看的数，是这东西现在能做什么、出了范围怎么办。数字说不完这些。”

沈见微没有急着反驳。他让季循逐行念出文件里真正存在的东西：包名、版本、Rust edition。季循又打开Ch09留下的首版范围草案，把构建、测试和发布的候选边界摆在旁边。两张纸挨着，却没有互相替代。

“`Cargo.toml`告诉Cargo怎样识别和组织这个包。”闻衡说，“其中的依赖、目标和功能选项，会改变Cargo怎样构建它；但它不负责描述每条业务路径，也不能证明我们说过的所有行为都已实现。”

“那这个版本号到底答应了什么？”季循问。

“它是我们选定的包版本。”沈见微说，“若要发布，就按约定维护版本变化；但工具不会替我们决定什么时候算破坏兼容，也不会替我们逐个通知依赖者。兼容承诺得由项目规则和发布过程说明。”

贺时进皱起眉：“你把话拆得太细，别人只会觉得我们什么都不肯承诺。”

“恰好相反。”程知序把scope推到文件旁边，“我们承诺在约定范围里做事，也承诺把边界讲明白。不能让一个版本数字替代使用说明。”

季循把光标移到文件末尾，打出一段依赖声明的空表头，又停住。

苏野平说：“先把常用的几样写上。以后缺什么再说。”

“依赖不是装饰性的占位。”闻衡答道，“写进去的包会进入Cargo的解析和构建。得先知道我们为什么需要它、用它做什么。”

“那就先空着？”季循问。

“如果现在确实没有已确认的依赖，就不为了显得完整而编一份清单。”沈见微说，“以后加依赖时，写明它解决什么问题，再检查解析出的具体版本和适用范围。”

沈见微在空白记录纸上另写了 `Cargo.lock`：“manifest表达依赖要求；后续Cargo解析依赖时，锁文件会记录一次具体解析结果。两者用途不同。锁住版本也不等于证明依赖没有缺陷，更不保证所有系统都能构建。”

韩砺年听了片刻，问：“那写这张纸，究竟替后来的人省下什么？”

“它让后来的人知道Cargo依据哪些声明工作，也让改动能被看见。”闻衡说，“但他们仍要读实现、看测试、核对实际运行范围。”

季循回到manifest，删去刚才那行空表头。他在scope旁边加了一句：**项目声明与行为说明分开维护；依赖加入时记录用途并复核解析结果。**

“这两份以后会不会对不上？”程知序问。

“会有这种可能。”沈见微说，“所以变更时要一起复核，不能因为文件存在就当承诺已经履行。”

贺时进没有再要求把版本改大。他只指着空白的依赖区：“等青炉真的需要第一项外部依赖时，谁决定加？”

“提出需求的人说明用途，维护者检查范围和代价，变更记录留下理由。”沈见微说，“具体流程还要等青炉开始协作后验证。今天先不把尚未发生的审批写成既定制度。”

季循把这句记进待定栏，没有塞进 `Cargo.toml`。这张文件因此仍然很短。短到看不出它将来会长成什么样，却足以让读者辨认：哪些是Cargo要读的声明，哪些承诺要由人另行解释。

闻衡在记录末尾写道：**一纸manifest不能替项目兑现承诺；它能让一部分约定有处可查，也让未写明的地方继续显眼。**

沈见微把它夹在范围草案之后。纸与纸之间没有合成一份万能契书，只留下了彼此需要核对的关系。

### 编辑核验备注

- `Cargo.toml`是Cargo读取的manifest，包含包元数据、依赖、目标、features等配置；不同字段影响不同Cargo行为，不应一概说成面向所有使用者的保证。
- 版本号不会自动通知依赖者，也不自动定义兼容策略；发布承诺须由维护规则与实际发布过程承接。
- `Cargo.toml`与`Cargo.lock`职责不同：前者声明依赖要求等信息，后者记录具体解析结果。锁文件不能证明依赖质量或跨平台构建成功。
