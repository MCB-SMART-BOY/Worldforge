# 明契卷 · 第86章 · 季循的成长

季循把那份帮助页打印出来，压在一块空白记录板下。桌边没有旁人替他报步骤。他先照 Ch82 留下的运行标记，在隔离目录里放回旧报告锁文件，再启动一次深查。

Doctor 走完了。报告写回却在那把锁前重试，计数一条条增加。面板没有再把上一轮的零状态挪过来；这轮被标成“失败，待恢复”。季循把 run id、锁等待和缺少 `report_written` 的位置记在同一页上。旧故障终于能被重现，而不是靠谁记得那半日发生过什么。

他没有把“清掉文件”当作修复。先确认锁属于哪个运行；只有证据表明持有者已经退出或锁已失效，才允许按恢复说明清理。无法确认时就停止操作，不能把删锁当成默认步骤。随后他让写回路径在等待超时后留下明确失败；只有报告实际写成，这一轮才更新为成功。失败路径保留原因和运行标识。第一遍回归时，他发现重试仍可能把旧结果当成当前结果，于是又把“报告写成”设为本轮成功的前置条件。

闻衡没有替他宣布通过，只问：“这条路径谁能再走一次？”

季循把帮助页递给段迟舟。段迟舟换了干净账户，从头照步骤运行。做到确认当前周期时，他停下来：“这里说看总览，可我怎么知道它显示的是这轮，不是旧的？”

季循没有解释那是显而易见的。他在步骤里加上运行标识核对：先确认当前轮次，再确认报告对应同一 run id；若没有 `report_written`，就不得把旧零状态读作本轮成功。段迟舟重新跑完，报告落下，面板才从待恢复转为本轮成功。两个人把复走所用的锁状态、输出和步骤版本记进记录。

闻衡在页边划出一条界线：这证明了一个预置旧锁路径能被复现并恢复，不证明所有异常退出、并发写入或历史目录都已安全。季循把这句话也留在验证记录里。他第一次交出去的不是“我修好了”，而是别人能独立重走、也能指出尚未覆盖之处的一条路。
