# 明契卷 · 第35章 · 旧注释

沈见微在整理旧代码时再次看到了那行旧注释——"此处逻辑不应被文档化。"这一次他沿着仓库历史查了注释的位置，找到一份较早的文件版本。

他先用 `git log --follow -- <path>` 查看这份文件的提交历史，再找到一个仍保留旧版本的提交，以 `git show <commit>:<path>` 读出当时的文件内容。旧版本里，那句注释仍贴在同一段逻辑旁边；之后代码迁入另一个模块，注释也跟着移动。提交说明只写了模块整理，没有解释这句话的来历。reflog 只记录本地引用过去指向哪里；真正给出文字的是提交中的文件快照。

历史记录让沈见微确认：这行注释不是他眼前副本临时多出的字，它至少随代码迁移过一次。但提交作者不必然是注释作者，迁移记录也不能说明是谁最初写下它、为何留下或后来为何不再展开。版本里没有那几句能替他解答的说明。

他把找到的提交、文件路径和前后版本并列记下，又添上“作者与意图未明”。如果这句话是警告，警告针对的究竟是什么？如果它只是当时的暂记，为何后来仍被保留？这些问题都没有从 Git 里浮出来。

"我只能确认这句话跟着代码走过一段路。"沈见微把笔尖停在“原因”一栏，没有落下去。"先记住我们看见了什么。别替留下它的人把后半句话补完。"
