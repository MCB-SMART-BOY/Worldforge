# 新版第94章《大道重拙》工作稿

> **状态：工作稿，不是正式正文。** 以具体接口选择呈现 Rust 的显式约束及其成本；不把某门语言写成普遍优胜，也不把某个特性泛化为所有场景的答案。

---

一段格式转换代码只要在隔离样本里跑一次，季循本想照着熟悉的脚本很快写完。沈见微却先让他标出：输入由谁持有，转换失败交给谁，结果是否还会被别的步骤使用。

“我还没写逻辑，你先问了这么多。”季循说。

“因为这次的结果会不会被保存、谁能继续用，决定了接口怎么写。”沈见微把两种草案并排摆开。一种是沿用现有轻量脚本，在临时目录里转换固定样本；另一种是放进青炉的 Rust 核心，显式写出所有权和错误返回，再承担构建与后续维护。

苏野平指出，这项转换只服务一次性整理，期限短、范围窄；若把它放进长期核心，团队就要维护一条当前没有长期使用者的路径。闻衡补充：反过来，若它后来变成持续服务，临时脚本也未必适合那个寿命和失败代价。

沈见微没有说 Rust “更安全所以必须用”。这次选择的是轻量实现，记录它只处理哪份样本、失败时停止在哪里；Rust 方案留作长期核心的候选，不因语法显得严谨就提前抽象进去。

季循把原先的“Rust更适合青炉”划掉，改成：“这项任务寿命短、输入范围已知；若维护期限或影响面改变，重新评估实现与责任。”

“这也算大道？”苏野平问。

“先看清自己要承担什么，再选工具。”沈见微说，“拙不是把每件事都做重，是不把省下的决定伪装成没有代价。”

### 编辑核验备注

- 语言选择按任务寿命、失败代价、调用边界和维护责任比较，不建立 Rust/Python/Go 的普遍排名。
- 本章的一次性格式转换是卷内选择场景；具体使用的轻量工具、输入数据和删除条件需在正式正文确认。
- 不把所有权规则说成自动保证业务正确，也不把借用检查器说成阻止所有运行期错误。
