# 新版第26章《Err之后》工作稿

> **状态：工作稿，不是正式正文。** 接续Ch25的失败边界，让季循在一条只验证成功样本的入口上使用`.unwrap()`；当必填项缺失时，`Err`被显式转成panic。本章呈现一次未覆盖的错误策略，不把`unwrap`写成静默吞错或一概禁止，也不说编译器会阻止它。

---

季循主动领了一个小改动：把检查报告接到命令入口，让固定样本跑完后能直接看到摘要。

原有路径只试过那份字段齐全的脱敏样本。入口拿到检查结果，就把摘要递到报告模块。季循顺着这条成功路径写好连接代码，很快跑出了同样的几行结果。

他把它写成：

```rust
let report = check_manifest(manifest).unwrap();
print_report(report);
```

“这儿为什么用`unwrap`？”苏野平问。

“固定样本已经验过了。”季循说，“只要检查通过，就会有报告。这样先把入口接起来，稍后再补失败样本。”

他说得很快，也没有藏着自己的取舍。成功样本能走通，模块路径也能找到；屋里没人要求他先把每个错误分支都写完才准继续。

程知序却指了指上一日的记录：“我们刚写过，缺回滚说明会返回具名错误。”

“对。”季循说，“但那份样本有回滚说明。”

闻衡没把这句话判成错，只让他把验证范围加进代码记录：**已验证：字段齐全的固定样本；未验证：必填项缺失时，入口如何交代。**季循点头写下，认为这只是一条还没补上的边界。

当天下午，程知序送来第二份脱敏样本。它只少了回滚说明，其他字段都与前一份一致。

“不要改数据。”她说，“让它照原样走一遍。我们要看青炉怎样说明不满足条件。”

季循把样本送进入口。

镜面闪了两下，停住。随后跳出熟悉而生硬的一行：

`thread 'main' panicked at ...`

季循的手指仍放在按键上，没有立刻移开。

这不是青炉误判了样本。检查函数已经按约定返回`MissingRollbackPlan`；是入口把这个`Err`交给了`unwrap`，在错误到达报告边界前触发了panic。

“编译器为什么没拦？”季循问。

闻衡把那行代码重新指给他看：“因为你没有忽略它。你明确写了：如果这里是`Err`，就panic。编译器看见的是一个完整的选择；它不能替你判断这个选择是否适合操作者。”

季循低头看着`unwrap`。他不是不知道错误存在，只是把“我当前手里的样本是成功的”误当成“这条入口的错误路径不需要处理”。

“我只验证了会通过的那份。”他说，“所以我把测试范围写窄了，心里却把结论写宽了。”

沈见微没有让他删掉所有`unwrap`。他问：“在这条面向操作者的入口上，遇到`MissingRollbackPlan`，谁能做什么？”

“程知序可以补说明，再重新检查。”季循说，“青炉应该告诉她缺了什么，不能只让命令炸掉。”

他把入口改成显式分支：

```rust
match check_manifest(manifest) {
    Ok(report) => print_report(report),
    Err(error) => print_check_error(error),
}
```

随后，他补了一份缺少回滚说明的测试样本，核对入口将具名错误交给报告层，没有输出通过结论，也没有把失败伪装成正常摘要。

“那`unwrap`以后都不能用吗？”季循问。

“不是。”闻衡说，“在测试里、或者你能证明某个内部前提成立的局部位置，它可能是有意选择。关键是别把未经验证的假设写成默认路径。”

季循把“裸`unwrap`”从那条入口删掉，却没有在门规里写“禁止一切`unwrap`”。他在代码评审记录中留下这次决定的范围：

> 面向样本调用者的检查入口必须为预期内的`Err`提供可读路径；局部断言另行说明前提和边界。

程知序重新运行那份脱敏样本。镜面没有给出通过，也没有突然沉默，只写明：

`未通过：缺少回滚说明。请补齐后重试。`

季循把这条结果并入测试记录。错误没有被消灭，但它终于落在有人能看懂、也有办法继续的地方。

### 编辑核验备注

- `.unwrap()`在`Err`时触发panic，不是忽略或吞掉`Err`；编译器允许它，因为这是显式调用。
- 因果链固定为：只测试成功样本→入口对`Result`调用`unwrap`→缺少必填项时检查函数返回具名`Err`→unwrap触发panic→入口改为显式报告错误并补覆盖样本。
- 本章不把所有`unwrap`列为禁用写法；批评的是面向操作者的预期错误路径未经评估就转成panic。
- 修正不等于证明所有样本或环境均可靠；仅补足当前必填项缺失的处理与测试。
- 可对照[Rust标准库`Result`文档](https://doc.rust-lang.org/std/result/)及[Rust标准库`Option`文档](https://doc.rust-lang.org/std/option/)。
