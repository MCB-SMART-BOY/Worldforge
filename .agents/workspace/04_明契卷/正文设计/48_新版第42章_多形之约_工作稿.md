# 明契卷 · 第42章 · 多形之约

沈见微把 `fn process<T: Display + Debug>(item: T)` 写在纸上，递给季循看。trait bound 不是"接受任何类型"，而是"接受任何实现了 Display 和 Debug 的类型"。函数要什么能力，签名里已经写出；编译器会在具体调用处检查传入类型是否满足，但不会保证所有错误都在函数定义处出现。

苏野平问，这是否说明Rust总能给出更清楚的诊断。沈见微摇头：“不能这么推。在C++里，未显式写出的模板要求有时要到具体类型实例化时才暴露，诊断可能带出很深的调用链；concepts也能把约束先写出来。Rust的trait bound同样会在具体调用不满足时由编译器报错。我们能说的是：接口把要求写明，后来者就有机会先看见它；不能保证哪种语言的每次诊断都更清楚。”
