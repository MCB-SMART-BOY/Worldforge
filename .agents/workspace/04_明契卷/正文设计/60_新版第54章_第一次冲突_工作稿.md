# 明契卷 · 第54章 · 第一次冲突

第一次 merge conflict 出现在配置文件里。沈见微加了一个新参数，季循则删去旧默认值；两人各自的改动在自己的分支上都能通过检查，合到一起却留下了重叠的文本。Git 标出了冲突区域，却不能判断新旧配置之间的语义关系。

"我以为自己只是在补一个入口，没想到你正在删它依赖的旧默认值。"沈见微看着冲突标记。"Git 只知道两边改了同一块文字，不知道我们是不是谈过，也不知道哪种配置才符合现在的约定。"

merge conflict 只说明 Git 无法自动合并某些重叠改动，不足以证明两个人没有沟通过，更不能代替他们判断语义。它给出的是需要人处理的差异。沈见微和季循重新核对调用方后，决定保留新参数，同时把旧默认值改成显式迁移选项。代码冲突把问题摆到了桌面上，如何和彼此通气，仍是团队自己的责任。
