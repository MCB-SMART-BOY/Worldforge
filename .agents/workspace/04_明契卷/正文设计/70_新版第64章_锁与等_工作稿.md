# 明契卷 · 第64章 · 锁与等

双项报表已能并行，第三个任务却一直排在队列末尾。值班记录上没有错误，只有越来越长的等待时间。

沈见微在共享缓存外加了 `Mutex`。锁住数据后，没有两个线程同时改写同一份状态；可他把格式化和磁盘写入也留在锁内，慢请求便拖住了后来的人。

季循把等待时间记到白板上：“它没有坏，只是在等我们把门打开。”

他们把临界区缩短：持锁时只复制需要的报表快照，随即释放锁，再在外面格式化和写入。第二轮采样里，等待明显缩短。没人把它称作死锁——这次只是锁竞争；若未来引入多把锁，顺序仍须另行审查。

沈见微没有急着换成 `RwLock`。先有证据，再选工具。门能挡住未经同步的并发访问，却不能替他们决定锁该持有多久。

桌上那份快照来自旧 C 解析库。季循指了指调用边界：“库里的共享状态，也在这把锁后面吗？”
