# 明契卷 · 第37章 · 经卷留痕

沈见微建立了青炉的文档体系。README——项目概述和快速开始。CONTRIBUTING——贡献指南，如何加新功能、如何测试、如何提交。ARCHITECTURE——架构决策记录，不是写"做了哪些决定"，是写"为什么这样决定，当时考虑了什么替代方案，为什么没选替代方案，此决定在什么前提下成立，前提改变时重新审视"。API docs——`cargo doc` 自动生成。

"不是写一本书——是让后来者知道从哪里开始读代码、加功能、测试和发布。每份文档回答一个具体问题。当前测试配置会执行库文档里标记的示例；如果公开接口变动使示例实际调用的内容不再成立，文档测试会失败，提醒我们回查代码与说明。它只守住这些被执行的片段，不能替团队验证没有覆盖的承诺。"

程知序按 README 的快速开始在干净目录走了一遍，到了固定样例。她问：“这一步证明青炉对所有输入都这样，还是只证明这份样例还能照做？”沈见微在文档旁补上测试范围。ARCHITECTURE.md则记录设计理由、考虑过的替代方案和成立前提；前提改变时，后来者可以重新评估，不必把它当成永久命令。
