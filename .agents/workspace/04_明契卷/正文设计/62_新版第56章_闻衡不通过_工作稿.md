# 明契卷 · 第56章 · 闻衡不通过

季循为 Ch47 暴露的结果错配提交了修复 PR。双项样本已经能稳定复现，代码也改成按请求标识配对；标题却只写着"修了一个 bug"，描述里只有一句"调整输出"。闻衡把 PR 退了回来。

"你的改动方向对——但描述我不接受。哪种输入会让报告错配？旧测试为什么没抓到？这次新增的双项样本验证了什么？我需要后来者读完 PR，能沿着复现条件、修复理由和测试判断它改了什么。"

闻衡不是在找所有代码缺陷——他在找这份 PR 里尚未交代的判断。编译器能发现一部分类型和语法问题，测试能覆盖已写出的行为；它们都不能保证开发者已经解释这次修复的来由。季循补上两项输入如何错配、请求标识如何配回产物，以及新增回归样本覆盖的路径。修复不只是一段 diff；PR 还要让后来者看见问题、依据和验证之间的关系。
