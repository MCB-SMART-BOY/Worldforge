# 明契卷 · 第66章 · 越过边界

依赖更新说明只有两行：新版本改用共享静态缓冲区，解析函数不再保证可重入。

季循把更新前后的实现对照起来。旧版本每次调用各自处理输入；新版本为了减少分配，把中间结果写进同一块静态内存。青炉的安全封装仍允许两个报表线程同时调用。双项样本里，两次调用拿到同一地址，输出出现交叠。

季循又翻到封装里的 `Drop`：它仍会对 `output_ptr` 调用 `free`。闻衡按住他递来的更新补丁：“先别只修并发。新版本返回的是静态缓冲区，所有权没有交给 Rust；把它交给 `Drop` 释放，同样不成立。”

“不是版本号自己把它变危险了。”闻衡看过变更说明后说，“是我们依赖的行为前提变了。旧缓冲区归 Rust 所有，新缓冲区只是借给我们读；锁住地址，不等于取得所有权。”

他们先停用并行路径，在隔离环境复走确认。随后沈见微把锁移到 FFI 调用与复制结果的完整区间：锁内调用 C、检查返回指针，并把有效字节复制进 Rust 自有的 `Vec<u8>`；空指针仍转成 `None`。C 返回的静态地址不交给 `Drop`，析构时只释放 Rust 自己分配的副本。锁外不再保留或读取 C 指针。

每一条调用路径都改为经过这层封装后，并行样本再次通过。评审记录注明：锁必须覆盖所有调用者的“调用—复制”区间；若有人绕开封装直接调用 C，互斥仍不能保护共享缓冲区。

沈见微划掉旧论证里“可重入”三个字，保留旧版证据，又添上新版本的前提和检查日期。unsafe 并没有忽然变成禁区；过期的是他们曾经相信的那条边界。
