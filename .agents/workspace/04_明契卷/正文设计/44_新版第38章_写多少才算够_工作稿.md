# 明契卷 · 第38章 · 写多少才算够

沈见微面对文档哲学的核心张力。写太多——文档变成负担，没人维护，过时，变成误导。写太少——后来者看不懂，又要问人。

"中间在哪里？不是写所有——是写后来者最可能卡住的地方和'为什么'。不是写'是什么'——'是什么'在代码里。'为什么'不在。代码说了这个函数接受 DataFrame 返回 dict——文档没有说为什么用 dict 而不是自定义类型，为什么在那个版本做了那个选择，什么约束迫使设计变成这样。"

三样合在一起——后来者不需要我。代码说了是什么。文档说了为什么是这样而不是那样。测试把选定的行为预期固定成可重复检查的用例。测试通过，只能说明这些用例覆盖的情况没有回归；它不能替团队证明所有承诺和未知条件。三者重叠处，才是后来者能够独立开始、也能继续验证的地方。

"写文档不是写说明书——是写决策记录。记录每一个选择背后的原因——不是为了证明当时选得对，是为了让后来者判断那些原因在现在是否仍然成立。不成立的时候他们自己决定怎么做。写多少才算够——不是字数。是后来者在凌晨打开文档能回答'这段代码为什么长这样'——就够了。"
