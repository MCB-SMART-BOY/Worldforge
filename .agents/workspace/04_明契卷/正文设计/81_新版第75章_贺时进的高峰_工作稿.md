# 明契卷 · 第75章 · 贺时进的高峰

北岭的回信只有两行：本期可以给青炉一个试用位置，窗口到周五为止；错过这一轮，下一次排期在一个月后。

贺时进把信放到桌上时，旁边还压着三份东西：已经通过样例的命令器、仍差几项旧桥说明的迁移页，以及一张尚未填完的兼容矩阵。后两样本来是沈见微要求随发布一起交出去的。

“我不是要你们把没测过的事说成测过。”贺时进先说，“可北岭现在还靠旧工具值守。一个月里，他们要么继续等，要么自己再搭一条没人接手的脚本。我们手里至少有一条通过了测试的入口。”

他的提议很直接：这周先发命令器；详细迁移手册和其余平台矩阵放进下一版。第一周由他收集使用者的问题，遇到不支持的路径就停用，不把诊断结果当作批准。窗口不会等他们把每一种旧环境都梳理完。拖延本身也在让门外的人继续承担成本。

沈见微看着“下一版”三个字。自己也曾靠一段临时命令熬过交付，再想着有空补说明。那时每多等一天，等着用工具的人就多绕一天。他知道贺时进说中了这一点；也知道后来者最常接到的，正是这样一张没有写明期限的欠条。

“能发，但范围要缩。”他说，“只承诺已验证的北岭样例。旧桥行为变化必须放在首屏，安装后怎么停用、怎么回退也一并给出。兼容矩阵剩下的组合标成未验证，不把它们折进一句‘支持北岭’。”

贺时进看了看排期：“这样他们可能只拿一半青炉回去。”

“那就让他们知道拿回去的是哪一半。”沈见微把发布页上的“全面兼容”删掉，改成“本次试用覆盖”。他保住了窗口，却放弃了更好听的发布词，也把青炉的第一批使用者限制在已经验证的样例内。其他团队要等下一轮。

贺时进没有说服所有人，也没被所有人否定。他把自己名字写进第一周值守栏，旁边补上停止条件：只要实际路径与试用说明不符，先暂停扩用，再回报样本。那不是长期方案，却是他愿意承担的短期责任。

苏野平盯着被删掉的“全面兼容”，说：“遗留环境不会等矩阵填满。有人得先把脚本跑起来，才知道该测什么。”

沈见微没有把那句话推回去。他把那份未完成矩阵移到两人中间：“那我们就谈谈，脚本先跑起来以后，什么必须跟着留下。”
