# 明契卷 · 第51章 · 留影为史

Git commit 保存文件快照和变更元信息；提交说明可以补上代码本身看不见的理由与验证线索。

沈见微写青炉的第一个 commit。里面只有scope、根与成员的`Cargo.toml`；Ch27复走过的原型源码、测试和已生成的`Cargo.lock`仍留在工作目录，没有进入版本历史。

季循看着空下来的`src/`路径：“那这次提交能让别人复走哪一步？”

“还不能。”沈见微没有把它叫作可复现的项目基线，“这是记录范围和包关系的起点。共享之前，下一次提交必须把源码、测试和复走步骤一并纳入。不能拿本地通过的结果冒充仓库里已有的能力。”

他在提交说明里写明：本次只登记scope与package manifest；原型代码、测试和锁文件尚未纳入。这个commit可以被后来者追问，却不能替他们重建那次试验。

"旧工具链里，变更散在各人的脚本和笔记中。现在用 `git blame` 能找到某行最近一次修改，再沿着 `git show`、日志和评审记录追上下文；单看它仍还原不了设计意图，理由要由参与者写下来。"沈见微指了指眼前的差异：“而这次提交连原型源码、测试和锁文件都没有。后来者能追问我们记了什么，却还不能复走那次验证。下一次提交得把这些一起补进来。”
