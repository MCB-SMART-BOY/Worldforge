# 明契卷 · 第89章 · 灰烬中的火

复盘桌上只留一条运行链。段迟舟报出的等待时间、最初那三句粗日志、后来补上的 run id 与步骤标记，都被抄到同一页。季循把 `report_write_retry` 和异常锁等待圈在一起；`watch_lock_acquired` 旁边则另写：只说明守望锁，不代表报告写锁已经取得。

他们按时间重排证据：doctor 完成；报告写回开始重试；没有出现成功的 `report_written`；这轮没有自己的最终状态；总览仍显示此前成功轮留下的零状态。原因不是检查本身变慢，而是报告写回沿用了旧单机发布锁语义，旧守望留下的锁文件未清，写回被卡在门外。

沈见微没有在记录里写“用户没看懂”。旧状态展示确实让失败不易被看见，恢复说明也不足；但报告锁与每轮状态的实现同样负有责任。程知序要求把“哪些数据已确认”“哪些只是推断”分开。于是记录将根因、放大因素、修改和仍未验证项列为四栏。

段迟舟核对修正后的报告，确认它对应新的运行标识，才恢复后续判断。季循把回归样本和复走步骤附在记录后；贺时进登记新增接入暂停造成的排期变化，并写明北岭仍是限定试点；沈见微补上旧锁语义的退场责任，不让这把锁只在事故会上被提起。

闻衡审过最后一遍，删掉“已彻底解决”几个字，换成“已复现并验证指定路径”。记录没有变轻，却终于能区分什么发生过、什么修过、什么还不知道。留在末尾的不是一句避免再犯，而是值守者下一次可以照着查的证据顺序。
