# 明契卷 · 第46章 · 拆骨

青炉已有 `qinglu-cli`、`qinglu-config`、`qinglu-core` 和 `qinglu-doctor` 四个 workspace 成员。构建与报告仍在`qinglu-core`里，沈见微把这两项职责拆成 `qinglu-build` 和 `qinglu-report`，再将新 package 加入workspace；原有成员继续保留。

不是"我觉得太大了"——而是这些代码服务于不同的使用者，有不同的承诺周期，边界值得拆开。程知序只需要 build，不需要直接依赖 report；新的依赖图让他能看清自己拿了什么，也让团队可以检查哪些变更与他无关。拆分并不保证 core 的任何变化都不会影响 build；能否不改调用方，仍取决于公开 API 是否兼容。

"`build-shim`以前指向`qinglu-core`里的构建模块；现在它改接`qinglu-build`公开的入口，旧脚本命令暂时不变。拆分不是把目录挪开就算完——还得迁移这条内部依赖，并复核输出。每个 crate 要写清自己承诺什么、不承诺什么。它们可以独立发布和定版本；workspace共享根`Cargo.lock`，却不会自动统一版本或保证接口兼容。若公开约定改变，调用方仍须明确升级。"
