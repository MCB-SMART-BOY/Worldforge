# 卷十「问鼎」Ch 91-100：兼容·重构·技术债·最黑暗的时刻

## Section 总览

- **章段**：Ch 91-100
- **叙事主题**：兼容的代价与技术债的利息——两笔不同的兼容账——退场日历——Rust的显式边界——梁故川留下的记录与空白——沈见微面对“文档也会被误用”的疑虑——在证据未齐时，仍选择把判断、前提和复核方法写在一起。
- **核心冲突**：沈见微能否在不替梁故川虚构动机的前提下，回应那句“此处逻辑不应被文档化”？他要面对的不是“梁故川为何离开”这一尚无答案的问题，而是眼前的风险：一条写得清楚的判断，可能被后来者当成无需复核的真理。如何把判断的来由、适用前提与失效信号一并交出去？
- **工具链阶段**：cargo-audit / 依赖管理 / 形式化边界 / 技术债管理
- **对象层**：史→史（旧记录来源、工程承诺与复核责任）
- **主相→蚀**：断史（旧记录的来源、前提和效力不完整；人物解释保持待证）
- **主角状态**：沈见微发现清晰的结论也可能被误用；他选择把证据范围、适用前提、未知项和复核方法并列记录。

### 第91章：旧劫未消

- **核心对象层**：史→史。技术债不是代码写得差，而是当时合理的选择在条件变化后继续产生维护成本。沈见微逐项核账时先区分两件常被叫作“桥”的事：`single-host-release-lock` 是旧发布锁语义留下的兼容债；`build-shim` 是旧构建脚本通向新 build 模块的迁移桥。它们的使用者、责任人和退场条件分别核验，不合并成同一笔账。
- **工程锚点**：技术债管理记录来源、成立前提、当前使用者、维护成本、责任人、复核日期与退出条件。账目能说明何时需要重新判断，不能仅凭到期日期替人决定如何拆除。
- **六拍骨架**：沈见微把锁策略债和 `build-shim` 分列在账上；锁债栏仍缺完整的可迁移策略，顾迁衡负责确认桥账里的调用方与复查日。程知序指出，继续维护锁语义占用每次发布前的人工核验时间；团队选择暂缓一项低优先级整理，先核清调用链与迁移责任，再比较维持、迁移和退场的成本。未核实的调用方不写成“无人使用”。

### 第92章：顾迁衡的旧桥

- **核心对象层**：门→门。本章只追踪 `build-shim`：旧构建脚本到青炉 build 模块的兼容层。桥账把 `build-shim` 的复查安排在建立六个月后；本章发生在该日期之前，顾迁衡先带沈见微盘点调用记录，确认哪些调用方已迁、哪些仍在用、哪些记录缺失。现有材料不支持“五个服务”或“一年前”的说法；`single-host-release-lock` 另列为锁策略兼容债，不算作这座桥。
- **六拍骨架**：顾迁衡说明桥账的六个月节点是复查日，不是自动拆除日。盘点发现一项调用仍未迁移；负责人展示当前入口和阻塞原因，程知序估算继续维护旧入口带来的发布核验成本。团队记下该调用方的迁移负责人和验收条件，保留原定复查日期；拆除要等调用清单复核、迁移验收通过后另作明确决定。顾迁衡不替依赖方承诺内部改造。

### 第93章：退场日历

- **核心对象层**：史→史。沈见微把退场日历改成有升级机制的审议日历：每项临时兼容层都记录提出日期、目标复查日、责任人、已知调用方、延期理由和迁移验收条件。延期次数达到约定上限时，事项自动升级到负责人和受影响方共同审议，并须制定有期限的迁移计划；系统不会自动断开仍在使用的依赖，也不把未迁移者静默改标为“不受支持”。
- **六拍骨架**：沈见微删去“日期一到就拆”的草案，改写为“日期一到，必须复查；延期必须说明代价、负责人和下一步；达到上限，升级裁定并公开风险”。有人担心这样会让临时方案继续拖延。顾迁衡答：没有升级压力，临时会变永久；没有依赖核验，强拆只是把账转嫁给不在场的人。两人将到期复查、依赖确认和验收通过分别写进日历。

### 第94章：大道重拙

- **核心对象层**：念→念（Rust为何坚持显式与约束——Rust哲学。"Rust——不是'难'——是'拙'——它不帮你做隐式转换——不帮你自动推断超出范围的类型——不帮你偷偷做垃圾回收——因为每一个隐式行为——在生产中——是一个你无法预测的行为——在凌晨——是一个你不知道为什么会发生的bug。"——与Python和Go的哲学形成跨卷对照——"Python——让你快速做到——Go——让你简单做到——Rust——让你'在做到之前——先说清楚'。"）
- **六拍骨架**：沈见微——"大道重拙——不是'Rust最好'——是——Rust的'拙'——是——'让你慢下来——在写的时候——面对所有的模糊——把它变得不模糊。'——这种拙——不是适用于所有场景——但在青炉——在需要'对后来者负责'的场景——拙——是美德。"

### 第95章：梁故川的遗产

- **核心对象层**：史→史。沈见微整理目前能找到的梁故川相关材料：一行未署名的旧注释、几份来源各异的草稿，以及韩砺年能确认的现场记忆。每件材料分别标注载体、可确认的年代范围和未知项；没有证据证明旧注释出自梁故川，也没有一份材料说明他为何离开。钟守玄曾回忆梁故川选择以文档和接口减少口传损耗，这段记忆与“他后来是否改变看法”仍是两个问题。
- **六拍骨架**：沈见微先列“可见文字”“韩砺年亲历”“钟守玄回忆”“自己的解释”四栏。他把“梁故川担心文档被当成真理”写成待证假说，不写成遗言。读者看见的遗产不是谜底，而是证据之间留下的空白：他确实写过；那行“不应被文档化”是谁在何时针对什么留下，仍无从确认。

### 第96章：韩砺年的沉默

- **核心对象层**：人→人。沈见微请韩砺年只谈自己亲历的部分。韩砺年只确认自己记得梁故川写过记录；他不知道梁为何离开，也不能确认那行旧注释是谁写的。沉默没有被揭开成答案，反而让沈见微第一次承认：亲历者的“不知道”也是历史记录的一部分。
- **六拍骨架**：韩砺年只谈自己记得的那几份记录，不替注释署名，也不替梁故川解释离开。他说：“我记得他写过。别的，我不能替他作证。”沈见微把这条记忆连同边界一并记入档案。梁故川选择写的事实，与他后来可能产生的疑虑，不再被压成单一立场。

### 第97章：不文档化

- **核心对象层**：史→史。沈见微面对那句“此处逻辑不应被文档化”，只把它当作一句待解释的旧注释。他提出两种都尚未证实的读法：它可能是对易变前提的警告，也可能是当时某个局部实现决定；“故意留白”与“尚未来得及补写”都不能排除。他的理解属于当下的沈见微，不替梁故川发言。
- **六拍骨架**：沈见微在注释旁写下自己的批注：“原文未署名；意图未明。我的暂定做法：写出判断、前提、失效信号和复核方法；若证据不足，明确标为未知。”他不再把“不文档化”解释成梁故川的隐秘教诲，而把它转化为一条可检验的写作约束：记录必须让后来者看见判断边界，也看见哪些部分还没有答案。

### 第98章：最黑暗的时刻

- **核心对象层**：史→史。沈见微把“梁故川害怕后来者把文档当成真理”写进一份内部整理稿，准备作为旧注释的背景说明。韩砺年读到后只问一句：“这是谁告诉你的？”桌上没有来源，只有那行未署名的注释和沈见微自己的推测。稿件已经送进评审，团队暂停引用，重新标记作者、时间和意图均待核。
- **六拍骨架**：撤回这段说明意味着历史章节要重排，原定评审也得延期。沈见微亲手删掉那句看似完整的解释，留下空白和证据目录。他第一次看见危险不在“写下来的都可能是错的”，而在自己把猜想磨成了事实的形状；梁故川的动机仍未知，真正刺痛他的，是他刚刚替沉默的人说了话。

### 第99章：不是放弃

- **核心对象层**：念→念。沈见微重整那份旧记录，把可见原文、版本来源、韩砺年亲历、钟守玄回忆和自己的推测分栏；每一条都注明能证明什么、不能证明什么。未查明的地方保留空白，不用更流畅的解释填满。
- **六拍骨架**：韩砺年只为自己亲历的部分签名，沈见微为推测标上作者和待核状态。评审因此可以继续，但梁故川的故事没有被“补齐”。沈见微仍然选择写下去：记录判断，也记录判断如何得来、何处可能失效，以及后来者可以从哪里继续查。

### 第100章：问鼎之后

- **核心对象层**：史→史。卷尾完成的是旧注释档案的更正：青炉公开当前能核实的来源、回忆边界和未知项，并给待查材料标注负责人。诊断器的 `v0.3.1` 仍是已发出的版本；修订措辞、接收方核验门槛与撤回流程尚在内部评审，程知序负责在下一轮发布前组织复核，闻衡审查处置状态，沈见微承担修订。
- **六拍骨架**：众人在记录板上签下各自负责的复核项。沈见微合上档案时，梁故川为何离开仍无答案；另一份报告也仍带着未经修正的退役建议，在外部试用者手中流转。卷十一从苏野平对技术适用范围的质疑开场，诊断报告引发的跨卷事故留到Ch105发生。

> 📝 卷尾。账目分列、延期升级复核；旧注释仍未解谜。沈见微以公开的前提声明、责任人和复核期限交接卷十一，不预告传讯结果。
