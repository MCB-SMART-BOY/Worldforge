# `.agents/` 全量内容与叙事增强设计

## 目标

逐文件审阅当前 `.agents/` 全部资料，修正过时或矛盾的口径，改善规则、流程、模板的可用性；并基于现行正文与因果证据检查跨卷线索和回收。对尚未写作且有明确承载位置的剧情段，设计至少三条相互照应、可在后续回收的伏笔链，其中至少一条具有二阶回读；新增复杂度必须改变人物选择、责任、代价或读者对已见证据的理解，不能只增加谜团数量。

## 读者与使用者

- 项目作者：需要可信、可维护的设定、章纲、进度和历史记录。
- 新读者与写作协作者：需要清楚区分现行正文、工作资料、历史蓝图与未证假设。
- 多 harness agent：需要能按任务找到正确资料，不被旧命令、旧章号或重复状态误导。

## 设计决策

1. 建立 `.agents/docs/audits/2026-11-14-file-coverage.tsv`，为每个文件记录审阅状态与判断；归档材料同样逐文件检查，但以保留原貌、标注效力为原则。
2. 按资料职责维护唯一状态源：正文顺序由实际卷索引定义；动态审校状态由实时账本定义；事实冲突保留证据并标待决；历史设计材料不得覆盖现行正文。
3. 新增或延展的伏笔须形成可追溯的“现有证据 → 角色当时的理解 → 新证据/回读 → 选择与代价”链条；至少三条线索应由不同载体或人物行动承担，并至少有一处二阶回读改变读者对早先证据的理解。证据不足时记录未知和竞争解释，不补造共同来源。
4. 先更新 canon 与工作区章纲/叙事设计，再决定是否触及正文；未写章的剧情提案不得伪装成已发生事实，不因增加伏笔而改写已确立的工程因果、人物动机或正文事实。
5. 结构重整可以大幅进行，但移走或替换唯一资料时必须保留原内容或历史副本并更新索引。

## 跨卷线索与改稿约束

- 对每条关键伏笔，说明现有锚点、初次呈现、角色当下解释、替代解释、回读位置、人物代价及仍不成立时的处理。
- 二阶回读应改变读者对证据、记录、责任或人物选择的理解；不可仅靠“重复出现”或隐藏新信息充数，也不可把普通细节一概改写成伏笔。
- 角色的选择、工程代价和信息边界驱动线索揭示；避免旁白提前讲解谜底。

## 非目标

- 不为了统一术语而重写全部小说正文。
- 不把历史档案或草稿伪装成现行规则。
- 不仅靠新增谜团制造复杂度；每个谜团要改变角色可做的选择或读者对既有因果的理解。
