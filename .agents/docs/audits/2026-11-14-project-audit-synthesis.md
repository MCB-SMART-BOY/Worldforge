## 目录与跨 harness 架构

- 根 `README.md` 现为唯一根级项目总览与读者导航，不再并列一份重复的根目录说明；旧目录材料中的独有设计内容迁入 `.agents/workspace/历史蓝图/` 并加上历史效力说明。该蓝图经过修订，不是原文件的逐字副本。
- 八卷目录已置于项目根目录。canon、workspace、supplements、harness、skills、docs 与 legacy 分别承载正典、当前工作资料、读者配套、流程、专项方法、维护记录和历史原件。
- 根 `AGENTS.md` 是共享规则入口；Codex、Omarchy OMP 与 DeepSeek Harness 共用 `.agents/skills/<id>/SKILL.md` 和中性相对路径。技能发现/调用由各 harness 自己负责，不假定统一 slash command。
- Claude 专属文件及旧配置留存在 `.agents/legacy/` 供历史查证，不作为活动指令。专项技能中没有可提取的可执行脚本；代码块用于报告格式、内容模板或示例。自动化页已标明示例未部署，因此没有重新建立无实际用途的 `scripts/` 目录。
- 主工作流为闭环：确认目标与工作区 → 查索引、正典和相邻证据 → 按需执行技能 → 最小修改 → 回读并按风险复核 → 更新唯一实时账本及相关索引 → 记录完成、未决项和续接点。质量门按任务适用，不把章节结构、张力或失败模式套成强制模板。

迁移证据边界：本综述形成时，根目录覆盖 808 篇卷内 Markdown；迁移前 Git HEAD 的旧 `正文/` 跟踪 756 个文件。多出的52篇可能来自当时未跟踪的工作稿；仅凭 Git 基线无法判断其先前位置，因此该时点的覆盖记录不证明旧版 tracked tree 与当前稿件一一等量。当前稿件统计以实时账本为准。
