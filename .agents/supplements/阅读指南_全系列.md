## 一、阅读顺序

**驭器卷（C++·玄枢）→ 化形卷（Python·息壤）→ 简阵卷（Go·驿河）→ 明契卷（Rust·青炉）**

### 这条阅读路径提供什么

- 驭器卷以 C++ 遗留系统玄枢为中心，呈现长期维护与知识交接的压力。
- 化形卷以 Python 与息壤为中心，观察快速试法如何面对可复现性和依赖边界。
- 简阵卷以 Go 与驿河为中心，把视线移到服务边界、运行状态和协作尺度。
- 明契卷以 Rust 与青炉为中心，继续追问显式规则、责任与工具的边界。

以上是主题导读，不是对每卷所有情节、卷内先后或角色终局的概括；实际事件与人物状态按正文和 canon 核对。

每卷都可独立阅读——跨卷角色和事件在首次出场时给予足够解释。不建议跳读，但跳了也不会卡死。

## 三、关键跨卷锚点

以下是阅读时可留意的主题和线索，不表示它们已被证明来自同一事件或机制。具体章次按正文、章纲和[全系列叙事架构与锚点账本](../canon/26_全系列叙事架构与锚点账本.md)核实；待证关系保留待证。

| 锚点 | 阅读时关注什么 |
|------|---------------|
| 断桥潮与跨卷事故链 | 同一事故如何在不同世界留下不同后果；每卷都要独立交代本卷可见的事实与代价 |
| 残码与首约 | 记录中出现的古老声明如何被逐层发现；作者、来源与未明条款保持在证据允许的范围内 |
| 约、检、式、在等旧信号 | 相似文本可以引发调查，但相似本身不能证明共同来源 |
| runbook 与语境 | 可复用的步骤为何仍需要前提、边界与本地判断 |
| 旧屋、石镜与放弃唯一 | 人物如何把判断权交给共同体；其回应应按正文和锚点账本理解 |

## 四、术语约定

- 工程术语的解释和英文原名按现行术语 canon 及所在卷的正文需要处理，避免将导读写成术语清单
- 虚构世界观概念通过场景自然解释，不另注
- 是否能迅速定位场景、视角和当前问题，可作为导读和审读的检查问题，不宣称现有每章都已满足

## 五、读完之后

第一阶段四卷围绕不同工程对象与责任选择展开。读到后续卷时，请以正文实际写出的证据理解角色和世界，不把主题相似直接当作同源证明。以下主题句是导读性表达，不等同于世界定律：

- 失守、记录和责任会在不同系统中以不同方式出现；它们之间的关系要由具体证据建立。
- 前提声明、风险标记和共同值守可作为思考工具，但须按真实工程场景调整。
- 如果手痒——在留白处写你的那行："接手的——你也写。"
