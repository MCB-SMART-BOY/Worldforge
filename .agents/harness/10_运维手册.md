# 10 · 运维手册

> `.agents/` 体系的维护操作指南。当需要新增卷、更新 canon、迁移结构、或处理异常时使用。

## 一、日常维护

### 1.1 更新实时审校账本

**触发条件**：每完成一章、一批审校或一项结构性迁移

**步骤**：
1. 更新 `.agents/workspace/正文全卷审校进度.md` 中对应任务的范围、证据、结果、未决项和续接位置
2. 只有当卷索引或章纲里存在与本次修改对应的状态记录时，才同步更新
3. 如果涉及跨卷锚点，更新 `.agents/canon/26_全系列叙事架构与锚点账本.md` 或对应资料
4. 不维护与实时账本重复的第二套全局完成率

### 1.2 更新卷索引

**触发条件**：章纲有重大调整、新增章节、人物变更

**步骤**：
1. 先区分卷根目录的正文索引与 `.agents/workspace/<卷>/00_卷索引.md`；前者说明正文顺序/稿件类别，后者导航工作资料。
2. 更新实际受影响的索引字段；不为每卷强行套用相同的状态表或目录层级。
3. 若存在对应术语/文学表达对照表且本次修改影响它，再同步更新；没有该表时不要凭模板臆造。

### 1.3 提交前检查

**触发条件**：每次 git commit

只有作者明确要求提交时才会发生提交；本节描述的是作者已要求提交后的检查，不构成自动提交要求。

**步骤**：
1. 过 Commit Gate（`03_质量门.md` §五）
2. 确认无 `AI 或 agent 共同署名`（铁律）
3. 确认 commit message 格式正确
4. 确认只包含目标文件

## 二、新增一卷

### 2.1 建立新卷资料

新卷结构由卷的写作需要决定。先检查根目录的卷命名约定、现行阅读序列、对应 canon 和作者确定的篇幅，再建立最小可用资料；第一阶段四卷的 120 章蓝图和既有目录结构不是新卷模板。

```bash
# 仅作填写示例；运行前须将值替换为作者已确认的目录名。
VOLUME_SLUG="XX_卷名"
VOLUME_DIR="$VOLUME_SLUG"
# mkdir -p ".agents/workspace/$VOLUME_SLUG" "$VOLUME_DIR"
# 按实际需要再创建人物、章纲、正文设计、研究或教学配套目录。
```

### 2.2 新增 canon 设定

1. 在 `.agents/canon/` 中创建新卷的设定文件（编号接续现有文件）
2. 更新 `.agents/canon/00_总览与使用说明.md` — 添加新文件到建议阅读顺序
3. 更新对应卷的设定、索引和章纲；`.agents/canon/23_四卷120章总蓝图.md` 只维护第一阶段四卷的历史蓝图，不作为新增卷的通用模板

### 2.3 更新 harness 文件

检查以下资料是否受影响；仅更新确需改变的部分：

| 文件 | 需要更新的内容 |
|------|--------------|
| `02_状态机.md` | 仅当新产出类型或状态转换无法由现有规则表达时更新 |
| `04_命令中心.md` | 若新卷需要专项路由或参考项，更新任务路由与资料索引 |
| `05_模板注册表.md` | 若新增/改变可复用模板，登记定义与适用范围 |
| 实时审校账本 | 作者开始推进该卷时，按已确认的状态口径建记录 |
| `09_集成验证.md` / canon26 | 只有建立跨卷因果或锚点时更新，并保留证据状态 |

### 2.4 更新项目文件

| 文件 | 更新内容 |
|------|---------|
| `AGENTS.md` | 若项目目录约束、入口路由或卷目清单发生变化则更新 |
| `README.md` | 按读者入口与已确定的阅读序列更新，不发布未确认的卷信息 |
| `.agents/README.md` | 更新目录映射 |
| `.agents/workspace/00_工作区说明.md` | 更新工作区职责与入口；创作顺序以根 README、卷内正文索引和实时账本为准 |

## 三、更新 Canon

### 3.1 新增 canon 文件

1. 编号接续现有最后一个文件
2. 更新 `.agents/canon/00_总览与使用说明.md` 的建议阅读顺序
3. 更新 `.agents/canon/README.md`（如果存在）
4. 检查是否有 harness 文件需要引用新 canon

### 3.2 修改现有 canon

**关键原则**：canon 是受版本管理的规则与事实资料，可以新增、澄清或修订；修改前后都要留下变更理由和证据边界。

| 修改类型 | 允许？ | 注意事项 |
|---------|--------|---------|
| 新增概念或规则 | 视需要 | 符合现行 canon 与 `check-canon` 要求；推动因果或改变世界运行的规则说明适用范围、触发条件与失效后果。普通术语、道具、意象和人物假说不强制补写失守形态 |
| 澄清或修改定义 | 允许，需审查影响 | 搜索 canon、正文、章纲和配套材料中的引用；区分修正错误与 retcon |
| 废弃概念 | 保留迁移痕迹 | 标明废弃时间、理由和替代项，不让旧定义继续以现行语气出现 |
| 调整卷级设定 | 允许，需证据 | 对照已写正文；不能用新设定抹去既有事实，冲突标为待裁定 |

### 3.3 Canon 修改的影响分析

修改 canon 后，执行：
1. `rg -n --hidden --glob '*.md' --glob '!**/legacy/**' --glob '!**/docs/**' "被修改的概念" .` — 搜索活动资料和正文中的引用；命中仅用于定位，须结合正文索引与上下文判断是否需要修改
2. 逐条评估是否需要更新
3. 如需提交，按作者要求使用清晰的提交说明；除项目规则明确规定外，不强制特定格式

## 四、新增 Skill

### 4.1 创建 Skill 文件

1. 在 `.agents/skills/<skill-id>/SKILL.md` 创建新技能
2. 添加 `name` 与 `description` YAML frontmatter；格式参考现有技能：
   - 功能说明（1-2句话）
   - 参数定义
   - 执行流程（步骤化）
   - 输出格式
   - Gotchas（常见错误）
   - 参考文件列表
3. 新增技能或改变其行为前，先设计一个能暴露预期误用的场景；按技能步骤执行并核对结果，修订后再用同一场景复核。没有可自动运行的测试工具时，采用人工或独立审阅验证；示例与报告模板不算测试。

### 4.2 集成到 harness

1. 在 `04_命令中心.md` 登记技能 ID、触发任务和路径；只有资料分区变化时才更新 `.agents/README.md`
2. 更新 `01_流水线.md` — 如果新 skill 参与流水线，更新对应 Phase
3. 仅当组件关系变化时更新 `00_架构总图.md`；普通技能登记不必重复列入总图

### 4.3 更新 AGENTS.md

根 `AGENTS.md` 只保留技能类别与路由规则；技能清单维护在 `.agents/README.md`。

## 五、结构迁移

### 5.1 重命名目录/文件

**原则**：尽可能不重命名——链接断裂成本高。

如果必须重命名：
1. `rg -n --hidden "旧路径" .agents AGENTS.md README.md` — 找到现行引用；忽略历史档案中的旧路径时，要确认其仍明确标为历史
2. 先更新所有引用，再重命名
3. 在迁移记录中注明旧→新路径映射、保留的唯一内容及新旧效力；是否提交仍由作者决定

### 5.2 拆分大文件

**原则**：当文件超过 500 行时考虑拆分。

1. 确定拆分边界（按主题或按 Section）
2. 创建新文件
3. 在原文件位置留下指针（"此内容已迁移至：`新路径`"）
4. 更新所有引用
5. 保留原文件（不删除）直到确认所有引用已更新

### 5.3 合并小文件

**原则**：当多个文件各自 < 30 行且主题紧密相关时考虑合并。

1. 确定合并后的文件结构
2. 创建合并文件
3. 在原文件位置留下指针
4. 更新所有引用

## 六、灾难恢复

### 6.1 实时账本与文件状态不一致

**症状**：实时审校账本与实际卷文件、索引状态不符

**恢复步骤**：
```bash
# 每卷执行章节存在性报告
for vol in [0-9][0-9]_*卷; do
  [ -d "$vol" ] || continue
  echo "=== $vol ==="
  find "$vol" -maxdepth 1 -type f -name '第*章*.md' -print | sort
done
```

1. 区分正式正文、来源稿、序章/续篇、附篇和索引
2. 按证据更新 `.agents/workspace/正文全卷审校进度.md`，并保留差异原因
3. 不用蓝图章数代替当前文件数或正式阅读顺序

### 6.2 章纲-正文不匹配

**症状**：正文内容与章纲描述不一致

**恢复**：
1. 分别记录章纲、索引、正文、全系列账本的具体证据；不要预设“正文总是对”或“章纲总是对”。
2. 若正文明确展示了已发生事件，不能仅为符合旧章纲而反向改写事实；仍需检查索引和全系列因果。
3. 只有作者明确选择方向或现行 canon 已有裁定时，才同步修订相应资料；否则标为待决并记录影响范围。

### 6.3 Git 状态混乱

**恢复**：
```bash
git status  # 了解当前状态
git log --oneline -10  # 最近的提交
git diff  # 未 staged 的更改
git diff --cached  # 已 staged 的更改
```

## 七、版本升级

### 7.1 Harness 版本升级

当 harness 体系自身需要升级时：

1. 更新 `00_架构总图.md` 中受影响的组件关系
2. 更新 `.agents/harness/README.md`
3. 如果新增了 harness 文件，更新架构总图
4. 如果修改了流水线/质量门/状态机，评估对现有写作流程的影响

### 7.2 Canon 版本升级

Canon 的版本在 `.agents/canon/00_总览与使用说明.md` 中维护。当 canon 发生重大变化时：

1. 更新版本号（如 v1.8 → v1.9）
2. 在版本说明中记录变化
3. 只在根 `AGENTS.md` 的入口或规则摘要确有变化时更新；它不承担动态状态

## 八、定期健康检查

建议在完成一组正文审阅、重大结构调整或跨卷映射更新后执行一次；分组范围按实际工作确定，不以固定章数触发。

### 检查清单

- [ ] 实时审校账本与本次核对的实际文件一致
- [ ] 有对应状态栏时，卷索引/章纲与实时账本一致
- [ ] 所有已写章节的文件名符合规范
- [ ] 无废弃命名残留（`百炼成仙`）
- [ ] 跨卷锚点状态准确
- [ ] 人物卡与实际出场一致
- [ ] 根 AGENTS.md 的目录/规则/入口信息与项目一致（动态状态仍留在实时账本）

### 执行命令

```bash
# 废弃命名检查
grep -rn "百炼成仙" .agents/ 0[1-8]_*卷 || echo "✅ 无废弃命名残留"

# 文件名规范检查
find 0[1-8]_*卷 -name "第*章*.md" | while read f; do
  basename=$(basename "$f")
  if ! echo "$basename" | grep -qP '^第\d+章_.+\.md$'; then
    echo "⚠️ $f"
  fi
done

# 工作区卷索引存在性；缺少索引不代表卷正文缺失或无正式映射
for vol in 01_驭器卷 02_化形卷 03_简阵卷 04_明契卷 05_容断卷 06_通界卷 07_守序卷 08_求式卷; do
  [ -f ".agents/workspace/$vol/00_卷索引.md" ] && echo "✅ $vol 卷索引" || echo "❌ $vol 卷索引缺失"
done

# 正文索引是另一类文件；目前没有索引的卷需要人工结合实时账本和正文核验
for vol in 01_驭器卷 02_化形卷 03_简阵卷 04_明契卷 05_容断卷 06_通界卷 07_守序卷 08_求式卷; do
  [ -f "$vol/00_正文索引.md" ] && echo "✅ $vol 正文索引" || echo "ℹ️ $vol 暂无正文索引，映射待核"
done
```

## 九、运维原则

1. **改动越小越好**：能改一个文件的，不改两个
2. **先更新引用，再移动文件**：避免断链
3. **每次运维操作后更新此手册**：如果发现了新的操作模式
4. **保留历史**：旧文件不删，用指针指向新位置——维护考古层
5. **机械检查可辅助自动化**：对已确认范围的文件、链接和格式可使用只读工具；脚本结果是线索，不能替代正文、因果和设定判断
