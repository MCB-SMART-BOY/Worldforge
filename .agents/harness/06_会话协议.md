# 06 · 会话恢复

> 本文件只处理跨会话恢复：如何从实时工作记录回到正确的任务、证据和续接点。一般会话入口、任务路由、执行闭环与结束记录统一见 `11_操作工作流.md`。

## 一、何时使用

用户要求“继续”“从上次接着做”，或当前任务明显承接先前工作时，按本协议恢复。新任务从根 `AGENTS.md` 和 `11_操作工作流.md` 进入，不需要为了启动会话而读完整本协议。

## 二、恢复顺序

1. 读取 `.agents/workspace/正文全卷审校进度.md` 中与当前任务相关的最近记录，提取已完成范围、未决问题、证据边界和续接位置。
2. 检查目标文件和 Git 状态，确认哪些改动属于当前任务；保留其他未提交修改。
3. 若账本没有明确续接点，结合用户最近指示和工作区证据定位任务；不依据旧快照、文件名或蓝图章号猜测下一章。
4. 确认具体目标卷、正文文件和对应章纲。读取相关前后文、卷级 canon 及审校报告；按任务需要加载技能。
5. 确认恢复后要做的第一项可验证动作，再进入 `11_操作工作流.md` 中的执行闭环。

## 三、索引与材料定位

| 材料 | 用途 | 恢复时如何使用 |
|------|------|----------------|
| `.agents/workspace/正文全卷审校进度.md` | 全项目实时审校记录 | 查当前任务的范围、结论、待决项与续接位置 |
| `卷根目录/00_正文索引.md` | 正文阅读顺序和稿件类别 | 文件存在时据此识别正式顺序；不存在时结合账本、正文和章纲核对，不臆造映射 |
| `.agents/workspace/XX_卷/00_卷索引.md` | 工作区导航、人物、章纲和资料信息 | 文件存在时辅助定位工作资料；不替代正文索引 |
| `.agents/workspace/XX_卷/章纲/` | 章节设计与情节依据 | 读取目标章及必要的相邻章纲 |
| 目标卷的正文与审校报告 | 已有叙事及修改证据 | 从上次修改位置和相邻文段恢复连续性 |
| `.agents/canon/09_驭器卷设定细化.md` 至 `12_明契卷设定细化.md` | 四个第一阶段主卷的具体设定 | 只读目标卷及任务涉及的文件；后续卷须按其对应 canon 定位 |
| `.agents/canon/26_全系列叙事架构与锚点账本.md` | 跨卷因果、锚点和映射证据 | 涉及跨卷事件时核对证据与状态 |
| `.agents/skills/<skill-id>/SKILL.md` | 专项操作方法 | 仅按当前任务调用 |

## 四、最小恢复上下文

当用户只说“继续”且任务链明确时，优先读取：

```text
实时审校账本中相关任务的记录
目标正文、目标章纲及必要的前后章
与当前问题直接相关的 canon / 审校报告 / skill
```

如果目标卷的正文索引或工作区卷索引不存在，不因缺少索引而自动创建或推断正式章序；先以现有正文、章纲和实时账本交叉核对，必要时把冲突记录为待核。

## 五、恢复检查

| 检查项 | 恢复目标 |
|--------|----------|
| 上次实际核读或修改到哪里？ | 避免重复或漏读 |
| 当前文件状态与账本一致吗？ | 识别账本过期或映射未确认的情况 |
| 哪些未提交改动属于其他工作？ | 避免覆盖或清理作者已有修改 |
| 需要哪些前后章、索引和 canon？ | 保持因果、连续性和设定边界 |
| 下一步是什么、如何验证？ | 恢复后能直接继续执行 |

## 六、常见恢复误区

| 误区 | 修正方式 |
|------|----------|
| 凭记忆续写 | 先读实时账本及现有正文，记忆只作定位线索 |
| 把历史快照当现状 | 用实时账本和文件证据核验 |
| 把工作区卷索引当正文目录 | 分别查正文索引与工作区索引，各自承担对应职责 |
| 直接套用旧蓝图章号 | 以确认过的正文映射、章纲和账本证据为准 |
| 一次加载全部 canon | 只加载目标卷和当前问题所需的材料 |
| 恢复时清理不相关改动 | 保留作者已有工作，只改当前任务范围 |
