# 00 · 架构总图

> 说明项目资料之间的职责、依赖和写作闭环。它是导航图，不是另一份正典或进度账本。

## 一、资料职责

```text
根 AGENTS.md ── 项目约束、优先级、入口路由
      │
      ├── canon/ ─────── 世界事实、系列因果、术语与写作规则
      ├── workspace/ ─── 人物、章纲、研究、正文设计、审校与实时账本
      ├── supplements/ ─ 面向读者或练习者的卷外材料
      ├── harness/ ───── 任务路由、工作流、质量门、恢复与维护
      ├── skills/ ────── 单项任务的可复用操作方法
      ├── docs/ ──────── 架构方案、计划和审计记录
      └── legacy/ ────── 迁移前文件的历史存档，不属于活动规则

仓库根目录的 `00_入界卷/` ── 非编年读者序卷与来源索引
仓库根目录的 `01–08_...卷/` ── 八卷正篇、正文索引及卷内稿件
```

| 资料 | 回答的问题 | 不负责什么 |
|---|---|---|
| 根 `AGENTS.md` | 进入项目先遵循什么、冲突时如何处理 | 重复展开完整正典或专项审阅清单 |
| `canon/` | 世界与故事中哪些事实/约束已成立 | 记录每天的工作进度 |
| `workspace/` | 当前人物、章纲、研究和审校推进到哪里 | 覆盖正文证据或自行裁定冲突 |
| `harness/` | 任务怎样进入、执行、复核和续接 | 取代技能的细节或正典内容 |
| `skills/` | 某类审阅、设计或生成任务具体怎么做 | 规定所有任务的总流程 |
| `supplements/` | 读者与练习者如何进入或实践 | 决定正文的现行章序 |
| `docs/` | 维护方案、计划和审计结论 | 充当故事设定或实时状态源 |
| `legacy/` | 旧资料曾如何组织 | 给当前 agent 发出可执行指令 |

## 二、事实与状态的来源

项目没有一个适用于所有问题的总排序。按事实种类找来源，并在证据冲突时保留冲突：

1. **当前阅读顺序、稿件类别与正文事实**：读者入口 `00_入界卷/` 按主题整理材料，不是编年依据；八卷正篇的顺序和稿件类别以各卷根目录的 `00_正文索引.md`（若已建立）及正文为准，不能仅凭文件名决定。
2. **人物、章纲和工作区导航**：看 `.agents/workspace/<卷>/` 内相应索引、人物卡和章纲。
3. **当前审校进度与续接点**：看 `.agents/workspace/正文全卷审校进度.md`。历史快照只用于回顾。
4. **基础世界规则、系列因果和术语**：分别查对应 canon 文件；若与正文或卷索引不一致，记录差异并标“待核”，不得悄悄抹平。
5. **旧蓝图**：只用于追溯设计意图。第一阶段四卷蓝图中的卷段名和章号不自动映射为全系列现行卷号、章号。

## 三、任务执行闭环

```text
识别用户目标
   ↓
根 AGENTS.md → 11_操作工作流.md：检查工作区、定位材料、确定任务范围
   ↓
按需读取正文索引、workspace 索引、canon 与前后章
   ↓
按当前 harness 支持的方式调用匹配技能；未自动发现时，直接读取 skills/<id>/SKILL.md 并按步骤执行
   ↓
实施修改 → 回读受影响内容 → 按风险复核正典、连续性和路径
   ↓
更新实时账本与确有对应字段的索引
   ↓
记录完成项、证据、待决事项与续接点；提交仅在作者明确要求时进行
```

### 按任务路由

| 任务 | 入口 |
|---|---|
| 章节写作 | [章节流水线](01_流水线.md) |
| 审阅或一般项目维护 | 先看 [操作工作流](11_操作工作流.md)；需要选专项任务时查 [任务路由与资料索引](04_命令中心.md) |
| 跨会话恢复 | [会话协议](06_会话协议.md) |
| 多代理并行与接力 | [多代理协作与交接](12_多代理协作与交接.md) |
| 单章审校/整卷审计/设定核验 | `review-chapter` / `audit-volume` / `check-canon` |
| 跨卷引用核验 | `check-cross-volume`，必要时附加 [集成验证](09_集成验证.md) |
| 章节设计/场景构思/人物/入门/实践单 | `design-chapter` / `craft-scene` / `gen-character` / `gen-entry` / `gen-practice` |
| 新增卷、结构迁移、规则或技能维护 | [运维手册](10_运维手册.md)，并更新受影响索引 |

技能的发现与调用界面由 Codex、Omarchy OMP、DeepSeek Harness 等运行环境决定。共享资料只约定技能 ID 和文件路径，不假设统一的斜杠命令或运行时能力。

## 四、控制与反馈

- [流水线](01_流水线.md) 描述章节从准备、设计、写作到审阅的过程。
- [状态机](02_状态机.md) 描述产出状态；真实项目状态以实时账本为准，不靠自动推断。
- [质量门](03_质量门.md) 提供按任务风险使用的检查标准；检查清单是复核辅助，不应为了打勾而机械套用。
- [模板注册表](05_模板注册表.md) 只登记实际模板位置和依赖，不决定事实或当前状态。
- [进度面板入口](07_进度面板.md) 只指向已归档的历史快照，不是状态源。
- [自动化](08_自动化.md) 记录未部署的只读检查示例及可选 hook；说明文件不等于脚本已经安装。

## 五、扩展与维护

新增卷时，以现行项目目录、该卷正文索引和相邻卷资料为依据建立工作区；不要机械复制第一阶段四卷的章数或五层/三件套假设。新增或迁移资料后：

1. 保留被替换资料中的唯一内容，并说明其效力是现行、历史还是待核。
2. 更新 `.agents/README.md`、本目录 `README.md` 中受影响的导航，以及其他相关索引和本地链接。
3. 若新增专项技能，检查 `04_命令中心.md` 和 `05_模板注册表.md` 是否确需更新。
4. 若改变流程、状态字段或自动化行为，同步维护对应 harness 文档；不重复复制整套规则。
5. 回查实时账本与卷索引，不以迁移计划或旧快照替代状态记录。

## 六、架构原则

1. **职责唯一，信息可链接**：规则、执行方法、工作状态和历史记录各有归处，避免多个文件争当真相源。
2. **证据先于推断**：目录名、旧章号、近似信号或结构相似性都不能单独证明事实映射或共同来源。
3. **按需加载**：从根入口出发，只读取能回答当前问题的资料和相邻证据。
4. **历史不等于现行**：旧文件保留其历史价值，同时显式标明不得用于推定当前章序或状态。
5. **人判断叙事，工具查机械错误**：自动化报告候选项；因果、人物选择、张力和文学表达仍需结合正文判断。
