# 08 · 自动化

> 自动化边界与历史评估样例。示例只适合发现机械候选，不替代人工审阅或判定正文质量。

> **部署状态与安全边界**：仓库没有从本页示例提取或安装的工具、Git hook；九项专项技能也不含可直接运行的脚本。下文代码块是待评估样例，不是项目命令或质量门。部分样例依赖 Bash、GNU 工具或 `grep -P`，并含固定章号、旧术语表等假设；复制前须核实依赖、索引覆盖和目标范围。示例只读取文件或提交消息并给出提示；hook 只有显式安装后才生效，其中 `commit-msg` 会拒绝不合规提交。输出不能证明正文合格，也不能裁定缺章或映射错误。

## 一、自动化哲学

在写作项目中，自动化与软件项目的自动化有本质区别：

| 维度 | 软件项目自动化 | 写作项目自动化 |
|------|--------------|--------------|
| 能自动化什么 | 编译、测试、lint、格式化 | 格式检查、术语核对、文件校验 |
| 不能自动化什么 | 架构设计、UX判断 | 文学质量、张力感知、情感共鸣 |
| 自动化目的 | 快速反馈，防止回归 | 消除机械错误，让审阅聚焦文学判断 |

**原则**：自动化机械检查，保留人文判断。

只有重复、跨卷适用、输入输出稳定且调用入口与维护责任明确的检查，才适合从示例整理为共享工具；当前样例不满足这一准入条件。

## 二、候选机械检查（示例）

### 2.1 文件名规范检查

```bash
# 示例：只检查命中的文件名，不移动或重命名文件
# 正确格式：第XX章_标题.md 或 第XX章_标题_副标题.md

find 0[1-8]_*卷 -name "第*章*.md" | while read f; do
  basename=$(basename "$f")
  if ! echo "$basename" | grep -qP '^第\d+章_.+\.md$'; then
    echo "⚠️ 文件名不规范: $f"
  fi
done
```

### 2.2 术语标注检查（铁律四之补充）

```bash
# 示例：只提示指定范围中常见术语的候选问题，不修改正文。
# 关键词列表不穷尽术语；脚本无法判断首次引入、明确复指、跨章重引或歧义，不能作为质量门。正式口径以 canon15/24 为准。

terms=(
  "所有权:ownership"
  "借用检查器:borrow checker"
  "健康检查:health check"
  "构建系统:build system"
  "版本控制:version control"
  "依赖:dependency"
  "回滚:rollback"
  "发布:release"
  "提交:commit"
  "分支:branch"
)

for f in "$@"; do
  for term in "${terms[@]}"; do
    zh="${term%%:*}"
    en="${term##*:}"
    # 粗略提示：同一文件内是否出现过对应括注；不能判断是否应标、标注位置或上下文义项。
    if grep -q "$zh" "$f" && ! grep -q "$zh（$en）" "$f"; then
      echo "⚠️ $f: '$zh' 未标注英文原名 '$en'"
    fi
  done
done
```

### 2.3 命名规范检查

```bash
# 检查是否残留废弃命名
grep -rn "百炼成仙" --include="*.md" 0[1-8]_*卷 .agents/ && echo "❌ 发现废弃命名残留"
grep -rn "xx百炼" --include="*.md" 0[1-8]_*卷 .agents/ && echo "❌ 发现废弃命名残留"

# 检查卷名格式
# 应为：万构界 · X卷
grep -rn "万构界" --include="*.md" 0[1-8]_*卷 .agents/ | grep -v "万构界·" | grep -v "万构界 " && echo "⚠️ 可能的命名格式问题"
```

### 2.4 章节连续性检查

```bash
# 示例：检查传入目录中可识别的章号间隔。正文索引、附篇及来源稿
# 可能使用不同编排；结果只作人工核查线索，不判定缺章或映射错误。
vol="$1"
ls "${vol}/" | grep -oP '第\K\d+' | sort -n | awk 'NR>1 && $1!=prev+1 {print "⚠️ 章节跳跃: " prev " → " $1} {prev=$1}'
```

### 2.5 Commit Message 署名检查（仅在提交时）

```bash
# 示例命令只读取最近一次提交消息；它不是 pre-commit 检查，
# 不能检查即将创建的提交。检查待提交消息应使用下方 commit-msg hook。

if git log -1 --format='%B' | grep -Eqi "co-authored-by.*(ai|agent|bot)"; then
  echo "❌ 铁律违反：commit message 包含 AI 署名"
  echo "如需处理已存在的提交，由作者决定是否改写提交历史；本示例不执行 amend。"
  exit 1
fi
```

## 三、可选 Git Hook 示例（未部署）

以下配置不是仓库现状。安装前先检查示例和当前文件约定是否仍适用；hook 只对安装它的本地 Git 仓库生效，不会自动同步给其他 harness 或协作者。示例中的文件名检查和术语检查只读取 staged 内容；pre-commit 在发现提示时仍返回成功。commit-msg 示例只读取消息文件，发现 AI/agent 共同署名时拒绝本次提交，不会自动改写提交历史或文件。

### 3.1 Pre-commit Hook

位置：`.git/hooks/pre-commit`（需手动安装）

```bash
#!/bin/bash
# 万构界 pre-commit 检查

PASS=true

# commit message 尚未生成时，pre-commit 无法检查它；署名检查应放在
# commit-msg hook 中（见下节）。

# 2. 检查文件名规范
STAGED_CHAPTERS=$(git diff --cached --name-only --diff-filter=ACM | grep '^.*第.*章.*\.md$')
for f in $STAGED_CHAPTERS; do
  basename=$(basename "$f")
  if ! echo "$basename" | grep -qP '^第\d+章_.+\.md$'; then
    echo "⚠️ 文件名不规范: $basename"
    echo "   期望格式: 第XX章_标题.md"
    PASS=false
  fi
done

# 3. 检查废弃命名
if git diff --cached -U0 | grep -q "百炼成仙"; then
  echo "❌ staged 更改中包含废弃命名「百炼成仙」"
  PASS=false
fi

if [ "$PASS" = false ]; then
  echo ""
  echo "以上问题不会阻止提交，但请尽快修复。"
fi

exit 0
```

### 3.2 Commit-msg Hook

位置：`.git/hooks/commit-msg`

```bash
#!/bin/bash
# 检查 commit message 格式

MSG=$(cat "$1")

# 禁止 AI 署名
if echo "$MSG" | grep -Eqi "co-authored-by.*(ai|agent|bot)"; then
  echo "❌ 铁律违反：commit message 不得包含 AI/agent 署名"
  echo "请移除 Co-Authored-By 行后重新提交。"
  exit 1
fi

exit 0
```

## 四、批量检查示例

这些代码块是供维护者评估的示例，不是已提取或部署的项目工具。运行前需在仓库根目录确认目标卷、文件命名和章号映射；输出只用于定位候选问题，不能替代正文索引、实时账本和人工判断。旧样例中的固定章数、术语表及路径须按实际范围调整。

### 4.1 生成术语检查报告

```bash
#!/bin/bash
# 对指定范围内的章节生成术语括注候选提示（不裁决是否合规）
# 用法示意: bash check_terms.sh 01_驭器卷 45 50
# 只读取正文并输出候选项；该示例基于两位数字章名和旧术语子集，
# 不适用于所有卷/稿件类别，运行前须先核对文件命名及 canon/24。

VOL="$1"  # 如 01_驭器卷
START="$2"
END="$3"

echo "=== 术语标注检查：${VOL} Ch${START}-${END} ==="

# 常见需要标注的术语（来自 .agents/canon/24）
declare -A TERMS=(
  ["构建系统"]="build system"
  ["版本控制"]="version control"
  ["依赖"]="dependency"
  ["回滚"]="rollback"
  ["所有权"]="ownership"
  ["内存安全"]="memory safety"
  ["并发"]="concurrency"
  ["静态分析"]="static analysis"
  ["动态检查"]="dynamic check"
  ["编译器"]="compiler"
  ["链接器"]="linker"
  ["调试器"]="debugger"
  ["健康检查"]="health check"
  ["负载均衡"]="load balancing"
  ["发布"]="release"
  ["部署"]="deploy"
  ["回退"]="rollback"
  ["迁移"]="migration"
  ["兼容性"]="compatibility"
  ["接口"]="interface"
  ["抽象"]="abstraction"
  ["泛型"]="generics"
  ["模板"]="template"
  ["宏"]="macro"
  ["测试"]="test"
  ["文档"]="documentation"
)

for ch in $(seq -w $START $END); do
  file="${VOL}/第${ch}章_"*.md
  # expand glob
  file=$(echo $file)
  if [ ! -f "$file" ]; then
    echo "Ch${ch}: 文件不存在"
    continue
  fi

  issues=""
  for zh in "${!TERMS[@]}"; do
    en="${TERMS[$zh]}"
    # 粗略候选：不分析语境、首次引入或跨章重标，结果须人工核对。
    if grep -q "$zh" "$file" && ! grep -q "${zh}（${en}）" "$file"; then
      issues="$issues  $zh→$en"
    fi
  done

  if [ -n "$issues" ]; then
    echo "Ch${ch}: ⚠️ 未标注$issues"
  else
    echo "Ch${ch}: ✅"
  fi
done
```

### 4.2 生成章节进度报告

```bash
#!/bin/bash
# 生成某卷的章节存在性报告
# 用法示意: bash chapter_report.sh 01_驭器卷
# 只读取目录并汇总文件存在性；120 章范围是旧蓝图示例，不代表现行映射。

VOL="$1"
DIR="${VOL}"

echo "=== ${VOL} 章节存在性报告 ==="
echo ""

total=0
written=0
missing=""

for ch in $(seq -w 1 120); do
  total=$((total + 1))
  match=$(ls "$DIR"/第${ch}章_*.md 2>/dev/null | head -1)
  if [ -n "$match" ]; then
    written=$((written + 1))
  else
    missing="$missing $ch"
  fi
done

echo "总计: $written/$total"
echo "完成率: $(( written * 100 / total ))%"
if [ -n "$missing" ]; then
  echo "蓝图范围内无同名文件（仅供核查，不表示缺章）: $missing"
fi
```

## 五、自动化与质量门的关系

| 质量门 | 自动化检查 | 人工判断 |
|--------|----------|---------|
| Prep Gate | 可选的文件/路径存在性提示 | 章纲和证据是否足以支持本次判断 |
| Design Gate | 可选的路径/链接/格式提示 | 因果、人物选择与叙事设计是否符合本章目标 |
| Prose Gate | 可选的术语候选、命名提示 | 事实、表达、节奏和人物代价是否成立 |
| Review Gate | 可选的文件名、链接存在性提示 | 跨卷叙述自足、因果链和连续性 |
| Commit Gate | 可选的提交消息与 staged 路径提示 | 是否符合作者指示和项目规则 |

## 六、自动化反模式

| 反模式 | 为什么错 |
|--------|---------|
| 过度自动化 | 试图用脚本判断"张力够不够"——这是人的判断域 |
| 把示例当成已部署工具 | 文档代码块不会自行执行，也未必适配全部卷；维护者核对用途、范围、依赖和结果后，再决定是否保存为工具 |
| 自动化替代审阅 | 脚本全绿 ≠ 章节质量过关 |
| 自动化成为瓶颈 | 因为脚本报 warning 就不提交——warning 是提醒，不是阻止 |
