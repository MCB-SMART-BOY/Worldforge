# 01 · 流水线

> 定义新章写作与实质性改写的常用闭环：准备、设计、写作、审阅。局部审校和项目维护从 `11_操作工作流.md` 按目标选步骤；提交始终由作者明确决定。

## 一、章节写作的常用顺序

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ PHASE 1  │───→│ PHASE 2  │───→│ PHASE 3  │───→│ PHASE 4  │
│ 准备      │    │ 设计      │    │ 写作      │    │ 审阅      │
│          │    │          │    │          │    │          │
│ 读章纲   │    │ 章节设计  │    │ 正文起草  │    │ 自查      │
│ 读卷设定 │    │ 场景构思  │    │ 适用时补注│    │ 审阅      │
│ 读相关   │    │ 张力设计  │    │ 结构自查* │    │ 修改      │
│ canon    │    │          │    │          │    │ 记录      │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
     │               │               │               │
     ▼               ▼               ▼               ▼
 Prep Gate       Design Gate     Prose Gate      Review Gate
 (通过才进入     (通过才进入     (通过才进入     (通过才完成)
  Phase 2)       Phase 3)       Phase 4)
```

* 结构自查、六拍和“三问”是可选的诊断工具；按本章目标使用。术语说明遵循 canon/15 与 canon/24，在首次引入、章节切换或语境有歧义时补足，不要求每次出现都重复标注。

## 二、Phase 1: 准备（Prepare）

**目标**：加载足以支持本章任务的材料，确认章纲、正文映射与工作范围；不要求通读所有参考资料。

### 输入
- 目标卷根目录的 `00_正文索引.md`（若存在，用于确认正式阅读顺序和稿件类别）
- `.agents/workspace/XX_卷/00_卷索引.md`（若存在，用于工作区导航、人物/章纲/状态信息；不替代正文索引）
- 目标卷的 `章纲/` 对应 Section 文件（读取本章章纲）
- 相关 canon 文件（按需，由本章的工程主题决定）

### 步骤

| # | 操作 | 执行方式 | 产出 |
|---|------|------|------|
| 1.1 | 查正文索引（若有）与工作区卷索引（若有），确认稿件类别及工作区导航；按账本、章纲和正文证据定位目标章 | 使用当前环境可用的文件查看或搜索能力 | 目标范围与前后文依据 |
| 1.2 | 读取本章章纲（结构、工程主题、张力设计） | 查看对应文件 | 章纲原文与适用的设计依据 |
| 1.3 | 读取对应卷级设定 | 查看对应文件 | 卷级约束：对象层级、文明命题、道统特质 |
| 1.4 | 读取相关 canon 补充（按主题） | 查看对应文件 | 补充材料 |
| 1.5 | 检查前后章正文（如果已写） | 查看对应文件 | 叙事连续性锚点 |

### Phase 1 完成标准
进入设计前，确认已有材料足以支撑本次目标；不适用项说明原因，缺少且会影响判断的证据列为阻断项。具体检查见 [Prep Gate](03_质量门.md#一prep-gate准备门)。

## 三、Phase 2: 设计（Design）

**目标**：生成足以支撑本章的设计，明确工程问题、人物选择、因果推进与信息边界；需要时用六拍、张力或揭示节奏作参照。

### 步骤

| 操作 | 工具 | 产出 |
|------|------|------|
| 形成足以支撑写作的章节设计 | `design-chapter` | 章节设计蓝图 |
| 复杂场景需要单独拆解时，规划行动、信息与选择 | `craft-scene`（按需） | 场景方案 |
| 按本章实际涉及内容核对工程原型、术语和信息边界 | 对应 canon、章纲索引（如有） | 必要的事实说明或待核项 |
| 对照质量门中的 Design Gate | [质量门](03_质量门.md) | 通过、待补证据或不适用项 |

### Phase 2 完成标准
设计足以支撑写作，且通过[质量门中的 Design Gate](03_质量门.md#二design-gate设计门)；按需核对术语，不适用时注明原因。

---

## 四、Phase 3: 写作（Write）

**目标**：将设计转化为符合本卷节奏和用户要求的正文；篇幅以指定范围、相邻正文和章节功能为准。

### 步骤

1. 依据章纲和设计起草正文，让人物行动、工程条件、选择与后果在场景中成立。
2. 作者完成 Prose Gate 自查；术语、场景代价、张力和新读者理解等项目按本章需要检查，不适用时无需补造记录。
3. 质量门见[质量门](03_质量门.md)，本章完成标准以用户目标、正文惯例及适用的硬约束为准。

### 正文写作规范

- **长度**：遵循作者本次目标及该卷现行正文惯例，不设全项目统一字数门槛
- **结构**：六拍骨架是诊断和设计工具；依据章节功能调整次序、密度或省略，不以表格齐全替代戏剧因果
- **术语**：按 canon/15 与 canon/24 现行口径处理；首次解释准确、后续使用清楚，避免重复标注打断阅读
- **叙事视角**：以本卷叙事目标和信息边界为准；主角视角是常用选择，不是强制视角
- **场景切换**：按上下文选择空行或分隔符；若使用分隔符，沿用相邻正文体例，不强制单一形式
- **对话**：遵循当前正文使用的中文标点惯例，并保持全章一致
- **文件名**：`第XX章_标题.md`

### 写作调性参考（第一阶段四卷的意象例，不作风格硬规定）

- **驭器卷**：古、重、考古气——"凌晨三点的玄枢散热塔"
- **化形卷**：快、灵、脚本气——"先跑起来再说"
- **简阵卷**：平、冷、值班气——"今晚又是你"
- **明契卷**：硬、准、边界气——"编译器不骗人，但人会"

### Phase 3 完成标准
完成正文初稿并通过[质量门中的 Prose Gate](03_质量门.md#三prose-gate写作门)。术语与场景自查按正文写作规范及本章需要执行。

---

## 五、Phase 4: 审阅（Review）

**目标**：按用户目标审阅正文，处理高优先问题，回查必要上下文并记录结果。单章可用 `review-chapter`，连续范围或整卷可用 `audit-volume`；必要时追加正典或跨卷核验。

### 步骤

| # | 操作 | 工具 | 产出 |
|---|------|------|------|
| 4.1 | 章节审校 | `review-chapter` | 审校报告 |
| 4.2 | 逐条修改 | 手动 | 修改后正文 |
| 4.3 | 设定验证（如涉及新设定） | `check-canon` | 设定验证报告 |
| 4.4 | 跨卷验证（如有跨卷引用） | `check-cross-volume` | 跨卷验证报告 |
| 4.5 | 过 Review Gate | 对照质量门 §Review Gate | ✅/❌ |
| 4.6 | 更新实时审校账本及受影响索引 | 手动 | 可续接的状态记录 |

提交不是本流水线阶段。只有作者明确要求提交时，才按 `.agents/harness/03_质量门.md` 的 Commit Gate 检查；完成审阅和更新账本不以提交为前提。

### Phase 4 完成标准
按[质量门中的 Review Gate](03_质量门.md#四review-gate审阅门)处理本次范围；回读受影响内容并更新实时审校账本及必要索引。

## 六、批量流水线（多章并行/连续）

### 6.1 连续写多章（同卷）

```
Phase 1 (批量准备)
    │
    ├── Chapter N   → Phase 2 → Phase 3 → Phase 4
    ├── Chapter N+1 → Phase 2 → Phase 3 → Phase 4
    └── ... → Chapter N+k → Phase 2 → Phase 3 → Phase 4
                         │
                         ▼
              Phase 4 (批量审阅: audit-volume)
```

**批量原则**：
- Phase 1 可以为目标范围批量准备；只加载本次任务和相邻连续性所需的章纲，不默认通读整卷材料
- Phase 2/3 逐章推进（每章有自己的设计蓝图；仅在章节功能需要时设计张力曲线）
- Phase 4 可按实际章纲分组、任务范围和风险安排批量审阅；发现连续性或共因问题时缩小审阅范围。具体数量不作固定要求。

### 6.2 按范围选择审阅节奏

| 范围 | 适用场景 | Phase 4 策略 |
|------|---------|-------------|
| 单章 | 需要精细处理的重点章节或作者指定章节 | `review-chapter` 逐章审阅 |
| 章纲分组 | 章纲文件、连续情节段或用户指定的一组章节 | `audit-volume` 按实际范围复盘，并更新实时审校账本 |
| 整卷/跨卷 | 卷级收束或涉及多个卷的共同因果 | `audit-volume`，必要时补 `check-cross-volume` 和集成验证 |

分组范围以实际章纲、正文索引和任务风险为依据，不按旧蓝图章号或固定篇数推定。

## 七、特殊章的流水线变体

### 7.1 阅读入口章节

额外步骤：
- Phase 1：先通过正文索引确认本卷入口；若确有跨卷承接，再读取相关前卷材料，不把阅读前卷作为理解本卷的前提
- Phase 2：设计时需包含"新读者入口"检查——这一章能否让从本卷开始读的人不掉队？
- Phase 3：尽早让新读者获得必要定位（人物、场景、眼前问题）；依场景节奏安排，不设硬性字数界线

### 7.2 卷尾或阶段收束章节

额外步骤：
- Phase 2：设计本卷结尾的情感或情节落点；如需要跨卷接口，明确它如何增益而不制造阅读前提
- Phase 3：收束与后续接口按故事需要安排，不强迫每个卷尾同时出现主题结论和悬念钩子
- Phase 4：按已确认的卷间接口检查后续承接；不从固定章号推断卷界

### 7.3 跨卷锚点章

额外步骤：
- Phase 2：先读取 `.agents/canon/26_全系列叙事架构与锚点账本.md`、当前卷索引和相关正文；仅在涉及第一阶段四卷的历史事件时，补查 canon/22
- Phase 3：确保事件从本卷主角的代价和病理重新叙述（跨卷铁律二）
- Phase 4：执行 `check-cross-volume` 验证

### 7.4 高潮章

额外步骤：
- Phase 2：若本章承担全卷高潮，确认其在当前卷结构中形成主要峰值或关键转折；不是全卷高潮的章节按自身功能设计
- Phase 3：让本章的核心选择与代价具有分量；代价是否不可逆需符合事件性质，不为制造高潮而夸大
- Phase 4：`audit-volume` 从整卷视角检查高潮位置、铺垫、回落和代价是否成立

## 八、流水线反模式

| 反模式 | 为什么错 | 正确做法 |
|--------|---------|---------|
| 跳过 Phase 1 直接写 | 不知道前后章在写什么 → 叙事断裂 | 至少读目标章的章纲 + 前后章的章纲 |
| Phase 2 设计太简略 | 只有概念口号，无法判断人物如何行动、选择怎样改变局面 | 补到足以支撑本章写作；若本章依赖明显张力变化，再指出关键转折或峰值 |
| Phase 3 写完不自查 | 把审阅负担全推到 Phase 4 | Prose Gate 是作者的责任，不是审阅者的 |
| 长批次连续写作而不回看 | 早期问题可能扩散到后续章节 | 按章纲分组和风险设置检查点；发现重复性问题时缩小批次 |
| Phase 4 只审不修 | 审阅发现的问题留在正文里 | 审一条改一条，改完回读并记录 |
