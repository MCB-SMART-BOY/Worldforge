# gen-practice — 实践单生成

从一章正文生成对应的「卷外配套」章节实践单。
**实践单不只是验证工程概念——它应该让练习者感受到：这个工程概念在真实世界里是怎么痛的，而学会它之后你能保护谁。**

中文工程术语首次引入时遵循 canon15/24 的准确英文原名规则；明确复指可省略。数量、练习层次和叙事方式按学习目标与实践单篇幅选择，不为达到固定数量而重复练习或虚构失败。

## 参数

- `chapter_path` — 章节文件路径
- `volume` — 所属卷；按项目根目录的现行卷目录和对应索引填写，不限于第一阶段四主卷
- `chapter_number` — 章号

## 生成前：核对当前章节

通用证据规则、当前状态来源和任务闭环见[操作工作流](../../harness/11_操作工作流.md)。本技能另需核对：

1. 查章节所属卷的现行索引和正文，确认章节编号、实际内容及其教学位置。
2. 涉及跨卷因果时参照 canon26、相关索引和正文；canon23 等旧蓝图只供主题追溯。
3. 正文、索引和账本未确认章号或映射时标“待核”，不据旧蓝图推算实践单所属卷段。

## 设计原则

### 从"验证概念"到"体验代价"

好的实践单不只是"你做一遍看能不能跑通"。适合通过动手发现问题时，可以让练习者：
1. 先**观察问题**（必要时用可控的小失败呈现）
2. 再**理解概念**（引入本章的工程方法来解决）
3. 最后**反思代价**（如果不这么做，谁会受伤）

### 练习情境（按需）

若人物或使用场景能让学习目标更具体，可用简短情境说明"我在替谁解决什么问题"；直接操作、比较或判断的练习不必添加虚构角色：
- "你是北院的新人，季循让你接手一段回退脚本；纸上的步骤和现场环境对不上……"
- "你的团队刚接手了一个三年前的 Python 项目，README 里写着 'just run main.py'……"

## 实践单模板

### 前置信息
- 所属卷/章
- 对应工程主题
- 本章涉及的四蚀（适用时填写）
- 前置知识要求
- 本章的人物或使用者代价（能从正文与学习目标中成立时填写）

### 可选练习层次

#### 第一层：碰撞练习（先观察问题，再理解概念）

- 目标：让练习者先经历"纸上写的走不通"，再引入正确做法
- 形式：用真实且可控的缺口或案例 → 练习者尝试 → 观察差异 → 引入概念 → 再做一次；不人为制造事故，也不把虚构失败当成正文事实
- 数量：按教学目标决定；避免为凑数重复或虚构失败
- 格式：
  ```
  ### 练习1-1：[标题]
  **场景**：[1-2句话的微型叙事，你和谁，在哪，什么压在你心上]
  **第一次尝试**：[你按"纸上写的"去做……]
  **观察到什么**：[结果、报错或困惑；如无明显失败，记录实际差异]
  **现在引入**：[本章的工程概念]
  **再做一次**：[用正确方法重新操作]
  **观察**：[这次有什么不同]
  **问自己**：如果你不知道这个概念，谁会在什么时间点受伤？
  ```

#### 第二层：变体练习（换个场景，概念还站得住吗？）

- 目标：确认读者能在不同场景中应用同一概念
- 形式：改变一个条件（语言/项目/团队规模/时间压力/人员变动）
- 数量：按需要选择，可省略
- 格式：
  ```
  ### 练习2-1：[标题]
  **变化**：[什么条件变了——人走了？项目大了？时间更紧了？语言换了？]
  **你的判断**：[一个需要做选择的开放问题]
  **为什么**：[引导读者写下决策理由]
  **如果选错了**：[代价会落在谁身上？]
  ```

#### 第三层：连接练习（这个概念在整个工程图景里的位置）

- 目标：确认读者能把本章概念放进更大的工程图景
- 形式：联系前章或预演后章的跨概念练习
- 数量：可选；仅在能形成有意义的跨概念连接时设计
- 格式：
  ```
  ### 练习3-1：[标题]
  **连接**：[连接哪两章的概念]
  **场景**：[一个需要综合判断的任务]
  **你的设计**：[需要做什么决策]
  **反思**：你现在做的这个决定，三个月后谁会感谢你？谁会骂你？
  ```

### 每层后的自检

- [ ] 我是否理解了练习要验证的概念？
- [ ] 我的操作结果是可复现的吗？
- [ ] 如果我不得不在凌晨两点把这个练习的结果交给一个不认识的人，他能接住吗？

### 章末反思

```
### 本章反思（按学习目标选问或改写）
1. 🩻 这一章帮你看见了哪一种工程病？
2. 😣 这个病的代价在真实项目中会落到谁身上？
3. 🛤️ 学完这章，你有没有比之前更有办法让后来者好走一点？

### 叙事回响（按学习目标选用）
回到这一章的正文，你觉得哪个角色在你做练习的时候一直在你脑子里？
他身上最让你放不下的那个瞬间是什么？
```

## 语言特定练习偏好

> 以下语言与卷的配套偏好只适用于第一阶段四主卷。实际卷名、章号和练习内容以指定正文及现行卷索引为准，不据此推断全系列卷序或章数。

### C++ / 驭器卷
- 偏构建系统、依赖分析、profile、wrapper 编写、考古层工具
- 练习常涉及：分析旧代码、写 adapter、写 runbook 条目、追溯隐式依赖
- **叙事场景偏好**：玄枢古器维护、守门者交接、旧核深处的隐性依赖、六维工具链从无到有

### Python / 化形卷
- 偏环境管理、依赖锁、脚本到 package 迁移、复现验证、类型渐进
- 练习常涉及：venv/poetry/uv、requirements 审计、notebook 清理、mypy类型检查
- **叙事场景偏好**：息壤脚本林、林过川遗迹、"上周还能跑"的调试现场、包管理从乱到治

### Go / 简阵卷
- 偏服务边界、健康检查、日志/追踪、部署回滚、并发模型
- 练习常涉及：写 health check、定义 API 契约、写 runbook、goroutine泄漏排查
- **叙事场景偏好**：驿河凌晨传讯牌、失明事故追踪、新手独立接值班、平台工程规模化

### Rust / 明契卷
- 偏 cargo 命令、项目结构、类型系统、错误处理、所有权
- 练习常涉及：新建项目、改 Cargo.toml、处理 Result/Option、写测试、borrow checker
- **叙事场景偏好**：青炉起炉过程、代码审查对峙、契约炸玄枢（跨卷回声）

## 输出

完整 Markdown 实践单文件。优先放入目标卷现有的 `.agents/supplements/XX_卷/`，并先核对该卷配套索引与模板；目录不存在或归属不明时，先给出建议位置并说明依据，不按示例路径自动新建目录。尚未确定目标卷的草稿可放入 `.agents/supplements/_草稿模板/`。

## Gotchas

- **去情境化的练习**：若情境能帮助练习者理解影响对象，可给出人物或使用场景；不要求每道练习都套入角色故事。
- **强造失败**：概念适合通过可控失败学习时，可先让练习者观察问题再应用方法；不适合安全模拟失败的内容，可以从分析、比较或决策开始，不虚构事故。
