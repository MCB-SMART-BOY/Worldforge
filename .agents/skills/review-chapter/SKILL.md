# review-chapter — 章节审校

审校单章正文，对照《万构界》现行规则给出证据化修改建议；连续章节或整卷复核使用 `audit-volume`。
**工程因果与设定边界是审校底线；戏剧张力和读者可及性按本章功能诊断，不要求每章采用同一种张力结构。**

## 参数

`chapter_path` — 章节文件路径（如 `04_明契卷/第01章_凡火未明_问题从何而来.md`）

## 审校前：核对当前章节

通用证据规则、当前状态来源和任务闭环见[操作工作流](../../harness/11_操作工作流.md)。本技能另需核对：

1. 查章节所属卷的现行索引、前后章和最新正文，确认章号、阅读顺序与人物状态。
2. 需要判断当前审校范围时查实时账本；涉及系列因果或跨卷锚点时参照 canon26、相关索引和正文。
3. canon23 等旧蓝图只供主题追溯，不决定当前卷序、章序或编号映射；未确认的锚点标“待核”，不据此判错或改写因果。

## 审校清单

### 一、三条核心审校问题

仅在与本章内容相关时判断；不适用或没有足够证据时注明原因。只有违反 canon、工程事实或损害本章目标的证据才形成问题，不以清单全勾作为通过条件。

1. **先工程，后修辞**：这一章的修辞是否压过了工程逻辑？读者能否清楚说出"这里在处理什么真实工程问题"？
2. **因果规则有边界**：若设定推动事件或改变世界运行，是否交代其适用范围、触发条件与失效后果？普通名词、道具、意象和人物假说可标“不适用”。
3. **成长=责任升级**：主角/核心人物的成长是否表现为责任扩容（能守更多、能立约、能传火），而非战力升级（更强、更快、更无敌）？

### 二、六拍结构诊断（按章节功能选用）

如六拍适合本章，检查其因果功能是否得到呈现；不适合的拍可注明理由，不因形式缺项判错：
1. 问题先出 —— 开场就让人看见痛
2. 讲清为什么痛 —— 不是"技术难"，是"这个难落到谁身上"
3. 引出语言特性/工具链/工程方法 —— 用真实术语，不是世界观隐喻
4. 在具体项目/器/门中落地 —— 青炉/玄枢/息壤/驿河
5. 团队/维护/继承视角复盘 —— 不止主角一个人
6. 收束到更高层判断 —— 一句话回扣本卷文明命题

### 三、剧情张力审计

按章节功能检查以下剧情张力维度；静场、过渡、回望等章节不必具备全部特征：

#### 3.1 张力曲线
- [ ] 若本章需要制造张力，节奏变化是否可辨识？上升、释放、留白、平静收束等均可按功能选择。
- [ ] 若本章设置张力高点或揭示，它的位置是否符合读者获得信息的节奏？
- [ ] 若本章有连续强刺激，是否需要留出理解或情感消化的空间？
- [ ] 章末是否以适合本章的方式收束：悬念、余震、行动方向或平静结束均可。

#### 3.2 揭示时机
- [ ] 本章的核心信息（工程真相/人物秘密/系统缺陷）是在读者最想知道的时刻给出的，还是过早/过晚？
- [ ] 有没有"角色知道但读者不知道"的张力？（戏剧反讽 —— 读者替角色捏一把汗）
- [ ] 有没有"读者知道但角色不知道"的张力？（读者看着角色走向陷阱）
- [ ] 揭示是"展示"出来的还是"告知"出来的？（展示 > 告知）

#### 3.3 情感锚点
- [ ] 本章是否提供了贴合叙事目标的情感入口或人物处境？
- [ ] 若本章承担人物情感变化，读者能否从行动、关系或处境中辨认？
- [ ] 章末情感余韵（如有）是否与本章功能相称？
- [ ] 是否避免了"全员冷静理性分析"？（工程小说最易犯的病：所有人都是工程师，没有人在情感上受伤）

#### 3.4 代价可视
- [ ] 若本章有重要代价，它是否具体、可辨认？
- [ ] 若剧情依赖持久代价，该代价是否具体且在后文保持一致？可逆与否按事件本身判断。
- [ ] 代价是否落在了具体的人身上，而不是抽象的"团队"或"项目"？

#### 3.5 因果链
- [ ] 本章的每一个重要事件是否都有一个"因为"在前面？（不是"然后发生了"，而是"因为X，所以Y"）
- [ ] 是否有任何事件出现得"太巧"？（巧合可以启动故事，但不能解决故事）
- [ ] 本章的事件是否自然生长自上一章的结局？（连接处不能生硬切换）

### 四、入门友好度审计

特别针对新读者的认知负荷：

- [ ] 新读者能否在适当位置辨认场景、视角和当前问题？不设固定字数。
- [ ] 新概念的密度是否妨碍理解？数量作为提示，结合解释和章节长度判断。
- [ ] 新术语首次出现时，是否以适合本章的语境、例子、行动或简洁说明让读者理解？不限定必须使用角色体验。
- [ ] 是否能用一句话讲清"这章写了什么"给一个没读过前文的人听？
- [ ] 工程术语的使用是否让不懂编程的读者也能从上下文猜出大意？（术语不是门槛，是氛围）

### 五、三问自查（按场景适用）

对承担世界观或人物责任推进的主要场景，按需检查：
1. 🩻 在结算哪一种四蚀（失式/乱流/背契/断史）？
2. 😣 代价落在谁身上？
3. 🛤️ 后来者有没有比之前更有路可走？

若不适用，或场景本身不承担世界观推进，注明即可；答不上不自动判错，应检查它是否影响本章目标。

### 六、术语铁律

- [ ] 是否保留了真实工程术语（Cargo/crate/trait/Result/CI/tracing/service 等）？
- [ ] 世界观术语是否只用于解释位置，而非替换真实术语？
- [ ] **术语标注**：中文工程术语首次引入时是否标注准确英文原名？明确复指可省略，跨章重引或歧义时重标。参考 canon15/24。
- [ ] **文学表达的语境**：只有当读者因此无法理解当前行动、规则或代价时，才检查是否需要补足场景语境；不要求隐喻逐项标注工程原型。
- [ ] 新出现的世界观概念是否在此卷内有够用解释（不假设读者读过别卷）？

### 七、命名规范

- [ ] 系列名固定为「万构界」
- [ ] 卷名格式为「《万构界·X卷》」
- [ ] 无 `xx百炼成仙` 残留

### 八、跨卷规则

若本章引用了共享事件或其他卷的角色：
- [ ] 是否在本章内给出了够用解释？
- [ ] 是否只做互文增益，不把别卷写成本章前提？
- [ ] 是否从本卷主角的代价和病理重新叙述？

## 输出

只填写适用于本章的结构检查项。结论可为符合、问题、待核或不适用，并附具体文本证据；不以模板项全部勾选作为完成标准。


## Gotchas（常见失分点）

- **情感入口**：若本章目标依赖人物处境，检查情绪是否落实在选择、关系或代价上。平静、克制或纯操作性段落不因此自动失分。
- **术语负荷**：新概念的数量只作提示；结合解释、篇幅和场景功能判断。若确实妨碍理解，再考虑延后或分散。
- **张力平铺**：若本章意图制造张力却始终同强度，可考虑变化节奏；呼吸点的位置和篇幅由章节功能决定。
- **告知而非展示**：发现自己在写"XX 是 YY"的定义式句子 → 改成角色在具体场景中撞上这个概念。
