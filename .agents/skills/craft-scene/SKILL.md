# craft-scene — 场景工艺

为一个具体场景做戏剧构造。场景可承担工程、人物、情节、氛围或过渡等功能；按当前任务判断它需要推进什么，不强迫每场同时承载工程解释和情感转折。

## 核心信念

> 万构界最好的场景，是让读者同时感受到两件事：
> 1. "原来这个工程概念是这样运作的"（认知收获）
> 2. "这个人的处境让我心里一沉"（情感共鸣）
>
> 两者结合常能形成有辨识度的场景；若某场只承担其中一项或其他功能，应看它是否服务章节整体。

## 参数

- `scene_context` — 场景在章节中的位置（前情 + 当前需要推进什么）
- `characters` — 场景中的人物
- `engineering_point`（可选）— 这个场景涉及的工程概念/方法/事实
- `emotional_point`（可选）— 需要呈现的情感变化或状态（困惑→明了？恐惧→勇气？信任→怀疑？希望→绝望？）
- `tension_target`（可选）— 若有助于沟通，可用相对等级描述张力目标；不作为机械评分

## 构思前：核对场景所在位置

通用证据规则、当前状态来源和任务闭环见[操作工作流](../../harness/11_操作工作流.md)。本技能另需核对：

1. 查场景所属卷的现行索引、章纲和前后正文，确认场景的因果位置与人物状态。
2. 涉及全系列锚点时参照 canon26 及相关卷索引、正文；canon23 等旧蓝图只供主题追溯。
3. 事件位置或跨卷回声未获索引、正文和账本确认时标“待核”，不按旧蓝图章号安排揭示。

## 场景设计流程

### 第一步：确定场景功能

先判断场景主要功能；可以有多个功能，但应看清它们的主次：

| 主功能 | 描述 | 本场景占的比例 |
|--------|------|--------------|
| 推进工程认知 | 读者学到了一个新工程概念或看见了一个工程病 | 按场景需要 |
| 推进人物弧线 | 人物做出选择，暴露信念、盲点或成长 | 按场景需要 |
| 推进情节 | 事件改变了后续行动方向 | 按场景需要 |
| 建立氛围 | 让读者感受世界/卷/项目的独特质感 | 按场景需要 |

可标注主功能与辅助功能；有多个并行功能时，说明它们如何互相支撑。

### 第二步：确定张力形态

若场景需要明确的张力引擎，可从以下来源中选择或自行说明；氛围、过渡和余韵场景不必强加冲突：

| 张力来源 | 读者在想什么 | 万构界里的典型场景 |
|---------|------------|-----------------|
| **认知张力** | "这个系统到底是怎么运作的？" | 追踪一个 bug、排查一个依赖链 |
| **人际张力** | "这两人的分歧会在哪一刻爆发？" | 代码审查对峙、师徒对修复方案的分歧 |
| **时间张力** | "还来得及吗？" | 开窗前夜、回滚倒计时、临时方案的有效期 |
| **代价张力** | "这个决定会伤到谁？" | 选择快速修复（累积债务）还是重构（延误工期） |
| **揭示张力** | "真相到底是什么？" | 找到一段三年前的代码，发现注释和实现矛盾 |
| **制度张力** | "规矩和现实哪个赢？" | 流程说必须先评审，但外面已经在等了 |

### 第三步：设计场景节奏

如场景需要转折，可参考三段式微型节奏：

```
开场 → 建立此刻的状态（谁在，在哪，什么压在心上）
转折 → 一个信息/事件/选择改变了局面
收束 → 新的状态确立，为下一个场景留下引力
```

必要时标注段落篇幅或节奏预期，不要求数字比例。

转折强度可与目标张力相互校准，例如：
- 张力 1-2：转折可以是一个认知上的小发现
- 张力 3：转折可以是令人不安的信息或被迫的选择
- 张力 4-5：转折通常需要显著改变局面；是否不可逆由剧情事实决定

### 第四步：设计场景内的信息释放

场景中读者和角色的信息差：

| 在这个场景中 | 读者知道 | 角色知道 |
|------------|---------|---------|
| 工程事实 | [列出] | [列出] |
| 人物情感/动机 | [列出] | [列出] |
| 即将发生的危险 | [列出] | [列出] |

若信息差能增强场景，可选择一种作为戏剧引擎：
- **读者知道，角色不知道** → 读者替角色捏汗（"别点那个！"）
- **角色知道，读者不知道** → 读者追问"你到底看到了什么？"
- **读者和角色都不知道** → 一起探索，一起撞墙（适合事故/调试场景）
- **读者和角色都知道** → 看着事情不可避免地向悲剧滑去（最沉重）

### 第五步：场景结尾的引力

根据场景功能决定是否需要明确的结尾引力。转场、停顿或余韵场景可以平静收束；若剧情需要推进，可选用：

- **未答问题**："他看到了什么？"
- **代价预告**："这个选择会在天亮前找上门"
- **情感余震**：一个意象、一个动作、一句沉默
- **因果钩子**："因为刚才做了X，现在已经来不及做Y了"
- **视角切换预告**："同一时刻，在另一扇门后……"

### 第六步：工程概念的场景化

将工程概念嵌入场景的具体动作中：

- ❌ 错误做法：角色A对角色B解释 trait 是什么（课堂教学式）
- ✅ 正确做法：角色B写了一个 trait 但忘了实现某个方法，编译器不通过，角色A指着报错说"它不认你，因为你答应的事没做"（冲突中学习）

若场景承担工程解释，尽量让概念与行动、判断或后果相连；纯粹传递背景的场景也可按章节需要使用。

**术语标注**：中文工程术语首次引入时标注准确英文原名；明确复指可省略，跨章重引或歧义时重标。文学表达按需通过场景建立工程原型，不必破坏叙事节奏地逐词括注。

### 第七步：情感锚点确认（人物情感为本场功能时使用）

- [ ] 若场景以人物为中心，人物感受是否通过行动、身体反应或对话变化呈现？
- [ ] 这个情感是否通过具体行动/身体反应/对话变化表现出来（而非直接告知"他很担心"）？
- [ ] 场景的情感温度是否有变化（开始冷 → 中间热 → 结尾温）？

## 场景蓝图输出

以下是可裁剪的起稿框架。按场景功能保留必要字段；张力等级、工程点、情感变化、三问等均可省略或标“不适用”。不要为了填模板而给静场、转场或氛围段添加冲突、不可逆代价或悬念。

交付物应说明场景目标与所在位置、必要的行动或信息节拍、人物选择及其后果（如适用），并标出事实缺口和待核项。场景蓝图本身不自动覆写正文；写入前按项目工作流核对目标文件与索引。

```markdown
## 场景蓝图：[场景名称]

### 功能定位
- **主功能**：[选一]
- **辅助功能**：[选一]
- **工程点（如适用）**：[这个场景让读者学到什么工程概念/看见什么工程病]
- **情感点（如适用）**：[这个场景呈现什么情感状态或变化]

### 张力设计
- **张力来源（如适用）**：[选一或自定义]
- **张力强度（可选）**：[用文字描述，或用1-5相对标记]
- **微型节奏（如适用）**：[开场、转折、收束如何安排；不要求比例]

### 信息差引擎
- 信息差（如有）：[读者或角色各自知道/不知道什么]
- 选择的戏剧模式（可选）：[同步/反讽/悬念/其他]

### 开场
> [第一段 —— 谁在，在哪，什么压在心上]

### 转折
> [核心事件/信息/选择 —— 改变了什么]

### 收束
> [新状态或余韵；若需要推进，可留出因果引力]

### 工程嵌入（本场承担工程解释时使用）
- **工程概念**：[真实术语]
- **出场方式**：[作为冲突的工具/作为冲突的原因 —— 具体怎么出现]
- **角色是否懂**：[懂 → 展示专业 / 半懂 → 展示盲点 / 不懂 → 展示学习]

### 情感锚点（如适用）
- **谁的情感在变化**：[角色名]
- **何种变化**：[从___到___]
- **如何表现**：[一个具体的行动/身体反应/对话选择]

### 三问（本场承担世界观或人物责任推进时选用）
1. 🩻 这个场景结算哪种四蚀？[失式/乱流/背契/断史]
2. 😣 这个场景的代价可被看见了吗？[谁/失去什么/在哪一刻]
3. 🛤️ 这个场景让后来者的路发生了什么变化？[更清晰了/更模糊了/暂时无变化但有伏笔]
```

## 场景序列设计（多场景组合时使用）

若一次设计多个连续场景，可标出场景之间的张力变化：

```
场景1（张力2）→ 场景2（张力3）→ 场景3（张力1·呼吸点）→ 场景4（张力4·小高潮）
```

规则：
- 连续高强度场景可检查是否造成疲劳，具体依节奏决定
- 需要时安排停顿或呼吸点，不规定场景数量
- 最高张力是否过早出现，取决于该场景是否给读者足够语境

## Gotchas（常见场景设计错误）

- **课堂式场景**：角色围坐一圈，轮流解释概念。这是万构界最常见的病——因为工程概念需要解释，最方便的方式就是让角色张嘴说。解法：把解释变成冲突。不是"我来教你 trait"，而是"你写的 trait 过不了审契者的校验，因为他认为你的抽象层级错了"。
- **强造冲突**：角色意见一致不等于场景无用。若场景需要张力，可从未知、时间、责任或代价中找到真实来源；不需要时允许平静协作、转场和余韵，不为制造冲突而虚构分歧。
- **情感标注式**：写"他感到沮丧"而不是展示沮丧（他把刚写的代码全删了，盯着空屏，手指悬在键盘上方三秒没动）。
- **信息均匀释放**：若信息密度单调影响阅读，可调整揭示时机；不强制使用突袭式揭示。
- **场景没引力**：场景结尾是一个自然的"段落结束"感。正确：场景结尾应该让读者不舒服——有个东西没解决、没回答、没放下。
