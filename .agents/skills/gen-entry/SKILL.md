# gen-entry — 入门引导生成

为《万构界》生成面向新读者的入门引导材料。
**工作目标：根据目标读者和当前正文，补足进入故事所需的方向感；不预设每卷都存在相同的阅读障碍。**

## 需要评估的阅读阻力

先检查目标卷的索引、正文和已有入门材料。陌生术语、背景知识或阅读顺序不明都只是待验证的问题；不要把旧审读中的局部观察写成全系列现状，也不要重复生成已有且仍准确的介绍。

## 参数

- `target` — 要生成什么入门材料：
  - `world-primer` — 世界概述（快速建立阅读方向）
  - `volume-entry` — 卷级入口页（依据现行卷内索引补写或优化，不擅自替换索引）
  - `chapter-zero` — "第零章"世界观引导叙事（一个独立短章，通过角色日常引入世界）
  - `reading-guide` — 阅读指南（推荐阅读顺序 + 每卷适合什么读者）
  - `glossary-lite` — 精简术语表（优先列出目标范围内理解正文所需的术语，附一句话解释 + 在哪个场景首次出现）
  - `all` — 全部生成

- `volume`（可选）— 限定到某卷

## 编写前：核对当前阅读路径

通用证据规则、当前状态来源和任务闭环见[操作工作流](../../harness/11_操作工作流.md)。本技能另需核对：

1. 查目标卷现行索引、最新正文和已有入口材料，评估真实阅读路径与读者阻力。
2. canon23 等旧蓝图只供第一阶段主题追溯，不用来推荐全系列顺序或推定卷内章号。
3. 索引未确认顺序或旧稿映射时明确标“待核”，不凭文件名编造正式章序。

## 设计原则（按目标读者与媒介取用）

### 1. 从角色体验出发，不从天而降
永远不写："万构界是一个由四相法则驱动的工程文明世界……"
而是写：一个角色在凌晨两点被回铃惊醒，发现纸上写的退路走不通。

**世界不是被解释出来的，是被角色撞上的。**

### 2. 冰山原则
冰山原则是强调取舍的比喻，不是内容比例指标。入门材料的目标不是让人"理解一切"，而是让人"想继续读"。
问自己：删掉这段信息，读者是否仍然能跟上场景？如果是 → 删除。

### 3. 新概念要在需要时变得可理解
在读者需要理解概念作用时提供足够语境；故障例子有助于解释时再呈现，不要求每个术语首次出现就展示失守。
不是："四蚀是指失式、乱流、背契、断史"
而是："纸上写着能退。他照纸走。到第三步，路断了。这就是背契——纸上的承诺和手里能走的路，是两回事。"

### 4. 控制认知负荷
- 注意概念密度，避免在同一短段落堆叠多个陌生术语；不设统一数量上限
- 在读者需要理解概念作用时提供够用解释；位置和形式由材料体裁决定
- 解释可通过角色体验、例子、图示或简洁说明完成，不强制单一呈现方式

### 5. 创造好奇，不是制造困惑
- 好的：读者问"为什么会这样？" → 想继续读
- 坏的：读者问"这是什么？" → 想去翻术语表
- 解法：先展示后果（有趣），再追溯原因（满足好奇）

中文工程术语遵循 canon15/24：在正文中首次引入时标注准确英文原名；连续语境明确复指可省略，跨章重引或有歧义时再标。入门材料中的解释形式和术语数量按媒介与理解需要决定，不以括注或栏目数量替代可读性判断。

## 各类入门材料的模板

以下模板中的栏目、例句和数量仅供起稿；按读者、媒介和现行索引增删。无法由正文核实的事实标为待核，不为填满模板而补造。

### A. World Primer（世界概述 · 简明示例）

目标：用适合发布媒介的篇幅，帮助读者判断如何进入故事；不设固定阅读时长。

以下为第一阶段四主卷的示例文案。生成其他卷或全系列入口时，应按对应卷索引与正典事实改写，不把该示例当成全系列事实清单。

格式：
```markdown
# 万构界 · 先读这个

> **这个世界不是由魔法驱动的。是由工程文明驱动的。**

- "道"不是修仙门派 → 是**编程语言**
- "器"不是法宝 → 是**软件项目**
- 第一阶段故事涉及 Rust、C++、Python 和 Go 等语言及其工程场景

第一阶段的故事以**式 · 流 · 契 · 史**及其失守形态组织主题。具体事故仍由正文中的工程因果解释，不只归类为抽象病症。

> 👹 最大的反派不是魔王。是一句话：**"先这样，回头再整理。"**

> 🏆 最高的成就不是战力突破。是：**后来者不用你在场，也能沿着路走下去。**

好了。现在你可以进正文了。
```

建议：保持简洁，突出入口信息；篇幅和解释量依发布媒介与读者需求调整。

### B. Volume Entry（卷级入口页）

目标：为读者介绍本卷主题、入口和阅读期待；它不能替代卷内正式 `00_正文索引.md`。章节顺序与稿件类别以现行索引为准。

格式：
```markdown
# XX卷 · 阅读入口

## 这卷关于什么（简短示例；篇幅按媒介调整）
> 一句话概括本卷核心命题。

## 这卷适合你，如果你——
- [一个读者能对号入座的具体情境]
- [可选：其他读者情境]

## 这卷的核心冲突
[简洁概括本卷工程内容及人物处境；篇幅按媒介调整]

## 这卷的主角是谁
[名字]，[职责]。他最怕的不是[表面恐惧]，而是[深层恐惧]。

## 你会学到什么
- [按读者需要选择工程概念；不规定条数]

## 章节导航（可选精选入口；完整顺序与稿件类别必须链接至正式索引）

发布入口页时应提供本卷正式索引链接。根据入口页的实际保存位置计算相对路径；不要把本模板中的路径说明原样留作链接目标。

| 章 | 标题 | 一句话（这章让你看见什么） |
|---|------|--------------------------|
| 序/01 | ... | ... |
```

入口页应链接本卷现行 `00_正文索引.md`，并说明本页是主题介绍或精选阅读建议。不得复制一份可能过期的完整章序来替代正式索引。

### C. Chapter Zero（可选的第零章引导叙事）

目标：一段长度按媒介和任务决定的独立短叙事，通过一个角色的日常场景，自然引入世界观。
**这不替代序章——它放在序章之前或作为附录。它的职责是"让读者在进入正片之前先有方向感"。**

设计约束：
- 用一个具体角色的具体日常开场（不是旁白，不是"在这个世界中……"）
- 主角可以是一个旁观者、一个新人、一个正在经历"第一次事故"的人
- 读者应能在合适位置辨认场景、视角和当前事件；不设固定字数
- 控制陌生概念的集中度；在需要时提供可理解的语境，不设固定术语配额
- 若引导材料要介绍四蚀，应通过恰当例子让读者理解，不强制每种材料都承担此目标
- 结尾可留下问题、情感余韵或清晰入口；按材料功能选择
- 可以引入四个卷的核心命题作为"远处的地标"（暗示但不展开）

可参考的六步叙事示例（按故事目的改写、删减或采用其他结构；“第三步”只是示例，不规定事故必须在某一步失败）：
1. **日常被打断**：一个普通的工程场景，被一个小事故打破
2. **第一次尝试失败**：角色按"纸上写的"去修，走到第三步卡住
3. **老手介入**：一个更有经验的人用"纸上没写"的方法修好了
4. **短暂的松气**：问题暂时解决，围观者散去
5. **一个人没走**：有人留在原地，看着修好的地方，说了一句话
6. **那句话才是真正的开场**：点出这个世界最核心的问题——"今天修好了，明天呢？"

### D. Reading Guide（阅读指南）

目标：帮助不同背景的读者找到最适合的入口。

下方是第一阶段四主卷的示例选项，不要求每份阅读指南保留全部路线。为其他卷或全系列制作指南时，按目标读者从根 README 和各卷现行索引选取入口；不从本例推断完整阅读顺序。

格式：
```markdown
# 万构界 · 阅读指南

## 你是什么类型的读者？

### 🚀 "我想最快感受到这个世界的味道"
→ 读 [驭器卷 第01章](../../../01_驭器卷/第01章_重器不眠.md)
理由：开场呈现一座持续运行的古核及其守护者，迅速建立工具链与继承压力。

### 🏗️ "我想从头了解这个世界的完整逻辑"
→ 从 [驭器卷 第01章](../../../01_驭器卷/第01章_重器不眠.md) 开始，按顺序读
第一阶段示例顺序：驭器→化形→简阵→明契。只在任务面向该阶段时使用；最终导航须从各卷现行 `00_正文索引.md` 和根 README 核对，不声称这是全系列完整顺序。

### 🦴 "我想看最有'古器'厚重感的"
→ 读 [驭器卷 第01章](../../../01_驭器卷/第01章_重器不眠.md)
理由：一座跑了十几年的古核和它不敢退休的守门人——如果这还不能引起你的兴趣，试试化形卷。

### 🔥 "我想看最快乐的工程灾难"
→ 读 [化形卷 第01章](../../../02_化形卷/第01章_这边能跑.md)
理由："我这边能跑"——每个程序员都说过的话，和它留下的脚本沼泽。

### 🟢 "我想看平台工程在规模化中的挣扎"
→ 读 [简阵卷 第01章](../../../03_简阵卷/第01章_扩域.md)
理由：47个已接入服务、23个人与凌晨值守的压力——模板全绿，底下在烧。

### 📚 "我想按顺序读"
→ 按卷内现行 `00_正文索引.md` 与根 README 确认的顺序填写。第一阶段四卷示例：驭器 → 化形 → 简阵 → 明契。
理由：从蛮荒到集大成。每卷可以独立阅读，但按顺序能看到完整的工具链文明演化史。
```

### E. Glossary-Lite（精简术语表 · 按阅读范围）

目标：只列出指定阅读范围内读者需要理解的术语。解释长度与首次出场定位按目标媒介调整；以下是紧凑示例，不设每个术语的固定行数。

格式：
```markdown
| 术语 | 一句话 | 首次出场 |
|------|--------|---------|
| 四相 | 式（结构）· 流（资源）· 契（承诺）· 史（版本） | 第1章（闻衡圈出说明纸上的漏洞时） |
| 背契 | 纸上的承诺和手里能走的路是两回事 | 第1章（回退步骤到第三步走不通） |
| ... | ... | ... |
```

范围：以本次阅读范围和实际理解需要为准；术语数量本身不判定密度是否过高。

## 输出

根据 `target` 参数生成对应的完整 Markdown 文件。

若 `target=all`，生成顺序为：World Primer → Volume Entry（每卷）→ Chapter Zero → Reading Guide → Glossary-Lite。

## Gotchas（常见入门设计错误）

- **信息过载**：入门材料的目标是帮助读者决定如何进入，不是读完就全懂。按媒介检查信息密度，不以固定字数判错。
- **定义式开场**：避免连续抽象定义；定义句、场景或具体意象均可使用，按媒介与读者需要组织。
- **读者门槛**：不要假设读者懂编程；保留准确工程术语，并在理解所需处提供解释或例子。
- **术语表依赖**：若理解正文必须频繁查表，检查正文是否缺少关键语境；不以术语表长度单独判错。
- **第零章变成缩微版正文**：第零章的角色和情节不应和正文章节重复。它是独立的"引桥"——短、具体、有自己的小完整性。
