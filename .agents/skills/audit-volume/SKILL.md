# audit-volume — 整卷审计

按用户指定范围复核一卷或连续章节的已写正文；单章问题使用 `review-chapter`。
**审计六个维度：情节逻辑、术语口径、教学顺序、跨章一致、跨卷合规、节奏与读者旅程。按用户目标与材料情况选取范围；不适用的维度说明原因。**

## 参数

- `volume` — 卷名
- `scope`（可选）— `full`（全卷）| `logic`（仅情节逻辑）| `terms`（仅术语口径）| `teaching`（仅教学顺序）| `cross`（仅跨卷引用）| `pacing`（仅节奏与读者旅程）

## 审计前：核对现行卷内事实

通用证据规则、当前状态来源和任务闭环见[操作工作流](../../harness/11_操作工作流.md)。本技能另需核对：

1. 按目标卷现行正文索引确认范围与稿件类别，阅读索引指向的正文；索引覆盖不足时，结合实时账本、章纲和正文核实，不凭文件名推断顺序。
2. 复核跨卷因果时，以 canon26、相关卷索引和正文为主；canon22 只用于第一阶段历史共享事件，不是全系列事件清单。
3. canon23 等旧蓝图仅供主题追溯，不决定当前卷序、章序或编号映射。
4. 索引、正文和实时账本之间的映射未明时标“待核”，不按旧蓝图补章号、挪动事件或把推测写成事实。

## 审计维度

### 一、情节逻辑连贯性

逐章检查；下面五项是常见锚点示例，按本卷结构和本次范围选用，不要求每卷都具备相同锚点：
- [ ] 若章节依赖此前建立的工程概念，前文是否给出足够铺垫？
- [ ] 人物弧线是否连续？（人物的认知/能力变化是否有跳跃？）
- [ ] 每章的问题是自然从前一章生长出来的，还是生硬切换？
常见锚点示例（按本卷实际结构选择，不要求全部出现）：
  1. 开局事故 — 读者第一眼能否看见病？
  2. 第一转折 — 主角从"补缝"转向"立约"的理由是否成立？
  3. 中段真相 — 是否暴露了体系最脆弱的位置？
  4. 高潮代价 — 主角是否真正放弃了"只有我能修"？
  5. 卷尾继承场景 — 后来者能否不依赖主角独立推进？

### 二、术语口径统一

中文工程术语首次引入时按 canon15/24 标注准确英文原名；连续语境中明确复指可省略，跨章重引、语义变化或可能混淆时重新标注。直接使用英文原词或文学隐喻不强制重复括注。

- [ ] 同一世界观概念在全卷中是否使用一致的名称？
- [ ] 真实工程术语的使用是否准确且一致？
- [ ] 新术语首次出现时是否有足够解释？
- [ ] 有没有用世界观术语替换了应该保留的工程术语？
- [ ] 跨卷人物/机构/事件的称呼是否与 `.agents/canon/` 一致？

### 三、教学顺序审查

第一阶段四主卷可对照 `.agents/canon/20_四卷学习目标_项目目标_思想命题对照表.md`；其他卷先查对应卷设定和现行大纲，不把该表当成八卷统一指标：
- [ ] 本章引入的概念是否匹配该卷的教学目标？
- [ ] 难度曲线是否合理？（不会突然跳跃到高级概念）
- [ ] 对需要读者理解其风险的核心概念，是否呈现了具体失效或误用后果？不要求每个术语都配一段故障。
- [ ] 章末是否留下了可延伸的思考入口（但不强迫读者去读别卷）？

### 四、跨章伏笔与回收

- [ ] 前章埋下的问题/冲突/人物是否在后章得到合理回收？
- [ ] 是否存在"提出了但从未回应"的伏笔？
- [ ] 是否存在"后章突然出现但前章毫无铺垫"的概念或人物？

### 五、跨卷引用合规

逐条检查跨卷引用是否满足四条铁律：
1. [ ] 互文只能增益，不能把另一卷写成本卷成立前提
2. [ ] 共享事件是否按本卷主角的代价和病理重新叙述？
3. [ ] 跨卷概念首次出场时是否在本卷内给出够用解释？
4. [ ] 卷尾接口是否能独立理解，并把跨卷关联作为可选延伸？

### 六、节奏与读者旅程（按任务范围选用）

#### 6.1 全卷张力曲线

如张力节奏是本次审计目标，或抽读发现节奏疑点，再按需标注张力峰值并绘制相关范围的曲线。数字是比较工具，不是质量门：

| 章 | 张力峰值 (1-5) | 峰值事件 | 呼吸点 |
|----|-------------|---------|--------|
| 01 | [1-5] | [什么事件] | [有无] |
| 02 | [1-5] | ... | ... |
| ... | ... | ... | ... |

检查：
- [ ] 张力变化是否服务本卷设计？平缓、循环或其他结构都可成立；观察到长段重复时，再判断它是有意安排还是造成疲劳。
- [ ] 是否有持续低张力或持续高张力而影响阅读的区段？不按固定章数或分值阈值判定。
- [ ] 高潮位置是否服务全卷结构？不预设倒数章节位置。
- [ ] 结尾是否提供符合本卷功能的余韵、行动方向或开放感？
- [ ] 若开篇显得过于紧迫，是否因此妨碍读者定位和理解？结合文本功能判断，不设固定分值。

> **分段尺度提示**：以现行卷内索引定义的章段为统计单元，不预设每段章数或全卷章数。跨段仍持续同一张力模式时，检查它是否有意延宕，还是造成读者疲劳。

#### 6.1 补充：长卷尺度处理建议

全量逐章标注工作量较大。按现行索引的章节分段批次处理：
1. 每段标注最高/最低张力章及段内走向（上升/下降/峰谷交替）。
2. 合并全卷后检查跨段连续模式；段数与每段章数均以当前索引为准。
3. 仅在发现异常时，对相关范围逐章细化标注。
将此原则用于6.2（认知负荷曲线）和6.3（情感弧线），不预设固定段数。

#### 6.2 读者认知负荷曲线

若读者认知负荷属于本次目标或出现理解疑点，可统计相关章节的新术语和工程概念；数量用于定位问题，不设统一配额：

| 章 | 新世界术语 | 新工程概念 | 累计术语负担 | 判定 |
|----|----------|----------|------------|------|
| 01 | [N] | [N] | [N] | ✅/⚠️ |
| ... | ... | ... | ... | ... |

检查：
- [ ] 开篇术语密度是否妨碍读者理解？结合章节长度、解释和目标读者判断，不设统一配额。
- [ ] 工程概念的分布是否影响理解或节奏？集中引入也可能适合本章功能。
- [ ] 以定义为主的章节是否有清晰的叙事或读者用途？只有影响阅读时才建议分散或改写。

#### 6.3 情感弧线

追踪主角/核心人物的情感状态地图：

| 章 | 主角情感状态 | 触发事件 | 变化方向 |
|----|------------|---------|---------|
| 01 | [状态] | [什么] | [→ 什么] |
| ... | ... | ... | ... |

检查：
- [ ] 若本卷设计人物弧线，情感状态变化是否可辨识？平稳或克制不自动等于没有弧线。
- [ ] 若人物弧线需要反复、犹疑或回退，这些变化是否有文本动因？不强制安排倒退。
- [ ] 情感低点的位置是否服务于本卷结构？不强制安排固定的"最黑暗时刻"。
- [ ] 若本卷以人物弧线收束，结尾与开篇的状态是否形成有意义的关系？不要求必须对比。

#### 6.4 入门可及性（全卷视角）

- [ ] 新读者能否在适当位置定位（在哪/谁的视角/发生什么）？不设固定字数。
- [ ] 开篇阶段结束时：读者能否回答"这个世界的核心冲突是什么"？
- [ ] 读者是否能理解与本卷核心冲突相关人物的处境和动机？不要求固定人物数量或恐惧表达。
- [ ] 是否有章节必须依赖术语表才能理解？如有，核查正文是否缺少必要语境。

### 七、各卷特有审计

> 本节列出第一阶段四卷的候选关注点，不是每卷的固定验收项。只有现行索引、正文或实时账本支持某条情节/锚点仍适用时才核查；蓝图、命题或人物解释不能单独证明事件已发生。具体位置以现行索引和正文为准。

#### 驭器卷（C++·玄枢）
- [ ] 玄枢的古器属性是否始终可感（不只是设定，而是场景中的重量）？
- [ ] 守门者的"不敢退休"是否始终有具体的工程原因（而非情绪渲染）？
- [ ] 继承者的成长线是否贯穿全卷（陆踏痕从空白记录本到值守日志）？
- [ ] **六维工具链演化**：构建/版本管理/静态分析/调试/测试/文档的每次进化是否由痛苦事件驱动？
- [ ] **考古层**：被时代抛弃的工具（autotools/lint/RCS/CppUnit/Purify）是否作为"文明化石"呈现而非"落后技术"？
- [ ] **史约相关线索（如适用）**：残码、修补者关系等内容的来源与证据等级是否在正文及 canon26 中有依据？未确认的身份、来源或映射保持待核。
- [ ] **入侵事件**：青炉诊断报告与 runbook 的跨卷回声是否符合当前因果账本和本卷正文？

#### 化形卷（Python·息壤）
- [ ] 息壤的"沼泽"是否在每个阶段都有不同的具体表现？
- [ ] "快"的价值是否得到了公正呈现（不只是批判速度）？
- [ ] 三层分治的出现是否有足够的铺垫？
- [ ] **包管理演化弧线**：pip→venv→requirements.txt→poetry→uv 的每一步是否由复现性痛苦驱动？
- [ ] **uv处理**：是否作为"暂时最好的归宿"而非终极方案呈现？
- [ ] 类型系统渐进演化（动态→Type Hints→mypy→Pydantic）是否自然融入剧情？
- [ ] **史约锚点**：相似记录缺口、不同停步原因与失传者谱系是否按当前索引和因果账本落位；未证实的同源关系保持未证实。
- [ ] **入侵事件**：runbook 与驿河相关的跨卷回声是否在本卷有独立因果和代价？
- [ ] **跨卷对话**：傅远洲与周栖野关于制度与空白的对话是否有本卷铺垫？
- [ ] **核心放弃**：放弃“速度自足”的情感准备是否充分？位置按现行索引核对。

#### 简阵卷（Go·驿河）
- [ ] 驿河的扩域压力是否逐章递增？
- [ ] 每个服务的接入/故障/修复是否都有可追溯的工程逻辑？
- [ ] "平台"从个人英雄到制度的转变是否自然？
- [ ] **并发模型演化**：goroutine→channel→goroutine泄漏→structured concurrency 的每一步是否合理？
- [ ] **可观测性**：从"绿色=活着"到"三视图"的演化是否痛苦驱动？
- [ ] **简洁哲学边界**：43项模板→4项+判断声明的过程是否展示了约定vs制度的张力？
- [ ] **史约相关线索（如适用）**：分别核对远古告警、温故来 512MB 和修补者谱系的正文来源与证据等级；未确认的谱系仍标假说/待核，不与已核实细节混作同一确定性。
- [ ] **入侵事件**：化形模块 OOM 的跨卷回声是否在本卷有独立因果和代价？
- [ ] **成阵/共约（仅在现行材料确认时）**：相关人物会合、选择及其后果是否有独立因果与情感铺垫？不预设四人汇合或史约诞生为既定事件。
- [ ] **阶段承接（如已写且有确认映射）**：本卷与后续材料的关系是否符合 canon26；待确认的呼应按假说或待核记录。

#### 明契卷（Rust·青炉）
- [ ] 青炉起炉的动机是否在每个阶段都有足够的工程理由？
- [ ] Rust 特性（所有权、trait、unsafe 等）是否作为"对问题的回答"而非"语法展示"出现？
- [ ] 若现行章纲或正文将“拥有工具仍须判断”设为沈见微的主题，是否由其选择和后果呈现，而非由审计者预设结论？
- [ ] Cargo、borrow checker、trait 与其他卷工程做法之间的对照，只有在正文或 canon26 确认相应映射时才核验；相似功能不自动构成跨卷来源。
- [ ] 每一章是否都能独立阅读（不假设读者读过前面三卷）？
- [ ] **史约相关线索（如适用）**：旧注释、梁故川资料和相关回声分别有哪些正文证据？未证同源、身份或动机保留为假说。
- [ ] **跨卷事故（若当前正文确认）**：诊断报告与玄枢受影响之间的因果是否由可核对的版本、传递和行动链支撑？
- [ ] 若人物选择涉及“写清楚”与其边界，是否由本卷具体处境和后果支撑；不预设人物必须放弃某条命题。
- [ ] 若出现被归于修补者的文字，作者、年代、来源和身份是否有正文证据？未确认时不称为终言或定稿事实。

## Gotchas

- **节奏盲区**：审计时只看逻辑连贯性，不看节奏曲线。长卷如果每章都是"问题→分析→解决→总结"的同一节奏，逻辑上无误但读者很快会走神；按现行索引定义的分段检查变化。
- **入门可及性**：兼顾熟悉系列的读者与第一次进入本卷的读者；核心情节不能依赖读过前卷才能理解。
- **情感弧线检查**：若本卷以人物变化为重点，检查克制或稳定的情绪是否仍通过选择、关系和代价形成变化；不要求每个人物都出现显著情绪起伏。
