# 化形卷 · 第104章 · Docker / PEX

尽管有onboarding文档，首次使用者仍需要配置Python、uv、系统依赖。季晚禾当初如果在Docker里跑——不需要花三个时辰排查为什么她机器上跑不通。

周栖野为`field-mapper`写了Dockerfile。`FROM python:3.11-slim`，安装依赖、复制代码、定义入口。Dockerfile把环境构建步骤写成可执行声明，比README更明确；要稳定复现，还得锁定基础镜像和依赖版本。"Dockerfile不只说你需要Python 3.11——它还写下了构建环境和安装依赖的步骤。不是一张清单——是可以执行的配方。"

季晚禾测试Docker版本。`docker run`——第一次就跑通了。项目所需的Python和依赖不再取决于她本机装了什么；运行仍以可用的Docker环境和镜像为前提。

另一边，周栖野把轻量的`csv-validator`打成`csv-validator.pex`。季晚禾在装有兼容Python 3.11的环境里执行`./csv-validator.pex input.csv`，同一份输入得到同一份校验结果。PEX把应用和依赖收进一个文件，却没有把Python解释器也一并带走；运行前仍要确认机器上的解释器版本符合声明。她把这条前提写进交付说明，没有把“单文件”说成“零环境”。

Docker让后来者不必在本机重建项目环境，但仍需Docker运行环境；PEX则让已有兼容解释器的人可以直接运行单文件。两种交付都把原本隐在作者机器里的部分前提显出来，也把各自尚未覆盖的边界留在说明里。入口的最后一公里——交付形式本身就是入口。
