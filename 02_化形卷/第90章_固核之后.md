# 化形卷 · 第90章 · 固核之后

事故资源记录附进部署复核单后，周栖野回到固核审查总表前。二十一块模块都完成了复现性审查：十四块在记录的环境中完全复现，七块仍待补充前提声明。CI、lint 与属性测试已经进入日常；跨域资源声明也被写进部署检查。审查完成了，表上的空白却没有因此消失。

“固核之后——不是所有模块都稳定了。”他在记录板上写道，“是我们终于知道哪些稳定，哪些还缺条件。精准的已知，比模糊的自信安全。”

他另开一栏，标题是**已知的未知**。

长期运行时，内存峰值会如何变化——尚未验证。  
Python 3.13 下的兼容性——尚未验证。  
并发测试已经覆盖到一百；一千并发下会怎样——尚未验证。

这几行没有给系统添上新的能力，也没有替未来的问题找到答案。它们只把“也许没问题”从承诺里拿开，改成后来者能看见、能重新检查的空白。

驿河的事故让周栖野知道，默认值会离开它原来的世界；现在他也知道，语境声明不能保证自己已经列尽所有语境。最危险的仍是那些他还不知道自己不知道的部分。固核之后，不是得到一张完整地图，而是知道哪些边界已验证，哪些还没有；再把没有走过的地方，标给下一位来者。

他在页脚写下：“这些项目不是风险清单的终点。若负载、运行时或部署方式改变，请重新验证；若出现新的未知，把它添在这里。”

固核审查至此告一段落。明天，息壤仍要继续运行；那些尚未验证的条件，也仍要由后来者接着看。
