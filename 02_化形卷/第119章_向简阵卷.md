# 化形卷 · 第119章 · 向简阵卷

顾迁舟把跨卷交接包放在桌上时，里面不是一份“可直接部署”的承诺，而是三项跨卷修订或重写的模块、一份 `csv-validator.pex` 单文件复现制品、对应的验证记录，以及一张没有填满的接收清单。

`seasonal-settlement-validator`曾在驿河的长期共享资源池里，因实际负载超过512MB默认配置所表达的资源预算而触发OOM。周栖野把全量载入改成分批处理，并将批次边界和内存观测写进 MRC；这能说明息壤侧完成了修复与复测，不能替驿河证明它在十一集群全量负载下安全。`field-mapper`升级到 1.3.0，带着版本化契约、锁定依赖和 Docker 构建步骤。`auto_field_mapper`则保留为林过川火种的重写版：核心映射逻辑还在，环境、测试和入口已经换成后来者能复现的形式。

包里还附着 `csv-validator.pex` 及其干净环境复现记录：它把应用和依赖打成单文件，但运行方仍须提供兼容的 Python 3.11 解释器。三层治理图、桥账和红色标签规则也一并收录。每份材料都写清验证发生在哪里。驿河的负载评估、长期运行、工具链适配以及接收方签字，仍在待办栏里。

“你把‘已经修好’和‘对方可以上线’分成两栏了。”周栖野检查清单。

“不分开，就会把我们的复测说成他们的保证。”顾迁舟把那张表推给他，“桥账也要带去。接口能不能接，不能只看代码；还得知道谁依赖、如何回退、什么条件下要停。”

周栖野在交接页写下：“息壤侧已复测；驿河侧待验证。”他没有替傅远洲签收，也没有把空栏涂成绿色。若接收方的负载超出声明范围，三项模块都必须先重新评估；若检查失败，交接就停在失败的那一步，不能靠“曾经在息壤跑过”继续推进。

顾迁舟收起桥账和两份模块材料，准备先去驿河。他带去的不是一套要求别人照抄的制度，而是息壤走过的事故、修复、边界和复核方法。周栖野把红色标签贴在包外：“让他们先看前提，再决定要不要接。”

这一次，门是开着的；门槛也被写了下来。顾迁舟跨过去之前，先把尚未验证的地方一一指出。那是息壤能给出的帮助，也是它不能替另一个世界做出的决定。
