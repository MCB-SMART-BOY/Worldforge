# 化形卷 · 第59章 · 保留为证据

周栖野把回信复印件放到桌上时，公共记录板前已经围了几个人。季晚禾标记过的那份 runbook 复印件先前就贴在那里；今天，他要把它的来处、对照和回应补齐。

桌面上摊着三样东西：纪承钧寄来的十七步迁移 runbook，季晚禾逐步执行后留下的标记，以及顾迁舟做的前提对照表。纸边被翻软了。季晚禾的红笔圈过十一个“待确认”，每个旁边都留着她试过什么、卡在哪里。顾迁舟的表格把十七步拆成四列：步骤、玄枢的前提、息壤有没有对应系统、没有时要付出的代价。

“你要把它们全贴上去？”顾迁舟问。

“原文、标记、对照表，还有我的回信。”周栖野把胶带剪成短段，“一个都不挑。成功的两步和卡住的十一步都留着。”

顾迁舟看向那份 runbook：“有人会把它当成息壤的操作指南。”

这正是周栖野停下来的地方。他抽出一张空白纸，先写下标题：**跨域流程采用前，先核对前提。**随后在下面补上说明：这份十七步流程建立在玄枢的依赖注册表、统一构建验证和渡桥司审批之上；息壤没有这些对应系统。季晚禾标出的十一个“待确认”，记录的是流程在息壤的实际执行结果，不是可以照抄的本地步骤。

“如果只贴流程，后来的人会从第三步再撞一次。”他说，“如果把失败原因也贴出来，他们至少知道先问什么。”

季晚禾站在记录板另一侧，仍捏着那支红笔。她认真执行过每一步，能确认的就确认，不能确认的才标出来。那十一个圈并不是她做不下去的证明；可公开它们，别人也会看见息壤缺少依赖登记、统一验证和明确审批人的事实。她把笔帽按紧，递给周栖野：“把我的备注也贴上。别替我把‘不知道’改成‘未完成’。”

“好。”周栖野答应。

他们没有取下季晚禾的标记页，而是以它为中心，把原始流程、前提对照表和周栖野的回信补在旁边。周栖野没有把十一个圈涂成统一的红块，而是让每一条旁边的手写说明都露出来。顾迁舟补上第三步的成本：息壤没有依赖注册表，只能人工查找 import 关系，每座桥约两到三个时辰；第八步没有统一构建系统，只能逐台验证，无法扩展；第十一步没有渡桥司，当前由他一人承担协调。

有人读完后问：“所以这套 runbook 是错的？”

“在玄枢，它是完整流程。”周栖野说，“在息壤，它不能直接执行。我们保留它，不是要证明写它的人错了，是让后来者看到它成立的条件，也看到条件缺席时会发生什么。”

他把最后一条胶带按实。记录板没有因此变成一套依赖管理系统，也没有替季晚禾补上那些缺失的确认。它只留下了一段可以复查的经过：谁寄来了什么，息壤按什么方式执行，哪些前提不存在，以及执行者为此留下的痕迹。

季晚禾退后一步，检查那十一个标记有没有被遮住。“这样可以。下一个人不用猜我当时为什么停在这里。”

周栖野将空白处留给后续的回应，没有把这面板子称作解决方案。它首先是一份教材：跨域知识要先声明前提；失败也要保留具体证据。之后，顾迁舟还得回到桥账，把退场中的桥一条条处理完。
