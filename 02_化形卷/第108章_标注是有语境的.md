# 化形卷 · 第108章 · 标注是有语境的

周栖野打开 `seasonal-settlement-validator` 的 MRC，找到那句“默认配置即可”，用笔划掉了“默认”。

它在息壤按小批量工作：季晚禾手动逐个集群处理，通常占用约 200MB；测试中内存从未超过 500MB。512MB并不是周栖野设定或验证出的上限，而是驿河接入表沿用的平台模板默认预算。他当时没有把息壤的测试条件和目标环境的资源预算对齐，也没有追问这个默认值的依据。驿河把模块作为长期服务放进共享资源池后，季度全量批次一次加载十一个集群的数据，内存需求升到 2.3GB，进程被杀，三条结算管道同时超时。

宋既明读完这段记录：“如果我们只写‘内存上限512MB’，它会被看成对所有环境的保证。”

“那就要写清楚这个数字在哪种场景下成立。”周栖野把空白页转向他，“不是出了事以后加一句‘仅供参考’。是把我们实际验证过的范围摆在承诺前面。”

他们没有先改声明，再把原来的代码原样交出去。周栖野把一次载入十一个集群的逻辑拆成按批读取：每批处理完成后释放中间结果，再进入下一批。季晚禾用息壤已有的单集群样本跑回归与边界测试，宋既明把这次复测的运行方式和观察到的资源范围写进 MRC。改动让全量数据不必同时驻留内存，但测试并未覆盖驿河的长期运行、共享资源竞争或十一集群整批负载；他们没有把一次修复写成任何环境都安全的证明。

他先写下模板：

> **语境声明：**以下内容基于息壤的典型使用场景。已验证条件：[场景、数据规模、运行方式]。已知边界：[未验证的负载、平台或运行时长]。若部署条件超出这些范围，请在目标环境重新评估相关承诺。

接着，他把事故前提填进去：息壤的记录来自人工、单集群批量处理；通常约 200MB，既有测试未超过 500MB。长期运行、共享资源池和十一集群全量处理并未在息壤验证。默认 512MB 不能当作跨环境的安全保证。跨到驿河之后，十一集群全量加载的内存需求达到 2.3GB，超过原有配置所预估的资源范围，三条管道超时——这组记录说明了原有标注的边界，也没有把一次事故伪装成所有未来部署的容量结论。

周栖野把这一段放到 MRC 最上方，又给 API 契约和入职文档加了相同的声明栏。不是每一份都填同一组数字；每份文档必须写自己的适用场景、已知限制和未验证项。宋既明在模板旁标出“已知边界”，提醒编写者不能把空白误填成保证。

“这不就是免责声明？”一位审阅者问。

“不是。”周栖野说，“免责声明是出了事以后说不归我管。语境声明是先说：在这些条件下，我做过这些验证；超出去的部分，我不知道。你可以据此决定要不要用，也可以在自己的环境重新测。”

他没有把模板伪装成新的性能标准，也没有写“所有环境安全”。这意味着每次跨域交付都得多做一轮确认；有些模块会因此暂时不能进入长期服务。周栖野把待验证的边界留在文档里，接受进度慢下来，也不再让“默认”替团队承诺他们没有测过的东西。

季晚禾读完那一页，指向手动逐集群的条件：“如果我以后不是这样跑，也要重评。”

“对。复现性也有语境。”宋既明说，“在息壤复现，不代表在驿河成立。”

周栖野把模板贴到公共记录板上。红色标签仍允许跨域引用，但每一次引用都要带上出处与成立条件；语境之外，接收者有权重新判断。下一步，他们要把这种“知道自己何时不在”的边界，也写进人员离开时的交接流程。
