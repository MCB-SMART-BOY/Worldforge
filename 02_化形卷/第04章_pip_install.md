# 化形卷 · 第04章 · pip install

季晚禾把石镜转向周栖野时，屏幕上不是一条报错，而是一串互相矛盾的版本提示。

“昨天我按你写的步骤装了 pandas。今天另一个脚本说版本太新，旧脚本又说找不到新接口。到底该听哪一个？”

周栖野先看了看她的命令记录：`pip install pandas`。他自己也常这么做。输入命令，包管理器替他找一个可用版本，问题便像是解决了。可这条命令没写版本，也没说明装进了哪个项目环境。两个人在各自的石镜上重复同一句话，得到的未必是同一套东西。

“我给你固定一个版本。”他伸手要拿她的石镜。

“固定在你的机器上，还是我的机器上？”季晚禾没有松手。

周栖野停住了。她不是在拒绝帮忙。她是在问，为什么一个项目的依赖要靠作者亲自到场才能说清。

宋既明从长案另一端走过来，听完后问：“你们的Python解释器和已安装的包，分别是什么？”两个人都答不完整。周栖野知道自己最近装过什么，却说不清那些包是不是给这一个脚本装的；季晚禾只知道她敲过安装命令。

宋既明在纸上画了两个方框。“全局安装就像把所有项目放进同一间仓库。一个项目升级了包，另一个项目也可能跟着受影响。先把这个项目隔开，再谈它要用什么。”

周栖野照着步骤创建了一个虚拟环境（virtual environment / venv）：`python -m venv .venv`。激活之后，提示符前多出环境名。他在里面安装脚本需要的包，并把此次确认能运行的pandas版本号写进一张临时清单。这只是复现当前样本的救急记录，不是长期锁定方案。步骤比他平常多了几行，每一步都得确认自己正在操作哪个环境。

季晚禾按同样的步骤，在自己的目录里重新建了一遍。她运行脚本，输出终于与样本一致。她没有笑，只把清单里“如何启动环境”那一行圈了起来：“下次如果换一台机器，这张纸还得能带我走到这里。”

“能。”周栖野说。他这次没有马上把石镜拿回来，等她从头独立走完一遍，才把结果记下来。

他们解决的是这一次安装，却没有解决依赖清单会不会过时、清单里的包是否真的都需要。宋既明把那张纸夹进文件夹：“隔离让起点可见。它不替你解释每个包为什么在这里。”

周栖野看着 `.venv` 这个新目录。过去，他把“能运行”当成起点。现在起点前多了一道门，但门后要带什么，还没有人说得清。

离开试法场前，季晚禾自己又走了一遍流程：确认目录、激活环境、按清单安装、运行固定样本。她刻意在步骤中间关掉终端，再重新打开，检查是否还记得如何回到项目环境。第一次她找错了目录，第二次才顺着记录找回来。周栖野想替她把步骤缩短，季晚禾却说先留着：“我宁愿多看两行，也不想下次把包装到另一个地方。”

他们没有把这份清单称作最终依赖声明。它既没覆盖所有旧脚本，也没说明每个间接依赖为何存在。它只把这一次成功的环境变得可重建一些。周栖野把“可重建一些”写在纸边，第一次接受一个工程动作可以改善入口，却不能一次消灭所有未知。
