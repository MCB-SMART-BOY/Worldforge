# 化形卷 · 第06章附 · 三层图，给息壤画第一张全景依赖地图

二十张试验纸的排查结果出来以后，试法场安静了整整一个上午。

不是因为震惊——是因为每个人都在想同一件事：二十张就翻了整整一天。息壤的共享目录里有几千张。如果每一张都需要两个人、一台石镜、三个时辰去手工核对，那这项工作本身就不可能在任何人退休之前完成。

叶藏拙是第一个打破沉默的人。他把自己那本记录本翻到空白页，在最上面画了三条平行的横线。

"我一直在想一个问题。"他说，"你们排查那二十张的时候，每一张都在追三样东西：它的数据源还在不在、它引的依赖还是不是那个版本、它的输出和当前真实数据差多少。你们实际上已经画了一张图——只是没把它画在纸上。"

他把三条横线标上名字。

第一条线：`数据源层`——外部数据、API、数据库连接、文件路径。

第二条线：`脚本与模块层`——试验纸、共享脚本、data_utils 这种内部依赖。

第三条线：`汇报与输出层`——汇报图表、结算结果、管理层看到的数字。

"每一张试验纸都同时穿过这三层。"叶藏拙说，"但以前我们只在第三层看见它——看见它吐出的那张图、那组数字。前面两层是什么、在哪、还在不在——从来没有人画成全图。"

· · ·

白又新把二十张排查记录摊开。每一张都有标注——数据源状态、依赖版本、输出一致性。他发现这些标注天然地属于叶藏拙那三条线的某一层。有些标的只在第一层——数据源失效。有些在三层都有问题——依赖版本冲突，输出跟着偏差。

"如果我们把排查结果填进这三层里，"他说，"至少能先看见——哪些线已经被摸过了，哪些还从来没人碰过。"

"那就画。"周栖野从他自己的石镜前站起来，把一张空白大纸铺在试法场的长墙上。

他在这张纸最上面写了一行：`息壤全景依赖图（首稿）——三层。`

"首稿。"岑照渠重复了这两个字，"你知道这意味着什么？"

"意味着它不是完整的。"周栖野说，"但林过川就是死在'等完整'上。我们先画不全的。不全比不画有用。"

· · ·

他们从被引用最多的五十张试验纸开始。

季晚禾负责第一层——数据源。她把五十张纸里引用的所有外部数据源都列了出来。四十二个名字。其中八个已经停用。六个路径已变更。三个指向的外部 API 需要密钥——密钥在某个已经调走的人名下。她在每一个旁边标注了当前状态、变更日期、和替代方案——如果有的话。

白又新负责第二层——脚本与模块依赖。他的方法和在驭器卷里看过的陆踏痕建石录索引几乎一模一样：每一张纸引了哪些内部脚本、哪些共享模块、哪个版本的 data_utils。他用三种颜色标注——绿的是已验证版本一致，黄的是存在多个版本需要确认，红的是依赖已经不存在或无法确定版本。写到第十三张的时候他停了——`pipeline_runner_v3.py` 引了一个叫 `old_data_pipeline_legacy_final` 的目录。这正是他第一天来息壤时找到三个版本、输出各不相同的那个目录。

"这一条，"他把这行标成粗红，"它从来没有被验证过。它的输出被七个流程引用。没有一个人知道哪个版本是对的。"

他把这条单独抄出来，贴在第二层的红区。

唐野渡负责第三层——汇报输出。他做了一件之前从来没有人做过的事：把每一张纸的输出和当前手工核对的数据放在一起比较。差多少。差在哪。是浮点精度还是逻辑变更。他在第三层图上标注了偏差类型和偏差度。然后他发现了一件比他预想更严重的事——有七张纸的输出被管理层报表直接引用，而这七张里有四张的输出已经和当前数据不一致。

"管理层看到的所有报表，有四成底层是过期的。"他说。

试法场里安静了一瞬。

然后岑照渠说了一句只有她会说的话："所以问题不在管理层信了什么。问题在他们信的东西——从来没有一条线能让他们自己追回到第一层去看数据源还在不在。"

· · ·

子夜。全景依赖图的第一稿贴满了长墙。

三层。五十张试验纸。每一张都有一条线从第一层穿过第二层到达第三层。有些线是绿色的——完整的、可追溯的、仍在被验证的。有些线是黄色的——存在疑问但暂时可用。有些线是红色的——断了。数据源丢了。依赖版本对不上。输出和真实数据不一致。没有人在中间标注过"请勿从此往下引用"。

白又新站在图前面，从头看到尾。

"这不是一张图。"他说，"这是息壤有史以来第一张病理解剖报告。"

"五十张里有多少红线？"宋既明问。

"十一张。不算最多。但它们被其他纸引用——下游超过七十张间接依赖它们。我们排查的五十张只是入口。再往下——"

"再往下没人知道。"

"对。"

宋既明走到图前面。他看的是那些绿线——那些完整的、可追溯的、从头到尾都有人标注的线。它们比红线少得多。

"这些绿线，每一根都是一个人在某一天多写了几行声明。"他说，"不是系统。是人在补。"

"那我们能不能——"季晚禾开口。

"能不能什么？"

"能不能让它不再只靠人补。"

周栖野看着她。

"第一层数据源——能不能让试验纸在运行时自动检查数据源最后更新时间，超过一定时间自动弹出提醒？"

"能。"

"第二层依赖——能不能让每次跑的时候自动比对当前依赖版本和纸里声明的版本，不一致就标黄？"

"能。"

"第三层输出——能不能在每次产出汇报数字的时候，附一行'本数字基于以下数据源生成，最后验证于某日'？"

"能。"

季晚禾停了下来。不是因为问完了——是因为她忽然意识到这三件事都不是新技术。每一件在别的系统里都有。只是化形之道从来没有把"能跑"之后的"跑的是对的吗"当成必须回答的问题。

"这三件事加在一起，"叶藏拙说，"就是把三层图从一张一次性考古报告，变成一个活着的检查系统。"

"那需要多久？"唐野渡问。

周栖野没有给工期。他只是拿起石笔，在那张全景依赖图的最下面加了一行：

`首稿。五十张。绿线：已验证。黄线：待确认。红线：已断裂——请勿继续向下游引用。`

然后他在旁边又写了一行更小的字：

`下一版：每一张新试验纸在第一次被放入共享目录时，自动标注它在三层图上的位置。`

写完以后他站在图前，忽然想起林过川。

如果林过川当年有这张图——哪怕只是五十张的首稿——他是不是就不用一个人跑遍共享目录去猜哪一张的 data_utils 是对的？他留在 README 里的"对不起"，是不是就不至于那么重？

周栖野不知道。但他知道一件事。

> 三层图不会让沼泽一夜干涸。但它会让后来者第一次看见——自己脚下踩的是实地，还是别人留下的、正在缓慢下沉的残骸。
