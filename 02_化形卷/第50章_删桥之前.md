# 化形卷 · 第50章 · 删桥之前

桥账初步整理完成后，顾迁舟选出一条看起来已满足退场条件的桥：`xirang-old-api-shim`。桥账上目前只登记了一名使用者；新 API 已经建成，按现有记录，这似乎是最容易处理的一条。

“我们不能只照着账本上的一个名字发通知。”周栖野说，“先公告，再确认有没有没登记的人。”

顾迁舟在公共记录板贴出弃用声明：旧 API shim 计划在三个月后退场，请使用者回复依赖情况，迁移步骤将在依赖核对后发出。两个时辰后，群聊里出现了五名使用者的回复。前四名都在顾迁舟预料之中；第五名从未登记过，也不知道自己依赖的是一条临时桥。

“桥账上不是只有我一个人吗？”顾迁舟重新打开原来的清单。第五名使用者贴出自己的脚本路径，却说不出完整依赖链。于是他们没有照日期直接推进，而是先检查 import 关系和运行时记录。

检查结果把已知使用者从一名扩展到七名：除了公开回复的五人，还有两处脚本调用没有对应的登记记录。此时还不能证明清单覆盖了所有调用方；七人只是目前找到的使用者。顾迁舟把名单标作“待逐一确认”，按七人的现有调用编写迁移步骤，保留三个月窗口，并要求每名使用者独立验证新接口。

周栖野看着公告和更新后的桥账。“我们以为退场条件已经满足，是因为清单只记录了我们知道的人。现在先把他们找全，再谈拆桥。”

这不是退场已经开始，而是第一次按流程做退场准备。下一步是通知每名已知使用者、给他们可执行的迁移路径，并在窗口到期后重新核验。桥账上的七个名字仍可能增加；在没有更多证据前，顾迁舟没有把“七”写成最终总数。
