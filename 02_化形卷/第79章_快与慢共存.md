# 化形卷 · 第79章 · 快与慢共存

休眠标记试行后的第一场讨论，周栖野没有带来新的归档清单。他在记录板上画了三行，写下三个目录：`lab`、`core`、`gate`。

唐野渡靠在桌边：“又要给速度立规矩？”

“先把现在的规矩说清楚。”周栖野在三行旁各留出两格，写上“速度”和“稳定”。“不是每一层都该用同一个标准。”

他给试法层写下速度10、稳定0；固核层写速度5、稳定8；入世层写速度2、稳定10。数字不是测量结果，只是他们讨论时用的刻度：越往外，依赖者越多，变更就越需要提前说明和验证。

“lab 是越快越好，”周栖野说，“可以试错，可以改接口，可以把实验停掉。但被外部引用时，要标明它是实验，不能让人误以为有稳定承诺。”

唐野渡看着第一个10：“那我在 lab 写的东西，不必先补到 core 的标准？”

“不必。你可以先让它跑起来。”

“出了问题呢？”

“留在 lab 的问题，就按实验处理。要进 core，才补 MRC、类型和测试，经过审核。进 gate 以后，调用方需要版本和兼容承诺，变更也要有迁移时间。”

宋既明伸手把“速度2、稳定10”那一格框起来：“gate 慢，不是因为写代码的人不够快。外面的人已经把它接进流程里。我们得给他们可预测的变化。”

季晚禾拿起那张图，沿着 gate 一行读了一遍。年底结算会依赖 `field-mapper`。对她来说，最重要的不是它能不能今天就多一个字段，而是已有字段到了约定版本还能不能用。她把图放回板上：“我愿意等一个变更窗口。我不想每次月底都先问接口有没有变。”

唐野渡没回应。他的速度曾让所有人追着他的提交跑；现在这张图把速度快慢写成了层的责任，也把一部分选择从他手里拿走。周栖野看见他盯着 lab 的那行，便把那格旁边的“标记实验”圈了出来。

“所以快不是被收走了？”唐野渡问。

“快留在它最有用的地方。”周栖野说，“lab 让尝试更快；core 让别人依赖时更稳；gate 让外部调用可预测。三层不是给所有人排一条速度名次，是让不同需求有各自的位置。”

唐野渡终于把椅子拉开，走到板前。他没有擦掉数字，只在 lab 的速度栏下写：“允许快速试验；标清实验状态。”然后在 core 和 gate 两栏旁写下“按晋升标准”和“按契约变更”。

“lab 是给我的快试空间，对吗？”

“是。core 和 gate 的规则由它们的依赖者一起守。”

“那我接受。”唐野渡说，“但别拿 gate 的速度去要求 lab。每次有人引用实验结果，也得告诉他那还是实验。”

周栖野把这句话抄进图的标题下。唐野渡没有被说服去变慢；他得到了一块可以继续快的地方，也承担起给实验标明边界的责任。季晚禾将图拍下来，准备在下一次结算前查版本和兼容承诺。

记录板上第一次同时出现三种速度期待。它们没有互相消灭：试法层保留试错的快，固核层用审核换取稳定，入世层以慢而可预测的变化履行契约。下一步，周栖野要确认这套分层本身有没有漏掉它没预见的情况。
