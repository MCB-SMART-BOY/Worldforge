# 化形卷 · 第06章 · 灵火高奖赏

季晚禾来时，没有带需求单。她把一份月度结算记录放到周栖野面前，指着最后一列：“这次我没有从头手工映射。按你那份脚本先跑，再核对异常项，原来要花一整天的活，半个时辰就收住了。”

“少掉的是重复劳动。”周栖野说。

“也是我能拿去查别的问题的时间。”她没有夸他，只把结果表交给他看。数字与她的手工抽样一致。周栖野盯着那几行，胸口升起熟悉的轻快：一个模糊的问题，被脚本变成了能看、能检查、能继续行动的东西。

消息很快传开。有人把新的表格拿来，有人问那段映射能不能接到另一个数据流程里。周栖野把共享目录的脚本数了一遍，发现自己并不确定哪些还在被使用。每次有人说“再加一个小功能”，他都能很快交出结果；每次交付之后，目录里就多一个名字，或者旧名字下面多一条新的调用路径。

白又新拿着一份 README 坐到他桌边。那是周栖野在季晚禾重建环境后，把临时清单整理成的说明，只覆盖已经验证过的月结样本。“我想按这里跑。”白又新先建了环境，照着文档安装 pandas，再打开脚本。跑到第三步时，输出与示例不同。

“文档说安装 pandas，没写版本。”白又新说，“我装的是当前能找到的版本。这里该继续，还是停下来？”

周栖野扫了一眼，几乎要直接接过石镜替他跑。那样最快。他已经看到可能的问题在哪里，只要改一行，白又新就能继续。

他伸出的手停在半空。

“你先别照我的环境改。”他说，“把你运行的命令和完整输出留下来。我跟你一起看差异。”

他们逐行对照。最终发现旧脚本依赖的一个接口已经变化。周栖野修了调用，让样本通过，但白又新并没有因此掌握所有前提。他把这次差异写进 README，列明刚才验证的环境和结果。

“现在我知道这一份为什么能跑了。”白又新说，“但不知道别的脚本是不是也一样。”

那天傍晚，周栖野把新修好的脚本放回共享目录。季晚禾省下的一天是真实的，白又新的卡顿也是真实的。灵火既照亮工作，也让更多人把事情带来这里。

谢催成经过时看见石镜上排开的需求，笑了一下：“大家都开始找你了。说明这条路走对了。”

周栖野也笑了。他想起叶藏拙那本账册，却没有把它拿出来。他还没找到能同时保住速度和这些新使用者的办法。

周栖野开始把求助的人按事情写在一张纸上：谁要过什么数据，哪个脚本被调用，结果是否回查过。写了半日，纸上仍有几处空白。有人只留下文件名，有人说是“同事发来的”，没人记得最初的作者。

他把纸钉在共享目录旁边，标题写“已知使用情况”。这个名字不够响亮，也没有把所有依赖都数出来，但至少提醒下一位：目录里的东西并不是放在那里就自动变成了公共设施。周栖野本想继续把所有脚本都补上说明，谢催成又递来一张急单。他把纸留在墙上，转身去处理新问题。
