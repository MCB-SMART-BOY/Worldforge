> 一个在写的小说系列。关于编程语言、工程文明、和"后来者还有没有路可走"。

---

## 👁️ 先读这个（30秒）

> **这个世界不是由魔法驱动的。是由工程文明驱动的。**

- "道"不是修仙门派 → 是**编程语言**
- "器"不是法宝 → 是**软件项目**
- 这里的人用 **C++** 守古核、用 **Python** 点火试法、用 **Go** 管服务阵、用 **Rust** 写契约

这个世界有四条法则——**式（structure）· 流（runtime）· 契（contract）· 史（history）**。每条崩了，长成一种病——**失式 · 乱流 · 背契 · 断史**。

> 🦠 故事里所有的大事故，追到底都是这四种病在发作。

> 👹 最大的反派不是魔王。是一句话：**"先这样，回头再整理。"**

> 🏆 最高的成就不是战力突破。是：**后来者不用你在场，也能沿着路走下去。**

## 📚 这是什么

**把 C++ / Python / Go / Rust 写成四卷奇幻小说。每卷120章（12卷×10章），共480章。**

不是"教程换皮"。每个世界有自己的道、自己的病理、自己的人物、自己的工程演化弧线。

| # | 卷 | 语言 | 核心项目 | 独有叙事维度 | 一句话 |
|---|---|---|---|---|---|
| 1 | **驭器卷** | C++ | 玄枢 | 六维工具链从无到有 | 一座跑了十几年的古器核心，和它不敢退休的守门人 |
| 2 | **化形卷** | Python | 息壤 | 包管理从乱到治 | "我这边能跑"的快乐，和它留下的脚本沼泽 |

| 4 | **明契卷** | Rust | 青炉 | 现代工程集大成者 | 从一场发版事故开始，学怎么写清楚边界和承诺——然后发现"写清楚"还不够 |

> 四卷合起来：**见病 → 追根 → 反照 → 结账 → 传火**
>
> 一条完整的工具链文明演化史：蛮荒（C++从零建立）→ 整顿（Python从乱到治）→ 规模化（Go从简到繁再归简）→ 集大成（Rust：所有工具都有了——然后呢？）

## ⚠️ 写作铁律速查

- **先工程，后修辞**：工程逻辑优先，修辞不能压过工程
- **中文专有名词每次注英文原名**：格式"所有权（ownership）"、"健康检查（health check）"。参考 `.claude/canon/24_世界术语-现实工程对照表.md`
- **文学表达标注工程原型**："玄枢"=大型C++遗留系统、"石录"=版本控制/commit历史、"火"=服务运行状态。参考 `.claude/workspace/01_驭器卷/章纲/00_章纲索引.md` 第六节
- **一切设定都要可失守**：每个概念都必须能回答"坏了会怎样"
- **一切成长都写成责任升级**，不写成战力升级
- **世界术语不替换真实工程术语**：Cargo、trait、Result、CI、tracing 等必须保留原文
- **永远不写"有人发明了好办法"**——只写"有人被旧办法伤得太深"
