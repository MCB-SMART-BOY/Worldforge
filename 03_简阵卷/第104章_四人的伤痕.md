# 简阵卷 · 第104章 · 四人的伤痕

同一时刻——四人各自收到了旧屋的召唤。

沈见微在青炉。记录板上一道旧伤痕浮现——来自他发给玄枢的诊断报告 `v0.3.1`。青炉侧的统计与范围声明都真实；越界的是生成器，它把“观测窗内未见调用”涂成绿色“可安全废弃”。纪承钧明知本地 Unix domain socket 未纳入观测、核验尚未闭合，仍批准在维护窗移除接口。旧代理吞掉 socket 错误、写出空文件；前两夜没有告警，第三夜汇总任务读到空文件后，三个服务先后失去响应，告警扩散到十七个外部调用方。沈见微要为工具建议越过证据负责，纪承钧要为明知盲区仍批准删除负责；两段责任不能互相抵销。他看着伤痕旁贴着的传讯原文——“不是指责——是继续。”放下手中的 crate 文档，起身。

纪承钧在玄枢。runbook 在息壤炸了之后散落的纸页还在旧石案上。他以为写了完整地图——十七步，每一步基于玄枢的扎实经验。但第三步——"确认所有下游依赖方已全部迁移"——在息壤是不可执行的步骤。季晚禾标记了十一个"待确认"。他的完整地图在 Python 的世界里不通行。他收到传讯的那一刻——想到了周栖野的回信——"你把你世界的前提当成了所有世界的前提。"他把纸页收好——和钟守玄留下的七个字"前提可能不成立"放在一起。起身。

周栖野在息壤。驿河那次 OOM 的记录还在板子上。白又新把模块带去驿河前，周栖野留下的测试观察是：息壤逐个处理集群时通常约占200MB，已有测试没有超过500MB。他没有验证驿河的共享池和一次全量批次，也没有把适用范围写进交接说明。驿河接入方沿用了服务模板里的512MB平台默认值；季度全量批次同时加载十一个集群，实测约2.3GB，耗尽共享池余量后进程被杀，三条结算管道超时。模板默认值由温故来维护，但现存配置没有记下选择依据；这与周栖野的单机测试观察是两条记录，不能合成一个“他继承了512MB”的故事。周栖野把这次责任写在自己能确认的范围内：没有把息壤测试边界和驿河待验证项交代清楚。他看着叶藏拙账本上的记录——"模块跨域部署后OOM——三条管道超时。"放下笔，起身。

傅远洲在旧屋。他的制度能保证有人接传讯牌——on-call轮值、手册签名、四项模板。但不能保证接的人会多写一行"待补"。制度是地板；而他刚找到的机器与纸页让他怀疑，信号可能早于驿河，也可能在等待回应。设备年代、两者是否同源、回应究竟是什么，他都还没有证据。他独自站在创始者的设计图前——发出最后的传讯。

四道伤痕——四种道的极限——同时浮现。沈见微看到自己的"写清楚"炸了别人。纪承钧看到自己的"完整地图"在另一个世界不通行。周栖野看到自己的"够快"在另一个平台成了炸弹。傅远洲看到自己的"充分制度"在远古告警面前沉默。同一道伤痕——"我以为我的道——就是道"——在他们各自的世界被击穿。另一头的召唤来自旧屋——同一次传讯同时到达四人——四个人各自放下手上的东西，出发。修补者工坊的门虚掩着——创始者的字迹还在墙上。石镜在等。
