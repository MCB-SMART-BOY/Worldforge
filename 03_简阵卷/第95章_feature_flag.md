# 简阵卷 · 第95章 · feature flag

那次因时序假设改变而让下游出问题的性能优化，若有feature flag（`特性开关`），就可以先只给百分之一的流量，再观察错误率、延迟和下游负载。影响不会归零，但在扩大范围之前，可以先发现问题并关掉开关，避免让全部流量同时承受变化。

Feature flag让变更不再是二进制开关——是渐进交付。开关层——on或off。百分比层——百分之一到十到五十到一百。定向层——特定用户或条件。部署不再是全量上线后祈祷——是先给少量流量，等几分钟，看指标。正常再扩大，异常就关掉开关并回滚代码。那百分之一的流量是一次真实环境验证——它不能替代测试，也不能保证没有副作用，但比只在测试环境观察更接近真实。

Flag不是永远的——有退场日期。每个flag创建时就标注了两周后要么全量要么删除。留在代码里的flag会变成新的技术债。特性开关让上线从赌博变成可控的实验——不是让变更更慢，是让变更更安全。
