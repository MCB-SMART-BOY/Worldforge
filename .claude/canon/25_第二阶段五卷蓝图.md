## 二、各卷核心张力

### 容断卷 —— 极端下的存活
- **核心问题**：当所有已知前提被打破——系统还能不能活？
- **工程锚点**：resilience engineering / chaos engineering / graceful degradation / circuit breaker / bulkhead
- **张力引擎**：不是"会不会炸"——是"炸了之后——哪些东西必须还在"
- **与第一阶段衔接**：四个平台都经历过OOM/断火——现在需要的是系统性的容断设计，而非单点修复

### 通界卷 —— 桥的制度化
- **核心问题**：跨世界的桥不能永远靠顾迁舟兄弟俩维护——制度需要规模化
- **工程锚点**：API gateway / service mesh / contract testing / schema registry / cross-domain SLO
- **张力引擎**：桥让世界相连——也让错误传播。制度化的桥不是消除风险——是让风险有名字
- **与第一阶段衔接**：渡桥司从四条道扩展到所有道。桥账从纸质变成协议

### 守序卷 —— 沉默的秩序
- **核心问题**：那些在旧系统里默默运行的规则——没人记得为什么——但所有人都在遵守
- **工程锚点**：legacy system migration / COBOL? / mainframe / institutional memory / organizational knowledge
- **张力引擎**：沉默的秩序比没有秩序更难改——因为它还活着——只是没人知道它为什么活着
- **语言推测**：Java——企业级、大量遗留系统、annotation驱动、设计模式成教条

### 求式卷 —— 结构的边界
- **核心问题**：当系统复杂到无人能理解整体——结构从哪里开始画？
- **工程锚点**：domain-driven design / bounded context / event storming / C4 model / architecture decision records
- **张力引擎**：画结构的人永远画不完——但画出来的部分让后来者不需要从零理解
- **与第一阶段衔接**：四蚀中的"失式"——结构崩塌——在这个卷被正面回应

### 造言卷 —— 给还没有语言的人
- **核心问题**：不是所有场景都适合现有语言——需要被造出来的语言是什么？
- **工程锚点**：DSL / parser combinator / compiler design / language workbench / linter/interpreter
- **张力引擎**：语言不是工具——是权力。有语言的人能写规则——没有语言的人只能承受规则
- **与第一阶段衔接**：Rust的"写清楚"、Python的"先让它跑"、Go的"少即是多"、C++的"考古"——四条路之后——还有路还没被造出来
