# 《万构界·明契卷》十卷三十章蓝图

## 一、文档定位

本文件是《明契卷》的当前章级蓝图，按现行 `00–18` 体系使用。

它不是新的世界观母本，而是：
- 《明契卷》的章节蓝图
- 从卷级设定走向章纲的中间层
- 用来校验每一章是否仍在服务“反黑箱 / 可继承秩序”主命题的工作文档

---

## 二、总主题

《明契卷》不是一本 Rust 语法书，而是一部讲述软件系统从立项、设计、实现、协作、发布、运行到长期维护的工程修行录。

它的章节推进必须始终服务两件事：
- 主角如何把青炉从“能救火的工具”做成“可继承的秩序之炉”
- 万构界如何第一次证明：秩序不必继续依赖少数人的记忆与侥幸

---

## 三、总结构

全卷采用“十卷三十章”推进，每卷三章，每一卷都是一次工程认知渡劫。

### 卷一：起炉问世
使命：先见病，再立约，不急着炫示语言特性。

#### 第一章：凡火未明，问题从何而来
- 写清现实痛点来自哪里
- 让读者先看见失序，而不是先看见语法
- 青炉的起点是病灶，不是灵感

#### 第二章：立炉之前，边界先行
- 讲 scope、非目标、最小承诺
- 让“约”先于“文”
- 确立青炉不是万金油

#### 第三章：选道而行，为什么是 Rust
- 不是吹语言强弱
- 而是说明为何此病必须借明契之道来治
- 立住“显式代价前置”的思想根

### 卷二：初入道途
使命：把工具链写成修炼环境，把 Cargo 写成理器法。

#### 第四章：铸炉开篇，工具链不是安装包
- rustup、toolchain、cargo、rustc 的现实位置
- 为什么工具链本身就是秩序的一部分
- 青炉第一次真正可被锻造

#### 第五章：一纸丹方，Cargo.toml 里的工程世界
- 包名、版本、依赖、feature、edition
- 为什么 manifest 不是配置杂项，而是项目的外显之约
- 青炉的第一份公开誓约

#### 第六章：气入经脉，所有权不是语法，是资源哲学
- 所有权、借用、move、drop 的根
- 资源边界如何从第一天就被看见
- 主角第一次承认“能跑”和“可守”不是一回事

### 卷三：炼体成形
使命：把“代码能写出来”推进到“器胚能成立”。

#### 第七章：术有门径，函数、模块与职责分离
- 函数、module、职责边界
- 代码结构第一次显出“式”
- 青炉从脚本感走向器胚感

#### 第八章：辨药识毒，Option、Result 与错误的正名
- 错误不是坏运气，而是被命名的失守
- panic 与 recoverable error 的边界
- 主角学会不再用侥幸吞掉失守

#### 第九章：初成器胚，第一个可用版本如何诞生
- 从零散能力到最小可用版本
- 让青炉第一次被别人真正拿去用
- 问题从炉中转向入世

### 卷四：筑基立制
使命：让项目从“可用”进入“可维护”。

#### 第十章：骨架初定，目录结构与核心抽离
- crate、module、目录结构与骨架抽离
- 为后续 workspace 埋下基础
- 主角第一次主动为未来的别人留位置

#### 第十一章：炉候可调，配置、环境与命令行参数
- config、env、CLI 参数
- 默认值、环境差异与行为一致性
- 让“只在我机器能跑”开始被治

#### 第十二章：经卷留痕，文档、注释与项目记忆
- 文档的地位
- README、注释、设计说明的边界
- 青炉第一次不只存在于主角脑中

### 卷五：结丹成阵
使命：从单体器胚进入多骨同炉。

#### 第十三章：契口分层，CLI 不等于万能入口
- core / cli / config 等能力拆分
- 为什么分骨不是花活，而是未来责任分离
- 青炉开始具备可演化形态

#### 第十四章：宗门初立，workspace 与多 crate 协同
- workspace 的真正意义
- 共约、共史、多骨同炉
- 主角第一次处理“项目内部的小共同体”

#### 第十五章：阵法有门，trait、泛型与抽象的节制
- trait、泛型、抽象边界
- 什么时候该抽象，什么时候不该
- 让“优雅”服从“可继承”

### 卷六：同门共修
使命：让青炉从个人项目变成真正的门内公共秩序。

#### 第十六章：留影为史，Git 不只是备份
- commit、branch、merge、tag
- 内史与项目记忆
- 历史第一次被认真书写

#### 第十七章：千里传书，远端仓库与协作秩序
- 远端仓库、fork、issue、PR、discussion
- 为什么协作不是把代码传来传去
- 青炉第一次面对“门外之问”

#### 第十八章：门规初成，提交规范、评审文化与新人接引
- review、CI、提交规范、贡献指南
- 审契与门规
- 新人能否进入，开始成为真实压力

### 卷七：化神守界
使命：把 Rust 的硬边界写成真正的责任哲学，而不是恐吓材料。

#### 第十九章：肉身不坏，内存安全的真实含义
- 安全不是神话，而是边界被写明
- 从 use-after-free 一类问题回看明契价值
- 青炉开始具备“可托付”感

#### 第二十章：心魔难驯，并发安全与共享状态的代价
- Send / Sync、锁、共享状态、并发代价
- 并发不是快，而是多流并起时仍要守界
- 主角第一次在速度与责任之间真做选择

#### 第二十一章：禁术与誓约，unsafe、FFI 与责任边界
- unsafe、FFI、外部旧核
- 为什么越界不等于邪法，而是自负额外证明之责
- 为与驭器卷接口埋钩子

### 卷八：炼器出山
使命：让青炉真正面对他人依赖。

#### 第二十二章：器成可试，测试体系与可靠性证明
- 单元、集成、契约、端到端
- 证契如何成立
- 青炉第一次开始可被验证地信任

#### 第二十三章：法宝传世，版本号、变更日志与发布承诺
- semver、release、changelog
- 对外立信，而不是简单发包
- 外史第一次真正出现

#### 第二十四章：开炉布道，crate 发布、二进制交付与用户入口
- 发布路径、安装方式、交付面
- 用户如何真正遇见青炉
- 使用者与维护者的关系开始反过来塑造青炉

### 卷九：问鼎守成
使命：让“上线之后怎么办”成为主线，而不是附录。

#### 第二十五章：入世之后，程序如何真正活着
- runtime、进程、服务、daemon、域
- 为什么器出炉后并不等于修行结束
- 青炉从器走向入世之器

#### 第二十六章：观天察地，日志、追踪、指标与可诊断系统
- 迹、脉、势
- observability 不是附加值，而是反失明机制
- 主角开始学会不靠直觉排障

#### 第二十七章：旧劫未消，兼容、重构、技术债与演进之术
- 渡桥、兼容层、弃用、迁移
- 技术债是四相失衡在时间中的沉积
- 青炉第一次真正背着旧世界前行

### 卷十：合道飞升
使命：把全书从技术成长收束到工程文明判断。

#### 第二十八章：大道重拙，Rust 为何坚持显式与约束
- 回答 Rust 的“慢、硬、重”究竟值不值
- 把前九卷经验重新收束到道心
- 显式不是形式癖，而是文明选择

#### 第二十九章：术与道争，何时该用 Rust，何时不该用 Rust
- 让读者学会取舍，而不是信仰
- 把明契之道放回诸道并立的全局
- 主角不再以“全部都用 Rust”为成熟标志

#### 第三十章：百炼终成，从写代码的人到立道之人
- 收束主角成长
- 验证后来者是否真的接火
- 青炉能否在主角不在场时继续存在

## 四、十卷之间的内在逻辑

### 卷一到卷三
从见病到器胚成立。
重点是：先知道为什么而做，再知道怎么把最小东西做对。

### 卷四到卷六
从可用到可共同维护。
重点是：项目开始为他人而写，历史与门规开始出现。

### 卷七到卷九
从安全边界到入世守成。
重点是：系统真的被人依赖后，责任、观测、迁移才开始全面结算。

### 卷十
从工程技巧收束到文明判断。
重点是：何时该用明契之道，何时不该，以及“立道之人”真正意味着什么。

## 五、贯穿全卷的五条暗线

### 1. 边界

《明契卷》里的大量关键问题，本质都落在边界：

- 值与资源的边界
- 生命周期边界
- 模块与 crate 的边界
- API 与契口的边界
- 团队职责边界
- 运行环境边界
- 安全边界
- 兼容边界

### 2. 责任

这卷必须不断追问：

- 谁拥有
- 谁能改
- 谁来保证
- 谁承担后果

### 3. 长期主义

这卷不能只写“怎么快点做完”，必须持续提醒：
今天为了省事跳过的约束，往往就是未来最重的劫。

### 4. 协作

前半卷可以偏个人起炉，后半卷必须越来越强地进入与他人共修的世界。

### 5. 取舍

成熟不是一路加码，而是知道：

- 什么时候该加
- 什么时候该减
- 什么时候该抽象
- 什么时候该停手
- 什么时候该重构
- 什么时候该不动

## 六、章级写法约束

每章原则上都按下面六步推进：

1. 先出问题  
2. 再讲为什么它在真实工程里会痛  
3. 再引出 Rust / 工具链 / 工程方法  
4. 在青炉项目里具体落地  
5. 站到团队与长期维护视角复盘  
6. 最后收一段本章悟道

---

## 七、首卷入口约束

《明契卷》既然是第一卷，就不能默认读者已经理解别卷。
后续把本蓝图下压成正式章纲时，必须同时守住下面五条：

1. 卷一到卷三必须先让读者看明白是谁在救火、谁在付代价、青炉为何必须起炉，再进入语言选择
2. 世界观术语首次出场时，必须绑在具体工程失序上，不能先给玄名、后补现实问题
3. Rust 特性首次出场时，必须先由事故、协作冲突或继承压力逼出，不能先讲语法再找剧情
4. 即使删去所有跨卷知识，卷一到卷三也仍须完整成立
5. 卷尾的后来者接火，必须只依赖本卷已经立住的门规、测试、文档与石录
