# 《化形卷》章节实践单：第05章《脚本林》

## 一、文档头
- 所属卷：化形卷
- 对应章节：第05章 脚本林
- 实践单状态：已可用

## 二、本章工程问题
- 快速迭代中每一个版本都被保留、从未清理——命名腐败（final_v2_really_final_FIXED）让后来者无法分辨哪个是当前版本、哪些已废弃、哪些仍在被外部依赖。清理速度永远追不上生产速度，直到人走了，遗迹还在

## 三、本章要立起的判断尺
- "回头再整理"是最危险的承诺——整理不会让面板变绿，不会让传讯牌停下来，不会让需求单少拍一张。然后有一天人走了，承诺还留在共享目录里，和那些 delete_later 的文件一起

## 四、故事映照
- 本章事件：叶藏拙带周栖野看林过川四年前留下的旧石镜——final_v2_really_final_use_this_one_FIXED、do_not_delete_working_version、temp_test_delete_later（三年未删）；林过川的 README 里写着"对不起"；周栖野在公共记录板上写下"我不会变成下一个林过川"
- 代价承担：林过川承担了全部速度的代价——他是息壤最早的点火者，也被永远做不完的紧急需求吞掉。周栖野在他留下的文件名里看见了自己的影子
- 为什么用这个工程动作照剧情：脚本林不是个人习惯——是谱系。是一种会传染的命名病。每一个"final"都在撒谎，每一个"delete_later"都在替未来挖沼泽

## 五、本章最小实践

### 核心概念
- 命名腐败（naming rot）
- 版本管理——文件版本 vs 逻辑版本
- 脚本遗迹（script archaeology）
- 清理即文档——删文件比复制文件更需要勇气

### 最小项目动作
- 清理你的共享目录或脚本目录。给每一个文件标注：当前版本 / 历史版本（保留原因） / 废弃版本（可删除日期）。像顾迁舟的桥账一样——每一条路都有搭桥日期和退场日期

### 必做练习
- 练习目标：体验从脚本林中分辨"火种"和"荒地"
- 输入：你的项目共享目录或脚本目录
- 输出：一份文件清单——标注每个文件的当前状态（在用/备用/废弃）、依赖方（谁还在调它）、清理建议（保留/归档/删除）
- 完成标准：另一个人看着清单就能知道哪个文件是当前版本，不需要靠"final"或"use_this_one"来猜

## 六、自检清单
- 我能说出我的共享目录里有多少个文件名带"final"
- 我能分辨林过川的"对不起"和卫千枢的"后来的人，对不起"是同一句话——以及我自己有没有正在制造同一句
- 我知道为什么删文件比复制文件更需要勇气——以及不删的代价最终由谁来付

## 七、常见误区
- 误区：旧版本留着又不占多少空间——万一以后要用呢
- 为什么不：留着不是因为"万一要用"——是因为删错了整个流程就断了。但"不敢删"的代价是后来者必须逐一考古每一个版本。空间不贵，认知负载才贵
