## 五、本章最小实践

### 1. 核心概念

- config
- env
- 参数优先级

### 2. 最小项目动作

- 为 `qinglu` 写清 file / env / CLI 参数三层优先级，并做一次具名配置校验

### 3. 推荐工具 / 命令 / 观察点

- 工具：配置文件、文本编辑器
- 命令：`env | sort`、`cargo run -- check --config ./sample.toml`
- 观察点：哪些值是显式传入的，哪些值只是“你机器上刚好有”

### 4. 必做练习

- 练习目标：让配置差异被公开说明，而不是被环境偷偷决定
- 输入：一份样例配置 + 一个环境变量 + 一个 CLI 参数
- 输出：一份优先级说明和最小解析逻辑
- 完成标准：明确写出三层优先级，并在缺失关键配置时返回具名失败而不是静默默认

### 5. 可选延伸

- 写一页“默认值为什么成立”的说明，练习解释默认而不是只声明默认

## 七、常见误区

- 误区一：
  - 表现：为了灵活，把一切都做成环境变量覆盖
  - 为什么不对：这样只是在给暗门立新壳
- 误区二：
  - 表现：发现行为不一致，就继续在 README 里追加一句注意事项
  - 为什么不对：如果优先级没被结构化写清，注意事项只会继续失真
