## 五、本章最小实践

### 1. 核心概念

- 最小可用版本
- dry-run
- 入口可信度

### 2. 最小项目动作

- 让 `qinglu` 至少具备一个别人能独立执行的“发布前校验”命令

建议把本节控制在一个可在 `20–40` 分钟内完成的范围。

### 3. 推荐工具 / 命令 / 观察点

- 工具：`cargo run`、`cargo test`
- 命令：`cargo run -- check ./sample-release.toml`、`cargo test`
- 观察点：新人是否只靠说明就能跑通，而不是继续私聊主角问入口

### 4. 必做练习

- 练习目标：做出第一个诚实可用的 `qinglu`
- 输入：当前 `qinglu` 原型 + 一份样例配置
- 输出：一个最小 `check` 子命令、一次成功运行记录、一次失败运行记录
- 完成标准：至少覆盖“配置正确时给出明确通过信息”和“配置错误时返回具名失败”，并让另一个人或另一个终端能够复走

### 5. 可选延伸

- 再补一页 `README` 的“快速开始”部分，验证你的入口说明是否已经能被后来者接住

## 七、常见误区

- 误区一：
  - 表现：为了显得厉害，把第一版做成包罗万象的壳
  - 为什么不对：你得到的通常不是可用，而是更大的新黑箱
- 误区二：
  - 表现：只在作者终端里演示成功，就宣布第一版成立
  - 为什么不对：这仍然没有跨过“别人能不能独立使用”的门槛
