## 二、本单定位

### 1. 本章工程问题

- 项目为什么这样长成，应该分别写进哪里，才不会让新史再次失真

### 2. 本章要立起的判断尺

- 文档不是一个桶，README、设计说明与注释各自承担不同记忆责任

## 五、本章最小实践

### 1. 核心概念

- README
- 设计说明
- 注释边界

### 2. 最小项目动作

- 为 `qinglu` 同时写一份 `README.md` 和一页设计说明，并删掉一段本来想硬塞进注释里的背景解释

### 3. 推荐工具 / 命令 / 观察点

- 工具：Markdown
- 命令：`find docs -maxdepth 2 -type f | sort`
- 观察点：哪个信息该给第一次进入者看，哪个信息该给维护者看

### 4. 必做练习

- 练习目标：给项目记忆分层，而不是堆在同一处
- 输入：当前 `qinglu` 项目
- 输出：`README.md` + `docs/design/0001-core-boundary.md`
- 完成标准：README 至少说明“项目做什么 / 不做什么 / 怎样开始”，设计说明至少解释一次边界取舍，代码注释只保留局部必要理由

### 5. 可选延伸

- 补一页“已知限制”，训练自己把暂时做不到的部分也写成公共记忆

## 七、常见误区

- 误区一：
  - 表现：所有解释都塞进 README
  - 为什么不对：这样新手看不懂，维护者也查不到关键取舍
- 误区二：
  - 表现：因为怕过时，就干脆不写设计说明
  - 为什么不对：不写不会减少失真，只会让失真失去入口
