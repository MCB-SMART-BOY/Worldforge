## 五、本章最小实践

### 1. 核心概念

- log
- trace
- metric
- run id

### 2. 最小项目动作

- 给一次关键命令补最小结构化日志、步骤标记和运行标识，让同一轮执行可以被串起来复盘

### 3. 推荐工具 / 命令 / 观察点

- 工具：日志输出与错误链
- 命令：`RUST_LOG=info cargo run -- doctor ./sample-release.toml`
- 命令：`cargo run -- explain last-run`
- 观察点：日志是否能回答“走到哪一步、在哪失败、下一步查哪里”

### 4. 必做练习

- 练习目标：让一次跨环境失败不再只能被描述成“它就是怪”
- 输入：一条包含读取配置、执行检查和输出结论的命令链
- 输出：最小观测口径设计
- 完成标准：至少包含
  - 一条人类可读日志
  - 一个关键步骤标记
  - 一个能串起同轮执行的运行标识

### 5. 可选延伸

- 为一条最关键的错误补一个“建议下一步检查哪里”的输出规范

## 七、常见误区

- 误区一：
  - 表现：日志只写情绪化描述，不写上下文和关键字段
  - 为什么不对：那会让所有问题继续依赖原作者现场翻译
- 误区二：
  - 表现：觉得有监控图就说明可观测已经成立
  - 为什么不对：若不能串回一次真实执行和错误链，图只是远距离围观
