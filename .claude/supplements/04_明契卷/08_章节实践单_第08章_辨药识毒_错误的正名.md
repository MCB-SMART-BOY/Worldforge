## 五、本章最小实践

### 1. 核心概念

- Option
- Result
- panic 边界

### 2. 最小项目动作

- 为 `qinglu` 定义一个最小错误类型，并把至少一条 `unwrap` 或布尔失败改成 `Result`

建议把本节控制在一个可在 `20–40` 分钟内完成的范围。

### 3. 推荐工具 / 命令 / 观察点

- 工具：`cargo check`、`cargo run`
- 命令：`cargo run -- --help`
- 观察点：失败时输出是否能说明“是什么错、下一步看哪里”，而不是直接崩溃或沉默

### 4. 必做练习

- 练习目标：让第一个失败路径从“猜”变成“看得见”
- 输入：当前 `qinglu` 原型
- 输出：一个最小 `enum QingluError` 和一条被显式传播的错误链
- 完成标准：至少区分“配置缺失”和“路径不存在”两类失败，并能用清楚消息返回给调用者

### 5. 可选延伸

- 给错误加一个“建议动作”字段，练习把失败说明写成对后来者有用的入口

## 七、常见误区

- 误区一：
  - 表现：用 `None`、空字符串或默认值统一表示所有失败
  - 为什么不对：这样得到的不是简洁，而是新的失明
- 误区二：
  - 表现：看见错误处理麻烦，就继续 `unwrap`
  - 为什么不对：短期省事会把代价重新推回使用者和后来者
