# 09 · 集成验证

> 跨卷一致性验证。当内容涉及多个卷时——在执行 `/check-cross-volume` 之外——需要额外执行的系统级验证。

## 一、验证维度

```
集成验证
├── 锚点对齐     — 跨卷锚点章号在四卷中一致
├── 共享事件     — 共享事件的叙述满足跨卷铁律
├── 术语一致     — 同一术语在各卷中定义一致
├── 人物交叉     — 跨卷人物的出场、行为、时间线一致
├── 时间线       — 四卷事件的时间线不矛盾
└── 入口可及     — 每卷可独立阅读，不依赖别卷为前提
```

## 三、共享事件叙述验证

### 3.1 跨卷铁律回顾（canon/15 §六）

1. 互文只能增益，不能把另一卷写成本卷成立前提
2. 共享事件每到一卷，都要按该卷主角的代价与病理重新叙述
3. 跨卷概念第一次在某卷出场时，必须在该卷内给出够用解释
4. 卷尾接口只能指向"后续放大"或"另一侧反照"，不能指向"必须先读前卷"

### 3.2 共享事件验证矩阵

对每个已落地的共享事件：

| 验证项 | 方法 | 通过标准 |
|--------|------|---------|
| 事件名称一致 | 跨卷对比事件描述 | 核心事实（谁/做什么/结果）不矛盾 |
| 本卷自足 | 仅读本卷正文 → 能否理解事件 | 不需要读别卷就能理解发生了什么 |
| 代价归属正确 | 事件在本卷中的代价落在谁身上 | 是本卷角色的代价，不是别卷角色的 |
| 病理独立 | 事件的病理是否从本卷重述 | 不是复制别卷的叙述，是从本卷的工程病理重新分析 |
