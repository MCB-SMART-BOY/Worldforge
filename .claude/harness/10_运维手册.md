# 10 · 运维手册

> `.claude/` 体系的维护操作指南。当需要新增卷、更新 canon、迁移结构、或处理异常时使用。

## 一、日常维护

### 1.1 更新进度面板

**触发条件**：每完成/提交一章或一批章

**步骤**：
1. 更新 `07_进度面板.md` 中对应卷的章状态
2. 更新对应卷 `workspace/XX_卷/00_卷索引.md` 中的进度状态表
3. 如果涉及跨卷锚点落地，更新 `07_进度面板.md` 的"跨卷锚点进度"表
4. 更新全局概览的完成率

### 1.2 更新卷索引

**触发条件**：章纲有重大调整、新增章节、人物变更

**步骤**：
1. 修改 `workspace/XX_卷/00_卷索引.md` 对应部分
2. 确认人物表、章节目录、进度状态表一致
3. 如果新增了文学表达或工程术语，更新"文学表达-工程原型对照表"

### 1.3 提交前检查

**触发条件**：每次 git commit

**步骤**：
1. 过 Commit Gate（`03_质量门.md` §五）
2. 确认无 `Co-Authored-By: Claude`（铁律）
3. 确认 commit message 格式正确
4. 确认只包含目标文件

## 二、新增一卷

### 2.1 创建卷工作区

```bash
# 1. 创建 workspace 五层结构
mkdir -p workspace/05_XX卷/{人物,章纲,正文设计,资料}

# 2. 创建卷索引
touch workspace/05_XX卷/00_卷索引.md

# 3. 创建 supplements 三件套
mkdir -p supplements/05_XX卷
touch supplements/05_XX卷/00_配套索引.md
touch supplements/05_XX卷/XX卷_卷级项目里程碑表.md
touch supplements/05_XX卷/XX卷_术语_工具_最小索引.md

# 4. 创建正文目录
mkdir -p 正文/05_XX卷
```

### 2.2 新增 canon 设定

1. 在 `canon/` 中创建新卷的设定文件（编号接续现有文件）
2. 更新 `canon/00_总览与使用说明.md` — 添加新文件到建议阅读顺序
3. 更新 `canon/23_四卷120章总蓝图.md` — 如果是四卷之外的新卷

### 2.3 更新 harness 文件

需要更新的 harness 文件：

| 文件 | 需要更新的内容 |
|------|--------------|
| `02_状态机.md` | 无结构变化（状态定义是通用的） |
| `04_命令中心.md` | 参考文件索引中添加新卷 |
| `05_模板注册表.md` | 无结构变化（模板是通用的） |
| `07_进度面板.md` | 添加新卷的进度行 |
| `09_集成验证.md` | 添加新卷的锚点和术语 |

### 2.4 更新项目文件

| 文件 | 更新内容 |
|------|---------|
| `CLAUDE.md` | 更新四卷表、进度状态、目录布局 |
| `README.md` | 如果是公开卷，更新项目说明 |
| `.claude/README.md` | 更新目录映射 |
| `.claude/workspace/00_工作区说明.md` | 更新推荐顺序 |

## 三、更新 Canon

### 3.1 新增 canon 文件

1. 编号接续现有最后一个文件
2. 更新 `canon/00_总览与使用说明.md` 的建议阅读顺序
3. 更新 `canon/README.md`（如果存在）
4. 检查是否有 harness 文件需要引用新 canon

### 3.2 修改现有 canon

**关键原则**：canon 修改是**向后兼容**的——只增不改。

| 修改类型 | 允许？ | 注意事项 |
|---------|--------|---------|
| 新增概念 | ✅ | 必须满足铁律一–五 |
| 修改已有概念的定义 | ⚠️ 慎用 | 检查所有引用该概念的正文是否需要更新 |
| 删除已有概念 | ❌ | 已有正文可能依赖它——只能标记为"已废弃" |
| 调整卷级设定 | ⚠️ 慎用 | 检查已写正文是否符合新设定 |

### 3.3 Canon 修改的影响分析

修改 canon 后，执行：
1. `grep -rn "被修改的概念" workspace/ 正文/ supplements/` — 找到所有引用
2. 逐条评估是否需要更新
3. 在 commit message 中注明影响范围

## 四、新增 Skill

### 4.1 创建 Skill 文件

1. 在 `skills/` 中创建新的 `.md` 文件
2. 格式参考现有 skill：
   - 功能说明（1-2句话）
   - 参数定义
   - 执行流程（步骤化）
   - 输出格式
   - Gotchas（常见错误）
   - 参考文件列表

### 4.2 集成到 harness

1. 更新 `04_命令中心.md` — 在路由表中添加新 skill 的条目
2. 更新 `01_流水线.md` — 如果新 skill 参与流水线，更新对应 Phase
3. 更新 `00_架构总图.md` — 在 skill 列表中体现

### 4.3 更新 CLAUDE.md

在 `CLAUDE.md` 的 Available Skills 表中添加新 skill。

## 五、结构迁移

### 5.1 重命名目录/文件

**原则**：尽可能不重命名——链接断裂成本高。

如果必须重命名：
1. `grep -rn "旧路径" .claude/ CLAUDE.md README.md 目录.md` — 找到所有引用
2. 先更新所有引用，再重命名
3. 在 commit message 中注明旧→新路径映射

### 5.2 拆分大文件

**原则**：当文件超过 500 行时考虑拆分。

1. 确定拆分边界（按主题或按 Section）
2. 创建新文件
3. 在原文件位置留下指针（"此内容已迁移至：`新路径`"）
4. 更新所有引用
5. 保留原文件（不删除）直到确认所有引用已更新

### 5.3 合并小文件

**原则**：当多个文件各自 < 30 行且主题紧密相关时考虑合并。

1. 确定合并后的文件结构
2. 创建合并文件
3. 在原文件位置留下指针
4. 更新所有引用

## 六、灾难恢复

### 6.1 进度面板失准

**症状**：进度面板显示的章数与实际不符

**恢复步骤**：
```bash
# 每卷执行章节存在性报告
for vol in 01_驭器卷 02_化形卷 03_简阵卷 04_明契卷; do
  echo "=== $vol ==="
  for ch in $(seq -w 1 120); do
    match=$(ls 正文/$vol/第${ch}章_*.md 2>/dev/null | head -1)
    [ -n "$match" ] && echo "Ch$ch: ✅ $(basename "$match")" || echo "Ch$ch: ❌"
  done
done
```

然后根据实际输出更新 `07_进度面板.md`。

### 6.2 章纲-正文不匹配

**症状**：正文内容与章纲描述不一致

**恢复**：
1. 确定以哪个为准（通常是正文——章纲是设计，正文是执行）
2. 如果以正文为准：更新章纲以匹配正文
3. 如果以章纲为准：修改正文
4. 记录不匹配的原因（设计变更、写作中发现更好的方向等）

### 6.3 Git 状态混乱

**恢复**：
```bash
git status  # 了解当前状态
git log --oneline -10  # 最近的提交
git diff  # 未 staged 的更改
git diff --cached  # 已 staged 的更改
```

## 七、版本升级

### 7.1 Harness 版本升级

当 harness 体系自身需要升级时：

1. 更新 `00_架构总图.md` 的版本表
2. 更新 `README.md`（harness 的 README）
3. 如果新增了 harness 文件，更新架构总图
4. 如果修改了流水线/质量门/状态机，评估对现有写作流程的影响

### 7.2 Canon 版本升级

Canon 的版本在 `canon/00_总览与使用说明.md` 中维护。当 canon 发生重大变化时：

1. 更新版本号（如 v1.8 → v1.9）
2. 在版本说明中记录变化
3. 更新 CLAUDE.md 中引用的状态信息

## 八、定期健康检查

建议每完成 30 章正文后执行一次：

### 检查清单

- [ ] 进度面板与实际文件一致
- [ ] 卷索引的进度状态表与进度面板一致
- [ ] 所有已写章节的文件名符合规范
- [ ] 无废弃命名残留（`百炼成仙`）
- [ ] 跨卷锚点状态准确
- [ ] 人物卡与实际出场一致
- [ ] CLAUDE.md 的状态信息最新

### 执行命令

```bash
# 废弃命名检查
grep -rn "百炼成仙" 正文/ .claude/ || echo "✅ 无废弃命名残留"

# 文件名规范检查
find 正文/ -name "第*章*.md" | while read f; do
  basename=$(basename "$f")
  if ! echo "$basename" | grep -qP '^第\d+章_.+\.md$'; then
    echo "⚠️ $f"
  fi
done

# 卷索引存在性
for vol in 01_驭器卷 02_化形卷 03_简阵卷 04_明契卷; do
  [ -f ".claude/workspace/$vol/00_卷索引.md" ] && echo "✅ $vol 卷索引" || echo "❌ $vol 卷索引缺失"
done
```

## 九、运维原则

1. **改动越小越好**：能改一个文件的，不改两个
2. **先更新引用，再移动文件**：避免断链
3. **每次运维操作后更新此手册**：如果发现了新的操作模式
4. **保留历史**：旧文件不删，用指针指向新位置——维护考古层
5. **自动化检查**：能用脚本验证的，不靠人眼
