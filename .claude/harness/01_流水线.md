# 01 · 流水线

> 章节写作的端到端流水线定义。从章纲到成稿提交——每步的输入、输出、工具、检查。

## 一、总流水线

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ PHASE 1  │───→│ PHASE 2  │───→│ PHASE 3  │───→│ PHASE 4  │
│ 准备      │    │ 设计      │    │ 写作      │    │ 审阅      │
│          │    │          │    │          │    │          │
│ 读章纲   │    │ 章节设计  │    │ 正文起草  │    │ 自查      │
│ 读卷设定 │    │ 场景构思  │    │ 术语标注  │    │ 审阅      │
│ 读相关   │    │ 张力设计  │    │ 三问自答  │    │ 修改      │
│ canon    │    │          │    │          │    │ 提交      │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
     │               │               │               │
     ▼               ▼               ▼               ▼
 Design Gate     Design Gate     Prose Gate      Review Gate
 (通过才进入     (通过才进入     (通过才进入     (通过才提交)
  Phase 2)       Phase 3)       Phase 4)       
```

## 二、Phase 1: 准备（Prepare）

**目标**：加载本章所需的所有参考材料，确认章纲定位。

### 输入
- 目标卷的 `00_卷索引.md`（确定本章在卷中的位置）
- 目标卷的 `章纲/` 对应 Section 文件（读取本章章纲）
- 相关 canon 文件（按需，由本章的工程主题决定）

### 步骤

| # | 操作 | 工具 | 产出 |
|---|------|------|------|
| 1.1 | 读取卷索引，确认本章位置、前后章关系 | Read | 上下文：前章概要、后章方向 |
| 1.2 | 读取本章章纲（六拍骨架、工程主题、张力设计） | Read | 章纲原文 |
| 1.3 | 读取卷级设定（canon/09-12 对应卷） | Read | 卷级约束：对象层级、文明命题、道统特质 |
| 1.4 | 读取相关 canon 补充（按主题） | Read | 补充材料 |
| 1.5 | 检查前后章正文（如果已写） | Read | 叙事连续性锚点 |

### 主题→Canon 快速索引

| 工程主题 | 参考 canon |
|---------|-----------|
| C++ 语言特性 | canon/09 (驭器卷设定), canon/18 (四主道特性) |
| Python 语言特性 | canon/10 (化形卷设定), canon/18 |
| Go 语言特性 | canon/11 (简阵卷设定), canon/18 |
| Rust 语言特性 | canon/12 (明契卷设定), canon/18 |
| 跨卷事件 | canon/22 (共享事件表), canon/23 §7 (锚点) |
| 术语英文原名 | canon/24 (术语对照表) |
| 四相/四蚀定义 | canon/01 |
| 对象层级 | canon/02 |
| 命名规范 | canon/16 |

### Phase 1 完成标准
- [ ] 已读本章章纲
- [ ] 已知前后章关系
- [ ] 已确认本章工程主题
- [ ] 已确认本章核心相与失守形态

## 三、Phase 2: 设计（Design）

**目标**：生成章节设计蓝图，明确六拍骨架、张力曲线、揭示节奏。

### 步骤

| # | 操作 | 工具 | 产出 |
|---|------|------|------|
| 2.1 | 执行章节设计 | `/design-chapter` | 章节设计蓝图 |
| 2.2 | 设计关键场景 | `/craft-scene`（按需，复杂章使用） | 场景大纲 |
| 2.3 | 确认术语清单 | 手动 + canon/24 | 本章必须出现的工程术语列表 |
| 2.4 | 确认文学-工程对照 | 手动 + 章纲索引第六节 | 本章世界术语的工程原型 |
| 2.5 | 过 Design Gate | 对照质量门 §Design Gate | ✅/❌ |

### Design Gate（详见 03_质量门.md §Design Gate）

- 六拍骨架完整？
- 工程主题明确？
- 张力曲线可辨识？
- 揭示节奏有设计？
- 术语清单 ≥ 5 个真实工程术语？
- 三问可预答？

### Phase 2 完成标准
- [ ] 设计蓝图完成
- [ ] Design Gate 通过
- [ ] 术语清单就绪

## 四、Phase 3: 写作（Write）

**目标**：将设计蓝图转化为正文，约3000–5000字。

### 步骤

| # | 操作 | 说明 | 产出 |
|---|------|------|------|
| 3.1 | 起草正文 | 遵循六拍结构，但不等分段 | 正文初稿 |
| 3.2 | 术语标注 | 每个中文CS术语注英文原名（铁律四之补充） | 已标注正文 |
| 3.3 | 三问自答 | 逐场景回答 🩻 😣 🛤️ | 自答记录 |
| 3.4 | 张力检查 | 张力曲线是否实际呈现（不是纸面设计） | 张力自评 |
| 3.5 | 入门检查 | 前500字能定位？新术语≤3？ | 入门自评 |
| 3.6 | 过 Prose Gate | 对照质量门 §Prose Gate | ✅/❌ |

### 正文写作规范

- **长度**：每章 3000–5000 字（约 60–100 行）
- **结构**：六拍骨架——但不等分段。有些拍压缩到半段，有些展开三页
- **术语**：铁律四之补充——每个中文CS术语每次出现注英文原名
- **叙事视角**：以本卷主角的视角为主，其他人物视角为辅
- **场景切换**：用 `· · ·` 分隔不同场景/时间
- **对话**：用中文引号 `""`——破折号 `——` 表示停顿，不是省略号
- **文件名**：`第XX章_标题.md`

### 写作调性参考

- **驭器卷**：古、重、考古气——"凌晨三点的玄枢散热塔"
- **化形卷**：快、灵、脚本气——"先跑起来再说"
- **简阵卷**：平、冷、值班气——"今晚又是你"
- **明契卷**：硬、准、边界气——"编译器不骗人，但人会"

### Prose Gate（详见 03_质量门.md §Prose Gate）

- 三总裁定满足？
- 六拍结构完整？
- 张力曲线有效？
- 术语铁律遵守？
- 三问每场景可答？

### Phase 3 完成标准
- [ ] 正文初稿完成
- [ ] 术语标注完成
- [ ] 三问自答完成
- [ ] Prose Gate 通过

## 五、Phase 4: 审阅（Review）

**目标**：系统性审阅正文，修改，提交。

### 步骤

| # | 操作 | 工具 | 产出 |
|---|------|------|------|
| 4.1 | 章节审校 | `/review-chapter` | 审校报告 |
| 4.2 | 逐条修改 | 手动 | 修改后正文 |
| 4.3 | 设定验证（如涉及新设定） | `/check-canon` | 设定验证报告 |
| 4.4 | 跨卷验证（如有跨卷引用） | `/check-cross-volume` | 跨卷验证报告 |
| 4.5 | 过 Review Gate | 对照质量门 §Review Gate | ✅/❌ |
| 4.6 | git commit | git | commit |

### Review Gate（详见 03_质量门.md §Review Gate）

- 审校报告的 ❌ 项已清零？
- 命名规范正确？
- 跨卷引用（如有）自足？
- 文学-工程对照在首次出现时建立？

### Commit Gate（详见 03_质量门.md §Commit Gate）

- 文件名正确？
- 无 Co-Authored-By: Claude？
- Commit message 格式正确？

### Phase 4 完成标准
- [ ] Review Gate 通过
- [ ] Commit Gate 通过

## 六、批量流水线（多章并行/连续）

### 6.1 连续写多章（同卷）

```
Phase 1 (批量准备)
    │
    ├── Chapter N   → Phase 2 → Phase 3 → Phase 4
    ├── Chapter N+1 → Phase 2 → Phase 3 → Phase 4
    ├── Chapter N+2 → Phase 2 → Phase 3 → Phase 4
    ├── Chapter N+3 → Phase 2 → Phase 3 → Phase 4
    └── Chapter N+4 → Phase 2 → Phase 3 → Phase 4
                         │
                         ▼
              Phase 4 (批量审阅: /audit-volume)
```

**批量原则**：
- Phase 1 可以批量准备（一次读整卷章纲）
- Phase 2/3 逐章推进（每章有自己的设计蓝图和张力曲线）
- Phase 4 可以批量审阅（每 5-10 章做一次 `/audit-volume`）

### 6.2 推荐的批量节奏

| 批量大小 | 适用场景 | Phase 4 策略 |
|---------|---------|-------------|
| 1 章 | 关键章（卷首、卷尾、高潮章） | `/review-chapter` 逐章审 |
| 5 章 | 常规推进（一卷的半个 Section） | 写完5章后 `/audit-volume` Section 级审阅 |
| 10 章 | 整卷 Section | 写完10章后 `/audit-volume` Section 级审阅 + 更新进度面板 |

## 七、特殊章的流水线变体

### 7.1 卷首章（每卷 Ch01/11/21...）

额外步骤：
- Phase 1：读取上一卷的卷尾章，确保叙事衔接
- Phase 2：设计时需包含"新读者入口"检查——这一章能否让从本卷开始读的人不掉队？
- Phase 3：前 500 字必须完成"我在哪/谁的视角/发生什么"

### 7.2 卷尾章（每卷 Ch10/20/30...）

额外步骤：
- Phase 2：设计时需包含"卷尾钩子"——给下一卷的读者一个继续的理由
- Phase 3：章末必须有收束（本卷主题的暂时结论）+ 钩子（下一卷的方向预告）
- Phase 4：检查与下一卷卷首章的衔接

### 7.3 跨卷锚点章

额外步骤：
- Phase 2：读取 canon/22 共享事件表中对应条目
- Phase 3：确保事件从本卷主角的代价和病理重新叙述（跨卷铁律二）
- Phase 4：执行 `/check-cross-volume` 验证

### 7.4 高潮章

额外步骤：
- Phase 2：设计时确认张力曲线为全卷最高点
- Phase 3：张力需要达到全卷峰值——代价必须可视化、不可逆、落在具体的人身上
- Phase 4：`/audit-volume` 需要从整卷视角评估高潮是否够高

## 八、流水线反模式

| 反模式 | 为什么错 | 正确做法 |
|--------|---------|---------|
| 跳过 Phase 1 直接写 | 不知道前后章在写什么 → 叙事断裂 | 至少读目标章的章纲 + 前后章的章纲 |
| Phase 2 设计太简略 | "六拍等分"、"张力虚高" | 设计到能回答"张力最高点在哪一行" |
| Phase 3 写完不自查 | 把审阅负担全推到 Phase 4 | Prose Gate 是作者的责任，不是审阅者的 |
| 批量写 10 章然后一起审 | 问题在第一章就出现，后面 9 章都带着同样的病 | 每 5 章至少停一次，做 Section 级审阅 |
| Phase 4 只审不修 | 审阅发现的问题留在正文里 | 审一条改一条，改完再提交 |
