# 03 · 质量门

> 每个流水线阶段的通过标准。质量门是**串行的**——前一扇门必须通过才能进入下一阶段。不跳级、不跳过。

## 质量门全景

```
Phase 1 (准备)           Phase 2 (设计)           Phase 3 (写作)           Phase 4 (审阅)
     │                        │                        │                        │
     ▼                        ▼                        ▼                        ▼
┌──────────┐            ┌──────────┐            ┌──────────┐            ┌──────────┐
│ PREP GATE│ ──通过──→ │DESIGN GATE│ ──通过──→ │PROSE GATE│ ──通过──→ │REVIEW GATE│
│          │            │          │            │          │            │          │
│ 章纲可读  │            │ 六拍完整  │            │ 铁律满足  │            │ 审校清零  │
│ 前后清楚  │            │ 工程明确  │            │ 张力有效  │            │ 命名正确  │
│ 主题确认  │            │ 张力有设计 │            │ 术语标注  │            │ 跨卷自足  │
│          │            │ 三问可答  │            │ 三问落地  │            │          │
└──────────┘            └──────────┘            └──────────┘            └──────────┘
                                                                              │
                                                                              ▼
                                                                       ┌──────────┐
                                                                       │COMMIT GATE│
                                                                       │          │
                                                                       │ 文件名    │
                                                                       │ 无AI署名  │
                                                                       │ Message   │
                                                                       └──────────┘
```

## 一、Prep Gate（准备门）

**位置**：Phase 1 结束时
**目的**：确认有足够的信息开始设计

| # | 检查项 | 判定标准 | 不通过时的动作 |
|---|--------|---------|--------------|
| P1 | 章纲已读取 | 已读目标章的章纲文件 | 去读章纲 |
| P2 | 前后章关系已知 | 能说出前一章的章末状态和后一章的起点 | 读前后章章纲 |
| P3 | 工程主题已确认 | 能说出本章核心工程概念（如"valgrind""SVN→Git迁移"） | 回看章纲和卷设定 |
| P4 | 核心相已确认 | 能说出本章主相（式/流/契/史）和对抗的蚀 | 回看章纲 |
| P5 | 卷级约束已知 | 能说出本卷的对象层级、文明命题、道统特质 | 读对应 canon/09-12 |

**Prep Gate 通过标准**：5/5 ✅

## 二、Design Gate（设计门）

**位置**：Phase 2 结束时
**目的**：确认设计蓝图足够具体，可以直接进入写作

### 2.1 结构完整性

| # | 检查项 | 判定标准 | 参考 |
|---|--------|---------|------|
| D1 | 六拍骨架完整 | 每拍有 ≥ 2 句具体描述（不是"此处写问题"） | canon/15 §四、六 |
| D2 | 工程主题明确 | 列出 ≥ 5 个本章将出现的真实工程术语 | canon/24 |
| D3 | 术语有英文原名 | 每个中文术语已确认英文原名 | canon/24 |
| D4 | 世界观切入句就绪 | 有一句桥接工程与世界观的切入句 | canon/15 §四·第五步 |

### 2.2 张力设计

| # | 检查项 | 判定标准 |
|---|--------|---------|
| D5 | 曲线形态明确 | 选定了攀升/倒钩/双峰/悬疑/崩塌之一 |
| D6 | 张力起点具体 | 能说出"读者在第几段开始感到不对" |
| D7 | 呼吸点设计 | 至少一处读者可以消化的位置 |
| D8 | 章末钩子具体 | 能说出读者翻页的动力（不是"想知道后续"这种空话） |

### 2.3 揭示设计

| # | 检查项 | 判定标准 |
|---|--------|---------|
| D9 | 揭示节奏表完整 | 开场/中段/章末 —— 读者知什么、角色知什么 |
| D10 | 张力类型选定 | 每段的同步/反讽/悬念已标注 |

### 2.4 预检

| # | 检查项 | 判定标准 |
|---|--------|---------|
| D11 | 三问预检可答 | 🩻 😣 🛤️ 在设计阶段能给出预判 |
| D12 | 入门可及性 | 前500字定位清楚，新术语 ≤ 3 个 |
| D13 | 前后衔接有因果 | "因为本章发生X，下一章必须面对Y" |

**Design Gate 通过标准**：≥ 11/13 ✅（D1-D4 为强制项，必须全部 ✅）

## 三、Prose Gate（写作门）

**位置**：Phase 3 结束时
**目的**：确认正文质量达到审阅标准

### 3.1 三总裁定（强制项——任何一项 ❌ = 门不通过）

| # | 检查项 | 判定标准 |
|---|--------|---------|
| W1 | 先工程后修辞 | 读者能清楚说出"这里在处理什么真实工程问题"。修辞没有压过工程逻辑。 |
| W2 | 设定可失守 | 涉及的世界观概念展示了失败形态（"坏了会怎样"）。 |
| W3 | 成长=责任升级 | 人物成长表现为责任扩容，不是战力升级。 |

### 3.2 六拍结构

| # | 检查项 | 判定标准 |
|---|--------|---------|
| W4 | 问题先出 | 开场就让读者看见痛——不是铺垫，是问题。 |
| W5 | 为什么痛 | 解释了"这个难落到谁身上"——有人，不是抽象团队。 |
| W6 | 引出方法 | 使用真实工程术语——不是世界观隐喻。 |
| W7 | 项目落地 | 在具体项目/器/门中落地——玄枢/息壤/驿河/青炉。 |
| W8 | 多方复盘 | 不止主角视角——团队/维护/继承者至少还有一个视角。 |
| W9 | 高层收束 | 章末有一句回扣本卷文明命题的判断。 |

### 3.3 张力实际呈现

| # | 检查项 | 判定标准 |
|---|--------|---------|
| W10 | 张力曲线可感知 | 读正文时有明显的紧张→释放→再紧张→章末高点的节奏。不是从头平到尾。 |
| W11 | 呼吸点实际存在 | 高张力后有半页静默或反思——让读者消化。 |
| W12 | 章末有钩子 | 合上这章后读者有"必须翻下一页"的动力。 |
| W13 | 代价可视化 | 代价让读者"看见"——具体场景中，具体的人，失去了具体的东西。 |
| W14 | 情感锚点存在 | 有一个可以共情的人——不一定是主角，但有人。不是全员冷静理性。 |
| W15 | 因果链清晰 | 每个重要事件有"因为"在前面。没有"太巧"的事件。 |

### 3.4 术语铁律

| # | 检查项 | 判定标准 |
|---|--------|---------|
| W16 | 真实术语保留 | 全文未用世界观术语替换真实工程术语（Cargo 还是 Cargo） |
| W17 | 中文术语注英文 | 每个中文CS/工程术语每次出现时注了英文原名（"所有权（ownership）"） |
| W18 | 世界术语有根 | 首次出现的世界观文学表达标注了工程原型 |
| W19 | 新概念自足 | 新术语在此卷内有够用解释（不假设读者读过别卷） |

### 3.5 入门友好度

| # | 检查项 | 判定标准 |
|---|--------|---------|
| W20 | 500字定位 | 前500字内读者能回答：我在哪？谁的视角？发生什么？ |
| W21 | 新术语配额 | 本章新引入世界观术语 ≤ 3 个 |

### 3.6 三问落地

| # | 检查项 | 判定标准 |
|---|--------|---------|
| W22 | 逐场景可答 | 每个主要场景的 🩻 😣 🛤️ 能从正文中读出 |

**Prose Gate 通过标准**：
- 强制项 W1-W3：全部 ✅
- W4-W22：≥ 16/19 ✅
- W16-W19（术语）：全部 ✅（术语铁律是强制子项）

## 四、Review Gate（审阅门）

**位置**：Phase 4 审阅完成后
**目的**：确认审阅完成且问题已解决

| # | 检查项 | 判定标准 |
|---|--------|---------|
| R1 | 审校报告 ❌ 清零 | `/review-chapter` 报告中的 ❌ 项已全部解决 |
| R2 | 命名规范正确 | 系列名「万构界」、卷名「《万构界·X卷》」、无 `xx百炼成仙` 残留 |
| R3 | 跨卷引用自足 | 如有跨卷引用，本章内给了够用解释（不假设读者读过别卷） |
| R4 | 跨卷叙述独立 | 共享事件从本卷主角的代价和病理重新叙述 |
| R5 | 文学-工程对照 | 首次出现的世界术语建立了工程原型对应 |
| R6 | 章节间衔接 | 与前章的因果链连续（不是因为"该写下一章了"所以切换） |
| R7 | 批量一致性 | 如果同批写了多章，章节间无矛盾（人物、术语、时间线一致） |

**Review Gate 通过标准**：7/7 ✅

## 五、Commit Gate（提交门）

**位置**：git commit 前
**目的**：确认提交本身符合项目规范

| # | 检查项 | 判定标准 |
|---|--------|---------|
| C1 | 文件名正确 | `第XX章_标题_副标题.md`（如有副标题）或 `第XX章_标题.md` |
| C2 | 文件位置正确 | 在 `正文/XX_YY卷/` 下 |
| C3 | 无 AI 署名 | Commit message 中无 `Co-Authored-By: Claude` 或任何 AI/Claude 署名（铁律：CLAUDE.md） |
| C4 | Commit message 格式 | 格式：`feat: 驭器卷 ChXX-XX 卷X「卷名」——简要描述` |
| C5 | 无意外文件 | 只包含目标章节和关联的状态更新文件 |
| C6 | 进度面板已更新 | 本次提交涉及的章在进度面板中状态已更新 |

**Commit Gate 通过标准**：6/6 ✅（C3 为绝对强制项——任何违反 = 必须 amend commit）

## 六、质量门的串行执行

### 规则
1. **不跳级**：不能从 Phase 1 直接跳到 Phase 3
2. **不跳过**：每扇门都必须显式通过（不能"我觉得差不多"）
3. **不倒退**：一旦通过的门，后续修改如果触及该门的检查项，需要**重新过门**

### 重新过门的触发条件

| 后续修改 | 需要重新过的门 |
|---------|--------------|
| 修改了工程主题 | Design Gate |
| 大幅修改正文（>30%） | Prose Gate |
| 修改了跨卷引用 | Review Gate |
| 修改了文件名 | Commit Gate |

## 七、质量门反模式

| 反模式 | 为什么错 | 正确做法 |
|--------|---------|---------|
| "差不多就行" | 质量门形同虚设 | 每项给出明确的 ✅/❌，❌ 必须有修复计划 |
| 审阅者代替作者过 Prose Gate | Prose Gate 是作者的自我检查，审阅是第二道 | 作者先过 Prose Gate，审阅者过 Review Gate |
| 批量过门 | 10章一起过 Prose Gate → 问题重复10次 | 每章单独过 Prose Gate，5-10章批量过 Review Gate |
| 门过了但问题还在 | "形式上"打勾但没有实际检查 | 每项检查必须有具体证据（引正文行、引术语清单等） |
