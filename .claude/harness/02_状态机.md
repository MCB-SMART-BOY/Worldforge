# 02 · 状态机

> 所有产出物的生命周期状态定义。任何时候都应该能回答："这一章现在是什么状态？"

## 一、核心状态

每个章节产出物经过以下状态流转：

```
  [章纲]           [正文设计]         [正文]            [审阅]           [完成]
    │                │                 │                 │                │
    ▼                ▼                 ▼                 ▼                ▼
┌────────┐      ┌────────┐       ┌────────┐       ┌────────┐       ┌────────┐
│  待建   │      │  待建   │       │  待写   │       │  待审   │       │  完成   │
│        │      │        │       │        │       │        │       │        │
└───┬────┘      └───┬────┘       └───┬────┘       └───┬────┘       └────────┘
    │                │                 │                 │                 ▲
    ▼                ▼                 ▼                 ▼                 │
┌────────┐      ┌────────┐       ┌────────┐       ┌────────┐       ┌────────┐
│  已完成  │ ──→  │  已完成  │ ──→   │  草稿   │ ──→   │  已审   │ ──→   │ (提交)  │
│        │      │        │       │        │       │        │       │        │
└────────┘      └────────┘       └───┬────┘       └───┬────┘       └────────┘
                                     │                 │
                                     ▼                 ▼
                                ┌────────┐       ┌────────┐
                                │  自查   │ ──→   │  修改   │
                                │        │       │        │
                                └────────┘       └────────┘
```

## 二、状态定义

### 2.1 章纲（Chapter Outline）

| 状态 | 含义 | 如何判断 |
|------|------|---------|
| `待建` | Section 文件已创建，但六拍骨架未展开 | 文件行数 < 50 或只有标题 |
| `已完成` | 六拍骨架完整，工程主题明确，张力有设计，三问可答 | 文件行数 ≥ 100，包含六拍和张力设计 |

**状态示例**：
```
驭器卷 Ch51: 章纲 ✅ (已完成) — 2026-06-13
驭器卷 Ch52: 章纲 ✅ (已完成) — 2026-06-13
```

### 2.2 正文设计（Body Design）

| 状态 | 含义 | 如何判断 |
|------|------|---------|
| `待建` | 未开始或仅有占位 | 文件不存在或只有标题 |
| `已完成` | 本章的正文设计文档就绪（读导、样场、入口设计等） | 正文设计文件存在且有实质内容 |

**注意**：不是每章都需要独立的正文设计文件。`正文设计/` 目录通常包含的是卷级设计文档和样场。章级设计由 `/design-chapter` 产出，整合在写作流程中。

### 2.3 正文（Prose）

| 状态 | 含义 | 如何判断 |
|------|------|---------|
| `待写` | 章纲已完成，正文未开始 | 文件不存在 |
| `草稿` | 正文已起草但未自查 | 文件存在，未执行 `/review-chapter` |
| `自查` | 已执行 `/review-chapter`，待修改 | 审校报告存在，有未解决的 ❌ |
| `修改` | 根据审校报告修改中 | — |
| `已审` | `/review-chapter` 通过（所有 ❌ 清零），待外部审阅 | 审校报告 ✅ |
| `完成` | 所有质量门通过，已提交 | git 已 commit |

**状态流转规则**：
- `待写 → 草稿`：正文起草完成
- `草稿 → 自查`：执行 `/review-chapter`
- `自查 → 修改`：审校发现 ❌
- `修改 → 自查`：修改后重新审校
- `自查 → 已审`：审校全部 ✅
- `已审 → 完成`：Review Gate + Commit Gate 通过

### 2.4 人物卡（Character Card）

| 状态 | 含义 | 如何判断 |
|------|------|---------|
| `待建` | 角色已命名但卡未写 | 文件不存在 |
| `骨架` | 9-section 模板已填但未深化 | 文件存在，部分 section 标注"待补" |
| `已完成` | 全部 9 sections 充实 | 无 "待补" 标记 |

### 2.5 资料（Research/Reference）

| 状态 | 含义 |
|------|------|
| `待建` | 资料条目已知，未收集 |
| `初稿` | 资料已收集，未整理 |
| `已完成` | 资料整理完毕，可作为写作参考 |

## 三、全卷状态汇总格式

### 3.1 卷级状态表（放在各卷 `00_卷索引.md` 中）

```markdown
## 📊 进度状态

| 卷段 | 章范围 | 章纲 | 正文设计 | 正文 | 审阅 | 备注 |
|------|--------|------|---------|------|------|------|
| 卷一「重器」 | Ch1-10 | ✅ | — | 9/10 | 9/10 | Ch10待写 |
| 卷二「追火」 | Ch11-20 | ✅ | — | 10/10 | 10/10 | ✅ |
| 卷三「空位」 | Ch21-30 | ✅ | — | 8/10 | 8/10 | Ch21,27-28待写 |
| ... | ... | ... | ... | ... | ... | ... |
```

### 3.2 进度编码

| 编码 | 含义 |
|------|------|
| `✅` | 全部完成 |
| `N/10` | N章完成，10-N章待推进 |
| `—` | 不适用（如正文设计不是章级产物） |
| `🔴` | 有阻塞问题 |
| `🟡` | 进行中 |
| `⚪` | 未开始 |

## 四、状态变更触发条件

### 4.1 章纲：待建 → 已完成

**触发条件**：
- 六拍骨架全部展开（每拍 ≥ 2 行具体描述）
- 工程主题明确（列出 ≥ 3 个真实工程术语）
- 张力设计有曲线形态和揭示节奏
- 三问可预答

### 4.2 正文：待写 → 草稿

**触发条件**：
- 正文文件已创建
- 长度 ≥ 2000 字
- 文件名符合规范

### 4.3 正文：草稿 → 自查

**触发条件**：
- 已执行 `/review-chapter`（或手动对照审校清单）
- 审校报告已产出

### 4.4 正文：自查 → 已审

**触发条件**：
- 审校报告所有 ❌ 项已清零
- 三总裁定 ✅
- 六拍结构完整
- 术语铁律遵守
- 三问全部可答

### 4.5 正文：已审 → 完成

**触发条件**：
- Review Gate 全部通过
- Commit Gate 全部通过
- git commit 成功

## 五、全局状态追踪

`07_进度面板.md` 包含所有四卷 480 章的全局状态。每完成一章，更新：

1. 该卷 `00_卷索引.md` 中的卷级状态表
2. `07_进度面板.md` 中的全局状态表

### 更新流程

```
完成一章
    │
    ├── 更新对应卷 00_卷索引.md 的进度状态表
    │   └── 修改对应卷段的 N/10 数字
    │
    └── 更新 07_进度面板.md 的全局状态表
        └── 修改对应卷和章的状态编码
```

## 六、状态查询

### 6.1 快速查询："现在做到哪了？"

1. 读 `07_进度面板.md` → 全局概览
2. 定位第一个 `待写` 或 `草稿` 或 `自查` 状态的章
3. 读该章的章纲和前后文 → 开始工作

### 6.2 精确查询："第X卷第Y章是什么状态？"

1. 读对应卷 `00_卷索引.md` 进度状态表
2. 读正文文件（如存在）→ 确认实际状态

### 6.3 批量查询："哪些章需要审阅？"

1. 读 `07_进度面板.md`
2. 筛选状态为 `草稿`、`自查`、`修改` 的章
3. 按卷和章号排序 → 从最早的开始审

## 七、状态机反模式

| 反模式 | 为什么错 |
|--------|---------|
| 正文写了但章纲状态没更新 | 进度面板失准——下次会话不知道实际进展 |
| 跳过自查直接标记"完成" | 质量门被绕过——问题留在正文里 |
| "已完成"后偷偷修改正文 | 修改后应该重新过 Prose Gate |
| 状态表只在提交时更新 | 进度面板应反映实时状态，不是提交后才更新 |
