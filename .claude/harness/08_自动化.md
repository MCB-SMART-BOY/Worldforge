# 08 · 自动化

> 可脚本化的重复检查。不是替代人工审阅——是让人工审阅聚焦于**只有人才能判断的事**。

## 一、自动化哲学

在写作项目中，自动化与软件项目的自动化有本质区别：

| 维度 | 软件项目自动化 | 写作项目自动化 |
|------|--------------|--------------|
| 能自动化什么 | 编译、测试、lint、格式化 | 格式检查、术语核对、文件校验 |
| 不能自动化什么 | 架构设计、UX判断 | 文学质量、张力感知、情感共鸣 |
| 自动化目的 | 快速反馈，防止回归 | 消除机械错误，让审阅聚焦文学判断 |

**原则**：自动化机械检查，保留人文判断。

## 二、可自动化的检查

### 2.1 文件名规范检查

```bash
# 检查正文文件名是否符合规范
# 正确格式：第XX章_标题.md 或 第XX章_标题_副标题.md

find 正文/ -name "第*章*.md" | while read f; do
  basename=$(basename "$f")
  if ! echo "$basename" | grep -qP '^第\d+章_.+\.md$'; then
    echo "⚠️ 文件名不规范: $f"
  fi
done
```

### 2.2 术语标注检查（铁律四之补充）

```bash
# 检查常见中文CS术语是否标注了英文原名
# 关键词列表（非穷举，来自 canon/24）

terms=(
  "所有权:ownership"
  "借用检查器:borrow checker"
  "健康检查:health check"
  "构建系统:build system"
  "版本控制:version control"
  "依赖:dependency"
  "回滚:rollback"
  "发布:release"
  "提交:commit"
  "分支:branch"
)

for f in 正文/01_驭器卷/第4*.md; do
  for term in "${terms[@]}"; do
    zh="${term%%:*}"
    en="${term##*:}"
    # 检查中文术语出现时是否至少有一次带了英文括号
    if grep -q "$zh" "$f" && ! grep -q "$zh（$en）" "$f"; then
      echo "⚠️ $f: '$zh' 未标注英文原名 '$en'"
    fi
  done
done
```

### 2.3 命名规范检查

```bash
# 检查是否残留废弃命名
grep -rn "百炼成仙" 正文/ && echo "❌ 发现废弃命名残留"
grep -rn "xx百炼" 正文/ && echo "❌ 发现废弃命名残留"

# 检查卷名格式
# 应为：万构界 · X卷
grep -rn "万构界" 正文/ --include="*.md" | grep -v "万构界·" | grep -v "万构界 " && echo "⚠️ 可能的命名格式问题"
```

### 2.4 章节连续性检查

```bash
# 检查某卷是否有章节号跳跃
vol="$1"
ls "正文/${vol}/" | grep -oP '第\K\d+' | sort -n | awk 'NR>1 && $1!=prev+1 {print "⚠️ 章节跳跃: " prev " → " $1} {prev=$1}'
```

### 2.5 Commit Message 格式检查

```bash
# 在 pre-commit hook 中运行
# 检查是否包含 Co-Authored-By: Claude（绝对禁止）

if git log -1 --format='%B' | grep -qi "co-authored-by.*claude\|co-authored-by.*ai\|co-authored-by.*anthropic"; then
  echo "❌ 铁律违反：commit message 包含 AI 署名"
  echo "请 amend commit 移除 Co-Authored-By 行"
  exit 1
fi
```

## 三、推荐的 Git Hooks

### 3.1 Pre-commit Hook

位置：`.git/hooks/pre-commit`（需手动安装）

```bash
#!/bin/bash
# 万构界 pre-commit 检查

PASS=true

# 1. 检查是否有 Co-Authored-By: Claude 在 staged 的 commit message 中
# （这在实际 commit 时检查，不是在 staged files 中）

# 2. 检查文件名规范
STAGED_CHAPTERS=$(git diff --cached --name-only --diff-filter=ACM | grep '^正文/.*第.*章.*\.md$')
for f in $STAGED_CHAPTERS; do
  basename=$(basename "$f")
  if ! echo "$basename" | grep -qP '^第\d+章_.+\.md$'; then
    echo "⚠️ 文件名不规范: $basename"
    echo "   期望格式: 第XX章_标题.md"
    PASS=false
  fi
done

# 3. 检查废弃命名
if git diff --cached -U0 | grep -q "百炼成仙"; then
  echo "❌ staged 更改中包含废弃命名「百炼成仙」"
  PASS=false
fi

if [ "$PASS" = false ]; then
  echo ""
  echo "以上问题不会阻止提交，但请尽快修复。"
fi

exit 0
```

### 3.2 Commit-msg Hook

位置：`.git/hooks/commit-msg`

```bash
#!/bin/bash
# 检查 commit message 格式

MSG=$(cat "$1")

# 禁止 AI 署名
if echo "$MSG" | grep -qi "co-authored-by.*claude\|co-authored-by.*ai\|co-authored-by.*anthropic"; then
  echo "❌ 铁律违反：commit message 不得包含 AI/Claude 署名"
  echo "请移除 Co-Authored-By 行后重新提交。"
  exit 1
fi

exit 0
```

## 四、批量操作脚本

### 4.1 生成术语检查报告

```bash
#!/bin/bash
# 对指定范围内的章节执行术语标注检查
# 用法: bash check_terms.sh 驭器卷 45 50

VOL="$1"  # 如 01_驭器卷
START="$2"
END="$3"

echo "=== 术语标注检查：${VOL} Ch${START}-${END} ==="

# 常见需要标注的术语（来自 canon/24）
declare -A TERMS=(
  ["构建系统"]="build system"
  ["版本控制"]="version control"
  ["依赖"]="dependency"
  ["回滚"]="rollback"
  ["所有权"]="ownership"
  ["内存安全"]="memory safety"
  ["并发"]="concurrency"
  ["静态分析"]="static analysis"
  ["动态检查"]="dynamic check"
  ["编译器"]="compiler"
  ["链接器"]="linker"
  ["调试器"]="debugger"
  ["健康检查"]="health check"
  ["负载均衡"]="load balancing"
  ["发布"]="release"
  ["部署"]="deploy"
  ["回退"]="rollback"
  ["迁移"]="migration"
  ["兼容性"]="compatibility"
  ["接口"]="interface"
  ["抽象"]="abstraction"
  ["泛型"]="generics"
  ["模板"]="template"
  ["宏"]="macro"
  ["测试"]="test"
  ["文档"]="documentation"
)

for ch in $(seq -w $START $END); do
  file="正文/${VOL}/第${ch}章_"*.md
  # expand glob
  file=$(echo $file)
  if [ ! -f "$file" ]; then
    echo "Ch${ch}: 文件不存在"
    continue
  fi
  
  issues=""
  for zh in "${!TERMS[@]}"; do
    en="${TERMS[$zh]}"
    # 检查是否出现中文术语但未在全文任何一处标注英文
    if grep -q "$zh" "$file" && ! grep -q "${zh}（${en}）" "$file"; then
      issues="$issues  $zh→$en"
    fi
  done
  
  if [ -n "$issues" ]; then
    echo "Ch${ch}: ⚠️ 未标注$issues"
  else
    echo "Ch${ch}: ✅"
  fi
done
```

### 4.2 生成章节进度报告

```bash
#!/bin/bash
# 生成某卷的章节存在性报告
# 用法: bash chapter_report.sh 01_驭器卷

VOL="$1"
DIR="正文/${VOL}"

echo "=== ${VOL} 章节存在性报告 ==="
echo ""

total=0
written=0
missing=""

for ch in $(seq -w 1 120); do
  total=$((total + 1))
  match=$(ls "$DIR"/第${ch}章_*.md 2>/dev/null | head -1)
  if [ -n "$match" ]; then
    written=$((written + 1))
  else
    missing="$missing $ch"
  fi
done

echo "总计: $written/$total"
echo "完成率: $(( written * 100 / total ))%"
if [ -n "$missing" ]; then
  echo "缺失: $missing"
fi
```

## 五、自动化与质量门的关系

| 质量门 | 自动化检查 | 人工判断 |
|--------|----------|---------|
| Prep Gate | 章纲文件存在性 | 内容是否足够具体 |
| Design Gate | 术语清单完整性（≥5） | 张力曲线是否有效 |
| Prose Gate | 术语标注检查、命名检查 | 六拍结构、张力呈现、情感锚点 |
| Review Gate | 文件名规范、跨卷引用存在性 | 跨卷叙述独立性、因果链连续性 |
| Commit Gate | Commit message 无 AI 署名、文件名正确 | — |

## 六、自动化反模式

| 反模式 | 为什么错 |
|--------|---------|
| 过度自动化 | 试图用脚本判断"张力够不够"——这是人的判断域 |
| 自动化从不运行 | 写了脚本但从不执行——等于没写 |
| 自动化替代审阅 | 脚本全绿 ≠ 章节质量过关 |
| 自动化成为瓶颈 | 因为脚本报 warning 就不提交——warning 是提醒，不是阻止 |
