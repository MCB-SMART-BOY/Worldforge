# 卷八「删模版」Ch 71-80：极简主义

## Section 总览

- **章段**：Ch 71-80
- **叙事主题**：模板从43项瘦到4项——不是删减本身——是"留下来的每一项——为什么它是必填的"。极简不是"少"——是"每一项都有被写下来的理由"。傅远洲与周栖野（化形卷主角）跨卷对话——"制度vs空白"——两个"少"的碰撞。
- **核心冲突**：简洁哲学的边界。Go的哲学是"少即是多"——但"少"有两面：(a) 少=让后来者思考更少——这是好的少 (b) 少=让后来者不知道——这是坏的少。傅远洲要划出这条边界——而周栖野的"空白"给了他一个对照。
- **工具链阶段**：极简主义实践 / 默认值系统审计 / 设计决策记录（ADR）/ 模板声明
- **对象层**：式→式（从模板的结构——到"为什么选这个结构"——结构的理由比结构本身更重要）
- **主相→蚀**：式 → 失式（模板本身变成"式"——但"式"如果失去了"为什么"——就从骨架变成束缚）
- **主角状态**：傅远洲从制度建立者到制度质疑者——"我建立的制度——会不会也变成另一种'43条传讯牌'？"与周栖野的对话让他看到了"少"的另一个极端——"少到没有痕迹"——那也不是答案。
- **跨卷锚点**：**Ch75 跨卷对话（傅远洲↔周栖野）**——制度vs空白。化形卷Ch95-97的对话从简阵卷视角重述。
- **卷尾落点**：模板瘦了——但瘦不是目的。让后来者知道"为什么选这些"才是。制度有了——但新人能接住吗？向卷九过渡。

### 第71章：删模版

- **核心对象层**：式→式（"43项模板——每一项都是'前人觉得好'。但前人觉得好——不等于后人需要。模板的每一行——都是一种负担——'不填就不能部署'——但有些项——没有人知道为什么要填。"傅远洲决定删模板——从43项减到4项。）
- **核心相与失守**：式 → 失式（模板本是"式"——结构、骨架。但当模板膨胀到43项——每一项都是"必须填"——式就从骨架变成了束缚——从帮助变成了障碍——因为填的人不知道"为什么必须填"。）
- **工程锚点**：模板极简主义（template minimalism）——不是"越少越好"——是"每一项必填项——都有可以被质疑的公开理由"。删模板的法则：(1) 如果没有人能说出"为什么这一项是必填的"——它不是必填的 (2) 如果可以自动化——它不该是必填的 (3) 如果问三个不同的人会得到三个不同的答案——它不是必填的——是混乱。
- **张力曲线**：对抗型（"为什么要删第17项——那是我们当年花了很多时间设计的！""当年为什么设计它？""因为......当时有个问题——需要这个检查——""那个问题现在还存在吗？""......不知道。""不知道——就是可以删。"）
- **角色焦点**：傅远洲（"每一项我删掉的模板——都是一个前人觉得重要的判断。我不是否定他们的判断——我是让'他们的判断'变成'现在的判断'——不是'过去的默认'。"）
- **六拍骨架**：
  1. 问题先出：傅远洲审视43项模板——问团队每一项"为什么它是必填的"——超过一半的答案以"以前......"开头
  2. 为什么痛：模板是给后来者的——但后来者被43项"必须"压住了——填模板的时间比写代码还长——"以前需要"变成了"现在不知道为什么要——但不敢删"
  3. 引出方法：删模板的三法则——(a) 说不出"为什么"→不是必填 (b) 可以自动化→不该必填 (c) 三个不同答案→混乱——不是必填
  4. 项目落地：傅远洲删掉了39项——留下4项——每一项旁边写了"为什么它留下来了"
  5. 多方复盘："删不是否定前人的判断——是把前人的判断从'默认'变回'判断'——让它重新被审视。"
  6. 高层收束：真正的简洁——不是少到没有——是每一项都有被质疑过的理由。

- **并发/观测/简洁/部署**：—/—/43→4/—

### 第72章：每项的理由

- **核心对象层**：式→约（留下来的4项——每一项旁边写了"为什么它在必填层"。这不仅仅是模板——这是**设计决策记录（ADR）**的雏形。每一项都不是"就应该这样"——而是"傅远洲选择这样——以下是他的选择依据"。）
- **核心相与失守**：契 → （正向——建立公共契约。"为什么这些是必须的"——从"我说是就是"变成"这是选择依据——你可以质疑——但质疑前先读它。"）
- **工程锚点**：设计决策记录（Architecture Decision Record / ADR）——不是"我决定了"——是"我决定了——这是我的决策上下文（context）——我的约束（constraints）——我考虑的替代方案（alternatives）——我预期此决策的保质期（expiry）。"每一项必填项附带的"为什么"——就是一个小型ADR。
- **张力曲线**：建设型（傅远洲为留下的4项各自写"为什么"——第1项：服务名称和负责人——"没有owner的服务会在凌晨找不到能接传讯牌的人"——这是从卷二Ch11-20学到的。第2项：资源请求（CPU/内存/磁盘）——"没有资源声明的服务——在OOM时是第一个被杀的"——这是从卷七Ch67学到的。第3项：依赖服务列表——"不声明依赖——你的变更可能杀了我——我的变更可能杀了你"——这是从卷三Ch21-30学到的。第4项：健康检查端点——"但注意：健康检查只查心跳——不等于'它在做正确的事'"——这是从卷五学到的。每一项——都是一个事故的教训。）
- **六拍骨架**：
  1. 问题先出：过去43项模板——每一项都是"必须"——但没有一项解释"为什么必须"
  2. 为什么痛：后来者看到"必须"——要么盲从——要么绕过——不会思考"为什么"
  3. 引出方法：每项附带"为什么"——写清楚"这一项是从哪个事故中学到的——不填的代价是什么"
  4. 项目落地：4项——每项附带依据——依据追溯到具体的事故章节（卷二的凌晨对账、卷三的日志端点、卷七的OOM）
  5. 多方复盘："不是傅远洲的权威让这些成为必填——是事故的教训让这些成为必填。傅远洲只是写了'教训的来源'。"
  6. 高层收束：设计决策不是权力——是责任。决定者必须为每一个决定——附带它成立的前提。

### 第73章：默认值审计

- **核心对象层**：史→史（全平台默认值审计——512MB只是冰山一角。傅远洲和团队审计了驿河51个服务的所有默认值——发现23个默认值"理由不可追溯"。每一个——都是定时炸弹。）
- **核心相与失守**：史 → 断史（默认值的理由丢失——等于"历史上做了一个聪明的决定——但后人不知道当时聪明在哪"——这比"做了愚蠢的决定"更危险——因为聪明决定在条件变化后会变成愚蠢决定——但后人看不到"条件变化"——因为他们看不到原始条件。）
- **工程锚点**：默认值系统审计（default value systematic audit）——不只是审计数字——是审计"数字背后的假设"。审计表：(1) 默认值 (2) 设定时间 (3) 设定人 (4) 当时的环境参数（服务数量/资源/负载）(5) 现在的环境参数 (6) 差异风险评级。
- **张力曲线**：考古型（从Ch66-69的512MB单点追查——扩展到全平台23个默认值——每一个背后都有一个"温故来"——做了聪明的判断——但理由丢了。傅远洲——"不止512MB。驿河的默认值——是一个等待被引爆的雷区。"）
- **六拍骨架**：
  1. 问题先出：512MB审计完成后——傅远洲决定审计全平台所有默认值
  2. 为什么痛：23个默认值理由不可追溯——每一个都可能在某天变成OOM、超时、拒绝服务
  3. 引出方法：默认值审计表——系统性追溯每一个默认值的"出生证"——对找不到理由的——标记"待审计"——暂时替换为保守值
  4. 项目落地：23个默认值中的18个找到了来源（by问老员工、翻旧文档、查部署记录）——5个完全无法追溯——标记"待审计"——替换为保守值
  5. 多方复盘："默认值是文明的'遗留智慧'——但智慧如果不说出'为什么'——就是'遗留炸弹'。"
  6. 高层收束：审计不是追责——是追"理由"。每一个被找回的理由——都是驿河的历史被重新连接。

### 第74章：三年前的故事

- **核心对象层**：史→史（温故来的规矩——"先看负载模式再设"——这十个字是修补者教的。温故来遵守了——看了11个服务的负载模式——设了512MB。他做了对的事——但他没有把"11个服务的负载模式"写下来——所以三年后——后人只看到512MB——看不到"11个服务"这个关键前提。）
- **核心相与失守**：史 → 断史（修补者教了方法——没教"方法的前提也需要被传递"。这不是恶意——是认知局限。修补者那代人——面对的是"从无到有建立秩序"——他们不习惯"秩序会被传给后人"——因为秩序对他们来说——是自己建的——不是接的。）
- **工程锚点**：默认值的完整传递——不是传数字——是传"数字+前提条件+为什么"。温故来的512MB——如果附带"当前11个服务——单服务最大512MB——总内存8GB——余量约2.4GB"——三年后51个服务时——后人会看到"前提变了——数字需要重新计算"。
- **张力曲线**：回忆型（傅远洲找到温故来留下的笔记——薄薄几页——"先看负载模式再设"的十个字旁边——有温故来画的草图——11个服务的调用关系——5.6GB总计——2.4GB余量。"他画了——但没写到默认值旁边。他的理解在草图上——但他的默认值在配置文件里——两个地方——没有连接。"）
- **角色焦点**：傅远洲（"温故来不是错了——是他做的判断和判断的依据——被储存在两个不同的地方。配置文件里——是判断。草图上——是依据。后来者只看到配置文件——没看到草图。这不是他的错——是他没有被告知：依据和判断——必须放在一起。"）
- **六拍骨架**：
  1. 问题先出：傅远洲找到了三年前温故来的笔记——看到了"先看负载模式再设"和草图
  2. 为什么痛：判断和依据被分离了——后来者继承了判断（512MB）——但无法继承依据（11个服务——8GB机器）
  3. 引出方法：默认值的"依据旁注"——每一个默认值旁边——必须写清楚当时的计算依据——不是附件——不是另一份文档——是旁边
  4. 项目落地：傅远洲在默认值审计规则中加了第六条——"依据必须与默认值在同一个文件中——不可分离。分离——等于丢失。"
  5. 多方复盘："修补者教温故来'先看负载模式再设'——温故来看了——但他写的是'512MB'——不是'因为总负载5.6GB+余量2.4GB→单服务最大512MB'。他写了答案——没写推导。"
  6. 高层收束：三年前——一个修补者的学生做了一个正确的判断。三年后——那个判断杀了凌晨的服务。不是判断错了——是判断的前提没有和判断一起传递。

### 第75章：制度vs空白

- **核心对象层**：念→念（**跨卷对话章**——傅远洲与周栖野（化形卷主角）的对话。两个最极端的"少"碰撞——驿河的"制度之少"（43→4）和息壤的"空白之少"（周栖野信奉的速度自足——"不做多余的事"）。）
- **核心相与失守**：（跨卷哲学对话——不是工程话题——是两个主角在世界观层面的对质。周栖野的"少"是：不做多余的事——速度够快——问题就能被追到——不需要预设制度。傅远洲的"少"是：每一项制度都有被质疑过的理由——只有经过事故验证的才留下。）
- **工程锚点**：制度与空白的边界——什么时候需要制度——什么时候制度本身就是多余的。两个"少"主义的对比：(1) 周栖野的"少"=空白——因为"速度够快——可以把制度省略——出问题再追" (2) 傅远洲的"少"=筛选——因为"制度是从事故中提炼的——每一项都有血的代价——不能省略——但也不能膨胀"。
- **张力曲线**：对峙型（周栖野路过驿河——看到记录板上的4项模板——"你们的模板只有4项？""从43项删的。""43项——太可怕了。在息壤——我们没有模板。""没有模板？""不需要。够快就行——出问题追得到。""但我们凌晨一点十四的OOM——追得到——但那个接传讯牌的人——她凌晨一点不该醒着。"）
- **角色焦点**：傅远洲↔周栖野（两个主角的首次深度对话——傅远洲的"制度是地板不是天花板"vs周栖野的"标注是有语境的"。）"你的4项——总有一天会有人觉得'4项也是多余的'。""对——所以我在每一项旁边写了'为什么'。不是为了证明它必须永远在——是为了让后来者知道——'如果这个为什么不再成立了——这一项可以删'。""你写的'为什么'——是语境。但语境会变。""对——所以每一项都有保质期。标注'为什么'——是标注'这个决策在什么前提下成立'。前提变了——决策该被重新审视。"）
- **六拍骨架**：
  1. 问题先出：周栖野路过驿河——看到极简模板——两个主角开始对话
  2. 为什么痛：两种"少"的对比——"空白"和"有理由的少"——后者不是更"多"——是更"诚实"
  3. 引出方法：制度的本质——不是"因为前人觉得好所以必须遵守"——是"因为前人用代价换来——所以写下来——但它有自己的保质期"
  4. 项目落地：傅远洲在模板第一页（see Ch78）加上了"此选择可能不完整"——这是周栖野"标注是有语境的"给他的启示
  5. 多方复盘：傅远洲——"你说的是对的——空白是好的——但空白的前提是：每一个人都知道方向。驿河的新人——凌晨接传讯牌——没有方向——制度是他们的地板。"
  6. 高层收束：制度不是越多越好——空白也不是。制度是"在地板上铺一层——让人不至于掉下去"。地板不是天花板——天花板是留给后来者的。

- **跨卷锚点**：傅远洲↔周栖野对话——与化形卷Ch95-97（周栖野的弧线收束）形成跨卷对称。对话内容在简阵卷侧重述——从傅远洲的视角理解周栖野的"空白"。

### 第76章：制度是地板不是天花板

- **核心对象层**：念→念（傅远洲的核心哲学陈述——"制度能保证有人接传讯牌。制度不能保证接的人会在手册上多写一行。制度是地板——防止掉下去。天花板——是后来者自己建的。"）
- **工程锚点**：制度的边界——制度能做什么（on-call轮值、回滚锚点、变更声明）——不能做什么（让接传讯牌的人多写一行注、让新人在凌晨独自判断、让后来者理解"为什么"）。制度是必要条件——不是充分条件。
- **张力曲线**：反思型（傅远洲独白——"我建的制度——所有权、on-call、观测、契约、行序——都在。但乔落凌晨写'待补'——不是任何制度要求的。制度没有说'你必须在手册上多写一行'——她写了——因为她是乔落——不是因为制度。"）
- **六拍骨架**：
  1. 问题先出：傅远洲反思——制度健全了——但"乔落的那行注"是制度之外的事
  2. 为什么痛：制度是地板——保证不会太差。但"好"——从来都是人做的——不是制度做的
  3. 引出方法：制度的角色——不是替代人的判断——是让人在判断时——有一个安全的底线
  4. 项目落地：在模板第一页加注——"以下必填项由傅远洲选定。此选择可能不完整。"（see Ch78）
  5. 多方复盘：制度给了地板——但天花板——要后来者自己建。"你不能替后来者走——你只能给他们路。"
  6. 高层收束：地板让人不摔死。天花板——让后来者可以想飞多高飞多高。不要把你的天花板——变成别人的地板。

### 第77章：乔落的那行注

- **核心对象层**：史→史（从Ch68"回滚路径标注待补"的延续——乔落的那行注在整个驿河传播。不是因为她写了什么了不起的东西——是因为"一个三个月的新人——在凌晨——在手册上写下了手册没有的东西"。）
- **核心相与失守**：（继承——正向。乔落的注是"继承"本身在行动——不是被动接受——是主动补充。"制度说——on-call要接传讯牌。制度说——事故要记录。制度没说——'如果你发现手册不完整——你要补充'。乔落做了制度没说的事。"）
- **工程锚点**：runbook的协作进化——手册不是一个人的产物——是所有处理过事故的人的共同笔记。乔落的注——"峰值高于上月约百分之十五"——被追踪到后续四个人——各自在它旁边加了补充。
- **张力曲线**：沉静型（傅远洲在手册上看到乔落的那行注——旁边多了四个人的笔迹——"确认。上月峰值确实低——因为上月有此服务的降级事件。" "此注已在部署窗口中考虑——同步峰值不能部署。" "建议加入默认值审计——峰值变化可能改变资源需求。" "已加入。见默认值审计第17条。"）
- **六拍骨架**：
  1. 问题先出：乔落凌晨的注——旁边多了四个人的笔迹
  2. 为什么痛：不是她的注有多准确——是她的注启动了四个人接力——"一行注——变成了五个人的共识。"
  3. 引出方法：runbook的社会性——好的手册不是"写完整"的——是"被接力"的——每个人加一点——逐步逼近完整
  4. 项目落地：傅远洲意识到——手册的签名不是权利——是责任。每一个签名——不意味着"这部分是我负责的"——意味着"这部分如果有错——我来修正"
  5. 多方复盘："乔落写的是'待补'——不是'我知道了'。她承认不知道——所以请后来者补充。'待补'是驿河最诚实的词。"
  6. 高层收束：最好的继承——不是一个人把知道的全写下来——是每个人都在别人写了的基础上——多写一行。"制度是地板。乔落的那行注——是天花板的第一块砖。"

### 第78章：模板第一页

- **核心对象层**：约→约（傅远洲在模板第一页加判断声明——"以下必填项由傅远洲选定。此选择可能不完整。"这是他从周栖野"标注是有语境的"得到的启示——也是他对"制度是地板不是天花板"的实践。）
- **工程锚点**：模板的"自反声明"——模板不是"这是真理"——是"这是傅远洲基于驿河的事故历史——在当前的语境下——选定的必填项"。(a) 声明选择者——"由傅远洲选定"——不是匿名的权威——是具体的人的选择 (b) 声明不完整——"可能不完整"——承认模板不是最终版 (c) 声明可以被质疑——"如果你认为某项不该是必填——或某项应该是必填但不在——来找我。"
- **张力曲线**：沉静型（傅远洲写完声明——"这可能是驿河最重要的四行字——不是因为它们正确——是因为它们承认自己可能不完整。"）
- **六拍骨架**：
  1. 问题先出：模板瘦了——43→4——但傅远洲意识到——"如果我不说'这是我选的'——后来者会认为'这是真理'。"
  2. 为什么痛：不加声明——模板就是新版的"43项"——不过数量少了——但权威感没变
  3. 引出方法：模板第一页——自反声明——让模板从"权威"变成"选择"——"选择可以被质疑——权威不能被质疑"
  4. 项目落地：傅远洲在模板第一页写下四行声明——团队看了——"这四行——比4项模板更重要。4项模板可能过期——但这四行——告诉后来者'它们可能过期'。"
  5. 多方复盘："最好的模板——是告诉后来者——'这个模板可能不完整——你来完善它'。"
  6. 高层收束：声明不完整——不是示弱——是给后来者空间。告诉他们——"我们建了地板——天花板是你的事。"

### 第79章：删模版之后

- **核心对象层**：式→史（模板瘦了——默认值审计了——制度有了自反声明。但"瘦不是目的"——目的是"让后来者知道——为什么选这些——不选那些"。删模版的真正成果——不是4项模板——是每一项旁边的"为什么"——和模板第一页的"此选择可能不完整"。）
- **工程锚点**：从"删模版"到"制度文化"——删是动作——但不删什么、为什么删——是文化。驿河现在有：(1) 4项必填模板——每项附带事故来源 (2) 默认值审计表——每个默认值附带环境前提 (3) 变更五问——每次变更附带影响声明 (4) 模板第一页——自反声明。
- **张力曲线**：建设型（记录板上——从Ch01的"51个服务——23个人——模板全绿"——到现在——"4项模板——每一项旁边写了'为什么'——模板第一页——写了'此选择可能不完整'。"这不是'到了'——这是'开始知道怎么走'。"）
- **六拍骨架**：
  1. 问题先出：删模版完成——但傅远洲回顾——"我们做了什么——只是删了39项模板吗？"
  2. 为什么痛：如果只是删——下一任负责人可以加回来——因为加回来不需要理由——"因为以前有"
  3. 引出方法：留下的不是模板——是文化。"每一项留下的——附带'为什么'。每一个被删的——附带'为什么删'。"理由——是文化的抗体——防止膨胀回潮
  4. 项目落地：删模版日志——记录了43项→4项的完整过程——每一项的去留——都有理由
  5. 多方复盘："删不是一次性的——是持续性的。只要'为什么'还在——后人就能继续删——当理由不再成立时。"
  6. 高层收束：极简不是结果——是过程。是持续地问——"这一项——现在——还有理由存在吗？"

### 第80章：新手之前

- **核心对象层**：人→人（过渡章——模板瘦了——制度有了——默认值审计了。但"制度能不能让新人接住？"——这是卷九的命题。乔落在Ch67的OOM中独立处理了——但那是"乔落"——不是"任何新人"。"制度照顾了'正常'——但凌晨从来不是正常。"）
- **工程锚点**：制度的边界——制度是给"正常情况"设计的——但事故是"不正常"。新人在凌晨面对"不正常"——能依靠的不是制度——是她自己的判断。"制度能给地板——但判断是天花板。"
- **张力曲线**：过渡型（傅远洲在记录板前——"我们有了最好的制度——最少的模板——最完整的审计。但下一个凌晨接传讯牌的新人——这些能帮到她吗？""能——给她地板。但判断——她需要自己建。"）
- **六拍骨架**：
  1. 问题先出：制度完备——但傅远洲不安——"制度是为了'不会再出问题'——但问题总会出新的"
  2. 为什么痛：制度是对过去的回答——未来会问制度没有覆盖的问题
  3. 引出方法：制度的终极测试——不是"它能不能防止已知的坑"——是"它能不能让新人面对未知的坑时——不至于掉到底"
  4. 项目落地：向卷九过渡——"乔落能接住了——但制度够不够让所有后来者都能接住？"
  5. 多方复盘：傅远洲——"下一个凌晨——传讯牌响——我希望接的人——有地板——也有判断。地板是我们给的——判断是她自己的。"
  6. 高层收束：制度能防住已知。但"未知"——是制度永远慢一步的地方。让后来者面对未知时能有地板——是制度的全部意义。
