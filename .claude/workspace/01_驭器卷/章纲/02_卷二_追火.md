### 第11章：托火之后

- **核心对象层**：[见Section总览]
- **核心相与失守**：史 → 断史
- **工程锚点**：跨卷人物——苏野平从明契来访
- **张力曲线**：攀升型（断火暂压→临时方案在变成永久→苏野平到来——跨卷新视角）
- **角色焦点**：纪承钧（焦虑——临时方案在变成永久方案）；苏野平（跨卷来访——提供外部视角）；钟守玄（'它在跑。别碰它。'）
- **六拍骨架**：
  1. 断火事故暂压两天后，纪承钧发现钟守玄的临时托火方案仍在运行——它正在变成永久方案
  2. 临时方案每多活一天，就越难被替换——因为它已经在支撑真实的外部系统。代价落在那些开始依赖临时方案的外部调用方
  3. 苏野平从明契来访——带着跨道依赖分析的经验。'我在明契那边见过类似的东西——但你们的更老'
  4. 纪承钧和苏野平一起审查临时方案——发现它不只是一个补丁，而是一个未经声明的wrapper
  5. 钟守玄：'它在跑。别碰它。'——守门者的保守不是因为懒，是因为怕。沈照痕：'不碰它——下次断火的时候它还在这，而你已经忘了它是怎么跑的'
  6. 临时方案不是问题——'临时'本身才是问题。因为没有人会给临时方案写文档

- **工程锚点**：跨卷互文——明契vs驭器的工程文化对比

  4. 纪承钧第一次看到'别人是怎么构建的'——意识到玄枢的构建方式不是'正常'，是'幸存'

### 第13章：依赖图初绘

- **核心对象层**：[见Section总览]
- **核心相与失守**：史 → 断史
- **工程锚点**：依赖可视化——graphviz/手绘依赖图
- **张力曲线**：攀升型（纸笔绘制依赖图→逐条确认→三分之一'未知'→恐惧和决心并存）
- **角色焦点**：纪承钧（从追火者变成制图者）；苏野平（提供工具视角）；钟守玄（能指出的越来越少——沉默越来越深）
- **六拍骨架**：
  1. 纪承钧开始画玄枢的依赖图——用最原始的方式：纸和笔
  2. 每画一条线就问钟守玄一次——钟守玄能指出三分之二的线的去向。剩下三分之一——'不确定'
  3. 苏野平建议用graphviz——'至少让机器帮你画'。但问题不是工具——是信息不全
  4. 第一版依赖图完成——三分之一标着'未知'。不是没有依赖——是没有人知道它们连着谁
  5. 沈照痕看着图：'至少你开始画了。以前——没人画过。'陆踏痕在图上标出三个'疑似临时'的节点
  6. 依赖图不是答案——是问题的地图。图上最可怕的东西不是线太多——是空白太多
- 📝 **路标章**：对应旧Ch01。保留核心场景，在120章结构中扩展前后文。

### 第14章：临时方案考古

- **核心对象层**：[见Section总览]
- **核心相与失守**：史 → 断史
- **工程锚点**：临时vs永久——wrapper的生命周期
- **张力曲线**：悬疑→崩塌型（追溯一个七年前的临时wrapper→'两周'变成七年→没有版本管理的代价→沉默）
- **角色焦点**：纪承钧（考古者——发现'临时'的恐怖）；钟守玄（沉默的见证者——他也曾是'先救火'的人）；陆踏痕（继承者视角——'什么时候可以动？'）
- **六拍骨架**：
  1. 纪承钧追到依赖图上一个'未知'节点——发现它指向一个wrapper。七年前搭的。当时说'用两周就换'
  2. wrapper还在用——搭它的人已经离职五年了。没有人知道它是怎么工作的——只知道'不能动'
  3. '两周'变成七年的机制：不是懒惰——是每个'两周'都被新的紧急事故打断。引出一个更深的痛：没有版本管理——没有人记录这个wrapper什么时候搭的
  4. 纪承钧试图追踪wrapper的变更历史——没有Git，没有SVN，只有文件夹备份。'玄枢_v2_最终版_真的最终_别改了.tar.gz'
  5. 钟守玄承认：'我也忘了它是谁搭的。我只知道——它还在跑，所以不能动。'陆踏痕：'那它什么时候可以动？'——没有答案
  6. 临时方案不是被遗忘的——是被'先救火'反复覆盖的。每一次救火都让临时方案更深地嵌入系统
- 📝 **路标章**：对应旧Ch01。保留核心场景，在120章结构中扩展前后文。

### 第15章：谁搭的桥

- **核心对象层**：[见Section总览]
- **核心相与失守**：史 → 断史
- **工程锚点**：断史症状——知识的匿名化
- **张力曲线**：悬疑型（追查wrapper作者→没有署名→没有Git→匿名文化→'署名意味着出事时找谁'）
- **角色焦点**：纪承钧（从考古到愤怒——'怎么会有人不署名？'）；钟守玄（'因为你没有经历过那个时代——那个时代，署名意味着出事时找谁。没有人想被找到。'）
- **六拍骨架**：
  1. 纪承钧继续追查wrapper的来源——想找到搭桥的人。但文档里没有署名。代码注释里没有。Git历史里没有——因为当时根本没有Git
  2. 不是没有人知道——是知道的人都不在。唯一可能知道的人是卫千枢——他三年前就离开了
  3. 桥的匿名化不是偶然——是'先这样，回头再整理'的文化导致的必然。每次搭桥都是紧急的——紧急到没有时间署名
  4. 纪承钧问钟守玄：'你搭过桥吗？'钟守玄：'搭过。不止一座。'——但他也不记得具体是哪几座
  5. 沈照痕提供了一个考古方法：从编译时间戳反推。追溯到一个七年前的Makefile——Makefile的作者署名是'玄枢维护组'。没有个人名字
  6. 匿名不是一个人的问题——是整个文化的问题。当'谁做的'不重要时，'为什么这样做'也不会被记录
- 📝 **路标章**：对应旧Ch01。保留核心场景，在120章结构中扩展前后文。

### 第16章：两周的临时

- **核心对象层**：[见Section总览]
- **核心相与失守**：史 → 断史
- **工程锚点**：工程人类学——'暂时'如何变成'永久'
- **张力曲线**：双峰型（发现17处'临时'代码→平均4.7年→'临时'是系统性谎言→钟守玄：'现在你明白了'）
- **角色焦点**：纪承钧（从愤怒到理解——'原来是这样'）；钟守玄（'现在你明白了'——守门者的重量）
- **六拍骨架**：
  1. 纪承钧发现一个模式：玄枢中有17处标记为'临时'的代码——平均存活时间：4.7年
  2. 每一处'临时'的诞生都是一个紧急事故——没有人有恶意。但每一个'回头再整理'都被下一个紧急事故打断
  3. 不是懒惰——是系统性压力。当'先救火'是唯一被奖励的行为时，'后来整理'永远不会发生
  4. 纪承钧做了一个实验：试图整理一处'临时'代码。花了三天——发现它连着四个外部系统。整理它需要协调四个团队
  5. 钟守玄看着他：'现在你明白了。不是不想整理——是整理的代价比看起来大一百倍。而且整理的窗口——永远在下一个事故之前关闭'
  6. '两周'变成七年不是因为两周很长——是因为'两周'本身就是一个谎言。说'两周'的人知道不止两周。听的人也知道。但两个人都不说破
- 📝 **路标章**：对应旧Ch01。保留核心场景，在120章结构中扩展前后文。

  2. 临走前，苏野平把他对玄枢依赖图的分析留给纪承钧——'我标了七处值得追的。但不完整。因为我只知道明契那边的依赖模式。你这边——可能还有我不知道的'

### 第18章：留下了什么

- **核心对象层**：[见Section总览]
- **核心相与失守**：史 → 断史
- **工程锚点**：跨卷合作——不完整的诚实
- **张力曲线**：攀升型（阅读苏野平的分析→'前提可能不成立'的标注→第一次看到有人声明局限→学习新写作方式）
- **角色焦点**：纪承钧（学习——从苏野平的'不完整'标注中学到了新的写作方式）；钟守玄（罕见的认可——'他写了前提可能不成立'）；陆踏痕（模仿——开始在自己的笔记中标注前提）
- **六拍骨架**：
  1. 纪承钧仔细读苏野平留下的依赖分析——七处标注，每处都写了'为什么值得追'
  2. 最珍贵的是——苏野平在每一处标注后面都写了'此处分析基于明契的依赖模式。在驭器语境下——以下前提可能不成立：...'
  3. 纪承钧第一次看到有人主动声明自己的局限——'不完整'不是推卸，是诚实。这和他见过的所有文档都不一样
  4. 钟守玄看了这份分析——沉默了很久。'这个人——他写了'前提可能不成立'。'——这是钟守玄第一次对跨道来客表示认可
  5. 陆踏痕把苏野平的分析抄进了自己的笔记本——'以后我写的东西——也要写前提。'
  6. 苏野平留下的不是一份分析——是一种写作方式。声明自己不知道什么——比假装什么都知道更值得信任
- 📝 **路标章**：对应旧Ch01。保留核心场景，在120章结构中扩展前后文。

### 第19章：追火之路

- **核心对象层**：[见Section总览]
- **核心相与失守**：史 → 断史
- **工程锚点**：追根决心——从依赖图到考古计划
- **张力曲线**：攀升→决心型（拼合依赖图+苏野平分析+钟守玄口述→三层考古计划→'你去追。第三层——等我准备好了'）
- **角色焦点**：纪承钧（从追火者到考古计划制定者）；钟守玄（'等我准备好了'——第一次承诺而非沉默）；陆踏痕（主动加入）；沈照痕（提供工具）
- **六拍骨架**：
  1. 纪承钧把依赖图、苏野平的分析、钟守玄的口述拼在一起——制定了一份考古计划
  2. 计划分三层：第一层追构建系统（从手写命令到Makefile的过渡），第二层追知识断层（从卫千枢的离开到现在的断火循环），第三层——追那个残码
  3. 纪承钧把计划给钟守玄看。钟守玄看了很久。'你去追第一层和第二层。第三层——等我准备好了，我告诉你。'
  4. 不是拒绝——是承诺。钟守玄第一次没有沉默——而是说'等我准备好了'
  5. 陆踏痕自愿加入第一层考古——'我可以翻旧文件。我擅长。'沈照痕提供观测工具——'考古也需要看。旧石录、旧Makefile、旧编译日志——都是数据。'
  6. 追火之路铺开了——不是一个人的路。是三个人各自的方向。但他们的方向都通向同一个深处
- 📝 **路标章**：对应旧Ch01。保留核心场景，在120章结构中扩展前后文。

### 第20章：追火之后

- **核心对象层**：[见Section总览]
- **核心相与失守**：史 → 断史
- **工程锚点**：卷尾收束——可见vs不可见
- **张力曲线**：收束型（依赖图第二版→'未知'降到五分之一→但最深的五分之一——在旧核深处→向卷三开门）
- **角色焦点**：纪承钧（依赖图完成——但知道这只是开始）；钟守玄（'更深处'——向卷三开门）；陆踏痕（学会了标注前提）
- **六拍骨架**：
  1. 依赖图第二版完成——这次'未知'从三分之一降到了五分之一。但剩下的五分之一——是最深、最老的部分
  2. 纪承钧意识到：可见的依赖已经够复杂了。不可见的——那些在钟守玄脑子里、在卫千枢的旧机器上、在已经清空的备份里的——才是真正的深渊
  3. 钟守玄看着第二版图：'你画出了三分之一。够好了。剩下的——需要进到更深处。'——'更深处'指的是旧核本身
  4. 陆踏痕在依赖图空白处写：'此处——待考古。前提：以下所有分析基于钟守玄的口述。钟守玄说——他也不确定。'——学会了苏野平的标注方式
  5. 卷尾落点：图有了——但图只是开始。下面要进入的是旧核本身。那些从未被文档化的深处
  6. 纪承钧在依赖图标题下加了一行：'此图基于纪承钧、苏野平、钟守玄的已知信息。已知之外——等后来者补充。'
- 📝 **路标章**：对应旧Ch01。保留核心场景，在120章结构中扩展前后文。
