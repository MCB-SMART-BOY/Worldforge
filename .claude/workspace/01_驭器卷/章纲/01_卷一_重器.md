# 卷一「重器」Ch 1-10：玄枢断火

## Section 总览

- **章段**：Ch 1-10
- **叙事主题**：玄枢连续运行十七日后断火——古器依赖英雄式维护
- **核心冲突**：功绩与风险可以同时成立。重器的强大本身就是脆弱。
- **工具链阶段**：蛮荒——六维皆无（手写命令/文件夹备份/编译器警告/printf/无测试/口传）
- **对象层**：器（从已有重器出发）
- **主相→蚀**：流→乱流（资源/运行时状态失控）
- **主角状态**：外围维护者，渴望进入内核。断火事故使他第一次真正看见古器的脆弱。
- **张力引擎**：一座从来没有真正停过的古器——停一次会发生什么？
- **卷尾落点**：火托住了，但靠的是同样的旧模式。真问题在更深的地方。

### 第01章：重器不眠

- **核心对象层**：器
- **核心相与失守**：流 → 乱流（玄枢的运行时状态依赖隐式知识）
- **工程锚点**：build system 蛮荒态——没有自动化构建，手写命令+贴墙上的纸条
- **张力曲线**：攀升型（从日常维护→逐步暴露深处的依赖不可见）
- **角色焦点**：纪承钧（主角建立——外围维护者，执行钟守玄交给他的热更迁移任务）；钟守玄（守门者——他的命令写在纸条上贴在墙边）
- **六拍骨架**：
  1. 问题先出：玄枢连续运行第十七日，纪承钧执行热更迁移任务——测试环境通过，部署到生产
  2. 为什么痛：古器深嵌进无数外部系统，迁移任何东西都像在活人体内做手术
  3. 引出方法：钟守玄的十七条私有命令——贴在墙上的纸条，每一条都是"不要问为什么，先跑"
  4. 项目落地：玄枢的热更迁移流程——从编译到部署，每一步都是手工命令
  5. 多方复盘：纪承钧执行完后感到不安——"这些命令为什么这样写？"
  6. 高层收束：古器的运行依赖的不是系统，是几个人的记忆
- **入门检查**：前置：无（卷首章）/ 新术语：玄枢、古器、驭器之道（≤3）
- **三问预检**：🩻乱流（运行时状态不可见） 😣外部调用方（他们不知道迁移在进行） 🛤️否——路只存在于钟守玄的脑子里
- **工具链阶段**：构建=手写命令，版本=文件夹备份，静态=编译器警告（3,742个warning被关掉），调试=printf，测试=无，文档=口传+纸条

### 第02章：断火

- **核心对象层**：器
- **核心相与失守**：流 → 乱流（运行时失控→回滚失败→外部系统连锁降级）
- **工程锚点**：编译链差异+平台差异——"测试环境通过"≠"生产环境能跑"
- **张力曲线**：倒钩型（丑时三刻突然断火→回溯原因→回滚失败→外部降级→临时托住）
- **角色焦点**：纪承钧（恐慌→自责→"我要学这个"）；钟守玄（沉默地用私有命令托火）；沈照痕（首次出场——从crash dump中定位断口）
- **六拍骨架**：
  1. 问题先出：丑时三刻，外部调用方开始出现零星超时——纪承钧的迁移引入了隐式依赖断裂
  2. 为什么痛：回滚失败——回滚策略没有覆盖跨层依赖。三个外部系统连锁降级。代价落在那些凌晨还在运行的设备操作者身上
  3. 引出方法：钟守玄用私有命令托住玄枢——其他人看不懂那些命令
  4. 项目落地：沈照痕从core dump中定位到真正断口——一处三年前的手工边界修正
  5. 多方复盘：事故暂时压住。没人庆贺。纪承钧问"我该学什么"——钟守玄说"你不该学这个"
  6. 高层收束：火被一个人托住了。和过去每一次断火一样。靠的是同一个人
- **入门检查**：前置：Ch01（玄枢是什么、纪承钧是谁）/ 新术语：回滚（rollback）、core dump（≤3）
- **三问预检**：🩻乱流（运行时失控→连锁降级） 😣外部调用方的凌晨值班者 🛤️否——靠同一个人托火，路没有变宽
- **工具链阶段**：同Ch01蛮荒态。断火的根因三年前就被引入了——但没测试、没文档、没静态分析能发现

> 📝 **路标章**：对应旧Ch02。保留丑时断火+钟守玄托火+沈照痕定位的核心场景。新增：外部调用方凌晨降级的平行剪辑（多视角展示古器断火的连锁效应）。

### 第03章：十七条命令

- **核心对象层**：器→文（钟守玄的私有命令——口传知识的物质形态）
- **核心相与失守**：史 → 断史（命令的"为什么"没有被传递）
- **工程锚点**：shell脚本作为构建工具——没有Makefile，只有手写命令序列
- **张力曲线**：悬疑型（纪承钧逐一追问十七条命令的来源→每一条都有故事→但不是所有故事钟守玄都愿意讲）
- **角色焦点**：纪承钧（从"我要学"转为"我要理解"）；钟守玄（每条命令背后都有一个事故——但他只讲了一半）
- **六拍骨架**：
  1. 问题先出：断火后第二天，纪承钧开始逐条追问钟守玄的十七条私有命令
  2. 为什么痛：每条命令都是一个曾经发生过的事故的伤疤——但伤疤的主人有些已经不在了
  3. 引出方法：钟守玄开始解释——第一条到第五条是卫千枢留下的，第六条是"我自己加的，因为五年前..."然后停住
  4. 项目落地：十七条命令覆盖了编译、链接、部署、回滚、观测——但没有任何文档记录
  5. 多方复盘：纪承钧意识到：如果钟守玄不在，这十七条命令就是天书
  6. 高层收束：第十七条命令——"echo 'done'"。纪承钧问这是什么。钟守玄："确认所有步骤都完了。我加的。因为有一次——没有echo，我以为跑完了。"
- **入门检查**：前置：Ch01-02 / 新术语：shell脚本（shell script）、编译（compile）、链接（link）（≤3）
- **三问预检**：🩻断史（命令的"为什么"丢失） 😣未来可能面对断火的维护者 🛤️开始——纪承钧第一次追问"为什么"
- **工具链阶段**：构建=手写命令的巅峰——十七条命令是"最先进的蛮荒"

### 第04章：追火者

- **核心对象层**：器→骨（纪承钧开始从表面事故追向深层结构）
- **核心相与失守**：史 → 断史（断火的历史模式——每两年一次）
- **工程锚点**：事故复盘（postmortem）的缺失——没有系统性的根因分析文化
- **张力曲线**：攀升型（从事故表象→逐层暴露历史模式→建立追根决心）
- **角色焦点**：纪承钧（主角建立核心驱动力——从"执行者"转变为"追火者"）
- **六拍骨架**：
  1. 问题先出：纪承钧翻查玄枢的断火记录——发现这不是第一次
  2. 为什么痛：每两年一次。每次都是同一个人（钟守玄）救的。每次的根因都没被记录
  3. 引出方法：沈照痕教纪承钧看core dump——"先学会看，才知道往哪追"
  4. 项目落地：纪承钧画出第一次断火的时序图——从表面超时追到深层隐式依赖
  5. 多方复盘：钟守玄看着纪承钧画的图——"你画对了一半。另一半——不在代码里。"
  6. 高层收束：纪承钧决定追到根——不管根有多深
- **入门检查**：前置：Ch01-03 / 新术语：core dump、时序图（timeline）、根因分析（root cause analysis）（≤3）
- **三问预检**：🩻断史（断火历史未被记录） 😣每次断火时的外部使用者 🛤️开始——纪承钧决定追根

### 第05章：旧适配层

- **核心对象层**：骨（旧适配层——wrapper的原始形态）
- **核心相与失守**：式 → 失式（适配层的结构边界不清——谁知道它怎么工作的？）
- **工程锚点**：build system——编译链中的适配层（adapter/wrapper）如何成为黑箱
- **张力曲线**：悬疑型（纪承钧追到一个适配层→没人知道它为什么这样写→追溯→发现它比玄枢的文档还老）
- **角色焦点**：纪承钧（第一次面对"没人知道"的代码）；钟守玄（承认："那段——我也只是照着跑"）
- **六拍骨架**：
  1. 问题先出：纪承钧追到断火的直接触发点——一处旧适配层中的平台条件编译
  2. 为什么痛：Linux上能跑，macOS上报错——这条适配层六年前写的，当时没有macOS调用方
  3. 引出方法：手写命令的局限——"./build.sh"在Linux上跑过，在macOS上跑了一半
  4. 项目落地：纪承钧试图读懂适配层——发现里面引用的一个宏，在整个代码库里搜不到定义
  5. 多方复盘：钟守玄："那个宏——在卫千枢的机器上。他那台机器——三年前清空了。"
  6. 高层收束：不是代码坏了。是"为什么这样写"只存在于一个人的脑子里——那个人不在了
- **入门检查**：前置：Ch01-04 / 新术语：适配层（adapter）、条件编译（conditional compilation）、宏（macro）（≤3）
- **三问预检**：🩻失式（适配层结构边界不清） 😣纪承钧（他需要花大量时间考古） 🛤️否——适配层仍然是黑箱

### 第06章：平台差异

- **核心对象层**：骨→阵（从一个适配层扩展到整个平台的差异矩阵）
- **核心相与失守**：式 → 失式（跨平台构建的结构性缺失）
- **工程锚点**：跨平台构建的痛——ABI差异、编译器版本、系统调用、字节序
- **张力曲线**：双峰型（发现第一个平台差异→暂时解决→发现更多→意识到这是系统性问题）
- **角色焦点**：纪承钧（从"修好这一个"到"这是整个门的问题"）；沈照痕（提供跨平台的观测视角）
- **六拍骨架**：
  1. 问题先出：修好适配层的macOS问题后——Windows上的外部调用方又报错了
  2. 为什么痛：玄枢在七个平台上运行——每个平台有不同版本的依赖，不同版本的编译器
  3. 引出方法：沈照痕展示玄枢的平台矩阵——一张表格，三分之二的格子写着"未知"
  4. 项目落地：纪承钧试图在第二个平台上重现构建——失败了。缺少一个只在Linux上存在的系统调用
  5. 多方复盘：钟守玄："我们一直知道。但每次都是——哪个平台出问题，修哪个平台。"
  6. 高层收束：平台差异不是bug——是没有跨平台构建系统的必然结果
- **入门检查**：前置：Ch05 / 新术语：ABI、系统调用（system call）、字节序（endianness）（≤3）
- **三问预检**：🩻失式（跨平台构建无结构） 😣非Linux平台的外部调用方 🛤️开始——意识到需要系统化的跨平台构建

### 第07章：不是第一次断

- **核心对象层**：史（玄枢断火的历史模式）
- **核心相与失守**：史 → 断史（断火历史被反复遗忘）
- **工程锚点**：事故历史的知识管理——为什么每次事故后"不会再发生"的承诺都会失效
- **张力曲线**：倒钩型（发现历史模式→震惊→深入→更震惊的发现→决心改变）
- **角色焦点**：纪承钧（从追火者变成考古者）；钟守玄（沉默——他知道的比他说出来的多）
- **六拍骨架**：
  1. 问题先出：纪承钧整理出一份玄枢断火历史——七次。每两年一次。每次都是钟守玄救的
  2. 为什么痛：每次事故后都有人说"不会再发生"——但每次发生的方式都不一样
  3. 引出方法：不是没有试图修——每次修的都是表面症状，不是深层原因
  4. 项目落地：纪承钧把七次断火的根因并排——发现它们在深处相连：都追溯到同一批未文档化的手工修正
  5. 多方复盘：沈照痕："每次修的都是流——没人修过史。所以史在反复咬人。"
  6. 高层收束：断火不是事故。是症状。真病在"没有人把修过的东西写下来"
- **入门检查**：前置：Ch01-06 / 新术语：知识管理（knowledge management）（≤1）
- **三问预检**：🩻断史（事故历史未被传承） 😣每次断火的新受害者 🛤️开始——意识到"修流不修史"的循环

### 第08章：钟守玄的手

- **核心对象层**：器→人（守门者与古器的身体关系）
- **核心相与失守**：流 → 乱流（守门者的手在旧机器上——不是拍，是放）
- **工程锚点**：隐式知识的肉身化——"gdb告诉你值是多少，但不告诉你值为什么是这个。那个'为什么'——在我脑子里"
- **张力曲线**：崩塌型（从平静的日常维护→逐层暴露守门者的孤独→章末情感最低点）
- **角色焦点**：钟守玄（全章核心——守门者的沉默、疲累和不被理解的重量）；纪承钧（旁观者——第一次看见钟守玄不只是"最强的维护者"）
- **六拍骨架**：
  1. 问题先出：断火后第三天，钟守玄一个人坐在旧机器前——手放在机器上，不是拍，是放
  2. 为什么痛：纪承钧看见钟守玄的手指——在第十七条命令的执行键上悬了很久。他怕按下去——也怕不按
  3. 引出方法：gdb可以告诉你值是多少——但"为什么是这个值"只存在于钟守玄的脑子里
  4. 项目落地：钟守玄开始讲——不是讲技术，是讲故事。"这台机器——我第一次碰它的时候，卫千枢还在。"
  5. 多方复盘：纪承钧意识到：钟守玄不是不想传。是有些东西——传了就不是那个东西了
  6. 高层收束：钟守玄的手从机器上移开。"好了。它在跑了。"
- **入门检查**：前置：Ch01-07 / 新术语：gdb（≤1）
- **三问预检**：🩻断史（守门者的知识无法传递） 😣钟守玄（他一个人扛着） 🛤️否——路仍然只通向他一个人

### 第09章：托火

- **工程锚点**：临时方案的生命周期——"先托住，再想办法"中的"先"能持续多久
- **张力曲线**：攀升→崩塌（火托住→短暂缓解→纪承钧意识到这不能继续→决心）
- **角色焦点**：纪承钧（从"我要学"到"这不能继续"——核心转向）；钟守玄（托火者——但他知道这不是解法）
- **六拍骨架**：
  1. 问题先出：钟守玄的私有命令跑完——玄枢恢复运行。外部系统逐一恢复

  3. 引出方法：但这次和每次都不一样——因为纪承钧开始追问了
  4. 项目落地：纪承钧在事故复盘会议上提出：不是修这次断火——是修让断火反复发生的那个东西
  5. 多方复盘：钟守玄没有说话。但他把第十七条命令的纸条从墙上取下来——递给纪承钧

### 第10章：重器之后

- **核心对象层**：器→史（从"修好这台机器"到"修好这台机器的传承"）
- **核心相与失守**：史 → 断史（重器之后——那些让它活着的人，他们的知识会死吗？）
- **工程锚点**：从"解决问题"到"建立系统"的思维转变——卷一收束
- **张力曲线**：收束型（事故平息→反思→建立卷一主题→为卷二铺路）
- **角色焦点**：纪承钧（卷尾落点——决定追根，不管多深）；钟守玄（沉默的目送者）
