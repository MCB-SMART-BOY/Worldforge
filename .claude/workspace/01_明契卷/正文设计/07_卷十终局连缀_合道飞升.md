## 二、连续正文

白板上只剩最后一条还没有被划掉的桥。

`legacy-fast-pass`

顾迁衡把退场日历钉在旁边，纸张边角压得很平，像一份不肯再给人装糊涂余地的裁定。最迟退场节点写得很清楚：

`卷十窗口前夜，自动入口关闭；仅保留公开命名的手工应急路径。`

贺时进把另一张表拍在桌上，声音比纸更硬。

“你们要真照这张日历走，今晚至少有两组窗口得往后挪。外侧工单已经排满了。延期、返工、抱怨，谁来扛？”

苏野平靠在桌边，替所有不耐烦的人把那条最熟悉的聪明路说了出来。

“桥名义上退，实际先别断干净。把自动入口藏回内部，挂个不对外写的开关。谁真顶不住，就让值守人知道那个口。等后面平一点，再慢慢拔。”

这方案太像这些年门里最擅长的赢法了。

聪明。

熟练。

也最会把明天继续压给后来者。

顾迁衡先抬起头。

“那这张日历就成笑话了。”

闻衡把迁移说明翻到最后一页，直接把最难听的后果压回桌面。

“前面写出去的弃用通知、帮助信息和 patch note，都会在今晚一起失效。”

程知序没有替谁缓和。她只是把真正必须被听见的话说完整。

“今晚的痛，到底是工具在折腾人，还是过去一直把代价藏起来，今天终于轮到大家一起结？”

屋里静了一瞬。

贺时进看向沈见微。

“别讲道心。我现在只问一件事。窗口要是丢了，门外那批人今天晚上怎么交代？”

沈见微看着那条桥，像看着一段陪众人熬过太多难夜、也替众人偷偷积了太多年债的旧习惯。

只要他点头，今晚多半还能顺过去。

可青炉也会在最该结账的一次，重新学会撒谎。

他拿过笔，把那条桥下的状态改成四个更冷的字：

`自动入口关闭`

然后在下面补了三行：

`手工应急路径保留 14 日，仅限已登记迁移失败、由值守人执行、必须写回 issue。`

`14 日后删除；若延期，需重发迁移说明、列明受影响范围与新增风险。`

`任何人不得私藏第二入口。`

苏野平先看字，再看他。

“你知道这意味着什么。”

“知道。”

“你知道今晚会有人骂你们把事情做重了。”

“知道。”

“你知道有些人会觉得，你们是在用一套更干净的说法，把痛全压回现实使用侧。”

程知序抬起眼。

“不是压回。”她说，“是终于不再装作没有。”

沈见微把笔放下。

“窗口受损，我们认。”

“抱怨上来，我们接。”

“但从今天起，任何应急都必须有名字、有范围、有记录、有退场。谁都不能再靠熟人默契把它活成第二套秩序。”

外侧的消息很快就涌进来。延期说明、返工追问、抱怨工单，一条接一条顶上最前面。屋里没人因为做了正确决定而轻松，甚至没人觉得自己赢了。

那一夜没有掌声。

只有闻衡把帮助信息改成更难看、也更诚实的一句：

`legacy-fast-pass 已关闭自动入口。仍受阻者请按迁移说明申请手工应急路径。`

窗口最终还是丢了一截。

天快亮时，沈见微站在空掉一半的屋里，看着白板上那三行字，第一次觉得“重”不是姿态。

重，是不把明天继续压给后来者。

第二天一早，门里最难听的那批话已经传回来了。

有人说青炉把事情做重了。

有人说这套规矩只适合闲时，不适合活人真要交付的时候。

还有人更直接：

“是不是以后凡事都得 Rust 化，才算文明？”

那句话被抄在白板最上面，像一根故意往人脸上戳的刺。

苏野平先把那根刺捏住。

“我替大家把话说得更明白一点。难道以后写个小脚本也得先把所有失败路径、资源边界、review 口径全摆上？难道试法的时候也要背着这么重的壳跑？难道慢和难，现在都能直接叫作文明了？”

贺时进也不替谁缓和。

“如果这套路只能在高纪律团队里成立，它到底是现实工具，还是少数人的理想器？”

顾迁衡没有先看谁，先把桌上的材料分成三堆。

“这一堆，是重器旧边界。”

“这一堆，是试法和临时桥。”

“这一堆，是守夜、交付和运行。”

“它们不是同一类病，也不该用同一把刀。”

闻衡在白板上把那句刺眼的话划成两半。

左边写：

`哪一层必须重？`

右边写：

`哪一层不该假重？`

程知序把门外人的真实要求压得足够具体。

“我不要你们替我选信仰。我只要两件事。第一，哪一层出了错，代价会直接打到使用者脸上。第二，哪一层今天还只是试法，别包装成我可以拿去押窗口的公共承诺。”

屋里安静了几息。

沈见微这时才走到白板前。

他没有先替 Rust 说话。

他先在左边写下四行：

`寿命长`

`多人协作`

`故障代价高`

`边界危险重`

“满足这四条的地方，就值得把代价前置。值得先写失败，先写资源归属，先写行为承诺，先写后来者能不能复走。因为那里的模糊，不会只伤今天写代码的人，它会伤一串以后根本没到过现场的人。”

然后他又在右边写下三行：

`高不确定试法`

`验证成本高于沉淀收益`

`只是薄壳编排`

“满足这三条的地方，不必强推明契。脚本、notebook、一次性试法链，本来就更接近化形之道。旧核接壤和长史重器，更像驭器之争。值守、交付、回滚、ownership，更接近简阵之治。”

他又补了三行：

`试法层：先快，但必须承认自己只是试法。`

`重器边界：先立界，不许把危险装成已经驯服。`

`守运层：先看流转和责任，不许用统一口径压平真实差异。`

白板终于不像一场语言争吵了。

更像一张迟到很久的分层图。

核心层要重。

试法层可以轻。

重器边界要诚实。

守运层要公开责任图。

每一层都可能说谎。

也每一层都该被放回更合适的位置。

苏野平盯着“试法层”那一行，问出了最后一记真正有效的追问。

“那我的快路，什么时候不再算无辜？”

沈见微看着他。

“当它开始被别人当成长期可信入口的时候。”

“当它开始躲开失败说明的时候。”

“当它开始不肯承认自己只是临时桥的时候。”

“到那时，它就不再只是化形，它已经在偷偷冒充明契。”

这句话让屋里真正安静了下来。

贺时进看着白板，终于不再问“你是不是 Rust 信徒”，而开始算另一笔账。

“所以你最后要的，不是一门语言的统治。”

“不是。”沈见微说，“我要的是，每一层都被放到更合适的位置。核心别再把模糊当灵活。试法别再把临时当永恒。重器别再把秘义当传火。守运别再把压平当简。”

他说到这里时，忽然知道自己终于从“选道的人”往前走了一步。

不是走到更纯。

而是走到更稳。

会后第三天，沈见微离开了门内。

外侧因断桥延期而起的争议比预估更重。有人要解释，有人要补偿方案，有人要把这次窗口受损算成青炉自找的麻烦。他必须亲自去接那批最难看的余波。

临走前，他只在值守板最上面留下一句话：

先沿 issue、日志、测试、迁移说明走。

不要先找人。

三天后的深夜，远端仓里的新 issue 被顶到了最上面。

标题只有一行：

`watch 模式下仍接受 legacy alias，迁移后结果偏旧。`

程知序把 run id 贴进讨论里，连多余的形容词都没有。

“不是挂了。更糟。它给了通过，但落在旧桥口。”

以前遇到这种安静，下一步往往是去找沈见微。

这一次没人动。

季循站在灯下，看着值守板那一行字，手心有一点汗。他不是第一次值夜，却是第一次在这类问题里，没有把目光下意识转向那个总能把火拽回来的位置。

闻衡先开口。

“先收症状。程知序，你只给事实。别替它解释。”

程知序点头。

“迁移后的第三组工件，在 `doctor --watch` 下仍接受旧 alias。一次性运行不会。帮助信息写着 watch 模式不再接旧桥。日志里第六步开始出现 `legacy route accepted`。输入、环境和两次 run id 我都贴上去了。”

顾迁衡已经翻到迁移说明最后一页。

“别急着把桥接回去。先看是谁让 watch 模式又碰到了它。”

季循把日志链一层层拉开。

先是模式判断。

再是配置读取。

再往后，是那条本该只留给手工应急路径的旧别名开关。

它没有消失。

它只是从不该经过的地方漏了进去。

“不是使用者误走旧路。”季循说，“是 watch 模式还在吃那条仅供手工应急的环境别名。一次性命令不会，所以前面的测试没撞上。问题在模式边界，不在迁移说明本身。”

闻衡只问了两个字。

“证据。”

季循把日志位置、对应路径和缺失的测试空档一项项贴进 issue，像把木楔钉进一扇不会再自己合上的门。

“`watch` 走的是长驻初始化，没走掉一次性入口那道 alias 拦截。旧桥没被重新宣布，只是有一条漏风的缝。”

顾迁衡把迁移表翻过一页，手指停在退场日期旁边。

“那就不续桥。补拦截，补提示，补一条 patch release。手工应急路径继续只留给明文值守场景，不放回 watch。”

程知序没有松气，她先问门外那批已经踩中的人怎么办。

闻衡接了过去。

“先写明受影响范围。再写清这不是‘建议更新’，是边界修补。帮助信息、迁移说明、patch note 一起改。”

她抬头看季循。

“你起补丁。顾迁衡审桥。程知序补复现链。我来卡说明和发布口径。”

没有人提沈见微。

事情忽然就开始沿门规自己往前走了。

季循开了分支：

`fix/watch-legacy-alias-leak`

他先补测试，再补拦截。不是先改代码，因为他忽然很清楚，今晚最怕的不是修不好，而是又一次把“我知道这里该怎样”留在自己手里。

程知序很快补上了复现步骤。

哪条命令。

哪组环境。

哪一行日志。

哪里与说明不符。

顾迁衡在 review 里只留下一句：

“别让手工应急路径再有任何机会被长驻模式误认。”

闻衡改得更狠。

她把“兼容行为修正”划掉，换成了：

“修复 watch 模式错误接受 legacy alias 的边界漏洞，并补写迁移提示。”

天快亮时，CI 过了。

patch tag 被打上去，迁移说明更新，帮助信息里的旧话也被拔掉，换成更冷、更清楚的一句：

`watch 模式不接受 legacy alias。若仍依赖旧桥，请按迁移说明切换到手工应急路径。`

程知序看着新版本推上远端，终于靠回椅背。

“这次不用等他回来，也能把话说清了。”

屋里没人接这句。

可也没人反驳。

更远的地方，沈见微大概还在另一场争执里，面对那些因为断桥而起的抱怨、损失和不解。这里没有人替他辩解，也没有人替他出场。

灯还亮着。

终端的最后一行停在那里，安静得近乎朴拙。

问题被记录。

补丁被验证。

说明被写回公共路径。

主角不在场。

火没有灭。

## 三、当前结论

这个连缀已经把卷十终局最关键的三处旧缺口补平了：

1. 第二十八章的失血、第二十九章的道争、第三十章的继承，现在已经被连成同一条不断线的因果链
2. 主角的成熟不再停在“我选 Rust”，而是推进到了“我知道何处必须重，何处不该强压此道”
3. 终章不再只是一个正确样场，而是能明确证明青炉已经开始脱离主角个人英雄主义

当前更适合的用法是：

1. 作为卷十正式正文的整体验算稿，回看第二十八章、第二十九章、第三十章之间的因果链是否仍然闭合
2. 与卷一正式正文对照，检查首尾镜像、病理回响与主角弧线是否真正闭环
3. 保留为驭器卷起步时的接口参照，确保“旧核重器与长史之身”能从这里自然接入共享事件表
