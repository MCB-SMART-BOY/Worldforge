# 《万构界·明契卷》卷尾样场：主角不在场时，火未灭

## 一、样场定位

- 对应章节：卷十 第三十章
- 对应章纲文件：[05_正式章纲_卷十.md](../../../../主卷/01_明契卷/章纲/05_正式章纲_卷十.md)
- 本样场目的：验证“主角不在场时，青炉仍能沿公共路径完成一次真实交火”

---

## 二、样场正文

夜已经很深，远端仓里的新 issue 还是被顶到了最上面。

标题只有一行：

`watch 模式下仍接受 legacy alias，迁移后结果偏旧。`

程知序把 run id 贴进讨论里，连多余的形容词都没有。

“不是挂了。”她说，“更糟。它给了通过，但落在旧桥口。”

屋里安静了一瞬。以前遇到这种安静，下一步往往是去找沈见微。有人发消息，有人打电话，有人先把话说成“等他回来再定”。

这一次没人动。

沈见微三天前就离开了门内，去处理外侧那批因断桥延期而爆出来的争议。他走之前只留下一句话，写在值守板最上面：

先沿 issue、日志、测试、迁移说明走。

不要先找人。

季循站在灯下，看着那一行字，手心有一点汗。他已经不是第一次值夜了，却是第一次在这类问题里，没有把目光下意识地转向那个总能把火拽回来的位置。

“先收症状。”闻衡把椅子拉开，声音不高，却把屋里每个人的动作都压进了轨道，“程知序，你只给事实。别替它解释。”

程知序点头，像在报一份平常得不能再平常的构件单。

“迁移后的第三组工件，在 `doctor --watch` 下仍接受旧 alias。一次性运行不会。帮助信息写着 watch 模式不再接旧桥。日志里第六步开始出现 `legacy route accepted`。我已经把输入、环境和两次 run id 都贴上去了。”

顾迁衡已经翻到了迁移说明最后那页。他不看人，先看日历。

“别急着把桥接回去。”他说，“先看是谁让 watch 模式又碰到了它。”

季循把日志链拉开。一层一层往下，先是模式判断，再是配置读取，再往后，是那条本该只留给手工应急路径的旧别名开关。

它没有消失。

它只是从不该经过的地方漏了进去。

季循盯着那一行字，忽然想起卷首那夜自己站在旧工具链旁边时的感觉。那时候每一条暗门都像藏在雾里。你知道一定有人知道路，可你不知道那个人什么时候来，也不知道那条路是不是会在你脚下忽然塌掉。

现在不一样。

现在至少雾是有边的。

“不是使用者误走旧路。”季循说，“是 watch 模式还在吃那条仅供手工应急的环境别名。一次性命令不会，所以前面的测试没撞上。问题在模式边界，不在迁移说明本身。”

闻衡抬眼看他：“证据。”

季循把日志位置、对应代码路径和一条缺失的测试空档一项项贴进 issue，像把木楔钉进一扇不会再自己合上的门。

“这里。”他说，“`watch` 走的是长驻初始化，没走掉一次性入口那道 alias 拦截。旧桥没被重新宣布，只是有一条漏风的缝。”

顾迁衡把迁移表翻过一页，手指停在退场日期旁边。

“那就不续桥。”他说，“补拦截，补提示，补一条 patch release。手工应急路径继续只留给明文值守场景，不放回 watch。”

门外风声很轻，像有人在更远的地方推着夜往前走。

程知序没有松气。她问的是另一笔账。

“已经踩中的那批人怎么办？”

闻衡接了过去。

“先写明受影响范围。再写清这不是‘建议更新’，是边界修补。帮助信息、迁移说明、patch note 一起改。”她看向季循，“你起补丁。顾迁衡审桥。程知序补现实复现链。我来卡说明和发布口径。”

没有人提沈见微。

这件事忽然就开始沿着门规自己往前走了。

季循开了分支，名字干净得近乎发冷：

`fix/watch-legacy-alias-leak`

他先补测试，再补拦截。不是先改代码，因为他忽然很清楚，今晚最怕的不是修不好，而是又一次把“我知道这里该怎样”留在自己手里。

程知序那边很快补上了复现步骤。她写得极短，每一句都像钉子。

哪条命令。

哪组环境。

哪一行日志。

哪里与说明不符。

顾迁衡在 review 里只留了一句：

“别让手工应急路径再有任何机会被长驻模式误认。”

闻衡改得更狠。她把季循原本写的“兼容行为修正”划掉，换成了：

“修复 watch 模式错误接受 legacy alias 的边界漏洞，并补写迁移提示。”

季循盯着那行改动，忽然笑了一下。那不是轻松的笑，更像一根绷了很久的线，终于知道自己该落在哪里。

天快亮时，CI 过了。

patch tag 被打上去，迁移说明更新，帮助信息里的那句旧话也被拔掉，换成更冷、更清楚的一句：

`watch 模式不接受 legacy alias。若仍依赖旧桥，请按迁移说明切换到手工应急路径。`

程知序看着新版本推上远端，终于靠回椅背，声音还是平的。

“这次不用等他回来，也能把话说清了。”

屋里没人接这句。

可也没人反驳。

更远的地方，沈见微大概还在另一场争执里，面对那些因为断桥而起的抱怨、损失和不解。这里没有人替他辩解，也没有人替他出场。

灯还亮着。

终端的最后一行停在那里，安静得近乎朴拙。

问题被记录。

补丁被验证。

说明被写回公共路径。

主角不在场。

火没有灭。

---

## 三、当前结论

这个样场已经能验证三件事：

1. 主角不在场时，继承者可以成为第一接火者
2. 使用者、渡桥人、审契者都能沿公共路径承担各自职责
3. 结尾不靠主角点化，也能成立“青炉继续存在”的事实

当前更适合的用法是：

1. 作为第30章正式正文的设计回看稿，检查“主角不在场时火未灭”是否仍成立
2. 对照第二十八章与第二十九章正式正文，回看桥单、patch 与迁移说明是否已经完全咬合
3. 保留为卷尾继承验证的教学样板，供卷外配套与后续各卷参照
