# 《万构界·明契卷》正式章纲：卷七到卷九

## 一、章纲定位

本章纲用于把《明契卷》后段最关键的卷七到卷九，从“十卷三十章母蓝图”继续压成可直接开写的正式章纲。

本轮只处理：

1. 卷七：化神守界
2. 卷八：炼器出山
3. 卷九：问鼎守成

选择先压这三卷，是因为它们负责解决《明契卷》后段最容易空掉的三处逻辑风险：

- 青炉会不会把“明契之道”写成一种只会阻止别人做事的洁癖，而不是责任哲学
- 青炉会不会在测试、发布、交付阶段重新滑回“说得比做得多”的外史失信
- 青炉会不会在真正入世后，因为运行失明与兼容共存，长成一个更大的新黑箱

---

## 二、后段裁定

卷七到卷九统一承担《明契卷》的“后段主危”：

**真正艰难的，不是把边界写出来，而是当世界要求你越界、提速、兼容、上线时，你是否还肯为每一次越界与承诺负责。**

这意味着：

1. 卷七必须把“安全”写成具体责任，而不是写成圣光设定
2. 卷八必须把“测试 / 发布 / 交付”写成对外立契，而不是项目尾声附录
3. 卷九必须把“运行 / 观测 / 迁移”写成长期战争，而不是上线后的碎事

---

## 三、卷七：化神守界

使命：把 Rust 的硬边界写成真正的责任哲学，而不是恐吓材料。这一卷必须让读者看见，明契之道不是“禁止越界”，而是“越界者必须额外举证”。

### 第十九章：肉身不坏，内存安全的真实含义

- 青炉在卷六之后被要求加入更重的 `doctor` 校验路径，要在一轮检查里同时读取构件清单、临时目录与历史缓存
- 苏野平提出沿用旧世界的共享暂存池，觉得这样最省分配与搬运
- 韩砺年回忆起旧工具链里一次极难复盘的怪错：
  - 清理动作先一步收走临时目录
  - 另一条钩子却还在读那批路径
  - 程序不是立刻炸掉，而是读到了错误对象，最后形成“同版异行为”
- 季循尝试把这套快路直接写进青炉，却不断被借用检查挡回
- 闻衡借题逼问主角：若你说不清“谁拥有这些东西、它们活到何时、谁能继续碰”，那你就没有资格谈可信
- 沈见微最终放弃更炫的共享引用方案，改为构造清楚的 `CheckPlan` 快照，把临时状态与长存状态明确拆开
- 本章必须落成三个可见动作：
  - 临时输入不再直接借壳长存
  - 核心检查动作改吃显式快照
  - 一类过去只能靠老手记住的“失效仍被继续读取”风险，被第一次写成可解释规则
- 本章结尾必须让团队第一次真正理解：
  - 安全不是“永不出错”
  - 安全是某些本来只能靠运气绕开的错，现在被边界提前拦住

教学点：

- 生命周期
- 内存安全
- 为什么 use-after-free 一类问题本质是责任失位
- 安全保证怎样回到工程现实

角色压力落点：

- 同门者：代表“先快一点，后面再整理”的真实诱惑
- 守门者：提供旧世界里最难讲清的反例
- 继承者：承担第一次正面撞上边界、却因此真正学会判断的代价

### 第二十章：心魔难驯，并发安全与共享状态的代价

- 青炉的最小可信入口站住后，贺时进立刻要求把多环境校验并起来，认为不提速就守不住现实窗口
- 程知序也站在使用侧施压：若一轮检查仍然拖得太久，大家很快就会重新回到旧快路
- 苏野平提议做一个全局共享缓存，让多条校验路径共用同一批结果
- 顾迁衡提醒众人：很多旧桥的副作用根本不是线程安全设计出来的，若并发写进同一片状态，只会更快制造新迷雾
- 季循试出一版并行原型后，立刻碰见两个新问题：
  - 共享结果收集器的写入顺序不稳定
  - 旧桥插件会偷偷改写全局临时状态
- 沈见微必须在这章做出一次不讨好的裁定：
  - 只读校验可以并行
  - 带副作用的桥与外部动作必须串行或被显式锁住
  - “快”只能建立在责任边界先成立之后
- 本章必须形成三个清楚动作：
  - 青炉第一次区分并行任务与串行任务
  - 共享状态第一次被公开点名为代价源，而不是便利工具
  - 一条看上去很提速的捷径被主角主动压下
- 本章结尾要让读者看见：
  - 并发不是“更快”
  - 并发是“多流同时存在时，你还守不守得住界”

教学点：

- `Send`
- `Sync`
- 锁与共享状态
- 并发设计为什么总是伴随代价

角色压力落点：

- 诱惑者：把时间压力顶到极限
- 使用者：证明性能和等待时间是真问题，不是伪命题
- 渡桥人：证明旧桥并不天然适合并行世界
- 主角：第一次为了长期可信，主动拒绝漂亮的短期提速结果

### 第二十一章：禁术与誓约，unsafe、FFI 与责任边界

- 卷七的最后一道关不是内部安全，而是旧世界无法立刻消失
- 顾迁衡带来一条现实难题：
  - 某批历史工件的校验仍然必须过一段旧原生库
  - 若完全不接这条桥，很多团队不会迁移到青炉
- 贺时进主张把旧库直接塞进现有入口里，先让现实流转起来
- 闻衡则明确提出：只要旧核进入青炉，它就必须被点名、被围栏、被留下额外证明责任
- 沈见微最终不把这条桥藏进核心层，而是单独立出受控边界：
  - 旧桥只通过清楚的适配模块进入
  - `unsafe` 只出现在明确可查的窄区
  - FFI 的前提、失败语义与退出条件一起写进项目记忆
- 季循第一次不是去“调用一段神秘旧核”，而是去维护一份可读的安全说明
- 本章必须让读者看见：
  - `unsafe` 不是邪法
  - 但它意味着额外的证明债、维护债与退出债
- 章尾要落在一个更成熟的判断上：
  - 真正可怕的不是越界
  - 真正可怕的是越界了却假装没有越界

教学点：

- `unsafe`
- FFI
- 边界包装
- 证明责任

角色压力落点：

- 渡桥人：代表现实连续性与迁移必要性
- 镜像者：代表“直接连上就能救火”的旧路诱惑
- 审契者：逼所有越界都留下明文
- 主角：承担“既不否认旧核存在，也不让旧核无名侵入”的双重压力

## 四、卷八：炼器出山

使命：让青炉真正面对他人依赖。这一卷必须把“别人为什么敢信你”写成工程动作，而不是写成主角气质。

### 第二十二章：器成可试，测试体系与可靠性证明

- 卷七立住安全边界后，青炉终于开始被更多人拿去跑真实流程
- 很快出现新的逼问：
  - 你说这次安全了，凭什么
  - 你说这条旧桥被围住了，别人怎么验证
- 程知序要求的不再是“有人跟着看”，而是“没有你在场我也能判断这次有没有变坏”
- 韩砺年翻出一批旧事故片段，里面有大量过去只能靠口述流传的边界案例
- 沈见微在这章必须把“证契”从口头变成体系：
  - 核心规则有单元测试
  - 契口行为有集成测试
  - 旧桥与扩展点有契约测试
  - 关键流程至少有一条端到端演练
- 季循第一次把一段旧事故固化成失败用例，而不是记成“前辈提醒”
- 本章结尾必须让团队承认：
  - 青炉开始不只是“看起来更稳”
  - 它第一次开始“可被验证地更稳”

教学点：

- 单元测试
- 集成测试
- 契约测试
- 端到端验证

角色压力落点：

- 使用者：逼“可信”必须变成可验证事实
- 守门者：把口传经验交给测试体系承接
- 继承者：证明测试本身也可以成为继承入口

### 第二十三章：法宝传世，版本号、变更日志与发布承诺

- 青炉内部渐稳之后，卷八最难的关变成对外立信
- 贺时进要求尽快给青炉打出第一个公开可传的版本，说现实窗口不会等你把话说得太满
- 顾迁衡提醒主角：不少旧流程其实偷偷依赖了青炉当前的细节行为，一旦改动不明说，外面迟早会把账全算回来
- 闻衡把问题掰得更狠：
  - 版本号是不是承诺
  - 变更日志是不是对外史负责
  - 发布时若故意不写那条会伤人的变化，算不算再一次背契
- 沈见微必须在这章立起对外发布口径：
  - 版本号不只是编号
  - 变更日志不只是宣传文案
  - 弃用、兼容、破坏性变化都必须明文
- 本章必须出现一次真正难看的推迟：
  - 团队本来准备出版本
  - 却因为一条未写清的行为变化，主动延后发布
- 本章结尾要让读者看见：
  - 公开发版本身就是立契
  - 诚实的延期，比失信的上线更像成长

教学点：

- semver
- changelog
- release checklist
- 弃用说明

角色压力落点：

- 诱惑者：代表“先发出去再说”的短期胜利学
- 渡桥人：代表兼容压力会怎样反咬发布
- 审契者：代表外史也必须可查、可追、可回头算账

### 第二十四章：开炉布道，crate 发布、二进制交付与用户入口

- 版本规则成立后，青炉终于要面对一个更具体的问题：
  - 别人到底怎样得到它
  - 别人第一次遇见它时会看见什么
- 程知序从使用侧提出最尖的问题：
  - 我不关心你内部多漂亮
  - 我只想知道怎么装、怎么跑、怎么判错
- 季循则第一次站到维护者前台，要处理来自门外的真正问题单
- 沈见微在这章必须做出一个克制决定：
  - 不为了显得“成熟”就把半熟 API 全暴露出去
  - 优先把二进制入口、安装路径、帮助信息和最小文档做扎实
- 本章必须形成四个可见动作：
  - 发布路径被写清
  - 安装方式被写清
  - `--help` / `--version` 一类入口开始承担公共解释责任
  - 使用者第一次反过来塑形项目路线
- 章尾必须让青炉真正迈出“出山”动作：
  - 它不再只由维护者设想用途
  - 它开始被真实用户使用和误用

教学点：

- crate 发布
- 二进制交付
- 用户入口
- 安装与帮助信息

角色压力落点：

- 使用者：第一次真正反向塑形青炉
- 继承者：第一次面对门外问题而不是门内作业
- 主角：第一次主动放弃“内部看起来更高级”的虚荣

## 五、卷九：问鼎守成

使命：让“上线之后怎么办”成为主线，而不是附录。这一卷必须把运行、观测、兼容与技术债写成明契之道最沉重的一场长期账。

### 第二十五章：入世之后，程序如何真正活着

- 青炉出山之后，不再只是手动跑几条命令的器
- 现实很快把它推向新的形态：
  - 被塞进发版流水线
  - 被挂进定时检查
  - 被要求在无人值守时持续守望
- 韩砺年讲出旧世界另一种沉默灾难：
  - 那些“平时挺好”的守夜进程
  - 一旦工作目录、环境变量、权限或锁状态变了，就会悄悄烂掉
  - 外面只会看到它还在活着，却不知道它早就不再可靠
- 沈见微必须在这章区分青炉的运行形态：
  - 一次性命令
  - 流水线调用
  - 长驻守望
- 本章必须让“程序真的活着”落成几个清楚动作：
  - 运行模式被点名区分
  - 进程边界、锁与退出条件被写明
  - 一类过去只在主角脑中存在的守夜经验，被第一次外显
- 本章结尾必须让读者看见：
  - 程序出炉不等于修行结束
  - 真正入世以后，才开始面对时间、环境与无人看守的压力

教学点：

- process
- service
- daemon
- 运行模式与退出条件

角色压力落点：

- 守门者：提供旧守夜流程的失败见闻
- 使用者：代表“没人盯着时也得可信”的现实要求
- 主角：第一次承认运行态本身也是契约

### 第二十六章：观天察地，日志、追踪、指标与可诊断系统

- 卷九的第二道难关来自一场真正的入世事故：
  - 青炉在一处远端环境里表现异常
  - 命令表面完成
  - 结果却迟迟与预期不符
- 众人第一反应仍然是“先找最懂的人看”
- 但这一次，沈见微强行压住英雄止火冲动，要求先沿观测路径复盘
- 季循第一次靠日志链与运行标记，而不是靠主角现场口述，追到问题真正发生的位置
- 沈见微在这章必须把 `qinglu-observe` 真正立起来：
  - 人类可读日志
  - 关键步骤标记
  - 能让跨环境问题被串起来的运行标识
  - 最小指标口径
- 本章必须让读者看见：
  - 观测不是豪华件
  - 观测是防止团队重新失明的反黑箱层
- 本章结尾必须落在一个结构性变化上：
  - 继承者第一次不靠主角直觉也能定位问题
  - 青炉第一次拥有“别人能顺着痕迹追你”的力量

教学点：

- log
- tracing
- metrics
- 可诊断系统

角色压力落点：

- 继承者：证明观测是后来者真正能接火的路径
- 使用者：提供入世现场的真实症状
- 审契者：代表“若观不到，就不算真的立住”

### 第二十七章：旧劫未消，兼容、重构、技术债与演进之术

- 卷九最终必须把“旧桥要不要拆”推上台面
- 顾迁衡整理出一份青炉当前桥单，把所有兼容动作第一次分成三类：
  - 必须立即保留
  - 可以限期共存
  - 必须明确淘汰
- 苏野平仍然为几条聪明的兼容壳辩护，认为这类桥留着最不伤现实
- 贺时进则把短期代价算得极硬：
  - 一旦拆桥
  - 培训、迁移、抱怨和窗口损失都要立刻爆出来
- 闻衡逼问众人：
  - 若每一条临时桥都因为眼前方便而永久保留
  - 那青炉和旧世界到底还有什么根本区别
- 沈见微必须在这章做出第一次真正会痛的裁定：
  - 至少一条高频兼容桥被正式标记退出时间
  - 至少一份迁移说明被写成公开路径
  - 至少一笔短期损失被承认为长期可继必须付的账
- 本章不能只停在“技术债存在”，而必须让技术债被具名、被分类、被安排退场
- 卷九结尾要落在高潮前夜的判断上：
  - 青炉已经有能力继续长大
  - 但它能不能继续诚实地长，还要看主角愿不愿意真的拆掉那条最方便的旧桥

教学点：

- 兼容层
- 弃用与迁移
- 重构
- 技术债

角色压力落点：

- 渡桥人：成为本章最核心的现实压力承受者
- 诱惑者：把短期绩效与季度代价顶到台前
- 同门者：代表“聪明桥壳”为什么总让人舍不得放手
- 主角：第一次把“长期主义”真正写成会伤当下的决定

## 六、卷七到卷九已固定的三个锚点

### 1. 守界裁定

已固定为：

**越界不是禁术；不写明边界、证明责任与退出条件，才是禁术。**

### 2. 对外立信

已固定为：

**测试、版本、发布与交付，不是项目尾声，而是青炉第一次真正向门外立契。**

### 3. 入世守成前夜

已固定为：

**卷九结尾必须出现一次限期拆桥与公开迁移动作，证明青炉愿意为长期可继支付短期代价。**

---

## 七、本轮修掉的不足

本文件主要修掉了下面四处旧缺口：

1. 卷七“安全 / 并发 / unsafe”不再只是知识点，而是有了旧桥、速度与证明责任的具体冲突
2. 卷八“测试 / 发布 / 交付”不再像教学附录，而是进入对外立信的主线
3. 卷九“运行 / 观测 / 迁移”不再停在附加说明，而是成为后半卷最重的现实账
4. 《明契卷》后段终于具备了把高潮代价推上台面的连续工程与人物压力链
