# 《万构界·明契卷》卷首事故逐场分镜：错版夜发

## 一、文档定位

本文件用于把 [01_卷首事故原型_错版夜发.md](./01_卷首事故原型_错版夜发.md) 继续下压成可直接起笔的逐场分镜。

它只负责三件事：

1. 把卷首事故拆成可写场次
2. 让人物冲突和工程病灶在第一章就同时露面
3. 给后续卷首样章提供明确的叙事节奏

本文件不是正文，但必须细到：

- 每一场谁在场
- 这一场把哪种病灶推上台
- 这一场在第一卷整体结构里负责什么转向

---

## 二、卷首总原则

卷首不能从解释概念开始，必须从“表面成功，真实失信”的违和感开始。

节奏上要遵守四条：

1. 先让读者看到命令成功，再让读者看到秩序失败
2. 先让程知序和季循撞墙，再让沈见微看见全局病灶
3. 裴照川必须把火救下来，否则读者不理解旧路为何持续被奖赏
4. 第一章结尾不能停在事故解决，而要停在“这只是延期”

---

## 三、逐场分镜

### 场一：窗口落下

- 时间：深夜，外部窗口即将关闭
- 地点：门内发版间
- 主视角：程知序
- 在场角色：程知序、贺时进、季循
- 本场目标：建立时间压力与“这是一条例行流程”的表面稳定感
- 场面动作：
  - 贺时进带着窗口信息压进来，话里只有一个结论：今晚必须发
  - 程知序按现行 README 和值守手册核对发版步骤
  - 季循第一次被叫来跟流程，只负责“照着做、记着看”
- 必须露出的信息：
  - 文档确实存在
  - 这条命令平时确实常用
  - 所有人都默认它是一条“可复走”的路
- 本场结尾钩子：
  - 程知序在终端前停了一瞬，问“还是这条？”
  - 贺时进回答：“还是这条，别再改了。”

### 场二：命令成功

- 时间：紧接上场
- 地点：同一地点
- 主视角：季循
- 在场角色：程知序、季循
- 本场目标：让读者先相信一次“平静完成”
- 场面动作：
  - 旧发版命令开始执行
  - 版本号正常生成
  - 说明模板自动吐出
  - 终端返回成功
- 必须露出的信息：
  - 表面上所有指标都像一次正常发布
  - 季循第一次产生“好像也没那么复杂”的错觉
- 本场结尾钩子：
  - 季循刚松一口气，外部回报就来了第一条异常

### 场三：同版异行为

- 时间：数分钟后
- 地点：发版间与远端回报窗口
- 主视角：程知序
- 在场角色：程知序、贺时进、季循
- 本场目标：打破“成功”幻觉，立起背契
- 场面动作：
  - 首批使用方反馈同一版本号行为不一致
  - 一组环境走新入口，一组仍走旧壳，一组直接失效
  - 贺时进第一反应不是追根，而是先压住扩散
- 必须露出的信息：
  - 问题不是“没跑完”，而是“跑成了不同东西”
  - 版本号与行为承诺开始脱节
- 本场结尾钩子：
  - 程知序低声说：“它不是坏了。它是在不同地方说了不同的话。”

### 场四：后来者进不去门

- 时间：异常出现后立刻
- 地点：排障侧台
- 主视角：季循
- 在场角色：季循、程知序
- 本场目标：把“继承失能”变成现场体感
- 场面动作：
  - 季循尝试按文档复走发版和定位流程
  - 他连续撞上没写明的环境变量、本地缓存和旧钩子顺序
  - 同样一份文档，对真正不在圈内的人没有实际入口
- 必须露出的信息：
  - 问题不在季循不聪明
  - 问题在门从来没有真正打开
- 本场结尾钩子：
  - 他抬头问程知序：“这一步为什么会去那条旧壳？”
  - 程知序答不上来，只能说“平时都是那几位知道。”

### 场五：守门者的沉默

- 时间：排障升级
- 地点：旧工具链维护侧
- 主视角：沈见微
- 在场角色：沈见微、韩砺年、季循、程知序
- 本场目标：让读者看见守门者不是恶意封门，而是长期活在不能轻动的恐惧里
- 场面动作：
  - 韩砺年赶到后第一句是“先别碰那段旧钩子”
  - 沈见微追问原因
  - 韩砺年只能给出碎片式解释：这段会连着本地状态、旧插件壳和历史缓存
- 必须露出的信息：
  - 守门者知道这里危险
  - 但他也没有一份完整可公开转交的地图
- 本场结尾钩子：
  - 沈见微第一次意识到，连韩砺年都不是在“掌握全图”，而是在背着碎图守夜

### 场六：快路再度上台

- 时间：窗口继续收紧
- 地点：发版间中央
- 主视角：沈见微
- 在场角色：沈见微、苏野平、贺时进、程知序
- 本场目标：把“快而有用”的真实价值推到台面，避免旧路变成纸片反派
- 场面动作：
  - 苏野平提出临时脚本与补丁链，主张先把今晚顶过去
  - 贺时进立刻支持，因为外部窗口不等人
  - 程知序知道这样能救火，但也知道这会把真正的问题再次压过去
- 必须露出的信息：
  - 快路不是虚假价值
  - 它之所以持续被奖励，是因为现实里它确实救得了命
- 本场结尾钩子：
  - 沈见微还没说话，门外就有人报：“裴照川到了。”

### 场七：英雄止火

- 时间：事故最紧时
- 地点：旧器接线台
- 主视角：季循
- 在场角色：裴照川、沈见微、韩砺年、苏野平、程知序
- 本场目标：让裴照川证明“为什么所有人都感谢英雄，也因此继续喂养旧病”
- 场面动作：
  - 裴照川不看文档，只问几句关键前提
  - 他凭记忆与经验拼起隐藏入口，补环境、换桥序、强行止火
  - 系统回稳，外部窗口勉强保住
- 必须露出的信息：
  - 这套旧秩序之所以活到今天，是因为真的有人能一把把它从火里拽回来
  - 也正因为这样，所有人都更难承认它已经病入骨
- 本场结尾钩子：
  - 现场有人松气，有人致谢，甚至有人开始说“这不也过来了”

### 场八：掌声里的失真

- 时间：止火之后
- 地点：逐渐安静的发版间
- 主视角：沈见微
- 在场角色：沈见微、裴照川、闻衡、程知序、季循
- 本场目标：让审契者把事故从“今晚已过”定性为“已经失信”
- 场面动作：
  - 闻衡对照版本说明、命令结果和现场补丁，明确指出这次已经构成背契
  - 程知序第一次明确拒绝“下次我私下再来找人跑一遍”的老路
  - 季循沉默地意识到：若不是站在现场，他永远学不会今天发生了什么
- 必须露出的信息：
  - 命令成功不等于契成立
  - 英雄止火不等于秩序成立
- 本场结尾钩子：
  - 闻衡对沈见微说：“今晚救回来的不是秩序，只是窗口。”

### 场九：延期，而非胜利

- 时间：第一章结尾
- 地点：发版间外侧走廊或夜风口
- 主视角：沈见微
- 在场角色：沈见微，可带裴照川或季循作短对照
- 本场目标：把事故收束成“必须起炉”的根因
- 场面动作：
  - 沈见微回看整条事故链
  - 他意识到自己最擅长的救火能力，也正是这套秩序迟迟不被重写的原因之一
  - 他第一次明确把问题看成：契、史、入口与责任同时失明
- 必须露出的信息：
  - 起炉理由已经成立
  - 主角不是旁观病灶的人，他也是旧秩序得以续命的一部分
- 本场结尾钩子：
  - 收在一句明确判断上：
    - 这不是一次被解决的事故
    - 这是一次被延期的崩坏

## 四、三章接口

### 对第一章的要求

- 必须完整包含场一到场九
- 不急着解释 Rust
- 只让读者先看见失信、失明与入口关闭

### 对第二章的接口

- 第二章应直接从场九后的事故拆解开始
- 把场二到场八暴露出的病灶拆成：
  - scope
  - 非目标
  - 最小可信入口

### 对第三章的接口

- 第三章再回答为什么要选明契之道
- 必须让“选 Rust”直接回应本分镜里的具体病理，而不是抽象优劣
