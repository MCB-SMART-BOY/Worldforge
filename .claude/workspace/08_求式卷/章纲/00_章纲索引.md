## 卷级设定

- **工程命题**：domain-driven design / bounded context / C4 model / event storming / architecture decision records (ADR)
- **核心张力**："画结构的人永远画不完——但画出来的部分让后来者不需要从零理解。"
- **四相主相**：式（结构的边界）
- **与前卷关系**：第一阶段"失式"被理解——求式卷正面回应结构的缺失

## 卷一「迷宫」Ch 1-10

| 章 | 标题 | 核心 |
|----|------|------|
| 1 | 没有地图 | 新人入职——问"系统的架构图在哪"——收到四张图——每一张都不一样——"哪一张是对的？""都是对的——在不同时间。都是错的——在现在。" |
| 2 | 过时的图 | 架构图上的模块——一半已经不存在——一半改名了——"图不会自动更新——但代码每天在变" |
| 3 | 口传的结构 | 结构在人的脑子里——"问老张——他知道这个服务为什么在那一层"——"老张离职了" |
| 4 | 结构的代价 | 没有结构图——每次变更要花一半时间考古——"考古的时间——比写代码的时间更长" |
| 5 | 不是画图 | 结构不是画图——是让后来者知道"这里有什么——它们怎么连接——为什么这样连接" |
| 6-10 | 建立结构文档体系——卷尾："结构不是完美的图——是诚实的图——标注了哪里不确定" |
