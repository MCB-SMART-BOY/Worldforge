### 第01章：这边能跑

- **核心对象层**：念→文（把念头快速变成能跑的代码）
- **核心相与失守**：契 → 背契（"先给个能跑的"——承诺被默认成立）
- **工程锚点**：Python脚本快速原型——`import`拼装、notebook试法、REPL（Read-Eval-Print Loop）即时反馈
- **张力曲线**：攀升型（时间紧→拼装成功→被奖赏→章末：一个被忽略的问题）
- **角色焦点**：周栖野（主角建立——最快点火的人，用一组notebook+临时脚本+手搓流程在极短时间内把别人不敢碰的问题做出了结果）；谢催成（外部压力——不断催促"先给个能看的"）；岑照渠（帮他把试法结果包成勉强能给人点开的入口）
- **六拍骨架**：

  3. 引出方法：Python的"先看见形"——不需要编译、不需要类型声明、不需要构建系统。写一行能跑一行。`import pandas`，`import requests`，拼起来就是一个解决方案。
  4. 项目落地：周栖野用notebook做探索、用脚本做批量、用`pip install`拉依赖——三个时辰交付了一个"能跑"的解决方案。

  6. 高层收束：一套虽然野但真的救了场的方法。结尾必须让读者直观感受：化形之道为什么会被现实持续奖赏。

### 第04章：pip install

- **核心对象层**：文（从"我能跑"到"我的依赖从哪来"——包管理的第一次自觉）
- **核心相与失守**：流 → 乱流（全局pip——所有人的Python环境互相污染）
- **工程锚点**：pip的全局安装问题——`pip install pandas`装的是哪个版本？全局环境意味着所有人的版本必须一致，但没有人能保证一致
- **张力曲线**：认知张力（周栖野试图理解：为什么同样的代码在别人的机器上报错？→发现pip全局安装的污染机制→引入venv）
- **角色焦点**：周栖野（第一次面对"我的环境不是别人的环境"——而且问题不在代码里）；宋既明（耐心解释pip的全局安装模型——"你装的pandas和季晚禾装的pandas可能不是一个版本。不是你的错——是pip没有隔离。"）
- **六拍骨架**：
  1. 问题先出：季晚禾跑周栖野的脚本——pandas报错。错误信息周栖野从未见过。
  2. 为什么痛："你装的pandas是什么版本？""我不知道——我跑`pip install pandas`，它装了什么就是什么。"
  3. 引出方法：virtualenv（虚拟环境）——为每个项目创建独立的环境。"隔离不是洁癖——是让后来者知道从哪里开始。"
  4. 项目落地：周栖野第一次创建venv——`python -m venv .venv`，`source .venv/bin/activate`，`pip install -r requirements.txt`。整个过程让他感到繁琐——但季晚禾的脚本能跑了。
  5. 多方复盘：宋既明："venv只是开始。你还需要告诉后来者你装了哪些包、什么版本。那就是requirements.txt——但我们下一章再说。"
  6. 高层收束：包管理不是魔法——是让"我这边能跑"变成"任何人都能跑"。但周栖野隐隐感到：这还不够。
- **入门检查**：前置：Ch01-03 / 新术语：pip、虚拟环境（virtualenv / venv）、包（package）（≤3）
- **三问预检**：🩻乱流（全局环境污染——所有项目的依赖混在一个Python里） 😣季晚禾——她代表所有被全局pip坑过的后来者 🛤️开始——venv让后来者有了独立的起点
- **包管理/类型/异步**：venv隔离/dynamic/sync

### 第05章：脚本成器

- **核心对象层**：文→器（一段脚本被五个人引用——它已经不再是脚本，是基础设施）
- **核心相与失守**：契 → 背契（脚本作者从未承诺过接口稳定性——但使用者已经把它当成了约定）
- **工程锚点**：脚本→依赖的质变——当一段脚本被足够多的人引用，它的修改成本不再是作者的，是所有人的
- **张力曲线**：倒钩型（周栖野想改一个函数签名→发现五个地方引用→每次试图改都发现新引用→"这不是我写的脚本——这是公共设施了"）
- **角色焦点**：周栖野（第一次感到"我的代码不再是我一个人的"）；季晚禾（代表使用者——"你改这个字段名——我那边有七个脚本会坏。"）
- **六拍骨架**：
  1. 问题先出：周栖野发现自己的脚本里有一个函数签名不合理——想改
  2. 为什么痛：改了——五个人的脚本坏了。他只能回退。但回退意味着这个不合理会一直被引用下去。
  3. 引出方法：这与C++世界的"ABI稳定性"是同一个问题——只是Python没有编译期检查，所有问题都在运行时爆炸
  4. 项目落地：周栖野逐个通知五个引用者——"我要改这个函数，你们准备一下。"但有一个人已经在用这个脚本做月度结算——改不动。
  5. 多方复盘：叶藏拙翻出记录——"你这个脚本——三个月内被引用了十一次。它已经不是脚本了——它是器。但没有人告诉你你造的是一件器。"
  6. 高层收束：从"脚本"到"器"的转变是无声的。没有门槛，没有仪式，没有审查。就是某一天——它突然变成了基础设施。而它的作者还不知道。
- **入门检查**：前置：Ch01-04 / 新术语：接口稳定性（API stability）、向后兼容（backward compatibility）（≤3）
- **三问预检**：🩻背契（未被声明的接口承诺——使用者依赖了作者不知道的契约） 😣季晚禾和所有依赖这个脚本的人 🛤️开始——周栖野第一次意识到"自己的代码"已经不再是自己的
- **包管理/类型/异步**：venv隔离/dynamic/sync

### 第06章：灵火高奖赏

- **核心对象层**：器（息壤作为平台开始成形——但"平台"的定义是靠使用量驱动的，不是靠设计驱动的）
- **核心相与失守**：流 → 乱流（从个人提效到团队依赖——使用量暴增，但治理结构为零）
- **工程锚点**：脚本与自动化如何从"个人提效"变为"团队依赖"——临界点：当脚本的"用户"数超过"作者"数时
- **张力曲线**：双峰型（第一个峰：季晚禾感谢——"你的脚本帮我省下了一整天"；第二个峰：白又新卡住——"我按你的README做了——卡在第三步"）
- **角色焦点**：周栖野（被推到"最会点火的人"的位置上——既享受又不安）；季晚禾（正面使用者——明确表示这套东西真的为她省了大量时间）；白又新（继承者首次尝试——失败。第一步就卡死。）
- **六拍骨架**：
  1. 问题先出：团队开始把越来越多模糊问题丢给息壤——"去找周栖野，他能跑出来。"
  2. 为什么痛：使用量暴增——周栖野的共享目录里已经有二十三个脚本。他不知道其中哪些还在用、哪些已经死了、哪些被他改过之后别人的引用断了。
  3. 引出方法：这本质上是一个"模块治理"（module governance）问题——只是现在还没有这个词
  4. 项目落地：季晚禾真诚地感谢周栖野——"你的脚本帮我省下了一整天。"这是化形之道最珍贵的奖赏：被人真正需要。
  5. 多方复盘：白又新按周栖野的README尝试跑一个脚本——卡在第三步。"你的README说'先装pandas'——但没说要装什么版本。我装的最新的——报错。"叶藏拙在角落里继续记录。
  6. 高层收束：所有人都知道这套方法有点乱——但没有人愿意在它最有效的时候叫停。灵火高奖赏的正反馈牢不可破。
- **入门检查**：前置：Ch01-05 / 新术语：模块治理（module governance）、README（≤2）
- **三问预检**：🩻乱流（脚本群无序生长——无人知道哪些在运行、哪些已死） 😣白又新——代表所有"按文档来但文档不够"的后来者 🛤️开始——白又新的失败暴露了入口问题
- **包管理/类型/异步**：venv隔离/dynamic/sync

### 第07章：叶藏拙的声音

- **核心对象层**：文→史（守门者的记录——把"现在正在发生的事"变成可追溯的历史）
- **核心相与失守**：契 → 背契（每一次"先这样，回头再整理"都是对后来者的债务——只是债主还不在场）
- **工程锚点**：工程考古学——记录"为什么这样写"比记录"写了什么"更重要。叶藏拙的账本不是bug追踪——是"前提追踪"。
- **张力曲线**：对峙型（叶藏拙摊开他的记录→周栖野第一次看到自己的"灵火"在他人眼中的样子→"你那个脚本——三个月前的人已经不会跑了。"）
- **角色焦点**：叶藏拙（守门者核心场景——他的记录不是批评，是证据。他在替无数走失的后来者说话。）；周栖野（从防御→"我不是故意的"→"但是它们确实在跑"→沉默）
- **六拍骨架**：
  1. 问题先出：叶藏拙把周栖野叫到一旁——翻开一本记录。"过去三个月——你写了十四个脚本。其中八个已经不能被三个月前的人复现。"
  2. 为什么痛：每一个"不能复现"的背后都有一个真实的人——他们花了时间尝试，失败了，然后去问了别人，或者放弃了。这些失败没有被记录在任何地方。
  3. 引出方法：叶藏拙的方法论——"我不记bug。我记前提。每一个脚本跑起来的隐藏前提：Python版本、pandas版本、哪个目录下有一个配置文件、哪个环境变量必须设成什么。"
  4. 项目落地：叶藏拙摊开一页——"这个脚本需要pandas≥1.3且<2.0。但你的README里写的是'pip install pandas'。pip装了2.1——它不认识某些API了。"
  5. 多方复盘：周栖野沉默了很久——"我不是故意的。""我知道。""但是它们确实在跑——""在你机器上。换了机器呢？换了人呢？三个月后呢？"
  6. 高层收束：叶藏拙合上账本——"我不是来批评你的。我是来告诉你——有人已经在替你记录你不想记录的东西了。那个人的账本里，你的灵火在别人的机器上长什么样。"

### 第08章：不只是快

- **核心对象层**：念（周栖野的自我认知——"我最快"是骄傲也是盲区）
- **核心相与失守**：契 → 背契（"快"作为一种身份认同——当你被定义为"最快的人"，慢下来就等于否定自己）
- **工程锚点**：速度伦理——工程中的"快"有两种：第一种是探索快（试法层的价值），第二种是交付快（入世层的要求）。混淆两者 → 沼泽。
- **张力曲线**：情感复合型（周栖野独处→翻看叶藏拙的账本→回忆自己做过的脚本→"我到底是在帮人还是在埋雷？"→唐野渡打断："别想太多。快就是你的道。"）
- **角色焦点**：周栖野（自我认知危机——"我最快的"正在从骄傲变成疑问）；唐野渡（镜像者的镜像功能——他不是敌人，他是周栖野最可能成为的样子："更快、更野、更不回头"）
- **六拍骨架**：
  1. 问题先出：周栖野独自翻看叶藏拙的账本——每一条记录都像一面镜子
  2. 为什么痛：他不是不想整理——是整理意味着承认"之前的做法有代价"。而那个"之前"——正是他最有成就感的时刻。
  3. 引出方法：工程中的"快"有两种价值——探索阶段的快（降低试错成本）和交付阶段的快（增加未知风险）。Python在探索阶段的快是真正的优势——问题在于把探索阶段的产出直接交付。
  4. 项目落地：周栖野回想起第一章的救场——"那一次我真的需要快。如果慢一步——月度结算延期。那个快——是对的吗？"
  5. 多方复盘：唐野渡出现——"你在想什么？""我在想——我做的事到底是在帮人，还是在埋雷。""都是。"唐野渡说。"快就是你的道。没有你的快——第一章他们就延期了。别让叶藏拙的账本让你怀疑自己。"
  6. 高层收束：唐野渡的话是对的——也是危险的。"快就是你的道"可以让周栖野不内耗——也可以让他永远不回头。
- **入门检查**：前置：Ch07 / 新术语：速度伦理（velocity ethics）、技术债（technical debt）（≤2）
- **三问预检**：🩻背契（"快"作为身份认同——让"慢"变为自我背叛） 😣周栖野自己——身份危机 🛤️暂未变化——唐野渡的安慰推迟了周栖野的觉醒
- **包管理/类型/异步**：venv隔离/dynamic/sync

### 第09章：点火之后

- **核心对象层**：文→域（息壤的使用范围超出了周栖野的视野——他不知道的东西正在变多）
- **核心相与失守**：流 → 乱流（使用范围的扩张速度超过了记录的速度）
- **工程锚点**：脚本生态系统的自组织——当足够多的脚本存在于共享空间，它们会互相引用、形成隐式依赖网。"import一个脚本"会成为最危险的依赖——因为你不知道那个脚本又import了什么。
- **张力曲线**：悬疑型（周栖野接到一个报修→追溯→发现这个报错来自一个他从未见过的脚本→那个脚本引用了他三个月前的一个函数→他已经忘了那个函数怎么写的了）
- **角色焦点**：周栖野（发现"自己造的"已经超出了"自己知道的"——失控感）；岑照渠（同门者——"不是只有你一个人在点火。每个人都在点火。火在互相烧。"）
- **六拍骨架**：
  1. 问题先出：周栖野接到一个报修——一个他从未见过的脚本报错
  2. 为什么痛：追溯发现——那个脚本`from zhou_utils import parse_fields`。`zhou_utils`是他三个月前写的——他已经忘了parse_fields的逻辑了
  3. 引出方法：隐式依赖网（implicit dependency graph）——Python的import机制让依赖关系"能跑就行"，没有人会主动画出依赖图
  4. 项目落地：周栖野打开`zhou_utils.py`——发现里面有`import requests; import pandas; from .helpers import normalize`。`helpers.py`在哪？在共享目录的一个子目录里。那个子目录——他也忘了。
  5. 多方复盘：岑照渠："不是你一个人的问题。我import了你的parse_fields——然后我的脚本被季晚禾引用。现在的问题是——如果改了parse_fields，炸的不只是你的东西。季晚禾根本不知道她依赖了你的函数——她只知道她依赖了我。"周栖野："她依赖了你——你依赖了我——我依赖了三个月前的自己——三个月前的自己已经不在这个房间里了。"
  6. 高层收束：火点了——照亮了路，也照亮了沼泽。沼泽不是一个人制造的——是每个人都在救火时留下的脚印。现在这些脚印互相交叠——分不清谁踩的。
- **入门检查**：前置：Ch01-08 / 新术语：隐式依赖网（implicit dependency graph）、导入链（import chain）（≤2）
- **三问预检**：🩻乱流（import链的无序生长——无人能画出完整的依赖图） 😣季晚禾——她在隐式依赖网的最外层，最脆弱 🛤️否——依赖网在继续生长
- **包管理/类型/异步**：venv隔离/dynamic/sync

### 第10章：沼泽边缘

- **核心对象层**：域（沼泽的全貌——但只是第一次瞥见）
- **核心相与失守**：式 → 失式（沼泽没有边界——没有结构——没有地图）
- **工程锚点**：技术债的可视化——不是"债有多少"，是"债在哪、谁欠的、欠了谁的"。沼泽的边缘画不出来，因为每发现一个新的引用链就扩展一次边界。
- **张力曲线**：崩塌型（周栖野和叶藏拙试图画出息壤的完整依赖图→每画一层发现新的一层→画到深夜→依赖图覆盖了整面墙→周栖野站在墙前——"这不是沼泽。这是一片海。"）
- **角色焦点**：周栖野（第一次看到沼泽的全貌——看到边缘——看不到边界以外的任何东西）；叶藏拙（"我已经记录了三个月。这面墙——只是我知道的部分。我不知道的——更多。"）
- **六拍骨架**：
  1. 问题先出：周栖野决定画出息壤的完整依赖图——"至少让我知道沼泽的形状。"
  2. 为什么痛：他和叶藏拙从自己的脚本开始→trace每一个import→每一个引用→每一个"我以为没人用"的函数→画了三个时辰
  3. 引出方法：Python的`import`链是可追溯的——`sys.modules`、`pipdeptree`——只是之前没有人追溯过
  4. 项目落地：依赖图覆盖了整面墙。二十三个脚本——对应着超过两百个隐式依赖关系。其中六十四个是循环引用——"你import我，我import你，但我们都不是故意这样写的。"
  5. 多方复盘：叶藏拙指着图的边缘——"这里——是你不知道的东西。季晚禾在引用的那个函数——你忘了它的存在。那个函数引用了林过川留下的一段代码——林过川在息壤出生之前就离开了。你的沼泽——有一部分不是你的。是你之前的那个人的。"
  6. 高层收束：周栖野站在墙前——第一次看到沼泽的边缘。边缘之外——他看不到任何东西。但至少现在他知道：沼泽存在。沼泽有形状。沼泽下面——还有更早的遗迹。
- **入门检查**：前置：Ch01-09 / 新术语：依赖图（dependency graph）、循环引用（circular import）（≤2）
- **三问预检**：🩻失式（沼泽没有结构——没有边界——没有地图） 😣所有被隐式依赖链连接的人 🛤️开始——依赖图是画地图的第一步
- **包管理/类型/异步**：venv有意识/dynamic/sync
