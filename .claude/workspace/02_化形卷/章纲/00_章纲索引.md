## 二、独有叙事维度：三维演化弧线

化形卷是第二卷。读者已在驭器卷中看见"没有工具链的蛮荒时代"——C++因为没有包管理器，只能用十七条手工桥管理依赖。化形卷是**对蛮荒时代的第一次系统回答**：Python世界天然就有包管理（pip），但"有包管理"和"包管理不制造新问题"是两回事。

### 维度一：包管理演化 —— 从 pip install 到 lock file

| 阶段 | 章段 | 工具状态 | 核心痛苦 |
|---|---|---|---|
| 蛮荒 | Ch 1-10 | `pip install` 全局安装 | "你装的是什么版本？""不知道，最新的。" |
| 隔离觉醒 | Ch 11-20 | virtualenv/venv | "在我机器上能跑"——因为我的环境是干净的 |
| 依赖声明 | Ch 21-30 | requirements.txt | "这个文件里三分之一已经不需要了，三分之一是错的" |
| 锁定依赖 | Ch 31-40 | pipenv/poetry → uv | lock file的哲学——"依赖的依赖也是依赖" |
| 现代归宿 | Ch 41-50 | uv/pixi | pip→conda→poetry→uv的演化不是"更好"，是"更诚实" |
| 制度化 | Ch 81-120 | lock file + CI验证 + 三层环境 | 入世层的契约：版本、兼容、废弃策略——写进代码里 |

### 维度二：类型系统 —— 从"什么都行"到"渐进类型"

| 阶段 | 章段 | 状态 | 叙事体现 |
|---|---|---|---|
| 动态自由 | Ch 1-10 | 没有类型——"快就完了" | 一个函数接受`data`——可能是DataFrame、dict、list、None |
| 类型注释 | Ch 21-40 | Type Hints (PEP 484) | "写类型是给自己加枷锁"——谢催成的抵抗 |
| 静态检查 | Ch 41-60 | mypy/pyright | 第一次全量类型检查——237个警告 |
| 运行时验证 | Ch 61-80 | Pydantic/FastAPI | 类型不只是注释——可以在运行时挡下非法数据 |
| 渐进哲学 | Ch 81-120 | 类型是契约，但不强制全量 | "关键路径上有类型就够了。试法层不需要。" |

### 维度三：异步演化 —— 从同步阻塞到结构化并发

| 阶段 | 章段 | 状态 | 叙事体现 |
|---|---|---|---|
| 同步阻塞 | Ch 1-20 | 一个请求卡住→全部门等 | "它卡在第三步。不知道在等什么。" |
| asyncio | Ch 31-60 | 协程——协作式多任务 | "它在等I/O。我们让它等的时候去做别的事。" |
| 生态分裂 | Ch 61-80 | trio/anyio——structured concurrency | "asyncio能跑——但出问题时谁知道哪个协程在等哪个？" |
| 生产化 | Ch 81-120 | asyncio + 观测 + 错误恢复 | 异步不只是快——是"等待时可以被观测" |

## 十、写作原则

- **先工程，后修辞**：每个工具/方法的引入必须有前置痛苦事件
- **中文专有名词每次注英文原名**：格式"虚拟环境（virtual environment / venv）"
- **文学表达标注工程原型**：参见第六节对照表
- **痛苦驱动**：pip→venv→requirements.txt→poetry→uv 的每一步演化都必须由一个具体事故触发
- **入门检查**：每章前置依赖≤2，新术语≤3
- **三问必答**：每章章纲必须能通过三问预检
