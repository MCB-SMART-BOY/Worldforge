## 卷一「崩塌」Ch 1-10 · 全平台崩溃

### 第1章：全绿全灭

- **六拍骨架**：全平台监控全绿——所有健康检查通过——所有supervisor树正常——然后一个外部API返回了意外的格式——七层服务全链崩溃——supervisor重启——再崩溃——循环。"不是没做容断——是容断的假设被一起打破了。"
- **工程锚点**：supervisor tree / restart strategy / crash loop
- **三问预检**：🩻乱流 😣所有依赖该平台的外部系统 🛤️开始——崩溃暴露了容断设计的前提缺陷

### 第2章：supervisor也没能救

- **六拍骨架**：回顾supervisor树的配置——`max_restarts: 3, max_seconds: 5`——重启了三次——然后supervisor自己放弃了。"不是容断失效——是容断的策略没有覆盖这种失败模式。"
- **工程锚点**：OTP supervisor / restart intensity / crash isolation

### 第3章：传讯牌全亮

- **六拍骨架**：事故发生后——所有传讯牌同时亮——值班的人不知道该先接哪一个——"容断不只是系统的——也是人的——当所有告警同时响——人怎么判断——先救谁。"
- **工程锚点**：alert storm / incident response / triage

### 第4章：根因不是代码

- **六拍骨架**：追查根因——不是代码bug——是一个外部依赖的行为变更——"容断保护了内部故障——但外部故障——在容断范围的边缘——炸了。"
- **工程锚点**：external dependency failure / blast radius

### 第5章：不是所有东西都该活

- **六拍骨架**：事故后复盘——有人提议给所有服务加更多supervisor——主角反驳："不是加更多保护——是决定——什么可以不活。容断不是保护一切——是保护最重要的。"
- **工程锚点**：triage / criticality tiering / SLO-driven resilience

### 第6-10章：展开事故影响——逐步建立容断新框架——卷尾：不是"不会再炸"——是"炸了之后——不该死的东西——不会死"
