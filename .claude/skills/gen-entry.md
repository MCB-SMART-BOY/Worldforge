# /gen-entry — 入门引导生成

为《万构界》生成面向新读者的入门引导材料。
**核心命题：万构界的入门太难。读者被直接扔进一个密集的世界观而没有地图。这个 skill 负责造地图。**

## 要解决的具体问题

当前《万构界》的阅读体验：
- 序章在 158 行内抛出约 15 个世界术语（宿域、外史册页、回火索、守门机、问心台、契册、白契纸、渡桥司、石录镜、旧兼容壳...）
- 没有"这是什么样的世界"的前置介绍
- 读者在没理解世界规则之前就被要求关心角色的工程决策
- 不懂编程的人在第一页就可能放弃

## 参数

- `target` — 要生成什么入门材料：
  - `world-primer` — 世界概述（30秒了解这个世界）
  - `volume-entry` — 卷级入口页（替换/增强当前的 `00_正文索引.md`）
  - `chapter-zero` — "第零章"世界观引导叙事（一个独立短章，通过角色日常引入世界）
  - `reading-guide` — 阅读指南（推荐阅读顺序 + 每卷适合什么读者）
  - `glossary-lite` — 精简术语表（只包含前5章必需知道的术语，附一句话解释 + 在哪个场景首次出现）
  - `all` — 全部生成

- `volume`（可选）— 限定到某卷

## 设计铁律（从研究提炼）

### 1. 从角色体验出发，不从天而降
永远不写："万构界是一个由四相法则驱动的工程文明世界……"
而是写：一个角色在凌晨两点被回铃惊醒，发现纸上写的退路走不通。

**世界不是被解释出来的，是被角色撞上的。**

### 2. 冰山原则
展示 1/8，隐藏 7/8。入门材料的目标不是让人"理解一切"，而是让人"想继续读"。
问自己：删掉这段信息，读者是否仍然能跟上场景？如果是 → 删除。

### 3. 每个新术语必须"即插即用"
引入一个新概念时，必须立刻让读者看见它"坏了是什么样"。
不是："四蚀是指失式、乱流、背契、断史"
而是："纸上写着能退。他照纸走。到第三步，路断了。这就是背契——纸上的承诺和手里能走的路，是两回事。"

### 4. 控制认知负荷
- 入门材料每页不超过 3 个新世界观术语
- 每个术语首次出现时，在同一个自然段内给出"一句话够用解释"
- 术语解释必须嵌入角色感知，不跳出叙事

### 5. 创造好奇，不是制造困惑
- 好的：读者问"为什么会这样？" → 想继续读
- 坏的：读者问"这是什么？" → 想去翻术语表
- 解法：先展示后果（有趣），再追溯原因（满足好奇）

## 各类入门材料的模板

### A. World Primer（世界概述 · 30秒版）

目标：让读者在 30 秒内决定"值不值得读"。

格式：
```markdown
# 万构界 · 先读这个

> **这个世界不是由魔法驱动的。是由工程文明驱动的。**

- "道"不是修仙门派 → 是**编程语言**
- "器"不是法宝 → 是**软件项目**
- 这里的人用 Rust 写契约、用 C++ 守古核、用 Python 点火试法、用 Go 管服务阵

这个世界有四条法则——**式 · 流 · 契 · 史**。每条崩了，长成一种病——**失式 · 乱流 · 背契 · 断史**。

> 🦠 故事里所有的大事故，追到底都是这四种病在发作。

> 👹 最大的反派不是魔王。是一句话：**"先这样，回头再整理。"**

> 🏆 最高的成就不是战力突破。是：**后来者不用你在场，也能沿着路走下去。**

好了。现在你可以进正文了。
```

要求：不超过 200 字。纯展示，零解释。

### B. Volume Entry（卷级入口页）

目标：替代 `00_正文索引.md`。不只是章节列表，而是"为什么你应该读这卷"。

格式：
```markdown
# XX卷 · 阅读入口

## 这卷关于什么（30字）
> 一句话概括本卷核心命题。

## 这卷适合你，如果你——
- [一个读者能对号入座的具体情境]
- [另一个具体情境]
- [第三个]

## 这卷的核心冲突
[一段不超过 80 字的概括，必须同时写清楚工程内容和人物代价]

## 这卷的主角是谁
[名字]，[职责]。他最怕的不是[表面恐惧]，而是[深层恐惧]。

## 你会学到什么
- [工程概念1]：[一句话，它在真实世界怎么痛]
- [工程概念2]：[同上]
- [工程概念3]：[同上]

## 章节导航
| 章 | 标题 | 一句话（这章让你看见什么） |
|---|------|--------------------------|
| 序/01 | ... | ... |
```

### C. Chapter Zero（第零章 · 世界观引导叙事）

目标：一个 800–1200 字的独立短叙事，通过一个角色的日常场景，自然引入世界观。
**这不替代序章——它放在序章之前或作为附录。它的职责是"让读者在进入正片之前先有方向感"。**

设计约束：
- 用一个具体角色的具体日常开场（不是旁白，不是"在这个世界中……"）
- 主角可以是一个旁观者、一个新人、一个正在经历"第一次事故"的人
- 必须在 300 字内回答：**在哪 / 谁的视角 / 现在发生什么**
- 全章引入的新世界观术语不超过 5 个，每个在出现时通过角色感知自然解释
- 必须展示至少一种"四蚀"的具体症状（让人看见病，不只是听到定义）
- 章末必须让读者产生一个具体的好奇（"后来呢？""为什么会这样？""那个人后来怎样？"）
- 可以引入四个卷的核心命题作为"远处的地标"（暗示但不展开）

叙事结构（6 拍简化版）：
1. **日常被打断**：一个普通的工程场景，被一个小事故打破
2. **第一次尝试失败**：角色按"纸上写的"去修，走到第三步卡住
3. **老手介入**：一个更有经验的人用"纸上没写"的方法修好了
4. **短暂的松气**：问题暂时解决，围观者散去
5. **一个人没走**：有人留在原地，看着修好的地方，说了一句话
6. **那句话才是真正的开场**：点出这个世界最核心的问题——"今天修好了，明天呢？"

### D. Reading Guide（阅读指南）

目标：帮助不同背景的读者找到最适合的入口。

格式：
```markdown
# 万构界 · 阅读指南

## 你是什么类型的读者？

### 🚀 "我想最快感受到这个世界的味道"
→ 读 [简阵卷 第01章](正文/04_简阵卷/第01章_扩域.md)
理由：开场即事故，30行内建立核心冲突。工程术语最少，人类情境最普适。

### 🏗️ "我想从头了解这个世界的完整逻辑"
→ 读 [明契卷 第01章](正文/01_明契卷/第01章_凡火未明_问题从何而来.md)
理由：从发版事故开始，逐步建立四相四蚀的概念。但注意——前5章术语密度较高。

### 🦴 "我想看最有'古器'厚重感的"
→ 读 [驭器卷 第01章](正文/02_驭器卷/第01章_重器不眠.md)
理由：一座跑了十几年的古核和它不敢退休的守门人——如果这还不能引起你的兴趣，试试化形卷。

### 🔥 "我想看最快乐的工程灾难"
→ 读 [化形卷 第01章](正文/03_化形卷/第01章_这边能跑.md)
理由："我这边能跑"——每个程序员都说过的话，和它留下的脚本沼泽。

### 📚 "我想按顺序读"
→ 明契 → 驭器 → 化形 → 简阵
理由：见病 → 追根 → 反照 → 结账。这是完整的认知弧线。
但注意：每卷可以独立阅读。不强制按顺序。
```

### E. Glossary-Lite（精简术语表 · 前5章必需）

目标：只列出读者在前 5 章会遇到的术语。每个术语最多两行解释 + 一个"在哪第一次出现"。

格式：
```markdown
| 术语 | 一句话 | 首次出场 |
|------|--------|---------|
| 四相 | 式（结构）· 流（资源）· 契（承诺）· 史（版本） | 第1章（闻衡圈出说明纸上的漏洞时） |
| 背契 | 纸上的承诺和手里能走的路是两回事 | 第1章（回退步骤到第三步走不通） |
| ... | ... | ... |
```

限制：不超过 10 个术语。超过 → 说明术语密度过高。

## 输出

根据 `target` 参数生成对应的完整 Markdown 文件。

若 `target=all`，生成顺序为：World Primer → Volume Entry（每卷）→ Chapter Zero → Reading Guide → Glossary-Lite。

## Gotchas（常见入门设计错误）

- **信息过载**：入门材料的目标是"让读者想读"，不是"让读者读完就全懂"。30秒版超过200字 → 重写。
- **定义式开场**：入门材料不应以任何"XX是YY"的定义句开头。必须以场景或具体意象开头。
- **傲慢的预设**：不要假设读者懂编程。工程术语保留（这是氛围），但每个工程术语出现时上下文必须让不懂的人也大概猜到它在干什么。
- **术语表成为拐杖**：如果术语表很长（>15条），说明正文本身没有在每个术语出现时做"即插即用"的嵌入解释。术语表是补救，不是设计。
- **第零章变成缩微版正文**：第零章的角色和情节不应和正文章节重复。它是独立的"引桥"——短、具体、有自己的小完整性。
