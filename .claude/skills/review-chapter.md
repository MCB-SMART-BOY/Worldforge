# /review-chapter — 章节审校

审校一章正文，对照《万构界》全部写作铁律给出修改建议。
**本章审校同时检验两条轴：逻辑正确轴 + 剧情张力轴。缺一不可。**

## 参数

`chapter_path` — 章节文件路径（如 `正文/04_明契卷/第01章_凡火未明_问题从何而来.md`）

## 审校清单

### 一、三条总裁定（必过）

1. **先工程，后修辞**：这一章的修辞是否压过了工程逻辑？读者能否清楚说出"这里在处理什么真实工程问题"？
2. **设定可失守**：若涉及世界观概念，是否展示了它的失败形态（坏了会怎样）？
3. **成长=责任升级**：主角/核心人物的成长是否表现为责任扩容（能守更多、能立约、能传火），而非战力升级（更强、更快、更无敌）？

### 二、六拍结构（通用章法）

检查章节是否走过这六拍，并标记缺失或薄弱环节：
1. 问题先出 —— 开场就让人看见痛
2. 讲清为什么痛 —— 不是"技术难"，是"这个难落到谁身上"
3. 引出语言特性/工具链/工程方法 —— 用真实术语，不是世界观隐喻
4. 在具体项目/器/门中落地 —— 青炉/玄枢/息壤/驿河
5. 团队/维护/继承视角复盘 —— 不止主角一个人
6. 收束到更高层判断 —— 一句话回扣本卷文明命题

### 三、剧情张力审计（⚠️ 新增维度）

本章必须同时过这五条剧情张力检查：

#### 3.1 张力曲线
- [ ] 本章是否有一条可辨识的张力曲线？（上升 → 小释放 → 再升高 → 章末高点或悬念）
- [ ] 张力最高点是否出现在一个"读者没想到但回想起来必然如此"的位置？
- [ ] 是否有至少一处"呼吸点"让读者消化前面的冲击？（连续高张力 = 读者麻木）
- [ ] 章末是否留下了"必须翻下一页"的理由？（悬念/未答问题/情感余震/代价预告）

#### 3.2 揭示时机
- [ ] 本章的核心信息（工程真相/人物秘密/系统缺陷）是在读者最想知道的时刻给出的，还是过早/过晚？
- [ ] 有没有"角色知道但读者不知道"的张力？（戏剧反讽 —— 读者替角色捏一把汗）
- [ ] 有没有"读者知道但角色不知道"的张力？（读者看着角色走向陷阱）
- [ ] 揭示是"展示"出来的还是"告知"出来的？（展示 > 告知）

#### 3.3 情感锚点
- [ ] 读者在本章中是否有一个可以共情的人？（不必是主角，但必须有人）
- [ ] 本章的情感弧线是什么？（困惑→明了？恐惧→勇气？孤独→连接？挫败→决心？）
- [ ] 章末的情感余震是什么？（读者合上这一章后，心里留下什么感觉？）
- [ ] 是否避免了"全员冷静理性分析"？（工程小说最易犯的病：所有人都是工程师，没有人在情感上受伤）

#### 3.4 代价可视
- [ ] 本章的代价是否让读者"看见"了？（不只是说"有人付出了代价"，而是具体场景：谁，失去了什么，在什么时刻）
- [ ] 代价是否不可逆？（可逆的代价不是代价，是暂存）
- [ ] 代价是否落在了具体的人身上，而不是抽象的"团队"或"项目"？

#### 3.5 因果链
- [ ] 本章的每一个重要事件是否都有一个"因为"在前面？（不是"然后发生了"，而是"因为X，所以Y"）
- [ ] 是否有任何事件出现得"太巧"？（巧合可以启动故事，但不能解决故事）
- [ ] 本章的事件是否自然生长自上一章的结局？（连接处不能生硬切换）

### 四、入门友好度审计（⚠️ 新增维度）

特别针对新读者的认知负荷：

- [ ] 本章前 500 字内，新读者能否回答这三个问题：**我在哪？谁的视角？现在发生什么了？**
- [ ] 本章新引入的世界术语是否不超过 3 个？（超过 3 个，新读者开始"跳读"）
- [ ] 每个新术语首次出现时，是否通过角色体验自然解释（而非旁白说明文）？
- [ ] 是否能用一句话讲清"这章写了什么"给一个没读过前文的人听？
- [ ] 工程术语的使用是否让不懂编程的读者也能从上下文猜出大意？（术语不是门槛，是氛围）

### 五、三问自查（每条场景必过）

对章节中每个主要场景：
1. 🩻 在结算哪一种四蚀（失式/乱流/背契/断史）？
2. 😣 代价落在谁身上？
3. 🛤️ 后来者有没有比之前更有路可走？

若两个以上答不上 → 场景未接上世界观核心。

### 六、术语铁律

- [ ] 是否保留了真实工程术语（Cargo/crate/trait/Result/CI/tracing/service 等）？
- [ ] 世界观术语是否只用于解释位置，而非替换真实术语？
- [ ] **⚠️ 铁律四之补充**：中文表达的CS/工程专有名词每次出现是否标注了英文原名？（如"所有权（ownership）"、"健康检查（health check）"）参考：`.claude/canon/24_世界术语-现实工程对照表.md`
- [ ] **⚠️ 文学表达原型**：首次出现的世界观文学表达（玄枢、石录、火、桥、传火等）是否通过场景或括号标注了工程原型？
- [ ] 新出现的世界观概念是否在此卷内有够用解释（不假设读者读过别卷）？

### 七、命名规范

- [ ] 系列名固定为「万构界」
- [ ] 卷名格式为「《万构界·X卷》」
- [ ] 无 `xx百炼成仙` 残留

### 八、跨卷规则

若本章引用了共享事件或其他卷的角色：
- [ ] 是否在本章内给出了够用解释？
- [ ] 是否只做互文增益，不把别卷写成本章前提？
- [ ] 是否从本卷主角的代价和病理重新叙述？

## Gotchas（常见失分点）

- **工程小说最常见的病**：所有人都是冷静理性的工程师，没有人真正在情感上受伤。如果你发现一整章没有人表现出恐惧、愤怒、羞耻、或脆弱的希望——这一章大概率漂在工程概念之上，没有沉到人的层面。
- **术语轰炸**：一章新概念超过 5 个，认知超载。解法：把概念分散到不同章，每章聚焦 1-2 个新概念 + 1 个旧概念深化。
- **张力平铺**：从头到尾同一强度 = 读者麻木。必须有呼吸点。高峰之后给半页静默。
- **告知而非展示**：发现自己在写"XX 是 YY"的定义式句子 → 改成角色在具体场景中撞上这个概念。
