# /review-chapter — 章节审校

审校一章正文，对照《万构界》全部写作铁律给出修改建议。

## 参数

`chapter_path` — 章节文件路径（如 `正文/01_明契卷/第01章_凡火未明_问题从何而来.md`）

## 审校清单

### 一、三条总裁定（必过）

1. **先工程，后修辞**：这一章的修辞是否压过了工程逻辑？读者能否清楚说出"这里在处理什么真实工程问题"？
2. **设定可失守**：若涉及世界观概念，是否展示了它的失败形态（坏了会怎样）？
3. **成长=责任升级**：主角/核心人物的成长是否表现为责任扩容（能守更多、能立约、能传火），而非战力升级（更强、更快、更无敌）？

### 二、六拍结构（通用章法）

检查章节是否走过这六拍，并标记缺失或薄弱环节：
1. 问题先出 —— 开场就让人看见痛
2. 讲清为什么痛 —— 不是"技术难"，是"这个难落到谁身上"
3. 引出语言特性/工具链/工程方法 —— 用真实术语，不是世界观隐喻
4. 在具体项目/器/门中落地 —— 青炉/玄枢/息壤/驿河
5. 团队/维护/继承视角复盘 —— 不止主角一个人
6. 收束到更高层判断 —— 一句话回扣本卷文明命题

### 三、三问自查（每条场景必过）

对章节中每个主要场景：
1. 🩻 在结算哪一种四蚀（失式/乱流/背契/断史）？
2. 😣 代价落在谁身上？
3. 🛤️ 后来者有没有比之前更有路可走？

若两个以上答不上 → 场景未接上世界观核心。

### 四、术语铁律

- [ ] 是否保留了真实工程术语（Cargo/crate/trait/Result/CI/tracing/service 等）？
- [ ] 世界观术语是否只用于解释位置，而非替换真实术语？
- [ ] 新出现的世界观概念是否在此卷内有够用解释（不假设读者读过别卷）？

### 五、命名规范

- [ ] 系列名固定为「万构界」
- [ ] 卷名格式为「《万构界·X卷》」
- [ ] 无 `xx百炼成仙` 残留

### 六、跨卷规则

若本章引用了共享事件或其他卷的角色：
- [ ] 是否在本章内给出了够用解释？
- [ ] 是否只做互文增益，不把别卷写成本章前提？
- [ ] 是否从本卷主角的代价和病理重新叙述？
