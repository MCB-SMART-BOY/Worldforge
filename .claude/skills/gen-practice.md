# /gen-practice — 实践单生成

从一章正文生成对应的「卷外配套」章节实践单。
**实践单不只是验证工程概念——它应该让练习者感受到：这个工程概念在真实世界里是怎么痛的，而学会它之后你能保护谁。**

## 参数

- `chapter_path` — 章节文件路径
- `volume` — 所属卷（明契卷/驭器卷/化形卷/简阵卷）
- `chapter_number` — 章号

## 设计原则

### 从"验证概念"到"体验代价"

好的实践单不只是"你做一遍看能不能跑通"。它让练习者：
1. 先**撞上问题**（制造一个可控的小失败）
2. 再**理解概念**（引入本章的工程方法来解决）
3. 最后**反思代价**（如果不这么做，谁会受伤）

### 每道练习的叙事包装

每个练习都有一个微型叙事场景（1-2 句话），让练习者知道"我在替谁解决什么问题"：
- "你是北院的新人，季循让你接手一段回退脚本，但纸上的步骤走到第三步就卡住了……"
- "你的团队刚接手了一个三年前的 Python 项目，README 里写着 'just run main.py'……"

## 实践单模板

### 前置信息
- 所属卷/章
- 对应工程主题
- 本章核心四蚀
- 前置知识要求
- **本章的"人性代价"**（一句话：学不会这个，谁会受伤？）← ⚠️ 新增

### 三个练习层次

#### 第一层：碰撞练习（先撞上问题，再理解概念）⚠️ 重新命名

- 目标：让练习者先经历"纸上写的走不通"，再引入正确做法
- 形式：一个故意不完整的场景 → 练习者尝试 → 撞墙 → 引入概念 → 再做一次
- 数量：2 个
- 格式：
  ```
  ### 练习1-1：[标题]
  **场景**：[1-2句话的微型叙事，你和谁，在哪，什么压在你心上]
  **第一次尝试**：[你按"纸上写的"去做……]
  **你撞上了什么**：[预期的失败/报错/困惑]
  **现在引入**：[本章的工程概念]
  **再做一次**：[用正确方法重新操作]
  **观察**：[这次有什么不同]
  **问自己**：如果你不知道这个概念，谁会在什么时间点受伤？
  ```

#### 第二层：变体练习（换个场景，概念还站得住吗？）

- 目标：确认读者能在不同场景中应用同一概念
- 形式：改变一个条件（语言/项目/团队规模/时间压力/人员变动）
- 数量：1-2 个
- 格式：
  ```
  ### 练习2-1：[标题]
  **变化**：[什么条件变了——人走了？项目大了？时间更紧了？语言换了？]
  **你的判断**：[一个需要做选择的开放问题]
  **为什么**：[引导读者写下决策理由]
  **如果选错了**：[代价会落在谁身上？]
  ```

#### 第三层：连接练习（这个概念在整个工程图景里的位置）

- 目标：确认读者能把本章概念放进更大的工程图景
- 形式：联系前章或预演后章的跨概念练习
- 数量：1 个
- 格式：
  ```
  ### 练习3-1：[标题]
  **连接**：[连接哪两章的概念]
  **场景**：[一个需要综合判断的任务]
  **你的设计**：[需要做什么决策]
  **反思**：你现在做的这个决定，三个月后谁会感谢你？谁会骂你？
  ```

### 每层后的自检

- [ ] 我是否理解了练习要验证的概念？
- [ ] 我的操作结果是可复现的吗？
- [ ] 如果我不得不在凌晨两点把这个练习的结果交给一个不认识的人，他能接住吗？

### 章末反思

```
### 本章三问
1. 🩻 这一章帮你看见了哪一种工程病？
2. 😣 这个病的代价在真实项目中会落到谁身上？
3. 🛤️ 学完这章，你有没有比之前更有办法让后来者好走一点？

### 叙事回响（⚠️ 新增）
回到这一章的正文，你觉得哪个角色在你做练习的时候一直在你脑子里？
他身上最让你放不下的那个瞬间是什么？
```

## 语言特定练习偏好

### Rust / 明契卷
- 偏 cargo 命令、项目结构、类型系统、错误处理
- 练习常涉及：新建项目、改 Cargo.toml、处理 Result/Option、写测试
- **叙事场景偏好**：北院旧发房、青炉起炉过程、代码审查对峙

### C++ / 驭器卷
- 偏构建系统、依赖分析、profile、wrapper 编写
- 练习常涉及：分析旧代码、写 adapter、写 runbook 条目
- **叙事场景偏好**：玄枢古器维护、守门者交接、旧核深处的隐性依赖

### Python / 化形卷
- 偏环境管理、依赖锁、脚本到 package 迁移、复现验证
- 练习常涉及：venv/poetry、requirements 审计、notebook 清理
- **叙事场景偏好**：息壤脚本林、林过川遗迹、"上周还能跑"的调试现场

### Go / 简阵卷
- 偏服务边界、健康检查、日志/追踪、部署回滚
- 练习常涉及：写 health check、定义 API 契约、写 runbook
- **叙事场景偏好**：驿河凌晨传讯牌、失明事故追踪、新手独立接值班

## 输出

完整 Markdown 实践单文件，可直接放入 `.claude/supplements/0X_XX卷/` 目录。

## Gotchas

- **去叙事化的练习**：练习变成纯粹的 CLI 操作步骤列表。"先跑这个命令，看输出，然后跑下一个。"——这不会让任何人记住任何东西。每个练习必须有一张人脸在背后。
- **跳过失败直接成功**：练习的步骤设计成"照着做就能跑通" → 练习者什么都没学到。必须先让他们撞上"纸上写的走不通"的瞬间——那才是本章概念真正被需要的原因。
