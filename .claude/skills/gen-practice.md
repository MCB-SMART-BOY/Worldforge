# /gen-practice — 实践单生成

从一章正文生成对应的「卷外配套」章节实践单。实践单的责任是：让学编程的读者在读完这章后，能动手做对应的工程练习。

## 参数

- `chapter_path` — 章节文件路径
- `volume` — 所属卷（明契卷/驭器卷/化形卷/简阵卷）
- `chapter_number` — 章号

## 实践单模板

### 前置信息
- 所属卷/章
- 对应工程主题
- 本章核心四蚀
- 前置知识要求（读者需要会什么才能做这些练习）

### 三个练习层次

每份实践单应包含三个层面的练习：

#### 第一层：验证性练习（本章概念的直接复现）
- 目标：确认读者理解了本章的核心工程概念
- 形式：操作步骤 + 观察点 + 预期结果
- 数量：2-3 个
- 示例格式：
  ```
  ### 练习1-1：[标题]
  **场景**：[一句话]
  **步骤**：
  1. ...
  2. ...
  **观察**：[读者应看到什么]
  **问自己**：[一个反思问题]
  ```

#### 第二层：变体练习（场景变化后是否能应对）
- 目标：确认读者能在不同场景中应用同一概念
- 形式：改变一个条件（语言/项目/团队规模/时间压力），让读者重新思考
- 数量：1-2 个
- 示例格式：
  ```
  ### 练习2-1：[标题]
  **变化**：[什么条件变了]
  **你的判断**：[一个需要读者做选择的开放问题]
  **为什么**：[引导读者写下理由]
  ```

#### 第三层：连接练习（联系前后章节的工程实践）
- 目标：确认读者能把本章概念放进更大的工程图景
- 形式：联系前章或预演后章的跨概念练习
- 数量：1 个
- 示例格式：
  ```
  ### 练习3-1：[标题]
  **连接**：[连接哪两章的概念]
  **你的设计**：[一个需要综合判断的任务]
  **反思**：[这个问题在真实项目里会怎么出现]
  ```

### 每层后的自检

每个练习后附「自检清单」：
- [ ] 我是否理解了练习要验证的概念？
- [ ] 我的操作结果是可复现的吗？
- [ ] 如果换一个项目/language，我会怎么改？

### 章末反思

```
### 本章三问
1. 🩻 这一章帮你看见了哪一种工程病？
2. 😣 这个病的代价在真实项目中会落到谁身上？
3. 🛤️ 学完这章，你有没有比之前更有办法让后来者好走一点？
```

## 语言特定练习偏好

### Rust / 明契卷
- 偏 cargo 命令、项目结构、类型系统、错误处理
- 练习常涉及：新建项目、改 Cargo.toml、处理 Result/Option、写测试

### C++ / 驭器卷
- 偏构建系统、依赖分析、profile、wrapper 编写
- 练习常涉及：分析旧代码、写 adapter、写 runbook 条目

### Python / 化形卷
- 偏环境管理、依赖锁、脚本到 package 迁移、复现验证
- 练习常涉及：venv/poetry、requirements 审计、notebook 清理

### Go / 简阵卷
- 偏服务边界、健康检查、日志/追踪、部署回滚
- 练习常涉及：写 health check、定义 API 契约、写 runbook

## 输出

完整 Markdown 实践单文件，可直接放入 `.claude/supplements/0X_XX卷/` 目录。
